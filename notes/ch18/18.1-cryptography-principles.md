# 18.1 Cryptography Principles

> 原書 p.716–734（Chapter 18: Extensions: Zb* & Zk* (Bit Manipulation and Cryptography)）
> 涵蓋 18.1.1 Finite Fields（GF(p)、GF(2ⁿ)）、18.1.2 AES（AddRoundKey、SubBytes、ShiftRows、MixColumns、KeyExpansion、Decryption）、18.1.3 Hash Functions（SHA-2）

## 這節在講什麼

這章講兩個擴充：Zb*（位元操作）和 Zk*（密碼學），放在同一章是因為它們共用同一個 ALU、有些指令重疊。但要懂 Zk* 的指令在做什麼，得先懂它們在加速什麼演算法。所以 18.1 是一節**數學與演算法的背景**，幾乎沒有 RISC-V 內容：先講有限體（finite field / Galois field），因為 AES 整個建立在 GF(2⁸) 上；再逐一拆解 AES 的五個運算單元；最後講 SHA-2 雜湊。看完會發現一件事——這些演算法用到的原始操作（XOR、移位、旋轉、查表、GF 乘法）在普通 ISA 上都要好幾條指令，這就是專用指令的價值所在。

## 關鍵點

### 密碼學要解決的三件事

> "Secrecy: Only A and B can see what is sent. Integrity: What A sends is what B receives. Authenticity: Nobody can impersonate A or B."
> — p.715

中文解釋：三個目標對應三種工具——**encryption/decryption 管保密、hashing 管完整性、signatures 管真實性**。這章只碰前兩者（對稱式加密與雜湊），因為 Zk* 擴充加速的就是這兩類。

### 為什麼需要密碼學專用指令

> "Pure software implementations are slow, power hungry, and vulnerable to timing attacks that can be exploited remotely. Modern instruction sets provide dedicated cryptographic instructions that are faster, simpler, and provide better performance than pure software implementations. Moreover, having dedicated cryptographic instructions promotes standardized software and reduced code size, which helps reduce the risk of inadvertent security flaws."
> — p.715

中文解釋：四個理由，其中**timing attack（時序攻擊）**最值得注意。如果加密程式的執行時間隨金鑰變化（例如查表造成快取命中/失誤的差異），攻擊者光靠測時間就能推出金鑰，而且可以遠端做。硬體指令執行時間固定，就堵住這條路。這也是後面 Zkt 擴充存在的原因。

### bit manipulation 的效益數字

> "For example, Section 21.2.3 shows these extensions make Embench 5% faster and 4% denser than an rv32imc baseline. In Section 21.1.3, CoreMark is 8% faster with bit manipulation instructions."
> — p.715

中文解釋：有具體數字很好。5–8% 不算驚人，但 Zb* 的硬體成本非常低（大多只是既有 ALU 加幾個運算），所以 CP 值高。

## 18.1.1 Finite Fields

### field（體）的定義

> "In mathematics, a field is a set that supports the operations of multiplication and addition. A field has additive and multiplicative identity elements, 0 and 1, respectively."
> — p.716

中文解釋：Table 18.1 列出六個性質：封閉性、單位元素、反元素、交換律、結合律、分配律。實數 ℝ 和有理數 ℚ 都是體；**整數不是**，因為 3 沒有乘法反元素（找不到整數乘 3 等於 1）。

### 為什麼密碼學要用有限體

> "Fields are the building block of many cryptographic algorithms that involve multiplication and addition. Computers use data types with finite precision, so, unsurprisingly, cryptography does too. A finite field or Galois field is a set with a finite number of elements."
> — p.717

中文解釋：邏輯很直接——電腦的資料型別位元數固定，所以用元素數量有限的體剛剛好。兩種常用：
- **GF(p)**：模質數 p 的整數算術
- **GF(2ⁿ)**：n 位元二進位數的算術，加法用 XOR、乘法溢位用 XOR 處理

（Galois 體以 Évariste Galois 命名。他十幾歲就做出抽象代數的重要貢獻，因批評校長被退學、因政治抗議入獄半年，20 歲死於一場為了女人的決鬥。）

### GF(2)：最小的有限體，也是最有用的

> "An important field for cryptography is GF(2), which is the smallest finite field that can exist. It is useful for computing because its set is the binary values {0, 1}. Interestingly, GF(2) addition is equivalent to an XOR gate, and GF(2) multiplication is equivalent to an AND gate."
> — p.718

中文解釋：這就是有限體與數位電路的接點。Fig. 18.2 的真值表：加法就是 XOR、乘法就是 AND。注意 1 的加法反元素是它自己（1+1 mod 2 = 0）——這個性質後面會一再用到。

### GF(2ⁿ)：把多項式看成位元

> "Another important Galois field for cryptography is GF(2ⁿ), whose elements are polynomials of degree up to n − 1 with coefficients {0, 1} in GF(2). GF(2ⁿ) is also called a binary extension field because the coefficients are binary numbers. Multiplication is performed modulo some irreducible polynomial m(x) of degree n."
> — p.718

中文解釋：這是整節最關鍵的觀念轉換。GF(2³) 的元素是 x² + x + 1 這種多項式，但**係數只有 0 或 1，所以可以直接當成 3 位元二進位數**。x 不是變數，只是用來標示「這是第幾個位元」的佔位符。Table 18.2 列出 GF(2³) 的 8 個元素與它們的反元素。

> "There is a one-to-one correspondence between polynomials in GF(2ⁿ) and n-bit binary numbers... In other words, addition in GF(2ⁿ) is simply bitwise XOR on the two n-bit binary representations, which is even easier than integer addition. The esoteric mathematics of Galois binary extension fields is cheap and easy to implement in hardware."
> — p.719

中文解釋：**加法 = XOR，一個閘就搞定，連進位都不用。** 這是 GF(2ⁿ) 在硬體上便宜的根本原因。而且每個元素都是自己的加法反元素（a ⊕ a = 0）。

### 乘以 x 就是左移一位 + 條件 XOR

> "In binary representation, multiplying a by x gives ax = a × 10 = (a << 1) mod m. Thus, multiplication by x is a left shift by 1. If the result has a 0 shifted into column n, it is less than m, and the modulus does nothing. Otherwise, as with polynomials, the modulus reduces the result by dropping the 1 from column n and XORing the other bits with f, the binary representation of f(x)."
> — p.720

中文解釋：這是式 (18.1)：

```
ax = (a[n−2:0] << 1)           當 a[n−1] = 0
   = (a[n−2:0] << 1) ⊕ f       當 a[n−1] = 1
```

其中 m(x) = xⁿ + f(x)。整個 GF(2ⁿ) 乘法只需要**移位和 XOR**，沒有真正的乘法器。這叫做 reduction（約化），把超出 n−1 次的多項式降回體內。

### AES 的 GF(2⁸) 乘法

> "AES treats bytes as elements of GF(2⁸) with m(x) = x⁸ + x⁴ + x³ + x + 1. Thus, f(x) = x⁴ + x³ + x + 1; f = 00011011."
> — p.721

中文解釋：這個 `0x1B` 常數在所有 AES 實作裡都會看到，來源就在這裡。Example 18.1 與 Table 18.3 示範怎麼算 a × b：先反覆左移 + 條件 XOR 0x1B 算出 ax⁰ 到 ax⁷，再依 b 的位元選擇要加總哪幾項。Code Example 18.1 的 C 程式把這件事寫成一個 while 迴圈（`examples/crypto/gfmul`）。

### 乘法反元素靠查表

> "Finding the multiplicative inverse of an element is complicated. It could be done by guess and check but is more efficiently performed by the extended Euclid algorithm. ... For a small finite field such as GF(2⁸), it is easiest to precompute and tabulate the inverses, as shown in Fig. 18.3."
> — p.722

中文解釋：GF(2⁸) 只有 256 個元素，直接做一張 16×16 的表最快。這張表是 AES S-box 的數學基礎。0 沒有反元素，表中填 0。

## 18.1.2 AES

### AES 的基本參數

> "AES operates on 128-bit blocks of plaintext to produce 128-bit blocks of ciphertext. The 128 bits at each intermediate step are called state and are organized as a 4 × 4 matrix of bytes s_{i,j} representing elements in GF(2⁸)"
> — p.723

中文解釋：AES 在 2001 年由 NIST 採用（取代 DES，因為 1988 年 EFF 用一顆客製晶片一天就破了 DES 的 56 位元金鑰）。它是**對稱式**加密——加密解密用同一把金鑰。金鑰可以是 128、192 或 256 位元，對應 N_r = 10、12、14 輪。

`state` 是 4×4 的位元組矩陣（Fig. 18.4），每個位元組是 GF(2⁸) 的一個元素。

### 一輪做什麼：confusion 與 diffusion

> "Each round performs a nonlinear substitution (for confusion), applies linear transformations to the rows and columns (for diffusion), and then adds that round's key, referred to as the round key. The first N_r − 1 rounds use the SubBytes, ShiftRows, MixColumns, and AddRoundKey units. The last round omits the MixColumns step because it does not contribute to security."
> — p.723

中文解釋：Shannon 在 1945 年提出的兩個概念（邊欄）：
- **confusion（混淆）**：讓密文與金鑰的關係模糊 → SubBytes 負責
- **diffusion（擴散）**：讓明文的一點改變散布到整份資料 → ShiftRows 與 MixColumns 負責

Fig. 18.5 是整體架構。最後一輪省略 MixColumns，因為那一步對安全性沒有貢獻（後面沒有非線性步驟可以配合了）。

### AddRoundKey：128 個 XOR 閘

> "Recall that addition in GF(2⁸) is XOR, so the AddRoundKey block is simply 128 2-input XOR gates to XOR the 128-bit state and 128-bit round key."
> — p.724

中文解釋：這是 GF(2ⁿ) 加法 = XOR 的直接應用。整個單元的硬體成本就是 128 個 XOR 閘。

### SubBytes：S-box 查表

> "The SubBytes unit replaces each of the 16 bytes in the state matrix with another byte using a 2⁸-input lookup table called the S-box (substitution-box), as shown in Fig. 18.6. The S-box performs substitution to introduce non-linearity into the cipher."
> — p.724

中文解釋：Fig. 18.7 是 256 個項目的完整 S-box 表。例如 s = 0x42 會被換成 0x2c。

> "S-boxes are common in symmetric key ciphers because they obscure the relationship between the plaintext and the ciphertext. The AES S-box is conceptually a 256-entry × 8-bit lookup table. It follows a mathematical structure, so it can also be synthesized onto logic gates, potentially in a more compact way"
> — p.724

中文解釋：關鍵字是 **non-linearity（非線性）**。前面所有運算（XOR、移位、GF 乘法）都是線性的，線性系統容易被代數方法破解。S-box 是 AES 唯一的非線性成分。它的內容不是隨機的——建構方式是「取 GF(2⁸) 的乘法反元素，再做一個仿射變換」，所以可以合成成邏輯閘而不用真的存一張表。

### ShiftRows：免費的擴散

> "The ShiftRows unit diffuses information across the block by rotating rows 1, 2, and 3 of the state matrix left by 1, 2, and 3 elements respectively, as shown in Fig. 18.8. Constant rotations simply rename the bits and require no hardware."
> — p.724–726

中文解釋：第 0 列不動、第 1 列左旋 1、第 2 列左旋 2、第 3 列左旋 3。**「常數旋轉只是把位元換個名字，不需要硬體」**——在硬體上就是接線，零成本。

### MixColumns：MDS 矩陣

> "The MixColumns unit also diffuses information by multiplying the state matrix by a simple linear transformation matrix containing values 0x01, 0x02, and 0x03, as shown in Fig. 18.9. This transformation is called maximum distance separable (MDS). If two plaintexts differ only in a single byte, the MDS transformation spreads that change to other bytes of the state in as few steps as possible."
> — p.725–726

中文解釋：MDS 的意義就是「擴散得最快」。而且乘數選得很妙：
- 0x01 = 多項式 1 → 乘 1 什麼都不用做
- 0x02 = 多項式 x → **左移一位 + 條件 XOR 0x1B**
- 0x03 = 多項式 x + 1 → 乘 x 之後再 XOR 原數

所以整個 MixColumns 只需要移位和 XOR，完全沒有通用乘法器。這是為什麼 AES 的設計者選這三個係數。

### KeyExpansion：從一把金鑰生出多把

> "The KeyExpansion unit performs the key schedule, which is the process of deriving the round keys K from the key. The key schedule distributes the entropy of the key across the rounds, making it resistant to certain types of attacks with related keys."
> — p.726

中文解釋：每一輪用不同的金鑰。Table 18.4 的變數：
- `N_k` = 金鑰的 32 位元字數（4 / 6 / 8）
- `N_r` = 輪數（10 / 12 / 14）
- `w` = 4(N_r + 1) 個 32 位元字，每四個組成一把 round key

Fig. 18.10 的演算法核心：前 N_k 個字直接從金鑰來；之後每個字 w_i = w_{i−N_k} ⊕ t，其中 t 通常就是 w_{i−1}，但每隔 N_k 個字要做一次 **RotWord（左旋一個位元組）→ SubWord（四個位元組各查一次 S-box）→ XOR Rcon**。Rcon_j = x^{j−1} mod m(x)，Table 18.5 列出 10 個值（0x01、0x02、0x04…0x80、0x1B、0x36）——注意第 9 個值從 0x80 變成 0x1B，正是因為乘 x 時發生了 reduction。

Table 18.6 是完整的展開例子。這裡的 RotWord + SubWord + XOR Rcon 就是 Zkne/Zknd 指令要加速的東西。

### 解密：反向但不對稱

> "Because the AES algorithm is a symmetric cryptographic algorithm, decryption (also called the inverse cipher) consists of the same steps as encryption but with operations replaced by their inverses, as shown in Fig. 18.12. The key schedule also changes. AddRoundKey is its own inverse because a = −a in GF(2ⁿ)."
> — p.729

中文解釋：AddRoundKey 是自己的反運算（因為 GF 中 a ⊕ a = 0），所以加解密共用同一批 round key，只是使用順序相反。其他三個都要換成反向版本：
- InvSubBytes 用一張反向 S-box
- InvShiftRows 右旋而非左旋
- InvMixColumns 用 Fig. 18.13 的矩陣（0x0e、0x0b、0x0d、0x09）——這些值比正向的 01/02/03 複雜得多，**所以解密比加密貴**。這就是為什麼 RISC-V 把 Zknd（解密）和 Zkne（加密）分成兩個擴充，只需要加密的系統可以不付解密的成本。

## 18.1.3 Hash Functions

### 雜湊函數的四個性質

> "Avalanche effect: Any change in the message will, with very high probability, change many bits of the digest. Pre-image resistant: Given a message digest, it is computationally infeasible to find the original message. Collision resistant: Given a message digest, it is computationally infeasible to find another message that produces the same digest. Fast and easy to compute"
> — p.731

中文解釋：**avalanche effect（雪崩效應）**是設計目標，另外兩個是安全性保證。注意最後一個「快」——雜湊要能大量使用（每次驗證檔案、每個區塊鏈交易），所以不能慢。

> "Hashes are used to verify data integrity and as a building block for digital signatures. Any alteration to a message will corrupt the message digest. Passwords are usually stored in hashed form instead of plaintext, so stealing the password file will not reveal the password itself."
> — p.731

中文解釋：三個用途：驗證完整性、數位簽章的基礎、密碼儲存。

### SHA-2 的地位

> "SHA-2 is the hash function used in most internet protocols, such as TLS, SSL, and PGP, as well as to verify transactions in Bitcoin and other cryptocurrencies. It was designed by the US National Security Agency (NSA) and was first published in 2001. ... SHA-2 generates 224-, 256-, 384-, or 512-bit message digests, replacing the SHA-1, MD4, and MD5 algorithms that produced shorter digests that are no longer considered secure."
> — p.731

中文解釋：SHA-1、MD5 已經被破（找得出碰撞），現在用 SHA-2。

### SHA-256 與 SHA-512 的差別只有參數

> "Table 18.7 summarizes the structure of SHA-256 and SHA-512. ... Fig. 18.14 describes the SHA-2 algorithm, which is the same for SHA-256 and SHA-512 except for the parameter values, and definition of sigma functions, as given in Table 18.7."
> — p.731–732

中文解釋：Table 18.7 的對照：
| | SHA-256 | SHA-512 |
|---|---|---|
| digest 長度 d | 256 | 512 |
| block 長度 m | 512 | 1,024 |
| word 長度 w | 32 | 64 |
| 輪數 r | 64 | 80 |

四個 **sigma 函數**是重點，因為它們正是 Zknh 指令要加速的對象。以 SHA-256 為例：
- Σ₀(x) = (x ror 2) ⊕ (x ror 13) ⊕ (x ror 22)
- Σ₁(x) = (x ror 6) ⊕ (x ror 11) ⊕ (x ror 25)
- σ₀(x) = (x ror 7) ⊕ (x ror 18) ⊕ (x >> 3)
- σ₁(x) = (x ror 17) ⊕ (x ror 19) ⊕ (x >> 10)

每個 sigma 在沒有專用指令時要 **6 條指令**（三次旋轉/移位 + 兩次 XOR，旋轉本身在沒有 Zbb 時還要兩條），一輪要用到好幾個——這就是 Zknh 一條指令抵好幾條的來源。

### 常數不是隨便選的

> "The random-looking initialization and round constants in Table 18.7 correspond to the most significant fractional parts of the cube and square roots of the first 8 and r prime numbers, respectively. They are called nothing-up-my-sleeve numbers and give confidence that they were not specially chosen by the NSA to provide a backdoor."
> — p.732（邊欄）

中文解釋：**nothing-up-my-sleeve numbers（袖子裡沒藏東西的數字）**是一個很重要的密碼學實務。常數必須「明顯沒有被精心挑選」，所以選用 π、e、質數的平方根這種任何人都能自己算出來的值。如果常數是一串無法解釋的十六進位數，就沒辦法排除後門的可能。

### SHA-2 的演算法結構

> "The algorithm also uses Choose (Ch) and Majority (Maj) functions which, respectively, choose y or z based on x and output 1 if a majority (at least 2 of the 3) inputs are TRUE."
> — p.732

中文解釋：
- Ch(x, y, z) = xy ⊕ x̄z，也就是「x ? y : z」逐位元選擇
- Maj(x, y, z) = xy ⊕ xz ⊕ yz，三個裡至少兩個為 1 就輸出 1

Fig. 18.14 的流程（Fig. 18.15 是視覺化的壓縮函數）：
1. 8 個字的 hash H 初始化成已知常數
2. 對每個 block：
   - **message schedule**：把 16 個字的 block 擴展成 r 個字 W。前 16 個直接複製，其餘 W_t = σ₁(W_{t−2}) + W_{t−7} + σ₀(W_{t−15}) + W_{t−16}
   - 8 個 **working variables** a_j 從上一個 block 的 hash 初始化
   - 跑 r 輪：T = a₇ + Σ₁(a₄) + Ch(a₀, a₅, a₆) + K_t + W_t，然後所有 a 右移一個位置，a₀ = Σ₀(a₀) + Maj(a₀, a₁, a₂) + T，a₄ = a₄ + T
   - block 結束後 H_j += a_j
3. 最後的 H 就是 digest

加法是 mod 2^w（溢位直接丟掉）。這個「擴散 + 壓縮」結構來自 **Merkle-Damgård method**，用來從一個壓縮函數建出抗碰撞的雜湊。

### 動手驗證

> "Most Linux distributions come with programs to compute the SHA-256 hash function to verify data integrity. For example, the command at the top of page 738 produces the hash for 'Hello World!' using SHA-256."
> — p.733

中文解釋：`echo -n "Hello World!" | sha256sum`。改一個驚嘆號成問號，整個雜湊就完全不同——這就是雪崩效應。

| working variables | SHA-2 每輪更新的 8 個字 |
| Choose (Ch) / Majority (Maj) | SHA-2 的兩個位元邏輯函數 |
| Merkle-Damgård method | 從壓縮函數建構抗碰撞雜湊的方法 |
| nothing-up-my-sleeve numbers | 來源明確可驗證的常數，用來排除後門疑慮 |

## 所以呢

這一節建立了兩個判斷標準。第一，AES 和 SHA-2 反覆用到的原始操作是：XOR、固定量的旋轉、移位、S-box 查表、GF(2⁸) 乘以 x（左移 + 條件 XOR 0x1B）。第二，這些操作在普通 ISA 上每個都要好幾條指令。下一節 18.2 就會看到 RISC-V 怎麼用 Zbb 的 `rol`/`ror`、Zbc 的 carry-less 乘法、Zbkx 的 crossbar permutation、以及 Zkne/Zknd/Zknh 的專用指令把這些壓成一條。
