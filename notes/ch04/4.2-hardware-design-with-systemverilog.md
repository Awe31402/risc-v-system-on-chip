## 這節在講什麼

**SystemVerilog 的「慣用寫法（idiom）目錄」。**

這節的組織邏輯不是「語言教學」，而是**「想要某種硬體，就寫某段固定的程式碼」**：

| 想要的硬體 | 慣用寫法 |
| --- | --- |
| 組合邏輯 | `assign` 或 `always_comb` |
| 正緣觸發正反器 | `always_ff @(posedge clk) q <= d;` |
| 有限狀態機 | 狀態暫存器 + `always_comb` 次態邏輯 + 輸出邏輯 |
| 記憶體 | 宣告 `bit` 陣列 + 同步讀寫 |
| 可組態硬體 | `generate`、參數、`parameter struct` |

**開宗明義那句話是整節的方法論：先看見硬體，再寫出對應的 HDL。**

最後 4.2.5 講 Wally 的可組態機制——這是整本書後面看懂 Wally 程式碼的必要前置。

## 關鍵點

### 方法論：先看見硬體，再寫程式碼

> "A good hardware designer visualizes the desired hardware (e.g., registers, memories,
>  FSMs, and combinational logic blocks) and then writes HDL idioms that imply such
>  hardware.... The most common novice error when using hardware description languages
>  is to think of them as software programming and to simply write code rather than
>  visualize hardware."
> — p.145

中文解釋：呼應 4.1 節的 beginner mistake 警告。**這是整章的核心方法論。**

邊欄給了更具體的建議（p.145 邊欄）：
> "A substantial fraction of the Verilog code you will discover in an Internet search is
>  bad or has subtle errors, so it is much better to think of the hardware you want and
>  then write the appropriate idiom. **If you aren't sure of what hardware you want, you
>  are likely to write bad code too.**"

**網路上搜到的 Verilog 有相當大一部分是爛的或有微妙錯誤。**

邊欄也提醒（p.145 邊欄）：
`$display` 等功能**不可合成**（只能寫 testbench 用），
`reg` 和 `wire` 是**歷史包袱，不該在現代設計中使用**。

### 階層 vs 行為

> "We design logic *hierarchically* or *structurally* by decomposing a complex system
>  into modules with well-defined inputs and outputs. Each of the modules is recursively
>  decomposed into smaller modules until the modules are simple enough that they can be
>  described *behaviorally*."
> — p.145

> "The designer must first consider whether a piece of behavioral logic is combinational
>  or sequential. Whereas *combinational logic* outputs depend only on current input
>  values, *sequential logic* outputs depend on current and previous input values and thus
>  have memory. For ease of design, we rely on the *synchronous sequential discipline*,
>  in which the only sequential elements are edge-triggered flip-flops or memories."
> — p.145

中文解釋：**兩個層次：結構（structural）描述怎麼接，行為（behavioral）描述做什麼。**
遞迴往下分解，直到小到可以直接行為描述。

**第一個要問的問題永遠是：這塊邏輯是組合還是時序？**
- **組合**：輸出只看目前輸入
- **時序**：輸出還看過去的輸入 → **有記憶**

**同步時序規範（synchronous sequential discipline）：唯一的時序元件是
邊緣觸發正反器或記憶體。** 這個自我限制讓設計可管理——
後面 latch 那段會看到違反它的後果。

### 4.2.1 模組與參數化

中文解釋：Code Example 4.1（p.146）的全加器示範最基本的模組：
```systemverilog
module fulladder(input  logic a, b, c,
                 output logic s, cout);
  assign s = a ^ b ^ c;
  assign cout = (a & b) | (a & c) | (b & c);
endmodule
```

**`logic` 型別可以是 0、1、z（浮接）或 x（未初始化或無效）。**

**Fig. 4.1（p.146）很值得看**：同一段 HDL 可以合成成
(a) 基本邏輯閘、(b) 最佳化後的邏輯閘、(c) **FPGA 查找表（LUT）**——
**三種截然不同的實作。合成工具在目標元件庫中挑「滿足時序的最低成本解」**（p.145）。

**參數化模組（Code Example 4.3，p.146）：**
```systemverilog
module mux2 #(parameter WIDTH = 8) (
  input  logic [WIDTH-1:0] d0, d1,
  input  logic             s,
  output logic [WIDTH-1:0] y);
  assign y = s ? d1 : d0;
endmodule
```
**實例化時覆寫參數（Code Example 4.4，p.147）：**
```systemverilog
mux2 muxa(d0, d1, s, y);                  // 預設 8-bit
mux2 #(12) muxb(data0, data1, sel, yout); // 12-bit
```

**"An instantiation is like grabbing parts from the hardware bin and then connecting
their inputs and outputs as desired."**（p.147）
——**實例化就像從零件箱拿零件出來接線。**

**instantiate vs call 的關鍵區別**（p.148 邊欄）：
> "In a typical programming language, a function *calls* another function.... In
>  contrast, a hardware description language *instantiates* modules, that is, creates an
>  instance of the module that permanently exists within the design, as opposed to
>  function calls, which only exist while they are being called. The mux4 in Code Example
>  4.5 can be built from three mux2 modules, which **exist on a chip whether or not the
>  inputs are changing.**"

**「不管輸入有沒有變，那些電路都在晶片上。」** 這是硬體和軟體最根本的差別。

**Wally 的結構化風格**（p.148 邊欄）值得注意：
> "Wally favors a structural coding style that decomposes datapath modules into simple
>  blocks, such as registers, multiplexers, memories, and Boolean equations, to emphasize
>  the hardware implied by the code.... **Beginning designers who don't want to think
>  about the hardware implied by Verilog statements also often use a behavioral style and
>  end up writing code that implies wasteful hardware or that won't synthesize.**"

**有經驗的設計者可以多用行為描述求簡潔；新手應該用結構化風格逼自己想清楚硬體。**

### 4.2.2 組合邏輯：`assign` 與運算子

> "Multiple assign statements all operate in parallel, just like the hardware they imply.
>  Hence, the order of assign statements in a module does not affect operation. This is a
>  major difference between HDLs and conventional sequential programming languages."
> — p.148

中文解釋：**`assign` 語句的順序無關緊要，因為它們同時存在。**
這是 HDL 和程式語言最根本的差異之一。

**Table 4.1 運算子優先序（p.149），由高到低：**

| 優先序 | 運算子 | 意義 |
| --- | --- | --- |
| 最高 | `~` | NOT |
| | `* / %` | 乘、除、模 |
| | `+ -` | 加、減 |
| | `<< >>` | 邏輯左/右移 |
| | `<<< >>>` | 算術左/右移 |
| | `< <= > >=` | 相對比較 |
| | `== !=` | 相等比較 |
| | `& ~&` | AND、NAND |
| | `^ ~^` | XOR、XNOR |
| | `\| ~\|` | OR、NOR |
| 最低 | `? :` | 條件（三元） |

**建議：用括號改變順序，或在你不希望讀者去記冷僻優先序時也加括號**（p.148）。

**Bitwise vs reduction 形式**（p.148）：
- **Bitwise（位元對位元）**：`y = a & b`，兩個 N-bit 輸入產生 N-bit 輸出
- **Reduction（歸約）**：`w = &a`，**一個 N-bit 輸入產生 1-bit 輸出**
  （把所有位元 AND 起來）

範例（Code Example 4.6，p.148）：
```systemverilog
assign eq = &(a ~^ b);   // 等同於 assign eq = (a == b)
```
**先逐位 XNOR（相等則為 1），再 reduction AND（全部相等才為 1）。**
Fig. 4.4（p.150）就是這個電路：四個 XNOR 閘接一個 4 輸入 AND。

**邊欄的重要風格規定**（p.149 邊欄）：
Verilog 也有 `&&`、`||` 邏輯運算子（把多位元輸入當 TRUE/FALSE）。
**"Our style uses bitwise operators exclusively and never attempts to interpret a
multibit input as TRUE or FALSE."**
——**Wally 風格只用位元運算子。** 因為 `011 && 111 = 1`（兩者都非零）這種語意容易出錯。

**運算成本的直覺**（p.149）很實用：
- **加減法**：N-bit 至少要 N 個全加器
- **相對比較（`<`、`>=`）**：幾乎和減法一樣貴
- **相等比較**：便宜，只要 N 個 XNOR 閘加一個 N 輸入 AND
- **常數移位免費**（只是接線）；**可變移位需要很多多工器，相當貴**
- **乘以 2 的冪次只是移位**；**一般乘法很貴**（部分積產生器陣列 + 加法器陣列）
- **除法和模運算很貴**，可行時應避免

**"Cost is proportional to chip area."**（p.149 邊欄）

### 4.2.2.2 `always_comb`：if 與 case

> "In classic Verilog, always blocks require a sensitivity list that is notoriously prone
>  to accidentally imply sequential logic instead of combinational logic or cause
>  mismatches between simulation and synthesized logic, so SystemVerilog introduced the
>  always_comb statement that will warn you if you make a mistake."
> — p.149–150

中文解釋：**`always_comb` 是 SystemVerilog 相對於 Verilog 的重要改進。**
舊的 `always @(...)` 要手寫 sensitivity list，漏掉一個訊號就會
**意外產生時序邏輯，或造成模擬和合成結果不一致**（最可怕的一種 bug）。
**`always_comb` 自動推導，而且寫錯會警告。**

**七段顯示解碼器（Code Example 4.7，p.150）示範 `case`：**
```systemverilog
always_comb
  case(digit)
                             // abc_defg
    0:       segments = 7'b111_1110;
    1:       segments = 7'b011_0000;
    ...
    default: segments = 7'b000_0000;
  endcase
```

**`default` 那行是關鍵，不能省：**
> "Note that the default statement is necessary so that the outputs are well-defined even
>  when an illegal input such as 1111 is applied; otherwise, the logic would remember the
>  old output, which implies a *latch* (called *latch inference*) and is not combinational
>  logic or synchronous sequential logic."
> — p.150

**latch inference（閂鎖推論）是最經典的 Verilog 陷阱**：
**只要有某個輸入組合沒有指定輸出，工具就會推論出一個 latch 來「記住舊值」。**
這破壞了同步時序規範，會造成時序分析困難和難以除錯的問題。
**避免方法：`always_comb` 裡每條路徑都要賦值，或加 `default`。**

（小技巧：**常數裡加底線 `_` 增加可讀性，模擬和合成工具會忽略它**，p.150 邊欄。）

**優先權電路（Code Example 4.8，p.151）示範 `casez`：**
```systemverilog
always_comb
  casez(a)
    4'b1???: y = 4'b1000;    // ? 是 don't care
    4'b01??: y = 4'b0100;
    4'b001?: y = 4'b0010;
    4'b0001: y = 4'b0001;
    default: y = 4'b0000;
  endcase
```
**`casez` 允許輸入中有 don't care（`?`）**，用來寫優先權編碼很自然。
書上說 `casez` 和 `if/else` 兩種風格「可讀性相當，隱含相同硬體」（p.151）。

### 4.2.2.3 x 與 z：兩種特殊值

> "SystemVerilog logic signals have four states: 0, 1, x, and z. x indicates unknown, and
>  z indicates *floating* (high impedance)."
> — p.151

> "Unknown (x) values have several possible causes. A logic signal with no driver or
>  multiple conflicting drivers has an unknown value. The output of a sequential element
>  such as a flip-flop or memory cell is unknown until a value is written. If a gate
>  receives an x or z input, it will produce an x output when it can't determine the
>  correct output value. For example, 1'b1 & 1'b x = x. But 1'b0 & 1'b z = 0 because
>  anything AND 0 is 0."
> — p.151

中文解釋：**x 的三個來源：沒有驅動源、多個衝突驅動源、時序元件尚未寫入。**

**x 的傳播規則很直覺：算不出確定答案就輸出 x，算得出就輸出確定值。**
`1 & x = x`，但 `0 & z = 0`（任何東西 AND 0 都是 0）。

**x 是 bug 的訊號**（p.151）：
> "The presence of x in simulation is generally an indication of a logic problem and
>  should be tracked down and fixed. An exception is that memories are generally
>  initialized to x. However, this is a problem when uninitialized memory is read, and
>  this x percolates into logic that affects the state of the system."

書上舉例（p.151–152）：**Wally 讀到未初始化的記憶體位址時，
x 會傳播穿過硬體頁表走訪器並讓模擬卡住。**

**Wally 的解法：用 `bit` 而非 `logic`**（p.152）：
> "SystemVerilog has another data type called bit that only represents 0 and 1. When
>  logic is converted to bit, x and z map to 0. As shown in Section 4.2.3.3, Wally uses
>  bit instead of logic in random access memory (RAM) to prevent uninitialized RAM from
>  corrupting the system and to cut simulation memory usage (**because bit takes half as
>  much space as logic**)."

**兩個好處：避免 x 汙染，而且模擬記憶體用量減半。**

**不要用 x 當錯誤指示**（p.152）：
> "Some designers have tried to cleverly use x as a mechanism to indicate problems, such
>  as an illegal instruction. Unfortunately, simulations may be optimistic or pessimistic
>  in a way that hides real problems or indicates phantom problems, so it's best not to
>  rely on x to detect design errors."

模擬器對 x 的處理可能**過度樂觀（藏住真問題）或過度悲觀（報假問題）**。

（Questa 模擬器把 **x 顯示成紅線、z 顯示成藍線**，p.151 邊欄。）

### Tristate 匯流排

> "A *tristate bus* has multiple drivers controlled such that at most one is active. If
>  the bus has one active driver, it takes the value from that driver. If no driver is
>  active, the bus floats. Tristate drivers are modeled with z."
> — p.152

中文解釋：Code Example 4.9（p.152）的 tristate buffer：
```systemverilog
module tristate #(parameter WIDTH=32) (
  input  logic [WIDTH-1:0] a,
  input  logic             en,
  output tri   [WIDTH-1:0] y);
  assign y = en ? a : 'z;
endmodule
```

**`tri` 型別而非 `logic`**（p.152 邊欄）：
> "logic signals can only have a single driver. Tristate busses have multiple drivers, so
>  they should be declared as a tri net.... Also note that a tri output from a module can
>  be used as a logic input to another module."

**三種情況的行為（Fig. 4.8 波形，p.153）：**
- 沒有 tristate 啟用 → **匯流排浮接（z）**
- 恰好一個啟用 → 取該驅動源的值
- **多個啟用且值不同 → 匯流排變成 x（contention，競爭）**

**重要的實務建議（p.153）：**
> "This coding style is not recommended within a chip. Tristate busses are slow and can
>  have contention if one driver turns ON before another turns OFF. Many cell libraries
>  don't even have tristate cells. Instead, tristate drivers are more appropriate for I/O
>  pins that must access an off-chip shared bus or for shared bidirectional pins."

**晶片內部不要用 tristate。** 它只適合 I/O 接腳。
Code Example 4.10（p.153）的 GPIO 示範雙向 I/O，
**雙向接腳宣告為 `inout` 而且必須是 `tri` 網路**。

### 4.2.3 時序邏輯：正反器

> "The SystemVerilog idiom for an ordinary *flip-flop*... On the rising edge of the clock,
>  a flip-flop copies the input to the output.... The <= operator is called a
>  *nonblocking assignment* and is often pronounced "gets." All nonblocking assignments
>  happen in parallel."
> — p.154

中文解釋：**最基本的慣用寫法（Code Example 4.11，p.154）：**
```systemverilog
module flop #(parameter WIDTH = 3) (
  input  logic             clk,
  input  logic [WIDTH-1:0] d,
  output logic [WIDTH-1:0] q);
  always_ff @(posedge clk)
    q <= d;
endmodule
```
**「共用時脈的一組正反器加上輸入輸出匯流排，叫做 register（暫存器）」**（p.154）。

### Blocking（`=`）vs Nonblocking（`<=`）：最重要的規則

> "Combinational logic in an always_comb block is best described with blocking assignments
>  (=) when one line depends on the previous. Nonblocking assignments also produce the
>  correct result, but the simulation will be slower because the always block may need to
>  be evaluated multiple times."
> — p.154–155

> "Sequential logic is best described with nonblocking assignments (<=) because <=
>  captures the way real hardware operates in parallel rather than consecutively."
> — p.155

中文解釋：**規則很簡單，但理由必須懂：**

| 場合 | 用哪個 | 理由 |
| --- | --- | --- |
| `always_comb` 組合邏輯 | **`=`（blocking）** | 一行依賴前一行時語意正確，模擬較快 |
| `always_ff` 時序邏輯 | **`<=`（nonblocking）** | **捕捉真實硬體「並行」而非「依序」的行為** |

**書上的例子非常清楚（p.155）：**
```systemverilog
// (a) 壞：用 blocking
always_ff @(posedge clk) begin
  b = a;   // Blocking
  c = b;   // Blocking
end
// → a 先複製到 b，然後「新的」b 複製到 c
// → b 和 c 都拿到 a 的值，只產生【一個】正反器

// (b) 好：用 nonblocking
always_ff @(posedge clk) begin
  b <= a;  // Non-blocking
  c <= b;  // Non-blocking
end
// → c 拿到 b 的【舊】值，同時 b 拿到 a 的舊值
// → 產生【兩個】正反器（正確的同步器）
```
Fig. 4.11（p.155）畫出兩者的硬體差異。

**這是 Verilog 最經典的陷阱之一**：同樣的兩行，只差 `=` 和 `<=`，
**合成出完全不同的電路。**

### 可重置正反器：同步 vs 非同步

中文解釋：Code Example 4.12（p.156）兩種寫法：
```systemverilog
// 非同步重置：reset 也在 sensitivity list 裡
always_ff @(posedge clk, posedge reset)
  if (reset) q <= 0;
  else       q <= d;

// 同步重置：只有 clk
always_ff @(posedge clk)
  if (reset) q <= 0;
  else       q <= d;
```
**差別就在 sensitivity list 有沒有 `posedge reset`。**

**兩者的取捨（p.155–156）：**

| | 非同步重置 | 同步重置（也叫 clear） |
| --- | --- | --- |
| 何時生效 | **reset 一上升就立刻** | 只在時脈上升時 |
| 優點 | **即使某些時脈來源還沒啟動也能運作** | 電晶體較少、較便宜 |
| 缺點 | **需要多很多電晶體，加上複雜的分佈樹**讓 reset 同時到達所有正反器 | 有 gated clock 時會很麻煩（重置期間時脈可能不動） |
| 適用 | **FPGA**（正反器內建非同步重置輸入） | **ASIC**（降低成本） |

**"Asynchronous resets must be glitch-free to prevent a spurious reset."**（p.155 邊欄）

**同步 clear 的另一個用途**（p.156）：
**把 pipeline 某一級沖掉（flush）**——藉由取消寫入控制訊號。
（呼應 2.7 節的 flush。）

**哪些正反器可以不要 reset**（p.156 邊欄）：
> "Reset can be eliminated for registers that always get a value before they are used.
>  For example, the register file does not need to be reset because a program should not
>  depend on the values of registers before they are initialized. In simulation,
>  registers without a reset start with an unknown value (x) until given a value.
>  Occasionally this x propagates through other logic, leading to subtle simulation
>  problems. **x also can be a clue of a bug in simulation, and nonreset registers can
>  obscure this clue. Wally resets all flip-flops to avoid these difficulties.**"

**Wally 選擇全部重置，換取除錯便利。**

### 帶啟用的正反器

中文解釋：Code Example 4.13（p.156）：
```systemverilog
always_ff @(posedge clk)
  if (en) q <= d;
```
**用途（p.156）：「可用來 stall 處理器的 pipeline 級，或節省電力。」**
（呼應 2.7 節的 stall。）

完整版（Code Example 4.14，p.157）把 enable、非同步 reset、同步 clear 串起來，
**注意優先序（由外而內）：`reset` > `en` > `clear`**：
```systemverilog
always_ff @(posedge clk, posedge reset)
  if (reset)    q <= 0;
  else if (en)
    if (clear)  q <= 0;
    else        q <= d;
```
**這個 `flopenrc` 模組在 Wally 的 pipeline 裡到處都是**（呼應 2.7 節每一級都能 stall/flush）。

### Latch：只在特殊場合使用

> "A *transparent* or *D latch* passes D through to Q as long as clock is asserted and
>  retains Q otherwise.... Transparent latches are not edge triggered and thus generally
>  should be avoided in a synchronous sequential design methodology, but they are needed
>  in special-purpose circuits such as clock gaters."
> — p.157

中文解釋：
```systemverilog
always_latch
  if (clk) q <= d;
```
**`always_latch` 是「我故意要 latch」的宣告。**
（對比前面說的 latch inference：不小心產生的 latch 是 bug，
刻意寫 `always_latch` 才是設計。）
Fig. 4.14（p.157）的 latch 符號**沒有三角形**（三角形代表邊緣觸發）。

### 4.2.3.2 有限狀態機（FSM）

> "FSMs are categorized as Moore or Mealy machines. In Moore machines, the outputs depend
>  only on the current state. In Mealy machines, the outputs depend on the current state
>  and inputs."
> — p.157

中文解釋：**Moore vs Mealy 的唯一差別是「輸出看不看輸入」**（Fig. 4.15，p.158）：
兩者都有 k-bit 狀態暫存器和次態邏輯；
**Mealy 的輸出邏輯多了一條從 inputs 來的線。**

**FSM 的標準三段式寫法（Code Example 4.16，p.159），以 2-bit 分支預測器為例：**
```systemverilog
typedef enum logic [1:0] {SNT, WNT, WT, ST} statetype;
statetype state, nextstate;

// 1. 狀態暫存器
always_ff @(posedge clk, posedge reset)
  if (reset) state <= WT;
  else       state <= nextstate;

// 2. 次態邏輯
always_comb
  case (state)
    SNT: if (t) nextstate = WNT;
         else   nextstate = SNT;
    WNT: if (t) nextstate = WT;
         else   nextstate = SNT;
    WT:  if (t) nextstate = ST;
         else   nextstate = WNT;
    ST:  if (t) nextstate = ST;
         else   nextstate = WT;
    default:    nextstate = WT;
  endcase

// 3. 輸出邏輯（Moore：只看 state）
assign p = (state == WT) | (state == ST);
```

**三段式結構要記牢：狀態暫存器（`always_ff`）+ 次態邏輯（`always_comb` + `case`）
+ 輸出邏輯（`assign`）。**

**`typedef enum` 的價值**（p.159 邊欄）：
> "typedef enum defines a new *enumerated type* called statetype, which has an underlying
>  type of logic [1:0]. This new type enables the user to use enumerated values, in this
>  case SNT, WNT, WT, and ST, instead of binary encodings for the states (i.e., 00, 01,
>  10, and 11). **This increases readability and ease of coding.**"

**沒有明確指定編碼時，就是自然順序（SNT = 00、ST = 11）**（p.158）。

**這個 FSM 本身值得理解**（Fig. 4.16，p.158，第 13 章會用到）：
四個狀態 Strongly Not Taken → Weakly Not Taken → Weakly Taken → Strongly Taken，
**重置到 Weakly Taken，依實際分支結果上下移動。**
**用兩個 bit 而不是一個，是為了讓偶發的例外不會立刻翻轉預測。**

**"Logic synthesis automatically derives the Boolean expressions and maps them onto
appropriate gates, saving the engineer from that time-consuming and error-prone task."**
（p.159）——**不用自己推布林式，這就是用 HDL 的價值。**

### 進階 FSM：合併狀態暫存器與次態邏輯

中文解釋：Code Example 4.17（p.160）的除法器控制器示範更緊湊的寫法：
```systemverilog
always_ff @(posedge clk)
  if (reset) state <= Idle;
  else case (state)
    Idle: if (div) begin
            state <= Busy;
            step  <= 1;
          end
    Busy: begin
            if (step[5]) state <= Done;
            step <= step + 1;
          end
    Done: state <= Idle;
  endcase
```

**三個技巧：**
1. **狀態暫存器和次態邏輯合併在同一個 `always_ff`**
2. **計數器整合進 FSM**（`step`）
3. **`begin`/`end` 包住多個動作**（等同 C 的 `{}`，p.160 邊欄）

**關鍵的語意差異（p.160）：**
> "The next state logic is implicit inside the always_ff. If the state is not changed, it
>  keeps its old value. **This is only legal in an always_ff because keeping an old value
>  implies sequential logic rather than combinational logic.**"

**在 `always_ff` 裡「沒賦值就保持舊值」是合法的（因為本來就是時序邏輯），
但在 `always_comb` 裡這樣做就會產生 latch inference。**

**書上的警告（p.160）：**
> "**Avoid coding FSMs like this until you are experienced enough to be able to visualize
>  the hardware you are implying.**"

一個實用的微最佳化（p.160 邊欄）：
**檢查 `step[5]` 等同於檢查 `step == 6'd32`，但邏輯較少**（1-bit 比較 vs 6-bit 比較）。

### 4.2.3.3 記憶體：讀取時序是關鍵

> "A *read port* consists of an address input a and a read data output rd. Memory reads can
>  be either *asynchronous* or *synchronous*.... With asynchronous (also called
>  *combinational*) read, the address stabilizes at some point, and the read data becomes
>  valid after a propagation delay. With synchronous (also called *edge-triggered*) read,
>  the address stabilizes at least some setup time before the rising edge of the clock.
>  The read data arrives some clock-to-Q propagation delay after the clock edge.
>  **Memory writes are always synchronous** because they need a timing edge indicating
>  when to write."
> — p.161

中文解釋：**這是記憶體最重要的區分（Fig. 4.20，p.161）：**

| | 非同步讀（組合式） | 同步讀（邊緣觸發） |
| --- | --- | --- |
| 時序 | 位址穩定後經過傳播延遲，資料有效 | 位址要在時脈前 setup，資料在 clk-to-Q 後到 |
| 成本 | 較大、較慢 | **除了極小記憶體外，較小且較快** |

**寫入永遠是同步的**（需要時間邊緣指示何時寫）。

**本書從 7.2.1 節起用同步記憶體**（p.161）。

**三種埠（p.161）：**
- **read port**：位址 `a` + 讀資料 `rd`
- **write port**：位址 `a` + 寫資料 `wd` + 寫致能 `we` + 時脈 `clk`
- **read/write port**：和 write port 接線相同，但多一個讀資料輸出；
  **`we` 時寫入，永遠都在讀**

**命名規則（p.162）很值得記，因為 Wally 程式碼到處都是：**
> "This book names memories based on the number of ports and how many can be used for
>  read, write, or read/write.... For example, a basic single-ported RAM is called
>  ram1p1rw because it has one port (1p) which is read/write (1rw). A dual-ported RAM
>  with byte enables and one read and one write port is called ram2p1r1wb."

**讀法：`ram<埠數>p<讀寫組合>[b][e]`**，
`b` = byte enable、`e` = chip enable。
例：`ram1p1rw`、`ram2p1r1wb`、`ram1p1rwbe`、`rf3p2r1w`（暫存器檔案，3 埠 2 讀 1 寫）。

### ROM 與 RAM 的慣用寫法

**ROM（Code Example 4.18，p.162）：**
```systemverilog
module rom1p1r #(parameter M=3, N=16) (
  input  logic [M-1:0] a,
  output logic [N-1:0] rd);
  bit [N-1:0] mem[2**M];
  initial $readmemh("romfile.dat", mem);
  assign rd = mem[a];            // 非同步讀
endmodule
```
**三個要點：**
1. **`mem` 宣告為 `bit` 而非 `logic`**——未初始化項目預設為 0 而非 x（p.162，呼應 4.2.2.3）
2. **`initial $readmemh("file", mem)` 從檔案載入記憶體內容**
3. 同步讀版本改成 `always_ff @(posedge clk) rd <= mem[a];`（p.163）

`romfile.dat`（Code Example 4.19，p.163）就是每行一個十六進位值，
**行數不足時剩餘項目預設 0000。**

**FPGA 通常用同步 block RAM 建大型 ROM，所以預期同步讀**（p.163）。

（`**` 是指數運算子；**`$clog2` 很好用——算定址所需位元數，
32 字的記憶體需要 `$clog2(32) = 5` 個位址位元**，p.162 邊欄。）

**RAM（Code Example 4.20，p.164）：**
```systemverilog
module ram1p1rw_async #(parameter M = 6, N = 32) (
  input  logic         clk, we,
  input  logic [M-1:0] a,
  input  logic [N-1:0] wd,
  output logic [N-1:0] rd);
  bit [N-1:0] mem[2**M];
  assign rd = mem[a];               // 非同步讀
  always_ff @(posedge clk)
    if (we) mem[a] <= wd;           // 同步寫
endmodule
```

**SRAM 的物理知識（p.163）：**
- **6T SRAM bit cell**（Fig. 4.22）：寫入時 bitline 和其互補線驅動相反值，
  wordline 脈衝壓過交叉耦合反相器；讀取時兩條 bitline 先預充電為高，
  再脈衝 wordline 把其中一條拉低
- **需要預充電和感測放大的週邊電路 + 解碼器 → 所以 SRAM 陣列通常是元件庫元件**
- **因為要用時脈來排序預充電和感測，所以 SRAM 是同步讀**
- 極小的記憶體用 flip-flop 或 latch 實作（週邊電路開銷太大時），**這種通常是組合式讀**

### Byte enable 與 chip enable

> "Systems often need to write only some of the bytes within a memory word.... A brute
>  force solution is to read the entire word, modify certain bytes using multiplexers, and
>  write the word back. This may take an extra clock cycle. If a memory with a per-byte
>  write enable is available, a more efficient solution is to only write the necessary
>  bytes."
> — p.164

中文解釋：Code Example 4.21（p.165）：
```systemverilog
input logic [N/8-1:0] we;        // 每個 byte 一個 write enable
genvar i;
always_ff @(posedge clk) rd <= mem[a];
for (i = 0; i < N/8; i++)        // generate loop
  always_ff @(posedge clk)
    if (we[i]) mem[a][i*8 +: 8] <= wd[i*8 +: 8];
```

**兩個新語法（p.165）：**
1. **`for` 迴圈是 generate loop**——**產生多份硬體**（4.2.5.4 節詳述），
   不是「執行迴圈」
2. **`+:` 是 indexed part-select（索引式部分選取）**：
   `wd[i*8 +: 8]` 表示**從 `i*8` 開始的 8 個位元**。
   `i = 2` 時選 `wd[23:16]`。等同於 `wd[i*8+7 : i*8]`，
   **但 SystemVerilog 合成偏好索引式寫法。**

**Chip enable（Code Example 4.22，p.166）：**
```systemverilog
always_ff @(posedge clk)
  if (ce) rd <= mem[a];
for (i = 0; i < N/8; i++)
  always_ff @(posedge clk)
    if (ce & we[i]) mem[a][i*8 +: 8] <= wd[i*8 +: 8];
```
**`ce` 停用時 RAM 忽略所有輸入並保持最後的 `rd`，用來省電**（p.165）。

### 多埠記憶體與暫存器檔案

中文解釋：三個慣用寫法（p.166–167，符號見 Fig. 4.24）：

**（1）`ram2p1r1w`：一讀一寫（Code Example 4.23）**
```systemverilog
always_ff @(posedge clk) begin
  rd1 <= mem[a1];                  // port 1 讀
  if (we2) mem[a2] <= wd2;         // port 2 寫
end
```
**埠編號附加在每個訊號上**：port 1 是讀埠（`a1`, `rd1`），port 2 是寫埠（`a2`, `wd2`, `we2`）。

**（2）`ram2p2rw`：兩個讀寫埠（Code Example 4.24）**

**（3）`rf3p2r1w`：暫存器檔案，兩個非同步讀 + 一個同步寫（Code Example 4.25）**
```systemverilog
logic [N-1:0] mem[2**M];   // ← 注意用 logic 不是 bit
assign rd1 = mem[a1];       // 非同步讀
assign rd2 = mem[a2];
always_ff @(posedge clk)
  if (we3) mem[a3] <= wd3;  // 同步寫
```
**這裡刻意用 `logic` 而非 `bit`**（p.166）：
> "This example uses logic rather than bit, so a simulation can detect bad programs that
>  use uninitialized registers."

**取捨很清楚：RAM 用 `bit` 避免 x 汙染；暫存器檔案用 `logic` 好抓「讀到未初始化暫存器」的 bug。**
（呼應 2.7 節的暫存器檔案，也呼應 4.2.3.1 的 reset 討論。）

### 記憶體元件庫的現實限制

> "ASIC vendor memory libraries vary widely in richness and configurability. Whereas a
>  basic memory library has only single-ported RAMs, a better library may have RAMs with
>  one read and one write port. For high speed, RAM arrays generally can't be larger than
>  about 128 rows × 256 bits. However, larger RAMs can be constructed from multiple
>  subarrays. Smaller memories are less area efficient because the decoder and column
>  circuitry overhead is a greater proportion of the total area."
> — p.167

中文解釋：**實務限制，設計時要知道：**
- **高速 RAM 陣列大約不能超過 128 列 × 256 bit**；更大的要用多個子陣列組成
- **太小的記憶體面積效率差**（解碼器和欄電路的開銷佔比太高）
- **基本元件庫只有單埠 RAM**

**三種記憶體的密度階梯（p.168）——這組數字很值得記：**
> "Note that SRAM is about **10 times denser per bit than flop-based memory**, and dynamic
>  RAM (DRAM) is about **10 times denser than SRAM**."

**flop < SRAM（×10）< DRAM（×100）**

**DRAM 的特性（p.168）：**
- **1T1C**（一顆電晶體 + 一個電容，Fig. 4.25）
- 需要複雜週邊電路，**必須週期性讀取並更新（refresh）**，否則電容漏電
- **每 bit 成本比 SRAM 便宜一個數量級以上**，但**延遲較長、頻寬低很多**
- **需要控制器管理 refresh 和高速晶片外介面**——
  **"A double data rate (DDR) DRAM controller is tricky to design and would be the subject
  of its own textbook; most design teams purchase memory controllers as prevalidated IP
  blocks."**（呼應 4.1.3 節的 reuse）

**ASIC 中的 RAM 慣用寫法會被合成成「基於 flip-flop 的記憶體」**（p.168 邊欄）——
**要用真正的 SRAM 必須明確實例化特定的 SRAM 巨集（第 6.5.3 節）。
Wally 目標為 FPGA 時，RAM 慣用寫法會盡可能映射到 block RAM（第 23 章）。**

### 4.2.4 其他語法：數字

> "The format for declaring *integer literal constants* (numbers) is N'Bvalue, where N is
>  the size in bits and B is a letter indicating the base, with b for binary, d for
>  decimal, h for hexadecimal, and, less commonly used, o for octal. If the base is
>  omitted, it defaults to decimal. **Omitting the size leads to subtle gotchas and should
>  generally be avoided** [Sutherland06]."
> — p.168

中文解釋：**Table 4.2（p.169）的例子：**

| Number | Bits | Base | Decimal | Stored |
| --- | --- | --- | --- | --- |
| `3'b101` | 3 | 2 | 5 | 101 |
| `8'b1010_1011` | 8 | 2 | 171 | 10101011 |
| `8'b11` | 8 | 2 | 3 | **00000011**（前面補 0） |
| `3'd6` | 3 | 10 | 6 | 110 |
| `8'hAB` | 8 | 16 | 171 | 10101011 |

**一定要寫位元寬度。** 底線被忽略，用來分隔長數字。

**唯一的例外（p.168）：填滿重複值時**
```systemverilog
assign data = '1;   // 全 1
assign data = '0;   // 全 0
assign data = 'z;   // 全 z
assign data = 'x;   // 全 x
```
**"This syntax is particularly convenient when the bit size is parameterized."**

### Bit swizzling（位元操弄）

> "Bit swizzling is the process of selecting, replicating, and concatenating signals and
>  constants to form new signals. The {} operator concatenates bits. To replicate bits,
>  use curly brackets around the number of times to replicate the bit; for example,
>  {5{a[2]}} replicates bit 2 of signal a, a[2], five times."
> — p.169

中文解釋：**兩個工具：`{}` 串接、`{N{x}}` 複製。**
Code Example 4.26（p.169）的實用範例：
```systemverilog
// 依 s 產生全 0 或全 1 的 64-bit 匯流排
assign s64 = {64{s}};

// 串接兩個 32-bit 成 64-bit
assign entire = {upper, lower};

// 混合常數與各段訊號
assign y = {{2{a[2]}}, b, a[1:0], 3'b101};

// 符號延伸與零延伸（呼應 2.2 節！）
assign csignext = {{4{c[3]}}, c};    // 複製符號位元
assign czeroext = {4'b0, c};

// 一次取得和與進位輸出
assign {cout, sum} = a + b;
```
**最後那行很實用**：`{cout, sum}` 讓加法的進位自然落到高位。

### 一位元閘控多位元

中文解釋：Code Example 4.27（p.170）——**兩種寫法，同樣的硬體：**
```systemverilog
assign y1 = reset ? '0 : a;      // 條件運算子
assign y2 = {N{~reset}} & a;     // bit swizzling
```
**書上偏好條件運算子（較簡潔），但提醒（p.170）：**
> "it is important to remember that it reduces to N AND gates rather than an N-bit 2:1
>  multiplexer."

**看起來像多工器，實際上只是 N 個 AND 閘**（Fig. 4.26，p.170）——
**這正是「要能看見隱含的硬體」的例子。**

### Delay：只在 testbench 用

> "Delays are necessary in testbenches to toggle signals, such as clocks, in the desired
>  sequence.... **Delays are ignored during synthesis** because the delay of a circuit
>  depends on its physical implementation and varies with voltage, temperature, and
>  manufacturing variations."
> — p.170

> "Delays are not necessary outside of testbenches. Some logic simulators, including
>  Verilator, are significantly faster when all signals toggle on the same clock edge. The
>  industry has mostly converged on a coding style with no # delays outside of testbenches,
>  and Wally follows this style."
> — p.171

中文解釋：**`#` 延遲只在 testbench 用，合成時被忽略。**
**設計碼裡不要有 `#`**——Verilator 等模擬器在所有訊號同時變化時快很多。

### Port connection：四種寫法

中文解釋：Code Example 4.29（p.171）示範四種接埠方式：
```systemverilog
// 1. ordered list（按順序）
flopr #(1) f0(clk, reset, x[0], y[0]);

// 2. connected by name（按名稱）
flopr #(1) f1(.clk(clk), .reset(reset), .d(x[1]), .q(y[1]));

// 3. implicit port connections（隱含，名稱相同時只寫一次）
flopr #(1) f2(.clk, .reset, .d(x[2]), .q(y[2]));

// 4. .* （自動連接所有同名埠）
flopr #(1) f3(.d(x[3]), .q(y[3]), .*);
```

**四種的取捨（p.171）：**
- **按順序**：簡潔，但**難讀**（要同時看宣告和實例化），
  而且**別人重排宣告順序時會產生微妙的 bug**
- **按名稱**：解決上述問題，但**要打很多字**
- **隱含（`.name`）**：名稱相同時只寫一次，**兼顧兩者**
- **`.*`**：最短，但**最難追蹤訊號怎麼在階層間傳遞**

**Wally 的風格（p.171 邊欄）：**
> "For brevity, we prefer ordered lists for simple modules such as flip-flops and muxes.
>  We connect by name with implicit port connections for more complex modules. We find .*
>  makes code difficult to read because it is harder to trace how signals propagate through
>  the module hierarchy, so we generally avoid it. However, .* can be helpful in a
>  testbench or top-level module where signals are all connected by name, but the large
>  number of names are tedious to type."

**簡單模組（正反器、多工器）用順序；複雜模組用隱含名稱；避免 `.*`。**

**未使用的輸出可以省略或留空**：`.outsigname()`（p.172）。

### 前處理器：`` `define `` 與 `` `include ``

中文解釋：**和 C 的 `#define`、`#include` 類似，但用反引號（`` ` ``）。**

```systemverilog
// config.vh（Code Example 4.30，p.172）

```

> "Macro expressions should have parentheses around them to avoid order-of-operations
>  issues when substituted into code."

>  macro is `defined in more than one place with different values, its behavior can be

**同一個巨集在多處以不同值定義，行為是不確定的。**
（這正是 4.2.5.6 節要改用 parameter struct 的原因。）

`` `include "config.vh" `` 插入整個檔案，**標頭檔慣例副檔名 `.vh` 或 `.svh`**。

中文解釋：

### 4.2.5 可組態硬體（Wally 的核心機制）

> "A complex SoC is usually configurable to support different needs.... **Wally takes such
>  configuration to an extreme, making almost everything configurable, including XLEN
>  (RV32 or RV64) and the supported extensions. This way, one code base can be used to
>  support many configurations, from RV32E to RV64GC.**"
> — p.173

中文解釋：**這節是看懂 Wally 程式碼的關鍵。** 四種可組態手段（p.173）：
**編譯期常數、有條件地停用未用訊號、設定訊號寬度、有條件實例化或產生多份硬體。**

### 停用訊號

```systemverilog
// Code Example 4.32, p.173
`include "config.vh"
assign WriteMSTATUSM = CSRMWriteM & (CSRAdrM == MSTATUSH) & (`XLEN == 32);
```
**XLEN = 64 時 `` `XLEN == 32 `` 是 0，整條訊號被綁為 0，
連帶相關邏輯都會被合成工具最佳化掉**（因為 `mstatush` 暫存器在該組態不存在）。

**Wally 的風格選擇（p.174 邊欄）值得注意：**
> "Verilog has an `ifdef compiler directive to conditionally compile code. Unused signals
>  could be conditionally eliminated with `ifdef rather than just set to 0. However, **we
>  find `ifdef clutters the code excessively and complicates simulation because signals
>  will exist in certain configurations and vanish in others. We prefer driving unused
>  signals to 0 and allowing logic synthesis to optimize them away.**"

**用「綁 0 讓合成器最佳化掉」而不是 `` `ifdef ``，因為訊號存在與否會讓模擬變複雜。**

### 可組態寬度的常數

> "When a signal width is parameterized, the width of its value must be adjusted to match.
>  Unfortunately, SystemVerilog does not accept expressions in bit widths;
>  (`XLEN-1)'b0 is not recognized."
> — p.174

中文解釋：**這是個實際會踩到的語法限制。** 解法是用 bit swizzling（p.174）：
```systemverilog
// 依 s 產生 XLEN-bit 全 0 或全 1
assign sx = {`XLEN{s}};              // 或 assign sx = s ? '1 : '0;

// 把 Instr[31:20] 符號延伸到 XLEN 位元
assign extend = {{(`XLEN-12){Instr[31]}}, Instr[31:20]};

// LT 放最低位，上面補 0
assign SLT = {{(`XLEN-1){1'b0}}, LT};
```
**（`'0`、`'1`、`'x`、`'z` 會填滿目的地的每個位元，所以也常用。
邊欄提醒：數字 0 永遠會填滿所有位元，可以安全地取代 `'0`。**，p.174 邊欄）

### 條件產生（Conditional generate）

> "Conditional generate statements allow hardware to be created based on a condition....
>  The condition must be known at compile time because hardware is either generated or not
>  generated; **it can't wink in and out of existence based on the value of a changing
>  signal.**"
> — p.174

中文解釋：Code Example 4.33（p.175）——**Wally 怎麼有條件地放進乘除單元：**
```systemverilog
logic [`XLEN-1:0] MulDivResultW;
logic             DivBusyE;

if (`M_SUPPORTED) begin: mdugen
  mdu mdu(.clk, .reset, .ForwardedSrcAE, ..., .FlushW);
end else begin  // No M instructions supported
  assign MulDivResultW = 0;
  assign DivBusyE = 0;
end
```

**四個要點：**
1. **條件必須在編譯期已知**（硬體要嘛存在要嘛不存在）
2. **`else` 分支把訊號綁 0**，避免浮接，合成時不產生硬體
3. **給 generate 一個名字（`begin: mdugen`）是好習慣**——
   **它在模擬中產生一層階層**：`top.mdugen.mdu`；沒命名的話模擬器會自動命名為
   `top.genblk0.mdu`（p.174）
4. **`generate`/`endgenerate` 關鍵字是選配的**，Wally 省略它們
   （p.175 邊欄：**"We omit them because brevity is the soul of wit."**）

### Generate loop（產生迴圈）

> "A *generate loop* creates multiple pieces of hardware based on a loop variable."
> — p.175

中文解釋：Code Example 4.34（p.175）的溫度計碼優先權電路：
```systemverilog
module prioritythermometer #(parameter N = 8) (
  input  logic [N-1:0] a,
  output logic [N-1:0] y);
  genvar i;
  assign y[0] = ~a[0];
  for (i = 1; i < N; i++) begin: therm
    assign y[i] = y[i-1] & ~a[i];
  end
endmodule
```

**`genvar` 是關鍵**（p.175）：
> "The loop index i is declared as a genvar, which is **not a physical signal in the
>  circuit but rather used to count the hardware being generated.**"

**`genvar` 不是電路裡的訊號，只是「產生硬體時的計數器」。**
（這正是「HDL 不是程式」的最好例子：這個 `for` 不會「執行」，它「展開」。）

**最有價值的一段（p.175）：**
> "The generate loop implies a chain of N-1 AND gates and N inverters, as shown in
>  Fig. 4.27(a). ... **Most synthesis tools, particularly Synopsys Design Compiler, are
>  smart enough to recognize this priority circuit and optimize it to a tree structure
>  rather than a ripple structure when speed matters**, as shown in Fig. 4.27(b), thus
>  reducing the delay from N-1 to log₂N AND gates along the critical path."

**你寫的是鏈狀結構（延遲 N-1），合成工具會自動轉成樹狀（延遲 log₂N）。**
**這又是 4.1 節「工具會幫你挑架構」的實例。**
Fig. 4.27（p.176）並排畫出漣波式和樹狀兩種實作。

### 模組陣列

> "To instantiate identical modules, SystemVerilog's *array of instances* notation is more
>  succinct than a generate loop."
> — p.176

中文解釋：Code Example 4.35（p.177）的 TLB RAM 是很好的範例：
```systemverilog
tlbramline #(`PPN_BITS+10) tlbramline[TLB_ENTRIES-1:0]
  (.clk, .reset, .re(Matches), .we(WriteEnables),
   .d(PTE[`PPN_BITS+9:0]), .q(RamRead), .PTE_G(PTE_Gs));
```

**SystemVerilog 的自動連接規則很直覺（p.176）：**
> "SystemVerilog connects signals to arrays as you would hope; for example, when the
>  Matches signal (of width TLB_ENTRIES) is connected to the one-bit tlbramline array re
>  port, **each instance of the array receives the corresponding bit of Matches.**
>  The q outputs of the tlbramline array are `PPN_BITS+10 bits wide and are bundled
>  together into the RamRead array."

**一位元的埠接到 N 位元訊號 → 每個實例拿對應的那一位元；
N 位元的埠接到 N 個實例 → 自動捆成陣列。**

**這個例子還示範了另一個重要模式：distributed AND-OR mux（分散式 AND-OR 多工器）**
（p.176）：
> "Unlike the ram1p1rw from Code Example 4.20 that takes a binary address and uses array
>  notation rd <= mem[a] to read from that address, **the tlbram reads all entries and
>  zeroes out the entries that don't match.** Specifically, tlbram takes a one-hot Matches
>  input that indicates which entry to read. Each tlbramline ANDs its Match signal with the
>  line to produce RamRead, which is 0 when its Match signal is 0. The or_rows module in
>  tlbram then performs a bit-wise OR on the RamRead signals."

**「全部讀出來，不匹配的清成 0，再全部 OR 起來」——
這是 CAM（內容定址記憶體）的基本結構**，
第 10 章的 cache 讀取也用同一個模式。

`or_rows` 模組（p.177）自己也用了遞迴式的 generate：
```systemverilog
if(ROWS == 1) assign y = a[0];
else begin
  logic [COLS-1:0] mid[ROWS-1:1];
  assign mid[1] = a[0] | a[1];
  for (row = 2; row < ROWS; row++)
    assign mid[row] = mid[row-1] | a[row];
  assign y = mid[ROWS-1];
end
```

### 4.2.5.6 Parameter struct：Wally 真正用的組態方式

> "`define is the simplest way to configure code. However, it does not scale well when a
>  piece of code is reused in different configurations. For example, consider building a
>  chip with five Wally cores, four of which are rv64gc application processors and one that
>  is an rv32e microcontroller for power and clock management. The different cores have
>  identical Verilog but use different config.vh files. **When the second config file is
>  read, it overwrites macros from the first one, leading to unpredictable behavior.**"
> — p.178

中文解釋：**這是 `` `define `` 方式的致命缺陷：巨集是全域的，同一顆晶片上不能有兩種組態。**

**解法：改用 Verilog 的 parameter，由頂層模組往下傳。**
但參數可能有**數十到數百個**，每個模組都列出來太麻煩——
**所以用 struct 一次傳一包。**

**完整機制分五個檔案（p.178–181）：**

**（1）`src/cvw.sv`：定義 package 和 struct（Code Example 4.36）**
```systemverilog
package cvw;
typedef struct packed {
  int   XLEN;         // 機器寬度（32 或 64）
  int   MISA;         // Machine Instruction Set Architecture
  ...
  logic M_SUPPORTED;  // 是否支援乘除擴充
} cvw_t;
endpackage
```
**`packed` 表示它是連續的位元欄位**（`int` 各 32 bit、`logic` 1 bit，
所以圖示的部分是 65 bit）。

**（2）`config/rv64gc/config.vh`：該組態專屬的參數（Code Example 4.37）**
```systemverilog
localparam XLEN = 32'd64;
localparam MISA = (32'h00000104 | 1<<5 | 1<<3 | 1<<18 | 1<<20 | 1<<12 | 1<<0);
`include "config-shared.vh"
```
**`localparam` 宣告具名常數，可以依賴其他參數。**

**（3）`config/shared/config-shared.vh`：由組態衍生的參數（Code Example 4.38）**
```systemverilog
localparam M_SUPPORTED = ((MISA >> 12) % 2 == 1);
```
**從 MISA 的第 12 個 bit 判斷是否支援 M 擴充**（呼應 2.5 節的 `misa` CSR）。

**（4）`config/shared/parameter-defs.vh`：初始化 struct（Code Example 4.40）**
```systemverilog
localparam cvw_t P = '{
  XLEN :        XLEN,
  MISA :        MISA,
  ...
  M_SUPPORTED : M_SUPPORTED
};
```
**`P` 就是 Parameters 的縮寫。**

**（5）各模組宣告接收 P（Code Example 4.41、4.42）**
```systemverilog
module wallypipelinedcore import cvw::*; #(parameter cvw_t P) (
  input logic clk, reset, ...);
  logic [P.XLEN-1:0] MDUResultW;       // ← 用 P.XLEN 而不是 `XLEN
  ieu #(P) ieu(.clk, .reset, ...);     // ← 參數往下傳
  if (P.M_SUPPORTED) begin:mdu
    mdu #(P) mdu(.clk, .reset, ..., MDUResultW);
  end
endmodule
```

**三個要記住的寫法：**
1. **`import cvw::*; #(parameter cvw_t P)` 加在模組宣告行**
2. **用 `P.XLEN` 而非 `` `XLEN ``**
3. **實例化時用 `#(P)` 把整包參數往下傳**

**Testbench 負責初始化（Code Example 4.43，p.181）：**
```systemverilog
`include "config.vh"
import cvw::*;
module testbench;
  `include "parameter-defs.vh"
  wallypipelinedsoc #(P) dut(.clk, .reset, ...);
endmodule
```

**多核異質 SoC 的做法（p.181）：**
> "In an SoC containing multiple different cores, replace parameter_defs.vh with files
>  defining different parameters for each core."

**這就解決了開頭那個問題：五個核心、兩種組態。**

（合成時用 **wrapper** 載入所需組態，第 6.3 節。）

## 名詞表

| 名詞 | 意思 |
| --- | --- |
| Structural / behavioral | 結構描述（模組如何連接）/ 行為描述（做什麼） |
| Synchronous sequential discipline | 同步時序規範：唯一的時序元件是邊緣觸發正反器或記憶體 |
| Instantiate vs call | 實例化（永久存在於設計中）vs 函式呼叫（只在呼叫期間存在） |
| Bitwise / reduction | 逐位元運算（N→N）/ 歸約運算（N→1，如 `&a`） |
| `always_comb` | 組合邏輯區塊，自動推導 sensitivity list 並在出錯時警告 |
| **Latch inference** | **閂鎖推論。`always_comb` 中有路徑未賦值時意外產生 latch——經典陷阱** |
| `casez` | 允許輸入含 don't care（`?`）的 case |
| x / z | 未知（無驅動、衝突、未初始化）/ 浮接（高阻抗） |
| `bit` vs `logic` | `bit` 只有 0/1（x,z 映射為 0），**佔一半模擬記憶體**；`logic` 有四態 |
| Tristate / contention | 三態匯流排 / 多個驅動源衝突導致 x。**晶片內部應避免，只用於 I/O 接腳** |
| **Blocking (`=`) / nonblocking (`<=`)** | **組合邏輯用 `=`；時序邏輯用 `<=`（捕捉並行行為）** |
| 非同步 / 同步 reset | reset 在 sensitivity list 裡 / 不在。FPGA 偏好非同步，ASIC 偏好同步 |
| `always_latch` | 刻意宣告 latch（對比意外的 latch inference） |
| Moore / Mealy FSM | 輸出只看狀態 / 輸出也看輸入 |
| `typedef enum` | 列舉型別，用名字取代二進位編碼，提升可讀性 |
| 非同步 / 同步記憶體讀 | 組合式（位址穩定後延遲）/ 邊緣觸發（時脈後 clk-to-Q）。**寫入永遠同步** |
| `ram1p1rw` 等命名 | `ram<埠數>p<讀寫組合>[b][e]`，b = byte enable、e = chip enable |
| `$readmemh` | 從檔案載入記憶體內容 |
| `$clog2` | ceiling of log₂，計算定址所需位元數 |
| `+:` | Indexed part-select，`wd[i*8 +: 8]` = 從 i*8 開始的 8 個位元 |
| 密度階梯 | flop < SRAM（約 ×10）< DRAM（約 ×100） |
| Bit swizzling | `{}` 串接、`{N{x}}` 複製，用於符號/零延伸與組態寬度常數 |
| `genvar` | generate loop 的索引，**不是電路訊號**，只用於計數產生的硬體 |
| Array of instances | 模組陣列，比 generate loop 更簡潔；一位元埠自動對應各實例 |
| Distributed AND-OR mux | 全部讀出、不匹配清 0、再 OR 起來。CAM 與 cache 讀取的基本結構 |
| `parameter struct` (`cvw_t P`) | **Wally 的組態機制**：一包參數由頂層往下傳，取代全域巨集 |

## 所以呢

**這節是「硬體 → HDL 慣用寫法」的對照表，也是讀 Wally 程式碼的字典。**

四個最容易出錯、最該記牢的點：
1. **`always_ff` 用 `<=`、`always_comb` 用 `=`**——寫錯會合成出完全不同的電路。
2. **`always_comb` 裡每條路徑都要賦值（或加 `default`）**，否則 latch inference。
3. **`genvar` 和 generate 是「展開硬體」，不是「執行迴圈」**——
   這是 HDL 和程式語言最根本的差別。
4. **Wally 用 `parameter struct P` 傳組態**，程式碼裡看到 `P.XLEN`、`#(P)` 就是這個機制。

還有一個貫穿全節的觀念：**合成工具比你想的聰明**——
優先權鏈會被轉成樹、綁 0 的邏輯會被消掉。
但前提是**你寫的是它認得的慣用寫法**。
