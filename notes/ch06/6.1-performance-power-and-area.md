# 6.1 Performance, Power, and Area (PPA)

> 原書 p.249–257（Chapter 6: Logic Synthesis）
> 含章首導論、6.1.1 Performance（6.1.1.1 Timing Constraints、6.1.1.2 Static Timing Analysis）、
> 6.1.2 Power、6.1.3 Area

## 這節在講什麼

**PPA 是評估任何硬體設計的三個指標，也是整章的主軸。**

章首先交代邏輯合成的流程（RTL → 閘級網表），然後三個子節各講一個指標：

1. **Performance（效能）= 時脈週期**
   核心是 **setup / hold 時間約束**和 **static timing analysis（STA）**——
   **這是整節最重要的部分，slack 的概念後面會一直用。**
2. **Power（功耗）= 瓦數**
   核心公式 **P_dyn = αCV²f**，以及 dynamic vs leakage 的區分。
3. **Area（面積）= 晶片空間 = 成本**

**三者互相取捨：效能通常要用功耗和面積換。**

## 關鍵點

### 邏輯合成在做什麼

> "Logic synthesis converts register transfer level (RTL) to hardware by mapping the RTL
>  (Verilog or VHDL) onto a library of cells. Synthesis attempts to minimize area and power
>  while meeting timing constraints. Thus, the key metrics are performance, power, and area
>  (PPA)."
> — p.249

中文解釋：**合成的目標函數要看清楚：
「在滿足時序約束的前提下，把面積和功耗最小化」。**

**時序是約束（constraint），面積和功耗是目標（objective）。**
這個不對稱很重要——工具不會為了省面積而犧牲時脈，
**它會先滿足時脈，剩下的才拿去省面積。**

### 合成的輸入：三樣東西

> "Logic synthesis begins by reading RTL files, constraints, standard cell libraries, and a
>  technology file. **Constraints include the floorplan (including chip area and blockages),
>  switching activity factors, target clock frequency, clock skew, and characteristics of input
>  and output pins (including delays, drivers, or loads).**"
> — p.249

中文解釋：**輸入清單很值得記，因為每一項都會影響結果：**

| 輸入 | 內容 |
| --- | --- |
| **RTL 檔案** | Verilog 或 VHDL |
| **約束（constraints）** | floorplan（晶片面積與禁區）、**切換活動因子**、**目標時脈頻率**、**時脈偏斜**、輸入輸出腳位特性 |
| **標準元件庫** | 見下 |
| **技術檔案** | 設計規則：金屬層數、金屬與 via 的寬度和間距 |

**「切換活動因子」出現在約束裡很有意思**——
它不影響功能，只影響功耗估算（見 6.1.2 節的 α）。

**標準元件庫的內容（p.249）：**
> "The *standard cell library* contains gates such as inverters, NAND2-NAND4 (2- to 4-input NAND
>  gates), NOR2-NOR4 (2- to 4-input NOR gates), compound AND-OR-Invert gates, and flip-flops.
>  **A robust cell library has multiple drive strengths for each cell to efficiently drive
>  different loads while optimizing PPA.**"

**「每個元件有多種驅動強度」是關鍵**——這是合成工具最主要的最佳化手段之一。

**還需要兩個額外的庫（p.249）：記憶體庫和 I/O pad cell 庫。**

**每個 cell 的特徵化（p.249）：**
> "Each cell in the library is characterized with delay and power for different loads under
>  different voltage and temperature operating conditions. The cell also contains physical views
>  suitable for placement and routing to build a chip."

**同一個元件在不同負載、電壓、溫度下有不同的延遲和功耗**——
這就是 6.2.1.1 節 PVT corner 的由來。

### 合成的四個步驟

> "Next, the synthesis tool **analyzes** the design to find syntax errors and translates it into
>  an HDL-independent intermediate format. Then it **elaborates** the design to map it onto a
>  technology-independent generic library including registers and arithmetic operations. It
>  **compiles** the design to map it onto the actual cell library and optimizes the choice of
>  cells attempting to meet timing while minimizing chip area. The compiler may **flatten** the
>  design to optimize better across module boundaries, **but this produces a giant blob of gates
>  that is difficult for the designer to understand or improve.**"
> — p.249

中文解釋：**四個步驟，每一步抽象層次降一級：**

| 步驟 | 做什麼 | 結果的抽象層次 |
| --- | --- | --- |
| **analyze** | 檢查語法，轉成與 HDL 無關的中間格式 | 語言無關 |
| **elaborate** | 映射到**技術無關的通用庫**（暫存器、算術運算） | 製程無關 |
| **compile** | **映射到實際的元件庫**，最佳化元件選擇 | 製程相關 |
| **flatten**（選配） | **打平模組邊界**以跨模組最佳化 | 沒有階層 |

**flatten 的取捨講得很直白：跨模組最佳化更好，
但結果是「一大坨閘，設計者難以理解或改進」。**
（呼應 4.3 節 Guideline 4.14：`.*` 也是類似的可讀性取捨。）

**physical synthesis（p.249）：**
> "A *physical synthesis* tool also places cells and estimates wire lengths **because wires
>  significantly affect timing.**"

**線長顯著影響時序**——這就是 2.8 節 Fig. 2.14 那張布局圖的由來。

**輸出（p.249–250）：**
> "The synthesis tool produces a mapped *netlist* that specifies the cells and their connections;
>  timing, area, and power reports; and possibly placement information. **After synthesis, a
>  *place and route* (P&R) tool performs detailed placement and routing to produce a
>  manufacturable chip layout.**"

**合成產出 netlist（網表），P&R 產出可製造的布局。**

**控制方式（p.250）：**
> "As with most other CAD (computer-aided design) tools, logic synthesis is controlled by a Tcl
>  (Tool Command Language) script that specifies files, constraints, and steps to perform."

**Tcl 腳本控制**（呼應 4.3.1.1 節邊欄：EDA 工具用 Tcl，所以大小寫敏感。Appendix D 講 Tcl）。

### 三個指標的定義

> "*Performance* is indicated by the clock period at which the system operates.... *Power* is
>  the number of watts drawn; it includes both *active power* while the system is running and
>  *leakage power* consumed when the clock is stopped.... *Area* is the chip space used by the
>  design, which also indicates the design cost."
> — p.250

中文解釋：**三個指標的商業意義（p.250），這段解釋了「為什麼要在乎」：**

| 指標 | 單位 | 為什麼重要 |
| --- | --- | --- |
| **Performance** | 時脈週期 | **PC 微處理器主要靠時脈行銷，小幅改進能帶來數十億美元營收** |
| **Power** | 瓦特 | **決定行動系統的電池大小與續航**；插電系統則決定**散熱成本與環境足跡** |
| **Area** | ASIC 用 μm²；FPGA 用邏輯元件與記憶體數量 | **等於設計成本**；決定能在有利潤的晶片上放多少功能 |

**"The performance generally trades off against power and area."**（p.250）
——**效能通常要用功耗和面積換。這是整章的核心取捨。**

**PPA 受三件事影響（p.250）：RTL 設計、製程技術與元件庫（6.2 節）、邏輯合成工具。**

### 時序約束：setup 與 hold

> "On the rising edge of the clock, each flip-flop's outputs may change. These new values
>  propagate through cones of logic to reach the inputs to the next flip-flops. **The new values
>  must settle sometime before the next rising edge of the clock. This is called the *setup time
>  constraint*. If new values reach the next flip-flop too soon after the clock edge, they might
>  slip through and corrupt the result. This is called the *hold time constraint*.**"
> — p.250–251

中文解釋：**兩個約束的直覺要分清楚：**

| 約束 | 擔心什麼 | 白話 |
| --- | --- | --- |
| **Setup** | **訊號來得太晚** | 下一個時脈邊緣前來不及穩定 |
| **Hold** | **訊號來得太早** | 在前一個值被取樣前就變了，把結果弄髒 |

**「太晚」和「太早」都不行——這是同步設計的核心張力。**

### 四個延遲參數

中文解釋：Fig. 6.1（p.251）定義了四個參數，**這組是整章的基礎詞彙：**

**組合邏輯（Fig. 6.1a）：**
- **t_cd（contamination delay，汙染延遲）**：輸出**可能開始**改變的最短時間
- **t_pd（propagation delay，傳播延遲）**：輸出**確定穩定**的最長時間
- **兩者之間輸出是未知的**（圖上用交叉陰影表示）

**為什麼有最小和最大兩個值（p.251）：**
> "The contamination and propagation delays are the minimum and maximum values.... **They may
>  differ because of input patterns, rising or falling edges, operating conditions such as voltage
>  and temperature, manufacturing variation that affects transistor currents or capacitances, and
>  aging that degrades transistors over time.**"

**五個變異來源：輸入樣式、上升/下降緣、電壓與溫度、製造變異、老化。**

**正反器（Fig. 6.1b）：**
- **t_setup**：輸入必須在時脈上升緣**前**穩定多久
- **t_hold**：輸入必須在時脈上升緣**後**保持多久
- **t_ccq（contamination clock-to-q）**：輸出最早開始改變的時間
- **t_pcq（propagation clock-to-q）**：輸出確定穩定的時間

**書上的比喻很好（p.251）：**
> "Just as a camera needs the subject to be still when the shutter is pressed to prevent blurring,
>  **the flip-flop needs the input to be stable around the rising edge of the clock to be sampled
>  reliably.**"

**像拍照時被攝者要靜止一樣——setup 和 hold 就是「快門前後要靜止多久」。**

### 兩個約束方程式

> "T_c ≥ t_pcq + t_pd + t_setup"
> — Eq. (6.1), p.252

> "t_ccq + t_cd > t_hold"
> — Eq. (6.2), p.252

中文解釋：**兩個方程式的結構完全不同，這是關鍵：**

**Setup（Fig. 6.2，p.252）：** 路徑從暫存器 R1 出發，經組合邏輯，到 R2。
```
T_c ≥ t_pcq + t_pd + t_setup
     └最慢的路徑要能在一個週期內走完┘
```
**用的是最大延遲（t_pcq、t_pd）。**

**Hold（Fig. 6.3，p.252）：**
```
t_ccq + t_cd > t_hold
└最快的路徑也不能太快┘
```
**用的是最小延遲（t_ccq、t_cd），而且方程式裡沒有 T_c。**

**這個差異極其重要，書上明說（p.254）：**
> "**this analysis is independent of clock frequency.... Hold time failures are catastrophic
>  because they cause the chip to run unreliably at any speed; thus, these failures cannot be
>  fixed by simply changing the clock speed.**"

**Setup 失敗 → 降低時脈就能解決。
Hold 失敗 → 災難性的，任何速度都不能用，必須重做。**

**最難滿足的 hold 情況（p.254）：**
> "The hardest case to satisfy is back-to-back flip-flops with no logic between them (t_cd = 0).
>  **Synthesis sometimes must insert delay buffers to ensure hold time is satisfied.**
>  Alternatively, **FPGAs often prevent hold time problems by providing a flip-flop that is so
>  slow (big t_ccq) that the system is guaranteed to work, albeit slowly.**"

**兩種解法：插延遲緩衝器，或（FPGA 的做法）故意把正反器做得很慢。**

### Clock skew：時脈不會同時到達

> "In a real system, clocks do not all switch at exactly the same time. The switching time might
>  vary because of **systematic errors** (e.g., different length clock wires going to two
>  registers), **random manufacturing variation** (e.g., a faster clock buffer in one path than
>  another), and **environmental variation** (e.g., a voltage spike causing the clock buffers to
>  momentarily speed up, shortening a clock cycle). These effects are collectively called
>  *clock skew*."
> — p.252

> "T_c ≥ t_pcq + t_pd + t_setup + t_skew"
> — Eq. (6.3), p.253

> "t_ccq + t_cd > t_hold + t_skew"
> — Eq. (6.4), p.253

中文解釋：**三個 skew 來源：系統性誤差（線長不同）、隨機製造變異、環境變異。**

**關鍵觀察：skew 讓兩個約束都變難。**
- Setup：加在右邊（可用時間變少）
- Hold：加在右邊（要求變嚴）

**這是為什麼時脈分佈網路（clock tree）是晶片設計中最重要的結構之一。**

**量級（p.253）：**
> "Setup and hold times and clock skew on an SoC are all measured in picoseconds (10⁻¹² s).
>  Nevertheless, **they are vitally important to achieve multigigahertz operation.**"

（Fig. 6.4 和 6.5，p.253，是加上 skew 後的時序圖，
時脈邊緣用陰影線表示它可能落在的範圍。）

### Static timing analysis：slack 的概念

> "Synthesis performs *static timing analysis* (STA) to determine the worst-case timing by adding
>  up the propagation delays along each path between clocked elements, **which starts at the
>  rising edge of the clock (*startpoint*), considered time = 0, passes through the Q output of
>  the flip-flop, and propagates through a chain of combinational logic. The path must arrive at
>  the D input of the next flip-flop (*endpoint*) some setup time before the next rising edge of
>  the clock.**"
> — p.253

> "The *arrival time* is the time at which the endpoint settles (t_cq + t_pd), and the *required
>  time* is the clock period less the setup time (T_c − t_setup). **The *slack* is the difference
>  between the required time and the arrival time. If the slack is positive, the circuit operates
>  properly at the desired frequency. If it is negative, the circuit cannot achieve the desired
>  frequency.**"
> — p.253

中文解釋：**STA 的三個數字，一定要記住：**

```
arrival time  = t_cq + t_pd           （訊號實際何時到）
required time = T_c − t_setup          （訊號最晚何時該到）
slack         = required − arrival     （餘裕）
```

**slack 為正 = 過關；為負 = 不過。**

**"static"（靜態）的意思是它不需要模擬**——
直接把路徑上的延遲加起來算，所以能涵蓋所有路徑，不像模擬只能測有跑到的。
（呼應 5.3 節 lint 的靜態分析思路。）

**WNS 和 TNS（p.254）：**
> "The *worst negative slack* (WNS) is the most negative slack of all paths, or zero if none are
>  negative. The *total negative slack* (TNS) is the sum of all the negative slacks at each
>  endpoint."

| 指標 | 意義 | 用來判斷 |
| --- | --- | --- |
| **WNS** | 所有路徑中最負的 slack | **問題有多嚴重** |
| **TNS** | 所有負 slack 的總和 | **問題有多普遍** |

**兩個一起看才完整**：WNS = −50ps、TNS = −50ps 表示只有一條路徑有問題（好修）；
WNS = −50ps、TNS = −5000ps 表示有一百條路徑有問題（要改架構）。

### Critical path 與合成工具的最佳化手段

> "The *critical path* is the one with the WNS, limiting the clock period. The synthesis tool
>  strives to reduce this critical path to improve performance."
> — p.254

中文解釋：**合成工具的四個最佳化手段（p.254），這份清單很有啟發性：**

1. **選擇高驅動強度的元件**
   > "if a gate must drive a high fanout (e.g., a select signal driving a 64-bit multiplexer),
   >  synthesis can choose a cell with a high *drive strength* that is larger but faster at
   >  driving the heavy load."
   （呼應 2.2 節：fanout 大就慢。）

2. **預先計算兩種可能，最後才選**
   > "If one signal arrives late on the critical path, the synthesis tool might **precompute the
   >  output assuming the signal is 0 and again assuming it is 1, then select the output from
   >  these two possibilities when the late signal arrives.**"
   **這叫 speculation（推測），用面積換時間。**

3. **關鍵路徑用快的結構，非關鍵路徑用小的**
   > "whereas a critical path might use a fast prefix adder, a noncritical path might use a
   >  smaller, cheaper ripple carry adder. **Hence, critical paths tend to use faster structures
   >  that cost more area, and noncritical paths use the smallest implementations.**"

4. **選擇性地插入低臨界電壓元件**
   > "Some processes offer low threshold voltage (low-V_t) transistors with better speed but
   >  exponentially more leakage power. **Synthesis inserts low-V_t cells selectively on the
   >  critical paths.**"
   （呼應 1.1 節：降低 V_t 讓次臨界漏電呈指數上升。）

**一個重要的觀察（p.254）：**
> "**In a well-balanced system, many paths are nearly equally long, and there is no single outlier
>  that could be optimized to speed up the whole system.**"

**平衡良好的系統裡沒有單一的瓶頸可以優化。**
——這也意味著**好的設計很難再改快**，而爛設計反而有明顯的改進空間。

### 合成不過時怎麼辦：兩個角色的分工

> "If synthesis cannot meet the target clock period, **the *logic design engineer* may modify the
>  RTL, simplifying the critical path or moving logic between pipeline stages. The *physical
>  design engineer* may tweak the synthesis constraints, such as flattening the module hierarchy
>  to enable more optimizations, preplacing modules so that critical cells are near each other,
>  tuning the clock network, or enabling low-V_t cells.**"
> — p.254

中文解釋：**兩個角色的工具箱不同：**

| 角色 | 手段 |
| --- | --- |
| **邏輯設計工程師** | **改 RTL**：簡化關鍵路徑、**在 pipeline 級之間搬移邏輯** |
| **實體設計工程師** | **改約束**：打平階層、預先放置模組、調整時脈網路、啟用低 V_t 元件 |

**「在 pipeline 級之間搬移邏輯」是很常用的一招**——
把某一級太重的邏輯搬到較輕的鄰居那一級（呼應 2.7 節：時脈由最慢的一級決定）。

**都失敗的話（p.254）：**
> "If none of these efforts succeed, **the chip will still operate correctly but at a reduced
>  clock frequency.** Moreover, static timing analysis assumes worst-case environment and
>  manufacturing. **The chip will often run faster than analysis predicted.**"

**setup 不過只是慢一點，不是壞掉。**
而且 STA 假設最壞情況，**實際晶片通常跑得比分析預測的快。**
（邊欄，p.254：**這就是 PC 玩家能超頻的原因，尤其配好的散熱系統。**）

### 時序分析範例

中文解釋：Code Example 6.1 和 Fig. 6.6（p.255）的完整計算，值得跟一遍：

```systemverilog
module example (
  input  logic       clk,
  input  logic [3:0] a,
  output logic       q);
  logic [3:0] b;
  logic       y;
  flop #(4) f1(clk, a, b);
  assign y = &b;          // 4-input AND
  flop #(1) f2(clk, y, q);
endmodule
```

**參數：** t_cq = 0.32 ns、t_setup = 0.13 ns、NAND 延遲 0.06 ns、NOR 延遲 0.09 ns、T_c = 2.0 ns。
（4 輸入 AND 被合成成 2-input NAND + NOR，見 Fig. 6.6 電路圖。）

```
arrival time  = 0.32 + 0.06 + 0.09 = 0.47 ns
required time = 2.0 − 0.13         = 1.87 ns
slack         = 1.87 − 0.47        = 1.40 ns   ← 正的，過關
```

### 功耗：dynamic vs leakage

> "As digital circuits toggle between 0 and 1, they consume *dynamic* power to charge and
>  discharge capacitance on the nodes. **Even when they are idle, they draw some *leakage* power
>  because transistors never turn completely OFF.**"
> — p.255

中文解釋：**兩種功耗：切換時的動態功耗，和閒置時的漏電功耗。**

**推導鏈（p.255–256），每一步都要懂：**

```
P = E / T_c                    (6.5)   功率 = 每週期能量 / 週期
P = E f                        (6.6)   = 能量 × 頻率
E_dyn = C V_DD²                (6.7)   充放電一個電容的能量
P_dyn = E_dyn f = C V_DD² f    (6.8)
P_dyn = α C V_DD² f            (6.9)   加上活動因子
P_leak = I_leak V_DD           (6.10)
```

**(6.7) 的物理**（p.256）：
充電一個電容從 0 到 V_DD 所需能量**與電容成正比、與電壓成平方**。
**一半存在電容裡，一半在充電過程中以熱散失**；
電容從 V_DD 放電回 0 時，剩下那一半也散成熱。

**晶片上所有電晶體和導線都有電容，微米尺度結構約在 femtofarad 等級（1 fF = 10⁻¹⁵ F）。**

### 活動因子 α：一個很實用的直覺

> "In general, the dynamic power is proportional to the *activity factor* α, which measures the
>  number of times the signal rises and falls each cycle."
> — p.256

中文解釋：**α 的典型值，這組數字很值得記住：**

| 訊號類型 | α | 理由 |
| --- | --- | --- |
| **時脈** | **1** | 每週期升降一次 |
| 每週期只變一次的資料訊號 | **½** | 只有一半時間在切換 |
| **真正隨機的資料訊號** | **¼** | 一半機率升降，另一半保持舊值 |
| **一般資料訊號（經驗值）** | **0.1** | **20% 的週期會升或降** |

**書上的解釋很具體（p.256）：**
> "Most signals switch even less often; for example, **only one or a few bits of the program
>  counter change in a typical cycle, and the upper bits of an integer are often all 0s.**
>  Empirically, α = 0.1 is a reasonable estimate."

**PC 的低位元常變、高位元很少變；整數的高位元常常全是 0。**
**這就是「活動因子遠小於 1」的實際原因。**

**α 也叫 toggle rate（切換率）。**

**整體功耗的算法（p.256）：**
> "Dynamic power is computed for each component based on that component's activity factor and
>  capacitance. **The power of an entire block or chip is the sum of the power consumed by each
>  component.**"

### Leakage 的兩個來源，以及何時重要

> "Transistors that are supposed to be OFF actually draw some leakage current I_leak. **This
>  leakage is predominantly subthreshold leakage between the source and drain, but tiny
>  transistors also have some tunneling current through the gate** as electronics quantum
>  mechanically teleport across the ultrathin gate insulator."
> — p.256

中文解釋：**兩個來源和 1.1 節完全一致：次臨界漏電（主要）和閘極穿隧。**

**何時重要（p.257）——這段很實用：**
> "**When a chip is operating at a high frequency f, the dynamic power is usually at least an
>  order of magnitude greater than the leakage power, so leakage can be ignored. However, when
>  the chip is idle, it often stops the clock, so f = 0, and leakage accounts for all of the
>  power. Mobile devices that interact with a user spend most of their time waiting for the user,
>  and hence their standby battery life is determined by the leakage power.**"

**兩種情境完全不同：**

| 情境 | 主導的功耗 | 實務意義 |
| --- | --- | --- |
| **高頻運作** | **動態功耗（大一個數量級以上）** | 漏電可忽略 |
| **閒置（停時脈，f = 0）** | **全部是漏電** | **手機的待機續航由漏電決定** |

**「手機大部分時間在等使用者」——所以待機續航取決於漏電，不是動態功耗。**

### 能量與面積的關聯

> "Energy depends on the number and size of components, so it correlates well with area. For
>  example, **the Wally floating-point divide/square root unit consumes an average of 0.28 fJ/μm²/
>  cycle in the TSMC 28HPC+ (TSMC28) process under typical conditions. Hence, minimizing area is
>  a rough proxy for minimizing power.**"
> — p.257

中文解釋：**這是一個很實用的經驗法則：面積小 ≈ 功耗低。**

Wally 的 FPU 除法/平方根單元的實測值：**0.28 fJ/μm²/cycle**（TSMC28，典型條件）。
**有了這種「每平方微米每週期的能量」數字，就能從面積估功耗。**

### 現代 SoC 的其他省電手段

> "Modern SoCs use other knobs to optimize power [Keating07, Weste12].
>  - **Cell libraries with multiple drive sizes and threshold voltages** allow the designer to
>    trade dynamic or leakage power for speed on the critical path.
>  - **Clock gating and power gating** turn off dynamic and leakage power, respectively, of idle
>    subsystems.
>  - **Dynamic voltage and frequency scaling** reduce the supply voltage and clock frequency to
>    save power when a component does not need to operate at peak performance.
>  - **Adaptive voltage scaling** measures the real-time chip performance and adjusts the supply
>    voltage to reduce the power wasted by unnecessarily large guard bands for manufacturing and
>    environmental variations."
> — p.257

中文解釋：**四招，各針對不同的浪費：**

| 手段 | 對治什麼 | 機制 |
| --- | --- | --- |
| **多種驅動強度與臨界電壓** | 非關鍵路徑的浪費 | 在關鍵路徑用快的，其他用省電的 |
| **Clock gating / power gating** | **閒置子系統** | 分別關掉動態功耗 / 漏電功耗 |
| **DVFS**（動態電壓頻率調整） | **不需要峰值效能時** | 同時降低供應電壓和時脈（**因為 P ∝ CV²f，降電壓效益是平方的**） |
| **Adaptive voltage scaling** | **保護頻寬（guard band）的浪費** | 即時量測晶片效能，動態調整電壓 |

**DVFS 之所以有效，就是因為 (6.9) 式裡 V 是平方項**——
電壓降 20%，動態功耗降約 36%。

**（注意：2.8 節說過 Wally 目前不支援 clock gating。）**

### 面積：合成的取捨

> "Synthesis makes many design decisions trading performance against area. For example, whereas
>  a ripple carry adder is slow but small, a prefix adder is larger but faster. **Synopsys Design
>  Compiler provides *DesignWare* arithmetic components that automatically select a good
>  implementation based on timing constraints.**"
> — p.257

> "As another example, cell libraries contain flavors of cells with different *drive strengths*.
>  A cell with a larger drive strength has wider transistors that deliver more current and can
>  drive a given capacitive load faster. However, **the cell also takes more area and power and
>  presents a larger capacitive load on the previous stage.**"
> — p.257

中文解釋：**兩個層次的面積/效能取捨：**

1. **架構層次**：ripple carry（慢、小）vs prefix（快、大）。
   **DesignWare 會依時序約束自動選。**
   （呼應 4.1 節：「你寫 `+`，工具幫你選加法器架構」。）

2. **元件層次**：驅動強度大的元件電晶體較寬，電流大、驅動負載快，
   **但佔面積、耗功耗，而且對前一級呈現更大的電容負載。**

**第二點的最後那句很重要：加大驅動強度不是免費的**——
它把負擔推給前一級。這就是為什麼不能所有元件都用最大驅動強度。

| 名詞 | 意思 |
| --- | --- |
| **PPA** | Performance, Power, Area。三個關鍵指標 |
| Standard cell library | 標準元件庫。含反相器、NAND、NOR、複合閘、正反器，**每種有多個驅動強度** |
| analyze / elaborate / compile / flatten | 合成四步驟：語法檢查 / 映射到通用庫 / 映射到實際元件庫 / 打平階層 |
| Netlist | 網表。指定元件及其連接 |
| P&R | Place and route。詳細擺放與繞線，產出可製造的布局 |
| **t_cd / t_pd** | 汙染延遲（最短）/ 傳播延遲（最長） |
| **t_setup / t_hold** | 時脈邊緣前必須穩定的時間 / 邊緣後必須保持的時間 |
| **t_ccq / t_pcq** | clock-to-Q 的最短 / 最長延遲 |
| **Setup 約束** | T_c ≥ t_pcq + t_pd + t_setup + t_skew。**失敗只是變慢** |
| **Hold 約束** | t_ccq + t_cd > t_hold + t_skew。**與頻率無關，失敗是災難性的** |
| **Clock skew** | 時脈偏斜。系統性、隨機製造、環境三種來源；**讓兩個約束都變難** |
| **STA** | Static timing analysis。不需模擬，直接累加路徑延遲 |
| **arrival / required / slack** | t_cq + t_pd / T_c − t_setup / required − arrival。**slack 為負即不過** |
| **WNS / TNS** | 最差負 slack（問題多嚴重）/ 負 slack 總和（問題多普遍） |
| **Critical path** | 關鍵路徑。WNS 所在的路徑，限制時脈週期 |
| Drive strength | 驅動強度。電晶體較寬、驅動快，但佔面積並增加前一級負載 |
| low-V_t | 低臨界電壓元件。較快但漏電呈指數增加；選擇性用於關鍵路徑 |
| **α（activity factor / toggle rate）** | 活動因子。時脈 = 1、隨機資料 = ¼、**一般資料經驗值 0.1** |
| **P_dyn = αCV_DD²f** | 動態功耗公式。**V 是平方項，所以降電壓最有效** |
| P_leak = I_leak V_DD | 漏電功耗。**閒置時佔全部功耗，決定待機續航** |
| Clock gating / power gating | 關掉閒置子系統的動態功耗 / 漏電功耗 |
| **DVFS** | 動態電壓與頻率調整 |
| DesignWare | Synopsys 的算術元件庫，依時序約束自動選實作 |

## 所以呢

**PPA 是評估硬體的三個指標，而效能通常要用功耗和面積來換。**

四件最該帶走的事：

1. **STA 的三個數字**：`arrival = t_cq + t_pd`、`required = T_c − t_setup`、
   **`slack = required − arrival`**。負的就是不過。
   **WNS 看嚴重度、TNS 看普遍度。**

2. **Setup 和 Hold 的不對稱**：
   **setup 失敗降時脈就能救，hold 失敗是災難性的**（與頻率無關，任何速度都壞）。

3. **P_dyn = αCV²f**，其中 **α 一般資料訊號約 0.1**，**V 是平方項**
   （所以 DVFS 降電壓最有效）。
   **高頻時動態功耗主導，閒置時漏電決定待機續航。**

4. **面積是功耗的粗略代理**——Wally 的 FPU 實測 0.28 fJ/μm²/cycle。
