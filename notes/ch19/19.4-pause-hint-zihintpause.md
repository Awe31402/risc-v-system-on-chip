# 19.4 Pause Hint: Zihintpause

> 原書 p.779（Chapter 19: Other Extensions）

## 這節在講什麼

一頁的小節。自旋鎖（第 17 章）在等待時會一直全速執行迴圈，浪費電力，在多執行緒系統上還會搶走其他執行緒的執行資源。`pause` 指令是一個 hint，告訴硬體「我在空轉，可以降低發射速率」。

## 關鍵點

### 問題與指令

> "Section 17.1.4.1 described spin locks, which can be used to wait until a resource is available. The processor wastes power while spinning and, in a multithreaded system, it wastes execution resources potentially available to another thread. The Zihintpause extension introduces a pause instruction, which is a hint suggesting that the hart temporarily reduce the instruction issue rate while spinning."
> — p.779

中文解釋：兩個成本——**電力**和**執行資源**。第二個在 SMT（同時多執行緒）處理器上特別明顯：一個執行緒在全速空轉，就等於偷走了另一個執行緒本來可以用的發射槽。

### 用法：一個迴圈只放一個

> "A spin lock loop should contain exactly one pause instruction."
> — p.779

中文解釋：這個規定很具體。Code Example 19.1 示範正確的位置——**放在「這次沒搶到鎖、要重試」的路徑上**，不是放在檢查迴圈裡：

```
spinlock:
        lr.w  t0, (a0)      # 讀鎖
        bnez  t0, retry     # 有人拿著 → 去 retry
        li    t1, 1
        sc.w  t0, t1, (a0)  # 試著拿鎖
        bnez  t0, retry     # 沒成功 → 去 retry
        ret                 # 拿到了
retry:
        pause               # 降低空轉功耗
        j     spinlock      # 再試
```

放一個而不是多個的理由：`pause` 的效果是「暫時降低發射速率」，放太多會讓真的搶到鎖時的反應變慢。

### 編碼與 Wally 的處理

> "pause is a hint encoded as a fence w (machine code: 0x0100000F), which does nothing."
> — p.779（邊欄）

中文解釋：又一個 hint 的巧妙編碼——`fence w`（只排序寫入）在既有處理器上是合法且無害的指令，所以老機器執行 `pause` 就等於執行一個不痛不癢的 fence。

> "Wally presently has no power management features to control instruction issue rate. It accepts the pause hint but ignores it."
> — p.779

中文解釋：和 19.1 的 `prefetch.*` 一樣——**接受編碼、忽略語意**。因為是 hint，這樣做完全正確。

## 名詞表

| 名詞 | 意思 |
| --- | --- |
| Zihintpause | 提供 `pause` hint 的擴充 |
| `pause` | 建議硬體暫時降低指令發射速率，編碼為 `fence w` |
| instruction issue rate | 指令發射速率 |
| SMT | 同時多執行緒，多個執行緒共用同一個核心的執行資源 |

## 所以呢

三個 hint（`prefetch.*`、`pause`）都被 Wally 忽略，但它們在真實的高效能處理器上是有意義的功耗與吞吐量控制。下一節 19.5 的 Zicond 則不是 hint——它是真的會改變架構狀態的指令，而且 Wally 有實作。
