### 第一支 C 程式與 setStats 量測法

> "Code Example 3.11 shows a simple program, sum.c, that illustrates a C program to
>  add the numbers from 1 to N. It also illustrates printing to the console, via the
>  HTIF, and verifying results."
> — p.115

> "It prints the number of cycles and instructions retired during the sum function
>  call by sandwiching that call between the setStats(1) and setStats(0) calls.
>  These calls have some latency, so mcycle and minstret are not sampled at exactly
>  the same time and are conservative."
> — p.115

中文解釋：`sum.c`（p.115）的結構值得學，**它是一個完整的自我驗證程式**：
```c
#include <stdio.h>   // printf
#include "util.h"    // setStats, verify

long sum(long N) { ... }

int main(void) {
  int s[1], expected[1];
  setStats(1);                    // 記錄起始 mcycle / minstret
  s[0] = sum(4);
  setStats(0);                    // 記錄結束值
  printf("s = %d\n", s[0]);
  expected[0] = 10;
  return verify(1, s, expected);  // 比對，0 表示成功
}
```

**三個要點：**
1. **`setStats(1)` / `setStats(0)` 夾住要量測的程式碼**——這是量效能的標準手法
2. **書上明說這個量法「conservative（偏保守，也就是偏大）」**——
   因為 `setStats` 本身有延遲，而且 `mcycle` 和 `minstret` 不是同一瞬間取樣的。
   **量小程式時誤差比例很大**（Table 3.6 會看到）。
3. **`verify` 回傳 0 表示成功**，符合 C 的慣例

執行結果（p.115）：
```
$ spike sum
s = 10
mcycle = 31
minstret = 38
```

### 編譯旗標：跑在裸機上要關掉什麼

中文解釋：Code Example 3.12（p.116）的 Makefile 旗標，**這組是裸機 C 程式的標準配方**：

```makefile
riscv64-unknown-elf-gcc -o $(TARGET) -g -O \
  -march=rv64gc -mabi=lp64d -mcmodel=medany \
  -nostdlib -static -lm -fno-tree-loop-distribute-patterns \
  -T../common/test.ld -I../common \
  $(TARGET).c ../common/crt.S ../common/syscalls.c
```

**逐項理由（p.116）：**

| 旗標 | 作用 |
| --- | --- |
| `-g` | 產生除錯符號 |
| `-O` | 基本最佳化 |
| `-march` / `-mabi` / `-mcmodel` | 產生 rv64gc + lp64d 的正確程式碼 |
| **`-nostdlib`** | **同時關掉 C 標準函式庫 `libc.a` 和啟動碼**。**是 `-nostartfiles` 的超集** |
| **`-static`** | 禁止動態連結共享函式庫，**這樣 ELF 反組譯才看得到整支程式** |
| `-lm` | 需要時連結數學函式庫 `libm.a` |
| **`-fno-tree-loop-distribute-patterns`** | **關掉「把迴圈換成 `memcpy`/`memset`」的最佳化** |
| `-T` / `-I` | linker script / include 搜尋路徑 |

**最後兩項的邏輯鏈很重要：**
因為用了 `-nostdlib`，標準函式庫不見了 →
編譯器如果把迴圈最佳化成 `memset` 就會**找不到符號** →
所以要用 `-fno-tree-loop-distribute-patterns` 關掉它。
**同理，也必須自己補上 `crt.S` 和 `syscalls.c` 這兩個最小啟動碼**
（借自 riscv-software-src/riscv-tests repo），才能用 HTIF 做 `printf` 和 `exit`。

**兩個邊欄的實用提醒：**
- `--save-temps` 旗標會保留前處理器、編譯器、組譯器的中間輸出
  （`.i`、`.s`、`.o`），**想理解整個流程時很有用**（p.116 邊欄）
- **最佳化旗標是大寫字母 O，不是數字 0**（p.116 邊欄）

### 三個最佳化等級

> "- `-O` Perform simple optimizations to reduce code size and execution time.
>  - `-O2` Perform all optimizations that don't bloat the code (compiling takes longer).
>  - `-O3` Perform all optimizations, including those that increase code size,
>    to decrease execution time."
> — p.116

中文解釋：**分界點很清楚：**

| 等級 | 做什麼 | 代價 |
| --- | --- | --- |
| `-O` | 簡單最佳化，**同時**減少程式大小和執行時間 | 幾乎沒有 |
| `-O2` | **所有不會讓程式碼變大的**最佳化 | 編譯變慢 |
| `-O3` | 所有最佳化，**包括會讓程式碼變大的** | 程式碼變大 |

**`-O2` 和 `-O3` 的分界是「程式碼大小」**（典型例子是迴圈展開和函式內聯）。
這呼應 2.8 節 Embench 用 `-Os`（大小）和 `-O2`（速度）兩組分別評分。

### 啟動碼做了什麼（很實用的一段）

> "The code begins at 0x80000000 in the .text.init section at the _start label defined
>  in crt.S. This startup code initializes all registers to 0 and turns on the
>  floating-point unit (FPU). It sets the trap vector mtvec to be the address of the
>  trap_entry function. If a trap (interrupt or exception) occurs, the trap_entry
>  function causes the program to exit with an error code. The startup code initializes
>  the global pointer, thread pointer, and stack pointer registers, gp, tp, and sp, to
>  RAM above the program section. It then calls _init in syscalls.c, which calls main()
>  from hart 0."
> — p.116–117

中文解釋：**這是「main() 之前發生了什麼」的完整答案，值得記住：**

```
0x80000000 (_start, in crt.S)
  1. 把所有暫存器初始化為 0
  2. 開啟 FPU
  3. 設定 mtvec = trap_entry（發生 trap 就帶錯誤碼退出）
  4. 初始化 gp（全域指標）、tp（執行緒指標）、sp（堆疊指標）
  5. 呼叫 syscalls.c 裡的 _init
       → _init 呼叫 main()（只在 hart 0）
```

**注意第 5 步的 "from hart 0"**——多 hart 系統上只有 hart 0 跑 main。
**第 3 步很典型**：裸機測試程式的 trap handler 就是「出事就死給你看」。

**程式記憶體映射（Fig. 3.3，p.117）**（原書此處為圖，以下為轉錄，由低位址往高）：

| 位址 | Section | 內容 |
| --- | --- | --- |
| 0x80000000 | `.text.init` | **crt0.S startup code** |
| 0x80001000 | `.tohost` | HTIF |
| 0x80002000 | `.text` | syscalls、main、sum |
| 0x80002748 | `.rodata.str1.8` | 字串常數 |
| 0x80002794 | `.rodata` | 常數 |
| 0x800028F0 | `.bss` | 未初始化資料 |
| 0x80002940 | `.tbss` ← **tp** | 執行緒資料 |
| 0x800030EC | | heap ← **gp** |
| 0x80022890 | | stack ← **sp** |

**這張圖是理解記憶體佈局的最佳教材**：
程式碼在低位址、資料在中間、**heap 往上長、stack 往下長**，中間留空。

### 最佳化的威力（本節最重要的對照）

中文解釋：**同一個 `sum` 函式，三個最佳化等級，結果差距巨大。**

**（1）不最佳化（Code Example 3.13，p.118）：**
```asm
addi sp,sp,-48     # 在堆疊上開 6 個 double word
sd   s0,40(sp)
addi s0,sp,48      # s0 = frame pointer
sd   a0,-40(s0)    # 把 N 存到堆疊
...
sd   zero,-24(s0)  # result = 0（存記憶體）
...
ld   a4,-24(s0)    # 每次迴圈都從記憶體載入
ld   a5,-32(s0)
add  a5,a5,a4
sd   a5,-24(s0)    # 再存回記憶體
```
> "It keeps local variables on the stack instead of in registers and accesses them
>  relative to the frame pointer s0. The code is grossly inefficient."
> — p.118

**所有區域變數都放在堆疊上，每次存取都要 load/store。**
Fig. 3.4（p.117）畫出堆疊配置：s0（frame pointer）指向原本的堆疊頂，
往下依序是 unused、result（s0−16）、i（s0−24）、N（s0−32）、unused。
**48 bytes，其中兩格根本沒用。**

**（2）`-O`（Code Example 3.14，p.119）：**
```asm
blez a0,80002016   # N <= 0 就回傳 0
addi a4,a0,1       # a4 = N+1（迴圈結束條件）
li   a5,1          # a5 = i = 1
li   a0,0          # a0 = result
add  a0,a0,a5      # result += i
addi a5,a5,1       # i++
bne  a5,a4,8000200c
ret
```
> "Now the program doesn't use the stack at all. It receives N in a0 and stores N+1
>  in a4 as a completion condition. It keeps i in a5 and uses a0 for result, which
>  saves copying a different register to a0 to return result at the end."
> — p.118

**完全不用堆疊，全部在暫存器裡。** 而且**直接把結果累加在 a0**，
省掉最後的搬移（呼應 2.1 節 Code Example 2.12 那個最佳化）。

書上也提醒（p.118）：**最佳化後反組譯器很難把組語對回原始 C 碼**，
因為編譯器重排了程式碼順序。**讀最佳化後的反組譯本來就比較難。**

**（3）`-O2` / `-O3`（Code Example 3.15，p.119）：**
```asm
8000271a: 45a9    li   a1,10
```
> "When -O2 or -O3 optimization is enabled, the compiler precomputes the result of
>  calling sum(4) as 10 and replaces the sum function entirely with assigning a1 to
>  10.... The call to verify is also eliminated because the compiler precomputes that
>  verify will return 0 (indicating success)."
> — p.119

**整個函式消失了，編譯器在編譯時就把答案算出來。** 連驗證都被最佳化掉。

**Table 3.6 實際數字（p.120）：**

| 最佳化等級 | mcycle | minstret | **真實指令數** |
| --- | --- | --- | --- |
| 無 | 115 | 132 | **62** |
| `-O` | 31 | 38 | **21** |
| `-O2` / `-O3` | 11 | 16 | **1** |

**兩個觀察：**
1. **從 62 條降到 1 條。** 這就是最佳化的威力。
2. **CSR 讀數（115/132）遠大於真實指令數（62）**——
   誤差來自 `setStats` 的呼叫開銷。書上說明（p.120）：
   **"These performance counters are more useful for longer programs where the
   overhead is negligible."** ——**量小程式不準，量大程式才有意義。**

（另外呼應 3.3.9 節：Spike 上每週期執行一條指令，
所以 mcycle 和 minstret 理想上應該相同，
但**因為讀取兩個計數器的順序不同，開銷略有差異**。）

### Inline assembly：在 C 裡塞組語

> "Code Example 3.16 illustrates *inline assembly language* used to add a single
>  assembly language instruction that can't be implied by standard C code."
> — p.120

中文解釋：**用途是「C 表達不出來的指令」**，典型例子是讀 CSR。

```c
long cycles;
asm volatile("csrr %0, 0xB00" : "=r"(cycles));   // 讀 mcycle
printf("mcycle = %ld\n", cycles);
```

**語法拆解（p.120 邊欄的說明很清楚）：**
- **`%0`** 代入第一個參數
- **`"=r"(cycles)`**：`=` 表示輸出，`r` 表示「放在某個暫存器裡」，
  `(cycles)` 是對應的 C 變數
- **編譯器自己決定用哪個暫存器**（這次選了 a1），然後 `%0` 就代入 a1
  > "If the program used more registers, cycles might be allocated to a different
  >  register, and the asm statement would pick the correct register."
- **`volatile` 關鍵字防止編譯器把這條組語最佳化掉**

反組譯結果（Code Example 3.17，p.121）確認：
```asm
b00025f3    csrr a1,mcycle
```

**`volatile` 是最容易忘記的一環**——沒加的話，編譯器看不出這條指令有副作用，
可能直接刪掉。

### C 與組語混合：靠 ABI 溝通

> "When a C program needs to integrate many lines of assembly language, the easiest
>  approach is to put the C and assembly language in different files and have them
>  communicate through function calls via the ABI's calling convention."
> — p.121

中文解釋：**兩種混合方式的取捨很清楚：**
- **少量指令** → inline assembly（3.4.2）
- **大量組語** → **分成不同檔案，用函式呼叫溝通**

做法只有兩個關鍵字（p.121）：
```c
extern int sum(int);    // C 檔宣告 extern，讓 linker 去別處找
```
```asm
.global sum             # 組語檔宣告 global，讓 linker 找得到
```

**「一邊 extern、一邊 global」就接起來了。**
其他的靠 ABI 自動搞定：**N 從 a0 傳進去、結果從 a0 回來**（p.121）。

另外 **`sum.S` 自己在堆疊上保存與還原 s0/s1**，所以跨呼叫安全，
而且**最佳化器不會動組語程式碼**（p.121）。

### 標準函式庫：靜態 vs 動態、glibc vs newlib

> "Whereas the libc standard library defines most of these functions, libm defines
>  math functions. Together, these are called the C *standard library*. Historically,
>  libc and libm were separated because the math libraries could be large and not all
>  programs needed them. libc is automatically linked unless -nostdlib is specified
>  when compiling. libm is only linked if the -lm flag is provided."
> — p.122

> "The libraries can be *statically linked*, such that a copy is incorporated into the
>  program, or *dynamically linked*, such that only one copy of the standard library
>  is in memory and many different programs can call this library. Dynamic linking
>  saves memory but requires some OS support. Hence, platforms such as Linux and
>  Windows tend to use dynamic linking, while simple embedded processors use static
>  linking. libc.so and libm.so are the *shared object* dynamically linked libraries,
>  while libc.a and libm.a are the statically linked *archive* libraries."
> — p.122

中文解釋：**兩組區分要記清楚：**

**（1）libc vs libm**
| | 內容 | 連結方式 |
| --- | --- | --- |
| `libc` | 一般函式（`printf`、`strlen`、`time`） | **自動連結**（除非 `-nostdlib`） |
| `libm` | 數學函式（`sqrt`、`cos`） | **要 `-lm` 才連結** |

分開的歷史理由：數學函式庫可能很大，不是每個程式都需要。

**（2）靜態 vs 動態連結**
| | 檔名 | 做法 | 適合 |
| --- | --- | --- | --- |
| **靜態（archive）** | `libc.a` | **複製一份進程式** | **簡單嵌入式處理器** |
| **動態（shared object）** | `libc.so` | 記憶體裡只有一份，多程式共用 | **Linux、Windows**（需要 OS 支援） |

**分界點是「有沒有 OS 支援」**——所以裸機一定用靜態（呼應 `-static` 旗標）。

**（3）glibc vs newlib**
> "The leading open-source implementations are glibc and newlib. *glibc* is often used
>  for Linux systems that already have it available as a shared library. *newlib* has
>  more permissive licensing terms and thus is often preferred for embedded software."
> — p.122

| | 適合 | 理由 |
| --- | --- | --- |
| **glibc** | Linux 系統 | 系統上已經有共享函式庫了 |
| **newlib** | **嵌入式** | **授權條款較寬鬆** |

**Wally 的工具鏈用 newlib**（`$WALLY/bin/wally-tool-chain-install.sh` 編譯的）。

### Multilib：為每種架構預編一份函式庫

> "The newlib standard library is precompiled so that GCC doesn't have to recompile
>  all of the library functions every time it compiles a program.... The best
>  implementation of a library depends on the machine architecture. For example,
>  sqrt() could be implemented with fsqrt.d in rv64gc but would require a lengthy
>  series of integer operations in rv32i. GCC solves this with the *multilib* feature,
>  which precompiles many flavors of newlib targeting different machine architectures."
> — p.122

中文解釋：**這解釋了 3.3.5 節那個「rv32i 上 `*` 會變成函式庫呼叫」的機制。**

問題：`sqrt()` 在有 FPU 的 rv64gc 上是一條 `fsqrt.d`，
在 rv32i 上要一長串整數運算。**同一個函式，不同架構的最佳實作完全不同。**

**解法 multilib：為 Table 3.2 列出的每種架構各預編一份 newlib，
GCC 根據 `-march` 自動挑對的那份連結。**

### crt.S 和 syscalls.c 做什麼

> "In brief, crt.S is an assembly language startup routine that initializes all
>  registers to 0, enables floating-point, initializes a global pointer and stack
>  pointer, and defines the .tohost label to terminate a program in simulation.
>  syscalls.c defines the printf function, which invokes putchar, which makes a system
>  call to write a character to the console via stdout. syscalls.c defines a few other
>  essential library functions such as memcpy(), memset(), strlen(), strcmp(), strcpy(),
>  and exit()."
> — p.123

中文解釋：**這兩個檔案是「沒有 OS 時的最小執行環境」**（在 `$WALLY/examples/C/common`）：

| 檔案 | 提供 |
| --- | --- |
| **`crt.S`** | 啟動碼：清暫存器、開 FPU、設 gp/sp、定義 `.tohost` |
| **`syscalls.c`** | **`printf`**（經 `putchar` 用 HTIF 寫到 stdout）、`memcpy`、`memset`、`strlen`、`strcmp`、`strcpy`、`exit` |

**書上建議「讀一讀這兩個檔案很有啟發」**（"It is informative to read through each
of these files"，p.122）。
**這就是用了 `-nostdlib` 之後必須自己補的東西**——最小可運作的 C 執行環境。

（`printf` 最終是透過 HTIF 的 `sys_write` 系統呼叫實現的，呼應 3.3.8 節。）

### Compiler Explorer：不用建 Makefile 就能看編譯結果

> "The Compiler Explorer at godbolt.org is a handy tool to quickly understand how code
>  compiles without having to set up a Makefile and type a series of commands. Choose
>  the architecture and compiler (e.g., RISC-V rv32gc gcc 10.2.0), and optionally
>  specify compiler flags such as -O or -O3. Type your C code in the left pane.
>  The disassembled output will appear in the right pane."
> — p.123

中文解釋：**實務上超好用的工具，強烈建議自己試。**

書上的示範（Fig. 3.5，p.123）用遞迴階乘函式：
- **(a) `-O`**：產生真正的遞迴——有堆疊操作（`addi sp,sp,-16`、`sw ra,12(sp)`）和 `call fact`
- **(b) `-O2`**：**編譯器聰明到把遞迴消掉，變成迴圈**（只剩 `mv`/`addi`/`mul`/`bne`）

**這是「編譯器比你想的聰明」的又一個例子**——
呼應 2.6 節批評 SPARC register window「有了好的編譯器就不需要」。

| --- | --- |

| `-nostdlib` | 同時關掉 C 標準函式庫與啟動碼；是 `-nostartfiles` 的超集 |
| `-static` | 靜態連結，避免動態共享函式庫 |

| `--save-temps` | 保留 `.i`、`.s`、`.o` 中間檔 |
| `-O` / `-O2` / `-O3` | 簡單最佳化 / 所有不增大程式碼的 / 所有（含增大程式碼換速度） |

| `syscalls.c` | 提供 `printf`、`memcpy`、`exit` 等最小函式庫 |
| Frame pointer | 框架指標（s0）。不最佳化時用來相對存取堆疊上的區域變數 |
| Inline assembly | `asm volatile("...", : "=r"(var))`；`volatile` 防止被最佳化掉 |
| `extern` / `.global` | C 端宣告外部符號 / 組語端宣告全域符號，兩者配對即可跨語言呼叫 |
| libc / libm | C 標準函式庫 / 數學函式庫（要 `-lm`） |
| Static / dynamic linking | `.a`（archive，複製進程式）/ `.so`（shared object，共用一份，需 OS 支援） |
| glibc / newlib | Linux 常用 / **嵌入式常用（授權較寬鬆）**，Wally 用 newlib |
| Multilib | 為多種機器架構預編多份函式庫，GCC 依 `-march` 自動選用 |
| Compiler Explorer | godbolt.org。線上快速查看 C 如何編譯成組語 |

## 所以呢

**本節最該記住的是 Table 3.6：同一支程式從 62 條指令變成 1 條。
最佳化等級不是微調，是數量級的差別——所以量測效能時一定要註明編譯旗標。**
另外兩個實務要點：
1. **裸機 C 的旗標配方**：`-nostdlib -static` + 自己補 `crt.S`/`syscalls.c`，
   並關掉會呼叫標準函式庫的最佳化。
2. **godbolt.org 是快速驗證想法的工具**，不必每次都建 Makefile。
