# 19.5 Conditional Instructions: Zicond

> 原書 p.779–782（Chapter 19: Other Extensions）
> 涵蓋 19.5.1 Test Plan、19.5.2 Wally Implementation

## 這節在講什麼

分支很貴——預測錯要清管線、就算預測對也佔用預測器的空間、而且擋住指令層級平行。其他架構用 conditional move（條件搬移）或 predication（謂詞執行）來避免分支，但 RISC-V 兩個都做不到，原因是**指令編碼裡沒有位置放第三個來源暫存器**。

Zicond 的解法很聰明：不做 conditional move，只做 **conditional zero**（條件歸零）——兩個指令 `czero.eqz` 和 `czero.nez`，可以組合出許多條件操作，而且只需要兩個來源暫存器。

## 關鍵點

### 分支的三種成本

> "Branches are expensive. When they are mispredicted, they flush the pipeline and reduce performance. Even when branches are predicted correctly, they take up space in the branch predictor memories. They also impact extracting instruction-level parallelism for superscalar and out-of-order microarchitectures."
> — p.779

中文解釋：第三個成本最容易被忽略。超純量/亂序處理器要同時看很多條指令，分支切斷了指令流，讓它們找不到足夠的獨立工作。

### 為什麼 RISC-V 不能做 conditional move

> "However, RISC-V lacks space in the instruction encodings to specify a third source register or condition code for full predication. Furthermore, conditional move instructions are difficult to implement in microarchitectures that use register renaming because they require reading three registers: the condition, the value to move, and the old value of the destination register that must be written to the renamed register if the condition is not satisfied."
> — p.780

中文解釋：**兩個理由，第二個更深刻**。`cmov rd, rs1, rc` 的語意是「條件成立就 rd = rs1，否則 rd 不變」。問題出在「不變」——在暫存器重新命名（register renaming）的機器上，每次寫入都會分配一個新的實體暫存器，所以「不變」其實是「把舊值複製到新的實體暫存器」。這需要**讀三個暫存器**（條件、新值、舊值），而 RISC-V 每條指令只有兩個讀埠。

### czero 的語意

> "RISC-V introduces a Zicond extension for conditional operations. This extension defines czero.eqz and czero.nez ... czero.eqz rd, rs1, rs2 sets rd = 0 if rs2 = 0, or rd = rs1 otherwise. czero.nez is similar but checks if rs2 ≠ 0."
> — p.780

中文解釋：關鍵在於「**條件不成立時輸出 0，而不是保持原值**」。這就繞開了「要讀目的暫存器舊值」的問題——輸出只取決於兩個來源。

> "Conditional zero instructions, czero.*, are easy to implement, even on a microarchitecture with register renaming and two register read ports per instruction issued."
> — p.780

中文解釋：這句話點出設計動機。Zicond 不是「最好用的條件指令」，而是「**在 RISC-V 的兩來源限制下能做到的最好的條件指令**」。

### 怎麼用兩個 czero 組出條件操作

> "A conditional operation add.eq rd, rs1, rs2, rc computes rd = (rc == 0) ? rs1 + rs2 : rs1. In other words, it conditionally makes rd equal to rs1 + rs2 if rc equals 0, and just rs1 otherwise."
> — p.780

中文解釋：Table 19.2 的模式很值得理解。`add.eq` 的實作是：

```
czero.nez rd,  rs2, rc    # rc ≠ 0 → rd = 0；rc = 0 → rd = rs2
add       rd,  rs1, rd    # rd = rs1 + (條件成立才是 rs2，否則 0)
```

**訣竅是「加 0 等於什麼都沒做」**。所以對 add、sub、or、xor 這四個運算（它們的單位元素都是 0），只要兩條指令。

但對 **and** 就不行了，因為 `a & 0 = 0` 而不是 `a`。所以 `and.eq` 要三條指令加一個暫存暫存器 `rtmp`：

```
and       rd,   rs1, rs2
czero.eqz rtmp, rs1, rc
or        rd,   rd,  rtmp
```

一邊算出「條件成立的結果」、另一邊算出「條件不成立的結果」，兩者其中一個會是 0，OR 起來就選出對的那個。`sel`（二選一）和 `mov` 也是這個三指令模式。

### 和分支比較，不一定划算

> "Table 19.3 compares how some common code sequences can be written with branches, conditional zero, or conditional moves. ... Conditional zero can sometimes replace a branch without increasing program length, but other times they take more instructions than a branch solution."
> — p.781

中文解釋：Table 19.3 的四個例子很有教育意義：
- `if (cond) x = 0;` → 分支要 3 條、czero 只要 **1 條**、cmov 1 條。**czero 大勝**（因為這正好就是 czero 的原生語意）
- `if (cond) x = 1;` → 分支 3 條、czero **4 條**、cmov 3 條。**czero 輸了**
- `if (cond == 0) x = x + y;` → 分支 3 條、czero **2 條**、cmov 2 條
- `if (y > 7) x = 2;` → 分支 4 條、czero **6 條**、cmov 4 條。**czero 輸最多**

> "Conditional moves (cmov) are more powerful than czero.* but are not part of the RISC-V instruction set because of the implementation difficulty."
> — p.781

中文解釋：書上很誠實地承認 cmov 比較強。Zicond 是實作可行性下的妥協。

**判斷原則**：目標值是 0 時 czero 最划算；目標值是非零常數或需要選擇兩個值時，就要多花指令。而且即使指令數變多，消除分支仍可能是贏的——因為省掉的是**預測錯誤的懲罰**，不是指令數。

### 測試與實作

> "The Zicond-extension instructions are tested with the riscv-arch-test suite. Table 19.4 lists the number of tests for each instruction."
> — p.781

中文解釋：`czero.eqz` 和 `czero.nez` 各 613（RV32）/741（RV64）個測試，總計 1,226 / 1,482。

> "The czero.* instructions are executed on the ALU using the existing AND gate. The AND gate's second source is set to either all 1s or all 0s to either select the first source rs1 or 0, respectively, based on rs2. ... A mux produces the ZeroCondMaskInvB of all 0 or all 1 for czero instructions based on rs2 == 0 (BZero). The controller is also modified to drive ALUSelect = 111 to choose the AND output when it decodes czero instructions."
> — p.782

中文解釋：**實作成本近乎零**。Fig. 19.9 顯示改動：
1. 一個 `= 0` 比較器產生 `BZero`（其實 ALU 通常已經有零偵測）
2. 一個小多工器產生 `ZeroCondMaskInvB`（全 0 或全 1）
3. controller 多一個 `ALUSelect = 111` 的編碼

然後就**完全複用既有的 AND 閘**：`rd = rs1 & (全 1 或全 0)`。這和 18.4 的 Zbs 是同一個手法——產生一個遮罩，然後讓既有的邏輯運算單元做事。

## 名詞表

| 名詞 | 意思 |
| --- | --- |
| Zicond | 條件操作擴充，提供 `czero.eqz` / `czero.nez` |
| conditional move (cmov) | 條件搬移，RISC-V 因編碼與重新命名困難而不採用 |
| predication | 謂詞執行，任何指令都能依條件碼決定是否執行（ARM、IA-64） |
| condition code | 條件碼 |
| register renaming | 暫存器重新命名，亂序處理器用來消除假相依 |
| `czero.eqz` / `czero.nez` | rs2 = 0 ／ ≠ 0 時輸出 0，否則輸出 rs1 |
| `BZero` | rs2 是否為 0 |
| `ZeroCondMaskInvB` | czero 用的全 0 或全 1 遮罩 |
| `ALUSelect = 111` | 選擇 AND 輸出的新 ALU 控制編碼 |
| instruction-level parallelism | 指令層級平行，分支會限制它 |

## 所以呢

Zicond 是一個很好的 ISA 設計案例研究：**受限於既有編碼格式（兩個來源暫存器），設計者選了一個較弱但實作可行的原語，讓編譯器用兩三條指令組合出想要的效果。** 效益不是全面的——有些情況比分支好，有些更差，要靠編譯器判斷。硬體成本則幾乎為零。下一節 19.6 跳出標準擴充，講怎麼自己做一個擴充。
