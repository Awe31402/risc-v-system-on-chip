## 關鍵點

### Wally 是什麼：可組態的參數化設計

> "This book explores RISC-V SoC design using an open-source configurable pipelined
>  processor affectionately known as Wally. Wally is described in SystemVerilog.
>  The features are parameterized, and the values are set in a configuration file.
>  Configurations range from a simple RV32E embedded core to a full-featured RV64GC
>  application processor with caches, branch prediction, and virtual memory."
> — p.70

中文解釋：**關鍵字是 parameterized（參數化）和 configuration file（組態檔）。**

這不是六個不同的處理器，而是**一份原始碼加六組參數**。
改組態檔就能從「最小的嵌入式核心」變成「能開 Linux 的應用處理器」。

**這種做法是第 4 章（HDL Design Practices）的核心主題之一**——
參數化設計是可重用 IP 的基礎（呼應 1.2 節的 design reuse）。

名字由來（p.70 邊欄）：
Wally 得名自 Harvey Mudd College 的吉祥物 **Wally Wart**，
牠的形象來自校內粗獷主義建築上那些扁平方形的突起物。

### Wally 不支援什麼（本書範圍的邊界）

> "Wally presently does not support:
>  - Advanced microarchitecture: superscalar, out-of-order, multithreading, multicore
>  - Clock gating and other power reduction techniques
>  - Certain extensions
>    - V: Vector instructions
>    - Zvk*: Vector cryptographic instructions
>    - H: Hypervisor
>    - Debug and trace interfaces
>    - Various recent smaller extensions"
> — p.70

中文解釋：**這份清單非常重要，它告訴你這本書會教到哪裡。**

**Wally 是一顆單核、循序（in-order）、5 級 pipeline 的處理器。**
沒有 superscalar、沒有 out-of-order、沒有多核。
（第 13、14 章會**講解**這些技術，但 Wally 本身沒實作。）

也沒有 clock gating——**所以書裡談功耗時要記得這個限制**（第 6 章）。

擴充方面缺 V（向量）和 H（hypervisor），這兩個都是大工程。

### OpenHW Foundation 與其他開源核心

> "Wally (formally CORE-V Wally: cvw) is a project of the OpenHW (Open Hardware)
>  Foundation, which curates and supports robust open-source cores. Many of the cores
>  have evolved from academic projects to industry-supported open products."
> — p.70–72

中文解釋：**正式名稱是 CORE-V Wally，縮寫 cvw**——
這是 repository 名稱和程式碼路徑裡會一直看到的字。

OpenHW 的其他核心（p.72），拿來對照可以理解 Wally 的定位：

| 核心 | 規格 | 基礎 |
| --- | --- | --- |
| **CV32A60AX** | RV32IMCA application class，**6 級** pipeline | Ariane |
| **CV32E40PV2** | RV32IMFC 微控制器，**4 級** pipeline | RI5CY |
| **CV32E20** | RV32[E|I][M]C 簡單低功耗微控制器 | lowRISC Ibex |

**Wally 是 5 級，剛好落在中間。**
注意「從學術專案演化成產業支援的開源產品」這條路徑——
這正是 1.8 節說的開源硬體運動在實務上長什麼樣。

授權方面（p.73 邊欄）值得一讀：
Wally 用 **SolderPad 授權**（Apache 的開源硬體版本），
理由是它「寬鬆地支援硬體與軟體開發，同時防止專利濫用，而且是 OpenHW Foundation 的標準」。
邊欄也簡述了各種授權的差別：**GNU 是 copyleft（衍生作品必須用同樣條款，所以禁止專有衍生）；
MIT/BSD 基本上「什麼都可以」，只要求標示出處與免責；Apache 較複雜但明確處理專利權。**

### Wally 方塊圖與模組階層

> "Fig. 2.13 shows a high-level block diagram of Wally. It uses the same 5-stage
>  pipeline described in Section 2.7.2. The SoC core connects via a bus interface to
>  the uncore block containing peripherals and memory."
> — p.73

中文解釋：**Wally 用的就是 2.7.2 節那個五級 pipeline**——
Fig. 2.13（p.74）底下一樣標著 Fetch / Decode / Execute / Memory / Writeback，
一樣有貫穿全圖的 hazard 單元。差別是每一格裡的東西多很多。

**Fig. 2.13 相對於 Fig. 2.11（簡化版）多出來的東西**（原書此處為圖，以下為轉錄）：
- **IFU 裡**：多了 **BP**（分支預測器）、**MMU**、**I$**（指令快取）、**decomp**（壓縮指令解壓）
- **IEU 旁邊**：多了 **MDU**（乘除單元，內含 mul 和 div）、**FPU**（含 FRF 浮點暫存器檔案與執行單元）
- **LSU 裡**：多了 **D$**（資料快取）、**MMU**、**HPTW**（硬體頁表走訪器）
- **右下角**：**privileged 單元**（含 trap 和 CSR）
- **最上面**：**EBU**（外部匯流排單元）通往 **uncore**

Table 2.6（p.75）列出主要模組（module name 就是 SystemVerilog 檔名）：

| 模組 | 說明 |
| --- | --- |
| **ifu** | 指令擷取單元。含 `cache`/`irom`、`mmu`、`bpred`、`decompress`、PC 邏輯 |
| **ieu** | 整數執行單元。含 `regfile`、`ieuresultmux`、`controller`（含 forwarding 與 mux 選擇）、`alu` |
| **mdu** | 乘除單元。含 `mul`、`div` |
| **fpu** | 浮點單元。含 `fpreg`、`fma`、`fdivsqrt`、`fcvt`、`fcmp` |
| **lsu** | 載入儲存單元。含 `cache`/`dtim`、`mmu`、`hptw` |
| **ebu** | 外部匯流排單元 |
| **hazard** | 危障單元 |
| **privileged** | 特權單元。含 `csr`、`trap` |

**頂層模組名稱是 `wallypipelinedcore`。**
這張表等於整本書後半的目錄——每個模組對應一到數章。

### Wally 的時序特性（很實用的一段）

> "Integer instructions have single-cycle latency and throughput. Loads, multiplies,
>  and most floating-point instructions have single-cycle throughput but 2-cycle
>  latency. A load immediately after a store also must stall for a cycle. Division
>  and cache misses have long latency, and they stall the pipeline. Mispredicted
>  branches are discovered in the Execute stage and thus must flush the next two
>  instructions. Writes to the CSRs flush the pipeline to ensure consistency."
> — p.73

中文解釋：**這段是 Wally 的效能規格摘要，值得整理成表背下來：**

| 操作 | latency（延遲） | throughput（產出率） | 後果 |
| --- | --- | --- | --- |
| 整數指令 | 1 週期 | 1 週期 | 無 |
| **load、乘法、多數浮點** | **2 週期** | 1 週期 | 緊接著用結果要 stall 1 次 |
| store 後緊接 load | — | — | **stall 1 週期** |
| **除法、cache miss** | 長 | — | **stall pipeline** |
| **分支預測錯誤** | 在 Execute 級才發現 | — | **flush 後面 2 條指令** |
| **寫 CSR** | — | — | **flush 整條 pipeline** |

**「latency 和 throughput 分開」這個區分要抓住**：
throughput = 1 表示可以每週期發一條進去（pipelined）；
latency = 2 表示結果要兩個週期後才拿得到。
所以 `lw x3, 0(x1)` 後面**緊接著**用 x3 就要 stall，隔一條就不用。

**分支錯誤 flush 兩條**——因為分支在第 3 級（Execute）才解決，前面已經抓了 2 條。
呼應 1.6 節：pipeline 越深，這個數字越大。

**寫 CSR 要 flush 整條 pipeline**，理由是 "to ensure consistency"——
CSR 會改變處理器行為（例如開關某個功能），
已經在 pipeline 裡的指令是用舊設定解碼的，必須重來。

### 記憶體陣列的實作選擇

> "The large memory arrays in the caches and branch predictor are implemented as
>  single-ported edge-triggered RAMs. The smaller multiported register files and TLB
>  content-addressable memories (CAMs) are implemented using flip-flops or latches
>  because many libraries for field programmable gate arrays (FPGAs) and
>  application-specific integrated circuits (ASICs) lack specialized cells for these
>  structures."
> — p.73

中文解釋：**這是一個實務上的取捨，理由很現實：**

| 結構 | 實作方式 | 理由 |
| --- | --- | --- |
| **大陣列**（cache、分支預測器） | 單埠、邊緣觸發 RAM | 密度高、有現成的 RAM 巨集 |
| **小的多埠結構**（暫存器檔案、TLB 的 CAM） | flip-flop 或 latch | **元件庫裡根本沒有這種特殊單元** |

**"lack specialized cells for these structures"** 是關鍵——
不是設計者想這樣做，是 FPGA 和 ASIC 的標準元件庫沒有多埠 RAM 可用。
**這是「理想設計」被「可用元件」限制住的典型例子**，第 6 章會再碰到。

### 六種組態：從最小到能開 Linux

> "Table A.1 lists standard configurations for which Wally has been tested, namely:
>  rv32e, rv32i, rv32imc, rv32gc, rv64i, and rv64gc."
> — p.73

中文解釋：**這六個組態的階梯很有教學意義，每一階加一組功能：**

| 組態 | 加了什麼 | 用途 |
| --- | --- | --- |
| **rv32e** | 最小。**無片上記憶體** | TSMC 28nm 下**面積最小、頻率最高** |
| **rv32i / rv64i** | 純整數指令集 + 小型片上記憶體 | 控制 SoC 的其他部分 |
| **rv32imc** | **+ 匯流排、周邊、特權模式、壓縮指令** | 低成本獨立晶片，控制家電、玩具、車用系統 |
| **rv32gc / rv64gc** | **+ 完整擴充、cache、分支預測、supervisor 模式、虛擬記憶體** | **能開 Linux 的應用處理器** |

**rv64gc 支援 RVA22S64 profile**（呼應 2.5 節）。

> "The more complex designs have a much lower frequency because the trap and
>  floating-point logic is on the critical path. The area increases substantially
>  as memories, floating-point, and branch prediction are added."
> — p.73

中文解釋：**代價說得很明白：複雜組態頻率低很多。**
關鍵路徑上是 **trap 邏輯和浮點邏輯**。
（後面 2.8.6 節給出實際數字：rv32e 是 2.99 GHz，rv64gc 只有 0.8 GHz——**差了將近 4 倍。**）

**這是第 6 章 PPA（Performance, Power, Area）取捨的活教材**：
功能不是免費的，每加一樣就付頻率和面積。

### 驗證：五套測試

> "Wally is verified with a variety of test cases, as listed in Table 2.7."
> — p.76

中文解釋：Table 2.7（p.76）的五套測試，**各自負責不同層面**：

| 測試套件 | 測什麼 |
| --- | --- |
| **riscv-arch-test** | 每條指令**單獨**的基本功能。由 RISC-V International 架構測試組提供 |
| **wally-riscv-arch-test** | riscv-arch-test **沒涵蓋**的部分，特別是 MMU 和特權操作 |
| **Coverage tests** | 程式碼覆蓋率——確認 Verilog 的每一行都被測到。功能覆蓋率仍在進行中 |
| **TestFloat** | FPU 的完整測試（來自 Berkeley） |
| **Linux boot** | 在模擬和 FPGA 上開機 Linux，確認正確執行 **5.5 億條指令**，涵蓋特權模式、CSR、中斷、周邊、虛擬記憶體 |

**這個組合的設計思路值得學**：
- 官方測試（riscv-arch-test）確認**符合標準**
- 自訂測試（wally-riscv-arch-test）補**官方沒測到的**
- 覆蓋率確認**沒有死角**
- 專項測試（TestFloat）攻**最難的部分**
- **開機 Linux 是最終的整合測試**——5.5 億條指令，任何一個環節錯了都過不了

書上邊欄非常誠實（p.76 邊欄）：

> "Experience teaches us that untested features usually have bugs. The verification
>  suites are not comprehensive enough to cover all corner cases, especially of the
>  privileged architecture, so we are confident that bugs remain."

**「沒測過的功能通常有 bug……我們有信心 bug 還在。」**
這句話的態度比內容更重要——呼應 1.2 節「驗證比設計還貴」。

### Benchmark：Wally 大約等於 ARM Cortex M4

> "Performance depends on a processor's cycle time and a program's number of
>  instructions and execution cycles, as described in Eq. (2.1). We use benchmarking
>  to measure the number of cycles and, in the next section, explore logic synthesis
>  timing analysis to obtain cycle time. Compiler optimization flags affect the number
>  of instructions."
> — p.76

中文解釋：**注意方法論**：效能公式的三項要用不同手段量測——
**benchmark 量週期數、邏輯合成量週期時間、編譯器 flag 影響指令數。**

**CoreMark 分數**（Table 2.8，p.77）。一個 CoreMark = benchmark 每秒跑一次；
分數通常報成 **CoreMark/MHz** 以正規化時脈：

| 處理器 | CoreMark/MHz |
| --- | --- |
| **Wally (rv32imb)** | **3.36** |
| Cortex M4 | 3.42 |
| RI5CY | 3.19 |
| **VeeR-EH2** | **6.3** |
| VeeR-EL2 | 3.9 |

> "Wally has similar performance to ARM's Cortex M4 and OpenHW Foundation's RI5CY.
>  Cadence's VeeR-EH2 is a dual-issue superscalar processor and has nearly twice the
>  CoreMark performance of Wally."
> — p.77

中文解釋：**Wally ≈ Cortex M4**，這是個合理的定位（一顆正經的嵌入式處理器）。
VeeR-EH2 快一倍，**因為它是 dual-issue superscalar**——
這直接展示了 2.8 節開頭「Wally 不支援 superscalar」的代價。

**Embench 分數**（Table 2.9，p.78），分成「最佳化程式碼大小（-Os）」和
「最佳化速度（-O2）」兩組，都以 ARM Cortex M4 為基準正規化：

| 處理器 | -Os Speed/MHz | -Os Size | -O2 Speed/MHz | -O2 Size |
| --- | --- | --- | --- | --- |
| **Wally (RV32IMBC)** | **1.01** | **1.01** | **1.09** | 1.18 |
| Cortex M4 (ARMV7M) | 0.90 | 1.00 | 1.00 | 1.15 |
| RI5CY (RV32IMC) | 0.93 | 1.05 | 0.93 | 1.27 |
| VeeR-EH2 (RV32IMACZb) | 1.18 | 1.11 | 1.33 | 1.26 |

> "Size and speed are normalized to the best achieved by an ARM Cortex M4, showing
>  that Wally has similar code density and is about 9% faster at the same clock rate.
>  Even though VeeR-EH2 is a tremendous superscalar processor with improved CoreMark
>  score, it is only 22% faster than Wally in Embench, showing that Embench is a more
>  realistic benchmark that is harder to game. RI5CY speed appears suspicious, being
>  equal for -Os and -O2."
> — p.77

中文解釋：**這段的方法論教訓比數字更值錢：**

1. **同一個處理器在不同 benchmark 上排名不同**：
   VeeR-EH2 在 CoreMark 上快 87%，在 Embench 上只快 22%。
2. **"harder to game"（比較難作弊）是評價 benchmark 的關鍵標準**——
   Embench 比較接近真實工作負載，所以差距縮小。
   （呼應 2.6 節批評 SPARC register window「在 benchmark 上表現好」。）
3. **數據異常要標出來**：作者直接說 RI5CY 的數字「看起來可疑」，
   因為 -Os 和 -O2 竟然一樣快。**這是讀 benchmark 該有的懷疑態度。**

### 實作：三種製程 + 三種 FPGA

> "Wally is designed to balance performance, power, and area rather than favor one
>  at great expense to the others. The SystemVerilog has been synthesized in 130-,
>  90-, and 28-nm complementary metal-oxide-semiconductor (CMOS) processes and on
>  three FPGAs. The results were reviewed to detect and eliminate grossly inefficient
>  structures caused by poor coding."
> — p.77

中文解釋：**"balance PPA rather than favor one"** 是 Wally 的設計哲學——
不追求極端，因為它是教學/基準平台（第 6 章會詳談 PPA）。

**"detect and eliminate grossly inefficient structures caused by poor coding"**
是很實用的一句：**把設計跑過合成，是檢查 HDL 寫得好不好的手段。**
寫得爛的 Verilog 會合成出離譜的電路——第 4 章的重點之一。

**FPGA**（p.78）：Xilinx Arty A7、VCU108、VCU118。
**FPGA 能開機 Linux，並透過 USB 線把開機訊息印到終端機**（第 23 章）。

### ASIC 布局：一張圖看懂面積都被誰吃掉

> "Fig. 2.14 shows a placement of the rv32gc configuration for a chip in the TSMC
>  28hpc+ 28-nm process. The components are placed during physical synthesis, but
>  routing has not been performed. The chip area is 0.7 mm on a side. The memory
>  arrays account for the largest part of the area."
> — p.78

中文解釋：Fig. 2.14（p.79）是 rv32gc 的實際布局圖（原書此處為彩色布局圖）。
圖上各區塊按單元上色，**看得到的區塊由大到小是**：
**I$DATA 和 D$DATA（兩大片，各佔約 1/4）、BTB 與 PHT（分支預測器，左側一長條）、
FPU（紅色，左下）、LSU（橘色）、IFU（紫/綠）、IEU（藍，很小）、MDU（粉紅，極小）**，
另有 I$Tags、D$Tags 幾條窄陣列。

**最重要的觀察：記憶體陣列佔了最大的面積。**
真正做運算的 IEU 和 MDU 小得可憐——
**這跟 1.2 節 Apple A15 die photo 的觀察完全一致：現代晶片的面積主要不是給運算用的。**

書上還指出幾個布局細節（p.78）：
- 每個 16-KiB cache 有四路，每路由四個 1-KiB 的 64×128 資料陣列和一個 64×22 tag 陣列組成
- **"we observe interesting tentacles where the IFU, LSU, and privileged unit closely
  interact with the 16 physical memory protection (PMP) checkers"**——
  圖中間那些觸手狀的連線就是 PMP 檢查器
- **FPU 跟其他區塊溝通最少，所以被放在角落**——
  **布局工具會把溝通多的放在一起**，這是自動產生的（"This floorplan is automatically
  generated during synthesis; each run is different."）

### 頻率與 FO4：跨製程比較的通用單位

> "Table A.1 summarizes the maximum frequency for each configuration in TSMC28,
>  ranging from 2.99 GHz for rv32e to 0.8 GHz for rv64gc. In this process, a
>  fanout-of-4 inverter (FO4) gate delay is 11.6 ps for typical silicon at nominal
>  (0.9 V) voltage and 25°C, which is a handy metric for normalizing frequency in a
>  process-independent fashion. Hence, the clock period (reciprocal of frequency)
>  ranges from 29 to 108 FO4 delays for the various configurations. The 5-stage
>  pipelines are not as aggressive as contemporary high-performance processors with
>  more pipeline stages that target closer to 50 FO4 delays per cycle."
> — p.78–79

中文解釋：**FO4 是這本書很重要的一個工具概念，一定要懂。**

**問題**：不同製程的 GHz 不能直接比（28nm 的 1 GHz 和 130nm 的 1 GHz 意義不同）。
**解法**：用 **FO4**（一個扇出為 4 的反相器的閘延遲）當單位。
**FO4 是製程無關的時間尺規**——
「你的時脈週期等於幾個閘延遲」這個數字，在任何製程下意義相同。

實際數字：
- TSMC 28nm 的 **1 FO4 = 11.6 ps**（典型矽、0.9 V、25°C）
- Wally 各組態的時脈週期是 **29 到 108 FO4**
  （rv32e = 2.99 GHz ≈ 29 FO4；rv64gc = 0.8 GHz ≈ 108 FO4）
- **現代高效能處理器（更多 pipeline 級）目標接近 50 FO4**

**怎麼解讀**：rv32e 的 29 FO4 **比高效能處理器還激進**（每級能做的事更少）；
rv64gc 的 108 FO4 則很寬鬆（每級塞了很多邏輯）。
書上的評語是 5 級 pipeline "not as aggressive"——
**因為級數少，每一級必須塞更多邏輯，所以時脈拉不高。**
這正是 1.6 節「superpipelining 換時脈」的另一面。

最後一個實務提醒（p.79）：
完整的 SoC 需要 bond pad 或 solder bump 連到外界（時脈、重置、周邊接腳、AHB 匯流排、電源與接地）。
**"The core is so small in 28 nm that it is dwarfed by the pads."**
——**核心在 28nm 下小到被接腳襯得微不足道。**
這是很有畫面的一句：做晶片時，有時候決定面積的不是電路，是接腳數。

## 所以呢

**Wally 是一顆單核、循序、5 級 pipeline 的可組態 RISC-V 處理器，
效能大致等於 ARM Cortex M4，最複雜的 rv64gc 組態能開 Linux。**
三個要帶走的實務概念：
1. **組態階梯的取捨**——rv32e 到 rv64gc，頻率從 2.99 GHz 掉到 0.8 GHz。功能不免費。
2. **FO4 是跨製程比較頻率的通用單位**（28nm 下 11.6 ps），後面章節會一直用。
3. **面積主要被記憶體陣列吃掉**，不是運算單元——這決定了第 10 章（cache）的重要性。
