# 2.4 Memory Map

> 原書 p.51–52（Chapter 2: Introduction to RISC-V）

## 這節在講什麼

很短的一節，但很實用。講兩件事：

1. **memory map（記憶體映射）**：什麼位址放什麼東西。
   RISC-V 用 **memory-mapped I/O**——周邊裝置不是用特殊指令存取，
   而是**佔用一段位址範圍，用普通的 load/store 讀寫**。
2. **reset vector（重置向量）**：開機時 PC 從哪裡開始。

這節給出 Wally 的實際記憶體配置圖（Fig. 2.8），
以及幾個之後會一直看到的周邊縮寫（CLINT、PLIC、GPIO、UART、SPI、SDC）。

## 關鍵點

### Memory map 是 EE 的一部分

> "The *memory map*, a key part of the EE, defines the addresses at which memory and
>  I/O peripherals are located. A representative memory map, used in the Wally
>  processor, is shown in Fig. 2.8 (and in Table A.2 in Appendix A). This memory map
>  contains a small boot ROM, a larger RAM, and various peripherals."
> — p.51

中文解釋：注意這句話把 memory map 歸為 **EE 的一部分**（呼應 2.3.6 節）——
它是「程式底下的世界長什麼樣」的一部分，不是 ISA 規定的。
**不同的 RISC-V 晶片有不同的 memory map。**

關鍵觀念是 **memory-mapped I/O**：
周邊不是用特殊的 I/O 指令存取（x86 有 `in`/`out` 指令），
而是**佔一段位址**。要跟 UART 說話，就是 `sw` 到 UART 的位址。
**好處是 ISA 不需要為 I/O 增加任何指令**——又是 RISC 精神。

### 六個周邊，先認名字

> "- CLINT: Core Local Interrupter, for handling software and timer interrupts
>  - PLIC: Platform-Level Interrupt Controller, for multiplexing external interrupts
>  - GPIO: General-purpose input/output, for reading and writing binary values from pins
>  - UART: Universal asynchronous receiver/transmitter, for serial communication,
>    such as printing to a terminal
>  - SPI: Serial Peripheral Interface, for higher-speed clocked serial communication
>  - SDC: Secure Digital (SD) Card controller"
> — p.51

中文解釋：**這六個縮寫在整本書後面會不斷出現，現在先建立印象：**

| 縮寫 | 全名 | 幹嘛的 | 白話 |
| --- | --- | --- | --- |
| **CLINT** | Core Local Interrupter | 軟體中斷和計時器中斷 | **核心自己的鬧鐘** |
| **PLIC** | Platform-Level Interrupt Controller | 多工外部中斷 | **外部中斷的總機** |
| **GPIO** | General-purpose I/O | 讀寫接腳的二進位值 | **通用接腳** |
| **UART** | Universal Asynchronous Receiver/Transmitter | 序列通訊 | **印字到終端機** |
| **SPI** | Serial Peripheral Interface | 高速同步序列通訊 | **快一點的序列埠** |
| **SDC** | SD Card controller | SD 卡 | **儲存** |

**兩個中斷控制器的分工要記住**：
CLINT 管**核心內部**的（計時器、軟體中斷），PLIC 管**外部**來的（周邊裝置）。
這兩個是跑 Linux 的必要條件（呼應 2.3.6 節說 QEMU 和 Sail 模擬它們）。

### Wally 的實際記憶體配置

中文解釋：Fig. 2.8（p.51）是 Wally 的預設記憶體映射圖。
**注意這張圖位址 0 在下面**（書上邊欄特別聲明：
"The field of memory systems is inconsistent on whether address 0 is shown at the
top or bottom of a memory diagram. This textbook uses the bottom."，p.51）。

由低位址往高位址排（原書此處為圖，以下為轉錄的位址表）：

| 位址範圍 | 內容 |
| --- | --- |
| 0x00001000 – 0x00001FFF | **Boot ROM** |
| 0x00013000 – 0x00013FFF | SDC |
| 0x02000000 – 0x0200FFFF | **CLINT** |
| 0x0C000000 – 0x0FFF0000 | **PLIC** |
| 0x10000000 – 0x10000007 | **UART** |
| 0x10040000 – 0x10040FFF | SPI |
| 0x10060000 – 0x100600FF | GPIO |
| 0x80000000 – 0x87FFFFFF | **RAM** |

**幾個值得記住的位址**：
- **0x80000000 = RAM 的起點**，也是程式通常的載入位址
- **0x10000000 = UART**（印字用）
- **0x02000000 = CLINT**（計時器）

周邊都集中在低位址（0x0–0x10060000 這段），RAM 在 0x80000000 之上——
中間留了一大片空洞，這樣未來要加周邊有空間。

書上邊欄補充 Wally 的相容性（p.52 邊欄）：
Wally 的 memory map **相容於 SiFive FU540 處理器和 QEMU 的 virt machine**
（virt 是 QEMU 的模擬平台，周邊配置適合開 Linux）。
一個例外：**UART 在 Wally 和 virt 上是 0x10010000，在 FU540 上是 0x10000000**。
第 4.4 節講 Wally 的設定檔，可以用來增減周邊或改記憶體映射。

（此處書上內文與邊欄的 UART 位址不同：Fig. 2.8 標 0x10000000，
邊欄說 Wally 是 0x10010000。以 Table A.2 為準。）

### 沒有外部 RAM 時：DTIM 和 IROM

> "Configurations without external RAM map the on-chip memories, data
>  tightly-integrated memory (DTIM), and instruction read-only memory (IROM) to
>  address 0x80000000 instead. Typically, the program begins at 0x80000000 and data
>  follows."
> — p.52

中文解釋：小型系統沒有外接 RAM，就把**晶片內的記憶體**映射到同一個 0x80000000。
- **DTIM**（data tightly-integrated memory）：緊耦合資料記憶體
- **IROM**（instruction read-only memory）：指令唯讀記憶體

**"tightly-integrated" 的意思是它直接掛在核心旁邊，不經過 cache**——
存取延遲固定且很短。這在即時系統很重要（延遲可預測）。

注意這個設計的好處：**不管有沒有外部 RAM，程式都從 0x80000000 開始。**
同一份程式碼不用改。

### Reset vector：開機從哪開始

> "On reset, the PC begins at an address called the *reset vector*, and some
>  instructions must be available at that address. In a real system, the reset vector
>  points to the boot ROM, which contains a *boot loader* that loads the next stage
>  of an OS from the SD card (or flash memory or hard disk, if they are supported).
>  In a simulator, the reset vector could point directly to RAM that was
>  preinitialized on reset with the program of interest."
> — p.52

中文解釋：**reset vector = 處理器一上電，PC 的第一個值。**
這是雞生蛋問題的起點：**那個位址上必須先有東西**，否則處理器無事可做。

兩種做法：
- **真實系統**：指向 **boot ROM**（唯讀，燒死的），裡面是 **boot loader**，
  負責從 SD 卡 / flash / 硬碟載入下一階段的 OS。
  **這是分階段開機**：ROM 裡的程式很小，只負責把大的東西搬進來。
- **模擬器**：可以直接指向 RAM，因為模擬器能在重置時就把程式預先放好。

書上邊欄給了 Wally 各種設定的實際 reset vector（p.52 邊欄）：

| 設定 | Reset vector | 原因 |
| --- | --- | --- |
| 大多數 Wally 設定 | **0x80000000** | 測試平台自動把程式載到 RAM 這個位址 |
| Buildroot Linux / QEMU | **0x1000** | 從 boot ROM 裡預載的 Linux boot loader 開始 |
| SiFive FU540 晶片 | **0x1004** | 給 bootloader 用 |

**"The reset vector is platform dependent"**（p.52 邊欄）——
這也是 memory map 屬於 EE 而非 ISA 的又一個證據。

## 名詞表

| 名詞 | 意思 |
| --- | --- |
| Memory map | 記憶體映射。定義記憶體與 I/O 周邊各自位於哪些位址；屬於 EE 的一部分 |
| Memory-mapped I/O | 周邊佔用位址範圍，用一般的 load/store 存取，不需要專用 I/O 指令 |
| CLINT | Core Local Interrupter。處理軟體中斷與計時器中斷（核心內部） |
| PLIC | Platform-Level Interrupt Controller。多工外部中斷 |
| GPIO / UART / SPI / SDC | 通用接腳 / 序列通訊 / 高速同步序列 / SD 卡控制器 |
| DTIM | Data tightly-integrated memory。緊耦合資料記憶體，不經 cache |
| IROM | Instruction read-only memory。晶片內指令唯讀記憶體 |
| Reset vector | 重置向量。處理器重置後 PC 的起始位址；平台相關 |
| Boot ROM / boot loader | 開機唯讀記憶體 / 開機載入程式，負責載入下一階段的 OS |

## 所以呢

**RISC-V 用 memory-mapped I/O，所以 ISA 不需要任何 I/O 指令——
周邊就是一段位址，用 `lw`/`sw` 存取。**
實務上要記住三個位址：**RAM 在 0x80000000、UART 在 0x1000xxxx、CLINT 在 0x02000000**，
以及 reset vector 在多數 Wally 設定下是 **0x80000000**。
這些數字在第 3 章跑第一個程式、第 8 章處理 trap、第 22 章開機 Linux 時都會用到。
