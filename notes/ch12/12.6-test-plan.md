# 12.6 Test Plan

> 原書 p.544（Chapter 12: Load/Store Unit）

## 這節在講什麼

**只有兩句話，但它很誠實地說明了「整合章的測試困境」。**

1. **LSU 沒有自己的測試**——全部靠前面各章的測試
2. **明確指出缺口：需要更全面地測試 cache 和 HPTW 的交互作用**

## 關鍵點

### 靠既有測試的組合

> "**The basic features of the LSU are tested with existing tests, including the load/store tests from Section 7.4,
>  the privileged memory access fault tests from Section 8.3, the bus tests from Section 9.4, and the MMU tests from
>  Section 11.3.**"
> — p.544

中文解釋：**四套既有測試，正好對應 12.1 節那張「各章加了什麼」的地圖：**

| 測試 | 來源 | 測 LSU 的哪一部分 |
| --- | --- | --- |
| **load/store 測試** | **7.4 節** | 基本的 load/store 功能 |
| **特權記憶體存取 fault 測試** | **8.3 節** | PMA/PMP 產生的 fault |
| **匯流排測試**（`ahb64_ram_*`） | **9.4 節** | AHB 介面與 burst |
| **MMU 測試**（`WALLY-mmu-sv*`） | **11.3 節** | TLB、頁表走訪、page fault |

**這個組合的邏輯是：LSU 是這四樣東西的整合，
所以分別測好這四樣，LSU 就「大致」測到了。**

**但這個邏輯有個明顯的漏洞——見下。**

### 明確的缺口

> "**A more comprehensive test plan would stress the cache and its interaction with the HPTW.**"
> — p.544

中文解釋：**一句話點出漏洞：「cache 和 HPTW 的交互作用」沒有被測到。**

**為什麼這個缺口特別重要，可以從前面幾節推出來：**

1. **12.3.4 節說 HPTW 必須走 D$**——
   所以 HPTW 的每一次 PTE 讀取都可能 cache hit 或 miss
2. **12.5.5 節的時序圖就示範了這個交互**：
   **level 1 PTE 在 D$ 命中（2 個週期），level 0 PTE miss（20 多個週期）**
3. **12.2.3 節那個「Wally 開機 Linux 當掉」的 bug 正是這類交互造成的**：
   **HPTW 的 D$ miss 產生的 LSU 匯流排請求，搶走了 IFU 的 burst**

**所以「cache 和 HPTW 的交互」不是理論上的顧慮——
它已經造成過一個「最難找出的 bug」。**

### 整合章的測試困境

中文解釋：**這節透露了一個一般性的問題，值得思考：**

**分別測試 A、B、C、D 四個元件都通過，不代表 A+B+C+D 的整合沒問題。**

**Wally 目前的做法（靠既有測試的聯集 + 開機 Linux）能抓到「明顯的」整合 bug，
但抓不到需要特定時序才會出現的組合**——
例如「DTLB miss 和 I$ miss 同一週期發生，且 HPTW 的第二次存取 miss」。

（呼應 5.1.3 節：單元測試 vs 系統測試的取捨；
以及 5.1.1 節：constrained random 測試專門抓「人寫不出來的」組合。）

**這也解釋了為什麼 5.1.1 節說 constrained random 測試有價值——
它舉的例子正好就是這類：
「IFU 因為 LSU 正在處理 TLB miss 而 stall 時，剛好來了中斷」。**

## 所以呢

**這節只有兩句話，但點出了整合章的核心測試問題：**

1. **LSU 沒有自己的測試**，靠 7.4（load/store）、8.3（fault）、
   9.4（匯流排）、11.3（MMU）四套測試的聯集。

2. **明確的缺口是「cache 和 HPTW 的交互作用」**——
   而這不是理論顧慮：**12.2.3 節那個「開機 Linux 當掉」的 bug
   正是這類交互造成的，書上稱它是「設計 Wally 時最難找出的 bug 之一」。**

**一般性的教訓：元件各自測通不代表整合沒問題。
這類 bug 需要 constrained random 測試或長時間的系統測試（開機 Linux）才抓得到。**

下一節（12.7）是本章總結。
