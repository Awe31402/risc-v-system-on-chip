## 關鍵點

### Cache 的本質：一個近似

> "**Microprocessor designers approximate a large, fast, cheap memory with a large, slow, cheap main memory
>  and a small, fast, cheap cache memory. If most memory accesses hit in the cache, the AMAT is almost as
>  fast as the cache, but the cost per total bit remains low. In a large system, this generalizes to a
>  multilevel memory hierarchy with caches of varying size and speed.**"
> — p.467

中文解釋：**"approximate"（近似）這個動詞用得好——
cache 不是真的做出「又大又快又便宜」的記憶體，是**製造出那個幻覺**。

**條件是「大部分存取要命中」**（呼應 10.1.1 節的 AMAT 公式）。

### Locality 與 cache line

> "**Caches exploit temporal and spatial locality to obtain a high hit rate: memory locations that have been
>  accessed recently are likely to be used again, and nearby memory locations are also likely to be used.
>  To exploit spatial locality, caches are organized as a collection of lines, commonly 512 bits (64 bytes,
>  or 8 double words) long.**"
> — p.467

中文解釋：**兩種 locality 對應兩個設計：
temporal → cache 本身的存在；spatial → cache line 的長度。**

### 位址的三段與三種 miss

> "**The cache only holds a subset of memory. The middle bits of the requested address (the set bits) select
>  the cache line, and the lower bits select the word within the line. The line also contains a tag as well
>  as valid and dirty bits. If the tag bits match the upper bits of the address and the line is valid, the
>  desired line is present, and the cache hits.**"
> — p.467

> "**Cache misses can be classified as compulsory (first time a line is accessed), capacity (cache is too
>  small to hold the working set), or conflict (multiple addresses map to the same cache line).
>  Long cache lines reduce compulsory misses at the expense of an increased miss penalty (time to transfer
>  a cache line). Larger caches reduce capacity misses at the expense of cost and speed. Associative caches
>  reduce conflict misses by providing multiple ways that can hold a given cache line, at the expense of
>  complexity, cost, and access speed.**"
> — p.467

中文解釋：**三種 miss 和三種解法的對應表，每個解法都有代價：**

| Miss 類型 | 解法 | 代價 |
| --- | --- | --- |
| **Compulsory** | **加長 cache line** | **miss penalty 增加**（傳輸時間變長） |
| **Capacity** | **加大 cache** | 成本與速度 |
| **Conflict** | **提高 associativity** | 複雜度、成本、存取速度 |

**「每個解法都有代價」是這張表的重點**——沒有免費的午餐。

### Miss 的處理與替換

> "**When a cache miss occurs, the entire line is transferred into the cache, so a subsequent access to
>  another word in the line will hit. If the set is full, it must evict another line to make room.
>  To exploit temporal locality by holding recently accessed lines, associative caches typically have an LRU
>  or pLRU replacement policy to select the way to evict. If the evicted line is dirty, it must also be
>  written back to memory.**"
> — p.467

中文解釋：**「抓整條 line 進來，所以接下來存取同一條 line 的其他字會命中」——
這就是空間局部性被利用的具體方式。**

### 典型的 L1 cache 規格（本節最實用的一段）

> "**A typical core makes most of its accesses to level 1 instruction and data caches (L1I$ and L1D$).
>  The cache size is limited by the desired access time and is typically 8−32 KiB. Because of interactions
>  with the virtual memory system described in the next chapter, each cache way is no bigger than the virtual
>  memory page size, usually 4 KiB. Therefore, the cache generally has 2, 4, or 8 ways, which is sufficient
>  to eliminate most conflict misses. Experience has shown that a 512-bit line size (64 bytes, or 8 double
>  words) is a good tradeoff between spatial locality and cache line transfer time. Hence, a common L1$
>  organization is 16 KiB, built from four 4-KiB ways, each containing 64 64-byte lines, which achieves a
>  miss rate of about 4% on Embench benchmarks. Wally rv32gc and rv64gc configurations use this cache
>  topology.**"
> — p.468

中文解釋：**這段把整章的取捨收斂成一組數字，值得完整記住：**

| 參數 | 典型值 | 決定因素 |
| --- | --- | --- |
| **Cache size** | **8–32 KiB** | **受期望的存取時間限制** |
| **Way size** | **≤ 4 KiB** | **不能大於虛擬記憶體 page size**（第 11 章） |
| **Ways** | **2、4 或 8** | **足以消除大部分 conflict miss** |
| **Line size** | **512 bits（64 bytes）** | **空間局部性 vs 傳輸時間的平衡** |
| **典型組織** | **16 KiB = 4 ways × 4 KiB，每 way 64 條 64-byte line** | |
| **Miss rate** | **約 4%**（Embench） | |

**推導鏈很清楚：
size 由存取時間決定 → way size 由 page size 決定 → 兩者相除得到 way 數。**

**Wally 的 rv32gc 和 rv64gc 就是用這個拓撲。**

**更高層的 cache（p.468）：**
> "**High-performance cores add an L2$ with about 256-1024 KiB capacity. Multicore systems add a L3$ with many
>  megabytes of capacity that is also responsible for maintaining coherence when multiple cores are accessing
>  the same data.**"

（呼應 10.1.6 節：「下一層至少要大 4–8 倍」。）

### Wally 實作摘要

> "**Wally uses a common parameterized module for both instruction and data caches. However, instruction
>  caches are read-only, so they eliminate the write, dirty, and writeback logic. The heart of the cache is
>  an array of cache ways. Each way is indexed by the set (middle bits of the address). The tags from each
>  way are compared to the upper bits of the address. The hit logic checks for a valid way with a matching
>  tag. If a hit occurs, a way selection mux picks the cache line from the matching way. For a read hit, the
>  `subcachelineread` mux picks the word from the line based on the lower bits of the address. For a write
>  hit, the cache writes the line on the next cycle and sets the line's dirty bit. The cache uses a byte mask
>  to specify which bytes in the line to write, depending on the size of the access and the word offset in
>  the low bits of the address.**"
> — p.468

中文解釋：**讀取和寫入的流程摘要：**
```
讀：set 索引 → 各 way 比 tag → hit logic → way selection mux → subcachelineread → word
寫：同樣先比 tag → 下一週期寫 line → 設 dirty bit → 用 byte mask 選 byte
```

**Miss 的處理（p.468）：**
> "**When a cache miss occurs, the `cachefsm` module sequences through a series of steps. The `cacheLRU`
>  module selects the way to replace using a pseudo-LRU algorithm. If the line is valid and dirty, it must be
>  written back to main memory via the AHB bus. The line transfer involves a sequence of consecutive word
>  transfers organized as a burst. The cache then fetches the missing line into a fetch buffer with another
>  AHB bus burst and finally writes the line into the cache. An early return mux saves a cycle from the miss
>  latency of a read data by returning the read data directly from the fetch buffer rather than waiting for
>  it to be written into the cache.**"

**Miss 的完整步驟：
`cacheLRU` 選 victim → dirty 就先 writeback（burst）→ fetch 新 line 進 fetch buffer（burst）
→ 寫進 cache。而 **early return mux 直接從 fetch buffer 回傳，省一個週期**。**

**Flush 與 invalidate（p.468）：**
> "**The cache also has hardware support for flushes and invalidates. Flushes iterate over every line in every
>  way, writing dirty lines back to memory. Cache invalidates clear the cache's valid bits. The `fence.i`
>  instruction enforces coherence between instruction and data caches by flushing the D$ and invalidating the
>  I$.**"

**三者的關係最後再確認一次：
flush = 寫回 dirty；invalidate = 清 valid；`fence.i` = flush D$ + invalidate I$。**

## 所以呢

**第 10 章讓處理器不必每次存取都走慢速的匯流排。**

三件最該帶走的事：

1. **典型 L1 cache 的規格推導鏈**：
   **size 由存取時間決定（8–32 KiB）→ way size 不能超過 page size（4 KiB）
   → 所以是 2/4/8 ways → line size 64 bytes。**
   **常見組織：16 KiB = 4 ways × 4 KiB，miss rate 約 4%。**

2. **三種 miss、三種解法、三種代價**：
   compulsory → 加長 line（但 miss penalty 增加）；
   capacity → 加大 cache（但成本與速度）；
   conflict → 提高 associativity（但複雜度與存取速度）。

3. **Wally 的實作用一個參數化模組同時做 I$ 和 D$**，
   `READ_ONLY_CACHE` 決定要不要寫入、dirty、writeback 邏輯。

**還有一個貫穿全章的觀念：cache 是非架構狀態，
所以它的錯誤不會讓程式跑錯，只會變慢——這就是它需要獨立效能驗證的原因。**
