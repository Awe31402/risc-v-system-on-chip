# 12.5 Examples

> 原書 p.534–544（Chapter 12: Load/Store Unit）
> 涵蓋 12.5.1 Cache Load Hit、12.5.2 Cache Store Hit、12.5.3 Cache Miss、
> 12.5.4 Uncached Access、12.5.5 TLB Miss、12.5.6 TLB Access Fault

## 這節在講什麼

**用六個情境走過完整 LSU 的運作，每個都配一張「高亮資料路徑」的圖。**

**這節的價值在於「把 12.1–12.4 的元件串成動態的流程」**——
前面幾節講的是「有哪些零件」，這節講「一次存取實際上走過哪些零件」。

六個情境由簡到繁：
**load hit → store hit → cache miss → uncached → TLB miss → TLB access fault**

**最該精讀的是 12.5.5 的 TLB miss**——它把 HPTW 的完整動作展開，
而且用了 11.2.1.1 節那個具體的頁表例子。

## 關鍵點

### Cache Load Hit：完整的資料路徑

> "**A load hit, highlighted in blue in Fig. 12.14, begins in the Execute stage using IEUAdrE, the address for
>  accessing the D$'s SRAM. The cache uses the page offset bits, which are never translated, to choose the set in
>  the cache. It reads the data, tags, and status bits. In the Memory stage, the TLB translates the virtual address
>  IEUAdrM to the physical address PAdrM if address translation is enabled; otherwise, PAdrM = IEUAdrM.
>  The cache compares its tags to PAdrM to indicate a hit and outputs all bytes in the cache line on ReadDataLine.
>  The sub-cache line read (SCR) module uses the offset bits of PAdrM to select the word within ReadDataLine to
>  produce ReadDataWord. Finally, because it is a hit, the mux passes ReadDataWord to ReadDataWordMuxM, optionally
>  performs an endianswap (ES), and selects the final ReadDataM using the `subwordread` (SWR) module.
>  The `cachefsm` remains in the Access state throughout the load hit.**"
> — p.534

中文解釋：**完整的路徑，值得背下來當作 LSU 的「標準流程」：**

```
Execute 級：
  IEUAdrE 的 page offset 位元 → 選 cache set（不需轉譯！）

Memory 級：
  IEUAdrM ──(TLB)──→ PAdrM          （轉譯關閉時 PAdrM = IEUAdrM）
  cache 讀出 data/tag/status
  比對 tag 和 PAdrM → Hit
  ReadDataLine（整條 line）
    → SCR（用 PAdrM 的 offset 選字）→ ReadDataWord
    → mux → ReadDataWordMuxM
    → ES（端序轉換）
    → SWR（subword 讀取）→ ReadDataM

cachefsm 全程停在 Access 狀態
```

**三個關鍵時機：**
1. **set 索引在 Execute 級就用了**（用未轉譯的 page offset）
2. **tag 比對在 Memory 級**（等 TLB 給出 `PAdrM`）
3. **`cachefsm` 完全不動**——命中是「零成本」的

### Cache Store Hit：只讀 tag

> "**Like loads, a store begins by reading the cache SRAM and optionally translating the virtual address IEUAdrM to
>  the physical address PAdrM. The cache reads only the tags, not the data. It compares PAdrM to the Tag and checks
>  the valid bit to detect a hit. On a hit, the cache sets up the CacheSet mux using PAdrM. In parallel,
>  WriteDataM travels through the `subwordwrite` and `endianswap` muxes (labeled SWW and ES) and is written into
>  the SRAM on the clock edge at the end of the Memory stage.**"
> — p.535

中文解釋：**和 load 的關鍵差異：`store 只讀 tag，不讀 data`。**
（呼應 10.4.2.2 節：這讓連續 store 不用 stall。）

**Byte mask 的兩層展開（p.535）：**
> "**Not shown, the `subbytemask` (SBM) module sets the corresponding byte write enables for the subword and then
>  the cache expands the byte write enables to the full width of the cache line in order to write WriteDataM into
>  the correct location in the cache line.**"

**兩層：`ByteMask`（字內哪些 byte）→ `LineByteMask`（整條 line 內哪些 byte）。**

### 連續存取的時序（Fig. 12.16）

中文解釋：**Code：load 0x10 → store 0x18 → load 0x20 → load 0x08，全部命中同一個 set（`CacheSet = 0`）。**

**從 Fig. 12.16（p.537）讀出的時序（p.535–536 說明）：**

| Cycle | 動作 |
| --- | --- |
| 1 | **Load 1**：比對 tag 並讀資料 |
| 2 | **Store**：比對 tag |
| **3** | **Store 寫資料；Load 2 被 stall 一個週期** |
| 4 | Load 2：比對 tag 並讀資料 |
| 5 | Load 3：比對 tag 並讀資料 |

**Stall 的原因（p.535–536）：**
> "**The second load stalls for a cycle because of the store delay hazard caused by a store writing the cache data
>  array during the Writeback stage and the following load attempting to read the cache data array in the same cycle
>  in the Memory stage. In cycle 3, the controller detects the hazard in the Decode stage when a store is executing
>  and a load is in the Decode stage. It asserts StallD to delay load 2 by a cycle and to insert a pipeline bubble
>  between the two instructions. The last load has single-cycle throughput.**"

**「store 後接 load 要 stall 一個週期」再次出現**
（呼應 7.2.2.3、10.4.2.3、12.4.1 節——**這個 hazard 在全書出現了四次**）。

**一個具體的數值例子（p.536）：**
> "**An 8-byte word is written, so ByteMask = 11111111 (0xFF), and the fourth 8-byte word of the 8-word line is
>  written, so LineByteMask expands this to 0x00000000FF000000 to indicate which 8 of the 64 bytes in the line
>  should be written.**"

### Cache Miss

> "**On a load or store miss, the cache fetches the missing line from the next level of memory over the bus, as
>  described in Section 12.2.1.... The cache outputs the cache line address, CacheBusAdr. `ahbcacheinterface` outputs
>  BeatCount to sequence through the words of the cache line and to increment LSUHADDR, then raises CacheBusAck when
>  FetchBuffer contains the cache line.**"
> — p.536

中文解釋：**三個訊號的分工：`CacheBusAdr`（起始位址）、
`BeatCount`（逐字遞增）、`CacheBusAck`（完成）。**
（時序圖見 Fig. 12.6，12.2.1 節已詳述。）

### Uncached Access

> "**The LSU makes uncached accesses to uncacheable devices such as I/O peripherals and also in cacheless systems with
>  external memory.... Section 12.3.1 reintroduces the PMA checker to select between cached and uncached bus access.**"
> — p.537

中文解釋：**Fig. 12.21（p.540）的時序，load 後接 store，都是 uncached（位址 0x10000002 和 0x10000000）：**

| Cycle | 發生什麼 |
| --- | --- |
| **1** | **Uncached load 開始**，從周邊位址 0x10000002 載入一個 byte，`LSUTRANS = 2` |
| **2** | **周邊需要更多時間 → 拉低 `LSUHREADY`**（Peripheral Busy） |
| **3** | **周邊輸出 `HRDATA = 0xC1` 並拉高 `LSUHREADY`** |
| **4** | **`buscachefsm` 把資料捕捉進 `FetchBuffer[0]` 並輸出 `ReadDataM`** |
| **5** | **Uncached store 開始**，位址 0x10000000，`LSUTRANS = NON_SEQ (2)`，`LSUHWRITE` assert，`WriteDataM = 0x55` |
| **6** | 周邊寫入慢，插入一個 wait state |
| **7** | **`LSUHREADY` 升起表示周邊完成寫入** |

**注意 `UncacheableM` 訊號在整個期間都是高的，而 `LSUStall` 也是。**

**三個 `buscachefsm` 狀態走一遍：Adr → Data → Mem3**（單字存取，不是 burst）。

### TLB Miss：最完整的情境（本節精華）

> "**The LSU processes TLB misses by fetching the missing PTE in the same way it would process a usual memory read.**"
> — p.540

中文解釋：**書上用 Fig. 11.10(b) 那個具體的 Sv32 頁表走一遍（p.541），
這段值得完整跟：**

**設定：**
- RV32、Sv32 虛擬記憶體
- **`satp` 的 PPN = 0x8000D** → **level 1 頁表在實體位址 0x8000D000**
- 程式要從**虛擬位址 0x00001234** 載入值 15151515
- **這個 PTE 不在 DTLB 裡**

**HPTW 的走訪過程：**
```
1. 從虛擬位址取出 VPN1 = 0、VPN0 = 1
   （Sv32：VA[31:22] = VPN1，VA[21:12] = VPN0，見 Fig. 11.8）

2. 讀 level 1 PTE：
   位址 = satp + VPN1 × 4 = 0x8000D000 + 0 = 0x8000D000
   PTE 值 = 0x20004CC1
   → 這是一個指向 level 0 頁表的有效 PTE，PPN = 0x080013

3. 讀 level 0 PTE：
   位址 = 0x08001300 + VPN0 × 4 = 0x080013004
   PTE 值 = 0x202000DF
   → 這是有效的 leaf PTE，PPN = 0x080800

4. HPTW 把這個 PTE 寫進 DTLB
5. LSU 重播（replay）那個 load
```

**（注意第 3 步的位址：0x080013000 + 1×4 = 0x080013004。）**

**Fig. 12.23（p.542）的完整時序，這張圖把 HPTW 的動作展開：**

| Cycle | 發生什麼 |
| --- | --- |
| **1** | **`DTLBMissM = 1`（TLB Miss）**；`SelHPTW` 升起；`LSUStall` 升起 |
| **2–3** | **讀 level 1 PTE**：`HPTWAdr = 0x8000D000`，`WalkerState` 走 L1_Adr → L1_Rd，**在 cache 命中**，`ReadDataM = 0x20004CC1` → 存進 `PTE` |
| **4** | **`IHADRM = 0x080013004`**，MMU 選它當 `PAdrM`；`WalkerState` 進 L0_Adr |
| **5** | **cache 用 `CacheSet = 0` 存取但 miss**（`DCacheStall` 升起） |
| **…（到 25）** | **cache 從匯流排抓取那條 line** |
| **26** | **`ReadDataM = 0x202000DF`**；`WalkerState` 進 **Leaf**；**`DTLBWriteM` 升起把 PTE 寫進 DTLB** |
| **27** | **重播原本的存取**：DTLB 命中，**`PAdrM = 0x80800234`**，`ReadDataM = 0x15151515`（load hit） |

**（p.543：「這個位址可能觸發另一次 cache miss 和抓取，
但為了節省篇幅，圖中顯示為 load hit。」）**

**三個值得注意的細節：**
1. **level 1 的 PTE 讀取在 D$ 命中（快），level 0 的 miss（慢）**——
   這就是 12.3.4 節說「PTE 可能在 D$ 裡」的實際效益
2. **`SelHPTW` 全程為高**——所以中斷被停用（`CommittedM`）
3. **最後要「重播」原本的存取**——HPTW 只負責填 TLB，不直接完成 load

### TLB Access Fault：A/D 位元的硬體更新

> "**When the processor accesses a page, it must update the access bit (A) if it is 0 and the dirty bit (D) if it is 0
>  on a write, as described in Section 11.4.2.2. If the hardware supports page table updates
>  (SVADU_SUPPORTED = 1), the HPTW issues a write to the PTE in memory while concurrently updating the TLB.
>  Otherwise, the system generates a page fault, and the operating system performs the update in software.**"
> — p.543

中文解釋：**書上的具體例子（p.543）：**

**設定：store 到虛擬位址 0x00801450（VPN = 0x00801）**
- **VPN 0x00801 在 TLB 裡**（所以不是 TLB miss）
- **但那個 PTE 是 0x20200817（PPN = 0x080802，`DAGU_XWRV = 0001_0111`）
  在實體位址 0x80015004，其中 `A = D = 0`**

**硬體支援時的動作：**
```
1. 設定 A 和 D 位元
2. 新的 PTE = 0x202008D7（DAGU_XWRV = 1101_0111）
3. 寫回實體位址 0x80015004
```

**（注意 `DAGU_XWRV` 從 `0001_0111` 變成 `1101_0111`：
D 從 0 變 1、A 從 0 變 1。）**

**Fig. 12.24（p.543）的時序（p.543–544）：**

| Cycle | 發生什麼 |
| --- | --- |
| **1** | **HPTW 設 `IHAdrM = 0x80015004`**，被選為 `PAdrM`；cache 選 `CacheSet = 0` |
| **2** | **cache 偵測到命中，設定 `LSUWriteDataM = 0x202008D7`** |
| **3** | **cache 把這個值寫進資料陣列；同時 HPTW 用新的 PTE 更新 TLB** |

**兩個寫入同時發生（記憶體和 TLB）——
這就是 11.4.2.2 節說「兩次寫入必須原子」的實際樣貌，
而原子性由 `SelHPTW` assert `CommittedM` 保證。**

## 名詞表

| 名詞 | 意思 |
| --- | --- |
| `IEUAdrE` / `IEUAdrM` / `PAdrM` | Execute 級位址（選 cache set）/ Memory 級虛擬位址 / 實體位址（比對 tag） |
| SCR / ES / SWR / SWW / SBM | sub-cache line read / endianswap / subwordread / subwordwrite / subbytemask |
| `ReadDataWordMuxM` | cache 命中時來自 `ReadDataWord`，uncached 時來自 `FetchBuffer` |
| `UncacheableM` | PMA 判定該位址不可 cache |
| `DTLBMissM` / `DTLBWriteM` | DTLB miss / 把新 PTE 寫進 DTLB |
| `WalkerState` | HPTW 的狀態：Idle → L1_Adr → L1_Rd → L0_Adr → L0_Rd → Leaf |
| `IHAdrM` | HPTW 走訪時的實體位址（會被選為 `PAdrM`） |
| Replay | TLB 填好後重新執行原本的記憶體存取 |

## 所以呢

**這節把 12.1–12.4 的靜態結構變成六個動態流程。四件最該帶走的事：**

1. **Load hit 的標準路徑**：
   **Execute 級用未轉譯的 page offset 選 set → Memory 級 TLB 給出 `PAdrM` 並比對 tag
   → SCR 選字 → ES 轉端序 → SWR 取 subword。**
   **`cachefsm` 全程停在 Access——命中是零成本的。**

2. **Store 只讀 tag 不讀 data**，所以連續 store 不用 stall，
   **但 store 後接 load 要 stall 一個週期**（這個 hazard 在全書出現四次）。

3. **TLB miss 的完整流程**：
   **HPTW 逐層讀 PTE（可能在 D$ 命中也可能 miss）→ 寫進 TLB → 重播原本的存取。**
   **`SelHPTW` 全程為高，所以中斷被停用。**

4. **A/D 位元的硬體更新是「同時寫記憶體和 TLB」**，
   原子性由 `CommittedM` 保證。
