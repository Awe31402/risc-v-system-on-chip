# 10.2 RISC-V Practices

> 原書 p.442（Chapter 10: Caches）

## 這節在講什麼

**很短，只有一個項目清單：RISC-V 架構特有的六個 cache 設計議題。**

**這節的價值是「地圖」——它把 cache 和其他章節的關聯一次列清楚。**
六個議題裡有五個指向別的章節，只有最後一個（Zi64b 擴充）是本節自己交代的。

## 關鍵點

### 六個 RISC-V 特有的 cache 議題

> "In addition to handling fetches, loads, and stores, RISC-V caches have several design issues specific to
>  the architecture:"
> — p.442

中文解釋：**逐項看，每一項都有一個具體的技術後果：**

**（1）原子記憶體操作（AMO）**
> "**Atomic memory operations (AMOs) read a memory location, modify it, and write back to the same location
>  in one indivisible, uninterruptable operation such that no other operation can access the memory between
>  the read and write. This is discussed in Chapter 17.**"

**「不可分割、不可中斷」對 cache 的意義：
一個 AMO 在 cache 上是「讀 + 改 + 寫」三個動作，
但中間不能讓別的核心插進來。**
（呼應 9.1.4 節的 bus locking。）

**（2）I$ 和 D$ 之間的一致性**
> "**Coherency between the I$ and D$ is maintained by flushing the D$ and invalidating the I$ using a
>  `fence.i` instruction. Cache invalidation and flushes are discussed in Sections 10.4.2.6 and 10.4.5.4.**"

**這是 10.1.8 節那個機制的 RISC-V 具體做法。**
（也呼應 8.4.5.5 節的 `fence.i` hazard 處理。）

**（3）PMA checker 決定可不可以 cache**
> "**A physical memory attributes (PMA) checker indicates whether an address is cacheable. For example,
>  memory-mapped peripherals cannot be cached because their value may change because of external events,
>  such as a voltage changing on a general-purpose input/output (GPIO) pin.**"

**這一項最重要，因為理由很根本：**

**周邊的值會因為外部事件而改變，而 cache 不知道。**
**所以 memory-mapped 周邊必須標記為 uncacheable。**

（這也呼應 9.5.5 節的 nonidempotent 讀取——
讀 UART 的接收緩衝器會清空它，這種操作絕對不能被 cache 攔截。）

**PMA 在第 11.4.1.1 節，LSU 處理 uncacheable 位址的邏輯在第 12.3.1 節。**

**（4）壓縮指令會跨越 cache line**
> "**When compressed instructions are supported, instructions may wrap across cache lines. Such spills will
>  be handled in Section 14.3.3.**"

**為什麼會跨越：C 擴充的指令是 2 bytes，所以 32-bit 指令可能從 line 的最後 2 bytes 開始，
另外 2 bytes 在下一條 line。**
**這叫 *spill*，要抓兩次才能組出一條指令。**
（呼應 2.5 節：有 C 擴充所以指令只需要 2-byte 對齊。）

**（5）OS 需要知道 cache line 大小**
> "**The operating system (OS) likes to know the size of a cache line so it can allocate memory sensibly
>  aligned to the cache. The Zi64b RISC-V extension indicates that cache lines are 64 bytes. This size has
>  become an industry standard because it is a good tradeoff between spatial locality and time to fetch a
>  missing cache line. Wally defaults to 64-byte (512-bit) cache lines and thus implements Zi64b by
>  default.**"

**三件事：**
- **OS 要知道 line size 才能把記憶體配置對齊到 cache**
  （避免一個資料結構橫跨兩條 line，造成不必要的 miss）
- **`Zi64b` 擴充宣告 cache line 是 64 bytes**
- **64 bytes 已成為業界標準**——理由是**「空間局部性」和「抓一條 miss line 的時間」之間的好取捨**
  （呼應 10.1.2 節：line 太長反而傷效能，以及 Fig. 10.7 的實驗曲線）

**Wally 預設 64-byte（512-bit）line，所以預設就實作了 Zi64b。**

## 名詞表

| 名詞 | 意思 |
| --- | --- |
| **AMO** | Atomic memory operation。讀-改-寫為一個不可分割、不可中斷的操作（第 17 章） |
| `fence.i` | flush D$ 並 invalidate I$，維持指令與資料 cache 的一致性 |
| **PMA checker** | Physical memory attributes 檢查器。**指出某位址是否可 cache** |
| **Uncacheable** | 不可 cache。**memory-mapped 周邊必須如此**，因為其值會因外部事件改變 |
| **Spill** | 壓縮指令跨越 cache line 邊界，需要兩次抓取（第 14.3.3 節） |
| **Zi64b** | RISC-V 擴充，宣告 cache line 為 64 bytes；**Wally 預設實作** |

## 所以呢

**這節是 cache 和其他章節的關聯地圖：**

| 議題 | 在哪一章 |
| --- | --- |
| AMO | **第 17 章** |
| `fence.i` 的 flush/invalidate | 10.4.2.6、10.4.5.4 節 |
| **PMA（可不可 cache）** | **11.4.1.1、12.3.1 節** |
| 壓縮指令的 spill | **14.3.3 節** |
| Zi64b（64-byte line） | 本節 |

**最該記住的一件事：memory-mapped 周邊必須是 uncacheable，
因為它們的值會因為外部事件而改變——cache 不知道，就會給出過期的資料。**

**以及一個業界標準：cache line = 64 bytes，
這是「空間局部性」和「填滿一條 line 的時間」之間的最佳平衡點。**
