## 關鍵點

### 這一步的變化

> "**This section integrates a D$ into the LSU, as shown in Fig. 12.3, if DCACHE_SUPPORTED = 1 in config.vh.
>  Key features include servicing load and store hits, fetching lines from the external bus for cache misses, and
>  writing back dirty evicted lines. Compared to Fig. 9.31, this LSU replaces the DTIM and `ahbinterface` modules
>  with cache and `ahbcacheinterface` modules. It temporarily drops the PMA logic because this version of the LSU
>  does not yet support uncached accesses; this capability will be restored in Section 12.3.1. The LSU retains the
>  subword read/write (SWR/SWW) and endian swap (ES) modules.**"
> — p.518

中文解釋：**三個替換 + 一個暫時移除：**

| 動作 | 內容 |
| --- | --- |
| **替換** | DTIM → **cache** |
| **替換** | `ahbinterface` → **`ahbcacheinterface`**（支援 burst） |
| **暫時移除** | **PMA 邏輯**（因為這版還不支援 uncached 存取，12.3.1 節會加回來） |
| **保留** | SWR / SWW / ES |

**注意「暫時移除 PMA」這個教學手法**——先簡化，之後再補齊。

### Cache 存取的兩階段時序

> "**All memory operations begin with the IEU calculating the address IEUAdrE in the Execute stage. On the rising
>  edge starting the Memory stage, loads and stores both read the cache's ways using the lower (set) bits of
>  IEUAdrE. Loads read both the tag and data using CacheSetTag and CacheSetData, but stores read only the tags,
>  using CacheSetTag. If one of the tags is valid and matches the upper bits of IEUAdrM, the cache hits.
>  Load hits output ReadDataM in the Memory stage, and store hits set up to write into the matching way
>  (using LSUWriteDataW and CacheSetData = the lower (set) bits of IEUAdrM) on the next rising clock edge, at the
>  start of the Writeback stage. Both loads and stores perform endian and subword muxing using the `endianswap`
>  (ES) and `subwordread/write` (SWR/SWW) modules.**"
> — p.518–519

中文解釋：**Load 和 store 的時序不對稱，這是關鍵：**

| | Load | Store |
| --- | --- | --- |
| **Memory 級開始** | **讀 tag 和 data**（`CacheSetTag` = `CacheSetData` = `IEUAdrE` 的 set 位元） | **只讀 tag** |
| **Memory 級** | **輸出 `ReadDataM`** | 設定寫入（`CacheSetData` = `IEUAdrM` 的 set 位元） |
| **Writeback 級開始** | — | **寫進 matching way** |

**「store 只在 Address 階段讀 tag」——這就是 10.4.2.2 節說的
「讓連續 store 不用 stall」的最佳化。**

**（p.519 邊欄的簡化說明：**「cache 的 `CacheSet{Tag/Data}` 輸入分別存取 tag 和 data 陣列，
**在 LSU 的圖和時序圖（如 Fig. 12.2、12.3）中簡化成 `CacheSet`。**」**）

### `ahbcacheinterface` 的角色

> "**Cache misses stall the pipeline while fetching the missing line over the bus. Fig. 12.4 shows how the
>  `ahbcacheinterface` manages communication between a cache and the EBU. At a high level, the `cachefsm` makes a
>  bus request to writeback or fetch an entire cache line by placing the line address on CacheBusAdr and raising
>  the write or read bit of CacheBusRW. For a write-back, the cache sends the evicted line ReadDataLine one word at
>  a time over ReadDataWord, and the `ahbcacheinterface` generates an AHB write burst. For a line fetch, the
>  `ahbcacheinterface` generates an AHB read burst and accumulates the words into FetchBuffer.
>  `ahbcacheinterface` raises CacheBusAck when the burst completes.**"
> — p.519

中文解釋：**握手協定很簡單：**
```
cachefsm → CacheBusAdr（line 位址）+ CacheBusRW（讀或寫）
ahbcacheinterface → 產生 AHB burst
完成 → CacheBusAck
```

**兩個方向的資料路徑（Fig. 12.4，p.519）：**
- **Writeback**：`ReadDataLine` → `ReadDataWord`（用 `SelBusBeat` 逐字選）→ `PreHWDATA` → `HWDATA`
- **Fetch**：`HRDATA` → 用 decoder 依 `BeatCountDelayed` 寫進 `FetchBuffer` 的對應字

### Burst 的機制

> "**`ahbcacheinterface` implements burst transfers, introduced in Section 9.2.2.5, to fetch or write consecutive
>  addresses in the cache line. Each access within the sequence is called a *beat*. A burst transfer can maximize
>  external memory throughput because large RAMs (e.g., off-chip DRAM) are faster at reading and writing
>  consecutive addresses than random addresses. The HBURST and HTRANS signals tell the RAM controller to expect and
>  optimize for such consecutive accesses. AHB interfaces pipeline their Address and Data phases, obtaining a burst
>  throughput of one word per cycle after some initial RAM latency.**"
> — p.520

中文解釋：**Burst 的效益：初始延遲之後，每週期一個字。**
（呼應 9.2.2.5 節：DRAM 在開啟的 page 內讀取快很多。）

**Burst 參數的計算（p.520）：**
> "**AHB burst transfers use a sequence of beats to access consecutive addresses. HSIZE defines the bus width for
>  a beat, and HBURST defines the number of beats. Wally has a bus width of AHBW (typically equal to XLEN).
>  Each beat uses the full bus width, so HSIZE encodes AHBW (HSIZE = 011 for 32 bits or 100 for 64 bits).
>  The number of beats in the burst is the cache line length (LINELEN) divided by AHBW. HADDR is incremented by the
>  bus width (in bytes) after each beat.**"

**Table 12.1（p.521）的三個組態：**

| Configuration | LINELEN | AHBW | HBURST | HSIZE |
| --- | --- | --- | --- | --- |
| N/A | 128 | 32 | **011（4 beats）** | 011（32 bits） |
| **rv32gc** | **512** | **32** | **111（16 beats）** | 011（32 bits） |
| **rv64gc** | **512** | **64** | **101（8 beats）** | 100（64 bits） |

**beat 數 = LINELEN / AHBW：512/32 = 16、512/64 = 8。**

**兩個計數器（p.520–521）：**
> "**Because AHB pipelines burst requests, the module tracks the Address phase beat using BeatCount and the Data
>  phase beat using BeatCountDelayed. During the Address phase, `ahbcacheinterface` sends the memory address
>  HADDR = CacheBusAdr + BeatCount << (AHBW/8). During the Data phase, the AHB cache interface stores HRDATA into
>  FetchBuffer at BeatCountDelayed.**"

**因為 AHB 有 pipeline，所以位址階段和資料階段的 beat 編號差一個——需要兩個計數器。**

**（p.520 邊欄：**「AHB cache 介面的 bus cache FSM 有一個參數 **`BURST_EN`，預設為 1**，啟用 burst 傳輸。
**可以停用以測試非 burst 傳輸。**第 23.2.2.5 節比較了使用 DDR3 記憶體的 FPGA 實作
在 burst 和非 burst 下的效能。」**）

### `buscachefsm`：五狀態機

> "**Fig. 9.23 shows the `busfsm` for a basic AHB interface, sequencing through Adr, Data, and Mem3 phases to read
>  or write a single word over the bus. By adding a cache to the system, the bus must now support both single-word
>  accesses (for peripheral accesses) and multiword bursts (for cache line fetches and writebacks). Fig. 12.5 shows
>  the `buscachefsm`, an enhanced version of `busfsm`. It adds the CacheFetch and CacheWriteback states.**"
> — p.521

中文解釋：**Fig. 12.5（p.522）在 `busfsm` 的三個狀態上加了兩個：**

```
                 ┌─ Adr ─┐
      ┌──────────┤       ├──────────┐
      ↓          ↓       ↓          ↓
 CacheFetch    Data    Mem3    CacheWriteback
（burst 讀）  （單字）        （burst 寫）
```

**Cache fetch 的流程（p.521）：**
> "**Cache bus requests start in the Adr state. If the cache requests a line fetch by asserting CacheBusRW[1] and
>  the bus is free (HREADY = 1), the FSM enters the CacheFetch state and starts an AHB read burst by setting
>  HTRANS = 2 (NON_SEQ) to indicate the first beat in the request. HBURST is set to the number of beats in the
>  burst as shown in Table 12.1. HWRITE is set to 0. If the bus is not ready, the FSM remains in the Adr state.**"

> "**The `ahbcacheinterface` uses a BeatCount counter to step through the beats in the burst each cycle the bus is
>  ready (HREADY). For example, a DDR memory may have many wait states to service the first beat but then have
>  single-cycle throughput for each subsequent beat. A comparator raises FinalBeatCount at the end of the burst.**"

> "**The FSM remains in the CacheFetch state until the burst completes. After the first beat completes, HTRANS is
>  set to 3 (SEQ) to signal sequential transfers in the burst. Each beat's HRDATA is written into the next word of
>  FetchBuffer. When the burst completes its last beat, the FSM sends the cache CacheBusAck, and the FSM returns to
>  the Adr state to wait for the next request.**"

**關鍵：第一拍 `HTRANS = 2`（NONSEQ），後續 `HTRANS = 3`（SEQ）。**

**一個省週期的最佳化（p.521–522）：**
> "**If the memory operation is a load miss, the cache writes the cache line into its SRAM but also bypasses the
>  SRAM to directly return ReadDataWord from the FetchBuffer to the core. Store misses merge the write data
>  (FinalWriteDataM) with the FetchBuffer signal according to ByteMask before writing the line into the cache.**"

（呼應 10.4.5.3 節的 early return mux。）

### 完整的時序範例：load miss

中文解釋：**Code Example 12.1（p.523）和 Fig. 12.6（p.523）：**
```asm
ld x1, 0x28(x0)    # miss
ld x2, 0x20(x0)    # hit（同一條 line）
sd x1, 0x30(x0)    # hit（同一條 line）
```
**假設 XLEN = 64、32-byte（4-word）cache line、64-bit（1-word）匯流排。
第一個 load miss，cache 抓取含 0x20–0x3F 的那條 line。**

**從 Fig. 12.6 讀出的時序：**

| Cycle | 發生什麼 |
| --- | --- |
| **1** | `IEUAdrM = 0x28`，`cachefsm` 在 Access 狀態 → **Load 1 Miss** |
| **1–2** | **`LSUHTRANS = 2`（NONSEQ）、`LSUHBURST = 3`（4-beat）、`LSUHADDR = 0x20`**；`buscachefsm` 進 Cache Fetch |
| **2–3** | **Bus Not Ready**（`LSUHREADY` 低，兩個 wait state） |
| **4–8** | **Fill FetchBuffer**：`LSUHRDATA` 依序給 `[20]`、`[28]`、`[30]`、`[38]`，`BeatCountD` 走 0→1→2→3，寫進 `FetchBuffer[0..3]` |
| **8** | **Write Line to Cache**（`cachefsm` 進 WriteLine → Adr Setup → Access） |
| **9** | **Load 1 Read Data**：`ReadDataM = [28]` |
| **10** | **Load 2 Read Data**：`ReadDataM = [20]`（命中） |
| **11** | **Store 1 Write Data**（命中） |

**「第一個字有兩個 wait state，後三個字單週期吞吐」——這就是 burst 的效益。**

### Cache Line Writeback

> "**The `buscachefsm` handles cache line writebacks similar to how it handles fetches. The CacheWriteback state
>  initiates a write burst similar to the fetch burst.**"
> — p.523

中文解釋：**Fig. 12.7（p.524）的時序：先寫回 dirty line（位址 0x5000），再抓 missing line（0x7000）。**

| Cycle | 發生什麼 |
| --- | --- |
| **0–3** | **Writeback Dirty Cache Line**：`LSUHWRITE = 1`，`LSUHADDR` 走 5000→5008→5010→5018，
`LSUHWDATA` 依序送出 200、208、210、218 |
| **4–8** | **Fetch Cache Line**：`LSUHADDR` 走 7000→7008→7010→7018，
`LSUHRDATA` 收到 100、108、110、118，寫進 `FetchBuffer[0..3]` |

**`SelBusBeat` 的作用（p.525）：**
> "**The BeatCount counter controls the SubCachelineRead (SCR) multiplexer (Fig. 12.4) by asserting SelBusBeat
>  during writebacks to step through the words of the cache line to write a 64-bit word over the bus in each beat.**"

**`CacheBusRW` 的編碼（p.525）：`1（01₂）` = writeback、`2（10₂）` = fetch。**

**一個很漂亮的最佳化（p.525）：**
> "**Observe from Fig. 12.5 that the `buscachefsm` transitions directly from the CacheWriteback state to the
>  CacheFetch state without an Adr state, pipelining the last beat Data phase of the writeback with the first beat
>  Address phase of the fetch and saving a cycle of latency. Similarly, the `buscachefsm` can write back multiple
>  lines consecutively without intervening idle states; this occurs during a cache flush, as described in
>  Section 10.4.5.4.**"

**「從 CacheWriteback 直接跳到 CacheFetch，不經過 Adr 狀態」——
利用 AHB 的 pipeline 特性，把寫回的最後一拍資料階段和抓取的第一拍位址階段重疊，省一個週期。**

**這個最佳化在 cache flush 時特別有價值**（連續寫回多條 line 而不插入 idle 狀態，
呼應 10.4.5.4 節那個「4,096 個週期」的計算）。

### Burst EBU

> "**The EBU from Section 9.5.2 arbitrates between the IFU and LSU AHB requests, with the LSU having priority.
>  Fig. 12.8 enhances the EBU to support burst transactions, with the changes shown in blue. The IFU's
>  `controllerinput` module adds a register and multiplexers to save and restore the IFU burst request, IFUHBURST,
>  during concurrent IFU and LSU requests.**"
> — p.525

中文解釋：**三個改動（Fig. 12.8，p.526）：**

**（1）多存一個 `IFUHBURST`**（原本只存 HADDR、HSIZE、HWRITE、HTRANS）

**（2）用 AND 閘把 `HREADY` 強制為 0：**
> "**Both the IFU's and LSU's `controllerinput` modules add an AND gate to force their HREADY signals (IFUHREADY or
>  LSUHREADY) to 0 when the other module has a burst in progress, which delays new requests until the in-flight
>  request completes.**"

**（3）產生 `IFUReq` / `LSUReq`：**
> "**The `controllerinput` module ORs the HTRANS bits to signal a request (IFUReq or LSUReq). HTRANS is 2 (NON_SEQ)
>  for the first word of a burst request and 3 (SEQ) during the remainder of the request.**"

**`ebufsmarb` 的增強（p.525）：**
> "**It adds a beat counter to track when the burst completes. The lookup table (LUT) decodes the number of beats
>  from HBURST, according to Table 12.1. When an LSU request arrives while the IFU is in the midst of a burst, the
>  LSUDisable signal asserts to delay the LSU request.**"

### 那個讓 Wally 開機當掉的 bug（本節最有價值的部分）

**p.526 邊欄講了一個完整的除錯故事，值得完整讀：**

> "**In its initial design, the EBU could disable IFU requests only, not LSU requests (see Fig. 9.25). In a system
>  without virtual memory, this worked, because concurrent LSU and IFU requests only occurred in the same cycle,
>  and the LSU always had precedence.**"

> "**However, in a system with virtual memory, LSU requests can occur after an IFU request is in flight because page
>  table walks occur during a stalled pipeline.**"

> "**For example, suppose a DTLB miss and I$ miss occur in the same cycle. The DTLB miss triggers a page table walk,
>  and the I$ miss causes an IFU AHB request. While the IFU request is in flight, the HPTW traverses the page tables
>  using the D$. The HPTW's first PTE access hits in the D$. However, its second access misses, which generates an
>  LSU AHB request to fetch the missing cache line. Because LSU requests were not disabled and the LSU has
>  precedence, the LSU request preempts the existing IFU cache line fetch, leaving stale instructions in the I$.
>  This caused Wally to hang during Linux boot.**"

> "**To fix this, the EBU added the IFUReq and LSUDisable signals. LSUDisable delays the LSU request in the example
>  above until the IFU transaction completes. This was one of the most difficult bugs to figure out while designing
>  Wally.**"

中文解釋：**這是全書最好的「整合階段才會出現的 bug」案例。把因果鏈整理出來：**

```
1. 原本的設計假設：「LSU 和 IFU 的請求只會在同一週期發生，而 LSU 優先」
   → 所以只需要停用 IFU 的請求
2. 但加了虛擬記憶體之後，這個假設不成立：
   → 頁表走訪發生在 pipeline stall 期間
   → 所以 LSU 的請求可以在 IFU 請求「進行中」才出現
3. 具體情境：
   - DTLB miss 和 I$ miss 同一週期發生
   - I$ miss 發出 IFU 的 AHB burst
   - 同時 DTLB miss 觸發頁表走訪
   - HPTW 的第一次 PTE 存取在 D$ 命中（很快）
   - HPTW 的第二次存取 miss → 發出 LSU 的 AHB 請求
   - LSU 優先 → 搶走正在進行的 IFU cache line fetch
   - → I$ 裡留下過期的指令
   - → Wally 開機 Linux 時當掉
4. 修法：加 IFUReq 和 LSUDisable，讓 LSU 的請求等 IFU 的交易完成
```

**三個教訓：**
1. **「LSU 優先」這個規則在單獨看時是對的（防 deadlock，9.5.2 節），
   但和虛擬記憶體組合後產生了新問題。**
2. **這種 bug 只在「整合之後」才出現**——
   單獨測 EBU、單獨測 MMU 都不會發現。
   （呼應 5.1.3 節：系統層級測試才抓得到整合 bug。）
3. **書上說「這是設計 Wally 時最難找出的 bug 之一」**——
   而且症狀是「開機 Linux 時當掉」，離根本原因非常遠。

## 名詞表

| 名詞 | 意思 |
| --- | --- |
| `ahbcacheinterface` | 支援 burst 的 AHB 介面；含 `buscachefsm`、`BeatCount`、`FetchBuffer` |
| **Beat** | burst 中的一次傳輸；**beat 數 = LINELEN / AHBW** |
| `HBURST` / `HSIZE` | burst 的拍數 / 每拍的匯流排寬度 |
| **`BeatCount` / `BeatCountDelayed`** | 位址階段的 beat 編號 / 資料階段的（**因為 AHB 有 pipeline 所以差一拍**） |
| **`buscachefsm`** | 五狀態：Adr、Data、Mem3、**CacheFetch**、**CacheWriteback** |
| `FinalBeatCount` | burst 最後一拍的旗標 |
| `SelBusBeat` | writeback 時讓 SCR mux 依 `BeatCount` 逐字輸出 |
| `CacheBusRW` | 1（01₂）= writeback、2（10₂）= fetch |
| `BURST_EN` | 參數，預設 1；可停用 burst 以測試非 burst 傳輸 |
| **`IFUReq` / `LSUDisable`** | **修正「LSU 搶走進行中的 IFU burst」那個 bug 的訊號** |

## 所以呢

**這節把 D$ 裝進 LSU，並讓匯流排支援 burst。三件最該帶走的事：**

1. **Burst 的效益**：初始延遲後每週期一個字。
   **rv64gc 是 8 拍 × 64-bit，rv32gc 是 16 拍 × 32-bit**（都是 512-bit line）。
   **需要兩個計數器（`BeatCount` 和 `BeatCountDelayed`），因為 AHB 有 pipeline。**

2. **兩個省週期的最佳化**：
   **load miss 直接從 `FetchBuffer` 回傳**（不等寫進 cache）；
   **writeback 直接跳到 fetch 不經 Adr 狀態**（重疊最後一拍和第一拍）。

3. **那個 bug 的故事**（p.526 邊欄）：
   **「LSU 優先」這個規則加上虛擬記憶體之後，
   讓 HPTW 的 LSU 請求搶走了進行中的 IFU burst，留下過期指令，開機 Linux 當掉。**
   **這是「整合階段才會出現」的 bug 的完美案例——
   單獨測 EBU 或 MMU 都發現不了。**
