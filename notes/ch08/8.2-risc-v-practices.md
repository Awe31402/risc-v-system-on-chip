## 關鍵點

### Trap 的九個步驟（本節最該背的東西）

> "The privileged specification also defines the causes and handling of traps.... As an overview,
>  **traps to machine mode operate as follows:
>  1. Elevate the privilege to M-mode.
>  2. Save the current program counter in the mepc (machine exception PC) CSR.
>  3. Place a code indicating the reason for the trap in mcause.
>  4. Optionally record additional information about the trap in mtval.
>  5. Record the previous privilege mode and interrupt enable state in mstatus.
>  6. Disable interrupts.
>  7. Jump to a *trap vector* address (address of the trap handler code) stored in mtvec.
>  8. The trap handler responds to the trap (Section 8.2.6).
>  9. The trap handler then uses the mret (M-mode exception return) instruction to return to the
>     address in mepc and to restore the privilege mode and interrupt enable.**"
> — p.339

中文解釋：**九步驟，前七步是硬體做的，第 8 步是軟體，第 9 步硬體配合軟體。**

**Fig. 8.1（p.340）把這些 CSR 整理成一張速查：**

| CSR | 內容 |
| --- | --- |
| **`mepc`** | **發生 trap 的 PC** |
| **`mcause`** | **Trap 原因** |
| **`mtval`** | Trap 的更多資訊（選配） |
| **`mstatus`** | **先前的特權模式與中斷致能狀態** |
| **`mtvec`** | **Trap handler 的指令位址** |
| **`mret`**（指令） | **回到 `mepc`，並還原先前的特權模式與中斷致能** |

**一個關鍵細節（p.339 邊欄）：**
> "**Note that each flavor of the epc is set to the PC of the instruction that traps. For some traps
>  such as interrupts or page faults, the trap handler returns to that PC to rerun that instruction.
>  For other traps, such as an environment call (ecall), the trap handler adds 4 to the epc so that
>  it returns to the next instruction.**"

**`mepc` 存的是「出事那條指令的 PC」，不是下一條。**
- **中斷或 page fault → 直接回到那個 PC 重跑**
- **`ecall` → handler 要自己 +4**，否則會無限迴圈

### Delegation：讓 trap 直接去 S-mode

> "Most traps in Linux are handled by the S-mode OS. An M-mode trap handler could reroute traps to
>  S-mode (in software), **but it is faster for the hardware to directly *delegate* the trap.
>  The medeleg and mideleg CSRs (machine exception and interrupt delegation registers) indicate which
>  exceptions and interrupts should be delegated to S-mode. This way, when such a trap occurs, it can
>  immediately go to the S-mode (OS) trap handler instead of the M-mode handler.**"
> — p.339–340

中文解釋：**委派的動機純粹是速度**——避免「先到 M-mode 再轉給 S-mode」的兩段路。

**兩個委派暫存器：`medeleg`（例外）和 `mideleg`（中斷）。**

**一條鐵律（p.352）：**
> "**traps never reduce privilege levels, so an exception occurring in M-mode will always trap to the
>  M-mode handler.**"

**Trap 永遠不會降低特權等級。**（所以 M-mode 裡發生的例外一定由 M-mode 處理。）

### 三個特權模式

> "**Table 8.1 lists the RISC-V privilege modes and their encodings. The processor boots in M-mode.
>  Simple embedded microcontrollers ("bare metal") only use M-mode. Secure microcontrollers add
>  U-mode to separate untrusted application code from a smaller trusted secure kernel. Processors
>  running sophisticated operating systems such as Linux also add a supervisor mode (S-mode)**,
>  which supports virtual memory and provides security while allowing an M-mode supervisor binary
>  interface (SBI) to abstract platform-specific details from the OS."
> — p.340

中文解釋：**Table 8.1（p.340）的編碼要記：**

| Code | Mode |
| --- | --- |
| **00** | **User** |
| **01** | **Supervisor** |
| 10 | （保留） |
| **11** | **Machine** |

**注意編碼不連續（沒有 10）**——這是為了給 hypervisor 留位置。

**三種系統的配置（p.340）：**

| 系統 | 模式 |
| --- | --- |
| **簡單嵌入式微控制器（裸機）** | **只有 M** |
| **安全微控制器** | **M + U**（把不受信任的應用碼和小型可信核心分開） |
| **跑 Linux 的處理器** | **M + S + U** |

**（p.340 邊欄：目前特權模式存在硬體裡，程式看不到它；
只能透過 `mret`/`sret` 改變。不過通常很明顯：使用者程式在 U-mode、
OS 在 S-mode 並對 M-mode 做 SBI 呼叫。**）

### 特權指令清單

> "The RISC-V privileged specification introduces the following instructions:
>  - **`mret`** Return from M-mode trap
>  - **`sret`** Return from S-mode trap
>  - **`wfi`** Wait for interrupt
>  - **`sfence.vma`** Synchronize virtual memory by flushing TLB entries"
> — p.341

中文解釋：**非特權規格也定義了三類（p.340）：
`csr*`（含 `csrrw`、`csrrs`、`csrrc`）、`ecall`、`ebreak`。**

### CSR 存取指令與 pseudoinstruction

> "RISC-V defines a family of instructions to read and modify the CSRs: csrrw, csrrs, and csrrc.
>  **Each reads the value of the CSR into rd. Then the instructions, respectively, write, set, or
>  clear bits of the CSR specified by rs1.**"
> — p.341

> "The instructions also come in immediate forms csrrwi, csrrsi, and csrrci, **that use a 5-bit
>  unsigned immediate instead of rs1** to indicate which bit to write, set, or clear."
> — p.341

中文解釋：**三個基本指令：**

| 指令 | 對 CSR 做什麼 |
| --- | --- |
| **`csrrw`** | **write**（整個寫入 rs1） |
| **`csrrs`** | **set**（`csr = csr \| rs1`） |
| **`csrrc`** | **clear**（`csr = csr & ~rs1`） |
| `csrrwi/si/ci` | 同上，但用 5-bit 無號立即值 |

**全部都會先把 CSR 原值讀進 rd——「read-modify-write」是一條指令完成的。**

**常用的 pseudoinstruction（p.341）：**

| Pseudoinstruction | 實際變成 | 用途 |
| --- | --- | --- |
| **`csrr rd, csr`** | **`csrrs rd, csr, x0`** | 只讀（rs1 = x0 表示不改） |
| **`csrw csr, rs1`** | **`csrrw x0, csr, rs1`** | 只寫（rd = x0 表示丟掉舊值） |
| **`csrs csr, rs1`** | — | `csr = csr \| rs1` |
| **`csrc csr, rs1`** | — | `csr = csr & ~rs1` |

**又是 x0 當「不做事」的標記**（呼應 2.1 節）。

### `ecall` 與 `ebreak`

> "Two instructions purposefully trigger an exception: ecall or ebreak. **ecall triggers an exception
>  to call the OS. For example, in a system with all three privilege modes, a U-mode program uses
>  ecall to invoke the S-mode OS through the application binary interface (ABI), and the OS uses ecall
>  to invoke the firmware through the supervisor binary interface (SBI).**"
> — p.341

> "**ebreak triggers a breakpoint exception to transfer control to a debugger. A debugger sets a
>  breakpoint by replacing the corresponding instruction with an ebreak and recording the replaced
>  instruction. When the program reaches the breakpoint, the ebreak trap occurs, entering the debugger
>  code.... To single-step through the instruction at the breakpoint, the debugger restores the
>  instruction at the breakpoint, inserts an ebreak at the next instruction, and returns to the
>  program.**"
> — p.341–342

中文解釋：**`ebreak` 的運作機制很值得知道——這是所有除錯器中斷點的實作方式：**
1. **除錯器把目標指令換成 `ebreak`，並記下原本的指令**
2. 程式跑到那裡就 trap 進除錯器
3. **要單步時：還原原本的指令、在「下一條」插入 `ebreak`、然後返回**

（呼應 3.6.2 節的 GDB。）

### `mret` / `sret` 的完整動作

> "mret sets the program counter to the return value stored in mepc and restores the previous privilege
>  mode and interrupt enable state from the mstatus register. **Specifically, it changes the privilege
>  mode to mstatus.MPP (machine previous privilege mode) and mstatus.MIE (machine interrupt enable) to
>  mstatus.MPIE (machine previous interrupt enables).**"
> — p.342

> "**mret then sets mstatus.MPP to the least privileged supported mode (U-mode, if supported) and sets
>  mstatus.MPIE. If mstatus.MPP was not M-mode, mret also clears mstatus.MPRV (the Modify PRIvilege
>  mode bit).... mret causes an illegal-instruction exception if attempted from S- or U-mode.**"
> — p.342

中文解釋：**`mret` 做的事比想像中多，五件：**
1. **PC = `mepc`**
2. **特權模式 = `mstatus.MPP`**
3. **`mstatus.MIE` = `mstatus.MPIE`**（還原中斷致能）
4. **`mstatus.MPP` 設成最低特權模式、`mstatus.MPIE` 設為 1**（清理現場）
5. **如果 MPP 不是 M-mode，還要清除 `mstatus.MPRV`**

**第 4 步是安全考量：把 MPP 設成最低權限，
避免「忘記設定就 mret」時意外提升權限。**

**`sret` 類似，但用 `sepc` 和 SPP/SIE/SPIE**，
而且 **`mstatus.TSR = 1` 時在 S-mode 執行 `sret` 會觸發非法指令例外**（TSR = trap on sret）。

**（p.342 邊欄：位元欄位的表示法是 `.<bitfield name>`，
例如 `mstatus.MPP` 表示 `mstatus` CSR 裡的 MPP 欄位。**）

### `wfi`：省電的等待

> "Most processors spend most of their time in an *idle loop*, waiting for an interrupt that indicates
>  the user has pressed a key, moved the mouse, or tapped the screen, or a timer is scheduling the
>  program's next action. **The wait for interrupt instruction (wfi) is used to save power while the
>  processor is in such an idle loop. After a wfi instruction executes, the processor stops executing
>  instructions until an interrupt is pending. wfi preferably puts the processor in a low power state,
>  stopping clocks to most of the core and possibly lowering the power supply voltage.**"
> — p.342

中文解釋：**`wfi` 的價值呼應 6.1.2 節：閒置時漏電決定待機續航。**

**一個容易誤解的行為（p.342 邊欄）：**
> "**wfi will resume program execution when an interrupt is pending even if interrupts are globally
>  disabled. In this case, the pending interrupt is not taken, but the code after wfi can poll
>  interrupt sources and respond without needing to save and restore registers as is done in a trap
>  handler. Thus, the system can improve response time by globally disabling interrupts before a wfi.**"

**這是個聰明的技巧：中斷全域關閉時，`wfi` 仍會被喚醒但不 trap——
所以可以「醒來後自己輪詢」，省下 trap handler 存還原暫存器的開銷。**

**`mstatus.TW`（timeout wait）的作用（p.342）：**
> "**if wfi is executed in U- or S-mode and mstatus.TW = 1 (TW = timeout wait) or wfi is executed in
>  U-mode and S-mode is supported, wfi will time out after an implementation-specific delay
>  (possibly 0) by triggering an illegal-instruction exception.**"

**這是給 hypervisor 用的：避免 guest OS 用 `wfi` 霸佔 CPU。**

### CSR 的位址編碼（很實用的規則）

> "RISC-V supports up to 4,096 CSRs, which are XLEN bits wide. **Some CSRs require 64 bits of
>  information and have an associated h upper half for RV32.** CSRs are specified by 12-bit addresses:
>  - **The two most significant bits of the address are 00 or 01 for standard read/write registers and
>    11 for read-only registers.**
>  - **The next two bits are 00 for U-mode, 01 for S-mode, and 11 for M-mode registers.
>    CSRs can only be accessed from a privilege level greater than or equal to their mode.**"
> — p.342–343

中文解釋：**CSR 位址的高 4 bit 就編碼了權限資訊，這個設計很漂亮：**

| bits[11:10] | 意義 |
| --- | --- |
| 00 或 01 | 標準讀寫暫存器 |
| **11** | **唯讀暫存器** |

| bits[9:8] | 所屬模式 |
| --- | --- |
| **00** | U-mode |
| **01** | S-mode |
| **11** | M-mode |

**所以硬體只要看位址的高 4 bit 就能檢查權限，不需要查表。**

**四千多個 CSR，其中需要 64 bit 的在 RV32 上有對應的 `h` 上半部暫存器。**

### `mstatus`：最複雜的 CSR

> "The 64-bit status register (mstatus or sstatus) holds information such as the previous privilege
>  level, interrupt enables, floating-point/vector enables, timeout wait, and XLEN for U- and S-mode.
>  **The status register is the most complex CSR. All the bits of the status register are accessible in
>  M-mode using the mstatus register, and a subset is accessible in S-mode using the sstatus register.**"
> — p.343

中文解釋：**Fig. 8.2（p.344）的 RV64 `mstatus` 欄位配置（由低到高）：**

| 位元 | 欄位 | 意義 |
| --- | --- | --- |
| 1 | **SIE** | S-mode 全域中斷致能 |
| 3 | **MIE** | **M-mode 全域中斷致能** |
| 5 | **SPIE** | S-mode 先前中斷致能 |
| 6 | UBE | U-mode 端序 |
| 7 | **MPIE** | **M-mode 先前中斷致能** |
| 8 | **SPP** | **S-mode 先前特權模式（1 bit）** |
| 10:9 | VS | 向量狀態 |
| 12:11 | **MPP** | **M-mode 先前特權模式（2 bit）** |
| 14:13 | **FS** | **浮點狀態** |
| 16:15 | XS | 擴充狀態 |
| 17 | **MPRV** | Modify effective privilege |
| 18 | **SUM** | Supervisor user memory |
| 19 | **MXR** | Make executable readable |
| 20 | TVM | Trap virtual memory |
| 21 | **TW** | Timeout wait |
| 22 | TSR | Trap on sret |
| 33:32 | UXL | U-mode 的 XLEN |
| 35:34 | SXL | S-mode 的 XLEN |
| 36 | SBE | S-mode 端序 |
| 37 | MBE | M-mode 端序 |
| **63** | **SD** | **State dirty** |

**RV32 拆成 `mstatus` 和 `mstatush` 兩個 32-bit 暫存器**（Fig. 8.3，p.344），
**相對位置相同，除了 SD 移到 bit 31，而且不支援 SXL/UXL。**

**`sstatus`（Fig. 8.4，p.344）是子集**：
**MIE、MPIE、MPP、MPRV、TVM、TW、TSR、SXL、SBE、MBE 這些從 S-mode 看不到。**

**三個 WxRy 縮寫（p.343 邊欄）值得記，規格書常出現：**

| 縮寫 | 意義 |
| --- | --- |
| **WPRI** | Writes Preserve values, Reads Ignore values（**保留欄位**） |
| **WLRL** | Write Legal/Read Legal values（**程式必須寫/讀合法值**） |
| **WARL** | Write Any/Read Legal values（**可以寫非法值，但不會生效**） |

### MPP/SPP、MIE/SIE、MPIE/SPIE

> "The 2-bit MPP field holds the previous privilege mode from before a trap into M-mode
>  (MPP = 00, 01, or 11 for U-, S-, or M-mode, respectively). The mret instruction restores the
>  privilege mode to the value saved in MPP. **Likewise, the 1-bit SPP field holds the previous
>  privilege mode before a trap into S-mode (SPP = 0 or =1 for U- or S-mode, respectively)**, and sret
>  restores the privilege mode saved in SPP."
> — p.343

中文解釋：**SPP 只有 1 bit，因為 S-mode trap 只可能來自 U 或 S。**

> "A trap handler must disable interrupts, at least initially, so that it is not interrupted while
>  processing an interrupt. The mstatus.MIE field enables (1) or disables (0) all M-mode interrupts for
>  a hart operating in M-mode. **In M-mode, interrupts delegated to S-mode are always disabled
>  regardless of SIE.**"
> — p.343–344

> "**When a trap to M-mode occurs, the old value of MIE is copied to MPIE, and MIE is cleared...
>  so that a recursive trap cannot immediately occur. The mret instruction restores MIE to the value
>  in MPIE to resume normal operation. Therefore, the trap handler generally does not need to
>  manipulate the mstatus.MIE bit in software.**"
> — p.344

中文解釋：**MIE/MPIE 的機制設計得讓軟體不用管：**
```
trap 發生：MPIE ← MIE，MIE ← 0     （關中斷，防止遞迴 trap）
mret：     MIE ← MPIE              （還原）
```
**這和 MPP/SPP 是完全平行的機制——「先前值」都存在一個 P 版本的欄位裡。**

**（p.344 邊欄警告：別把 `mie` 暫存器（含個別中斷致能）
和 `mstatus.MIE` 全域中斷致能欄位搞混！名字很像但完全不同。**）

### FS/VS/XS/SD：延遲儲存的最佳化

> "Floating-point and vector extensions introduce new registers. **If these registers are in use, the
>  trap handler must save and restore them during context switches, which is a costly operation.
>  The FS and VS fields indicate whether floating-point or vector registers are *dirty* (different
>  from the last saved version) and need saving.**"
> — p.345

中文解釋：**Table 8.2（p.345）的四個狀態：**

| Status | FS/VS | 意義 |
| --- | --- | --- |
| **00** | **Off** | 關閉，存取浮點暫存器會觸發非法指令 trap |
| **01** | **Initial** | 初始 |
| **10** | **Clean** | 乾淨（和上次存的一樣） |
| **11** | **Dirty** | **髒的，需要儲存** |

**運作流程（p.345）：**
> "**The hardware sets FS = 11 (dirty) when the processor writes a floating-point register or fcsr.
>  When FS indicates a dirty state, the OS must save the floating-point registers and fcsr during a
>  context switch. Once the state is saved, FS can be marked as clean (FS = 10), and future context
>  switches do not need to save the floating-point state unless it is written again.**"

**這是很經典的「dirty bit」最佳化：只在真的改過時才存。**

**`SD`（state dirty）是總開關（p.345）：**
> "**SD (state dirty) is set if FS, VS, or XS is 11. When SD is 0, no state is dirty and context
>  switches do not need to save or recall any floating-point, vector, or other extension state.**"

**`SD` 放在 bit 63（或 RV32 的 bit 31）——最高位元，因為那樣「檢查是否為髒」最快
（看符號位元即可）**（p.343 提到 RV32 把 SD 移到 bit 31「to make checking dirty state easy」）。

**實用提醒（p.345 邊欄）：**
> "**On reset, typically mstatus.FS = 00, and floating-point is disabled.** The OS may enable
>  floating-point during the boot process. **When writing a bare-metal M-mode program with
>  floating-point instructions, don't forget to turn on floating-point, lest your program take an
>  illegal-instruction trap.**"

啟用方式（p.345）：
```asm
lui  t0, 2         # 1 in bit 13
csrs mstatus, t0   # Set FS = 01 = initial
```

### 其他 mstatus 欄位

**端序（p.345）**：`MBE`/`SBE`/`UBE` 控制 load/store 是 little-endian（0）或 big-endian（1）。
**「指令永遠是 little-endian，這樣反組譯器才能明確解讀指令。」**
（呼應 2.1 節。）

**`TVM`/`TSR`（p.346）**：給 hypervisor 用。
**`TVM = 1` 時 S-mode 存取 `satp` 或執行 `sfence.vma` 會觸發非法指令例外；
`TSR = 1` 時 S-mode 執行 `sret` 會觸發。**

**`UXL`/`SXL`（p.346）**：RV64 上控制 U-mode 和 S-mode 的有效 XLEN。
**Table 8.3（p.346）：01 = 32、10 = 64、11 = 128。**
**「這些欄位常被硬接成 10」**（不需要動態改變寬度的處理器）。

### `misa` 與機器資訊暫存器

> "The machine ISA (misa) register bitfields indicate which standard extensions are supported by the
>  processor.... **The association of letters to features is a bit too cute, and RISC-V has long ago run
>  out of letters. Additional extensions have longer names starting with Z (for any mode) or S (for
>  supervisor mode).... At the time of this writing, a standard way to discover which extensions are
>  available in a hart is still being defined. Linux tests for the presence of some extensions by
>  trying them during boot, taking an illegal instruction trap if the extension is unavailable, and
>  generating a table of which extensions are available.**"
> — p.346

中文解釋：**這段揭露了一個現實問題：沒有標準方法查詢支援哪些擴充。**
**Linux 的做法是「試試看」——執行該擴充的指令，
如果觸發非法指令 trap 就表示不支援。**
（呼應 2.5 節邊欄：具名擴充的查詢機制還在制定中。）

**機器資訊暫存器（p.346）**：`mvendorid`、`marchid`、`mimpid`、`mhartid`、`mconfigptr`，
**全部唯讀，簡單單核處理器可以全為 0。**
**JEDEC 收費指派 Vendor ID；RISC-V International 免費指派 Arch ID。**

### 效能計數器

> "RISC-V has up to 32 64-bit performance counters to keep track of various events.
>  **The first three are standard, measuring the number of clock cycles, number of timer ticks, and
>  number of instructions retired. The others are platform dependent and optionally configurable.**"
> — p.346

中文解釋：**三個標準計數器：**

| 編號 | 名稱 | 計什麼 |
| --- | --- | --- |
| **0** | **`cycle`** | 這個 hart 經過的時脈週期數 |
| **1** | **`time`** | **系統計時器**（可能以獨立於 hart 時脈的固定速率運作） |
| **2** | **`instret`** | 這個 hart 退休的指令數 |
| 3–31 | `hpmcounter3-31` | 平台相關、可組態（cache 存取/miss、分支預測/錯誤、pipeline stall…） |

**M-mode 和唯讀視圖的成對設計（p.347）：**

| M-mode（可讀寫） | 低權限（唯讀） |
| --- | --- |
| `mcycle`/h | `cycle`/h |
| — | `time`/h |
| `minstret`/h | `instret`/h |
| `mhpmcounter3-31`/h | `hpmcounter3-31`/h |

**存取控制（p.347）——這是安全考量：**
> "**Performance counters raise security risks such as timing attacks, in which information is deduced
>  by measuring the speed of variable latency operations such as cache accesses or division. Thus, the
>  mcounteren and scounteren bits can selectively turn off access to counters from S- and U-mode,
>  respectively.**"

**效能計數器會造成 timing attack 風險**——
從 cache 存取或除法的速度可以推斷資訊。
**所以 `mcounteren` 和 `scounteren` 可以選擇性關閉低權限的存取。**

**其他相關 CSR（p.347）：**
- `mhpmevent3-31`/h：選擇哪個事件被哪個計數器觀察
- **`mcountinhibit`：停用計數器以降低能耗**

**`time` 的特殊性（p.347 邊欄與內文）：**
> "**The time register comes from a system timer rather than a per-hart timer, so there is no mtime
>  register to which a user could write the time. The system timer is often in the Core Local
>  Interruptor (CLINT) peripheral.**"
> **「`time`/h 是記憶體映射的暫存器，不是 CSR。」**

**Pseudoinstruction（p.347）：`rdcycle rd` 等同 `csrr rd, cycle`；
還有 `rdtime`、`rdinstret`，RV32 另有 `h` 版本讀上 32 bit。**

**溢位不是問題（p.348 邊欄）：**
> "**Overflow of 64-bit counters is not a practical concern in present systems. If a counter increments
>  every cycle at 1 GHz, it would have to run continuously for 585 years before overflowing.**"

**擴充名稱（p.348）：`Zicntr`（標準三個）、`Zihpm`（硬體效能監視器）、
`Sscounterenw`（`scounteren` 可寫）。**

### CSR 與周邊的互動

> "**The timer value and most interrupts come from peripherals outside the RISC-V core. In many systems,
>  these peripherals are called the *Core Local Interruptor* (CLINT) and the *Platform-Level Interrupt
>  Controller* (PLIC). The CLINT contains the system timer.... It also contains timer compare registers
>  and software interrupt registers on a per-hart basis to generate machine timer and software
>  interrupts for each hart. The PLIC prioritizes and routes interrupts from other peripherals to the
>  external machine and supervisor interrupt inputs of each core. These peripherals are accessed using
>  memory-mapped input/output (I/O) rather than through CSRs.**"
> — p.348

中文解釋：呼應 2.4 節。**分工很清楚：**

| 周邊 | 負責 |
| --- | --- |
| **CLINT** | **系統計時器 + 每 hart 的 timer compare 與軟體中斷暫存器** → 產生 **timer 和 software 中斷** |
| **PLIC** | **把其他周邊的中斷排優先序並路由**到每個核心的 **external 中斷**輸入 |

**都是 memory-mapped I/O，不是 CSR。
但讀 `time` 會回傳 CLINT 計時器的值，而 `mip`/`sip` 會受周邊的中斷輸入影響。**
（第 20 章詳述。）

### 環境組態暫存器

> "Some RISC-V extensions raise security risks, especially when the OS or firmware is not designed to
>  support them. **For example, the Sstc extension defines a stimercmp CSR. If the M-mode firmware has
>  not been enhanced to save and restore stimercmp when switching between S-mode processes, such
>  processes could exchange covert information by writing and reading stimercmp.**...
>  **The {m/s}envcfg registers allow the system to disable such extensions at lower privilege levels
>  when they are not safely supported.**"
> — p.348

中文解釋：**這是一個很有啟發性的安全問題：
新擴充加入的 CSR，如果舊韌體不知道要在 context switch 時存還原它，
兩個行程就能用它偷偷傳訊息（covert channel）。**

**解法：`menvcfg`/`senvcfg` 可以在低特權等級停用這些擴充。**

**Fig. 8.5（p.349）的欄位：**

| 欄位 | 控制什麼 |
| --- | --- |
| **STCE**（bit 63） | **Sstc 的 `stimercmp`**；= 0 時 S-mode 存取觸發非法指令 |
| **PBMTE**（62） | **Svpbmt**（Page Based Memory Types） |
| **ADUE**（61） | **Svadu**（硬體 A/D 更新）；= 0 時需要更新 A/D 位元就觸發 page fault |
| CBZE/CBCFE/CBIE（7:4） | **Zicbo\***（cache 管理操作：`cbo.zero`/`flush`/`inval`） |
| **FIOM**（0） | **Fence of I/O implies Memory**：`fence` 也隱含主記憶體存取的排序 |

**`menvcfg` 永遠是 64 bit，RV32 用 `menvcfg h` 存取上半部。
STCE、PBMTE、ADUE 控制 S-mode 功能，所以只存在於 `menvcfg`。
其他位元在兩個暫存器都有，而且 U-mode 要啟用時兩邊都要設。
不支援的擴充其欄位硬接為 0。**（p.348）

**`mseccfg`（p.349）**：控制 Zkr 亂數產生和 Smepmp；**Wally 兩者都不支援，所以硬接為 0。**

### 重置行為

> "**On reset, a core begins in M-mode. The PC is set to an implementation-defined reset vector,
>  typically 0x1000 or 0x80000000. mcause is set to a value indicating the cause of the reset or 0 if
>  the system does not distinguish reset conditions. mstatus.MIE and mstatus.MPRV are cleared, and the
>  pmp registers are all disabled by setting the A and L fields to 0. Other hart state is undefined,
>  so the system must initialize all registers and CSRs before using them.**"
> — p.349

中文解釋：**重置後確定的只有五件事：**
1. **M-mode**
2. **PC = reset vector**（通常 0x1000 或 0x80000000，呼應 2.4 節）
3. `mcause` = 重置原因（或 0）
4. **`mstatus.MIE` 和 `mstatus.MPRV` 清除**（關中斷）
5. **PMP 全部停用**

**其他 hart 狀態是未定義的——所以韌體必須自己初始化所有暫存器和 CSR。**
（呼應 3.4 節的 `crt.S`：它就是在做這件事。）

### Trap 的分類與 Table 8.4

> "RISC-V traps are classified as either *exceptions*, which are caused by instructions, or
>  *interrupts*, which are caused by external events such as a key press. **Some exceptions are also
>  referred to as *faults*.**"
> — p.350

> "**Table 8.4 summarizes the standard RISC-V traps, listed in priority from highest to lowest.
>  If multiple traps occur on the same instruction, the highest priority is triggered.**
>  For a trap into mode *x* (machine or supervisor), the xcause, xepc, and xtval registers are written.
>  **The most significant bit of the xcause register is 1 for an interrupt and 0 for an exception.
>  The trap code is written into the low bits of xcause.**"
> — p.350

中文解釋：**Table 8.4（p.351）是本節最實用的表，一定要熟。按優先序由高到低：**

| | Trap | 中斷位元 | Trap Code | `xtval` |
| --- | --- | --- | --- | --- |
| **中斷** | **M-mode external** | 1 | **11** | 0 |
| | M-mode software | 1 | **3** | 0 |
| | M-mode timer | 1 | **7** | 0 |
| | S-mode external | 1 | **9** | 0 |
| | S-mode software | 1 | **1** | 0 |
| | S-mode timer | 1 | **5** | 0 |
| **例外** | **Instruction page fault** | 0 | **12** | PC |
| | Instruction access fault | 0 | **1** | PC |
| | **Illegal instruction** | 0 | **2** | **Instruction** |
| | Instruction address misaligned | 0 | **0** | Target Address |
| | Breakpoint | 0 | **3** | PC |
| | **`ecall` from U-mode** | 0 | **8** | 0（a0 = arg） |
| | **`ecall` from S-mode** | 0 | **9** | 0（a0 = arg） |
| | **`ecall` from M-mode** | 0 | **11** | 0（a0 = arg） |
| | Store/AMO address misaligned | 0 | **6** | Store Address |
| | Load address misaligned | 0 | **4** | Load Address |
| | Store/AMO page fault | 0 | **15** | Store Address |
| | Load page fault | 0 | **13** | Load Address |
| | Store/AMO access fault | 0 | **7** | Store Address |
| | Load access fault | 0 | **5** | Load Address |

**幾個記憶重點：**
1. **`xcause` 的最高位元：1 = 中斷、0 = 例外**
2. **中斷的優先序：external > software > timer，且 M > S**
3. **`ecall` 的 code 依來源模式不同：U = 8、S = 9、M = 11**
4. **`xtval` 的內容依 trap 類型不同**：
   非法指令存**指令本身**、page fault 存**位址**、`ecall` 存 0
5. **Instruction 相關的例外優先於 Load/Store 相關的**
   （因為取指令在前）

**（表格註腳，p.351：用 Zicclsm 擴充在硬體處理未對齊 cacheable 存取時，
store/load misaligned fault 的優先序變成最低。）**

### 水平 trap 與垂直 trap

> "**Traps that are handled in the same privilege mode where they were caused (machine to machine or
>  supervisor to supervisor) are called *horizontal* traps. Traps to a higher privilege level are
>  *vertical* traps. Traps never go to a lower privilege level.**"
> — p.350

中文解釋：**兩個詞值得記：水平 trap（同模式）、垂直 trap（往上）。
永遠不會往下。**

### M-mode trap 的 CSR 清單

> "**When a trap to M-mode occurs, the privilege mode and machine interrupt enable (mstatus.MIE) are
>  stored to mstatus.MPP and mstatus.MPIE, respectively, so that mret can later return to the correct
>  state. The privilege mode is set to M-mode, and mstatus.MIE is cleared so that the trap won't be
>  immediately interrupted again.**"
> — p.350

中文解釋：**七個 M-mode trap 相關的 CSR（p.350）：**

| CSR | 內容 |
| --- | --- |
| `mstatus` | 中斷致能、先前中斷致能、先前特權模式 |
| `mcause` | 中斷或例外的原因 |
| `mtval` | 提供額外 trap 資訊的值 |
| **`mtvec`** | **trap handler 的位址（vector）** |
| **`mepc`** | **Exception PC，存 trap 的返回位址** |
| **`mscratch`** | **通常存 exception stack pointer** |
| **`mip`** | **Interrupt pending，列出目前 pending 的中斷** |
| **`mie`** | **Interrupt enable，列出哪些中斷會被接受** |

**`mscratch` 的典型用法很重要**：trap handler 一進來什麼暫存器都不能用
（因為會破壞被中斷的程式），**所以用 `csrrw` 和 `mscratch` 交換一個暫存器，
就得到一個可用的指標。**（8.2.6 節的範例會示範。）

**S-mode 完全對稱**（p.351）：`mstatus.SIE` → `mstatus.SPP` 和 `SPIE`，
用 `sepc`、`scause`、`stval`、`stvec`、`sscratch`、`sip`、`sie`。

### RISC-V 的 trap 都是 precise

> "**RISC-V exceptions are precise: all instructions prior to the exception complete, and neither the
>  instruction causing the exception nor any subsequent instructions change the architectural state of
>  the system before the exception is handled. This is accomplished by flushing the instruction that
>  caused the exception and any subsequent instructions that are in-flight in the pipeline.**"
> — p.352

> "**RISC-V interrupts are also precise. Although interrupts are not caused by a particular instruction,
>  they are handled between instructions, with all instructions up to some point retired and no
>  instructions after that point modifying architectural state. Interrupts are handled within a bounded
>  amount of time from the triggering condition.**"
> — p.352

中文解釋：呼應 8.1.2 節。**實作方式很簡單：flush 造成例外的那條指令以及後面所有在飛的指令。**

**中斷的 precise 定義不同**：中斷不是某條指令造成的，
**所以它「在指令之間」處理——某點之前全部退休，某點之後都沒改動架構狀態。**
**而且「在觸發條件後的有限時間內處理」。**

### 例外的委派：`medeleg`

> "The medeleg (exception delegation) register controls which exceptions are delegated to S-mode.
>  **It contains a bit for each of the standard exception causes from Table 8.4, as shown in Fig. 8.6,
>  where each grey bit corresponds to an exception cause (unused bits, such as 10 and 14, are set to 0).
>  A one in a given bit delegates that exception to the S-mode handler.**"
> — p.352

中文解釋：**`medeleg` 的 bit N 對應 Table 8.4 的 trap code N。**
Fig. 8.6（p.352）顯示 bit 14 和 bit 10 硬接為 0（未使用的 code）。

**實務上委派什麼（p.352）：**
> "**For example, in a system with a Linux-like S-mode OS, medeleg normally delegates at least page
>  faults, U-mode OS calls, and breakpoints to S-mode because these exceptions should be handled by the
>  OS. If they weren't delegated, the M-mode handler would have to pass them along to the OS.**"

**至少要委派：page fault、U-mode 的 `ecall`、breakpoint。**

### 四類例外

**（1）非法指令（p.352–353）**
> "A hart throws an *illegal-instruction exception* when it tries to execute an instruction that either
>  doesn't exist or is unavailable in the current privilege mode. **The 0x00000000 instruction is always
>  illegal**, and many other instructions are not implemented in the base ISA or standard extensions.
>  Some instructions such as mret are unavailable in lower privilege levels. **Accessing an unimplemented
>  CSR or a privileged CSR from a lower privilege level also throws an illegal-instruction exception.**"

**`0x00000000` 永遠是非法指令**——這很有用，因為未初始化的記憶體通常是 0，
**跑飛的程式會立刻被抓到。**

**（2）Access fault（p.353）**
> "A hart throws an *access fault* when it tries to fetch, read, or write from an inaccessible memory
>  location. **Examples include reading from a nonexistent memory location, writing to a read-only memory
>  (ROM), making word accesses to a peripheral that only handles byte accesses, or accessing a protected
>  region of memory from an insufficient privilege level.** Accessible regions are defined by *physical
>  memory attributes* (PMA, essentially generalized memory address decoders) and *physical memory
>  protection* (PMP) registers described in Section 11.2.2."

**「對只支援 byte 存取的周邊做 word 存取」也算 access fault**——這個容易忽略。

**（3）位址未對齊（p.353）**
> "Most memories can only directly handle accesses from an address that is *naturally aligned*, that is,
>  a multiple of the access size. **For example, loading a 4-byte word from 0x1000 is fine, but loading
>  that word from 0x1001 is not because it involves bytes from the words at both 0x1000 and 0x1004.**"

> "**The trap handler could kill the program or it could handle the exception by issuing a pair of
>  aligned accesses and then shift, mask, and merge to deliver the misaligned result and return to the
>  program.**"

**未對齊存取可以用軟體模擬：兩次對齊存取 + 移位遮罩合併。**

**指令位址未對齊的細節（p.353）很值得懂：**
> "**Note that branch and jump offsets are implicitly a multiple of 2 and that jalr sets the least
>  significant bit of the destination address to 0, so instruction addresses are inherently a multiple
>  of 2. When the Compressed extension is not supported, instructions are 4 bytes long and must be word
>  aligned, so a branch or jump to an odd multiple of 2 causes an exception. When the Compressed
>  extension is supported, instructions only require halfword alignment so instruction
>  address-misaligned exceptions cannot occur.**"

**有 C 擴充就不可能發生指令位址未對齊例外**（因為 2-byte 對齊一定滿足）。
（呼應 2.1 節：分支偏移最低位元恆為 0。）

**（p.353 邊欄：Zicclsm 擴充讓 cacheable 主記憶體區域在硬體支援未對齊存取，
這種存取較慢但不會觸發例外。第 19.2 節。**）

**（4）Page fault（p.354）**
> "When virtual memory is enabled, attempting to access a virtual page that is not in physical memory
>  throws a *page fault*. **The OS can then fetch the virtual page from storage and place it in physical
>  memory before reattempting the access. Virtual memory also allows pages to be designated as
>  user-only or supervisor-only, and code-only or data-only; violating these protections causes a page
>  fault that might terminate the program.**"

### 中斷：三類 × 兩個等級

> "**RISC-V defines three types of interrupts (timer, software, and external—TI, SI, and EI,
>  respectively) at two privilege levels, machine and supervisor. Interrupts are managed with the mip
>  and mie machine interrupt *pending* and *enable* registers shown in Fig. 8.7.**"
> — p.354

中文解釋：**3 種 × 2 個等級 = 6 個中斷。Fig. 8.7（p.354）的位元位置：**

| bit | `mip` / `mie` | 意義 |
| --- | --- | --- |
| **1** | SSIP / SSIE | S-mode software |
| **3** | MSIP / MSIE | M-mode software |
| **5** | STIP / STIE | S-mode timer |
| **7** | MTIP / MTIE | M-mode timer |
| **9** | SEIP / SEIE | S-mode external |
| **11** | MEIP / MEIE | M-mode external |

**位元編號和 Table 8.4 的 trap code 一致。**

**只有 6 個 bit 有用（p.354 邊欄）：**
> "**Only 6 bits of the interrupt registers are not hardwired to 0 (Figs. 8.7 and 8.8).
>  All bits tied to 0 are optimized away.**"

**`mideleg`（Fig. 8.8，p.354）的 bit 位置相同。**

**命名的混淆（p.355）：**
> "**The machine and supervisor interrupt nomenclature is confusing. Machine and supervisor interrupts
>  have no fundamental hardware differences, but supervisor interrupts are conventionally delegated to
>  the S-mode handler, while machine interrupts go to the M-mode handler. Thus, in a system with an
>  S-mode OS, mideleg is set to 0x222 to delegate supervisor external, timer, and software interrupts
>  to the S-mode handler.**"

**「machine 中斷」和「supervisor 中斷」在硬體上沒有本質差別，
只是慣例上前者給 M-mode handler、後者委派給 S-mode。**
**`mideleg = 0x222` = bit 1、5、9 = S-mode 的三個中斷。**

**`sip`/`sie` 是 `mip`/`mie` 的子集（p.355）：**
> "**Only the bits of sip that are delegated are visible: sip = mip & mideleg. sip.SSIP (S-mode
>  software interrupt pending) is writable in order to clear the interrupt after it is handled; the
>  other sip bits are read-only because they are caused by external agents.**"

**中斷優先序（p.355）：**
> "**When multiple interrupts are pending, RISC-V processors prioritize M-mode interrupts before S-mode
>  and external, then software, and then timer interrupts.**"

（和 Table 8.4 一致。）

### 中斷的產生

中文解釋：**Fig. 8.9（p.355）的中斷來源：**

| 來源 | 產生什麼 |
| --- | --- |
| **PLIC** | `SExtInt`、`MExtInt` → **SEIP、MEIP** |
| **CLINT** | `TimerInt`、`SwInt` → **MTIP、MSIP** |
| **軟體寫 `mip`** | mip.SEIP、mip.SSIP、mip.STIP → SEIP、SSIP、STIP |
| **`time ≥ stimecmp`** | `STimerInt`（由 `menvcfg.STCE` 選擇）→ STIP |

**注意 SEIP 是 PLIC 的 `SExtInt` 和軟體寫入的 OR**——
**所以 M-mode 軟體可以「假造」S-mode 外部中斷。**

**三種中斷的用途（p.355–356）：**

| 類型 | 產生者 | 用途 |
| --- | --- | --- |
| **External** | **PLIC** | 周邊裝置（序列埠有資料等）。**handler 要查詢 PLIC 才知道是哪個周邊** |
| **Software** | **CLINT**（一個 hart 寫另一個 hart 的記憶體映射位元） | **hart 之間的溝通（IPI）** |
| **Timer** | **CLINT**（`mtime` 超過 `mtimecmp`） | **OS 排程器的心跳，用來切換任務** |

**清除中斷的方式（p.356）：**
- **External**：handler 查詢 PLIC → 處理該周邊 → **寫周邊的暫存器清除中斷**
- **Software**：**寫 CLINT 的記憶體映射位元清除**
- **Timer**：**把 `mtimecmp` 寫成超過目前時間的值**

**Sstc 擴充的動機（p.356 邊欄）：**
> "**It is cumbersome for the timer interrupt to trap to a machine mode handler that sets STIP that
>  causes a trap to the supervisor mode handler. The RISC-V Sstc extension adds a stimecmp register to
>  produce supervisor timer interrupts directly from hardware when time ≥ stimecmp.
>  menvcfg.STCE must be set to 1 to enable this capability.**"

**沒有 Sstc 的話，S-mode 計時器中斷要繞兩層；有了就直接產生。**

### 中斷產生的邏輯（Fig. 8.10）

> "**A hart takes an interrupt if interrupts are globally enabled and if any interrupt is both pending
>  in mip and enabled in mie. The global enable depends on whether the interrupt is delegated to S-mode
>  or not. Interrupts are always globally enabled in U-mode. Delegated interrupts are globally enabled
>  in S-mode when mstatus.SIE is set and are globally disabled in M-mode. Undelegated interrupts are
>  globally enabled in S-mode and in M-mode when mstatus.MIE is set. In other words, undelegated
>  interrupts are enabled when mstatus.MIE = 1 (regardless of mode) or in any mode other than M-mode.**"
> — p.356–357

中文解釋：**這段邏輯很繞，整理成表：**

| 中斷類型 | U-mode | S-mode | M-mode |
| --- | --- | --- | --- |
| **已委派（給 S）** | **永遠啟用** | **`mstatus.SIE`** | **永遠停用** |
| **未委派（給 M）** | **永遠啟用** | **永遠啟用** | **`mstatus.MIE`** |

**兩條原則可以推出整張表：**
1. **中斷在「比它的目標模式更低權限的模式」下永遠啟用**
   （因為它會提升權限，不會有問題）
2. **在「等於目標模式」時看對應的 SIE/MIE**
3. **在「高於目標模式」時永遠停用**（trap 不會降權）

**Fig. 8.10（p.356）的電路：
`MIntGlobalEnM` 和 `SIntGlobalEnM` 由 `mstatus.MIE`、`mstatus.SIE` 和
目前模式（M_MODE、U_MODE、S_MODE）算出，
然後每一個中斷做 `mip & mie & 對應的 global enable`，
最後全部 OR 起來得到 `InterruptM`。**

### Interrupt Vectoring

> "The addresses in mtvec or stvec are the trap vector (i.e., trap handler address) for M- or S-mode....
>  **This trap vector must be a multiple of 4, so the bottom two bits are ignored and treated as 0.**"
> — p.357

> "**To handle interrupts faster, RISC-V optionally allows the core to jump to a different address
>  depending on the interrupt source. This is called *vectored interrupts*. RISC-V enables interrupt
>  vectoring by making the bottom two bits of the trap vector be 01. Exceptions still jump directly to
>  the trap vector (discarding the least significant bit), but interrupts jump to the trap vector plus
>  four times the trap cause (i.e., the trap cause shifted left by 2 bits). For example, a machine
>  software interrupt has a cause of 3, so it jumps to the trap vector +12.**"
> — p.357

中文解釋：**`mtvec` 的低 2 bit 是模式選擇：**

| 低 2 bit | 模式 |
| --- | --- |
| **00** | **Direct**：所有 trap 都跳到同一個位址 |
| **01** | **Vectored**：**中斷跳到 `base + 4 × cause`**，例外仍跳 base |

**例：M-mode software interrupt 的 cause = 3 → 跳到 base + 12。**

**對齊要求（p.357）：**
> "**Processors with vectored interrupts typically require that the trap vector is aligned to a multiple
>  of 64 (i.e., its lower 6 bits are 0) so that the vector addition reduces to concatenating the shifted
>  cause with the upper bits of the trap vector address.**"

**對齊到 64 的倍數，加法就變成串接——省掉一個加法器。**

**兩個實用註記（p.357 邊欄）：**
> "**There is only room for one instruction at the trap vector, so this instruction is normally a jump
>  to the actual trap handler.**"
> **「每個 vector 只有一條指令的空間（4 bytes），所以通常放一個跳躍。」**

> "**Exceptions are not vectored because they are less sensitive to latency. For example, a timer
>  interrupt must be handled quickly, but an illegal-instruction exception does not.**"
> **「例外不做 vectoring，因為它們對延遲較不敏感。」**

**（p.357 邊欄也提到 **RISC-V Advanced Interrupt Architecture (AIA) 擴充
（Smaia/Ssaia）2023 年 6 月批准**，用更通用的中斷控制器取代 PLIC，
支援 PCI Express 的 message-signaled interrupt，並降低 hypervisor 的中斷開銷。）

### 完整的 trap handler 範例（8.2.6）

中文解釋：Code Example 8.1（p.358–360）是一份完整可跑的 RV64 M-mode trap handler，
**處理計時器中斷和 `ecall`。這是本章最實用的程式碼，值得完整讀。**

```bash
$ cd $WALLY/examples/asm/trap
$ make
$ make sim
```

**（1）初始化（設定 trap 環境的標準流程）**
```asm
la sp, topofstack           # 初始化堆疊指標
la s6, begin_signature      # s6 指向 signature 記憶體

jal set_timecmp             # 設定計時器

la   t0, trap_handler
csrw mtvec, t0              # mtvec = trap_handler
csrw mideleg, zero          # 不委派中斷
csrw medeleg, zero          # 不委派例外
li   t0, 0x080
csrw mie, t0                # mie bit 7 = machine timer interrupt
la   t0, topoftrapstack
csrw mscratch, t0           # mscratch 存 trap 堆疊指標
csrsi mstatus, 0x8          # 開啟 mstatus.MIE 全域中斷致能
```

**六個步驟：設 `mtvec` → 清 `mideleg`/`medeleg` → 設 `mie` → 設 `mscratch` → 開 `MIE`。**
**注意 `mscratch` 在 trap 發生前就要設好。**

**（2）主程式**
```asm
main:
    li a0, 0
    ecall                   # 系統呼叫進入 user mode
    li t0, 0x1000
loop:
    addi t0, t0, -1
    bne  t0, zero, loop     # 等計時器中斷
done:
    li a0, 4
    ecall                   # 終止程式
    j self_loop
```

**（3）Trap handler 的開頭：用 `mscratch` 換出一個可用暫存器**
```asm
.align 2                    # trap handler 必須對齊到 2^2 = 4 的倍數
trap_handler:
    csrrw tp, mscratch, tp  # 交換 mscratch 和 tp
    sd t0, 0(tp)            # 在堆疊上保存 t0 和 t1
    sd t1, -8(tp)
```

**`csrrw tp, mscratch, tp` 是經典技巧：一條指令同時「拿到 trap 堆疊指標」
和「保存原本的 tp」。** 這解決了「handler 一進來沒有可用暫存器」的雞生蛋問題。

**（4）判斷是中斷還是例外**
```asm
    csrr t0, mcause
    csrr t1, mtval
    sd t0, 0(s6)            # 把 mcause 和 mtval 寫進 signature
    sd t1, 8(s6)
    addi s6, s6, 16
    bgez t0, exception      # msb 是 0 就是例外
```

**`bgez` 檢查 `mcause` 的最高位元——這正好用上「中斷位元是 msb」的設計。**

**（5）中斷處理**
```asm
interrupt:
    jal set_timecmp         # 遞增下次的計時器比較值
    j trap_return
```
**清除計時器中斷的方式就是把 `mtimecmp` 設到未來。**

**（6）例外處理**
```asm
exception:
    csrr t1, mepc
    addi t1, t1, 4          # mepc + 4，讓例外返回下一條指令
    csrw mepc, t1
    li   t1, 8
    andi t0, t0, 0xFC       # cause = 8, 9, 或 11 都是 ecall
    bne  t0, t1, trap_return
```

**`mepc + 4` 是 `ecall` 必須做的**（呼應 8.2 節開頭的邊欄）。
**`andi t0, t0, 0xFC` 很巧妙：把低 2 bit 遮掉，
8、9、11 都會變成 8，一次比對三種 `ecall`。**

**（7）改變特權模式（示範 `mstatus.MPP` 的操作）**
```asm
changeprivilege:
    li   t0, 0x00001800     # 遮掉 mstatus.MPP（bits 11-12）
    csrc mstatus, t0
    andi a0, a0, 0x003      # 只留參數的低 2 bit
    slli a0, a0, 11         # 移到 MPP 的位置
    csrs mstatus, a0        # 設定想要的特權等級
```

**先 clear 再 set 是修改 CSR 欄位的標準做法**（因為 `csrw` 會蓋掉整個暫存器）。

**（8）返回**
```asm
trap_return:
    ld t1, -8(tp)           # 還原 t1 和 t0
    ld t0, 0(tp)
    csrrw tp, mscratch, tp  # 還原 tp
    mret
```

**（p.360 邊欄的警告值得記：**
> "**The system call (ecall) to change privilege mode in Code Example 8.1 is very useful in test code,
>  but it would be dangerous in a real system!**"
**「這在測試碼很有用，但在真實系統會很危險！」**——
因為任何 U-mode 程式都能用它提升自己的權限。）

## 名詞表

| 名詞 | 意思 |
| --- | --- |
| **Trap 九步驟** | 升權→存 `mepc`→存 `mcause`→存 `mtval`→存 `mstatus`→關中斷→跳 `mtvec`→處理→`mret` |
| `medeleg` / `mideleg` | 例外 / 中斷委派暫存器。bit N 對應 Table 8.4 的 trap code N |
| **Horizontal / vertical trap** | 同特權模式處理 / 往更高特權模式。**永遠不往下** |
| `csrrw` / `csrrs` / `csrrc` | CSR 寫 / 設位元 / 清位元；都會先把舊值讀進 rd |
| `csrr` / `csrw` | Pseudoinstruction：只讀（rs1 = x0）/ 只寫（rd = x0） |
| **`mscratch`** | 通常存 exception stack pointer；**`csrrw tp, mscratch, tp` 是取得可用暫存器的經典技巧** |
| **MPP / SPP** | M/S-mode 先前特權模式。`mret`/`sret` 據此還原 |
| **MIE / MPIE** | 全域中斷致能 / 先前值。**trap 時 MPIE←MIE、MIE←0；`mret` 時 MIE←MPIE** |
| **FS / VS / XS / SD** | 浮點/向量/擴充狀態（00 Off、01 Initial、10 Clean、**11 Dirty**）；SD 是三者的 OR |
| **WPRI / WLRL / WARL** | 保留欄位 / 必須寫讀合法值 / 可寫非法值但不生效 |
| `misa` | 指出支援哪些字母擴充；**目前沒有標準方法查詢具名擴充** |
| `cycle` / `time` / `instret` | 三個標準效能計數器；**`time` 來自 CLINT，是記憶體映射而非 CSR** |
| `mcounteren` / `scounteren` | 選擇性關閉低權限對計數器的存取（**防 timing attack**） |
| `menvcfg` / `senvcfg` | 環境組態暫存器；在低特權等級停用有安全風險的擴充 |
| **CLINT / PLIC** | 產生 timer 與 software 中斷 / 排序並路由 external 中斷 |
| **`mip` / `mie`** | 中斷 pending / enable；bit 1,3,5,7,9,11 對應 S/M 的 software/timer/external |
| **Vectored interrupts** | `mtvec` 低 2 bit = 01；**中斷跳 `base + 4×cause`，例外仍跳 base** |
| Sstc / `stimecmp` | 讓 S-mode 計時器中斷直接由硬體產生，不必繞 M-mode |
| Naturally aligned | 位址是存取大小的倍數 |
| PMA / PMP | Physical memory attributes（位址解碼器）/ physical memory protection |

## 所以呢

**這節是 RISC-V 特權架構的完整規格，資訊量很大。四個最該記熟的東西：**

1. **Trap 的九步驟**，以及五個核心 CSR：
   **`mepc`（回家的路）、`mcause`（為什麼）、`mtval`（細節）、
   `mtvec`（去哪）、`mstatus`（先前狀態）。**
   **`mepc` 存的是出事那條指令的 PC——`ecall` 的 handler 要自己 +4。**

2. **Table 8.4 的 trap code**，尤其是
   **最高位元 1 = 中斷、0 = 例外**，
   **`ecall` 依來源模式是 8/9/11**，
   **非法指令是 2 且 `mtval` 存指令本身**。

3. **`mstatus` 的三組成對欄位**：
   **MPP/SPP（先前特權）、MIE/SIE（全域致能）、MPIE/SPIE（先前致能）。**
   **trap 時「現值搬到 P 版本」，`mret` 時搬回來。**

4. **中斷致能的規則**：
   **在比目標模式低權限的模式下永遠啟用、等於時看 SIE/MIE、高於時永遠停用。**

還有兩個很實用的程式技巧：
- **`csrrw tp, mscratch, tp`**：一條指令解決「handler 沒有可用暫存器」。
- **修改 CSR 欄位要「先 clear 再 set」**，不能直接 `csrw`。
