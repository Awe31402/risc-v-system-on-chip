# 16.6 Wally Implementation

> 原書 p.655–669（Chapter 16: Extensions: F/D/Q/Zfh/Zfa (Floating-Point)）
> 涵蓋 16.6.1 Floating-Point Unit（含暫存器檔、結果多工器）、16.6.2 Unpacking Unit、16.6.3 FMA、16.6.4 Divide and Square Root、16.6.5 Convert、16.6.6 Move、16.6.7 Compare、16.6.8 Sign Injection、16.6.9 Classify、16.6.10 Zfa、16.6.11 Postprocessing、16.6.12 Privileged Unit Changes、16.6.13 IEU Changes、16.6.14 Hazard Unit Changes、16.6.15 LSU Changes

## 這節在講什麼

前面幾節講的是「通用 FPU 該長什麼樣」，這節是 Wally 的實際 RTL。重點有兩個。第一，Wally 的 FPU 是**可設定的**：half/single/double/quad 任選子集，全部共用同一套硬體（用最寬的精度 FLEN 當內部格式，輸入時擴展、輸出時捨回目標精度）。第二，加浮點不是只加一個模組——IFU、IEU、LSU、privileged unit、hazard unit 全都要改，這節逐一列出改了什麼。

## 關鍵點

### FPU 在哪一級、延遲多少

> "The FPU operates in the Execute and Memory stages with a two-cycle latency and single-cycle throughput, except that division and square root have longer latencies and stall the pipeline."
> — p.655

中文解釋：Fig. 16.20 顯示 FPU 橫跨 Execute 與 Memory。two-cycle latency + single-cycle throughput 表示它是管線化的（每 cycle 可以收一個新指令），但相依的下一條指令要停一個 cycle。`fdivsqrt` 是例外，它在 Execute 做前處理、跑很多 recurrence cycle、在 Memory 做後處理，期間整條管線停住。

### FPU 要接的五個對象

> "The FPU connects to the LSU for loads and stores, to the IEU for moves and converts, to the privileged unit for the fcsr, and to the hazard unit for stalls."
> — p.655

中文解釋：這句話就是 16.6.12–16.6.15 那幾小節的來源。加浮點是一個牽動全機的改動，不是插一個 IP 進去就好。

### FLEN 與可設定精度

> "The FPU is parameterized to support half-, single-, double-, and quad-precision or any subset thereof. The highest precision supported by the FPU is called FLEN. ... Legal combinations are: F, FD, FDQ, HF, HFD, and HFDQ."
> — p.655–657

中文解釋：注意「合法組合」是有限制的——不能只支援 half 而沒有 single，也不能跳過 double 直接做 quad。精度由 `misa` 裡的 F/D/Q 位元加上 `ZFH_SUPPORTED` 設定決定。例如 RV32IFD 的 XLEN = 32 但 FLEN = 64。

### 多精度共用硬體的四步策略

> "The fregfile register file holds the highest precision FLEN, with lower precisions NaN-boxed. The execution units, such as the FMA, are also sized for the highest supported precision but can handle lower precisions. The unpacking unit (unpack) extends lower-precision operands to FLEN. The postprocessing unit (postprocess) rounds to the target precision."
> — p.657

中文解釋：這是整章最核心的實作決定。策略是「進來全部擴展成最寬格式、中間一律用最寬格式算、出去再捨回目標精度」。好處是執行單元只要一套；代價是低精度運算浪費了硬體、也沒有比較快。Table 16.17 是 `fmt` 欄位的編碼：00 single、01 double、10 half、11 quad，對應的 PLEN（運算元長度）是 32/64/16/128。

### 浮點暫存器檔要三讀一寫

> "The floating-point register file has 4 ports: 3 read ports and 1 write port. It has 32 entries, each FLEN-bits wide... Because multiport memories are not available in many ASIC processes, the register file can be implemented with standard cells using FLEN*32 enabled flip-flops, three 32:1 FLEN-bit read multiplexers, and a 5:32 write decoder."
> — p.658

中文解釋：三個讀埠是因為 FMA 要 X、Y、Z 三個運算元（整數暫存器檔只要兩讀）。ASIC 製程通常沒有三讀埠的 SRAM 可用，所以只能用標準單元硬刻——FLEN×32 個 flip-flop 加三組大多工器，面積比整數暫存器檔大得多。

### 結果多工器為什麼要「預先」多工

> "The postprocessor result arrives late, so the other results are premultiplexed in the execute stage to save time and registers."
> — p.658

中文解釋：這是一個典型的時序技巧。`fcmp`、`fsgninj`、int-to-float move 這些結果早就好了，先在 Execute 級把它們選成一路；等 postprocess 的慢結果出來，只需要一個 2:1 多工器就收尾。如果全部丟進一個大多工器等最慢的訊號，關鍵路徑會變長，而且要多存好幾組暫存器。

### unpack 怎麼驗證 NaN boxing

> "Unpacking also verifies that lower-precision numbers are properly NaN-boxed by having all 1s in the leading bits. It asserts the NaN output if they are not boxed correctly. Thus, if a program inadvertently attempts to perform a double-precision operation on a single-precision number in a double-precision register, the number is treated as NaN to warn about the mistake."
> — p.659

中文解釋：這正是 16.4.2 的 NaN boxing 在硬體上的回收。錯誤不會靜靜地產生垃圾數字，而是變成 NaN——一個看得見的訊號。

### 擴展指數的巧妙做法

> "Extending the exponent to the desired length and bias initially seems difficult but simplifies gracefully. ... In other words, the lower 7 bits remain the same, and if e7 is 0, the upper bits are 0111; otherwise, they are 1000. Thus, extending an exponent reduces to inserting complemented versions of the raw exponent's most significant bit."
> — p.659

中文解釋：這個推導很漂亮。把 8 位元、bias 127 的指數擴成 11 位元、bias 1023，需要加 1023 再減 127 = +896 = 01110000000。做完之後發現：低 7 位不變，高位只是最高位的反相重複。所以硬體上根本不用加法器，只要接線 + 一個反相器。如果原本是 subnormal（指數全 0），把 e₀ 改成 1 即可（對應 16.2.1 講的 subnormal 指數修正）。Example 16.20 完整走了一遍 half → single 的例子。

### Wally 的 FMA 比通用版多了符號反轉

> "Compared to the basic FMA from Section 16.2.2, the RISC-V FMA provides the option of inverting the addend, the result, or both: W = ±(X × Y ± Z). Thus, it supports all four flavors of RISC-V instructions: fmadd, fmsub, fnmadd, fnmsub. The FMA is also used to compute fadd, fsub, and fmul by setting one of the sources to 1.0 or 0.0."
> — p.660

中文解釋：七種指令一個單元包辦。這就是 16.2.2 說的「FMA 是 FPU 的主力」。

### 除法延遲公式與 k 參數

> "Division and square root perform a variable number of steps to produce b = N_f + 1 fraction bits, with N_f depending on the target precision. Radix-2^r operations produces r-bit digits so requires b/r steps. ... The unit contains k copies of the recurrence hardware to perform k steps per cycle. Preprocessing and postprocessing each involve an extra cycle."
> — p.660

中文解釋：公式 (16.8)：`Cycles = ceil((1 + b/r) / k) + 2`。`k` 就是 `FDIVSQRT_STEPS_PER_CYCLE` 設定。Table 16.18 的延遲：double 在 radix-2 k=1 要 57 cycles，k=4 剩 15；radix-4 k=2 要 16。這是典型的面積/速度取捨——複製 k 份 recurrence 硬體換延遲。rv64gc 用 radix-4、k=4、`IDIV_ON_FPU=1`；rv32gc 用 radix-4、k=2、`IDIV_ON_FPU=0`、`IDIV_BITSPERCYCLE=2`。

### 兩種設定並存是刻意的

> "Also, having different configurations makes the regression suite test both floating-point and integer division hardware and different k."
> — p.661

中文解釋：不是為了效能才設不同，而是為了讓回歸測試同時涵蓋兩種實作路徑。這是驗證導向的設計決策。

### 整數除法搬到 FPU 上的代價

> "When IDIV_ON_FPU is 1 in the configuration files, the integer division logic from Section 15.4.3 is removed, and the FPU divider is enhanced to support integer division. ... DivBusyE is disabled; instead, FDivBusyE is used to stall both integer and floating-point division."
> — p.661

中文解釋：好處是省掉 MDU 裡的除法器。代價是要加整數的前後處理、改 FSM 選 cycle 數、在 IEU 資料路徑加一個多工器從 FPU 而非 MDU 取結果。而且 rv32gc 選擇不這麼做——運算元小，獨立的整數除法器反而划算。

### 轉換指令的命名規則

> "Note that the first letter specifies the destination format (half/single/double/quad) and the second specifies the source format, so fcvt.s.d converts a double to a single. w and wu are signed and unsigned 32-bit integers, and l and lu are signed and unsigned 64-bit integers."
> — p.661

中文解釋：**目的地在前、來源在後**，這點很容易記反。Table 16.19 列出每種模式組合下支援哪些轉換。RV64 因為多了 `l`/`lu`，整數轉換的數量直接翻倍。另外 RISC-V 的 float-to-int 轉換會設 Inexact 旗標（IEEE 稱這個運算為 *ConvertToIntegerExact*）。

### Sign injection：幾乎免費的三個指令

> "The fsgn sign injection block handles the fsgnj, fsgnjn, and fsgnjx instructions that modify the sign of X based on the sign of Y according to Table 16.20. The hardware involves only a few 1-bit multiplexers and gates."
> — p.662

中文解釋：Table 16.20：`fsgnj` 取 Y 的符號、`fsgnjn` 取 Y 符號的反相、`fsgnjx` 取兩者 XOR。這三個看似冷門，其實是三個常用操作的偽指令基礎：
- `fmv ft1, ft0` → `fsgnj ft1, ft0, ft0`（同一個來源，符號不變 = 搬移）
- `fneg ft1, ft0` → `fsgnjn ft1, ft0, ft0`（符號反相 = 取負）
- `fabs ft1, ft0` → `fsgnjx ft1, ft0, ft0`（自己 XOR 自己 = 0 = 取絕對值）

用幾個 1-bit 邏輯閘實作三個常用運算，這是 RISC-V 指令集設計精簡哲學的好例子。

### fclass 輸出 10 個 bit

> "The fclassify classification module handles the fclass instruction that writes a 10-bit code to the integer register file based on the characteristics of X according to Table 16.21. All of the characteristics are determined during unpacking, and the module contains only a handful of gates."
> — p.662–663

中文解釋：Table 16.21 的 10 個 bit（one-hot）：0 −∞、1 負正規、2 負 subnormal、3 −0、4 +0、5 正 subnormal、6 正正規、7 +∞、8 signaling NaN、9 quiet NaN。幾乎不花硬體，因為 unpack 已經把這些訊號算出來了。

### 為什麼 fround 要另外做一個模組

> "Reusing fcvt logic and adding the conversion back to floating-point would significantly increase the FPU postprocessing critical path or add an extra cycle that the pipeline does not presently support. Therefore, Wally adds a dedicated fround module that is surprisingly simple."
> — p.663

中文解釋：直覺會想「fround 不就是 float→int→float 嗎，重用 fcvt 就好」。但那條路會壓垮關鍵路徑或多花一個 cycle。專用模組反而簡單：用 thermometer-encoded 的 `TMask`（低位全 1，標出哪些位元進 sticky bit T'）、`IMask`（高位全 1，標出截斷後的整數部分 TRUNC）、以及 one-hot 的 `HotE`/`HotEP1`（標出 L' 和 R' 在哪一欄），靠 AND-OR 遮罩就抽出 L'、R'、T' 三個捨入位元。Fig. 16.22 是演算法、Fig. 16.23 是方塊圖、Example 16.21 示範 6.75 → 7.0。

### Zfa 對 Wally 的具體改動

> "When ZFA_SUPPORTED = 1, the FPU is enhanced to support the additional instructions from Section 16.4.5. The new and modified modules include: fli: New module with tables of immediates... fround: New rounding module... fpu: Two new move multiplexers... fcmp: Modifications supporting the NaN handling and flags for fminm/fmaxm/fltq/fleq; specialcase: fcvtmod.w.d result and flag multiplexing"
> — p.663

中文解釋：可以當成「加一個擴充要動哪些檔案」的範例清單。`fli` 只是一張常數表（用 rs1 和目的地大小當索引）。

### 可選的 IEEE 相容模式

> "By default, the Wally FPU generates canonical NaNs according to the RISC-V specification. When IEEE754 = 1 in config_wally.vh, the FPU will propagate NaN payloads instead, as recommended in the IEEE standard. This costs additional muxes in the postproc and fcmp units."
> — p.666

中文解釋：Wally 兩種行為都能做，設定切換。這也量化了 16.4.3 那個「不值得加多工器」的判斷——代價就是 postprocess 和 fcmp 裡的幾個多工器。

### 動態捨入模式的效能陷阱

> "Dynamic rounding is effectively a requirement of the C99 programming language standard. However, changing the fcsr flushes the pipeline, so performance is better when specifying the rounding mode in the instruction if modes change often."
> — p.666

中文解釋：改 `fcsr` 會 flush 管線（因為它是 CSR 寫入，後面已經取進來的指令可能用錯模式）。所以如果程式要頻繁切換捨入模式，把模式寫進指令的 `rm` 欄位遠比改 `fcsr` 划算。

### privileged unit 的兩個改動

> "When floating-point extensions are supported, the user-mode CSR module (csru) contains the fcsr, which is the only RISC-V user-mode CSR state. ... mstatus.FS is set to 11 (dirty) whenever FloatRegWriteW asserts."
> — p.666

中文解釋：`fcsr` 是 RISC-V 唯一的 user-mode CSR 狀態，所以 `csru` 這個模組就只為它存在（Fig. 16.24）。第二點的 dirty 位元很重要：只要有指令寫了浮點暫存器，硬體就把 `mstatus.FS` 設成 11（dirty），OS 看到 dirty 才需要在 context switch 時存那 32 個浮點暫存器——這是實打實的效能優化。

### hazard unit 加了兩種停頓

> "Like the integer multiplier and the LSU, the FPU's fma and fcvt modules have a two-cycle latency, introducing a structural hazard. If the sources of these floating-point instructions are dependent on the result of the preceding instruction, the processor must stall for a cycle. ... The IEU's controller generates FCvtIntStallD when this is detected during Decode."
> — p.668

中文解釋：Fig. 16.26 把 FPU 相關訊號標成藍色。兩個新的 stall 來源：`FPUStallD`（浮點指令相依於前一個兩週期指令）和 `FCvtIntStallD`（整數指令相依於 float-to-int 轉換的結果），都 OR 進 `StallDCause`。另外 `FDivBusyE` 加進 Flush Cause——和 15.4.4 的 `DivBusyE` 一樣，分支預測錯誤要等除法做完才能 flush Execute 級。至於 `fcmp`/`fclass`/`fmv` 這些單週期的 FPU→IEU 運算不需要新的停頓。

### LSU 為什麼可能需要快取

> "The external bus remains AHBW (typically XLEN), so if FLEN > AHBW, the system uses a data cache to service the wide accesses rather than going out to external memory. ... Presently, an LSU without a cache is unable to support the wide accesses needed for RV32D."
> — p.669

中文解釋：這是一個隱藏的相依性。RV32D 的 FLEN = 64 但 XLEN = 32，外部匯流排只有 32 位元，一次 64 位元的浮點 load/store 沒辦法直接發出去。有快取的話，快取線本來就比 64 位元寬，可以一次服務完；沒快取就做不到。LSU 還要加 `FWriteDataM` 埠、一個 IEU/FPU 寫入資料的多工器（寬度 LLEN = max(FLEN, XLEN)），以及把 FLEN 寬的 `ReadDataWordM` 縮成 AHBW 寬的 `LSUHWDATA` 的多工器給快取寫回用。

## 名詞表

| 名詞 | 意思 |
| --- | --- |
| FLEN | FPU 支援的最高精度位元數 |
| PLEN | 當前運算元的精度長度（≤ FLEN） |
| LLEN | max(FLEN, XLEN)，LSU 資料路徑寬度 |
| `fmt` | 指令中指定精度的欄位（00 single、01 double、10 half、11 quad） |
| `fregfile` | 浮點暫存器檔，32 entry × FLEN bit，3 讀 1 寫 |
| `premultiplex` | 在關鍵路徑外先把快的結果選好，減少最後一級多工延遲 |
| `FDIVSQRT_STEPS_PER_CYCLE` (k) | 每 cycle 跑幾步 recurrence |
| `IDIV_ON_FPU` | 是否讓整數除法借用 FPU 的除法器 |
| `FDivBusyE` | 除法進行中的訊號，用來 stall 管線 |
| thermometer code | 溫度計編碼，低位（或高位）連續全 1 的遮罩 |
| `TMask` / `IMask` | fround 用來抽出 sticky 位元／整數部分的遮罩 |
| `csru` | user-mode CSR 模組，只含 fcsr |
| `mstatus.FS` = 11 | dirty，表示浮點暫存器被改過，context switch 需要儲存 |
| `FPUStallD` / `FCvtIntStallD` | FPU 相依造成的兩種新停頓訊號 |
| Zfhmin | 只提供 half 的載入/儲存/搬移/轉換，計算用更高精度做的精簡擴充 |

## 所以呢

Wally 的 FPU 示範了一個完整的可設定浮點實作：用最寬精度共用硬體、把慢的東西（除法）做成可設定步數、把 corner case 全集中在 unpack 與 postprocess 兩端。同樣重要的是它揭露了加浮點的隱性成本——五個模組要改、暫存器檔面積暴增、RV32D 還被迫要有快取。下一節 16.7 做總結，然後第 17 章換題目：多執行緒與原子指令（A 擴充）。
