# 12.7 Summary

> 原書 p.544（Chapter 12: Load/Store Unit）

## 這節在講什麼

第 12 章總結，一段加一份清單。

**很短，但那份清單很有價值：它列出「整合本身需要哪些新硬體」——
也就是「把零件組起來」不是免費的。**

## 關鍵點

### LSU 的組態光譜

> "**The LSU is a highly configurable module responsible for loads and stores. In the simplest configuration, it only
>  has a DTIM. In the most sophisticated configuration, it interfaces to the EBU for main memory access, has a D$ to
>  service most accesses, contains an MMU with a TLB for virtual to physical address translation, a PMP for physical
>  memory protection, and a PMA for physical memory address checking; it also has an HPTW to service a TLB miss by
>  the HPTW taking over the memory system to walk the page table.**"
> — p.544

中文解釋：**兩個極端：**

| | **最簡單** | **最完整** |
| --- | --- | --- |
| 核心記憶體 | **只有 DTIM** | **D$** |
| 外部存取 | 無 | **EBU** |
| 位址轉譯 | 無 | **MMU + TLB** |
| 保護 | 無 | **PMP + PMA** |
| TLB miss | 無 | **HPTW（接管記憶體系統去走訪頁表）** |

**「HPTW taking over the memory system」這個描述很傳神**——
HPTW 不是一個獨立的記憶體介面，它是**借用 LSU 的資料通路**
（呼應 12.3.4 節的 `IHAdrM` mux 和 12.4.4 節的 `GatedStallW`）。

### 整合本身需要的五樣新硬體（本節精華）

> "**All these components have been described in earlier chapters. Some LSU features needed to coordinate among the
>  components include the following:
>  - The `buscachefsm` to sequence cache line fetches and writebacks
>  - Multiplexers so that the HPTW can take over the address and write data signals during page table walks
>  - Stall logic for multicycle LSU operations and data dependencies
>  - Trap logic for page, access, and misaligned faults
>  - Disabling interrupts when a multicycle memory operation is in flight**"
> — p.544

中文解釋：**「所有這些元件都在前面章節描述過了」——
但整合它們需要五樣新東西。這份清單是本章的核心貢獻：**

| 新增的協調機制 | 解決什麼問題 | 在哪一節 |
| --- | --- | --- |
| **`buscachefsm`** | **cache line 的 burst 抓取與寫回** | 12.2.1、12.2.2 |
| **多工器讓 HPTW 接管位址和寫入資料** | **頁表走訪時要用 HPTW 的位址** | 12.3.4（`IHAdrM`、`IHWriteDataM`） |
| **Stall 邏輯** | **多週期 LSU 操作 + 資料相依** | 12.4.1（`LSUStallM`、`GatedStallW`） |
| **Trap 邏輯** | **page、access、misaligned fault** | 12.4.2 |
| **停用中斷** | **多週期記憶體操作進行中** | 12.4.3（`CommittedM`） |

**這份清單的意義：整合不是「把方塊接起來」那麼簡單。
五樣中有三樣（stall、trap、停用中斷）是「和 pipeline 其餘部分協調」的邏輯。**

### 三個貫穿全章的設計原則

中文解釋：**把前面各節的內容抽出來，可以歸納出三個原則：**

**（1）「一旦開始就必須完成」**
- 匯流排交易（12.4.1、12.4.3）
- cache 的部分狀態更新（`DcacheCommittedM`）
- HPTW 的頁表走訪（`SelHPTW`）
- **後果：都要 assert `CommittedM` 延後中斷**

**（2）「pipeline stall 時，LSU 內部要繼續跑」**
- `GatedStallW = StallW & ~SelHPTW`（12.4.4）
- cache 和匯流排的 FSM 只在操作結束時檢查 Stall
- **否則會死鎖：stall 等 cache 完成，cache 等 unstall**

**（3）「cache 和 TLB 是虛擬/實體定址的邊界」**（12.3.3）
- **匯流排永遠只看到實體位址**
- cache way ≤ 4 KiB 讓 cache 和 TLB 能平行存取

## 所以呢

**第 12 章把第 7、9、10、11 章的零件組成完整的 LSU。**

三件最該帶走的事：

1. **整合需要五樣新硬體**（本章的核心貢獻）：
   **`buscachefsm`、HPTW 接管用的多工器、stall 邏輯、trap 邏輯、停用中斷的邏輯。**
   **其中三樣是「和 pipeline 協調」的邏輯——整合的成本主要在這裡。**

2. **`GatedStallW = StallW & ~SelHPTW` 是全章最關鍵的技巧**：
   **整條 pipeline stall，但 LSU 繼續跑以服務 HPTW。**
   否則就死鎖了。

3. **12.2.3 節那個「開機 Linux 當掉」的 bug 是本章最有價值的案例**：
   **「LSU 優先」這個單獨看正確的規則，加上虛擬記憶體之後，
   讓 HPTW 的請求搶走了進行中的 IFU burst。**
   **這種 bug 只有整合之後才會出現。**

下一章（第 13 章）做另一半：IFU，包括指令 cache 和分支預測器。
