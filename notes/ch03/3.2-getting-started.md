# 3.2 Getting Started

> 原書 p.90–91（Chapter 3: RISC-V Software Tool Flow）

## 這節在講什麼

安裝說明。很短，重點是**三種安裝方式**和**兩個環境變數**。

書上刻意不寫詳細步驟，因為會過時——**真正的說明在 repo 的 README。**
這節只交代架構：誰做什麼、東西裝在哪、怎麼確認裝好了。

## 關鍵點

### 三種安裝方式

> "Wally and its tools may be installed and used in one of three ways:
>  - On a personal Linux computer, having administrative access to install tools.
>    Clone the repository into a home directory.
>  - On a shared Linux server, where an administrator installs shared tools and users
>    clone the Wally repository into their home directories. We expect this to be the
>    most common case for universities and companies.
>  - Users install a Docker container that includes Ubuntu and some preinstalled tools."
> — p.90–91

中文解釋：**三種方式的差別在「工具裝在哪、誰有權限」：**

| 方式 | 工具裝在哪 | 適合誰 |
| --- | --- | --- |
| **個人 Linux 電腦** | 自己裝（需要 admin 權限） | 自學、個人開發 |
| **共用 Linux 伺服器** | **管理員裝一份共用**，使用者各自 clone repo | **大學和公司最常見** |
| **Docker 容器** | 容器裡已預裝 | **權限有問題、OS 不受支援、或 Linux 環境麻煩時** |

**共用伺服器模式是主流**，因為 RISC-V 工具鏈編譯很久、佔空間大，
而且商用 EDA 工具的授權是綁伺服器的（呼應 3.1 節）。

### 安裝說明在 repo，不在書上

> "The directions are likely to evolve over time, so they are part of the README in
>  the CORE-V-Wally (cvw) repository at github.com/openhwgroup/cvw."
> — p.91

> "The directions include *New User Setup* and *Toolchain Installation and
>  Configuration*. On a shared Linux server, each user performs the New User Setup,
>  and the administrator performs Toolchain Installation. On a personal Linux computer,
>  the user does both."
> — p.91

中文解釋：**兩份說明，對應兩種角色：**
- **New User Setup**：每個使用者都要做（設環境、clone repo）
- **Toolchain Installation and Configuration**：**管理員做一次**（編譯安裝工具鏈）

在個人電腦上，**兩份都要自己做**。

**書上明說步驟會演變，所以以 README 為準**——
讀這本書時遇到指令跑不動，先去看 repo 的 README。

### 兩個環境變數（最實用的一點）

> "Wally uses the environment variables $RISCV to point to the shared RISC-V tools
>  (typically in /opt/riscv or ~/riscv) and $WALLY to point to the cvw repository in a
>  home directory (typically ~/cvw). The setup.sh script sets these variables and
>  others to run RISC-V tools."
> — p.91

中文解釋：**這兩個變數整本書的指令都會用到，一定要記住：**

| 變數 | 指向 | 典型路徑 |
| --- | --- | --- |
| **`$RISCV`** | **共用的 RISC-V 工具** | `/opt/riscv`（共用伺服器）或 `~/riscv`（個人） |
| **`$WALLY`** | **cvw repository** | `~/cvw` |

**設定方式：執行 `setup.sh`。**

這個分離很合理：**工具是共用的（一份就好），repo 是個人的（每人一份）。**
所以 `$RISCV` 可能在 `/opt`（系統層），`$WALLY` 在家目錄。

（3.3.1 節的第一個範例就用到：`cd $WALLY/examples/asm/example`。）

### 確認裝好了：跑回歸測試

> "The New User Setup directions involve running make to build the tests, which takes
>  a while. Then run regression-wally. If all goes well, you'll see it print "Success"
>  on each test and then "SUCCESS! All tests ran without failures.""
> — p.91

中文解釋：**安裝驗證流程：**
```
make               # 建置測試（會跑很久）
regression-wally   # 跑回歸測試
```
**成功的訊號是：每個測試印 "Success"，最後印 "SUCCESS! All tests ran without failures."**

**"regression"（回歸測試）這個詞很重要**——
意思是「把所有測試重跑一遍，確認沒有退步」。
這是硬體開發的日常動作（第 5.11.6 節詳述）。

### 裝不起來的後路：Docker

> "If installing the toolchain on your system is problematic (because of lack of
>  administrator privileges, unsupported OS, general Linux software woes, and so on),
>  the cvw repository docs/docker.md describes how to install a Docker container with
>  many of the tools."
> — p.91

中文解釋：**Docker 是逃生門。** 文件在 `docs/docker.md`。
列出的三個典型問題（沒有管理員權限、OS 不受支援、一般的 Linux 軟體麻煩）
正好對應 3.1 節那句「找到所有工具都支援的 Linux 平台是持續的麻煩」。

**注意措辭是 "many of the tools"（許多工具）而非全部**——
商用工具（Questa、Design Compiler）不會在容器裡。

## 名詞表

| 名詞 | 意思 |
| --- | --- |
| `$RISCV` | 環境變數，指向共用的 RISC-V 工具（`/opt/riscv` 或 `~/riscv`） |
| `$WALLY` | 環境變數，指向 cvw repository（通常 `~/cvw`） |
| `setup.sh` | 設定上述環境變數及其他執行 RISC-V 工具所需設定的腳本 |
| New User Setup | 每位使用者都要做的設定步驟 |
| Toolchain Installation | 工具鏈安裝，共用伺服器上由管理員執行一次 |
| `regression-wally` | 回歸測試指令，用來確認環境與程式碼正常 |
| Regression（回歸測試） | 把所有測試重跑一遍，確認改動沒有造成退步 |

## 所以呢

**記住兩個環境變數 `$RISCV`（工具）和 `$WALLY`（repo），以及驗證指令 `regression-wally`——
後面所有章節的指令都建立在這兩個變數上。**
安裝細節以 repo 的 README 為準，書上的會過時；裝不起來就用 `docs/docker.md` 的容器。
下一節（3.3）開始真正動手：寫第一支組合語言程式，組譯、連結、反組譯、模擬。
