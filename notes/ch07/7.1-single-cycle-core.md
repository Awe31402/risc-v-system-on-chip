### 相對於 2.7 節的五個結構改變

> "On the surface, Fig. 7.2 closely resembles the simplified core from Fig. 2.9. **The prominent
>  structural change is a new AltResult multiplexer, which chooses an alternate value to write to
>  the register file: either the immediate for lui or PCPlus4 for jump return addresses.**
>  Under the hood are several other changes:
>  - The datapath is configurable to be either 32 or 64 bits for RV32 or RV64.
>  - **The ALU is enhanced to support the additional operations (xor, set less than unsigned,
>    shifts). It takes an extra bit of control to specify RV64's RW/IW instructions.**
>  - **The LSU adds circuitry to perform subword loads and stores.**
>  - **The comparator generates more flags (equal, less than, less than unsigned) to handle all
>    the flavors of branches, and the controller picks the appropriate flag.**
>  - The extender is enhanced to support U-format instructions.
>  - The controller adds entries for the new instruction categories: jalr, lui, and auipc."
> — p.301

中文解釋：**六個改變，每一個都對應一組新指令。**
**`AltResult` 多工器是唯一的結構性新增**——
因為 `lui` 要寫立即值、`jal`/`jalr` 要寫 PC+4，兩者都不是 ALU 的輸出。

**一個重要的設計決定（p.301 邊欄）：**
> "This design is slightly different than the processor in *Digital Design and Computer
>  Architecture* [Harris21], which uses the ALU for branch comparisons and a separate adder for
>  branch address calculations. **The revised organization, which uses the ALU for address
>  calculation and a dedicated branch comparator, saves a bit of hardware when supporting all
>  instructions and decreases critical path delay in small configurations.**"

**用 ALU 算位址 + 專用比較器，比用 ALU 比較 + 專用加法器好。**
（理由在 7.1.3.6 節詳述。）

### 架構狀態

> "Any processor must have a certain amount of *architectural state* to remember the information
>  visible to the programmer. In RISC-V, the architectural state comprises the PC, which contains
>  the address of the current instruction, and the integer register file (IRF), which contains
>  registers x1-x31. **The single-cycle microarchitecture has this architectural state,
>  instruction and data memories, and no other memory elements.**"
> — p.302

中文解釋：呼應 2.7 節的架構狀態定義。**單週期版本沒有任何非架構狀態。**

**暫存器檔案的三個埠（p.303）：**
> "The IRF has three ports, so it can read two source registers and write a destination register
>  in one cycle. Ports 1 and 2 are read ports, each with a 5-bit address (A1/A2) that specifies
>  which of the 32 registers to read, and an XLEN-bit read data port (RD1/RD2).... Port 3 is a
>  write port where A3 specifies the register and WD3 specifies the data to write; WE3 specifies
>  whether to write and a clock specifies when to write (on the rising edge). **Register 0 is
>  hardwired to 0, and writes to it are ignored.**"

（呼應 2.7 節和 4.2.3.3 節。）

**記憶體的性質（p.303）：**
> "In this implementation, the instruction memory is read-only and is preloaded with the program
>  before the processor starts executing. The data memory is readable and writable."

### 立即值延伸：Table 7.2 是完整規格

> "Another source of operands for many instructions comes from a 12-, 13-, 21-, or 32-bit
>  immediate that is encoded in a 12- or 20-bit immediate field that is scattered around the
>  instruction.... **The extender is just a big multiplexer controlled by an ImmSrc signal that
>  depends on the instruction format.**"
> — p.303

中文解釋：**Table 7.2（p.303）是 extend 模組的完整規格，
比 2.2 節的 Fig. 2.4 更精確：**

| ImmSrc | ImmExt | Type | 說明 |
| --- | --- | --- | --- |
| **000** | `{{20{Instr[31]}}, Instr[31:20]}` | **I** | 12-bit signed |
| **001** | `{{20{Instr[31]}}, Instr[31:25], Instr[11:7]}` | **S** | 12-bit signed |
| **010** | `{{20{Instr[31]}}, Instr[7], Instr[30:25], Instr[11:8], 1'b0}` | **B** | 13-bit signed |
| **011** | `{{12{Instr[31]}}, Instr[19:12], Instr[20], Instr[30:21], 1'b0}` | **J** | 21-bit signed |
| **100** | `{Instr[31:12], 12'b0}` | **U** | 20-bit signed |

**五個要點：**
1. **B 和 J 型末尾硬接 `1'b0`**（呼應 2.1 節：最低位元恆為 0）
2. **U 型最特殊：不做符號延伸，而是左移 12 位**（`lui`/`auipc`）
3. **RV64 還要再把 bit 31 延伸到 63:32**（p.303）
4. **符號位元永遠是 Instr[31]**（呼應 2.2 節：fanout 最大所以位置固定）
5. `ImmSrc` 是 3 bit（2.7 節的簡化版只有 2 bit，因為沒有 U 型）

**編碼「看起來很怪但其實是最佳化過的」（p.303 邊欄）：**
> "RISC-V immediate encodings are strange to look at but are optimized to minimize the cost and
>  delay of the sign extension multiplexers and to avoid interfering with the other instruction
>  fields."

### 三個算術區塊

> "The processor has three arithmetic blocks:
>  - **ALU**: Performs an arithmetic, shift, or logical operation and address calculation
>  - **Comparator**: Compares two registers to produce flags for branches
>  - **Incrementer**: Increments the PC by 4 to calculate the next PC"
> — p.303

中文解釋：**Table 7.3（p.304）列出每種指令用到哪些算術電路，這張表是資料通路的地圖：**

| 類別 | ALUResult | IEUResult | IEUAdr（與目的地） | Comparator |
| --- | --- | --- | --- | --- |
| R-Type ALU | **R1 op R2** | ALUResult | x | |
| I-Type ALU | **R1 op ImmExt** | ALUResult | x | |
| Loads/Stores | X | x | **R1 + ImmExt → LSU** | |
| Branches | X | x | **PC + ImmExt → IFU** | **R1 cmp R2** |
| `jal` | X | **PCPlus4** | **PC + ImmExt → IFU** | |
| `jalr` | X | **PCPlus4** | **R1 + ImmExt → IFU** | |
| `lui` | X | **ImmExt** | x | |
| `auipc` | **PC + ImmExt** | ALUResult | x | |

**讀表的重點：**
- **ALU 的第一個來源是 R1 或 PC**（`auipc` 和 branch/`jal` 用 PC）
- **第二個來源是 R2 或 ImmExt**
- **`IEUAdr` 是 ALU 加法器的早期輸出**，直接給 LSU 和 IFU 當位址

**為什麼要有 IEUAdr 這條早期輸出（p.304）：**
> "**To minimize delay, the ALU also provides its adder output early (before the ALU's internal
>  multiplexer, see Fig. 7.3) as IEUAdr, which is sent to the LSU and IFU (instruction fetch unit)
>  as an address for memory operations, branches, and jumps.**"

**（p.305 邊欄再確認：「IEUAdr 輸出比 ALUResult 快，因為它跳過了多工器延遲。
這降低了存取記憶體時的關鍵路徑。」）**

### ALU 的結構

中文解釋：Fig. 7.3（p.305）的 ALU 電路圖。**核心結構：**
> "The ALU computes all operations in parallel and selects ALUResult from among them with a large
>  multiplexer. **The adder optionally inverts the B input to perform sub, slt, or sltu.**
>  The shifter performs logical left shifts and logical and arithmetic right shifts (sll, srl, and
>  sra). In RV64, it also handles W-type shifts on 32-bit words. **The slt and sltu functions
>  compute the lt and ltu flags and place them in the least significant bit of the result, with 0s
>  in the upper bits.** Bitwise gates perform and, or, and xor."
> — p.305

**ALUSelect 的編碼（從 Fig. 7.3 讀出）：**

| ALUSelect | 運算 |
| --- | --- |
| **000** | add / sub |
| **?01** | shift |
| **010** | slt |
| **011** | sltu |
| **100** | xor |
| **110** | or |
| **111** | and |

**「所有運算並行計算，再用一個大多工器選」——
這是 ALU 的標準做法，因為選擇比串聯快。**

**四個控制訊號：`SubArith`、`W64`、`Right`（= Funct3[2]）、`ALUSelect[2:0]`。**

### 加法器：交給合成工具

> "The adder in the ALU performs addition or subtraction based on the control signal SubArith.
>  When SubArith = 0, it adds, computing Sum = SrcA + SrcB. When SubArith = 1, it subtracts,
>  computing Sum = SrcA + SrcB + 1 = SrcA − SrcB, **using the two's complement identity that
>  -X = X̄ + 1.** Adder architectures and their area/delay tradeoffs have been heavily researched....
>  **It is usually expedient to describe the adder with + in the HDL and allow the logic synthesis
>  tool to select the best adder given the constraints. If the adder is timing critical, synthesis
>  generally produces a parallel prefix tree with O(log₂N) delay.**"
> — p.305

中文解釋：**減法的技巧：反相 B 並把進位輸入設為 1**（二補數）。
**`SubArith = 1` 同時當作「反相 B」和「進位輸入」——一個訊號做兩件事。**

**加法器架構交給合成工具選**（呼應 4.1、6.1、6.2.2 節）。

### Funnel shifter：本節最巧妙的設計

> "An N-bit *funnel shifter* creates a (2N-1)-bit input word and then right shifts it to produce
>  an N-bit result, like a funnel necking down from wide to narrow. On the other hand, an N-bit
>  *barrel shifter* takes an N-bit input and rotates it to produce an intermediate N-bit result.
>  It then applies a mask to handle sign or zero extension on the bits that should be discarded.
>  **Funnel shifters are simpler for RISC-V because the integer instruction set does not have
>  rotate instructions.**"
> — p.306

中文解釋：**兩種移位器架構，RISC-V 選 funnel shifter，因為整數指令集沒有旋轉指令。**

（邊欄，p.306：**barrel shifter 想像成一個橫躺的木桶，輸入位元畫在圓周上；
旋轉木桶後從新的頂點讀起，就得到旋轉後的位元序列。**）

**Funnel shifter 的運作原理（p.306），這段要懂：**
> "A funnel shifter creates a source word Z_{2N-2:0}, shifts it right by k, and delivers the bottom
>  N bits as the result Y."

**核心觀念：所有移位（左移、右移、算術右移）都轉換成「對一個加寬的 Z 做右移」。**

| 移位類型 | Z 的組成 | 移位量 |
| --- | --- | --- |
| **srl**（邏輯右移） | **A 在低 N 位，上面 N−1 位補 0** | k |
| **sra**（算術右移） | **A 在低 N 位，上面補符號位元 A_{N-1}** | k |
| **sll**（邏輯左移） | **A 在最高 N 位，下面 N−1 位補 0** | **k̄（= N−1−k）** |

**左移轉右移的技巧最漂亮（p.306）：**
> "Shift left logical (sll) places A in the most significant N bits of Z and 0s in the bottom N-1
>  bits of Z and then right shifts by the bit-wise complement of k (k̄), which is N-1-k.
>  For example, **a left shift by 0 becomes a right shift by N-1 (i.e., all 1s: 111…1), which
>  discards all the 0s and produces Y = A.** Likewise, a left shift by 1 becomes a right shift by
>  N-2 (i.e., 1111…10), which produces Y = {A_{N-2:0}, 0}."

**「左移 k」= 「把 A 放在高位、右移 (N−1−k)」，而 N−1−k 剛好是 k 的位元反相。
所以只要一組 XOR 閘就能切換左右移。**

**Table 7.4（p.307）64-bit 版（含 W 型）：**

| Shift Type | Z | Shift Amount |
| --- | --- | --- |
| `srl` | `{63'b0, A_{63:0}}` | k |
| `sra` | `{{63{A_63}}, A_{63:0}}` | k |
| `sll` | `{A_{63:0}, 63'b0}` | **k̄** |
| `srlw` | `{95'b0, A_{31:0}}` | k |
| `sraw` | `{64'b0, {31{A_31}}, A_{31:0}}` | k |
| `sllw` | `{32'b0, A_{31:0}, 63'b0}` | **k̄** |

**Table 7.5（p.307）是 RV32 的簡化版（只有三種，Z 只要 63 bit）。**

**硬體結構（Fig. 7.4，p.306）：**
> "Fig. 7.4 shows a 64-bit funnel shifter that can handle the various flavors of RV64I shifts.
>  This design uses a multiplexer to choose 127 bits of Z according to Table 7.4 followed by
>  **six levels of 2:1 multiplexers to shift right by each power of two.**"

**127 bit → 95 → 79 → 71 → 67 → 65 → 64**，
**六級 2:1 多工器分別右移 32、16、8、4、2、1 位。**
**匯流排寬度一級一級收窄——這就是「漏斗」的由來。**

**XOR 閘負責左移時反相移位量**（p.307）。
**有些實作用 4:1 或 8:1 多工器減少邏輯層數**（p.307）。

**Example 7.1（p.307）的計算值得跟一遍：**
> "How does a 64-bit funnel shifter perform the 32-bit arithmetic left shift (`sllw`)
>  0x00000024 << 4?
>  **Solution:** The inputs are A = 0x0000000000000024 and k = 0b000100. The funnel shifter forms
>  the 127-bit input word Z according to Table 7.4: **Z = {32'b0, A_{31:0}, 63'b0}** =
>  0x0000000000000012000000000000000. The shift amount is **k̄ = 0b111011 = 59**.
>  The funnel shifter shifts Z right by the shift amount, producing 0x000000000000240."

**左移 4 = 右移 59。驗證：0x24 << 4 = 0x240 ✓**

### Set Less Than：溢位的處理

> "`slt` and `sltu` instructions compute {C, Sum} = A − B = A + (B̄ + 1) and check if the result is
>  negative, which indicates that A < B. They can make the sign determination based on the two most
>  significant bits of the difference {C, Sum_{N-1}}, which are called the **C (carry out** or,
>  simply, **carry)** and **N (negative)** flags: N = Sum_{N-1}."
> — p.308

中文解釋：**兩種比較的判斷方式不同，這是重點：**

**無號比較（簡單）：**
> "For unsigned comparison, A and B are both positive. If the carry out is 0, A − B is negative
>  (so A is less than B). **Thus, `sltu` = C̄.**"

**`sltu` = 進位輸出的反相。一個閘搞定。**

**有號比較（要處理溢位）：**
> "For signed comparison, we must consider overflow. When overflow occurs, the result's sign bit
>  (and thus, N) is wrong. **When subtracting, overflow occur when two conditions are true:
>  (1) A and B have opposite signs, which, when subtracting, is effectively adding values of the
>  same sign: (A_{N-1} ⊕ B_{N-1}), and (2) the result's sign (N = Sum_{N-1}) differs from A's sign:
>  (A_{N-1} ⊕ N). Thus, the *overflow* flag V = (A_{N-1}⊕ B_{N-1})(A_{N-1} ⊕ N).**
>  The true result is negative when N ⊕ V. In other words, when overflow occurs, the N flag gave
>  the wrong value, so it must invert. This simplifies to
>  **`slt` = N ⊕ V = A_{N-1}B̄_{N-1} + A_{N-1}N + B̄_{N-1}N.**"

**推理鏈：**
1. 溢位條件：**A 和 B 符號相反，且結果的符號和 A 不同**
2. 溢位時 N 是錯的，所以要反相：**真正的「小於」= N ⊕ V**
3. 化簡後得到一個三項的 sum-of-products

**（邊欄提醒，p.308：**「小心 negative flag 的 N 和字長的 N 是無關的同名變數。」**）**

### W-Type 指令的 Trunc 多工器

> "For W-type RV64 instructions, the full 64-bit result should be truncated to 32 bits and then sign
>  extended into the upper 32 bits. **The 32-bit Trunc multiplexer shown in Fig. 7.5 performs this
>  operation by choosing the upper half of ALUResult from either the full result or by sign-extending
>  bit 31. In RV32, no W-type instructions exist, and this Trunc multiplexer is omitted.**"
> — p.308

中文解釋：**Trunc 多工器很簡單：`W64 = 1` 時上半部全部取 bit 31（符號延伸），
否則取原本的上半部。**（呼應 2.1 節 W 指令的語意。）

**`W64 = 0` 時 ALUResult[63:32] = FullResult[63:32]；
`W64 = 1` 時 ALUResult[63:32] = {32{FullResult[31]}}。**

### 為什麼要專用比較器（四個理由）

> "The dedicated branch comparator produces the eq and lt/ltu flags for branches based on two source
>  registers. **Wally uses a dedicated comparator rather than reusing the adder and slt logic because
>  comparison is on the critical path of a simple pipelined processor and because the adder is also
>  needed to compute the branch destination.** The comparator is faster than the regular ALU for
>  several reasons:
>  - **The branch comparator inputs come from the register file, rather than the Src{A/B} and SubArith
>    muxes.**
>  - **Computing flags is less expensive than producing a full XLEN-bit result.**
>  - **The flags are available without waiting for ALU multiplexing after the adder.**"
> — p.308–309

中文解釋：**四個理由，每一個都是「省掉一段延遲」：**
1. **加法器已經被拿去算分支目標位址了**（Table 7.3：branches 的 IEUAdr = PC + ImmExt）
2. **輸入直接來自暫存器檔案，不經過 SrcA/SrcB 多工器**
3. **只算旗標比算完整 XLEN 位元便宜**
4. **不用等加法器後面的 ALU 多工器**

（呼應 6.5.3 節 Table 6.11：rv32e 和 rv32i/rv64i 的關鍵路徑都在分支比較。）

### Prefix comparator：從減法器最佳化而來

中文解釋：**Equations 7.1–7.6（p.309）是最佳化的 prefix comparator：**

```
預計算（Precomputation）
(7.1)  E_i = ~(A_i ⊕ B_i)      A 和 B 的第 i 位元相等
(7.2)  L_i = Ā_i B_i            A 的第 i 位元 < B 的第 i 位元（無號）

前綴遞迴（Prefix Recursion）
(7.3)  E_{i:j} = E_{i:k} E_{k-1:j}                    位元 i:j 相等
(7.4)  L_{i:j} = L_{i:k} + E_{i:k} L_{k-1:j}          位元 i:j 無號小於

輸出邏輯（Output Logic）
(7.5)  eq  = E_{N-1:0}          A == B
(7.6)  ltu = L_{N-1:0}          A < B（無號）
```

**(7.4) 的邏輯要理解：「i:j 小於」= 「上半部小於」**或**「上半部相等且下半部小於」。**
這就是字典序比較的遞迴定義。

**有號比較的技巧（p.309），非常漂亮：**
> "**Signed comparison can be performed with the same hardware as unsigned comparison by flipping
>  the most significant bit of A and B.** The principle is that unsigned numbers are in the range
>  [0, 2^N − 1], and signed numbers are in the range [−2^{N-1}, 2^{N-1} − 1]. **Flipping the most
>  significant bit is equivalent to adding 2^{N-1} to both positive and negative two's complement
>  numbers and converts them to unsigned inputs (i.e., shifts them to the range [0, 2^N − 1])
>  without changing which one is less.**"

**「反相最高位元」= 「加上 2^{N-1}」= 把有號範圍平移到無號範圍，而大小關係不變。**

**Example 7.2（p.310）的驗證：**
> "Compare −7 and 3: −7 is 0xFFFFFFF9, and 3 is 0x00000003. **Flipping the most significant bit of
>  each number and performing unsigned comparison results in: 0x7FFFFFF9 < 0x80000003, which is
>  correct (−7 < 3).** −5 is 0xFFFFFFFB, and −10 is 0xFFFFFFF6. Flipping... results in:
>  0x7FFFFFFB ≥ 0x7FFFFFF6, which is correct (−5 ≥ −10)."

**所以完整的比較器只要加兩個 XOR 閘**（p.310）：
> "Thus, the comparator handles both signed and unsigned comparison by adding two XOR gates to
>  conditionally flip the most significant bits of each input for signed comparison and then using
>  the unsigned comparison described earlier.... **Thus, an N = 2^ℓ-bit comparator's critical path
>  involves an XOR to handle signed/unsigned comparison, two 2-input gates for precomputation, and
>  ℓ levels of AND and AND-OR logic to compute L_{N-1:0} and E_{N-1:0}.**"

**關鍵路徑 = 1 個 XOR + 2 個 2 輸入閘 + log₂N 層 AND/AND-OR。**

### 比較器 vs 減法器：省了多少

中文解釋：**Equations 7.7–7.14（p.310）是減法器版本的遞迴，
和比較器的結構幾乎一樣（P 對應 E、G 對應 L）。**

**Fig. 7.6（p.311）並排畫出兩者的 prefix network，差別很明顯（p.311）：**
> "For both networks, the precomputation is the same, with N AND, XOR, and NOT gates. **The optimized
>  comparator produces only the final eq and ltu results, so it does not need to calculate the
>  intermediate column results or the Sum output. Thus, whereas the subtractor has Nlog₂N / 2
>  recurrence cells (black boxes), the comparator only has N recurrence cells, and the N final XORs
>  to produce the Sum in the subtractor are not needed in the comparator.**"

**省了多少：**
| | 遞迴單元數 | 最後的 XOR |
| --- | --- | --- |
| **減法器** | **N·log₂N / 2** | N 個 |
| **比較器** | **N** | 0 |

**N = 32 時：減法器 80 個遞迴單元，比較器只要 32 個，而且省掉 32 個 XOR。**
**理由是「比較器只要最終結果，不需要中間各欄的結果」**——
Fig. 7.6(b) 上看得出來只有最右邊那一條鏈。

**但實務上不用自己寫（p.311）：**
> "**Despite these design optimizations, Design Compiler is smart enough to synthesize high-level
>  operations onto well-optimized DesignWare blocks, so we do not need to write prefix equations to
>  get satisfactory results.** Thus, Wally's comparator module in Code Example 7.1 expresses the
>  comparison operations in Verilog using == and < statements rather than prefix equations."

**Code Example 7.1（p.311）的實際程式碼，只有四行：**
```systemverilog
// For signed numbers, flip msb before comparing
assign af = {a[WIDTH-1] ^ sgnd, a[WIDTH-2:0]};
assign bf = {b[WIDTH-1] ^ sgnd, b[WIDTH-2:0]};
assign eq = (a == b);      // Equality
assign lt = (af < bf);     // Signed or unsigned less than
```
**`sgnd` 控制要不要反相最高位元——一個訊號就切換有號/無號。**
（呼應 4.1 節：寫 `<`，工具幫你選最佳實作。）

**硬體的巧妙之處（p.313）：**
> "**This table simplifies to a 4:1 multiplexer to select the flag of interest followed by an XOR to

### ALU Decoder

> "The controller's ALU decoder determines the ALU's operation by producing ALUSelect and SubArith,
>  which is 1 when subtracting or arithmetic right shifting.... **W64 comes from the main decoder,
>  and Right = Funct3[2], which is 1 when right shifting.**"
> — p.313

中文解釋：**`ALUSelect = Funct3` 對 ALU 指令，或 000 對 `auipc`**（p.314）。

**`SubArith` 的邏輯（p.314）：**
```
slt      = (Funct3 == 010)
sltu     = (Funct3 == 011)
sra      = (Funct3 == 101 & Funct7[5])
sub      = (Funct3 == 000 & Funct7[5] & Op[5])
SubArith = ALUOp & (slt | sltu | sra | sub)
```

**`sub` 要檢查 `Op[5]` 的理由（p.314 邊欄）：**
> "**Note that sub also needs to look at bit 5 of the opcode to distinguish sub from addi, which has
>  the same Funct3 field and no Funct7.**"

**因為 `addi` 沒有 Funct7 欄位（那些位元是立即值的一部分），
所以必須用 Op[5] 分辨 R-type（有 Funct7）和 I-type（沒有）。**

**Lazy decoder 的代價（p.314 邊欄）——重要：**
> "**This decoder is *lazy* in that it only looks at bit 5 of Funct7 rather than checking
>  Funct7 == 0100000. When traps are supported, RISC-V strongly recommends throwing an
>  illegal-instruction exception if Funct7 ≠ 0100000. Thus, when ZICSR_SUPPORTED = 1, the decoder is
>  stricter, at the cost of a few extra gates.**"

（呼應 2.7.1.2 節的 lazy decoder，這裡給了它的解決方案。）

### LSU：subword load/store 的實作

> "The DTIM internally accesses entire XLEN-bit words or double words. **To handle an instruction such
>  as lb, lbu, lh, or lhu, the DTIM reads the full word, extracts the appropriate byte or halfword,
>  places it in the least significant bits of the result, and then sign extends to full length.**
>  To handle sb or sh, **the DTIM replicates the subword into all positions of the data write signal's
>  word. It asserts byte write signals (ByteMask) to indicate which bytes within the word should be
>  written based on the size of the store (indicated by Funct3) and the offset within the word
>  (in the least significant bits of Adr).**"
> — p.315

中文解釋：**這是本節最實用的實作知識。兩個方向的處理完全不同：**

| 方向 | 做法 |
| --- | --- |
| **Subword load** | **讀整個字 → 抽出對應的 byte/halfword → 放到最低位元 → 符號或零延伸** |
| **Subword store** | **把 subword 複製到整個字的所有位置 → 用 ByteMask 指定哪些 byte 真的要寫** |

**「複製到所有位置 + byte mask」是個聰明的做法**——
不必用多工器把資料移到正確位置，**只要把它複製滿，再用遮罩選。**

**Fig. 7.9（p.315）的 RV64 LSU 有三個子模組：**

**（1）`subwordwrite`**：用 `Funct3[1:0]` 選擇
```
00 → 8 copies of WriteData[7:0]      （sb）
01 → 4 copies of WriteData[15:0]     （sh）
10 → 2 copies of WriteData[31:0]     （sw）
11 → WriteData[63:0]                 （sd）
```

**（2）`swbytemask`**：從 `{Funct3[1:0], Adr[2:0]}` 產生 8-bit ByteMask
```
(sb) 00_000 → 00000001    (sh) 01_00x → 00000011
(sb) 00_001 → 00000010    (sh) 01_01x → 00001100
(sb) 00_010 → 00000100    (sh) 01_10x → 00110000
...                       (sw) 10_0xx → 00001111
(sb) 00_111 → 10000000    (sw) 10_1xx → 11110000
                          (sd) 11_xxx → 11111111
```
**注意 `sh` 的位址只看 Adr[2:1]（低位是 x），`sw` 只看 Adr[2]，`sd` 完全不看**——
**因為對齊要求。**

**（3）`subwordread`**：用 `Funct3[2:0]` 選出並延伸
```
011 → ld（整個 64-bit）
010 → lw（SEXT）    110 → lwu（ZEXT）
001 → lh（SEXT）    101 → lhu（ZEXT）
000 → lb（SEXT）    100 → lbu（ZEXT）
```
**先用 Adr 的低位元選出對應的 byte/halfword/word，再依 Funct3[2] 決定符號或零延伸。**
（`Funct3[2] = 1` 表示無號，呼應 2.1 節。）

**RV32 版本更簡單（p.315）：「去掉 `sd`、`ld`、`lwu`，只產生 4-bit ByteMask 和
32-bit WriteData 與 ReadData。」**

**另一種做法及其缺點（p.315 邊欄）：**
> "**Another way to perform a subword write to memory is to read the word from memory, modify it, and
>  write it back. This is slower and consumes more power.** The hardware to implement bit or byte
>  enables is modest, so most static random access memory (SRAM) generators and field programmable gate
>  array (FPGA) memories support such enables."

### LLEN：原生存取寬度

> "The LSU supports subword operations, but the random access memory (RAM) always reads and writes
>  full-length *native* words. When the core doesn't have floating-point hardware, the native length is
>  **LLEN = XLEN**. When floating-point is added in Chapter 16, the native length becomes
>  **LLEN = max(XLEN, FLEN)**. Read LLEN as the "longer" of XLEN and FLEN."
> — p.315–316

中文解釋：**LLEN = max(XLEN, FLEN)。**

**書上的例子（p.316）：**
> "For example, **a RV32GC configuration has XLEN = 32 but FLEN = 64, so the native accesses are
>  64-bit words. The ReadData and WriteData bus widths are this native length.**"

**RV32GC 的資料匯流排是 64 bit，不是 32 bit**——
因為要載入雙精度浮點數。
（呼應 5.7.1 節那個 assertion：`FLEN > XLEN` 時必須有資料 cache。）

## 所以呢

**這節把 2.7 節的玩具核心擴充成完整的 RV{32/64}I 單週期處理器。**

五個最該帶走的設計技巧：

1. **Funnel shifter**：把三種移位統一成「加寬後右移」，
   **左移靠「移位量取反相」實現**——一組 XOR 閘就切換方向。

2. **有號比較 = 反相最高位元後做無號比較**——兩個 XOR 閘解決。

3. **Prefix comparator 比減法器省很多**（N vs N·log₂N/2 個遞迴單元），
   **因為只要最終結果，不要中間欄的值。**

4. **Subword store 的「複製滿 + ByteMask」**比「移位到正確位置」簡單。

5. **Branch logic 只要一個 4:1 mux + 一個 XOR** 就處理七種分支。

還有兩個系統層面的觀念：
- **`IEUAdr` 是 ALU 的早期輸出**——跳過多工器，縮短記憶體存取的關鍵路徑。
- **`LLEN = max(XLEN, FLEN)`**——RV32GC 的資料匯流排是 64 bit。

下一節（7.2）把這個單週期核心切成五級 pipeline。
