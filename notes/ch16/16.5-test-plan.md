# 16.5 Test Plan

> 原書 p.651–655（Chapter 16: Extensions: F/D/Q/Zfh/Zfa (Floating-Point)）
> 涵蓋 16.5.1 riscv-arch-test、16.5.2 TestFloat

## 這節在講什麼

浮點驗證分成兩層。第一層用 riscv-arch-test（第 13 章那套 RISCOF 流程）跑真正的 RISC-V 程式，證明「指令有接上管線、解碼對、寫回對」。第二層用 UCB TestFloat 直接對 Verilog 模組灌測試向量，證明「每個運算單元的每個 corner case 都算對」。第二層跳過 CPU，因為要跑的案例數量是千萬等級，走指令流太慢。

## 關鍵點

### 兩層驗證各自負責什麼

> "Floating-point verification is notoriously tricky. Wally tests the FPU using the riscv-arch-test suite to prove basic functionality of the pipeline and the units and also tests each unit using the robust UCB TestFloat suite to verify corner cases."
> — p.651

中文解釋：分工很清楚。arch-test 管「整體有沒有接對」，TestFloat 管「算得對不對」。兩者都需要，少了任何一邊都有洞。

### riscv-arch-test 的來源是 IBM 的測試套件

> "The riscv-arch-test suite contains rv32i_m/F, rv32i_m/D, rv64i_m/F, and rv64i_m/D test suites for single- and double-precision floating-point instructions. It is derived from the IBM Floating-Point Test-Suite for IEEE [Aharoni08]. The IBM test suite defines categories of tests identified in Table 16.14. IBM uses the FPgen test generator to create inputs covering all the situations."
> — p.651–652

中文解釋：Table 16.14 列出 29 個測試類別（B1–B29），值得看一眼它們在測什麼，因為那就是浮點最容易出錯的地方清單：
- B1 基本型別的所有正負號組合（0、1、min subnorm、subnorm、max subnorm、min norm、norm、max norm、INF、NaN）——三輸入指令就要 13,835 個案例
- B3 捨入（sign、LSB、guard、sticky）1,124 個
- B4/B5 溢位與接近溢位、下溢與接近下溢
- B7 sticky bit 計算、B8 捨入邊界附近 1,684 個
- B10–B13 加法專屬：移位、移位配上特殊 significand（7,016 個）、cancellation、cancellation 產生 subnormal 結果
- B14–B18 FMA 專屬，其中 B15「FMA: shift combined with special significands」光 double 就 102,005 個案例
- B20/B21 除法的 trailing zeros 與 divide-by-zero
- B22–B29 各種轉換

### FMA 測試被拆出來平行跑

> "The floating-point tests are the slowest part of the regression, and the FMA tests are the biggest part of the floating-point tests. To speed up regression, the FMA tests are separated out to run in parallel with the other tests."
> — p.652

中文解釋：從 Table 16.14 的數字就看得出來為什麼——B15 一個類別的 double 案例數就超過十萬。所以有 rv32gc_arch32d_fma、rv64gc_arch64f 這類拆開的測試套件。另外約 91% 的測試用 RNE 模式，其餘才測其他捨入模式。

### TestFloat 直接測 Verilog，不走指令

> "TestFloat produces test cases to check compliance of floating-point implementations using the UCB SoftFloat library to compute expected results. Wally has a testbench to run the TestFloat tests directly on Verilog FPUs rather than by creating RISC-V programs."
> — p.652

中文解釋：這是關鍵的效率決定。testbench 是 `$WALLY/testbench/testbench-fp.sv`，它讀 `$WALLY/tests/fp/vectors` 下的向量，餵進 unpacker 和各個單元，直接比對結果與旗標。跳過取指、解碼、寫回，一個 cycle 就能測一個案例。

### 測試向量的產生量與 level 選擇

> "It generates separate test vectors files for every rounding mode rm ∈ {rd, rne, ru, rz, rnm} and precision fp ∈ {f16, f32, f64, f128}. Integer conversions also support integer precisions ip ∈ {i32, u32, i64, u64}."
> — p.652

中文解釋：五種捨入模式 × 四種精度 × 每個運算 = 一大堆檔案。Table 16.15 給出數量：fadd/fsub/fmul/fdiv 各 46,464 個，fsqrt 依精度 2,448/8,800/26,112/69,108 個，**fmadd 有 6,133,248 個**。TestFloat 有 `-level 1` 和 `-level 2` 兩個檔次，Wally 對「單輸入」運算（sqrt、convert）用 level 2，其餘用 level 1——因為 level 2 對雙輸入運算會產生數千萬到數億個案例。完整測試向量有 8 GB，所以是現場產生而不是存進 repo。

### RISC-V 偏離 SoftFloat 預設行為的四個地方

> "RISC-V deviates from the default IEEE behavior of SoftFloat in four ways: 1. RISC-V NaN boxes lower-precision floating-point numbers stored in wider registers. 2. Floating-point to unsigned integer conversions of negative numbers produce all 1s in IEEE but all 0s in RISC-V. 3. Floating-point to integer conversions that overflow the positive range produce the most negative integer (0x8000…) in IEEE, but the largest positive integer (0x7FFF… signed or 0xFFFF… unsigned) in RISC-V. 4. Operations with a NaN input preferably propagate the payload to the output in IEEE but produce a canonical NaN in RISC-V."
> — p.654

中文解釋：這就是為什麼 SoftFloat 要用 `SPECIALIZE_TYPE=RISCV` 編譯旗標。這四點全都是「合法但不同」的選擇，如果沒設這個旗標，參考模型會和硬體對不起來，然後你會花很久 debug 一個根本不是 bug 的東西。第 3 點特別實用：飽和（saturate）到最大正整數比環繞到最小負整數對程式設計師友善得多。

### 測試向量的檔案格式

> "For example, f32_mulAdd_rne.tv is shown in Fig. 16.18. The first three 32-bit hexadecimal numbers are the three source operands. The fourth 32-bit number is the result. The next two digits are a 5-bit hexadecimal number representing flags: {Invalid, Divide by Zero, Overflow, Underflow, Inexact}."
> — p.652

中文解釋：純文字、底線分隔、用 `$readmemh` 讀進來。簡單到不需要任何 parser。

### 除法器另有一套整數/浮點合併向量

> "make also creates test vectors for the combined integer divide/remainder and floating-point divide/square root unit in tests/fp/combined_IF_vectors/IF_vectors. ... The format of these vectors is operation_A_B_Y_flags_roundingMode, with the operation code defined in Table 16.16."
> — p.652–655

中文解釋：因為 16.2.3 講過 `fdivsqrt` 同時服務整數與浮點除法，所以測試向量也要合併。Table 16.16 的十種 operation code：0 div、1 fdiv、2 fsqrt、3 rem、4 divu、5 remu、6 divw、7 divuw、8 remw、9 remuw。這些向量從 `tests/riscof/work` 已編譯的 RISCOF 測試案例衍生而來。

### 怎麼跑

> "$ wsim fdqh_rv64gc fma -t testbench_fp / $ wsim fdqh_rv64gc div -t testbench_fp -gui / $ wsim fdqh_rv64gc cvtint -t testbench_fp -sim verilator"
> — p.655

中文解釋：第一個參數是設定（fdqh_rv64gc 表示四種精度都支援），第二個是要測的運算（add、sub、mul、div、sqrt、fma、cmp、cvtint、cvtfp），`-t testbench_fp` 指定用浮點專用 testbench。產生向量的指令是在 `$WALLY/tests/fp` 下跑 `make -jobs`。

### TestFloat 測不到的指令

> "Note that TestFloat does not produce vectors for RISC-V instructions fclass, fsgnj, fsgnj{n|x}, fmax or fmin."
> — p.652（邊欄）

中文解釋：這幾個是 RISC-V 特有或不涉及算術的指令，SoftFloat 沒有對應函式，只能靠 riscv-arch-test 那一層覆蓋。

## 名詞表

| 名詞 | 意思 |
| --- | --- |
| riscv-arch-test | RISC-V 官方架構相容性測試套件（第 13 章 RISCOF 流程） |
| FPgen | IBM 用來產生浮點測試輸入的工具 |
| TestFloat | 用 SoftFloat 算出預期答案、產生測試向量的工具 |
| `testbench-fp.sv` | Wally 直接測 Verilog FPU 模組的 testbench |
| `.tv` 檔 | test vector 檔，十六進位運算元 + 結果 + 旗標 |
| `$readmemh` | Verilog 讀十六進位檔進記憶體陣列的系統函式 |
| level 1 / level 2 | TestFloat 的測試強度檔次 |
| `SPECIALIZE_TYPE=RISCV` | 讓 SoftFloat 採 RISC-V 行為的編譯旗標 |
| saturate | 溢位時停在最大/最小值而非環繞 |
| cancellation | 相減造成高位大量歸零 |
| combined_IF_vectors | 整數與浮點除法合併的測試向量 |

## 所以呢

驗證策略講完了：兩層測試 + 一個要小心設定的參考模型。到這裡「通用 FPU 該長什麼樣」和「怎麼證明它對」都有了，最後一步是看 Wally 實際上怎麼把這些兜進一個可設定、支援多精度共用硬體的 RTL 裡——下一節 16.6。
