# 3.1 Platform Requirements and Tool Overview

> 原書 p.90（Chapter 3: RISC-V Software Tool Flow）

## 這節在講什麼

工具清單。很短，但**建立一組重要的分類**：

模擬器有三種，速度和精確度差好幾個數量級，用途完全不同：
**ISS（指令集模擬器）< emulator（模擬機）< logic simulator（邏輯模擬器）**。

搞混這三者會用錯工具——這是本節最該帶走的東西。

另外交代了平台需求（Linux + Bash）和必要/選配工具的分野。

## 關鍵點

### 平台：Linux + Bash

> "Wally uses a Linux-based development flow. Although the tools may work under a
>  variety of shells, the directions are tested on the Bash shell, which is the
>  default on most Linux distributions."
> — p.90

中文解釋：**Linux 是硬需求，Bash 是建議。**

書上邊欄列出實測過的發行版（p.91 邊欄）：
**Ubuntu LTS、Red Hat Enterprise Linux、AlmaLinux、Rocky Linux、Debian Stable、OpenSUSE Leap。**

邊欄還說明了為什麼要在意發行版（p.91 邊欄）——這是很現實的一段：
> "As of mid-2025, Synopsys and Cadence support their integrated circuit design CAD
>  tools on Red Hat Enterprise Linux 8.4+ and 9.1+. Thus, Red Hat is suitable for
>  organizations hosting CAD tools on the same server. Red Hat is expensive for
>  universities, but AlmaLinux and Rocky are free and compatible Red Hat clones.
>  We use AlmaLinux 9.5 in our development. **Finding a Linux platform supported by
>  all the necessary and rapidly evolving tools is an ongoing hassle for hardware
>  developers.**"

**「找一個所有工具都支援的 Linux 平台，是硬體開發者持續的麻煩。」**
原因是商用 EDA 工具（Synopsys、Cadence）只認證特定的 Red Hat 版本。

### 必要工具（免費）

> "The main tools, which are freely available, are:
>  - **GCC**: The *software toolchain* for compiling programs to run on Wally
>  - **Spike**: RISC-V *instruction set simulator* (ISS)
>  - **Sail**: RISC-V ISS, formal architecture model
>  - **QEMU**: RISC-V *emulator* for simulating a core with peripherals
>  - **Verilator**: Logic simulator and lint"
> — p.90

中文解釋：**五樣必要工具，兩類：**
- **編譯**：GCC（第 3.3、3.4 節）
- **模擬**：Spike、Sail、QEMU（第 3.3、3.5、3.6 節）
- **驗證硬體**：Verilator（第 5 章）

注意 **Sail 被標註為 "formal architecture model"**——
它不只是模擬器，是**RISC-V 架構的形式化定義**（呼應 2.3 節說它重視可證明的正確性）。
所以 Sail 是「黃金標準」：**有爭議時它說了算。**

### 選配工具（多數要錢）

> "Optional tools are:
>  - **Questa**: Logic simulator (Siemens)
>  - **VCS**: Logic simulator (Synopsys)
>  - **Design Compiler**: Logic synthesis tool for custom chips (Synopsys)
>  - **ImperasDV**: RISC-V simulator for lockstep simulation (Synopsys)
>  - **Vivado**: Logic synthesis tool for FPGAs (AMD-Xilinx)"
> — p.90

> "A limited version of Vivado is free, but Questa and Design Compiler require
>  licenses from Siemens and Synopsys, respectively. Both licenses are expensive and
>  only available to companies and universities."
> — p.90

中文解釋：**這裡有個現實的門檻要知道：**

| 工具 | 用途 | 取得 |
| --- | --- | --- |
| **Vivado** | FPGA 合成（第 23 章） | **有免費精簡版** |
| Questa / VCS | 邏輯模擬（第 5 章） | 昂貴授權，只賣公司和大學 |
| Design Compiler | ASIC 合成（第 6 章） | 昂貴授權 |
| ImperasDV | **lockstep（逐步比對）模擬**（第 5.6 節） | 商用 |

**個人自學者的可行路線：用 Verilator 取代 Questa/VCS，用 Vivado 免費版做 FPGA，
ASIC 合成那部分（第 6 章）就只能讀不能做。** 這個限制要先知道。

### 三種模擬器的分類（本節最重要的概念）

> "An *instruction set simulator* (ISS), such as Spike, simulates how instructions
>  running on a core change the architectural state and memory. It does not model
>  peripherals, nor does it attempt to predict the number of cycles the program takes."
> — p.90 邊欄

> "In contrast, an *emulator*, such as QEMU, also models the behavior of peripherals
>  but still does not accurately predict the number of execution cycles. An emulator
>  is needed to boot Linux because this operating system (OS) depends on peripherals
>  such as a timer, as well as terminal input/output."
> — p.90 邊欄

> "A *logic simulator*, also called a *cycle-accurate simulator*, such as Verilator or
>  Questa, simulates the actual hardware as defined by the SystemVerilog code; it
>  captures exactly how many cycles are required, accounting for microarchitectural
>  details such as pipeline hazards, cache misses, or branch mispredictions. Logic
>  simulators are orders of magnitude slower than Spike or QEMU, but they are critical
>  in verifying the correct implementation."
> — p.90 邊欄

中文解釋：**這張表是本節的核心，一定要記熟：**

| 類型 | 代表 | 模擬架構狀態 | 模擬周邊 | **週期精確** | 速度 |
| --- | --- | --- | --- | --- | --- |
| **ISS** | Spike、Sail | ✓ | ✗ | ✗ | 快 |
| **Emulator** | QEMU | ✓ | **✓** | ✗ | 最快 |
| **Logic simulator**（cycle-accurate） | Verilator、Questa | ✓ | ✓ | **✓** | **慢好幾個數量級** |

**三個判準記法：**
1. **要開 Linux 嗎？** → 需要 emulator（因為 Linux 依賴計時器和終端機 I/O）
2. **要知道跑幾個週期嗎？** → 需要 logic simulator
   （只有它算得出 pipeline hazard、cache miss、分支預測錯誤的成本）
3. **只想看指令對不對？** → ISS 就夠，而且快很多

**"orders of magnitude slower"** 是關鍵——
呼應 2.3 節的數字：QEMU 約 10 億指令/秒、Spike 約 1 億、Sail 約 100 萬，
而邏輯模擬器還要更慢。**所以驗證策略是分層的**：
先用快的跑大量測試，再用慢的驗證關鍵路徑（第 5 章的主題）。

最後那句是整個驗證方法論的基礎（p.90 邊欄）：
**"It is useful to compare the results of an ISS or emulator with a logic simulator
to verify the SystemVerilog."**
——**拿 ISS 當黃金參考，跟邏輯模擬的結果比對。**
這就是 lockstep 模擬（第 5.6 節），也是 ImperasDV 的用途。

### 編譯工具鏈的三個角色

> "The term *compiler* generally refers to a tool that converts a program from a
>  high-level language, such as C, into an executable. The compiler can also refer to
>  just the first step of creating an executable, which is converting the program into
>  assembly; the *assembler* converts the assembly into machine code, and the *linker*
>  then groups programs and libraries into a single executable."
> — p.90 邊欄

中文解釋：**"compiler" 這個字有廣狹兩義，容易混淆：**
- **廣義**：高階語言 → 執行檔（整條流程）
- **狹義**：高階語言 → 組合語言（只有第一步）

**完整三步：**
```
C 原始碼 --[compiler]--> 組合語言 --[assembler]--> 機器碼(.o) --[linker]--> 執行檔
```

這對應第 2 章開頭 Fig. 3.1（p.89）那張工具鏈圖：
`.c` 和 `.s` 經 gcc（compiler / assembler）變成 **ELF object file（.o）**，
再經 gcc（linker）合成 **ELF executable（.elf）**，
然後可以用 `objdump` 反組譯、或送進 `spike` / `sail` 模擬並產生 log。

> "Chapters 4 and 5 introduce hardware design and verification using SystemVerilog

>  Chapter 6 discusses synthesis targeting a custom chip (application-specific

中文解釋：**工具的使用時機地圖：**

## 名詞表

| 名詞 | 意思 |
| --- | --- |
| Compiler / Assembler / Linker | 高階語言→組語 / 組語→機器碼 / 合併成單一執行檔 |
| **ISS**（instruction set simulator） | 只模擬架構狀態與記憶體，**不模擬周邊、不算週期數**。如 Spike、Sail |
| **Emulator** | 也模擬周邊，但仍不精算週期。如 QEMU。**開 Linux 需要它** |
| **Logic simulator**（cycle-accurate） | 模擬 SystemVerilog 定義的實際硬體，**週期精確**但慢好幾個數量級。如 Verilator、Questa |
| Verilator | 免費的邏輯模擬器兼 lint 工具 |
| Sail | RISC-V 的**形式化架構模型**，兼 ISS |
| ImperasDV | 商用工具，用於 lockstep（逐步比對）模擬 |
| Lint | 靜態檢查工具，找出可疑的 HDL 寫法 |

## 所以呢

**本節最該記住的是三種模擬器的分工：
要開 Linux 用 emulator（QEMU）、要算週期數用 logic simulator（Verilator/Questa）、
只看指令行為用 ISS（Spike/Sail）。**
以及一個現實限制：**Questa 和 Design Compiler 要昂貴授權**，
個人自學可用 Verilator 和 Vivado 免費版替代大部分工作。
下一節（3.2）開始實際安裝。
