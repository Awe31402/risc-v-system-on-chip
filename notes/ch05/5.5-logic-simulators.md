## 關鍵點

### 事件驅動模擬的原理

> "A logic simulator applies test vectors to a model of a system and computes the outputs.
>  We use SystemVerilog to describe both the system model and input generation. Our system
>  model is coded with synthesizable Verilog because it describes hardware, whereas the test
>  vectors are generated by a nonsynthesizable testbench."
> — p.207

> "Traditional *event-driven logic simulation* maintains a list of signal changes called
>  *events* that happen at a particular time. Each event causes the logic that depends on the
>  signal to be reevaluated. For example, when the code on the right-hand side of an assign
>  statement or a <= or = in an always_comb block changes, the signal on the left-hand side
>  is recomputed. If the left-hand signal changes, this creates a new event that gets added
>  to the list."
> — p.207

中文解釋：**event-driven（事件驅動）的機制：**
1. 維護一張「**事件**」清單——某個時間點某個訊號會變化
2. 訊號一變，**重新計算所有依賴它的邏輯**
3. 如果計算結果讓左邊的訊號也變了，**產生新事件加入清單**
4. 重複

**這解釋了為什麼模擬慢**：每一次訊號變化都要連鎖重算一堆邏輯。
（呼應 5.1.4 節：SoC 模擬只有幾 kHz。）
**也解釋了為什麼 4.2.4.4 節說「所有訊號在同一個時脈邊緣變化時 Verilator 快很多」**——
事件集中在同一時刻比較好處理。

**Delta delay（很重要的概念）：**
> "If the assignment has a delay, the new event will be added after that delay. Otherwise,
>  the new event will be added after an infinitesimal *delta* delay that appears to be zero
>  in simulation yet keeps events ordered to reflect cause and effect."
> — p.207

**delta delay 是「無限小但非零」的延遲**——
模擬時間上看起來是 0，但**保證事件的因果順序正確**。
這是模擬器處理「同一時刻的連鎖反應」的方法。

**解譯 vs 編譯（p.207）：**
> "Older simulators are interpreted, but most modern simulators compile the Verilog into a
>  faster executable form."
（呼應 3.6 節 QEMU 的 JIT——同樣的加速思路。）

### 四個主流模擬器

> "Leading commercial HDL simulators include Questa from Siemens (formerly called ModelSim,
>  from Mentor Graphics), Cadence Xcelium, and Synopsys VCS. All are mature products that
>  support SystemVerilog, VHDL, and SystemC. **Verilator is a leading free open-source
>  Verilog/SystemVerilog simulator.**"
> — p.207

中文解釋：

| 模擬器 | 廠商 | 授權 |
| --- | --- | --- |
| **Questa**（原 ModelSim） | Siemens（原 Mentor Graphics） | 商用 |
| Xcelium | Cadence | 商用 |
| **VCS** | Synopsys | 商用 |
| **Verilator** | 開源 | **免費** |

**商用的三個都支援 SystemVerilog、VHDL、SystemC；Verilator 只支援 Verilog/SystemVerilog。**

### Questa：互動模式

中文解釋：**GUI 啟動（p.207）：**
```bash
$ cd $WALLY/examples/verilog/fulladder
$ vsim fulladder.sv
```

**操作步驟（p.207）：**
1. Compile → Compile… 選 `fulladder.sv`
2. Simulate → Start Simulation… 展開 `work` library，選 `testbench`
3. **點 Optimization Options，改成 "Apply full visibility to all modules (full debug mode)"**
   ← **關鍵**：否則 Questa 會把內部訊號最佳化掉，看不到
4. Objects pane 選全部訊號 → Add → To Wave（或拖到波形視窗）
5. 輸入 `run 100` 或 `run all`

**`run 100` 跑 100 個模擬 tick（10 個時脈週期），足夠跑完 8 個測試向量**（p.207）。

**輸出（p.208）：**
```
VSIM > run 100
#        8 tests completed with          0 errors
# ** Note: $stop    : .../fulladder.sv(42)
VSIM2 > quit
```

**重跑的技巧（p.208）——實用：**
```
VSIM > restart -f    # 重啟模擬但保留波形設定
VSIM > run 100
```
**`restart -f` 不會讓你重新加一次波形。**

Fig. 5.2（p.208）是 Questa 的波形畫面（原書此處為波形截圖），
可以看到 clk、reset、a、b、c、cout、s 和 vectornum 逐步遞增。

### Questa：do file 與批次模式

> "Better yet, you can create a script called a *do file* that compiles and simulates for you."
> — p.208

中文解釋：**Code Example 5.3（p.209）的 `fulladder.do`：**
```tcl
# Compile, optimize, and start the simulation
vlog fulladder.sv
vopt +acc work.testbench -o workopt
vsim workopt

# Add waveforms and run the simulation
add wave *
run -all
view wave
```
**三個指令的分工：`vlog`（編譯）、`vopt`（最佳化，`+acc` 保留可見度）、`vsim`（模擬）。
預設把編譯結果放在 `work` 目錄。**

執行：`$ vsim -do fulladder.do`

**批次模式（Code Example 5.4，p.209）——回歸測試用：**
```tcl
vlog fulladder.sv
vopt +acc work.testbench -o workopt
vsim workopt
run -all
quit                 # ← 差別在這：不加波形、跑完就離開
```
執行：`$ vsim -c -do fulladder-batch.do`
**`-c` 旗標啟動批次模式。**

> "If you don't need the GUI to debug, you can run in batch mode, which is faster.... **This
>  is handy for regressions, which run many simulations and report whether they passed.**"
> — p.209

**再包一層腳本（p.209）：**
寫一個一行的腳本 `sim-fulladder-batch`，`chmod 755` 設為可執行，
之後直接 `./sim-fulladder-batch`。

**最簡單的方式：`qrun`（p.209）**
```bash
$ qrun fulladder.sv
```
**`qrun` 自動從模組階層判斷頂層 testbench，然後編譯、最佳化、模擬。**

（實務提醒，p.209 邊欄：**沒有 X2Go 或 VNC 時，用 `ssh -Y` 加批次模擬很有生產力。
Questa GUI 雖然能透過 `ssh -Y` 開啟，但慢到很痛苦。**）

### Verilator：編譯成 C++ 再跑

> "Verilator is an open-source SystemVerilog simulator. **Verilator converts the SystemVerilog
>  code into a C program that simulates its behavior, then compiles and runs the C program.**
>  Because it is open source, Verilator is a key component of open-source hardware design.
>  **Verilator is gaining traction at companies as well because simulator licenses are
>  expensive and because Verilator can be as fast or faster than commercial simulators.**"
> — p.210

中文解釋：**Verilator 的原理和其他模擬器不同：它把 SystemVerilog 翻成 C 程式再編譯執行。**
（所以嚴格說它是「編譯器」而非「解譯器」，這也是它快的原因。）

**兩個採用理由：免費，而且速度不輸甚至勝過商用模擬器。**

**歷史（p.210）：**
1994 年由 Paul Wasson 在 DEC 構思，**1998 年開源**，Wilson Snyder 自 2001 年主導開發。
早期限制多（只支援 Verilog 子集、testbench 只能用 SystemC），
**在本書撰寫期間 Verilator 已能模擬 SystemVerilog testbench 和 Wally 的所有功能，
而且能跑 Wally testbench 上的所有回歸測試。**

**目前的限制：**
> "Verilator does not yet support UVM (see Table 5.1), but work is in progress."

**三步驟操作（p.210）：**
```bash
$ cd $WALLY/examples/verilog/fulladder
$ verilator --binary --top-module testbench --trace fulladder.sv
$ obj_dir/Vtestbench
```

**引數說明（p.210）：**

| 引數 | 作用 |
| --- | --- |
| `fulladder.sv` | 要編譯的 Verilog 檔案清單 |
| `--top-module testbench` | 指定頂層模組（通常是 testbench） |
| **`--binary`** | **要 Verilog 產生 C 程式碼並編譯成執行檔** |
| **`--trace`**（選配） | **啟用產生 `.vcd` 波形檔**（testbench 呼叫 `$dumpvars` 時） |

**Verilator 建立 `obj_dir` 目錄**，裡面有執行檔 `Vtestbench` 和 C 程式碼。

**輸出（p.211）：**
```
- Verilation Report: Verilator 5.025 devel ...
cycle: 00000001 vectornum 00000000 testvectors[vectornum]: 00000
cycle: 00000002 vectornum 00000000 testvectors[vectornum]: 00000
...
     10 tests completed with        0 errors
- fulladder.sv:49: Verilog $finish
- Simulation Report: Verilator 5.025 devel
```

### 看波形：GTKWave

> "The waveforms recorded in the VCD file can be displayed with commercial or open-source
>  viewers. For example, invoke the open-source GTKWave viewer using:"
> — p.211

```bash
$ gtkwave -f fulladder.vcd
```

中文解釋：**點進 TOP → testbench 階層看內部訊號清單，再點選加入波形檢視器**（p.211）。
Fig. 5.3（p.212）是 GTKWave 的畫面（原書此處為截圖），
左側是階層樹和訊號清單，右側是波形。

**這組合（Verilator + GTKWave）是完全免費的模擬與波形檢視方案。**

### VCS

> "Synopsys VCS is another commercial HDL simulator. Like Verilator, it compiles HDL code
>  into an executable, which is then run. By default, the executable is named simv."
> — p.212

```bash
$ cd $WALLY/examples/verilog/fulladder
$ vcs -sverilog -full64 fulladder.sv
$ ./simv
```

中文解釋：**VCS 和 Verilator 一樣是「編譯成執行檔再跑」**，預設執行檔名 `simv`。
`-sverilog` 啟用 SystemVerilog，`-full64` 是 64 位元模式。

### 三個模擬器的比較（整理）

| | **Questa** | **Verilator** | **VCS** |
| --- | --- | --- | --- |
| 授權 | 商用（昂貴） | **免費開源** | 商用（昂貴） |
| 原理 | 編譯成較快的執行形式 | **翻成 C 程式再編譯** | 編譯成執行檔 `simv` |
| GUI / 波形 | **內建，成熟** | 無；配 **GTKWave** 看 VCD | — |
| 批次 | `vsim -c -do`、`qrun` | 本來就是命令列 | `./simv` |
| 停止方式偏好 | **`$stop`**（要產覆蓋率） | **`$finish`** | — |
| UVM | 支援 | **尚不支援**（開發中） | 支援 |
| 速度 | — | **不輸甚至勝過商用** | — |

## 名詞表

| 名詞 | 意思 |
| --- | --- |
| **Event-driven simulation** | 事件驅動模擬。維護訊號變化事件清單，變化時連鎖重算 |
| Event | 事件。特定時間發生的訊號變化 |
| **Delta delay** | 無限小但非零的延遲。模擬時間上為 0，但保證事件的因果順序 |
| Questa | Siemens 的商用模擬器（原 ModelSim） |
| `vlog` / `vopt` / `vsim` | Questa 的編譯 / 最佳化 / 模擬指令 |
| **do file** | Questa 的腳本檔，自動化編譯與模擬 |
| `vsim -c` | 批次模式（無 GUI），回歸測試用 |
| `qrun` | Questa 的一鍵指令，自動判斷頂層並完成全流程 |
| `restart -f` | 重啟模擬但保留波形設定 |
| **Verilator** | 免費開源模擬器。**把 SystemVerilog 翻成 C 程式再編譯執行** |
| `--binary` / `--top-module` / `--trace` | 產生執行檔 / 指定頂層 / 啟用 VCD 輸出 |
| `obj_dir` | Verilator 產生的目錄，含執行檔與 C 程式碼 |
| GTKWave | 開源波形檢視器 |
| VCS | Synopsys 的商用模擬器，預設執行檔 `simv` |

## 所以呢

**理解 event-driven 模擬的機制，就理解了為什麼模擬慢——
每個訊號變化都要連鎖重算，而 SoC 有數百萬個訊號。**

實務上的三件事：
1. **完全免費的方案是 Verilator + GTKWave**，而且速度不輸商用工具。
   自學者用這組就夠（第 3.1 節也把 Verilator 列為必要工具）。
2. **Questa 的 GUI 適合除錯，但要記得開 full debug mode**，
   否則內部訊號會被最佳化掉看不到；除錯完用 `-c` 批次模式跑回歸。
3. **`restart -f` 保留波形設定**——除錯循環中省下大量重複點擊。
