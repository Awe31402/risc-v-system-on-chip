# 8.5 Summary

> 原書 p.380–381（Chapter 8: Privileged Operations）

## 這節在講什麼

第 8 章總結，六段。

**結構是「從動機到機制到實作」：
為什麼要特權模式 → trap 怎麼運作 → CSR 分類 → Wally 怎麼做。**

**第二段和第三段把「trap 發生時硬體和軟體各做什麼」
濃縮成兩句話——這是全章最好的速查。**

## 關鍵點

### 為什麼需要特權模式

> "**A robust microprocessor needs to protect itself from crashes or compromise caused by buggy or
>  malicious programs.** Bad instructions cause exceptions, such as illegal-instruction, access-fault,
>  address-misaligned, or page-fault exceptions. **System calls (ecall) and debugger breakpoints (ebreak)
>  are also exceptions.** The microprocessor also receives interrupts from asynchronous events, such as
>  timers, interprocessor communication, or external peripherals. **Exceptions and interrupts are
>  collectively called *traps*.**"
> — p.380

中文解釋：**例外的兩種來源要分清楚：**
- **壞指令造成的**：非法指令、access fault、位址未對齊、page fault
- **刻意觸發的**：`ecall`（系統呼叫）、`ebreak`（除錯中斷點）

**中斷則來自非同步事件：計時器、處理器間通訊、外部周邊。**

### 特權模式的分層

> "**Traps leave the current program and jump to a trap handler. Processors add multiple privilege modes
>  for robustness and security. Programs run in user mode, in which mode they cannot interfere with each
>  other. The trap handler is part of the firmware that runs in machine mode, in which it has full power
>  to allocate machine resources and kill faulty programs. Application processors add an intermediate
>  supervisor mode, to run an OS such as Linux without giving the entire OS kernel full M-mode powers.
>  Each privilege mode is associated with a set of CSRs to configure traps, enable features, or monitor
>  performance counters.**"
> — p.380

中文解釋：**三層的職責分工，這段講得最清楚：**

| 模式 | 誰在跑 | 能力 |
| --- | --- | --- |
| **User** | 應用程式 | **不能互相干擾** |
| **Supervisor** | **Linux 等 OS** | **中間層，不給 OS 核心完整的 M-mode 權力** |
| **Machine** | **韌體（含 trap handler）** | **完整權力：分配機器資源、終止故障程式** |

**S-mode 存在的理由說得很精準：
「讓 OS 跑起來，但不給它完整的 M-mode 權力。」**
——**這是縱深防禦（defense in depth）：即使 OS 被攻破，也還有一層。**

### 特權指令回顧

> "The mret and sret instructions return from M- and S-mode trap handlers. **csrrw, csrrs, and csrrc
>  instructions read and write, set, or clear CSRs, respectively. The wfi instruction can be used to save
>  power by placing the processor in a low-power state until an interrupt occurs.**"
> — p.380

### 委派與 trap 的硬體動作

> "**In a system without S-mode, traps always elevate the privilege to M-mode. In a system with S-mode,
>  traps default to M-mode, but traps can be delegated to the S-mode OS via the medeleg and mideleg
>  registers.** A set of CSRs communicates information about the trap. Let *x* = m (machine) or s
>  (supervisor), the privilege mode of the trap handler. **When a trap occurs, the core enters *x* mode.
>  It saves the old program counter in xepc, disables interrupts, places a code in xcause that indicates
>  the reason for the trap, places additional information such as the bad address or instruction in xtval,
>  and jumps to a trap handler at xtvec.**"
> — p.380–381

中文解釋：**硬體做的五件事，一句話記住：**

**「進入 x 模式 → 存 `xepc` → 關中斷 → 寫 `xcause` → 寫 `xtval` → 跳 `xtvec`」**

（呼應 8.2 節的九步驟，這是壓縮版。）

### Trap handler 做的事（軟體側）

> "**The trap handler typically swaps the stack pointer (sp) with an exception stack pointer in the
>  xscratch register, then saves the integer registers onto the exception stack so that it can use the
>  registers without corrupting the program that was running. It then reads xcause to determine the cause
>  of the trap and respond accordingly. For example, it may perform a system call, respond to the timer
>  or external interrupt, or kill a program that made a bad memory access. The trap handler then restores
>  the registers and stack pointer. Finally, it performs the xret instruction, which reenables interrupts,
>  restores the old privilege level, and returns to the old program counter stored in xepc.**"
> — p.381

中文解釋：**軟體側的六個步驟，和 8.2.6 節的程式碼完全對應：**

1. **用 `xscratch` 交換堆疊指標**（拿到例外堆疊）
2. **把整數暫存器存到例外堆疊**（這樣才能用暫存器而不破壞被中斷的程式）
3. **讀 `xcause` 判斷原因**
4. **依原因處理**：系統呼叫、回應計時器/外部中斷、或終止做了壞記憶體存取的程式
5. **還原暫存器和堆疊指標**
6. **`xret`**：重新啟用中斷、還原特權等級、回到 `xepc`

**「硬體五步 + 軟體六步」就是完整的 trap 生命週期。**

### CSR 的分類

> "**CSRs with names beginning with m can only be accessed from M-mode, so lower privilege programs cannot
>  seize control of the processor.** The mstatus register is particularly important; it contains bitfields
>  to globally enable interrupts, specify the privilege mode to which the trap handler should return,
>  configure endianness, and so forth. **Other machine CSRs contain codes defining the vendor,
>  architecture, implementation, and hart IDs, and information about the supported extensions.
>  mcycle and minstret are standard performance monitor counters that track the number of cycles and
>  instructions that have elapsed. The platform-dependent mhpmcounter hardware performance monitor
>  counters keep track of the number of times other events occur, such as cache misses or branch
>  mispredicts.**"
> — p.381

> "**Similarly, CSRs starting with s can only be accessed from S-mode or above. The satp supervisor address
>  translation and protection CSR controls virtual memory, which is described in depth in Chapter 11.**"
> — p.381

中文解釋：**命名規則就是權限規則：`m` 開頭只能從 M-mode 存取、`s` 開頭從 S-mode 以上。**
（呼應 8.2.3 節：CSR 位址的 bits[9:8] 直接編碼了模式。）

**`mstatus` 被特別點名為「特別重要」**——
它管全域中斷致能、trap 返回的特權模式、端序等。

### Wally 的實作摘要

> "**Wally adds a privileged unit to track the privilege level, store the CSRs, and handle traps and
>  privileged instructions. Traps, xret instructions, CSR writes, and fences flush the pipeline to discard
>  partially completed instructions and ensure subsequent instructions see the updated privilege and
>  CSRs.**"
> — p.381

> "**If big-endian mode is supported, the LSU adds endianswap muxes to reverse the bytes written and read
>  from the data memory. Instructions are always stored in little-endian order.**"
> — p.381

> "**Wally defines an extensive set of wally-riscv-arch-test programs to test privilege modes, traps, and
>  CSRs.**"
> — p.381

中文解釋：**一句話總結 pipeline 的影響：
「trap、`xret`、CSR 寫入、fence 都會 flush pipeline，
以丟棄部分完成的指令，並確保後續指令看到更新後的特權和 CSR。」**

**「指令永遠以 little-endian 儲存」再次強調**（呼應 2.1、8.2.3.1 節）。

## 所以呢

**第 8 章給處理器加上了保護機制。**

三件最該帶走的事：

1. **Trap 的完整生命週期 = 硬體五步 + 軟體六步：**
   - **硬體**：進入 x 模式 → 存 `xepc` → 關中斷 → 寫 `xcause` → 寫 `xtval` → 跳 `xtvec`
   - **軟體**：`xscratch` 換堆疊 → 存暫存器 → 讀 `xcause` → 處理 → 還原 → `xret`

2. **三層特權模式的分工**：
   **U-mode 程式互不干擾、S-mode 跑 OS 但不給完整權力、M-mode 韌體有完整權力。**
   **S-mode 的存在是縱深防禦——即使 OS 被攻破還有一層。**

3. **特權功能對 pipeline 的代價**：
   **trap、`xret`、CSR 寫入、fence 都要 flush pipeline，CSR 讀取要 stall。**
   這是「確保後續指令看到更新後狀態」的最簡單做法。

**還有一個貫穿全章的實作原則：
所有架構狀態的改動都集中在 Writeback 級開始的那一刻，
所有 trap 都集中在 Memory 級——這讓 precise trap 變得可實作。**

下一章（第 9 章）給處理器接上匯流排，讓它能存取外部記憶體和周邊。
