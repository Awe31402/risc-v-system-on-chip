# 7.5 Summary

## 這節在講什麼

第 7 章總結。**結構很清楚：先依三個單元（IFU、IEU、LSU）回顧，
再回顧 pipeline 的五級和三大 hazard。**

## 關鍵點

### 整體架構與簡化

> "This chapter has developed a processor that runs the RV{32/64}I base instruction set.
>  The processor is partitioned into an instruction fetch unit (IFU), integer execution unit (IEU),
>  and load/store unit (LSU). **The processor has no external memory interface, so it uses an
>  instruction ROM (IROM) in the IFU to hold instructions and data tightly-integrated memory (DTIM)
>  in the LSU to hold data. The architectural state comprises the program counter (PC) and the 31
>  registers in the integer register file (IRF).**"
> — p.333

中文解釋：**三個單元的分工再確認一次**（呼應 2.7 節）。
**架構狀態 = PC + 31 個暫存器**（x0 硬接為 0，不算）。

### 三個單元的職責

> "**The IFU contains the IROM, organized as a 32-bit wide read-only memory. It also contains an
>  incrementer to add 4 to the PC and a mux to select PC + 4 or the branch/jump target address from
>  the IEU.**"
> — p.333

> "**The IEU contains a datapath and a controller.** The datapath has the IRF, extension logic to
>  assemble an immediate from various bits of the instruction, and an ALU capable of
>  addition/subtraction, shifts, and logical operations. **Branch comparison is on the critical path
>  for simple processors, so the datapath has a fast branch comparator separate from the ALU.**
>  The datapath also has a variety of multiplexers to choose sources and results appropriately.
>  **The controller contains combinational logic that decodes the op and funct fields of the
>  instruction to determine write enables and multiplexer selects.**"
> — p.333

中文解釋：**「分支比較在簡單處理器的關鍵路徑上，所以要有獨立於 ALU 的快速比較器」**——
這是本章最重要的設計決定之一（7.1.3.6 節的四個理由，
以及 6.5.3 節 Table 6.11 證實了 rv32e/rv32i/rv64i 的關鍵路徑都在這裡）。

> "**The LSU contains the DTIM, organized as an XLEN-bit wide RAM with a single read/write port and
>  byte write enables. It has subword read multiplexers controlled by the least significant address
>  bits and the access type to choose a subset of the word and sign or zero-extend the subword to
>  XLEN-sized ReadData. It also has subword write logic to replicate the smaller WriteData value and
>  turn on the appropriate byte enables.**"
> — p.333

中文解釋：**LSU 的兩個方向再確認一次：**
- **讀：用位址低位元選出子字 → 依存取型別符號或零延伸**
- **寫：複製較小的 WriteData → 開啟對應的 byte enable**

（呼應 7.1.6 節。）

### 從單週期到 pipeline

> "**We begin with a single-cycle core, then convert it into a pipelined design by adding pipeline
>  registers and hazard/forwarding logic and adapting timing for synchronous memories (DTIM and
>  IROM).** The five stages of the pipeline are:
>  **Fetch**: Read instruction from IROM and update PC
>  **Decode**: Decode instruction to compute control signals, read registers from IRF
>  **Execute**: Execute ALU, branch, and jump instructions and calculate an address for loads/stores
>  **Memory**: Read or write DTIM if applicable
>  **Writeback**: Update IRF with new result"
> — p.333–334

中文解釋：**五級的一句話定義，值得背下來：**

| 級 | 做什麼 |
| --- | --- |
| **Fetch** | 從 IROM 讀指令、更新 PC |
| **Decode** | 解碼算出控制訊號、從 IRF 讀暫存器 |
| **Execute** | 執行 ALU、分支、跳躍；**算 load/store 的位址** |
| **Memory** | 讀或寫 DTIM |
| **Writeback** | 用新結果更新 IRF |

**注意「三個改變」的清單（p.333）：
加 pipeline 暫存器、加 hazard/forwarding 邏輯、
以及「為同步記憶體調整時序」**——第三項常被忽略但很關鍵（7.2.1 節）。

### Hazard 的四句話總結（本節精華）

> "**Pipelining greatly increases the clock frequency at a modest increase in complexity. Hazards are
>  the main challenge for a pipelined processor.**"
> — p.334

> "**When one instruction depends on the result of a previous instruction that is not yet written
>  back to the register file, the forwarding logic, in many cases, resolves the problem by forwarding
>  the result of the previous instruction to multiplexers at the start of the Execute stage for the
>  current instruction.**"
> — p.334

> "**Unfortunately, load instructions have a two-cycle latency, and their result is not available
>  until the end of the Memory stage. Hence, the hazard unit stalls the pipeline for a cycle when a
>  load is immediately followed by a dependent instruction.**"
> — p.334

> "**A store followed by a load also causes a stall because of a structural hazard with the memory's
>  address port.**"
> — p.334

> "**Finally, the direction of a branch is not known until the comparison is in the Execute stage.
>  The processor continues fetching consecutive instructions as if the branch is not taken, so it
>  must flush the next two instructions when it discovers that a branch should be taken.**"
> — p.334

中文解釋：**四種情況、三種解法，整理成一張表：**

| 情況 | 解法 | 代價 |
| --- | --- | --- |
| **一般的 RAW 相依** | **轉發到 Execute 級開頭的多工器** | **0 週期** |
| **load 後緊接相依指令** | **stall 一週期**（load 有 2 週期延遲，結果到 Memory 級末才有） | 1 週期 |
| **store 後緊接 load** | **stall 一週期**（記憶體位址埠的結構危障） | 1 週期 |
| **分支成立** | **flush 後面兩條**（分支方向到 Execute 級才知道） | 2 週期 |

**「pipeline 大幅提高時脈頻率，複雜度只是溫和增加」**——
但那個「溫和」要打折扣，因為 7.2.2.4 節邊欄說 hazard 單元是最難做對的部分。

## 所以呢

**第 7 章做出了一顆完整的 RV{32/64}I 五級 pipeline 處理器。**

三件最該帶走的事：

1. **五級的分工**：Fetch（取指令）→ Decode（解碼+讀暫存器）→
   Execute（運算+算位址）→ Memory（存取資料）→ Writeback（寫回）。

2. **四種 hazard 情況與代價**：
   - **一般 RAW → 轉發，0 週期**
   - **load-use → stall 1 週期**
   - **store-load → stall 1 週期**（同步記憶體的位址埠衝突）
   - **分支成立 → flush 2 條指令**

3. **一個關鍵設計決定：用獨立的快速比較器而非 ALU 做分支比較**——
   因為分支比較在簡單處理器的關鍵路徑上，
   而且 ALU 的加法器同時要算分支目標位址。

**這顆核心還缺很多東西**（trap、CSR、cache、匯流排、虛擬記憶體、各種擴充），
**下一章（第 8 章）先補上特權操作。**
