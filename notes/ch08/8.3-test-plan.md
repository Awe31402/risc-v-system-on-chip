# 8.3 Test Plan

> 原書 p.360–364（Chapter 8: Privileged Operations）
> 含 8.3.1 Generating Exceptions、8.3.2 Generating Interrupts

## 這節在講什麼

**特權功能的測試計畫。**

這節最有價值的不是測試清單，而是**兩張「怎麼刻意觸發每一種 trap」的表**
（Table 8.8 例外、Table 8.9 中斷）——
**這是寫特權測試碼時最實用的參考。**

另外還有一段很誠實的自白：**特權測試是最難寫的測試之一，
而且沒有可靠的參考模型可以驗證。**

### 為什麼特權單元 bug 特別多（三個原因）

> "**The privileged unit had a high number of difficult bugs for a variety of reasons:
>  - Complex specification with many easily-overlooked corner cases
>  - Exceptions and CSR accesses disrupt pipeline behavior
>  - This unit interacts with peripherals, which were also lightly tested**"
> — p.362

中文解釋：**三個原因，每一個都有結構性的理由：**

| 原因 | 為什麼難 |
| --- | --- |
| **規格複雜，corner case 容易被忽略** | 特權規格比主規格還長還複雜（呼應 8.1 節） |
| **例外和 CSR 存取會打亂 pipeline 行為** | **要 flush、要 stall，和 hazard 單元糾纏**（8.4.5 節） |
| **這個單元和周邊互動，而周邊也測得很少** | 兩個測試不足的東西相乘 |

### 最誠實的一段：測試本身可能就是錯的

**邊欄（p.362）值得完整讀：**
> "**The privileged tests are among the more difficult tests to write. Enumerating the cases to test is
>  lengthy, and checking that the tests cover all of these cases requires care. Our reference model of
>  Spike (see Section 3.3.8) lacks the peripherals to generate some of the interrupts, so the tests
>  cannot be checked against a reference model, increasing the chance of making the same error
>  misinterpreting the specification in the test case as in the RTL.**"

> "**The privileged specification leaves many choices to the implementation, and these tests are only
>  written to check Wally's implementation, not all valid implementations.** Even for Wally, these
>  tests only cover basic privileged functions. **We believed these tests were better than anything else
>  we could find at the time they were written in 2022 but expect more comprehensive tests will
>  eventually be available from the RISC-V Architecture Test Special Interest Group.**"

中文解釋：**這段揭露了三個嚴重的方法論問題：**

1. **Spike 缺少產生某些中斷的周邊 → 無法拿參考模型比對 →
   「測試碼和 RTL 對規格有同樣誤解」的機率變高。**
   （呼應 3.7.3 節和 5.1.2 節：參考模型該由不同團隊寫。）

2. **特權規格留了很多實作選擇，所以這些測試只驗證 Wally 的實作，
   不是所有合法實作。**

3. **即使對 Wally，這些測試也只涵蓋基本的特權功能。**

**「我們相信這些測試比 2022 年當時能找到的任何東西都好，
但期待 RISC-V 架構測試 SIG 最終會提供更完整的測試。」**

### 測試碼的組織

> "All privileged tests are in tests/wally-riscv-arch-test/riscv-test-suite/rv{32,64}i_m/privilege.
>  **riscv-arch-test intends to support U- and S-mode tests in directories named rv{32,64}i_{u,s}.
>  This naming structure is not yet implemented, so the non-M-mode tests are placed in
>  rv{32,64}i_m/privilege/testname-{u,s}-01. Configurations that do not support U- or S-mode should
>  omit the associated tests.**"
> — p.362

中文解釋：**命名結構還沒實作，所以非 M-mode 的測試暫時放在 M-mode 目錄下，
用檔名後綴 `-u-01` / `-s-01` 區分。**

**共用的測試函式庫（p.362）：**
> "The Wally privileged tests include the **WALLY-TEST-LIB-32/64.h** file. **This file includes a
>  generic trap handler that logs a signature for each trap, including mcause and optionally mtval and
>  certain mstatus bits. It also contains a collection of functions and macros to cause traps and change
>  privilege modes. Most tests call these functions directly. The MMU/PMA/PMP tests contain a table of
>  tests, and calls a function called `run_test_loop` that applies each test.**"

**兩種測試組織方式：**
- **一般測試：直接呼叫函式庫的函式**
- **MMU/PMA/PMP 測試：用一張測試表 + `run_test_loop` 逐一套用**

### Table 8.8：怎麼刻意觸發每種例外（超實用）

> "RISC-V defines 14 standard exceptions as listed in Table 8.4. **Table 8.8 gives an example of how each
>  exception is triggered.**"
> — p.362

中文解釋：**Table 8.8（p.364）是本節最實用的表，寫測試時直接抄：**

| 例外 | 怎麼觸發 |
| --- | --- |
| **Instruction address misaligned** | **不測試**——因為特權測試用 Compressed 擴充跑，**永遠不會產生未對齊的指令位址** |
| **Instruction access fault** | `jr zero` // 跳到未實作的位址 |
| **Illegal instruction** | **`.word 0`** // **0x00000000 永遠是非法指令** |
| **Breakpoint** | `ebreak` |
| **Load address misaligned** | `li t3, 0x2000001` / `lw t4, 0(t3)` // **周邊存取必須對齊** |
| **Load access fault** | `lw t1, 0(zero)` // 從未實作的位址載入 |
| **Store address misaligned** | `li t3, 0x2000001` / `sw t4, 0(t3)` |
| **Store access fault** | `sw t4, 0(zero)` |
| **`ecall` from U-mode** | `GOTO_U_MODE` 巨集 + `ecall` |
| **`ecall` from S-mode** | `GOTO_S_MODE` + `ecall` |
| **`ecall` from M-mode** | `GOTO_M_MODE` + `ecall` |
| Instruction/Load/Store page fault | 見第 11.3 節的 MMU 測試 |

**三個值得學的技巧：**
1. **`.word 0` 是最簡單的非法指令**（呼應 8.2.5.2 節）
2. **位址 0 通常未實作 → 用來觸發 access fault**
3. **未對齊測試用周邊位址（0x2000001）而非主記憶體**——
   **因為 Zicclsm 擴充讓主記憶體的未對齊存取由硬體處理，不會 trap，
   但周邊仍然會產生例外**（p.363 邊欄明說：
   "misaligned accesses to peripherals still generate an exception.
   Therefore, these exceptions are tested by accessing the CLINT."）

**第一列的「不測試」也很有啟發：
有 C 擴充就不可能發生指令位址未對齊，所以測不了。**

### Table 8.9：怎麼觸發每種中斷

> "Six interrupts exist, as listed in Table 8.4: timer, software, and external interrupts, each handled
>  in M- or S-mode. **Table 8.9 gives examples of how each interrupt can be triggered by a test program.
>  Recall from Section 8.2.5.4 that some interrupts are caused by peripherals and others are caused by
>  writing to the mip or sip registers.**"
> — p.363

中文解釋：**Table 8.9（p.365–366）。四個代表性的例子：**

**（1）S-mode software——最簡單，寫 `sip`**
```asm
li   t3, 0x2      # SSIP is bit 1
csrs sip, t3      # Set supervisor software interrupt pending
```

**（2）M-mode software——寫 CLINT 的記憶體映射位元**
```asm
la t3, 0x02000000   # MSIP register in CLINT
li t4, 1
sw t4, 0(t3)        # Write MSIP bit of the mip register
```
**注意 M-mode software 中斷不能靠寫 `mip` 產生**（那個位元是唯讀的），
**必須寫 CLINT。**

**（3）M-mode timer——最複雜，要處理 64-bit 加法**
```asm
li   t3, 0x30           # Desired offset from the present time
mv   a3, t3             # Stop waiting for interrupt after this many loops
la   t4, 0x02004000     # mtimecmp register in CLINT
la   t5, 0x0200BFF8     # mtime register in CLINT
lw   t2, 0(t5)          # Low word of mtime
lw   t6, 4(t5)          # High word of mtime
add  t3, t2, t3         # Add desired offset to the current time
bgtu t3, t2, nowrap     # Check new time exceeds current time (no wraparound)
addi t6, t6, 1          # If wrap, increment most significant word
sw   t6, 4(t4)          # Store into most significant word of mtimecmp
nowrap:
  sw t3, 0(t4)          # Store into least significant word of mtimecmp
time_loop:
  addi a3, a3, -1
  bnez a3, time_loop    # Wait for interrupt to occur or loop to time out
```
**書上註明「這段程式碼在 RV32 和 RV64 都能用；
單獨 RV64 的話用 double-word 加法和儲存會更簡單」。**

**兩個要學的地方：**
- **`bgtu t3, t2, nowrap` 偵測 32-bit 加法的進位**，然後手動遞增高位字
- **`time_loop` 是 timeout 機制**——**如果中斷沒發生，測試不會永遠卡住**

**（4）M-mode external——最複雜，要設定 PLIC 和 GPIO**
```asm
# ---------- Configure PLIC ----------
la t3, 0xC200000     # PLIC IntThreshold[M-mode]
li t4, 0
sw t4, 0(t3)         # PLIC IntThreshold[M-mode] = 0
la t3, 0xC201000     # PLIC IntThreshold[S-mode]
li t4, 7
sw t4, 0(t3)         # PLIC IntThreshold[S-mode] = 7
la t3, 0xC000000     # PLIC IntPriority base address
li t4, 1
sw t4, 0x0C(t3)      # PLIC IntPriority[3] = 1
la t3, 0x0C002000    # PLIC IntEnable[M-mode]
li t4, 0b1000
sw t4, 0(t3)         # PLIC IntEnable[M-mode][3] = 1
la t3, 0x10060000    # GPIO base address
li t4, 0x1
sw t4, 0x08(t3)      # GPIO.output_en = 1 enable pin 1 as an output
sw t4, 0x04(t3)      # GPIO.input_en = 1 also enable pin 1 as an input
# for loopback test
sw zero, 0x1C(t3)    # Clear GPIO.rise_ip
sw zero, 0x24(t3)    # Clear GPIO.fall_ip
sw zero, 0x2C(t3)    # Clear GPIO.high_ip
sw zero, 0x34(t3)    # Clear GPIO.low_ip
sw t4, 0x28(t3)      # GPIO.high_en = 1 enable interrupt on high input
sw t4, 0x0C(t3)      # GPIO.output_val = 1 raise pin 1 (cause interrupt)
```

**這段示範了「用 GPIO 回授（loopback）產生外部中斷」的技巧：
把同一支腳同時設成輸出和輸入，然後輸出高電位 → 自己觸發自己的輸入中斷。**

**S-mode external 的做法（p.366）：
「和 M-mode external 一樣，但把 S 優先權門檻設為 0、M 設為 7，
並在位址 0x0C002080 啟用 S-mode 的來源 3。」**
**用優先權門檻來決定中斷送到哪個模式——這是 PLIC 的機制。**

## 所以呢

**這節最實用的是那兩張「怎麼刻意觸發每種 trap」的表（Table 8.8、8.9）。**

三件最該帶走的事：

1. **觸發例外的技巧**：
   **`.word 0`（非法指令）、位址 0（access fault）、
   周邊位址 + 1（未對齊——不能用主記憶體，因為 Zicclsm 會用硬體處理）。**

2. **觸發中斷的技巧**：
   **S-mode software 直接寫 `sip`；M-mode software 要寫 CLINT；
   timer 要處理 64-bit 加法的進位並加 timeout；
   external 要設定 PLIC 優先權和 GPIO loopback。**

3. **一個嚴重的方法論問題**：
   **Sail 缺少產生中斷的周邊，所以中斷測試沒有參考模型可比對——
   「測試碼和 RTL 對規格有同樣誤解」的風險很高。**
   而且**特權規格留了很多實作選擇，這些測試只驗證 Wally，不是所有合法實作。**

下一節（8.4）看 Wally 怎麼實作這些特權功能。
