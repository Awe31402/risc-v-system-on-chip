# 9.4 Test Plan

> 原書 p.410–411（Chapter 9: Bus Interface）

## 這節在講什麼

**全書最短的一節之一，只有三段。但它很誠實地承認了測試不足。**

兩件事：
1. **AHB 主要是「靠正常使用記憶體和周邊」順便測到的**
2. **有一組專門的 `ahb64_ram_*` 測試，命名編碼了兩個變數**

**最該注意的是最後那句自白：「更完整的測試計畫會有幫助。」**

## 關鍵點

### 主要靠「順便測到」

> "**The AHB bus has primarily been tested through normal use of memory and peripherals.**"
> — p.410

中文解釋：**這是一個很誠實但也很有問題的說法。**

**「正常使用」測到的是「常見情況」，測不到 corner case**——
例如 9.2.2.3 節那個「寫→讀要插 wait state」的情況、
9.5.2 節 EBU 的仲裁衝突、或 `HREADY` 長時間為低的情形。

（呼應 5.1.1 節：ad-hoc 測試能快速建立基本信心，但不保證完整。）

### 專門的延遲與 burst 測試

> "**The `ahb64_ram_{0/1/2}_{0/1}_rv64gc` tests stress the variable latency AHB interface and burst mode
>  operation. The first number gives the RAM latency (0, 1, or 2 extra cycles of memory latency), and the
>  second number indicates whether burst mode cache line fills are enabled (1) or not (0).**"
> — p.410–411

中文解釋：**測試名稱本身就是一份參數表，這種命名法值得學：**

```
ahb64_ram_<latency>_<burst>_rv64gc
              │        └─ 0 = 無 burst、1 = 啟用 burst 模式的 cache line fill
              └─ 0、1、2 = 額外的記憶體延遲週期數
```

**所以總共有 3 × 2 = 6 種組合。**

**兩個變數各測試一個面向：**

| 變數 | 測什麼 |
| --- | --- |
| **RAM latency（0/1/2）** | **可變延遲的 AHB 介面**——周邊拉低 `HREADY` 插入 wait state 的處理 |
| **Burst（0/1）** | **burst 模式的 cache line fill**（第 12.2.3 節） |

**「可變延遲」是關鍵字**——
因為固定延遲的周邊只會走同一條路徑，**變動延遲才會測到 FSM 的等待狀態。**
（呼應 9.2.2 節：`busfsm` 在 Data 狀態會一直等到 `HREADY` 升起。）

### 測試怎麼製造記憶體流量

> "**These tests use fadd_b11-01, where the active data exceeds the cache sizes and, thus, generates memory
>  traffic.**"
> — p.411

中文解釋：**這是一個很實用的技巧：
用「工作集大於 cache 容量」的測試程式來強迫產生匯流排流量。**

**如果資料都在 cache 裡命中，匯流排根本不會動，測不到任何東西。**
所以要挑一個會不斷 cache miss 的程式——這裡用的是浮點加法測試 `fadd_b11-01`。

**（p.411 邊欄：「第 10 章描述 cache。」）**

### 誠實的自白

> "**A more comprehensive test plan would be beneficial.**"
> — p.411

中文解釋：**一句話承認測試不足。**

這和第 5 章、第 8.3 節的態度一致（呼應 5.12 節的謙卑）：
**明確標示出哪些地方測試不夠，而不是假裝都測過了。**

**對讀者的意義：如果你要把 Wally 的 AHB 介面用在真實產品上，
這是一個需要自己補強的地方。**

## 名詞表

| 名詞 | 意思 |
| --- | --- |
| `ahb64_ram_{0/1/2}_{0/1}_rv64gc` | AHB 測試；第一個數字是 RAM 額外延遲週期、第二個是是否啟用 burst |
| Variable latency | 可變延遲。周邊用 `HREADY` 插入不定數量的 wait state |
| Burst mode cache line fill | 用 burst 傳輸一次填滿整條 cache line（第 12.2.3 節） |
| `fadd_b11-01` | 工作集超過 cache 容量的測試程式，用來產生記憶體流量 |

## 所以呢

**這節很短，但有兩個實用的測試方法值得學：**

1. **用參數編碼在測試名稱裡**（`ahb64_ram_<latency>_<burst>`）——
   一眼就看得出這個測試在測什麼組合。

2. **要測匯流排，就得挑「工作集大於 cache」的程式**——
   否則資料都在 cache 命中，匯流排根本不會動。

**以及一個要記住的限制：AHB 主要是「靠正常使用順便測到」的，
書上自己也說「更完整的測試計畫會有幫助」。**
