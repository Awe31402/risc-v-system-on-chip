# 3.5 Sail Simulation

> 原書 p.124–127（Chapter 3: RISC-V Software Tool Flow）

## 這節在講什麼

**Sail 是 RISC-V 的官方形式化規格**——不只是一個模擬器。

這節最重要的一句話是：**英文規格書和 Sail 規格不一致時，以 Sail 為準。**
也就是說 **Sail 是最終的權威**，而 Spike 只是「比較好用的參考模型」（呼應 3.3.8 節）。

除此之外講了 Sail 的三個用途、它的 trace 輸出格式、以及它的速度限制（很慢）。

## 關鍵點

### Sail 是最終權威

> "The official formal and executable specification of the RISC-V architecture is
>  written in a language called Sail [RISCV-SAIL]. Indeed, if the English
>  specification is ever ambiguous or deviates from the Sail specification, Sail takes
>  precedence."
> — p.124

中文解釋：**"formal and executable"（形式化且可執行）是關鍵。**

一般的規格書是英文寫的，英文有歧義。Sail 規格是**程式碼**，
程式碼沒有歧義——而且**可以直接執行**。

**"Sail takes precedence"（以 Sail 為準）是本節最該記住的一句。**
遇到爭議時，跑一下 Sail 就知道答案。

### Sail 的三個用途

> "Sail is a pseudocode-like language for describing ISAs. Sail serves several
>  purposes:
>  - Documents the behavior of each instruction in an ISA in a precise and readable way.
>  - Automatically creates a simulator that exactly matches the specification.
>  - Generates definitions for theorem provers aiming to prove properties about an ISA
>    or implementation."
> — p.124

中文解釋：**一份描述、三種產出，這是形式化方法的價值所在：**

| 用途 | 意義 |
| --- | --- |
| **文件** | 精確且可讀地描述每條指令的行為 |
| **模擬器** | **自動產生**一個「完全符合規格」的模擬器 |
| **定理證明** | 產生給定理證明器用的定義 |

**第二點特別重要**：模擬器是從規格**自動產生**的，
所以**不可能出現「模擬器和規格不一致」的 bug**——這正是它能當權威的原因。
（對比 Spike 是手寫的 C++，可能和規格有出入。）

### Sail 長什麼樣

中文解釋：Code Example 3.19（p.124）是 I-type 指令的 Sail 描述：
```
function clause execute (ITYPE (imm, rs1, rd, op)) = {
  let immext : xlenbits = sign_extend(imm);
  X(rd) = match op {
    RISCV_ADDI  => X(rs1) + immext,
    RISCV_SLTI  => zero_extend(bool_to_bits(X(rs1) <_s immext)),
    RISCV_SLTIU => zero_extend(bool_to_bits(X(rs1) <_u immext)),
    RISCV_ANDI  => X(rs1) & immext,
    RISCV_ORI   => X(rs1) | immext,
    RISCV_XORI  => X(rs1) ^ immext
  };
  RETIRE_SUCCESS
}
```

**這段很好讀，而且完全對應 2.1 節的說明：**
- `sign_extend(imm)` —— **立即值一律符號延伸**
- `<_s` 和 `<_u` —— **有號和無號比較是不同的運算**（`slti` vs `sltiu`）
- `zero_extend(bool_to_bits(...))` —— 比較結果是 0 或 1
- `RETIRE_SUCCESS` —— 指令成功退休（呼應 2.3 節的 retired）

**這就是「精確且可讀」的意思**——比英文句子精確，又比 C++ 好讀。

### 實作細節與生態

中文解釋：幾個邊欄的補充資訊：

**Sail 語言本身**（p.124 邊欄）：
用 **OCaml** 寫的（ML 的衍生語言，ML 常用於定理證明器）。
編譯器在 github.com/rems-project/sail。

**不只 RISC-V**（p.124 邊欄）：
**MIPS、ARM、IBM Power 的 Sail 描述也存在。**
邊欄還提出了一個願景：
> "The holy grail of formal specification and theorem proving would be to prove that
>  an HDL implementation of the ISA is logically correct. Much research remains before
>  this can be automated for complex cores."

**「形式化規格的聖杯，是證明某個 HDL 實作在邏輯上正確。」**
——也就是不用測試，直接**證明**硬體是對的。目前對複雜核心還做不到。
（第 5.10 節會談形式驗證。）

**模擬器名稱**（p.124）：
Sail 產生的模擬器叫 **`sail_riscv_sim`**，用 C++ 編譯，
所以也叫 **`sail_cSim`**。書上口語上用 "Sail" 泛指它。

**組態方式**（p.124 邊欄）：
`sail_riscv_sim` 用 **JSON 組態檔**控制支援哪些擴充。
- `--print-default-config` 可以看預設組態
- **預設是 RV64 加上大多數擴充，而且刻意「匹配 Spike 的實作選擇」**
- 指定組態：
  ```bash
  sail_riscv_sim --config $WALLY/tests/riscof/sail_cSim/rv64gc.json \
    $WALLY/examples/asm/sumtest/sumtest
  ```

### Sail 的 trace 輸出格式

中文解釋：執行方式（p.125）：
```bash
$ cd $WALLY/examples/asm/sumtest
$ sail_riscv_sim sumtest --test-signature sumtest.sig --trace=all
```

**輸出格式（p.124 說明 + p.125–126 範例）：**
> "On each instruction, Sail prints the instruction number, processor mode
>  (e.g., [M] for machine), program counter, and machine and assembly instruction.
>  It then prints any registers or memory that are modified."

```
[9] [M]: 0x0000000080000010 (0x0002B503) ld x10, 0x0(x5)
mem[R,0x0000000080004000] -> 0x0000000000000004
x10 <- 0x0000000000000004
```
**逐項對照：**
`[9]` 指令序號 → `[M]` 特權模式 → `0x...80000010` PC →
`(0x0002B503)` 機器碼 → `ld x10, 0x0(x5)` 組語 →
下面兩行是**這條指令改變了什麼**（讀了記憶體、寫了 x10）。

**這個格式對除錯非常有用**——它明確列出每條指令的副作用。

開頭還會印出關鍵資訊（p.125）：
```
ELF Entry @ 0x80000000
HTIF located at 0x80001000
begin_signature: 0x80004008
end_signature: 0x80004018
CSR mstatus (0x300) <- 0x00000000A00000000
CSR misa (0x301) <- 0x80000000034112F
```
**注意 `misa` CSR**——呼應 2.5 節，它記錄支援哪些擴充。

結尾（p.126）：
```
htif[0x0000000080001000] <- 0x0000000000000001
htif-syscall-proxy cmd: 0x0000000000001
SUCCESS
```
**寫 1 到 HTIF 就結束並印 SUCCESS**（呼應 3.3.8 節）。

Signature 檔（p.126）：
```
$ more sumtest.sig
0000000a      # sum(4) = 10
00000000
0000001d      # 29 條指令
00000000
```
**注意 8-byte 的 double word 被拆成每行 4 bytes 印出**（p.124），
所以 `0x0A` 佔兩行（低 4 bytes 和高 4 bytes）。

### Sail 的速度限制

> "The Sail RISC-V simulator runs at about 300,000 instructions per second, and
>  substantially slower for floating-point instructions. It is a bottleneck for the
>  RISCOF test signature generation, as will be described in Section 3.7.2."
> — p.124

中文解釋：**約 30 萬指令/秒**（2.3 節說約 100 萬，這裡給了更保守的數字），
**浮點指令還要慢很多**。

**對照組（呼應 3.1 節的分類）：**

| 工具 | 速度 | 定位 |
| --- | --- | --- |
| QEMU | ~10 億指令/秒 | 最快，開 OS 用 |
| Spike | ~1 億指令/秒 | 方便的參考模型 |
| **Sail** | **~30 萬指令/秒** | **權威規格**，但很慢 |

**"It is a bottleneck"（它是瓶頸）**——
產生 RISCOF 測試 signature 時，Sail 是整個流程最慢的一環（第 3.7.2 節）。

**這就是「權威」的代價**：為了保證完全符合規格，犧牲速度。
實務上的策略是：**日常用 Spike/QEMU 跑得快，最終認證時才用 Sail。**

## 名詞表

| 名詞 | 意思 |
| --- | --- |
| **Sail** | RISC-V 的官方形式化、可執行規格語言。**規格衝突時以它為準** |
| Formal specification | 形式化規格。用無歧義的語言（而非英文）描述行為 |
| `sail_riscv_sim` / `sail_cSim` | Sail 產生的模擬器（C++ 編譯） |
| OCaml | Sail 的實作語言，ML 的衍生語言 |
| Theorem prover | 定理證明器。Sail 可產生給它用的定義 |
| `misa` CSR | 記錄處理器支援哪些擴充 |
| `--trace=all` | Sail 的完整追蹤輸出（指令序號、模式、PC、機器碼、組語、副作用） |
| `--test-signature` | 產生 signature 檔以供比對 |

## 所以呢

**Sail 是 RISC-V 的最終權威——它是形式化規格，而且模擬器是從規格自動產生的，
所以「模擬器符合規格」是保證的，不是希望的。**
代價是很慢（約 30 萬指令/秒），所以實務策略是：
**開發時用快的（Spike/QEMU），最終認證時用 Sail。**
它的 trace 格式（每條指令列出所有副作用）對除錯特別有用。
