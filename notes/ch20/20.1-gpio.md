# 20.1 GPIO

> 原書 p.784.e2–784.e8（Chapter 20: Peripherals）
> 涵蓋 20.1.1 Memory Map、20.1.2 Loopback Testing、20.1.3 Test Plan、20.1.4 Wally Implementation
> 註：第 20 章是線上章節，頁碼格式為 784.eN

## 這節在講什麼

前 19 章都在做處理器核心，第 20 章開始往外看——讓核心變成一個真正 SoC 的那些周邊。這章講五個：GPIO、CLINT（計時器與軟體中斷）、PLIC（外部中斷控制器）、UART（序列埠）、SPI。

20.1 是 GPIO（general-purpose I/O，通用輸入輸出），最簡單也最常用的周邊：控制晶片上最多 32 根腳位，每根可獨立設成輸入或輸出，而且可以在腳位為 0、1、上升緣或下降緣時產生中斷。

## 關鍵點

### 這章的整體背景

> "In RISC-V, the SiFive Core Local Interruptor (CLINT) has become a de facto standard timer and software interrupt controller [FE310]. The Platform-Level Interrupt Controller (PLIC) is the standard RISC-V external interrupt controller that arbitrates among external interrupts and routes them to the appropriate harts [PLIC22]. The SiFive GPIO peripheral [FE310] is a de facto standard for general-purpose I/O. Many Linux system serial ports are compatible with the classic Texas Instruments PC16550D Universal Asynchronous Receiver/Transmitter (UART) [PC16550]."
> — p.784.e1

中文解釋：注意「**de facto standard（事實標準）**」這個詞出現了兩次。RISC-V 規格本身只規定 PLIC，CLINT 和 GPIO 是 SiFive 定義的、被大家沿用；UART 更是沿用 1980 年代的 TI PC16550D。這是一個實務教訓：**周邊介面的價值在於相容性，不在於設計得多漂亮**——Linux 驅動程式已經支援 16550，做一個相容的就能直接跑。

> "On Wally, the peripherals are in the uncore module and connect to the bus via an AHB-to-APB bridge"
> — p.784.e1

中文解釋：呼應第 9 章。周邊都掛在 APB（慢速匯流排）上，透過橋接器接到 AHB。只有 ROM 和 RAM 直接用 AHB。

### 測試周邊的通用技巧：loopback

> "When testing peripherals, it can be helpful to connect their outputs back to their inputs so a test program can drive known values and read them back. This is known as loopback testing."
> — p.784.e1

中文解釋：這是驗證周邊的核心技巧，GPIO 和 SPI 都用（設定參數 `GPIO_LOOPBACK_TEST`、`SPI_LOOPBACK_TEST`）。沒有 loopback 的話，測試程式寫出去的值就消失在晶片外，沒辦法在模擬裡驗證。

### GPIO 的介面與功能

> "The general-purpose input/output (GPIO) peripheral controls up to 32 GPIO pins on a chip. It can configure each pin individually to be an input or output and can generate interrupts when a particular pin is 0, 1, rises, or falls."
> — p.784.e2

中文解釋：Fig. 20.1 的四組訊號：APB（給 CPU 存取暫存器）、`GPIOIntr`（送給 PLIC）、以及三組給 I/O 驅動器的訊號 `GPIOPinsIn`、`GPIOPinsOut`、`GPIOPinsEn`。

**為什麼要三組訊號而不是一組雙向線？** 因為晶片內部不用 tristate（三態）。腳位驅動器需要知道「要輸出什麼值」（`Out`）和「要不要驅動」（`En`），讀回來的是 `In`。`En = 0` 時腳位是高阻抗，可以被外界驅動。

### 暫存器的基本組成

> "Each register has 32 1-bit fields corresponding to the 32 GPIO pins. The output_en (output enable) register enables the tristate drivers when a bit is 1 to make the corresponding pin an output. The output_val register contains the values to drive onto the output pins. The input_val register contains values read from the input pins. The input_en register makes the corresponding bits in input_val 0 when not enabled. The out_xor register conditionally inverts the output value going to the pin."
> — p.784.e2

中文解釋：Table 20.1 的 17 個暫存器（offset 0x00–0x40）。每個都是 32 位元，**即使在 RV64 上也是 32 位元**——因為一根腳位對應一個位元。重設後全部清 0，所以**預設全部是輸入**（安全的預設值：不驅動任何東西）。

`out_xor` 看起來很奇怪，但很實用：有些外部元件是 active-low（低電位有效），設定 `out_xor` 就能讓軟體照正常邏輯寫 1 表示「開」，硬體自動反相。

### 輸入要過同步器

> "The inputs are generally asynchronous to the peripheral (APB) clock, so they are synchronized to the peripheral's clock domain with a 2-stage synchronizer (see Fig. 20.4) to prevent metastability."
> — p.784.e2

中文解釋：這是數位設計的基本功但很重要。外面的按鈕、感測器什麼時候變化完全不受時脈控制，直接進 flip-flop 可能違反 setup/hold 時間造成**亞穩態（metastability）**——輸出停在 0 和 1 之間一段不確定的時間，讓下游邏輯看到不一致的值。兩級同步器讓第一級的亞穩態有一整個週期衰減。

### 中斷 pending 位元是 sticky 的，寫 1 清除

> "Interrupt pending bits are sticky so that the bit will remain 1 even if the input becomes 0. Writing a 1 to an interrupt pending bit clears it. This may seem counterintuitive but allows a programmer to easily clear a particular pending interrupt without disturbing other pending interrupts."
> — p.784.e2

中文解釋：這是 memory-mapped I/O 的經典慣例，**write-1-to-clear（W1C）**。為什麼不用「寫 0 清除」？因為那樣要做 read-modify-write：讀出目前的值、把想清的那位改成 0、寫回去——而中間如果有新中斷來，就會被誤清掉（race condition）。W1C 只要 `sw` 一個只有目標位元為 1 的值，其他位元寫 0 表示「不動」，完全沒有 race。

`sticky`（黏著）則是必要的：一個上升緣可能只持續幾奈秒，如果不記住，軟體根本來不及看到。

### 四種中斷條件

> "the low_ip, rise_ip, and fall_ip interrupt pending bits are set by an input being 0, rising, or falling, and will remain set until a 1 is written to the interrupt pending (*_ip) register. The interrupt enable registers (high_ie, low_ie, rise_ie, fall_ie) control whether particular GPIO pins generate an interrupt when the interrupt pending bit is set. If any of the high, low, rise, or fall interrupts are both pending and enabled, the GPIOIntr signal raises to inform the interrupt controller."
> — p.784.e2

中文解釋：四種條件（high / low / rise / fall）各有一對 `_ie`（enable）和 `_ip`（pending）暫存器。**pending 與 enable 分離**是關鍵設計：pending 位元不管有沒有 enable 都會設起，所以軟體可以用輪詢（polling）而不開中斷；enable 只控制要不要真的驚動 CPU。

最後所有 `_ip & _ie` 的結果 OR 起來成為 `GPIOIntr`（Fig. 20.4 的 Interrupt Merge）。

### 一個完整的 GPIO 程式

> "Consider the system in Fig. 20.2 in which two pushbutton switches and a light-emitting diode (LED) are connected to GPIO pins. The pulldown resistors set a default value of 0 when the switches are not pressed. The series current-limiting resistor sets the brightness of the LED and prevents overheating and damage to the pin by preventing it from driving too much current."
> — p.784.e4

中文解釋：Example 20.1 的硬體配置：GPIO[0] 和 GPIO[1] 接兩個按鈕（各配 10 kΩ 下拉電阻），GPIO[2] 經 330 Ω 電阻接 LED。組語版：

```
la  t0, 0x10060000   # GPIO 基底位址
li  t1, 3
sw  t1, 4(t0)        # input_en = 0b11，啟用腳位 0、1
li  t1, 4
sw  t1, 8(t0)        # output_en = 0b100，啟用腳位 2
loop:
lw  t2, 0(t0)        # 讀 input_val
beq t2, zero, led_off
sw  t1, 0xC(t0)      # output_val = 4，點亮 LED
j   loop
led_off:
sw  t0, 0xC(t0)      # 熄滅
j   loop
```

C 版本則示範了一個關鍵細節：

> "The volatile keyword tells a C compiler that the variable might change between accesses, even though it is not modified by the program. It forces the compiler to fetch the variable from memory rather than use the last value stored in a register. Memory-mapped I/O registers should be declared volatile because the hardware might change them."
> — p.784.e5（邊欄）

中文解釋：**`volatile` 是 memory-mapped I/O 程式的必要條件**。沒有它，編譯器看到 `while(1) { switches = *GPIO_INPUT_VAL; ... }` 會認為 `*GPIO_INPUT_VAL` 在迴圈裡不會變，於是把它提到迴圈外只讀一次——程式就永遠讀到同一個值。

（書上很誠實地在邊欄註明：「None of the code examples in this chapter are tested. Caveat emptor.」）

### loopback 測試怎麼做

> "On the GPIO peripheral, GPIOPinsIn and GPIOPinsOut are normally connected at the top level of the chip to the I/O pin drivers. When the Wally GPIO_LOOPBACK_TEST configuration is set, the GPIO module connects the signals internally, so GPIOPinsIn gets its value from GPIOPinsOut when GPIOPinsEn is set. This facilitates testing at lower levels of the SoC hierarchy when there are no pin drivers."
> — p.784.e5

中文解釋：注意 loopback 是**條件式**的——只有 `GPIOPinsEn` 設起（該腳位是輸出）時才把輸出接回輸入。這模擬了真實情況：輸出腳位上的值確實可以讀回來。

測試計畫：檢查 reset 狀態、在 loopback 模式下驅動輸出並檢查輸入、逐一測試每個中斷 enable 與 pending 位元。

### GPIO 模組的實作

> "Fig. 20.4 shows a schematic of the GPIO module (gpio_apb) in the RV32 configuration of Wally. It is an extension of the simplified APB GPIO module from Section 9.2.1. The module contains a 14-register × 32-bit register file that holds the GPIO registers (excluding the input_val, pue, and ds registers from Table 20.1). input_val is a synchronized register at the top of the schematic, and pue and ds are not implemented."
> — p.784.e7

中文解釋：實作重點：
- **14 個暫存器 × 32 位元**的小暫存器檔。`input_val` 不在裡面（它不是軟體寫的，是同步器的輸出）。
- **位址解碼器**看位址低位元決定讀寫哪個暫存器；`memwrite` 在 APB 的 access phase 且 `PSEL` 有效時產生。
- **read multiplexer** 依同一個解碼結果選出要讀的暫存器。
- RV64 版本「相同，只是多加了多工器在 `PRDATA` 和 `PWDATA` 上，用來存取 64 位元字的上半或下半」。

`pue`（內部上拉）和 `ds`（驅動強度）沒有實作：

> "Wally does not rely on I/O pads having internal pull-up resistors or adjustable drive strength, so it does not implement the pue and ds registers."
> — p.784.e8

中文解釋：這兩個暫存器控制的是**類比性質的 I/O pad 特性**，不是數位邏輯。Wally 是純數位設計，所以跳過。

### 中斷 pending 的 set/clear 邏輯

> "Fig. 20.5 shows a schematic of the gray box in Fig. 20.4 that sets and clears pending interrupts. Recall that writing 1s to bits in an interrupt pending register clears those interrupts. PWDATA indicates which interrupts to clear. Pending interrupt bits are set when their condition (rise/fall/high/low) occurs, indicated by signal cond."
> — p.784.e8

中文解釋：Fig. 20.5 的邏輯非常小——每個位元就是 `next_ip = cond | (ip & ~(we & PWDATA))`：條件發生就設起，或者保持現值除非被寫 1 清掉。整個 GPIO 中斷系統就是 32 份這個一位元電路乘以四種條件。

## 名詞表

| 名詞 | 意思 |
| --- | --- |
| GPIO | general-purpose I/O，通用輸入輸出腳位 |
| de facto standard | 事實標準，非正式規定但業界通用（CLINT、GPIO、UART 都是） |
| memory-mapped I/O | 用載入/儲存指令存取周邊的控制、狀態、資料暫存器 |
| loopback testing | 把輸出接回輸入以便測試 |
| `GPIOPinsIn` / `GPIOPinsOut` / `GPIOPinsEn` | 讀回值／驅動值／是否驅動（三態致能） |
| tristate driver | 三態驅動器，可進入高阻抗狀態讓別人驅動 |
| metastability | 亞穩態，違反 setup/hold 時造成的不確定輸出 |
| 2-stage synchronizer | 兩級同步器，讓亞穩態有時間衰減 |
| sticky bit | 黏著位元，設起後不會自動清除 |
| write-1-to-clear (W1C) | 寫 1 清除，避免 read-modify-write 的 race condition |
| `_ie` / `_ip` | interrupt enable ／ interrupt pending 暫存器 |
| `out_xor` | 條件式反相輸出，方便驅動 active-low 元件 |
| `pue` / `ds` | 內部上拉致能／驅動強度（Wally 未實作） |
| `iof_en` / `iof_sel` | I/O function enable / select，腳位多工給其他周邊用 |
| `volatile` | C 關鍵字，強制每次都從記憶體讀取，MMIO 必備 |
| pulldown resistor | 下拉電阻，讓未驅動的輸入有確定的預設值 |
| current-limiting resistor | 限流電阻，保護 LED 與腳位 |
| `gpio_apb` | Wally 的 GPIO 模組 |

## 所以呢

GPIO 雖然是最簡單的周邊，但它示範了周邊設計的所有共通模式：memory-mapped 暫存器、位址解碼、W1C 的 pending 位元、enable/pending 分離、輸入同步器、loopback 測試。後面四個周邊都會重複用到這些。下一節 20.2 的 CLINT 更簡單（只有三個暫存器），但它提供 OS 排程最關鍵的東西——計時器中斷。
