## 關鍵點

### GCC 工具鏈

> "This chapter has described the RISC-V toolchain, simulators, and test suites used in
>  an open-source Linux-based development environment widely used by professional
>  developers. GNU's gcc provides an assembler, linker, and C compiler that support many
>  architectures including RISC-V. It outputs RISC-V programs as ELF files that also
>  contain headers, debug information, and the symbol table. objdump disassembles ELF
>  files to assembly language."
> — p.140

中文解釋：**"widely used by professional developers"（專業開發者廣泛使用）**
這句值得注意——這不是教學用的玩具環境，**就是業界實際在用的東西**。

三個工具的分工再看一次：
- **`gcc`**：組譯器 + 連結器 + C 編譯器（支援多種架構）
- 輸出 **ELF**（含 header、除錯資訊、符號表）
- **`objdump`**：反組譯 ELF 成組合語言

### 三個模擬器的最終定位

> "Spike, Sail, and QEMU are three standard RISC-V simulators. Spike was the original
>  golden RISC-V simulator and remains the easiest to use. Sail is a newer simulator that
>  also serves as RISC-V's formal executable architecture specification. QEMU is an
>  extremely fast open-source emulator, and it interfaces nicely with GDB for debugging."
> — p.140

中文解釋：**一句話一個定位，這是整章最好的摘要：**

| 工具 | 一句話定位 | 速度 | 何時用 |
| --- | --- | --- | --- |
| **Spike** | 最早的黃金模擬器，**最好用** | ~1 億指令/秒 | 日常快速檢查、互動除錯 |
| **Sail** | **RISC-V 的形式化可執行規格** | ~30 萬指令/秒 | **需要權威答案**、產生標準 signature |
| **QEMU** | 極快的模擬機，**GDB 整合好** | ~10 億指令/秒 | **開 OS**、原始碼層級除錯 |

**挑工具的三個判準（整章濃縮）：**
1. **要開 OS / 要 GDB 除錯** → QEMU（記得加 `-icount 0` 才有正確指令數）
2. **要標準答案 / 有規格爭議** → Sail
3. **只想快速看指令對不對** → Spike
4. **（要精確週期數）** → 都不行，**要用邏輯模擬器**（第 5 章）

### 測試套件的用途

> "This chapter also showed how to use the toolchain and simulators to compile RISC-V
>  verification test suites and generate expected results."
> — p.140

中文解釋：**"generate expected results"（產生預期結果）是關鍵。**

本章的工具鏈在驗證流程中扮演的角色，**不是驗證硬體本身，
而是產生「硬體該給出什麼答案」的標準答案。**

實際比對硬體是第 5 章的事——本章交出去的東西是
RISCOF `work/*/ref/` 目錄下的 `memfile`、`.addr`、`.lab` 和 signature。

## 所以呢

**第 3 章建立的是「軟體側」：怎麼把程式編出來、怎麼在模擬器上跑、
怎麼產生標準答案。硬體還沒出現。**

帶走三件事：
1. **裸機編譯配方**：`-march` / `-mabi` / `-mcmodel` / `-nostdlib` + `crt.S`、`syscalls.c`
2. **三個模擬器的選用原則**：Spike 好用、Sail 權威、QEMU 快且能除錯
3. **signature 比對機制**——這是所有自動化測試的共同基礎，第 5 章會用同一套來驗硬體

下一章（第 4 章）換到硬體側：SystemVerilog 與 HDL 設計實務。
