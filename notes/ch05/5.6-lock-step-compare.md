# 5.6 Lock-Step-Compare

> 原書 p.212–214（Chapter 5: Design Verification）
> 含 5.6.1 RVVI-TRACE Interface

## 這節在講什麼

**比 signature 更強的驗證方法：每執行一條指令，就把整個架構狀態和參考模型比對一次。**

論證的結構很清楚：
1. **先說 signature 的三個限制**（為什麼不夠）
2. **再提出 lock-step-compare**（每條指令都比）
3. **然後說它的兩個難處**（中斷注入、規格歧義）
4. **最後介紹標準介面 RVVI-TRACE 和商用工具 ImperasDV**

**核心優勢一句話：錯誤在發生的當下就被發現，而不是幾百萬條指令之後才浮現。**

## 關鍵點

### Signature 的三個限制

> "Signature checking has several limitations in verification. **A program typically produces
>  one signature word after a sequence of instructions, and that might not capture all design
>  errors.** For example, an early version of riscv-arch-test floating-point tests created a
>  signature with the result of the instruction but not the floating-point flags, thus missing
>  bugs in the flag logic. Moreover, **a system test such as running a benchmark or booting
>  Linux doesn't produce a signature or only indicates success (e.g., a login prompt) after
>  millions of instructions.**"
> — p.212

中文解釋：**三個限制，逐條看：**

| 限制 | 說明 |
| --- | --- |
| **1. 粒度太粗** | 一串指令才產生一個 signature word，中間的錯誤可能被蓋掉 |
| **2. 只記錄部分狀態** | **書上的例子很經典：浮點測試只記結果不記 flag，所以 flag 邏輯的 bug 全漏掉** |
| **3. 系統測試根本沒有 signature** | 開 Linux 只有「幾百萬條指令後出現登入提示」這個成敗訊號 |

**第二點特別值得記**：signature 能抓到的，只有你想到要放進 signature 的東西。
**你沒想到要檢查的，就永遠不會被發現。**

（呼應 5.1.1 節 Pentium FDIV：測了，但測錯對象。）

### Lock-step-compare 的定義

> "A more robust verification methodology is *lock-step-compare*, in which a testbench logs
>  **all the architectural state that changes when an instruction completes** and compares
>  against a reference model, **reporting every discrepancy**. The state includes the program
>  counter (PC), integer and floating-point registers, control and status registers (CSRs),
>  and memory. **In this way, deviations are discovered immediately rather than possibly
>  being hidden or causing a subtle failure much later.**"
> — p.212–213

中文解釋：**「每完成一條指令，就記錄所有變動的架構狀態，和參考模型比對，回報每一個差異。」**

**要比對的架構狀態清單（呼應 2.7 節的架構狀態定義）：**
**PC、整數暫存器、浮點暫存器、CSR、記憶體。**

**最後那句是這個方法的全部價值：偏差在當下就被發現。**

**對比 signature 的除錯體驗：**
- **signature 失敗**：只知道「最後結果錯了」，要從幾百萬條指令裡找出哪裡開始錯
- **lock-step 失敗**：**直接告訴你第 N 條指令的 x5 應該是 3 但你算出 4**

### Lock-step 的兩個難處

> "**A key requirement of operation is to inject the same interrupts into the reference model
>  as the DUT, so they remain in *lockstep***, following the same program counter sequence
>  and producing exactly the same architectural state after each instruction."
> — p.213

中文解釋：**難處一：中斷必須同步注入。**

中斷是**非同步**的（呼應 2.3 節）——它可能落在任何一條指令之間。
如果 DUT 在第 1000 條指令後被中斷，而參考模型在第 1001 條後才中斷，
**兩者的 PC 序列立刻分岔，之後全部都「不一致」，但其實沒有 bug。**

**所以必須把完全相同的中斷注入參考模型。**「lockstep（步調一致）」這個名字就是從這來的。

> "Another challenge is that **the RISC-V specification is both configurable and ambiguous in
>  many places**, so the reference model must be configured to exactly match the behavior of
>  the DUT when multiple behaviors are legal. The reference model must not only agree on XLEN
>  and supported extensions but also on subtle behavior such as **whether the UXL bits of the
>  mstatus register are writable, such that user-mode XLEN can be changed at runtime**."
> — p.213

中文解釋：**難處二：規格既可組態又有歧義。**

**「多種行為都合法」時，參考模型必須設定成和 DUT 完全一樣。**
（呼應 5.1.2 節的 unspecified behavior。）

書上給的例子很細微：**`mstatus` 的 UXL 位元可不可以寫
（也就是使用者模式的 XLEN 能不能在執行時改變）**——
這種層次的細節都要對齊，否則就會出現假的不一致。

**這說明了 lock-step 的代價：設定參考模型本身就是一項工程。**

### ImperasDV：商用的 lock-step 工具

> "ImperasDV is a widely used commercial lock-step-compare tool. It requires a tracer in the
>  testbench to log the changing state using the RVVI-TRACE standard interface [RVVI-TRACE].
>  **The DUT runs programs in the usual fashion, while the Imperas reference model runs the
>  same programs, takes the same interrupts, reads the same values from memory and peripherals,
>  and reports tracer discrepancies**, as shown in Fig. 5.4.... **Synopsys acquired Imperas in
>  2024.**"
> — p.213

中文解釋：**Fig. 5.4（p.213）的架構（原書此處為方塊圖，以下為轉錄）：**

```
┌─ Top-Level Testbench (SystemVerilog) ─┐   ┌────── ImperasDV ──────────────────┐
│  UVM env (optional)                   │   │ ImperasFC        ImperasFPM       │
│  Simulation Control                   │   │ Functional       RISC-V Reference │
│  ┌──────────────┐                     │   │ Coverage         Model            │
│  │ RISC-V Core  │──[RVVI TRACER]──┐   │   │                                   │
│  │ RTL (DUT)    │                 ├───┼───┼→ trace2cov       Configuration    │
│  └──────────────┘                 │   │   │  trace2api  ──→  State Comparison │
│  ┌──────────────┐   RVVI-TRACE ───┘   │   │  trace2log       Pipeline Sync    │
│  │   Memory     │←─[Test]             │   │                  Scoreboard       │
│  └──────────────┘                     │   │                  Pass/Fail        │
└───────────────────────────────────────┘   └───────────────────────────────────┘
```

**讀法：DUT 端有個 RVVI TRACER 把狀態變化透過 RVVI-TRACE 介面送出；
ImperasDV 端有參考模型（ImperasFPM）和功能覆蓋率（ImperasFC），
負責狀態比對、pipeline 同步、scoreboard 和成敗判定。**

**注意右側有 "Pipeline Synchronization"（管線同步）**——
這正是處理「DUT 有 pipeline 而參考模型沒有」這個落差的機制。

**四個「相同」是關鍵（p.213）：跑相同的程式、接收相同的中斷、
從記憶體和周邊讀到相同的值、然後回報差異。**

### RVVI-TRACE：標準介面

> "RVVI-TRACE defines a SystemVerilog interface, capturing the state changes that occur during
>  each instruction. **Wally uses RVVI both to communicate with ImperasDV during lockstep
>  simulation and to provide the state to riscvISACOV functional coverage.**"
> — p.214

中文解釋：**RVVI-TRACE 是一個「標準化的狀態輸出介面」。**

**它有兩個用途（一箭雙鵰）：**
1. **lock-step 模擬時和 ImperasDV 溝通**（本節）
2. **提供狀態給 riscvISACOV 做功能覆蓋率**（第 5.9 節）

**這就是標準介面的價值：同一份狀態輸出，餵給兩個不同的工具。**

**Table 5.4（p.214）的 RVVI-TRACE 訊號——這張表就是「一條指令的完整副作用」：**

| 訊號 | 大小 | 意義 |
| --- | --- | --- |
| `clk` | 1 | 更新狀態的系統時脈 |
| `insn` | 32 | **目前的指令** |
| `trap` | 1 | **是 trap 而非指令退休** |
| `pc_rdata` | XLEN | **指令的 PC** |
| `x_wdata` | XLEN × 32 | 寫入整數暫存器檔案的新值 |
| `x_wb` | 32 | **哪些整數暫存器被寫入**（每位元對應一個暫存器） |
| `f_wdata` | FLEN × 32 | 寫入浮點暫存器檔案的新值 |
| `f_wb` | 32 | 哪些浮點暫存器被寫入 |
| `csr` | XLEN × 4,096 | 寫入 CSR 的新值 |
| `csr_wb` | 4,096 | **哪些 CSR 被寫入** |

**讀表的重點：`_wdata` 是「新值」，`_wb` 是「哪些被寫」的 one-hot 遮罩。**
`csr` 有 4096 個是因為 CSR 位址是 12 bit（2¹² = 4096）。

**注意 `trap` 訊號**：trap 發生時指令沒有退休，行為不同，所以要單獨標記
（呼應 2.3 節的 trap 機制）。

### Wally 的實作

> "testbench/common/wallyTracer.sv sends register changes (register files and CSRs) from the
>  Writeback stage to the RVVI-TRACE interface. It also **pipelines other signals (such as PCF,
>  InstrF, and TrapM) into the Writeback stage, accounting for stalls and flushes**, and sends
>  them to RVVI-TRACE."
> — p.214

中文解釋：**這段揭露了一個重要的實作細節：所有狀態都要對齊到 Writeback 級。**

為什麼？**因為只有到了 Writeback 級，指令才真正「退休」**（呼應 2.3 節的 retired）。
在此之前的指令可能被 flush 掉——**那些不算數。**

所以 tracer 要做的事是：
- 暫存器檔案和 CSR 的變化本來就在 Writeback 級發生 ✓
- **但 `PCF`（Fetch 級的 PC）、`InstrF`（Fetch 級的指令）、`TrapM`（Memory 級的 trap）
  這些在較早的級產生的訊號，必須一路 pipeline 到 Writeback 級**
- **而且要正確處理 stall 和 flush**

**這正好是 4.3.1.2 節那個「跨級元件是 bug 常見來源」的實例。**

## 名詞表

| 名詞 | 意思 |
| --- | --- |
| **Lock-step-compare** | 每條指令完成時比對所有變動的架構狀態與參考模型 |
| Signature checking | 執行一串指令後產生一個結果字並比對；**粒度粗、只記部分狀態** |
| Lockstep | 步調一致。DUT 與參考模型跟隨相同的 PC 序列與架構狀態 |
| Interrupt injection | 中斷注入。必須對 DUT 和參考模型注入相同中斷，否則兩者分岔 |
| **RVVI-TRACE** | 標準 SystemVerilog 介面，輸出每條指令造成的狀態變化 |
| ImperasDV | 商用 lock-step-compare 工具（Synopsys 於 2024 年收購 Imperas） |
| `x_wdata` / `x_wb` | 寫入暫存器的新值 / 哪些暫存器被寫入的遮罩 |
| `wallyTracer.sv` | Wally 的 tracer，把 Writeback 級的狀態送到 RVVI-TRACE |

## 所以呢

**Lock-step-compare 相對於 signature 的核心優勢：偏差在當下就被抓到，
而不是幾百萬條指令後才以某種怪異的形式浮現。**

三件要記住的事：
1. **Signature 只能抓你想到要放進去的東西**——
   浮點測試漏掉 flag 就漏掉所有 flag 的 bug。
2. **Lock-step 的兩個難處**：**中斷必須同步注入**（否則假不一致），
   **規格歧義處參考模型要設定得和 DUT 一致**。
3. **RVVI-TRACE 一份輸出餵兩個用途**：lock-step 比對（本節）和功能覆蓋率（5.9 節）。
   而 Wally 的 tracer 必須把所有訊號對齊到 **Writeback 級**——只有退休的指令才算數。

下一節（5.7）換一種手段：assertion，在錯誤汙染架構狀態之前就抓到它。
