# 16.4 RISC-V Practices

> 原書 p.646–651（Chapter 16: Extensions: F/D/Q/Zfh/Zfa (Floating-Point)）
> 涵蓋 16.4.1 Floating-Point Control and Status Register、16.4.2 Registers and NaN Boxing、16.4.3 NaNs in RISC-V、16.4.4 Floating-Point Move Instructions、16.4.5 Zfa Additional Floating-Point Instructions

## 這節在講什麼

IEEE 754 規定了數字格式與運算行為，但沒規定「捨入模式存在哪」「旗標怎麼讀」「單精度值放進 64 位元暫存器要怎麼擺」。這節講 RISC-V 在 IEEE 之上的具體決定：`fcsr` 這顆 CSR、32 個浮點暫存器與 NaN boxing、只用 canonical NaN 不傳 payload、`fmv` 家族的搬位元指令，以及後來補上的 Zfa 擴充。有幾個決定明顯是為了「省硬體」而不是「照規格抄」，值得注意。

## 關鍵點

### RISC-V 的浮點擴充有哪些

> "As described in Section 2.8, RISC-V has optional Zfh, F, D, and Q extensions for half-, single-, double-, and quad-precision floating-point instructions that are compliant with the IEEE standard. It also has optional Zfa additional floating-point instructions applicable to all precisions."
> — p.646

中文解釋：四種精度各是獨立的擴充，可以只實作其中幾個。Zfa 是後來補的雜項指令集。另外還有一個提案中的 L 擴充處理十進位浮點（decimal floating-point），目前還在開發。

### 重開機後 FPU 是關著的

> "Recall from Section 8.2.3.1 that the status.FS bits enable floating-point. They are typically 00 at reset, which disables the FPU and makes floating-point instructions cause illegal-instruction exceptions. Write 01 to status.FS before executing floating-point code."
> — p.646

中文解釋：這和第 8 章的 privileged 架構接上了。FS 預設關閉有兩個好處：不用浮點的系統可以省電（clock gate 整個 FPU），而且 OS 做 context switch 時可以靠 FS 判斷這個 process 有沒有動過浮點暫存器，沒動過就不必存/復原那 32 個暫存器。

### fcsr 的欄位配置

> "RISC-V has a floating-point control and status register (fcsr) shown in Fig. 16.17(a) that defines the dynamic rounding mode and flags. Each floating-point instruction has an rm field to either specify the rounding mode or dynamically select the mode indicated by the fcsr."
> — p.646–647

中文解釋：Fig. 16.17(a)：bit 7:5 是 `frm`（捨入模式），bit 4:0 是五個旗標 NV/DZ/OF/UF/NX。指令裡的 `rm` 欄位若寫 `111`(DYN) 就用 `fcsr.frm`；也可以在指令裡直接指定（例如 `fadd.s f0, f1, f2, rtz`）。Table 16.10 是五種模式的編碼：000 RNE、001 RTZ、010 RDN、011 RUP、100 RMM，101/110 保留，111 DYN（放在 `fcsr.frm` 裡是非法值）。

### 為什麼要有 DYN 這個模式

> "The C11 language defines the fesetround() function to change rounding modes on the fly while a program is running. This effectively mandates that instruction sets support dynamic rounding modes."
> — p.647（邊欄）

中文解釋：語言層的需求逼出硬體設計。編譯器編譯 `a + b` 時不知道執行期的捨入模式是什麼，所以只能發出 DYN，讓硬體去查 `fcsr`。

### 旗標是「累積」的，而且沒有浮點 trap

> "If an instruction has an exception condition such as divide by zero or underflow, that bit in the accrued exception flag register is set and remains set until cleared by software. Thus, a program can run efficiently with no exception checking, then test if any of the flags are set at the end of the calculation. RISC-V does not have any floating-point traps."
> — p.647–648

中文解釋：這是很重要的設計取捨。accrued（累積）表示旗標只會被設起、不會自動清掉，軟體要自己寫 0。好處是每個浮點指令都不必檢查例外、不必精確中斷，跑得快；壞處是出錯時無法知道是哪一行出的。另外 RISC-V 還提供 `frm` 和 `fflag` 兩顆 CSR（Fig. 16.17(b)(c)），讓程式不用遮罩就能單獨存取這兩塊。underflow 的判定 RISC-V 採 **detect tininess after rounding**。

### NaN boxing：小精度值放進大暫存器

> "If the D extension is supported, the registers are all 64 bits wide, and single-precision values are held in the least significant half of the register with all 1s in the upper half. This is known as NaN boxing because the double-precision value is a NaN with a payload of the single-precision value in the bottom half."
> — p.648

中文解釋：這招很聰明。上半填全 1 之後，整個 64 位元讀起來剛好是一個 NaN（指數全 1、fraction 非 0）。所以如果程式錯把一個 single 值當成 double 來用，結果會是 NaN 而不是一個看起來合理的垃圾數字——錯誤會自己現形。Example 16.19：half 的 1.0 = 0x3C00 存進 quad 暫存器就是 0xFFFF...FFFF3C00（上面 112 個 1）。

### RISC-V 不傳遞 NaN payload

> "The IEEE 754 specification and default SoftFloat implementation recommend propagating the payload from one of the NaN inputs to a NaN output. In contrast, RISC-V produces a canonical quiet NaN (or, simply, canonical NaN) as the output of any floating-point operation resulting in NaN. This canonical NaN has a positive sign and all fraction bits of 0 except the most significant bit."
> — p.648

中文解釋：IEEE 建議把輸入 NaN 的 payload（fraction 裡那些位元，可以用來記錄錯誤來源）傳到輸出。RISC-V 不做。邊欄給的理由很直白：「NaN payload 在可攜程式裡根本沒人用，不值得為了選 payload 加一個多工器」。Table 16.11 的 canonical NaN：half 7E00、single 7FC00000、double 7FF8000000000000、quad 7FFF8000...0。所以 SoftFloat 要加 `SPECIALIZE_TYPE=RISCV` 編譯旗標才會產生一致的行為。

### fmv 只搬位元，不做轉換

> "The fmv family of instructions moves raw bits between integer and floating-point registers without conversion, as summarized in Table 16.12. If the integer register is wider than the floating-point format, moves to floating-point take the lower bits of the integer register, and moves from floating-point sign-extend the bits to the width of the integer register."
> — p.649

中文解釋：注意 `fmv` 和 `fcvt` 的差別：`fcvt.s.w` 把整數 5 轉成浮點 5.0（位元樣貌完全變了）；`fmv.w.x` 把整數暫存器的 32 個位元原封不動搬進浮點暫存器（可能變成一個奇怪的小數）。四個指令：`fmv.x.w`、`fmv.w.x`、`fmv.x.d`、`fmv.d.x`（後兩個只有 RV64D 有）。

### Zfa 是「用久了才發現少了這些」

> "As the RISC-V ecosystem of compilers and libraries matured, developers discovered a variety of handy floating-point instructions were absent from the initial F, D, Q, and Zfh specifications."
> — p.649

中文解釋：Zfa 的內容（Table I.26）：
- **`fli`**：載入 32 個常用常數之一。為什麼需要？「載入浮點常數出乎意料地貴」——從記憶體載入要等 DRAM，用算的則要一堆 add/shift 組出整數再轉浮點。Table 16.13 列出這 32 個值（−1.0、最小正規數、各種 2 的冪、1.0~1.75 的四分之一刻度、∞、canonical NaN 等）。
- **`fround`/`froundnx`**：照捨入模式把浮點數捨入成整數值，但結果仍是浮點。對應 IEEE754-2019 的 *roundToIntegral* / *roundToIntegralExact*。選對捨入模式就能實作 C 的 `trunc()`、`ceil()`、`floor()`、`round()`。`froundnx` 多設 Inexact 旗標。
- **`fmvh`/`fmvp`**：RV32D 和 RV64Q 用來在浮點暫存器與「一對」整數暫存器之間搬資料（因為浮點暫存器比整數暫存器寬一倍）。
- **`fminm`/`fmaxm`**：和 `fmin`/`fmax` 幾乎一樣，差別在「只要有一個輸入是 NaN 就回 canonical NaN」，對應 IEEE754-2019 的 *minimum*/*maximum*；`fmin`/`fmax` 對應 *minimumNumber*/*maximumNumber*。
- **`fltq`/`fleq`**：和 `flt`/`fle` 一樣但輸入是 quiet NaN 時不設 Invalid 旗標（*compareQuiet* vs *compareSignaling*）。
- **`fcvtmod.w.d`**：專門加速 JavaScript 的 Number。JS 的 Number 是 double，但有時要當成 mod 2^32 的有號整數用。這指令像 `fcvt.w.d` 但永遠朝 0 捨入，取無界結果的低 32 位元再符號擴展，∞ 和 NaN 都轉成 0。

## 名詞表

| 名詞 | 意思 |
| --- | --- |
| `fcsr` | floating-point control and status register，含 frm 與五個旗標 |
| `frm` / `fflag` | 只含捨入模式／只含旗標的 CSR 別名 |
| `status.FS` | mstatus 裡啟用 FPU 的兩個位元，reset 時為 00（關閉） |
| accrued flag | 累積旗標，設起後不自動清除 |
| DYN | rm 欄位值 111，表示用 fcsr.frm 動態決定捨入模式 |
| NV/DZ/OF/UF/NX | Invalid / Divide by Zero / Overflow / Underflow / Inexact 五個旗標 |
| RNE/RTZ/RDN/RUP/RMM | 五種捨入模式（最近偶數／朝零／朝 −∞／朝 +∞／最近且平手取大值） |
| NaN boxing | 小精度值存進大暫存器時上半填全 1，整體成為 NaN |
| canonical NaN | 正號、fraction 只有最高位為 1 的標準 quiet NaN |
| payload | NaN 的 fraction 位元，可用來攜帶額外資訊（RISC-V 不用） |
| `fmv` | 搬原始位元，不做數值轉換 |
| Zfa | 後續補充的雜項浮點指令擴充 |
| roundToIntegral | IEEE754-2019 的「捨入成整數值但保持浮點型別」運算 |
| compareQuiet / compareSignaling | 遇 quiet NaN 不設／會設 Invalid 的比較 |
| L extension | 提案中的十進位浮點擴充 |
