> 涵蓋 15.2.1 Signed and Unsigned Operations、15.2.2 Division Special Cases、

## 這節在講什麼

**M 擴充的規格細節。四個子節：**

1. **有號無號的版本**（15.2.1）：呼應 15.1.1 節
2. **除法的特殊情況**（15.2.2）：**除以 0 和溢位——RISC-V 不拋例外**
3. **軟體實作**（15.2.3）：**沒有 M 擴充時要花 195 條指令**
4. **Zmmul**（15.2.4）：只要乘法不要除法

**最該記住的是 15.2.2 的兩個特殊值（除以 0 的結果）

## 關鍵點

### 指令清單

> "**As shown in Table I.5..., RV32M has multiply, divide, and remainder instructions that operate on the full
>  XLEN-bit words, treated as signed or unsigned values.**"
> — p.604

> "**RV64M adds word operations `mulw`, `divw`, `divuw`, `remw`, `remuw` that act on the lower 32-bit word of each
>  operand, which is sign-extended to fill 64-bit registers.**"
> — p.604

中文解釋：**RV64M 的 W 版本和第 2 章的 W 後綴指令同一個道理**
（呼應 2.1 節：C 語言的 `int` 在 64 位元機器上仍是 32-bit）。

### 有號無號的指令設計

> "**As discussed in Section 15.1.3, multiplication of two N-bit numbers produces a 2N-bit result, with the least
>  significant N bits being the same independent of the operands' sign. These XLEN least significant bits are produced
>  by the `mul` instruction. `mulhu`, `mulhsu`, and `mulh` compute the most significant XLEN bits for each combination
>  of unsigned × unsigned, signed × unsigned, and signed × signed.**"
> — p.604

> "**Similarly, division and remainder instructions have different flavors for signed and unsigned.**"
> — p.604

中文解釋：**注意除法沒有 `divsu`（有號 ÷ 無號）。**

**（p.604 邊欄解釋了為什麼：**
「C 和相關語言禁止在算術敘述中混用有號和無號變數；有號的輸入會自動轉成無號。
**因此 `div` 和 `divu` 就夠了，沒有 `divsu`。
但 `mulsu` 用於多字元有號乘法的程式碼，
把一個輸入的最高位字（含符號位元）乘上另一個輸入的其他無號字。**」**）

**這個不對稱很有意思：乘法需要 `mulhsu`，除法不需要 `divsu`——
因為它們的使用場景不同。**

### 除法的兩個特殊情況

> "**RISC-V defines results for integer division by zero and overflow. In RISC-V, division by 0 (rs2 = 0) produces a
>  result of rd = all 1s. Remainder by 0 (rs2 = 0) produces a result of rd = rs1. For example, 0x12345678/0x00000000
>  produces a quotient of 0xFFFFFFFF and a remainder of 0x12345678.**"
> — p.604

中文解釋：**除以 0 的結果，要記住：**

| 運算 | 結果 |
| --- | --- |
| **`div` / `divu` 除以 0** | **rd = 全 1（0xFFFFFFFF，即有號的 −1）** |
| **`rem` / `remu` 除以 0** | **rd = rs1（被除數本身）** |

**「餘數 = 被除數」其實很合理——
因為 `X = Q × 0 + REM` 在任何 Q 下都要求 `REM = X`。**

**溢位（p.605）：**
> "**Signed division of the largest negative number (e.g., 0x80000000) by −1 overflows because the result is larger
>  than the largest positive number (e.g., 0x7FFFFFFF). RISC-V defines the result to be the largest negative number.
>  For example, signed division of 0x80000000/0xFFFFFFFF produces a quotient of 0x80000000 and remainder of
>  0x00000000.**"

**唯一的溢位情況：最負數 ÷ (−1)。**
（因為二補數的範圍不對稱：−2^31 的相反數 +2^31 超出範圍。）

**結果定義為「最負數本身」（0x80000000），餘數為 0。**

**最重要的一點（p.605）：**
> "**RISC-V does not trigger hardware exceptions for either of these cases because no arithmetic instructions cause
>  exceptions. The programmer or compiler can test for division by 0 with `beq rs2, zero, div0_error_handler` before
>  performing the divide.**"

**「沒有任何算術指令會造成例外」——這是 RISC-V 的一個設計原則。**

**好處：簡化硬體（不用在除法器裡加 trap 邏輯）和 pipeline（算術指令永遠不 trap）。
代價：程式設計師要自己檢查。**

（對照 x86：整數除以 0 會觸發例外。）

### 沒有 M 擴充要花多少：195 條指令

> "**When the M extension is not supported, RISC-V performs multiplication and division in software. For example,
>  Code Example 15.1 shows how `a * b` for RV32I compiles into a call to the libgcc `__mulsi3` function.
>  The function may take up to 195 instructions, so it is far slower than hardware multiplication.**"
> — p.605

中文解釋：**Code Example 15.1（p.605）的組語值得看，因為它就是 15.1.3 節說的
「用移位和加法做乘法」的軟體版：**

```asm
__mulsi3:
    mv   a2, a0       # Save a in a2
    li   a0, 0        # Init result = 0 in a0
.L1:
    andi a3, a1, 1    # Get lsb of b
    beqz a3, .L2      # If lsb = 0, skip
    add  a0, a0, a2   # Else result += a
.L2:
    srli a1, a1, 1    # b = b >> 1
    slli a2, a2, 1    # a = a << 1
    bnez a1, .L1      # Repeat while b != 0
    ret
```

**對應的 C 程式碼（p.605）：**
```c
int mul(int a, int b) {
  int b0, result = 0;
  do {
    b0 = b & 0x1;
    if (b0) result += a;
    b = b >> 1;   // Logical shift
    a = a << 1;
  } while (b);
  return result;
}
```

**這就是「一次處理一個 bit」的 radix-2 乘法**——
和 15.1.3 節的硬體 array multiplier 做的是同一件事，
**只是硬體一個週期做完，軟體要跑 195 條指令。**

**「195 條指令」這個數字量化了 M 擴充的價值。**

**（除法函式庫在 github.com/gcc-mirror/gcc/blob/master/libgcc/config/riscv/div.S，p.606。）**

### Zmmul：只要乘法

> "**RISC-V defines an optional extension Zmmul, which contains all of the multiply instructions but none of the divide
>  or remainder instructions. It is intended for embedded processors that need fast multiplication but rarely use
>  division. Zmmul saves hardware and simplifies the pipeline control by eliminating the multicycle divider.
>  The M extension implies Zmmul.**"
> — p.606

中文解釋：**Zmmul 的動機和效益：**

| 面向 | 效益 |
| --- | --- |
| **使用頻率** | **嵌入式處理器需要快速乘法，但很少用除法** |
| **硬體** | **省掉除法器** |
| **Pipeline 控制** | **簡化——因為除法器是多週期的** |

**第二個效益（簡化 pipeline 控制）比第一個（省面積）更值得注意**——
**多週期的除法器需要 stall 邏輯、FSM、busy 訊號（15.4.4 節），
拿掉它能省下不少複雜度。**

**「M 擴充蘊含 Zmmul」——所以 Zmmul 是 M 的真子集。**

## 名詞表

| 名詞 | 意思 |
| --- | --- |
| `mul` / `mulh` / `mulhu` / `mulhsu` | 低 XLEN bits / 高 XLEN bits 的有號、無號、有號×無號 |
| `mulw` / `divw` / `divuw` / `remw` / `remuw` | RV64M 的 32-bit 字運算，結果符號延伸 |
| **除以 0** | **`div` → 全 1；`rem` → rs1（被除數）** |
| **有號除法溢位** | **最負數 ÷ (−1) → 商 = 最負數、餘數 = 0** |
| **無算術例外** | **RISC-V 的算術指令永遠不 trap**；要自己檢查除以 0 |
| `__mulsi3` | libgcc 的軟體乘法函式，**最多 195 條指令** |
| **Zmmul** | 只有乘法沒有除法的擴充；**省硬體並簡化 pipeline 控制** |

## 所以呢

**這節的四個實用要點：**

1. **除以 0 的定義值得記**：
   **`div` 得到全 1（−1），`rem` 得到被除數本身。**
   **溢位只有一種情況：最負數 ÷ (−1)。**

2. **RISC-V 的算術指令永遠不拋例外**——
   這簡化了硬體和 pipeline，代價是程式要自己檢查。

3. **沒有 M 擴充時，一次乘法要跑最多 195 條指令**——
   這是 M 擴充價值的量化。

4. **Zmmul 的價值不只是省面積**——
   **拿掉多週期的除法器也簡化了 pipeline 控制。**
