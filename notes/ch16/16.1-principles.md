## 關鍵點

### 為什麼需要標準

> "**Early mainframe and minicomputers used a chaotic soup of idiosyncratic vendor-specific floating-point formats
>  [Beebe17]. The Institute for Electrical and Electronic Engineers (IEEE) standardized floating-point arithmetic in
>  1985, facilitating vendor-independent numerical programming [Severance98].**"
> — p.617

中文解釋：**「一鍋各廠商自訂格式的混沌濃湯」——這個描述很傳神。**
**IEEE 754（1985）的價值是讓數值程式能跨廠商移植。**

**演進（p.618）：**

| 版本 | 加了什麼 |
| --- | --- |
| **1985** | 單精度、雙精度 |
| **2008** | **FMA（fused multiply-add）**、半精度與四倍精度、十進位浮點 |
| **2019** | 八倍精度等小幅擴充 |

**FMA 的價值（p.618）：**
> "**The 2008 version of the IEEE 754 standard added fused multiply-add (FMA), which is faster and more accurate by
>  avoiding rounding between the two steps (multiply and add).**"

**「避免兩步之間的捨入」——這既快又準。**
（p.625 邊欄補充：**「大多數數值演算法，包括矩陣乘法和濾波，都涉及乘法後接加法。
一步算完再捨入，比乘、捨入、加、再捨入，更快也更準確。」**）

**（p.617 邊欄的實務警告：**「IEEE 754 標準異常難讀。本節總結一般概念。
**追查隱晦的浮點 bug 時，你可能需要翻標準來釐清。**」**）

### Table 16.1：五種格式（全章最該記的表）

> "**Binary floating-point numbers are normally written in the following form:
>  (−1)^s × (1.f) × 2^{(e−bias)}**"
> — Eq. (16.1), p.618

中文解釋：**三個欄位：sign（s）、biased exponent（e）、fraction（f）。**

**「隱藏的 1」（p.618）：**
> "**Because normalized numbers always have a leading 1 before the fraction, this 1 is not stored in the binary
>  representation. This leading 1 is sometimes called the "hidden 1." The (1.f) term is called the *normal
>  significand*, or simply the *significand* and will be abbreviated m. m has 1 integer bit and N_f fraction bits.**"

**用 bias 而非二補數的理由（p.618 邊欄）——這個設計決定很聰明：**
> "**It may seem odd to use biased exponents rather than two's complement representation for exponents. This approach
>  has been widespread since the 1960s because it allows programs to compare floating-point numbers using ordinary
>  integer comparison [Beebe17]. With a biased exponent representation, larger floating-point numbers have larger
>  values when their bit patterns are treated as signed integers.**"

**「用整數比較就能比較浮點數」——這是 bias 表示法的價值。**

**Table 16.1（p.618）：**

| Name | Common Name | N_f | N_e | **bias** | e_min | e_max | Range | 十進位精度 |
| --- | --- | --- | --- | --- | --- | --- | --- | --- |
| binary16 | **half** | **10** | **5** | **15** | −14 | 15 | ±10⁴ | **3** |
| binary32 | **float/single** | **23** | **8** | **127** | −126 | 127 | ±10³⁸ | **7** |
| binary64 | **double** | **52** | **11** | **1,023** | −1,022 | 1,023 | ±10³⁰⁸ | **16** |
| binary128 | quad | 112 | 15 | 16,383 | −16,382 | 16,383 | ±10⁴⁹³² | 34 |
| binary256 | octuple/oct | 236 | 19 | 262,143 | −262,142 | 262,143 | ±10⁷⁸⁹¹³ | 71 |

**三個關係要記住：**
- **`bias` = 2^{N_e−1} − 1**（例如單精度 2⁷ − 1 = 127）
- **`e_max` = bias、`e_min` = 1 − bias**
- **全 0 和全 1 的 biased exponent 保留給特殊情況**

**（p.619 邊欄的有趣註記：**「雙精度有 53 bit 或 log₁₀(2⁵³) ≈ 16 位十進位精度。
**這足以數出從地球排到月球再回來的病毒粒子數量。
能表示的最大數約 2^1024 ≈ 10^308。**」**）

**（p.618 邊欄：**「有些架構，特別是 x86，支援 **80-bit 的 double extended precision** 格式。」**）

**Example 16.1（p.619）：把 −9.625 寫成單精度**
```
負數 → sign = 1
9.625 = 1001.101₂ = 1.001101 × 2³
biased exponent = 3 + 127 = 130 = 10000010₂
去掉隱含的 1 → fraction = 001101
→ 0xC11A0000
```

**Example 16.2（p.619）：把 0x3FDB000000000000 轉回十進位**
```
sign = 0（正）
biased exponent = 1021 → 真實指數 = 1021 − 1023 = −2
fraction = 1011
→ 1.1011 × 2⁻² = 11011 × 2⁻⁶ = 27/64 = 0.421875
```

### Table 16.2：四種特殊情況

> "**The IEEE floating-point standard defines some special cases, encoded with the largest or smallest value in the
>  biased exponent field, as shown in Table 16.2. All the other floating-point numbers are referred to as *normalized*
>  and have a biased exponent that is not all zeros or ones.**"
> — p.620

中文解釋：**Table 16.2（p.620）——這張表要背：**

| Sign | Biased Exponent | Fraction | Special Case |
| --- | --- | --- | --- |
| 0 | **全 0** | 全 0 | **+0** |
| 1 | **全 0** | 全 0 | **−0** |
| any | **全 0** | **非 0** | **Subnormal** |
| 0 | **全 1** | 全 0 | **+∞** |
| 1 | **全 1** | 全 0 | **−∞** |
| any | **全 1** | **非 0** | **NaN** |

**記憶方式：`exponent 全 0` = 很小（零或 subnormal）、
`exponent 全 1` = 很大或無意義（無限大或 NaN）；
`fraction` 是否為 0 決定是哪一種。**

### 零與無限大

**零（p.620）：**
> "**Because IEEE 754 floating-point numbers technically use a sign-magnitude format, representations of both positive
>  and negative zero exist. −0 occurs when a very small negative number is rounded to zero. Comparisons ignore the sign
>  of zero, so +0 and −0 are considered equal. Note that +0 is conveniently written with all zeros.**"

**「+0 剛好是全 0」——所以清零記憶體就自然得到 +0。**

**無限大（p.620）：產生的四種方式：**
- **溢位**（有限運算元產生很大的結果）
- **除以零**
- **`log(0)` 或很大正數的指數**
- **大多數以無限大為輸入的運算**

**具體編碼：半、單、雙精度的 +∞ 分別是 0x7C00、0x7F800000、0x7FF0000000000000。**

### NaN

> "**Not a Number (NaN) indicates a result that has no other sensible answer. For example, 0/0 or √−1 produces NaN.**"
> — p.621

中文解釋：**產生 NaN 的三類運算（p.621）：**

| 類別 | 例子 |
| --- | --- |
| **不定形式** | **0 × ∞、0/0 或 ∞/∞、x % y（x 為 ∞ 或 y 為 0）、∞ − ∞** |
| **結果為複數的實數運算** | **負數開平方根、負數取對數、超出 [−1,1] 的反正弦/餘弦** |
| **至少一個 NaN 輸入的運算** | — |

**qNaN vs sNaN（p.621）：**
> "**The nonzero fraction in the NaN is called its *payload* and can carry implementation-specific information about the
>  cause of the NaN. NaNs are also classified as *quiet* (qNaN) or *signaling* (sNaN). Operations on sNaNs trigger an
>  invalid operation exception even if the result is not NaN. Thus, a program may set uninitialized variables to a sNaN
>  value to detect if they are accidentally used. Unfortunately, the encoding of sNaNs is also
>  implementation-specific, making them hard to use in portable code. Operations producing a NaN, such as those listed
>  above, deliver a qNaN.**"

**sNaN 的巧妙用途：「把未初始化的變數設成 sNaN，
這樣意外使用它們時就會被偵測到」**——和 3.3.10 節 `0xdeadbeef` 同一個思路。

**但 sNaN 的編碼是實作相關的，所以難以在可攜程式中使用。**

**（p.621 邊欄：**「**fraction 欄位的 msb 為 1 表示 quiet NaN，0 表示 signaling NaN。
產生 NaN 的 RISC-V 指令產生 *canonical NaN*，它的 fraction msb 設起、其他 fraction 位元清零。**」**）

### Subnormal：最有爭議的部分

> "***Subnormal* numbers, also called *subnorms*, are very small positive or negative numbers. They fill the *underflow
>  gap* below the smallest positive and smallest negative normalized numbers. Their true exponent is always e_min, but
>  they have no implicit leading 1 before the fraction.**"
> — p.621

中文解釋：**Subnormal 的兩個特徵：真實指數固定為 e_min、沒有隱含的 1。**

**例子（p.621）：單精度的 0x00300000**
```
exponent 欄位 = 0 → subnormal
fraction = 01100…00
→ 0.0110…00 × 2⁻¹²⁶ = 3 × 2⁻¹²⁹
```

**為什麼需要 subnormal（p.621）——這個例子很有說服力：**
> "**Numerical analysts find that subnormal numbers make it easier to write robust, stable numerical software
>  [Coonen81]. For example, consider the following code to avoid division by zero:
>  `if (a ≠ b) y = 1/(a−b);`
>  If (a−b) is smaller than the smallest normalized number and subnorms don't exist, (a−b) will be truncated to 0 and
>  cause a division by zero error despite the check. Subnormal numbers provide *gradual underflow*; loss of precision
>  occurs slowly for tiny numbers.**"

**「即使檢查了 a ≠ b，沒有 subnormal 的話 (a−b) 仍可能變成 0」——
這就是 gradual underflow（漸進下溢）存在的理由。**

**（p.621 邊欄的現實：**「**Subnormal 是 IEEE 754 規格中最有爭議的部分，
因為它們最難實作，而且增加 FPU 的成本和延遲。
因此它們有時用軟體實作，而那會在它們出現時降低效能。**」**）

**Subnormal vs denormalized（p.622）：**
> "**Like subnormal numbers, *denormalized* numbers have a leading 0 in the significand, but unlike subnormal numbers,
>  they have an arbitrary exponent. Subnormal numbers are denormalized numbers with a true exponent of e_min....
>  The original IEEE 754 standard used denormal to refer to such numbers, but the 2008 revision of the specification
>  switched to the more proper term *subnormal*. The literature still has a mix of the two terms.**"

**「denormalized」是較廣的概念，「subnormal」是其中指數為 e_min 的那些。**

### 五種捨入模式

> "**The result of floating-point arithmetic may not be exactly represented with the precision available and must be
>  rounded to a representable value. IEEE 754 defines five rounding modes.**"
> — p.622

中文解釋：**五種模式與各自的用途：**

| 模式 | 全名 | 用途 |
| --- | --- | --- |
| **RNE** | **Round to nearest even** | **預設；也叫 unbiased rounding，避免系統性偏差，維持平均零誤差** |
| **RNTA** | Round to nearest ties away | **某些金融計算法律要求**（如歐元換算）；也叫 RNM |
| **RZ** | Round toward zero | 截斷（truncation） |
| **RN** | Round toward −∞ | **interval arithmetic** |
| **RP** | Round toward +∞ | 同上 |

**RNE 為什麼是預設（p.622）：**
> "**It rounds to the closest representable value. If two values are equally close (a "tie"), it rounds to the even
>  value. This is also called *unbiased rounding* because it avoids introducing systematic errors by rounding up or down
>  on a tie. Thus, it maintains an average zero error in computation.**"

**「平手時捨入到偶數」——這避免了「總是向上」造成的系統性偏差。**

**Interval arithmetic（p.622）：**
> "**They can be used to perform *interval arithmetic* [IEEE1788.1-2017].... a computation is repeated with both
>  rounding modes; thus, the true answer is guaranteed to lie in an interval between an upper and lower bound.
>  If the interval is small, the program knows that the answer is close to exact.... If the interval is large, the
>  program can detect numerical instability.**"

**「用兩種方向的捨入各算一次，真答案保證在區間內」——這是偵測數值不穩定的方法。**

### 捨入的三種結果與 ulp

> "**Rounding is performed by computing the exact result and then picking the appropriate representable result.
>  The rounded result may be one of the following:
>  - **TRUNC:** The result with the fraction truncated to the number of bits in the floating-point representation.
>  - **RND:** TRUNC plus 1 in the least significant bit of the representable fraction....
>  - **MAXNUM or ∞:** For results that overflow before rounding.**"
> — p.623

中文解釋：**`MAXNUM` = 最大的正規化數（1.1111…111 × 2^{e_max}）。**
**溢位時依捨入模式得到 ±∞ 或 ±MAXNUM**（p.623）：
**「RZ 把很大的正數捨入到 MAXNUM，而 RP 捨入到 ∞」。**

**ulp 的定義（p.623）：**
> "**The 1 in the least significant bit is known as an *ulp* (*unit in the last place*, rhymes with *gulp*).
>  Informally, for any real number x, ulp(x) is the gap between the two closest finite floating-point numbers
>  straddling x.... ulp is helpful to reason about rounding error without getting bogged down in exponent or precision.
>  Whereas rounding to nearest produces an error no more than ½ ulp, the other rounding modes produce an error of no
>  more than 1 ulp.**"

**兩個誤差界限要記住：**
- **Round to nearest：誤差 ≤ ½ ulp**
- **其他模式：誤差 ≤ 1 ulp**

**Example 16.3（p.623）：半精度的 x = 2.125，求 ulp(x)**
```
x = 2.125 × 2⁰ = 1.0625 × 2¹ = 1.0001000000 × 2¹
半精度有 10 個 fraction bit
前一個數 a = 1.0000111111 × 2¹
ulp(2.125) = b − a = 0.0000000001 × 2¹ = 2⁻⁹
```

### GRS：三個捨入位元（本節最重要的技術內容）

> "**Computing the exact result is troublesome, especially because division and square root can have an infinite number
>  of bits in the exact result (e.g., for 1/3 or √2). Fortunately, rounding can be performed using only the N_f fraction
>  bits and three additional bits: the *guard* (G), *rounding* (R), and *sticky* (T) bits. L is the least significant
>  bit (lsb) of the N_f fraction bits of the exact result (TRUNC). G is the next bit of the exact result followed by the
>  *rounding* bit R and the *sticky* bit T, which is 1 if any of the remaining bits are nonzero (i.e., T is the OR of
>  all the remaining bits of the exact result). Together, G, R, and T are called the *rounding bits*.**"
> — p.623

中文解釋：**這是浮點硬體的關鍵簡化：**

**「無限多位元的精確結果，只需要保留 N_f + 3 個位元就能正確捨入」。**

```
精確結果： [───── N_f 個 fraction bit ─────][L][G][R][T...T]
                                            └─┬─┘ └┬┘ └──┬──┘
                                        lsb  guard round  sticky
                                                          （其餘所有位元的 OR）
```

| 位元 | 意義 |
| --- | --- |
| **L** | 可表示的 fraction 的最低位元 |
| **G**（guard） | 下一個位元 |
| **R**（round） | 再下一個位元 |
| **T**（sticky） | **其餘所有位元的 OR** |

**Example 16.4（p.624）的完整計算：**
```
1.1111 1111 11 × 2⁵ + 1.0000 0001 10 × 2¹
第二個數右移 (5−1) = 4 位對齊指數
  1.1111 1111 11      × 2⁵
+ 0.0001 0000 0001 10 × 2⁵
─────────────────────────
 10.0000 1111 1101 10 × 2⁵
= 1.0000 0111 1100 110 × 2⁶   （正規化）
   └── 10 個 fraction bit ──┘└┬┘└┬┘
                        L=1  G=0 R=0, T=OR(1,1,0)=1
```

**Table 16.3（p.624）——正規化移位對 GRS 的影響：**

| Normalization Shift | **L'** | **R'** | **T'** |
| --- | --- | --- | --- |
| **No** | **L** | **G** | **R \| T** |
| **Yes** | **G** | **R** | **T** |

**為什麼需要這張表（p.624）：**
> "**Dividing two numbers in the range [1, 2) produces a quotient in the range (1/2, 2). If this quotient is less than
>  1, it requires a left normalization shift by one bit to bring it back into the range [1, 2). This moves G into the
>  least significant fraction bit. The guard bit hence guards against a loss of precision.**"

**「guard bit 防止精度損失」——這就是它名字的由來。**
**左移一位時，G 移進最低位，所以有效的 lsb 變成 G、捨入位元變成 R、sticky 變成 T。**

### Table 16.4：完整的捨入決策表

> "**The rounding decision must be made based on the rounding mode, the sign, the overflow flag, and the L', R', and T'
>  bits, according to Table 16.4.**"
> — p.624

中文解釋：**Table 16.4（p.625）的關鍵列。以正數（Sign = 0、Overflow = 0）為例：**

| L' | R' | T' | **RNE** | RNTA | **RZ** | **RP** | RN |
| --- | --- | --- | --- | --- | --- | --- | --- |
| x | 0 | 0 | TRUNC | TRUNC | TRUNC | TRUNC | TRUNC |
| x | 0 | 1 | TRUNC | TRUNC | TRUNC | **RND** | TRUNC |
| 0 | 1 | 0 | **TRUNC** | **RND** | TRUNC | RND | TRUNC |
| **1** | **1** | **0** | **RND** | RND | TRUNC | RND | TRUNC |
| x | 1 | 1 | **RND** | RND | TRUNC | RND | TRUNC |
| x | x | x（**Overflow = 1**） | **+∞** | +∞ | **+MAXNUM** | +∞ | **+MAXNUM** |

**RNE 的規則濃縮成一個公式（p.625）：**
> "**RNE rounds down when the R' bit is 0 and rounds up when the R' and T' bits are 1. When only the R' bit is 1, the
>  number is exactly halfway between two representable values, and RNE rounds to an even value by rounding up if
>  L' = 1 and rounding down if L' = 0. Hence, **RNE rounds up for R' & (L' | T')**.**"

**`RNE 進位 = R' & (L' | T')`——一行布林式。**

**其他模式的規則（p.624）：**
- **RZ 永遠截斷**，溢位時捨入到 MAXNUM
- **RP：截斷負數；正數只要結果不精確（R' 或 T' 為 1）就進位**
- **RN：相反**

**Example 16.5（p.625）：接續 Example 16.4，L=1, G=0, R=0, T=1，不需正規化移位
→ L'=L=1、R'=G=0、T'=R|T=1。
查表：RNE → TRUNC = 1.0000 0111 11；RP → RND = 1.0000 1000 00。**

**Example 16.6（p.625–626）：0x4010 × 0x4420（半精度）的完整計算，
展示了同一個精確結果在五種模式下的四種不同答案：**
```
0x4010 = 1.000001 × 2¹
0x4420 = 1.00001 × 2²
精確積 = 1.0000 1100 001 × 2³
半精度只有 10 個 fraction bit → L=0, G=1, R=0, T=0
無移位 → L'=0, R'=G=1, T'=R|T=0
→ 這是恰好的平手（tie）
RNE  → TRUNC = 0x4830  （捨入到偶數）
RNTA → RND   = 0x4831  （平手向上）
RZ   → TRUNC = 0x4830
RN   → TRUNC = 0x4830
RP   → RND   = 0x4831
```

**（p.626 邊欄的 Table Maker's Dilemma：**
「對於三角函數、對數等函數，**難以找到捨入所需的精確結果。
例如精確結果非常接近兩個可表示值的中間時，可能需要無限量的計算
才能決定它是略高還是略低於邊界。這叫 *Table Maker's Dilemma*。**
精確捨入不切實際時，函式可以任意挑 TRUNC 或 RND 其中一個可表示值。
**這叫 *faithful result*，和正確結果最多差一個 ulp。**」**）

### 五種旗標

> "**The IEEE 754 standard defines five types of exceptions that must be signaled by setting a status flag or taking a
>  trap whenever they arise: Invalid, Division by Zero, Overflow, Inexact, and Underflow. Invalid, Division by Zero, and
>  Underflow are never raised when Overflow is raised or when any of the inputs are NaN or INF. The Overflow and
>  Underflow flags depend on the *intermediate result* obtained by rounding the exact answer to the specified precision
>  but with an unbounded exponent.**"
> — p.626

中文解釋：**「intermediate result」這個概念很關鍵：
把精確答案捨入到指定精度，但指數範圍不受限。**
**Overflow 和 Underflow 旗標都是依它判斷的。**

**Invalid 的完整清單（p.626）：**
- **sNaN 上的運算**
- **0 × ∞ 或 ∞ × 0**（RISC-V 中 ∞ × 0 + qNaN 也設 Invalid）
- **0/0 或 ∞/∞**
- `rem(x, y)`（y = 0 或 x = ∞ 但都不是 NaN）
- **負數開平方根**
- **兩個無限大的有效減法**（∞ − ∞）
- **浮點轉整數時輸入是 NaN、∞、或超出整數範圍**
- **NaN 的比較（< 或 ≤）**
- `log(x)`（x 是 NaN、∞ 或 0）
- 超出 [−1, 1] 的反正弦/餘弦

**Division by zero（p.627）：非零有限數除以零、`log(0)`。**

**Overflow（p.627）：**
```
Overflow = I_e > e_max        （16.2）
```
**（p.627 邊欄：**「**即使答案不是無限大也可能設 Overflow。**
例如半精度的 0x7800 + 0x7800 = 1.0 × 2¹⁵ + 1.0 × 2¹⁵，
中間結果是 1.0 × 2¹⁶。依捨入模式會變成 ∞ 或 MAXNUM，
**但兩種情況下 Overflow 旗標都會設。**」**）

**Inexact（p.627）：**
```
Inexact = R' | T' | Overflow   （16.3）
```
**「捨入後的結果和無限精度下的結果不同」。**

**Underflow（p.627）——最微妙的：**
```
Underflow = (I_e < e_min) & Inexact   （16.4）
```
> "**If the result is *tiny* and a loss of accuracy occurs. A result is considered tiny when it is subnormal
>  (|result| < 2^{e_min}). A loss of accuracy occurs when the Inexact flag is set.... The IEEE 754 specification has an
>  ambiguity that tininess may be detected either before rounding or after rounding to an intermediate result; not all
>  implementations set this flag in the same way. **RISC-V detects tininess after rounding the exact answer to the
>  intermediate result with bounded precision but unlimited exponent range.** Note that underflow is signaled when a
>  very small result is rounded to zero but not when the exact result is zero.**"

**Underflow 需要「tiny」**和**「不精確」**兩個條件同時成立。**

**（p.628 的四個例子值得看，它們展示了 Underflow 的微妙之處：**
- **`0x0000 + 0x0400 = 0.0 + 0.1 × 2⁻¹⁴`**：tiny **但精確** → **不設 Underflow**
- **`0x0800 × 0x0800 = 1.0 × 2⁻²⁶`**：**捨入到 0.0 或 MINNUM → 不精確 → 設 Underflow**
- **`0x07FE × 0x3400 + 0x0200`**：中間結果能精確表示（指數無限制），
  **但實際指數範圍有限，在 RNE 下捨入到 1.0 × 2⁻¹⁴。
  結果不精確且 tiny，所以設 Underflow——即使最終結果是正規化的！**
- **`0x07FF × 0x3400 + 0x0200`**：RNE 下捨入到 1.0 × 2⁻¹⁴，不 tiny → **不設 Underflow**；
  **但 RZ 下捨入到 0.1111 1111 11 × 2⁻¹⁴，tiny 且不精確 → 設 Underflow**）

**最後一個例子最能說明問題：同一個運算，不同捨入模式下 Underflow 旗標不同。**

**（p.628 邊欄的實務技巧：**「有些演算法刻意避免上溢/下溢。
例如計算向量長度 √(x² + y²) 時，直接實作在任一輸入很大或很小時會上溢或下溢。
**函式可以檢查是否有旗標被設，若有則用 `x√(1 + (y/x)²)`（x > y 時）重算。
這種替代計算避免不必要的上溢/下溢，但更耗時且需要額外程式碼。**」**）

### 定點表示法（後面章節一直用）

> "**Floating-point hardware uses fixed-point arithmetic internally to operate on the significand. To keep track of the
>  number of integer and fraction bits and whether the number is signed or unsigned, we use the Q and U formats.
>  U*a.b* indicates an unsigned fixed-point number with a integer bits and b fraction bits. Q*a.b* indicates a two's
>  complement signed number with a integer bits and b fraction bits. In this chapter, we also use U*a*, Q*a*, and
>  B^b*a* to indicate unsigned, two's complement signed, and biased integers with a bits and a bias of b.**"
> — p.628–629

中文解釋：**四種記號，讀後面的浮點章節必備：**

| 記號 | 意義 |
| --- | --- |
| **U*a.b*** | **無號定點：a 個整數位元、b 個小數位元** |
| **Q*a.b*** | **二補數有號定點** |
| **U*a* / Q*a*** | a 位元的無號 / 有號整數 |
| **B^b*a*** | **a 位元、bias 為 b 的偏置整數** |

**Table 16.5（p.629）的例子，位元樣式 `10111`：**

| Format | Interpretation | Value |
| --- | --- | --- |
| **U3.2** | 2² + 2⁰ + 2⁻¹ + 2⁻² | **5.750** |
| **U2.3** | 2¹ + 2⁻¹ + 2⁻² + 2⁻³ | **2.875** |
| **Q2.3** | **−2¹** + 2⁻¹ + 2⁻² + 2⁻³ | **−1.125** |
| **U5** | 2⁴ + 2² + 2¹ + 2⁰ | **23** |
| **Q5** | **−2⁴** + 2² + 2¹ + 2⁰ | **−9** |
| **B¹⁵5** | 2⁴ + 2² + 2¹ + 2⁰ **− 15** | **8** |

**運算的位元數規則（p.629）——這幾條後面會用到：**

| 運算 | 結果格式 |
| --- | --- |
| **U*a.b* 的範圍** | **[0, 2^a)** |
| **Q*a.b* 的範圍** | **[−2^{a−1}, 2^{a−1})** |
| **加法**（a 和 c 個整數位元） | **max(a, c) + 1 個整數位元** |
| **U*a.b* × U*c.d*** | **U(a+c).(b+d)** |
| **Q*a.b* × Q*c.d*** | **Q(a+c−1).(b+d)** |

**「有號乘積比無號少一個整數位元，因為有號數的範圍較小」**（p.629）。

**（p.629 邊欄：**「定點數常用於應用特定運算，如訊號處理和機器學習，
那裡低功耗和便宜的大規模平行硬體比精度重要。
**例如 Q1.15 格式用來表示 ±1 之間的正規化數字，
這很方便因為這種數字相乘後仍在同樣範圍。
但兩個 Q1.15 數的乘積常用 Q1.31 表示以保持精度。**」**）

## 所以呢

**這節是浮點硬體的完整基礎。五件最該帶走的事：**

1. **Table 16.1 和 Table 16.2 要背**：
   **格式參數（bias = 2^{N_e−1} − 1）和四種特殊情況的編碼。**

2. **GRS 三個位元是浮點硬體的關鍵簡化**：
   **無限多位元的精確結果，只要保留 N_f + 3 個位元就能正確捨入。**
   而 **sticky bit 是「其餘所有位元的 OR」**。

3. **RNE 的進位條件是一行布林式：`R' & (L' | T')`。**

4. **Underflow 是最微妙的旗標**：
   **要同時「tiny」（< 2^{e_min}）和「Inexact」才設。**
   同一個運算在不同捨入模式下，Underflow 旗標可能不同。

5. **Ua.b / Qa.b 記號是讀後面浮點章節的必備工具**，
   特別是乘法的位元數規則：**Q*a.b* × Q*c.d* = Q(a+c−1).(b+d)**。

**還有一個貫穿的觀念：subnormal 是最有爭議的功能——
它讓數值軟體更穩健（gradual underflow），但也是 FPU 最難實作、最貴的部分。**
