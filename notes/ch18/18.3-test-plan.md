# 18.3 Test Plan

> 原書 p.748–749（Chapter 18: Extensions: Zb* & Zk* (Bit Manipulation and Cryptography)）

## 這節在講什麼

極短的一節。位元操作與密碼學指令都用 riscv-arch-test 測，產生方式和第 7 章那套隨機測試一樣。重點是 Table 18.10 與 18.11 的測試數量，能看出哪些指令被認為風險較高。

## 關鍵點

### 測試方法沿用既有框架

> "The bit manipulation and cryptographic instructions are tested with the riscv-arch-test suite. The configuration files to generate these random tests are similar to the one described in Section 7.4. Tables 18.10 and 18.11 list the number of test cases for each instruction."
> — p.748

中文解釋：不需要新的驗證方法。這些指令的特性是**輸入輸出都是純組合邏輯、無狀態、單週期**——給隨機運算元、比對預期結果就夠了。這和第 16 章浮點需要專屬 testbench、第 17 章原子指令需要製造預約失效的情境，是完全不同的難度等級。

### 測試數量反映的資訊

> Table 18.10 riscv-arch-test for Zb* extensions ... Total 9,151 (RV32B) / 17,137 (RV64B)
> — p.749

> Table 18.11 riscv-arch-test for Zk* extensions ... Total 3,639 (RV32Zk) / 4,595 (RV64Zk)
> — p.749

中文解釋：幾個值得注意的分布：
- **Zb\* 的測試量是 Zk\* 的兩倍多**。因為 Zb* 指令數量多，而且 `max`/`min`/`xnor`/`orn`/`sh*add` 這類每個都有 500–720 個測試——它們是通用運算，運算元空間大。
- **移位量固定的指令測試較少**。`clz`/`cpop`/`ctz` 只有 68（RV32）/132（RV64）個，因為輸出空間本來就只有 0~XLEN。
- **AES 指令的測試出奇地少**。`aes64es`/`aes64esm`/`aes64ds`/`aes64dsm` 各只有 57 個。原因是它們的行為完全由查表和固定置換決定，沒有需要大量隨機探索的邊界條件；而 `aes32*` 系列有 281 個，是因為多了 2 位元的 byte-select 欄位要窮舉。
- **`aes64ks2` 有 280 個、`aes64ks1i` 有 86 個**。key scheduling 的 round constant 要逐一測到。
- **RV32 與 RV64 的欄位互補**。Table 18.11 裡 `aes32*` 只有 RV32 欄有值、`aes64*` 只有 RV64 欄有值、`sha512sig0h/l` 這類拆半指令只存在於 RV32——這張表直接反映了 18.2.7 講的 RV32/RV64 策略分歧。
