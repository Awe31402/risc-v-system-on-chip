## 關鍵點

### 匯流排的通用原理

> "**A bus interface provides a standardized way for a system to communicate with external memory or
>  peripherals. Modern on-chip buses normally use synchronous point-to-point links between a controller and
>  one or more peripherals. The controller generates a clock signal and sends an address and some control
>  information to each peripheral. During a write operation, the controller also sends the write data.
>  During a read operation, the peripheral responds with the read data. The peripheral may insert wait
>  states if it needs longer to respond. Because of the point-to-point links, the controller uses a read
>  multiplexer to choose the read data from the selected peripheral.**"
> — p.427

中文解釋：**這段把現代晶片內匯流排的五個標準做法一次列完：**

| 特性 | 為什麼 |
| --- | --- |
| **同步（synchronous）** | 實作簡單；周邊需要位址在時脈邊緣前 setup（9.1 節） |
| **點對點（point-to-point）** | **共享匯流排在 SoC 上有延遲建模、競爭驗證、缺 repeater 的問題**（9.1.3 節） |
| **控制器產生時脈、送位址和控制訊號** | — |
| **周邊可以插入 wait state** | 不是所有周邊都能一個週期回應（9.1.2 節的 handshaking） |
| **用讀取多工器選出被選中周邊的資料** | **點對點的必然結果**（9.1.3 節 Fig. 9.5b） |

**「因為是點對點連結，所以需要讀取多工器」——
這個因果關係要記住：不用 tristate 共享，就得用多工器選。**

### 高效能匯流排的三個特性

> "**High-performance buses are normally pipelined to overlap consecutive accesses. They support features
>  such as burst and subword transfers and bus locking for atomic operations. Many bus protocols are used in
>  industry, so a bridge is often needed to adapt between protocols.**"
> — p.427

中文解釋：**三個特性各對應一個需求：**

| 特性 | 解決什麼 |
| --- | --- |
| **Pipeline（重疊連續存取）** | **吞吐量**（AHB 因此約為 APB 的兩倍，9.2.2 節） |
| **Burst 與 subword 傳輸** | **Burst 減少重複仲裁開銷、配合 DRAM 的 page 特性；subword 讓部分寫入可行** |
| **Bus locking** | **原子操作**（第 17 章） |

**最後那句是實務現實：業界有很多匯流排協定，所以常需要 bridge。**
（呼應 9.2 節的 AHB-to-APB bridge，以及 9.3 節那些各家的匯流排。）

### Wally 的實作

> "**Wally uses an EBU to connect the IFU and LSU to a single AHB bus so they can access peripherals and
>  external memory, beyond the capacity of an IROM or DTIM. When both the IFU and LSU want to use the bus at
>  the same time, the EBU grants priority to the LSU so the pipeline can make forward progress.**"
> — p.427

中文解釋：**EBU 的兩個要點：**
1. **目的**：讓 IFU 和 LSU 能存取超出 IROM/DTIM 容量的周邊和外部記憶體
2. **仲裁**：**LSU 優先，「so the pipeline can make forward progress」**

**注意這裡的理由措辭：「讓 pipeline 能往前推進」**——
呼應 9.5.2 節說的 deadlock 問題。
**LSU 在 Memory 級，如果它一直拿不到匯流排，前面的級全部卡住，
而 IFU 抓再多指令也沒用。**

### 多週期傳輸帶來的互鎖需求

> "**Bus transfers take multiple cycles and must finish once they have started, so the EBU interlocks with
>  the hazard and privileged units to stall the pipeline and prevent interrupts during in-flight transfers
>  until the transfer completes.**"
> — p.427

中文解釋：**一句話總結 9.5.5 節的整套機制。三個關鍵詞：**

| 關鍵詞 | 對應的機制 |
| --- | --- |
| **"take multiple cycles"** | **`busfsm` 的三個狀態（Adr → Data → Mem3）** |
| **"must finish once they have started"** | **`BusCommitted`：Data 階段起就不能中途放棄** |
| **"interlocks with the hazard and privileged units"** | **`BusStall` 給 hazard 單元、`Committed` 給 trap 單元** |

**「一旦開始就必須完成」是整個互鎖機制的根本原因**——
因為裝置那邊已經在動作了，中途放棄會讓狀態不一致
（尤其是 9.5.5 節邊欄提到的 nonidempotent 存取）。

## 所以呢

**第 9 章讓處理器能跟外界溝通。**

三件最該帶走的事：

1. **現代晶片內匯流排的標準做法**：
   **同步 + 點對點 + 讀取多工器 + wait state**。
   **點對點是關鍵決定**——它排除了 tristate，所以必須用多工器。

2. **AHB 的 pipeline 讓吞吐量翻倍，代價是寫入資料晚一週期**——
   這個歷史包袱造成 SRAM 介面「寫→讀」要插 wait state。

3. **匯流排交易「一旦開始就必須完成」**，
   所以需要三層互鎖：
   **`BusStall`（stall pipeline）、`BusCommitted`（延後中斷）、
   Mem3 的自環（防止重發請求）。**

**而 EBU 的 LSU 優先不是效能選擇，是防止 deadlock 的正確性要求。**
