# 5.7 Assertions

> 原書 p.214–217（Chapter 5: Design Verification）
> 含 5.7.1 Immediate Assertions、5.7.2 Concurrent Assertions

## 這節在講什麼

**SystemVerilog Assertions（SVA）：在 RTL 裡直接寫下「這個性質必須成立」。**

核心價值一句話：**在問題汙染架構狀態之前就抓到它，
所以能直接指出根本原因，而不是讓你從症狀往回推。**

兩種 assertion：
- **immediate（即時）**：檢查「此刻」的運算式。語法簡單，用途廣。
- **concurrent（並行）**：檢查**跨越多個時脈週期**的行為。功能強大但語法複雜。

## 關鍵點

### Assertion 的定位：加速除錯

> "*SystemVerilog Assertions* (SVAs) check that the RTL conforms to a specification. **They
>  warn of trouble long before it propagates to the architectural state. Thus, they speed
>  debug by pinpointing the root cause of a problem.** Some of the most common places for
>  assertions are in FIFOs (first in, first out queues), bus interfaces, and state machines.
>  Assertions are also used in functional coverage and formal verification to specify
>  properties that must be checked."
> — p.214

中文解釋：**這裡建立了一個「抓 bug 的時間軸」，值得和前兩節對照：**

| 手段 | 何時發現問題 |
| --- | --- |
| **Assertion** | **問題發生的當下，在 RTL 內部** ← 最早 |
| Lock-step-compare | 問題影響到架構狀態時（該條指令結束） |
| Signature | 一串指令跑完後 |
| 系統測試（開 Linux） | 幾百萬條指令後 |

**越早發現，除錯成本越低。** 這就是 assertion 的全部價值。

**三個最常放 assertion 的地方（很實用的指引）：**
**FIFO**（先進先出佇列）、**匯流排介面**、**狀態機**。
——共同點是：**它們都有明確的「不該發生」的狀態**
（FIFO 滿了還寫、協定違規、跳到非法狀態）。

**assertion 還有兩個延伸用途**：功能覆蓋率（5.9 節）和形式驗證（5.10 節）。

（深入教學可看 [Mehta20]，p.214。）

### Immediate assertion 的語法

> "*Immediate assertions* test an expression at the time they are executed. They are placed
>  in initial or always (always_comb/always_ff) blocks, which determines when they execute.
>  **Assertions are written so that the expression is TRUE unless there is a defect in the
>  design.**"
> — p.215

```systemverilog
assert (expression) <statement1> <else statement2>
```

中文解釋：**寫法的方向要記對：運算式為真代表「沒問題」，
為假才觸發**——和 `if` 的直覺相反。

**行為規則（p.215）：**
- `expression` 為 TRUE（1）→ 執行 `statement1`
- `expression` 為 **0、x 或 z** → 執行 `statement2`
  ← **注意 x 和 z 也算失敗**（呼應 4.2.2.3 節：x 是 bug 的訊號）
- 省略 `statement1` → 通過時保持安靜（**這是常態**）
- **省略 `else statement2` → 失敗時自動呼叫 `$error`**

### 四個嚴重等級

> "- $fatal(errcode, message)
>  - $error(message)
>  - $warning(message)
>  - $info(message)
>  Each of these statements prints the message. **$fatal also terminates the simulation** by
>  calling $finish(errcode), with the codes described in Table 5.3. **Assertions typically use
>  $error to report a violation.**"
> — p.215

中文解釋：**四個等級由重到輕：**

| 等級 | 行為 |
| --- | --- |
| **`$fatal(errcode, message)`** | 印訊息**並終止模擬**（呼叫 `$finish`） |
| **`$error(message)`** | 印訊息。**assertion 違規的標準用法** |
| `$warning(message)` | 印訊息（較輕微） |
| `$info(message)` | 印訊息（純資訊） |

**選擇準則：**
- **組態錯誤 → `$fatal`**（繼續跑也沒意義，見下面的例子）
- **執行中的違規 → `$error`**（記錄下來但繼續跑，才能一次找出多個問題）

### 實例：Wally 的組態檢查

中文解釋：Code Example 5.5（p.216）的 `riscvassertions.sv`——
**這就是 4.4 節提到的那個組態防呆模組：**

```systemverilog
module riscvassertions import cvw::*; #(parameter cvw_t P);
  initial begin
    assert (P.PMP_ENTRIES == 0 || P.PMP_ENTRIES==16 || P.PMP_ENTRIES==64)
      else $fatal(1, "Illegal number of PMP entries: PMP_ENTRIES must be 0, 16, or 64");
    assert (P.S_SUPPORTED || P.VIRTMEM_SUPPORTED == 0)
      else $fatal(1, "Virtual memory requires S mode support");
    assert (P.DCACHE_SUPPORTED || ~P.F_SUPPORTED || P.FLEN <= P.XLEN)
      else $fatal(1, "Data cache required to support FLEN > XLEN because AHB/DTIM bus width is XLEN");
    ...
  end
endmodule
```

**四個設計要點：**
1. **放在 `initial` 區塊裡，所以只在模擬一開始檢查一次**（p.215）——
   組態參數不會變，檢查一次就夠
2. **全部用 `$fatal`**——組態錯了就沒必要繼續跑
3. **錯誤訊息包含「正確值是什麼」**（"must be 0, 16, or 64"），不只說「錯了」
4. **三條 assertion 各自代表一種約束類型：**
   - **合法值集合**：PMP_ENTRIES 只能是 0/16/64
   - **功能相依**：虛擬記憶體需要 S-mode（呼應 2.5 節）
   - **微架構限制**：FLEN > XLEN 時必須有資料 cache，
     **因為 AHB/DTIM 匯流排寬度是 XLEN**（所以 RV32 只有在啟用 cache 時才支援 FLEN = 64 雙精度）

**這段的關鍵洞見（p.215）：**
> "**Hence, the assertions enforce legal configurations as part of the code base rather than
>  part of the documentation that a user might lose or not read.**"

**「把合法組態的約束放進程式碼，而不是放進使用者可能弄丟或不讀的文件。」**
——這是「可執行的規格」的思路（呼應 3.5 節的 Sail）。

實際的錯誤輸出（p.216）：
```
# ** Fatal: Illegal number of PMP entries: PMP_ENTRIES must be 0, 16, or 64
```

### Deferred immediate assertion：處理毛刺

> "Sometimes the assertion may fire while expression is glitching, producing a faulty error
>  during a transient invalid state that resolves to a good state. **Deferred immediate
>  assertions add the final keyword, which causes the assertion to wait until expression
>  settles before evaluating.**"
> — p.216

```systemverilog
assert final (expression) <statement1> <else statement2>
```

中文解釋：**這是個實務上會踩到的問題。**

組合邏輯在穩定之前會有**毛刺（glitch）**——短暫經過一些無效的中間值。
**一般的 immediate assertion 會對這些暫態誤報。**

**`assert final` 等訊號穩定後才評估。**

### Concurrent assertion：跨週期的性質

> "*Concurrent assertions* describe behavior that spans clock cycles. They are called
>  concurrent because they execute in parallel with the rest of the design. They use a
>  succinct and powerful notation suited to describe multicycle events in synchronous
>  sequential systems. **The SystemVerilog 1800-2017 specification devotes more than a hundred
>  pages to concurrent assertions**, but this section just touches on a simple example."
> — p.216

中文解釋：**「規格書用了超過一百頁講並行 assertion」**——
這句話就說明了它的複雜度。本書只講一個簡單例子。

**核心概念（p.216）：**
> "Concurrent assertions are expressed using *properties*, which in turn may depend on
>  *sequences*. Properties use the *implication operator* |-> to imply a relationship between
>  an *antecedent* and a *consequent*. **If the antecedent is satisfied, the concurrent
>  assertion checks the consequent and reports if it is violated.**"

**三層結構：sequence → property → assertion。**

**`|->` 是蘊含運算子**：**前件（antecedent）成立時，才檢查後件（consequent）。**
（前件不成立時 assertion 自動通過——這叫 vacuous pass，是 SVA 的常見陷阱。）

### 實例：AHB 匯流排協定檢查

中文解釋：書上的例子是檢查 AHB 匯流排協定（p.216–217）。

**要檢查的性質（自然語言版）：**
> "when the HREADY signal is low, indicating that a peripheral needs a wait state, the
>  controller must not change the transfer type HTRANS from one bus cycle to the next, except:
>  - The controller can change HTRANS from IDLE to NONSEQ.
>  - If the controller was busy in the previous cycle of a burst transfer, HTRANS can go from
>    BUSY to SEQ.
>  - During reset, the protocol does not apply."

**Code Example 5.6（p.217）的 SVA 版本：**
```systemverilog
transaction_type_stability: assert property (
  @(posedge HCLK) disable iff (!HRESETn)
    !HREADY |-> $stable(HTRANS)                        |
                ($past(HTRANS) == AHB_IDLE)            |
                (($past(HTRANS) == AHB_BUSY) & (HBURST != 3'b000))
);
```

**逐項對照，這是整節最值得學的部分：**

| SVA 元素 | 意義 | 對應自然語言 |
| --- | --- | --- |
| `transaction_type_stability:` | **assertion 的名稱**，用於報告 | — |
| `@(posedge HCLK)` | 在 HCLK 上升緣評估 | 每個匯流排週期 |
| **`disable iff (!HRESETn)`** | **重置期間停用** | 「重置時協定不適用」 |
| `!HREADY` | **前件** | 「HREADY 為低時」 |
| `\|->` | 蘊含 | 「就必須…」 |
| **`$stable(HTRANS)`** | **和前一週期相同** | 「HTRANS 不得改變」 |
| **`$past(HTRANS) == AHB_IDLE`** | **前一週期是 IDLE** | 例外一 |
| `($past(HTRANS) == AHB_BUSY) & (HBURST != 0)` | 前一週期是 BUSY 且在 burst 中 | 例外二 |

**三個要記住的內建函式：**
- **`$stable(x)`**：x 和前一週期相同
- **`$past(x)`**：x 在前一週期的值
- **`disable iff (條件)`**：條件成立時停用這條 assertion

**設計的漂亮之處：三個例外用 OR（`|`）串起來當後件**——
「必須穩定，**或者**是這兩種例外之一」。
**自然語言的「except」直接翻成邏輯的 OR。**

**這也是為什麼 assertion 適合匯流排介面**（本節開頭的三個場合之一）：
協定規則本來就是「什麼情況下不准做什麼」的形式，和 SVA 的語法天然契合。

## 名詞表

| 名詞 | 意思 |
| --- | --- |
| **SVA** | SystemVerilog Assertions |
| **Immediate assertion** | 即時斷言。執行到時檢查運算式；放在 `initial` 或 `always` 區塊 |
| `$fatal` / `$error` / `$warning` / `$info` | 四個嚴重等級；**`$fatal` 會終止模擬**，**違規通常用 `$error`** |
| **Deferred immediate assertion** | `assert final`。等運算式穩定後才評估，避免毛刺誤報 |
| Glitch | 毛刺。組合邏輯穩定前的暫態無效值 |
| **Concurrent assertion** | 並行斷言。描述跨越多個時脈週期的行為 |
| Property / sequence | 性質 / 序列。並行斷言的組成層次 |
| **`\|->`（implication operator）** | 蘊含運算子。**前件成立時才檢查後件** |
| Antecedent / consequent | 前件 / 後件 |
| `$stable(x)` / `$past(x)` | x 與前一週期相同 / x 在前一週期的值 |
| `disable iff (cond)` | 條件成立時停用該斷言（如重置期間） |
| `riscvassertions.sv` | Wally 檢查組態參數合法性的模組（見 4.4 節） |

## 所以呢

**Assertion 的價值是「抓得早」：在錯誤汙染架構狀態之前就指出根本原因。**

三件實務要點：
1. **三個最該放 assertion 的地方：FIFO、匯流排介面、狀態機**——
   共同點是它們都有明確的「不該發生」的狀態。
2. **`riscvassertions.sv` 示範了一個好習慣：
   把合法組態的約束寫進程式碼，而不是寫進文件。**
   組態錯誤用 `$fatal`（繼續跑沒意義），執行中違規用 `$error`。
3. **並行 assertion 的核心是 `|->`（前件 → 後件），
   加上 `$past`、`$stable`、`disable iff` 三個工具**，
   就能把「協定規則 + 例外」直接翻譯成一行程式碼。

下一節（5.8）換個角度：不是檢查「有沒有錯」，而是量測「測得夠不夠」。
