# 9.3 Other SoC Buses

> 原書 p.410（Chapter 9: Bus Interface）

## 這節在講什麼

**AMBA 以外的四種 SoC 匯流排，每種一段。**

很短，但**它的價值在於「每種匯流排和 AHB/AXI 的差異點」**——
這些差異點反映了不同的設計取捨。

**最有洞見的是最後那句關於 TileLink 的評語：
SiFive 做了一個技術上不錯的新匯流排，但客戶還是偏好 AHB 或 AXI。**

## 關鍵點

### Wishbone：開源但商用不多

> "**Wishbone is an open-standard SoC bus developed by Silicore Corporation and maintained by OpenCores for
>  portable IP cores [Wishbone10]. It has similarities to AHB but doesn't delay write data by a cycle.
>  It lacks the cache coherency features of AXI and other buses. Wishbone is compatible with many free
>  OpenCores, but it is not used as much in commercial systems.**"
> — p.410

中文解釋：**Wishbone vs AHB 的關鍵差異：不把寫入資料延遲一個週期。**

**這其實是個優點**——呼應 9.2.2 節邊欄說的
「AHB 的寫入資料晚一週期是從 ARM6 繼承來的歷史產物」，
而且它讓 SRAM 介面變複雜（寫→讀要插 wait state）。
**Wishbone 沒有這個包袱。**

**但缺點是沒有 cache coherency 功能，而且商用系統用得不多。**
**技術上更乾淨 ≠ 市場成功**（這個主題會在 TileLink 那段再出現一次）。

### OBI：OpenHW 的選擇

> "**The OpenHW group uses the Silicon Labs Open Bus Interface [OBI22] in several of its RISC-V processors.
>  It resembles a simplified AXI interface, with an address and response channel.**"
> — p.410

中文解釋：**OBI = 簡化版的 AXI，只有位址和回應兩個通道。**
（AXI 有五個通道，見 9.2.3 節。）

**OpenHW 是 Wally 所屬的組織（呼應 2.8 節），
但 Wally 本身用 AHB 而非 OBI。**

### CoreConnect：IBM 的，已式微

> "**CoreConnect, developed by IBM, is another commercial SoC bus. It includes a high-speed processor local
>  bus (PLB) with a bridge to a simpler on-chip peripheral bus (OPB). It is available for free but requires
>  a license from IBM. Xilinx FPGAs used CoreConnect IPs before switching to AXI; little CoreConnect IP is
>  now available.**"
> — p.410

中文解釋：**架構和 AMBA 一樣是「快的 + 慢的 + bridge」：
PLB（processor local bus）對應 AHB，OPB（on-chip peripheral bus）對應 APB。**

**「免費但需要 IBM 授權」這個組合本身就是採用的障礙。**
**Xilinx FPGA 換到 AXI 之後，CoreConnect 就沒什麼 IP 了。**

### TileLink：技術上有道理，但市場不買單

> "**SiFive developed an open-standard SoC bus called TileLink for ease of implementation and to provide high
>  speed and cache coherence [TileLink20]. A key difference between AHB and TileLink is that AHB allows one
>  controller to directly communicate with multiple peripherals, but TileLink allows only point-to-point
>  links between a single controller and a single peripheral. TileLink adds a switch component when it
>  needs to connect multiple controllers or peripherals. TileLink's point-to-point links facilitate
>  high-speed SoC networks in which the link is pipelined to permit multiple messages in-flight
>  concurrently.**"
> — p.410

中文解釋：**TileLink vs AHB 的關鍵架構差異：**

| | **AHB** | **TileLink** |
| --- | --- | --- |
| 一個控制器連多個周邊 | **可以直接連** | **不行，只能點對點** |
| 多控制器/多周邊 | 用 interconnect matrix（multilayer AHB） | **加一個 switch 元件** |
| 好處 | 簡單系統接線少 | **點對點連結可以 pipeline，讓多個訊息同時在飛** |

**TileLink 的設計思路是「徹底的點對點」**——
呼應 9.1.3 節說的「SoC 晶片內匯流排用點對點接線」，TileLink 把這個原則推到極致。
**代價是連多個裝置時一定要加 switch。**

**結局（p.410）：**
> "**However, SiFive has found that customers preferred the broadly accepted AHB or AXI bus rather than a
>  novel bus.**"

**「客戶偏好廣為接受的 AHB 或 AXI，而非新的匯流排。」**

**這句話和 Wishbone 那段是同一個教訓：
匯流排標準的價值主要來自生態系（能接現成 IP），
所以「技術上更好」很難打敗「大家都在用」。**
（呼應 9.1 節開頭：「用標準 SoC 匯流排才能接現成的周邊」。）

## 名詞表

| 名詞 | 意思 |
| --- | --- |
| **Wishbone** | Silicore 開發、OpenCores 維護的開放標準；**類似 AHB 但不延遲寫入資料**；無 cache coherency |
| **OBI** | Silicon Labs Open Bus Interface；**簡化版 AXI，只有位址與回應通道**；OpenHW 的部分核心採用 |
| **CoreConnect** | IBM 的；**PLB（快）+ OPB（慢）+ bridge**；免費但需授權，已式微 |
| PLB / OPB | Processor local bus / On-chip peripheral bus |
| **TileLink** | SiFive 的開放標準；**只允許點對點連結，多裝置要加 switch**；可 pipeline 讓多訊息並行 |

## 所以呢

**四種匯流排各有一個和 AMBA 不同的設計決定：**

| 匯流排 | 差異點 |
| --- | --- |
| **Wishbone** | **不延遲寫入資料**（避開 AHB 的歷史包袱），但無 cache coherency |
| **OBI** | 簡化成兩個通道 |
| **CoreConnect** | 架構同 AMBA，但需要 IBM 授權 |
| **TileLink** | **徹底點對點，多裝置要加 switch**；可 pipeline |

**最該帶走的是那個市場教訓：
SiFive 發現客戶偏好廣為接受的 AHB/AXI，而非新的匯流排。**
**匯流排標準的價值主要來自生態系——技術優越性很難打敗網路效應。**
（這和第 1 章 x86「贏在便宜和現貨，不是贏在設計」是同一個道理。）
