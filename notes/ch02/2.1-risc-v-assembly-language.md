# 2.1 RISC-V Assembly Language

> 原書 p.32–43（Chapter 2: Introduction to RISC-V）
> 涵蓋 2.1.1–2.1.12 全部子節

## 這節在講什麼

RV32I 指令集的完整導覽。核心是**六種指令型別（R/I/S/B/J/U）**——
這個分類不是教學用的方便說法，**它直接對應到機器碼的編碼格式**（2.2 節），
所以整本書後面設計 decoder、immediate extension 都要用到。

分類的依據只有兩件事：**用了幾個來源暫存器、有沒有立即值、立即值多長。**

後半段講三件實務的事：**暫存器慣例**（誰負責保存誰）、**endianness**、
**pseudoinstruction**（組譯器的語法糖），最後用 13 個 C→組語對照範例收尾。

Table 2.1（p.33）是這節的總表，六型一次看完。

## 關鍵點

### 六種指令型別的分類總表

> "Instructions are classified into six types based on their operands and encoding,
>  as shown in Table 2.1."
> — p.32

中文解釋：Table 2.1（p.33）的內容整理如下，**這張表要背起來**：

| Type | 說明 | 來源暫存器數 | 目的暫存器數 | 立即值 |
| --- | --- | --- | --- | --- |
| **R** | Register-type | 2 | 1 | 無 |
| **I** | Immediate-type | 1 | 1 | 12-bit |
| **S** | Store-type | 2 | **0** | 12-bit |
| **B** | Branch-type | 2 | **0** | 13-bit branch offset |
| **J** | Jump-type | 1 | 1 | 21-bit jump offset |
| **U** | Upper immediate-type | 1 | 1 | 20-bit upper immediate |

**看表的訣竅**：
- 來源暫存器**最多 2 個**——呼應 1.7 節說 ARM 用三個來源暫存器是設計陷阱。
- **S 和 B 沒有目的暫存器**（store 和 branch 都不寫回暫存器），
  所以它們的編碼可以把 rd 那 5 個 bit 挪去放立即值。這就是為什麼它們的立即值擺得那麼怪（2.2 節）。
- B 的 13-bit 和 J 的 21-bit 都是**奇數 bit 數**，這是因為最低位元恆為 0（見下面）。

### R-Type：只碰暫存器，由 ALU 執行

> "R-type instructions have only register operands: two source registers and one
>  destination register. For example, add x3, x1, x2 computes the sum of the values
>  in source registers x1 and x2 and puts the result in destination register x3.
>  R-type instructions are executed by the integer *arithmetic/logic unit* (ALU)."
> — p.33

中文解釋：格式固定是 `op rd, rs1, rs2`——**目的暫存器寫在前面**（和 x86 相反，跟 MIPS 一樣）。

R-type 包含四類（p.33）：
- **算術**：`add`、`sub`
- **邏輯**：`and`、`or`、`xor`
- **移位**：`sll`（邏輯左移）、`srl`（邏輯右移）、`sra`（算術右移）
- **比較**：`slt`、`sltu`

### 有號 / 無號：同一套加法電路，兩種解讀

> "Arithmetic and logical operations are the same, whether their operands are
>  treated as unsigned or two's complement signed numbers."
> — p.33

中文解釋：**這是二補數最重要的性質，也是硬體能省下一半電路的原因。**
`add` 不需要知道運算元是有號還是無號——同一個位元樣式，兩種解讀都正確。

書上的例子（p.33）：`add 1110, 0001 = 1111`，
無號解讀是 14 + 1 = 15，有號解讀是 −2 + 1 = −1。**兩個都對。**

但**比較不一樣**。`slt`（有號）和 `sltu`（無號）必須是兩條不同的指令：
`slt 1110, 0001 = 1`（因為 −2 < 1），但 `sltu 1110, 0001 = 0`（因為 14 ≥ 1）（p.34）。
**加減法可以共用，比較不行**——這是設計 ALU 時的關鍵區分。

### 移位：srl 和 sra 的差別，以及除法陷阱

> "Shift left logical (sll) fills the bottom bits with 0s. Shift right logical (srl)
>  fills the upper bits with 0s. Shift right arithmetic (sra) fills the upper bits
>  with the old sign bit. A left or right shift by k is equivalent to a multiply or
>  divide by 2^k. When dividing, use srl if the number is unsigned or sra if it is signed."
> — p.33

中文解釋：三種移位的填補規則：`sll` 下方補 0、`srl` 上方補 0、`sra` **上方補原本的符號位元**。

**為什麼右移要分兩種而左移不用？** 因為左移補 0 對有號無號都對，
但右移時有號數必須保持符號。書上的例子（p.33）：
`sra 1110, 0001 = 1111`，有號解讀 −2 >> 1 = −2/2 = −1 ✓。
如果用 `srl` 就會得到 `0111` = 7，完全錯誤。

還有一個陷阱要注意：`sll 1110, 0001 = 1100`，
有號解讀是 −2 << 1 = −4 ✓，但**無號解讀是 14 << 1 = 28，會溢位成 12**（p.33）。
左移會溢位，右移不會。

### I-Type：一個暫存器 + 12-bit 立即值

> "I-type instructions take a source register, a 12-bit signed *immediate*
>  (i.e., a constant in the instruction that is immediately available without
>  accessing memory), and a destination register. The immediate is sign-extended
>  to XLEN before use."
> — p.34

中文解釋：**immediate（立即值）的定義值得留意**：常數直接編在指令裡，不用存取記憶體就拿得到。
所以叫「立即」。而且**一律符號延伸**到 XLEN（32 或 64）。

I-type 的成員（p.34）：
- **Loads**：`lw`、`lh`、`lhu`、`lb`、`lbu`
- **Jumps**：`jalr`
- **算術**：`addi`
- **邏輯**：`andi`、`ori`、`xori`
- **移位**：`slli`、`srli`、`srai`
- **比較**：`slti`、`sltiu`

**注意沒有 `subi`**——書上邊欄直說了原因：
"subi is not needed because it can be performed by an addi with a negative immediate."（p.34）
**這就是 RISC 精神的具體例子：能用現有指令表達的就不加新指令。**

### Load 的定址方式，與 subword load 的兩種版本

> "Loads read a value from memory and place it in the destination register. The
>  memory address is computed by adding the sign-extended immediate to a base
>  address in the source register."
> — p.34

> "*Subword loads* come in normal and unsigned versions. The normal version (lb/lh)
>  sign-extends the byte or half-word to the full XLEN length. The unsigned version
>  (lbu/lhu) zero-extends."
> — p.34

中文解釋：**位址 = 基底暫存器 + 符號延伸的立即值。** 這是 RISC-V 唯一的定址模式。
只有一種——對照 1.7 節說 ARM 的「彈性定址模式」是設計陷阱。

subword load（載入小於一個字的資料）**必須指定延伸方式**：
`lb` 符號延伸（適合 `signed char`），`lbu` 零延伸（適合 `unsigned char` 或原始位元組）。
注意 store 沒有這個區分——存進去就是截斷，不需要延伸。

另外書上有個 **`sltiu` 的陷阱**（p.34 邊欄）：
"sltiu sign-extends the immediate to 32 bits before treating it as an unsigned
number for comparison!" ——立即值**先符號延伸，才當無號數比較**。
所以 `sltiu x1, x2, -1` 實際是跟 0xFFFFFFFF 比。

### S-Type：store，沒有目的暫存器

> "S-type instructions are stores. They take two source registers and a 12-bit
>  signed immediate. Like loads, they add the immediate to the first source register
>  to compute an address. Then they store the contents of the second source register
>  into that address."
> — p.34

中文解釋：`sw rs2, imm(rs1)` —— 位址算法**和 load 完全一樣**（rs1 + imm），
差別只在資料流方向：load 把記憶體寫進 rd，store 把 rs2 寫進記憶體。

**因為沒有 rd，S-type 才需要一個和 I-type 不同的編碼格式**——
立即值被拆成兩段塞進原本 rd 的位置。這是 2.2 節那張「立即值被打散」的圖的由來。

### B-Type：分支，最低位元恆為 0 是關鍵技巧

> "They compare the two source registers. If the condition is satisfied, they take
>  the branch by sign-extending the immediate (also called the *branch offset*) and
>  adding it to the PC."
> — p.35

> "Because the 13-bit branch offset will always be a multiple of 2, and thus its
>  least significant bit will always be 0, only its upper 12 bits are encoded in the
>  instruction's immediate field. The processor must append the implicit least
>  significant 0 before sign-extending and adding to the PC. So, the branch offset
>  spans the range [−4096, 4094]."
> — p.35

中文解釋：**這是 RISC-V 一個很漂亮的省位元技巧，一定要搞懂。**

推理鏈：指令一定在 2-byte 邊界上（見下）→ 分支偏移一定是 2 的倍數 →
最低位元一定是 0 → **那就不要編碼它，執行時再補回去** →
同樣 12 個編碼位元，**定址範圍加倍**。

書上邊欄解釋了為什麼是 2-byte 而不是 4-byte（p.35）：
"Ordinary RISC-V instructions are 4 bytes long, but compressed instructions are
2 bytes, so instructions may be on 2-byte boundaries. They are never at odd
addresses, so the least significant bit (lsb) of the branch offset is always 0.
RISC-V gains additional branching range by omitting the branch offset's lsb when
encoding this immediate in the instruction."

分支指令共六條，三組成對：
`beq`/`bne`（等於/不等於）、`blt`/`bge`（有號小於/大於等於）、`bltu`/`bgeu`（無號版）。

### J-Type：jal，範圍 ±1 MB

> "The only J-type instruction is *jump and link* (jal), which makes an unconditional
>  PC-relative jump and saves PC+4 in the destination register as the return address."
> — p.35

> "jal adds this jump offset to the PC and jumps to that address. For unconditional
>  jumps (j), x0 is used as the destination register to discard the return address."
> — p.35

中文解釋：`jal` 做兩件事——**跳**（PC += offset）和**記**（rd = PC+4）。
「link」就是「記下回來的路」的意思。

和 B-type 同樣的技巧：21-bit 偏移，只編碼上面 20 bit，
所以範圍是 **[−1048576, 1048574]**，約 ±1 MB。

**最後那句是 RISC-V 的招牌手法：用 x0 當目的暫存器來「丟掉」結果。**
`j label` 其實就是 `jal x0, label`——跳了但不記回程。
**一條指令靠不同的暫存器參數變出兩種語意，不必加新指令。**
這個手法後面會一再出現（pseudoinstruction 那節）。

### U-Type：lui + addi 組出 32-bit 常數

> "U-type instructions also use a destination register and a 20-bit immediate.
>  They shift the immediate left by 12 bits into the upper bits of a 32-bit word,
>  filling the lower bits with 0s."
> — p.35

> "The *load upper immediate* (lui) instruction places the shifted immediate in the
>  destination register. In combination with addi, this is useful for creating
>  32-bit constants."
> — p.35

中文解釋：**問題**：指令只有 32 bit，怎麼塞得下一個 32-bit 常數？
**答案**：拆兩步。`lui` 給上面 20 bit，`addi` 給下面 12 bit。20 + 12 = 32。✓

**但這裡有個很容易踩的坑，書上特別警告：**

> "Remember that 12-bit immediates are sign-extended, which could throw off the
>  upper bits by 1. For example, to load the constant 0x00003800 into x1, use the
>  following sequence. −2048 in 12-bit two's complement is 0x800, which is
>  sign-extended to 0xFFFFF800."
> — p.35

```asm
lui  x1, 0x0004      # x1 = 0x00004000
addi x1, x1, -2048   # x1 = 0x00004000 + 0xFFFFF800 = 0x00003800
```

書上明說直覺寫法是錯的（p.36）：
"The more intuitive sequence of lui x1, 0x0003; addi x1, x1, 0x800 would produce
0x00002800 instead of the intended result."

**原因**：`addi` 的立即值是**有號**的。0x800 在 12-bit 二補數是 −2048，不是 +2048。
所以低位加了個負數，上位要**先多加 1** 來補償。
這件事組譯器會幫你處理（用 `li` pseudoinstruction），但看反組譯時會看到這個 +1。

### auipc：PC 相對定址，做位置無關程式碼

> "The *add upper immediate to PC* (auipc) instruction adds the shifted immediate
>  to the program counter and places it in a destination register."
> — p.36

> "auipc rd, 0 is used to copy the PC into rd. auipc is also useful for computing
>  arbitrary offsets relative to the program counter for either loads/stores or jumps."
> — p.36

中文解釋：`auipc` = `lui`，但加上 PC。用途是**位置無關**（position-independent）——
不管程式被載到哪個位址都能正確運作。

長距離跳躍的標準組合（p.36）：
```asm
auipc x1, 0x10002    # x1 = 0x80001000 + 0x10002000 = 0x90003000
jalr  x1, 0x456(x1)  # Jump to 0x90003000 + 0x456 = 0x90003456
                     # x1 = PC + 4 = 0x80001008
```
**`auipc` 給上面 20 bit，`jalr` 的 12-bit 立即值補下面**——
又是「20 + 12 = 32」的老套路。
書上邊欄提醒一個細節：x1 在這裡很方便當暫存器用，因為它反正會被回傳位址蓋掉（p.36 邊欄）。

### Other instructions：ecall、ebreak、fence

> "The base instruction set defines ecall and ebreak for OS calls and debugger
>  breakpoints, as discussed in Section 2.3.6. If there is no privileged mtvec trap
>  vector control register, these instructions do nothing."
> — p.36

> "The base instruction set also defines the fence instruction for memory ordering.
>  A simple single-core in-order processor such as Wally inherently executes memory
>  accesses in program order and thus can ignore fence."
> — p.36

中文解釋：三條特殊指令。`ecall`（系統呼叫）、`ebreak`（除錯中斷點）、`fence`（記憶體排序）。

**重點是後半句**：在簡單的單核、循序處理器上，`fence` 可以當 NOP 處理，
因為記憶體存取本來就照程式順序發生。**`fence` 只有在亂序或多核系統才有意義**（第 17.2.2 節）。
這是 ISA 設計的常見做法：定義好語意，允許簡單實作用最簡單的方式滿足它。

所以 RV32I 官方是 40 條指令，但書上說「37 條 essential」——
差的三條就是 `fence`、`ecall`、`ebreak`（p.32 邊欄：
"RV32I also has fence, ecall, and ebreak instructions, bringing the official total
to 40, but these can be ignored in a simple implementation."）。

### RV64I：多 12 條，關鍵是 W 後綴

> "RV64I adds ld and sd to load and store 64-bit *double words*. It also adds lwu
>  to load an unsigned word into the bottom 32 bits of a 64-bit register and fill
>  the top 32 bits with 0s. Furthermore, shift amounts are extended to 6 bits."
> — p.36

> "So RV64 provides add, subtract, and shift instruction versions with a w suffix
>  (which we call RW- and IW-type instructions) to support 32-bit operations.
>  Any result bits overflowing the 32-bit word are discarded, and then the 32-bit
>  result is sign-extended to fill the 64-bit register."
> — p.36

中文解釋：**W 後綴指令（`addw`、`subw`、`sllw`…）的存在理由值得理解，因為它揭露了一個實務痛點。**

問題是：C 語言的 `int` 在 64 位元機器上**仍然是 32-bit**。
64-bit 暫存器裡存 32-bit int 的慣例是**符號延伸**（bit 31 延伸到 bit 63:32）。
但如果你用 64-bit 加法去加兩個這樣的值，結果的上 32 bit 可能是錯的。

書上邊欄給了一個具體例子（p.36 邊欄）：
0x8000_0000 + 0x8000_0000，32-bit 結果應該是 0。
符號延伸成 64-bit 是 0xFFFF_FFFF_8000_0000，兩個相加得 0xFFFF_FFFF_0000_0000。
**上 32 bit 不是正確的符號延伸（應該全 0），所以結果無法直接當 32-bit int 用。**

修正它需要額外的遮罩指令（"would require costly masking sequences to fix"），
所以 RV64 乾脆提供 W 版本：**算完丟掉溢位、再符號延伸回 64-bit**，一步到位。

### 暫存器慣例：誰負責保存誰

> "The x0 register is also called zero and is hardwired to 0 because it is such a
>  commonly used constant."
> — p.37

> "x1 is called ra and is used to hold the *return address* when making a function
>  call with a jal instruction. x2 is called sp and points to the *top of the stack*.
>  The s0-s11 *saved* registers are used for local variables that must preserve their
>  value across function calls, while the t0-t6 *temporary* registers hold intermediate
>  results that can be overwritten during function calls. Function calls pass their
>  inputs in the a0-a7 *argument* registers and return their result in a0."
> — p.37

中文解釋：**這是 ABI（呼叫慣例）的核心，寫組語或看反組譯一定要熟。**

| 暫存器 | 別名 | 用途 | 跨函式呼叫會保存嗎 |
| --- | --- | --- | --- |
| x0 | zero | 硬接為 0 | — |
| x1 | ra | return address（回傳位址） | 否（caller 要自己存） |
| x2 | sp | stack pointer（堆疊頂端） | 是 |
| s0–s11 | saved | 需要跨呼叫存活的區域變數 | **是**（callee 要保存） |
| t0–t6 | temporary | 中間結果，呼叫後可能被蓋掉 | **否** |
| a0–a7 | argument | 傳參數；a0 也是回傳值 | 否 |

**s vs t 的區分是關鍵**：用 `s` 就要自己在函式開頭存、結尾還原（有成本）；
用 `t` 不用存，但呼叫別的函式後就不能信任它的內容。
下面的階乘範例會示範這個取捨。

書上邊欄解釋了為什麼編號排得這麼亂（p.37 邊欄）：
"The strange ordering of register names was selected so that RV{32/64}E systems
with only 16 registers (x0-x15) would still have some registers available for each
purpose." ——**為了讓只有 16 個暫存器的嵌入式版本（E 擴充）每一類都還有得用。**

### Endianness：位元組在字裡的順序

> "A processor's *endianness* defines how it stores the bytes within a word.
>  In little-endian, the least significant byte in a 32-bit word is stored at an
>  offset of 0 from the start of a word address, and the most significant byte is
>  stored at an offset of 3. In big-endian, the order is reversed."
> — p.37

中文解釋：Fig. 2.1（p.37）把兩種排法並排畫出來。
書上的例子最實用：把字 `0x1234F0E0` 存到位址 0x8。
- **Big-endian**：位址 0x8 存 `0x12`（最高位元組先），0xB 存 `0xE0`
- **Little-endian**：位址 0x8 存 `0xE0`（最低位元組先），0xB 存 `0x12`

所以 `lb t0, 8(x0)` 讀位址 8 的一個 byte，
**big-endian 回傳 0x12，little-endian 回傳 0xE0**（p.37）。

**RISC-V 預設是 little-endian**（p.37 邊欄）。
邊欄還有一個重要細節：`status` 暫存器可以把 load/store 切成 big-endian 模式（第 8.2.3.1 節），
但**指令永遠以 little-endian 格式抓取**——資料的端序可以變，指令的不行。

### Pseudoinstruction：組譯器的語法糖

> "RISC-V is missing many instructions that would be useful to a programmer, but
>  these can be implemented using existing instructions."
> — p.37

> "The programmer can use the pseudoinstruction, but the assembler replaces it with
>  the real add instruction."
> — p.38

中文解釋：**這是 RISC-V 保持指令集精簡的關鍵手法，也是 1.6 節 RISC 哲學的直接體現：
讓指令集小，讓組譯器補足人性化。**

書上給的對照（p.38）：

| Pseudoinstruction | 實際變成 | 說明 |
| --- | --- | --- |
| `li rd, imm` | `addi rd, x0, imm` | load immediate（小立即值） |
| `ble rs1, rs2, label` | `bge rs2, rs1, label` | **把運算元對調就成了反向比較** |
| `j label` | `jal x0, label` | 丟掉回傳位址 |
| `mv rd, rs1` | `addi rd, rs1, 0` | 加 0 就是搬移 |

**注意這三種手法**：
1. **拿 x0 當常數 0 的來源**（`li`、`mv`）
2. **拿 x0 當垃圾桶**（`j`）
3. **對調運算元產生反向操作**（`ble` ← `bge`）

這就是為什麼 RISC-V 不需要 `subi`、不需要 `bgt`、不需要 `mov`——
**都能用既有指令換個寫法做到，而每省一條指令就省下解碼硬體。**

### C 到組語：從簡單到遞迴的 13 個範例

書上 2.1.12 節用 13 個 Code Example 示範 C 怎麼翻成組語。
假設的變數配置（p.38）：`a,b,c` 在 s0,s1,s2；`i,j` 在 s3,s4；
陣列 `grades[100]` 基底位址在 s5；`name[80]` 基底位址在 s6。

**（1）基本運算（Code Example 2.1–2.3, p.38–39）**
```asm
a = b + c;        →  add  s0, s1, s2
a = b & 0xFF;     →  andi s0, s1, 0xFF
a = a + b - c;    →  add t0, s0, s1    # 用 t0 放中間結果
                     sub s0, t0, s2
```
重點：複雜運算要**拆成多步，用 temporary 暫存器接中間值**。

**（2）條件判斷：分支條件要反過來寫（Code Example 2.4–2.5, p.39）**
```asm
if (i == j)          bne s3, s4, done   # 條件「不」成立就跳過
  a = 1;             li  s0, 1
                  done:
```
**這是組語最反直覺的一點**：C 寫「如果成立就做」，組語寫「**如果不成立就跳過**」。
所以 `==` 變 `bne`、`<=` 變 `bgt`。書上說得很清楚：
"The assembly language branches over the body if the opposite condition is true"（p.39）。

if/else 則要多一個無條件跳躍跳過 else 區塊。

**（3）迴圈（Code Example 2.6–2.7, p.40）**
while 迴圈的骨架：標籤 → 檢查反向條件跳出 → 迴圈本體 → 跳回標籤 → 結束標籤。
for 迴圈多了初始化和 postoperation 兩部分，但編譯後結構和 while 一樣。

注意 `a = a * 2` 被編成 `slli s0, s0, 1`——**乘以 2 的冪次用移位，不用乘法指令**
（`mul` 要 M 擴充才有）。

**（4）陣列存取：位址 = 基底 + index × 元素大小（Code Example 2.8–2.9, p.40–41）**
```asm
grades[i] = grades[i] + 14;
  slli t1, s3, 2      # t1 = i * 4   （int 是 4 bytes，所以左移 2）
  add  t1, s5, t1     # t1 = &grades[i]
  lw   t2, 0(t1)      # t2 = grades[i]
  addi t2, t2, 14
  sw   t2, 0(t1)      # grades[i] = t2
```
**固定索引**（如 `grades[1]`）直接用立即值偏移：`lw t0, 4(s5)`（p.41）。
**變動索引**才需要算位址。**「index 先左移 2 再加基底」是陣列存取的標準樣式**，
後面看反組譯時會一直看到。

**（5）字串：C 字串以 0 結尾（Code Example 2.10, p.41）**
```asm
while (name[i])       # C 裡 0 是 FALSE，非 0 是 TRUE
  add t0, s6, s3      # t0 = &name[i]
  lb  t1, 0(t0)       # 用 lb 讀一個 byte（char）
  beq t1, zero, done  # name[i] == 0 就結束
```
**char 用 `lb` 不用 `lw`**，而且不需要 `slli`（因為元素大小是 1）。

**（6）函式呼叫與堆疊（Code Example 2.11, p.42）**
階乘函式示範完整的呼叫慣例：
```asm
fact: addi sp, sp, -8     # 堆疊往下長，開出 8 bytes
      sw   s0, 0(sp)      # 保存 s0（因為我要用它）
      sw   s1, 4(sp)      # 保存 s1
      ...                 # 本體：參數 n 在 a0
done: mv   a0, s0         # 回傳值放 a0
      lw   s1, 4(sp)      # 還原
      lw   s0, 0(sp)
      addi sp, sp, 8      # 收回堆疊
      ret
```
**四個要點**：
1. **堆疊往下長**（`addi sp, sp, -8` 是分配，`+8` 是釋放）。Fig. 2.2（p.42）畫了
   呼叫前 / 呼叫中 / 呼叫後三個時刻的 sp 位置和堆疊內容。
2. **用了 s 暫存器就必須存和還原**（callee-saved）。
3. **參數進 a0，回傳值出 a0。**
4. `ret` 是 pseudoinstruction（回到 ra 指的位址）。

**（7）編譯器最佳化：換用 t 暫存器（Code Example 2.12, p.42）**
> "An optimizing compiler will observe that there are no function calls within fact,
>  so result and i can be kept in temporary registers rather than needing to save
>  and restore s0 and s1."
> — p.42

**這個對照非常值得看**：改用 t0/t1 之後，開頭四行（調整 sp、存兩個暫存器）
和結尾四行全部消失，函式從 13 條指令縮到 8 條。
**條件是「這個函式內部沒有呼叫別的函式」**——所以 temporary 不會被誰蓋掉。
這就是 s/t 區分的實際價值。

**（8）遞迴：ra 也必須存（Code Example 2.13, p.43）**
```asm
else: addi sp, sp, -8
      sw   ra, 0(sp)    # ← 關鍵：保存回傳位址
      sw   a0, 4(sp)    # 保存參數 n
      addi a0, a0, -1
      jal  factr        # 遞迴呼叫（這會覆寫 ra！）
      lw   t0, 4(sp)    # 還原 n
      lw   ra, 0(sp)    # 還原 ra
      addi sp, sp, 8
      mul  a0, t0, a0   # n * factr(n-1)
      ret
```
> "Before the function can call itself, it must save the previous return address
>  and argument n on the stack."
> — p.43

**遞迴比一般呼叫多要存兩樣：`ra` 和參數 `a0`。**
原因很直接：`jal` 會把新的回傳位址寫進 `ra`，舊的就沒了；
而 `a0` 要傳新參數進去，也會被蓋掉。
**這就是堆疊存在的理由——每一層遞迴需要自己的一份 ra 和參數。**

（`mul` 來自 M 擴充，不在 RV32I 裡，見 p.42 邊欄。）

## 名詞表

| 名詞 | 意思 |
| --- | --- |
| R/I/S/B/J/U-type | 六種指令型別，依運算元與編碼分類 |
| Immediate | 立即值。編在指令裡的常數，不用存取記憶體 |
| XLEN | 暫存器寬度，32 或 64 |
| Sign-extend / zero-extend | 符號延伸（複製符號位元）/ 零延伸（補 0） |
| Subword load | `lb`/`lh` 符號延伸；`lbu`/`lhu` 零延伸 |
| Branch offset | 分支偏移。13-bit，但只編碼上 12 bit（lsb 恆為 0），範圍 [−4096, 4094] |
| Jump offset | 跳躍偏移。21-bit，只編碼上 20 bit，範圍 [−1048576, 1048574] |
| `lui` / `auipc` | 載入上位立即值 / 上位立即值加 PC（用於位置無關程式碼） |
| Linking | `jal`/`jalr` 把 PC+4 存進目的暫存器，記下回程 |
| W-suffix (RW/IW-type) | RV64 的 32 位元運算版本，溢位丟棄後符號延伸回 64-bit |
| ra / sp / s0-s11 / t0-t6 / a0-a7 | 回傳位址 / 堆疊指標 / 保存 / 暫時 / 參數與回傳值 |
| Endianness | 端序。RISC-V 預設 little-endian；指令永遠以 little-endian 抓取 |
| Pseudoinstruction | 偽指令。組譯器用既有指令實作的語法糖，如 `li`、`mv`、`j`、`ret` |

## 所以呢

**六種指令型別（R/I/S/B/J/U）是整本書的地基——
它們不只是語法分類，而是機器碼格式、decoder 設計、immediate extension 硬體的直接依據。**
另外兩個反覆出現的設計手法值得記住：
**用 x0 當常數 0 和垃圾桶**、**省略恆為 0 的最低位元換取兩倍定址範圍**。
下一節（2.2）把這些型別翻成實際的 32-bit 二進位編碼。
