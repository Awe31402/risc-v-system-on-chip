# 23.2 Wally FPGA Implementation

> 原書 p.784.e80–784.e99（Chapter 23: FPGA Implementation）
> 涵蓋 23.2.1 SD Card、23.2.2 Arty A7 Setup（建 SD 卡、合成、燒錄、UART 終端、AHB burst 效能、ILA）、23.2.3 Supporting Other Boards、23.2.4 Wally Zero Stage Bootloader

## 這節在講什麼

把 Wally 真的做成一台電腦。核心觀念是：**`wallypipelinedsoc` 本身只是一顆 CPU，要變成能用的電腦還缺很多東西**——DRAM 控制器、時脈產生器、非揮發性儲存、跨時脈域轉換。這節示範怎麼用五個 AMD IP 模組把這些洞補起來。

最有價值的部分是 **23.2.2.5 的 AHB burst 效能實驗**——一個 `define` 改掉，開機時間從 2 分 17 秒變成 7 分 43 秒，記憶體頻寬掉到 1/8。這是全書把「架構決策」量化得最清楚的一次。

## 關鍵點

### 目標平台

> "Specifically, the fpga configuration (a variation of rv64gc) of wallypipelinedsoc has been run on an Arty A7-100T board, an FPGA development board available from Digilent for $299 in 2024. The board contains a Xilinx SC7A100TCSG324-1 FPGA, which is a midsized Artix-7 FPGA containing: 63,400 LUTs and 126,800 flops; 4,860-KiB block RAM organized as 135 36-Kib dual-ported memories; 240 DSP slices (25 × 18-bit multiplier, adder, and accumulator); 6 clock managers with phase-locked loops (PLLs); Up to 300 I/O pins"
> — p.784.e80

中文解釋：**$299 就能擁有一台跑 Linux 的自製 RISC-V 電腦**。Table 23.1 列出完整的購物清單：開發板 $299、USB 線 $4.99、PmodSD 轉接板 $9.99、SD 卡 $12.99、讀卡機 $29.99——**總共不到 $360**。

### 五個 IP 模組補的洞

> "The wallypipelinedsoc module requires additional peripherals to implement a functional computer, including a dynamic random access memory (DRAM) memory controller, a PLL to generate arbitrary clock frequencies, and an interface to nonvolatile memory storage such as an SD flash card."
> — p.784.e81

中文解釋：Table 23.2 的五個 AMD IP：

| 模組 | 功能 |
| --- | --- |
| `sysrst` | 把非同步的 reset 按鈕同步到時脈 |
| `mmcm` | 時脈產生器（內含 PLL） |
| `ahbaxibridge` | AHB 轉 AXI4 |
| `clkconverter` | 跨時脈域（20 MHz CPU ↔ 200 MHz 記憶體） |
| `memctrlddr3` | DDR3 記憶體控制器 |

**這張表本身就是一堂課**——五個模組裡有三個在處理「時脈」和「協定轉換」，完全沒有計算功能。真實系統的複雜度大量花在這種黏合邏輯上。

> "The mixed-mode clock manager (mmcm) is AMD IP that contains a PLL, which takes the 100-MHz on-board clock and generates three system clocks: 167 MHz (for memory controller calibration), 200 MHz (for the DDR memory interface), and 20 MHz (CPUCLK for the Wally core)."
> — p.784.e81

中文解釋：**一塊板子上有四個不同的時脈**（100 MHz 晶振 + 三個產生的）。CPU 只跑 20 MHz，記憶體介面跑 200 MHz——這就是為什麼需要 `clkconverter`。

> "The AMD DRAM controller (memctrlddr3) implements the AXI4 subordinate protocol that converts bus read and writes into DDR3 DRAM read and writes. memctrlddr3 also handles the nuances of DRAM management, including I/O timing, skew compensation, periodically refreshing data at each memory address, and opening and closing memory banks. The full scope of memory controller design is its own textbook."
> — p.784.e82

中文解釋：**「記憶體控制器設計本身就是一本教科書」**——這句話說明了為什麼要用 IP 而不自己寫。DRAM 需要週期性 refresh、bank 管理、時序校正，這些都是類比與時序混合的難題。

### SD 卡：為什麼用慢的 SPI 介面

> "The SD card communicates using the 1-bit SPI interface. With a clock frequency of f_c, the bandwidth is (f_c transactions/s) × (1 bits/transactions)/(8 bits/byte) = f_c/8 bytes/s. The maximum frequency of 25 MHz delivers 3.125 MB/s. Although relatively slow, SPI has several advantages: it does not require a costly license, and the Linux kernel contains built in drivers for it."
> — p.784.e83–e84

中文解釋：**選慢的介面是刻意的商業決定**。邊欄說明：SD 卡還有 SDIO 介面，50 MHz、4 bit，能到 25 MB/s（快 8 倍），**但需要付昂貴的授權費**。SPI 免費而且 Linux 有現成驅動——這是第 20 章「de facto standard 的價值在於驅動程式已經寫好」的再次印證。

另外兩根訊號接到 GPIO：**card detect（CD）接 GPIO[2]**（卡片插入時中斷 CPU）、**write protect（WP）接 GPIO[3]**（高電位時禁止寫入）。SD 卡插槽本身沒辦法透過 SPI 告訴你這些，只能用額外的腳位。

### 四個步驟

> "1. Build the SD flash card to hold a Buildroot Linux image. 2. Synthesize Wally and place and route it on the FPGA. 3. Program the FPGA to be configured as Wally. 4. Connect a UART terminal interface."
> — p.784.e84

中文解釋：注意順序——**先準備 SD 卡，因為 FPGA 一燒好就會立刻開始開機**。

### SD 卡的分區配置

> "This script creates a GPT and then 4 partitions. Partition 1 contains the device tree, partition 2 contains OpenSBI, partition 3 contains Buildroot, and partition 4 contains a mountable file system ext4."
> — p.784.e86

中文解釋：這裡出現了 22.2 講的「模擬與真實硬體的差別」——在 QEMU 裡這些檔案直接塞進記憶體，在 FPGA 上要**從 SD 卡的分區讀出來**。GPT（globally unique identifier partition table）告訴 ZSBL 每個分區在哪。

FPGA 用的 device tree 是 `wally-artya7.dts`，比 QEMU 版多了三段：`refclk`（20 MHz 給 SPI 用）、`gpio0`（定義 CD 和 WP 腳位）、`spi@13000`（定義 SD 卡插槽，`mmc-spi-slot`、最高 1 MHz、3.3 V）。`bootargs` 也改成 `console=ttyS0,115200`。

### 合成與燒錄

> "On a fast computer, synthesis, place and route, and bitstream generation takes around 20 minutes."
> — p.784.e86

中文解釋：**20 分鐘**——對照第 22 章「RTL 模擬跑 Linux 要 20 小時」，合成一次就能跑幾分鐘開機，非常划算。

（邊欄：Vivado 要用超過 90 GiB 的磁碟空間。Arty A7 用免費版就夠，更大的 FPGA 才需要付費授權。）

一個實用的除錯提示（邊欄）：**Vivado 有時會把 JTAG 時脈設太高**。規格是 JTAG 不能超過除錯器時脈的 2.5 倍，而 Wally 的除錯器用 20 MHz，所以要手動把 JTAG 調到 7.5 MHz。

### 連上終端

> "$ screen /dev/ttyUSB0 115200"
> — p.784.e90

中文解釋：USB 線同時提供兩個裝置——一個燒錄/除錯、一個 USB-to-UART。要先確認自己在 `dialout` 群組（`sudo usermod -a -G dialout <username>`）。

> "After about 40 seconds, OpenSBI prints a banner similar to Fig. 22.3. Over the next minute, Linux outputs boot messages and prompts the user for root login. ... When logged in, the terminal behaves just like a conventional Linux system. It is possible to run text editors and benchmarks, write new programs, and save files to the flash card."
> — p.784.e91

中文解釋：**前 40 秒完全在做 SD 卡的 DMA 傳輸**（把 OpenSBI 和 kernel 搬進 DRAM），之後才是真正的開機。

### FPGA 上的 CoreMark 比模擬慢

> "Wally's CoreMark performance in hardware (on an FPGA) is worse than in simulation for two reasons. First, CoreMark is not compiled with the same optimization described in Sections 21.1.1 and 21.1.2. Second, the FPGA's clock is 20 MHz, and the Linux kernel takes a timer interrupt every 4 ms equal to (20 × 10^6 cycles/s) × (4 × 10^-3 s) = 80 × 10^3 cycles. The average interrupt latency is 6,300 cycles, 7.9% of the CPU's time."
> — p.784.e92

中文解釋：**這是全書唯一一次量化「跑 OS 的成本」**。CoreMark 在 FPGA 上只有 2.2 CM/MHz，模擬裡是 2.83。拆解：
- 2.83（裸機、最佳化過）
- → 2.61（**計時器中斷吃掉 7.9%**）
- → 2.27（沒用 signed 整數的 13% 最佳化，見 21.1.1）
- ≈ 2.2（實測）

**每 4 ms 的計時器中斷要花 6,300 個週期**——這就是 22.2.11.2 節講 Sstc 擴充時說「開銷可能很可觀」的具體數字。

### AHB burst：全書量化最清楚的架構決策

> "With burst, the Arty A7 boots Linux in 2 minutes and 17 seconds, but without burst, it takes 7 minutes and 43 seconds."
> — p.784.e93

中文解釋：**改一個 `define BURST_EN 0` 就讓開機時間變成 3.4 倍。** `ramspeed` 的數字更驚人：

| 區塊大小 | 有 burst | 無 burst |
| --- | --- | --- |
| 1 KiB（進快取） | 138 MB/s | 109 MB/s |
| 16 KiB（進快取） | 123 MB/s | 3.42 MB/s |
| 1024 KiB（超出快取） | 30.5 MB/s | 3.13 MB/s |

> "Data strides that don't fit into the cache (those ≥ 16 KiB, highlighted in blue font), show a dramatic drop in bandwidth, about 1/8th of the original. This configuration has 8 words per cache line, so one cache line fetch or writeback burst becomes 8 single transactions."
> — p.784.e93

中文解釋：**掉到 1/8 正好對應「一條快取線 8 個字」**——沒有 burst 的話，每個字都要付一次完整的 DRAM 交易開銷。

> "The reason burst is so effective is that DRAM memories are optimized for large transfers but require many cycles of overhead to initiate a transaction. Burst amortizes that cost for all words in a cache line, thus reducing average memory latency."
> — p.784.e93

中文解釋：DRAM 的成本結構是「**啟動交易很貴，之後連續讀很便宜**」（要開 row、等 RAS-to-CAS 延遲）。burst 把這個固定成本攤給整條快取線。

> "It is worth revisiting Amdahl's law, which states: 'Make the common case fast.' Typically, we assume a program's working set will fit in the L1 cache. However, this assumption fails for the majority of ramspeed's execution and, thus, results in overall poor performance. For comparison, CoreMark scores 1.875 CoreMarks/MHz without burst, just 22% slower than with burst (compared to ramspeed's 7800% slower)."
> — p.784.e93

中文解釋：**這個對比是整節的精華**——同一個硬體改動，對 CoreMark 只差 22%，對 ramspeed 差了 78 倍。原因是 CoreMark 的工作集塞得進快取（呼應 21.1 講的「D$ misses 只有 76 次」），而 ramspeed 刻意不塞。

教訓：**benchmark 的選擇決定你看到什麼**。只看 CoreMark 會嚴重低估 burst 的價值。

### ILA：在真實硬體上看訊號

> "After programming the FPGA with the Wally SoC, a new window to the right of the Hardware panel called hw_ila_1 displays the ILA (Integrated Logic Analyzer) interface."
> — p.784.e93

中文解釋：Table 23.3 列出預設探測的六個訊號：`PCM`、`InstrValidM`、`InstrM`、`TrapM`、`IEUAdrM`、`MemRWM`——**全部在 Memory 級**，因為那是指令已經確定會完成、位址也算好的時刻。

ILA 的用法：設觸發條件（例如 `PCM == 0x1186`），按播放，等條件成立就抓一段波形。

> "The ZSBL reads the GPT partition header from the flash card to find the locations of the partitions containing the device tree, OpenSBI, and the kernel. It copies OpenSBI and Linux to DRAM using DMA transfer directly from the SD card's manager without using the CPU. However, the bootloader does not need to do other work during this time, so it implements a busy loop to continuously poll for the SD card's interrupt flag."
> — p.784.e94

中文解釋：這是 ILA 的一個實際應用——**用 PC 值加上 objdump 反推出 CPU 在做什麼**。觸發在 0x11AA 發現 CPU 卡在一個兩指令的迴圈（load + branch），對照 `boot.objdump` 就知道那是在輪詢 SD 卡的中斷旗標。

### 加自訂訊號到 ILA 的兩個步驟

> "First, the logic must be annotated with (* mark_debug = "true" *) in the source code so the optimizer knows not to remove the net from the netlist."
> — p.784.e95–e96

中文解釋：**第一個問題是「訊號會被最佳化掉」**。合成工具會把沒用到的中間訊號消掉，所以要標記保留。但直接在 RTL 裡加標記很醜，所以 Wally 的做法是：把原始碼複製到 `CopiedFiles_do_not_add_to_repo`，再用腳本 `insert_debug_comment.sh` 根據 `marked_debug.txt` 自動加上標記。**這是一個很好的工程實務——不汙染主原始碼。**

第二步是寫 Tcl 命令把訊號接到 ILA 探針，`proberange` 腳本能自動產生。

### 支援其他板子

> "However, Wally uses nearly all the FPGA resources on the Arty A7 and is limited to a 20-MHz clock. Other FPGAs enable the possibility for multicore, larger caches, accelerators, and higher clock speeds."
> — p.784.e96–e97

中文解釋：Arty A7 已經快裝不下了（後面 Table 23.5 會看到 82% 的 LUT 使用率）。

（邊欄有一個有趣的商業知識：**loss leader**——VCU108 的 FPGA 晶片本身要 $21,000，但 AMD 補貼到 $7,700 賣；VCU118 的晶片 $59,000，板子只賣 $9,099。目的是讓工程師習慣用貴的 FPGA。）

換板子要改六件事：board files、top-level RTL、記憶體控制器、時脈與時序約束、I/O 腳位映射、device tree 與 ZSBL。

一個很真實的硬體踩雷紀錄：

> "The root cause of the problem is that the VCU118 level shifter assumes the daughter boards provide strong pull-up resistors less than 300 Ω; however, the PmodSD board has a different level shifter and uses 10-kΩ pullups. We built custom SD card boards with 300-Ω pullup resistors. Even with this change, the SD card controller cannot run faster than 11 MHz without errors."
> — p.784.e98

中文解釋：**上拉電阻不匹配（300 Ω vs 10 kΩ）導致要自己做板子**——這種問題在模擬裡完全看不到，只有接上真實硬體才會遇到。這正是 23.1 說「FPGA 能接真的外部硬體」的價值與代價。

### ZSBL 在 FPGA 上做的事

> "The ZSBL, also referred to simply as the bootloader, is system dependent because it must manage peripheral-dependent features such as the SD card clock. ... The ZSBL reads GPT partition 1 to find the location and size of the device tree, copying it into Wally's RAM at 0x87000000. Partition 2 contains the OpenSBI bootloader and firmware called FW_JUMP ... The ZSBL copies FW_JUMP into RAM at 0x80000000. Next, it copies the Linux kernel from partition 3 to 0x80200000. Finally, it flashes LED0 5 times by driving the GPIO[0] pin and jumps to 0x80000000 to start the OpenSBI bootloader."
> — p.784.e99

中文解釋：**對比 22.2.5 節的模擬版 ZSBL（只有 18 條指令、什麼都不做就跳走），FPGA 版真的要做搬運工作**：讀 GPT、從三個分區搬三個檔案到三個位址、閃 LED 表示成功、跳走。

**閃 LED 五次**是一個很實際的除錯手法——沒有終端輸出的階段，LED 是唯一的生命跡象。

## 所以呢

這一節示範了「從 CPU 到電腦」中間那一大段常被忽略的工作：時脈產生、跨時脈域、協定轉換、記憶體控制、非揮發性儲存。**五個 IP 模組裡沒有一個在做計算。**

三個值得帶走的數字：**AHB burst 讓開機快 3.4 倍、記憶體頻寬差 8 倍**（而 CoreMark 只差 22%——benchmark 選擇決定你看到什麼）；**計時器中斷吃掉 7.9% 的 CPU 時間**；**$360 就能自己做一台跑 Linux 的 RISC-V 電腦**。
