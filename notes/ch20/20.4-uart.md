# 20.4 UART

> 原書 p.784.e13–784.e19（Chapter 20: Peripherals）
> 涵蓋 20.4.1 Memory Map、20.4.2 Test Plan、20.4.3 Wally Implementation

## 這節在講什麼

UART（universal asynchronous receiver/transmitter，通用非同步收發器，唸作 "you-art"）是最老也最頑強的介面。它的關鍵字是 **asynchronous**——**只有資料線，沒有時脈線**。收發雙方靠「事先講好速率」加上「每個字元開頭的 start bit 重新對時」來同步。

這節也解釋了一件事：為什麼一個 1980 年代的晶片（TI PC16550D）的暫存器佈局到今天還在用。

## 關鍵點

### UART 的歷史來源

> "Computers historically communicated with teletype machines or VT100 text consoles over phone lines using a modem. A modem (short for modulator/demodulator) operates asynchronously because it is impractical to send a clock signal over a phone line. It communicates information with audio pulses at tens to thousands of bits per second traveling both directions along the line."
> — p.784.e13

中文解釋：**非同步的根源是「電話線上沒辦法再拉一條時脈線」**。這個 1960 年代的限制，決定了 UART 至今的樣貌。

> "Many devices still use the UART standard for backward compatibility or historical reasons, despite the existence of simpler and faster SPI and I²C serial links."
> — p.784.e13

中文解釋：書上很直白——UART 又慢又複雜，留下來純粹是因為相容性。

### 一個字元的波形

> "The TX line idles high. The start of the transmission is indicated by TX going low for one bit period; this is called the start bit. The UART then sends data bits (typically 8), optionally followed by a parity bit used to detect an error in the transmission. Finally, it raises TX for at least one bit period; this is called the stop bit."
> — p.784.e14

中文解釋：Fig. 20.9 的時序。每個部分都有理由：
- **idle 是高電位**：這樣「線斷掉」和「一直在傳 1」可以區分（線斷了會被上拉成高，看起來像 idle）
- **start bit 是低電位**：從 idle 的高電位下降，產生一個明確的邊緣讓接收端對時
- **stop bit 是高電位**：讓線回到 idle，這樣下一個 start bit 的下降緣才看得出來

### baud rate 不等於 bit rate

> "If the UART uses one start bit, one stop bit, no parity bits, and an 8-bit character, it takes 10 bit periods to send 8 data bits. Hence, the UART speed is called the baud rate rather than the bit rate. ... For example, 9600 baud means 9600 bit periods per second, or 960 characters per second (9600 bit periods/second × 8 data bits/10 bit periods × 1 character/8 data bits) after accounting for the start and stop bits."
> — p.784.e14

中文解釋：**9600 baud 的實際資料量是 960 位元組/秒，不是 1200**——因為每 10 個 bit period 只有 8 個是資料，另外兩個是 start 和 stop 的開銷（20% 額外負擔）。

### 「一堆吹毛求疵的參數」

> "The UART is asynchronous, so the baud rate is set by mutual agreement between the transmitter and receiver rather than by a common clock. The existence and polarity of the parity bit and the number of data and stop bits is also set by agreement. ... In a normal cable, RTS of the UART connects to RTS of the device, and CTS connects to CTS, but in a null modem cable, RTS connects to CTS and vice versa. ... As you can see, UART communication has many fussy parameters that must be set exactly right on each end, or the system will fail and be hard for ordinary users to troubleshoot."
> — p.784.e14–e15

中文解釋：這段是整節最實用的警告。要對上的參數包括：baud rate、資料位元數、stop bit 數、parity 的有無與極性、handshake 訊號的接法、電壓準位（RS-232 的 ±12 V 還是邏輯準位的 3.3 V）。**任何一項不合就完全不會動，而且沒有錯誤訊息**——這就是為什麼 USB 被發明出來。

（邊欄：「USB 就是為了終結這些麻煩的 UART 設定而開發的，順便提高資料率、縮小接頭、降低纜線成本。不幸的是，USB 有先天的安全漏洞。例如 USB 隨身碟的韌體可以被設定成偽裝成鍵盤裝置，輸入惡意的按鍵。」）

### 接收端怎麼對時：16 倍取樣

> "It typically begins with a high-speed peripheral clock PCLK operating at the system clock frequency (clk). The UART divides the peripheral clock down by a baud rate divisor × 2^UART_PRESCALE to 16 times the desired baud rate. The UART oversamples the RX line at this 16x clock. The first high-to-low transition indicates going from idle to the start bit. The UART can then wait 8 clock periods and sample every 16 clocks thereafter to measure the data bits in the middle of their window."
> — p.784.e15

中文解釋：這是 UART 最核心的技巧，值得畫在腦中：

```
16x 時脈：||||||||||||||||||||||||||||||||
RX：     ‾‾‾\___start___/‾‾‾‾D0‾‾‾‾\___D1___/
             ↑        ↑            ↑
          偵測下降緣  等8拍取樣    再等16拍取樣
```

**為什麼是 8 拍？** 因為 start bit 佔 16 拍，等 8 拍剛好落在正中間。之後每 16 拍取樣一次，就會一直落在每個資料位元的正中間——**這樣即使雙方時脈有幾個百分點的誤差，累積到第 10 個 bit 也還不會偏出取樣窗**。

### 除頻係數的計算

> "For example, suppose the system clock runs at 320 MHz, and UART_PRESCALE = 5. If the baud rate is 9600, the 16x clock is at 9600 × 16 = 153.6 kHz, and its period is 1/153600 = 6.51 μs. The baud rate divisor should be the baud period/(2^UART_PRESCALE / f_clk) = 6.51 × 10^-6 s/(2^5 / 320 × 10^6 Hz) = 65.1, so the UART uses a baud rate divisor of 65 to generate a 16x clock with a 6.5-μs period. The error is small enough that the UART can sample all of the bits in the character accurately, and then synchronize again to the next start bit."
> — p.784.e15

中文解釋：這個例子示範了兩件事。第一，除頻分兩段（prescale 的 2^5 加上除頻係數 65），這樣暫存器只要 16 位元就能涵蓋很大的頻率範圍。第二，**65.1 被無條件捨去成 65，造成 0.15% 的誤差**——這是可接受的，因為每個字元開頭都會重新對時（re-synchronize），誤差不會累積超過 10 個 bit period。

### THR / RBR 與 buffer overflow

> "A UART classically has a Transmit Holding Register (THR) and a Receiver Buffer Register (RBR) along with control signals to indicate whether each of these registers is full. A host processor sends a character by waiting until the THR is empty and then writing a byte to the THR. ... If a second character arrives before the host reads the first from the RBR, a buffer overflow occurs, and data is lost."
> — p.784.e15

中文解釋：這是最原始的設計——**只有一個字元的緩衝**。9600 baud 下每 1 ms 就來一個字元，如果 CPU 沒在 1 ms 內讀走就丟資料。

> "More advanced UARTs have a first-in, first-out (FIFO) buffer on the transmitter and receiver so that the system can send and receive many characters before having to wait for buffers to empty. UARTs may also generate interrupts when the buffers are empty so that the host can do other work and get notified when the next character is ready."
> — p.784.e15

中文解釋：兩個改進——FIFO 緩衝和中斷。有了它們，CPU 不用一直輪詢。

### 為什麼是 16550

> "The original IBM PC used the 8250 UART in its COM port. At speeds above 9600 baud, the PC had trouble servicing interrupts fast enough to avoid buffer overflows. The 16550 UART [PC16550] added FIFOs while maintaining backward compatibility, and the register set for the 8250/16550 remains a widely used standard. ... RISC-V Linux has device drivers for UARTs compatible with the classic 16550, as well as the simpler SiFive FU540 UART [FU540]."
> — p.784.e15

中文解釋：這段解釋了 16550 為什麼會成為永久標準——**它加了 FIFO 但保持暫存器相容**，所以舊軟體繼續能跑、新軟體能用新功能。Linux 有現成的驅動程式，這是做一個 16550 相容 UART 的最大理由。

### 八個暫存器塞進八個位址

> "The PC16550 has a memory-mapped interface with eight 8-bit registers at offsets of 0−7 from the base address."
> — p.784.e16

中文解釋：Fig. 20.10 的暫存器表初看很混亂，因為**八個位址要塞進超過八個暫存器**，靠兩個技巧：

1. **讀寫不同**：offset 0 讀是 RBR（收到的資料）、寫是 THR（要送的資料）。offset 2 讀是 IIR（中斷識別）、寫是 FCR（FIFO 控制）。
2. **DLAB 換頁**：

> "Bit 3 of the LCR is the Divisor Latch Access Bit (DLAB). When DLAB is set, writes to address 0 and 1 set the low and high byte of the baud rate divisor, respectively, rather than the THR and IER. This divisor is normally programmed during initialization, and then DLAB is cleared."
> — p.784.e16–e17

中文解釋：**DLAB 是一個「換頁」開關**。設起來時，位址 0 和 1 變成除頻係數的低位元組（DLL）和高位元組（DLM）。因為除頻係數只在初始化時設一次，用完就把 DLAB 清掉，之後位址 0/1 恢復正常用途。這是 1980 年代省位址空間的典型手法。

八個暫存器的用途：
- **RBR/THR**（0）：收/發資料
- **IER**（1）：中斷致能
- **IIR/FCR**（2）：中斷識別 / FIFO 控制
- **LCR**（3）：Line Control——資料位元數、stop bit 數、parity、DLAB
- **MCR**（4）：Modem Control——DTR、RTS，**bit 4 是 Loop 欄位，設定 loopback 測試**
- **LSR**（5）：Line Status——錯誤狀態（parity error、overrun）、THR 空、資料就緒
- **MSR**（6）：Modem Status——更多握手訊號
- **SCR**（7）：Scratch——「一個位元組的隨意空間，現在幾乎沒用」

### 一個完整的 UART 程式

> "Write a function to configure the UART to operate at 9600 baud with eight data bits, one start bit, one stop bit, and no parity. Set the baud rate divisor to 65 as in the earlier example. Also write functions to send a character and receive a character."
> — p.784.e18（Example 20.4）

中文解釋：Example 20.4 的三個函式：

```c
void uartInit(void) {
  *UART_LCR = 0b10000011;  // 8 位元資料、1 stop bit、無 parity、DLAB=1
  *UART_DLL = 65;          // DLAB=1 所以這裡寫的是除頻係數
  *UART_LCR = 0b00000011;  // 清掉 DLAB
}

void uartSend(char c) {
  while (!(*UART_LSR & (1<<5)));  // 等 THRE（THR 空）
  *UART_THR = c;
}

char uartReceive(void) {
  while (!(*UART_LSR & (1<<0)));  // 等 DR（Data Ready）
  return *UART_RBR;
}
```

**注意 RBR、THR、DLL 的位址完全相同（0x10000000）**——靠讀/寫和 DLAB 區分。這正是前面兩個技巧的實際效果。`volatile` 再次必要，不然那兩個等待迴圈會變成無窮迴圈。

### 測試與實作

> "The general method of testing the UART is to transmit data in loopback mode under various configurations and check that the received data is correct. The tests check each configuration of the line control register. They verify that interrupts occur from the transmitter's line status register, the modem control register, and the FIFO. They also check that the receiver FIFO triggers thresholds and overflow."
> — p.784.e18

中文解釋：loopback 由 MCR 的 bit 4 開啟——這是**晶片本身就提供的功能**，不像 GPIO/SPI 需要 Wally 加設定參數。

> "Wally has a 16550-compatible UART. The logic is interesting to those who are curious how a serial port works, but it is too complex to describe in this chapter. Consult Wally's Verilog (src/uncore/uartPC16550D.sv) for details."
> — p.784.e19

中文解釋：書上直接承認太複雜不講。這本身就是一個訊息——**UART 是這五個周邊裡最複雜的**，因為它要處理非同步取樣、多種可設定格式、FIFO、以及一堆 modem 握手訊號。Fig. 20.11 的原廠方塊圖可以看出規模。

## 所以呢

UART 示範了一個「因為歷史限制而複雜，又因為相容性而無法簡化」的介面。它的核心技術——16 倍取樣加每字元重新對時——是所有非同步通訊的基本手法，值得理解。下一節的 SPI 則是完全相反的設計哲學：多拉一條時脈線，換取簡單、快速、幾乎沒有參數要對。
