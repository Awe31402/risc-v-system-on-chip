# 15.4 Wally Implementation

> 原書 p.607–614（Chapter 15: Extensions: M (Multiply and Divide)）
> 涵蓋 15.4.1 Multiplication、15.4.2 Division and Remainder、15.4.3 Multiply and Divide Unit、
> 15.4.4 Hazard Unit

## 這節在講什麼

**Wally 的 MDU（乘除單元）實作。**

**兩個單元的特性截然不同，這是本節的主軸：**

| | **乘法器（`mul`）** | **除法器（`div`）** |
| --- | --- | --- |
| 延遲 | **固定 2 週期**（Execute + Memory） | **長且可變**（32/k + 2 或 64/k + 2） |
| 吞吐量 | **每週期一條**（pipelined） | **一次只能一個**（不 pipelined） |
| 對 pipeline | 只需要 `MDUStallD` | **需要 `DivBusyE` stall Execute 級** |

**最該精讀的是 15.4.1 的「為什麼不直接寫 `x * y`」——
這是本章唯一一處偏離「交給合成工具」原則的地方，而理由很有說服力。**

## 關鍵點

### MDU 的整體定位

> "**Fig. 15.17 shows how Wally adds an optional multiply and divide unit (MDU). Multiplication takes place in the
>  Execute and Memory stages with a two-cycle latency. Division has a long latency, which stalls the pipeline and
>  delivers a result in the Memory stage.**"
> — p.607

> "**When the M extension is disabled but ZMMUL_SUPPORTED = 1 in the Wally configuration, Wally provides the
>  multiplier but not the divider.**"
> — p.607

中文解釋：**兩個組態旗標：M 擴充（含除法器）或只有 `ZMMUL_SUPPORTED`（只有乘法器）。**
（呼應 15.2.4 節。）

### 為什麼不直接寫 `x * y`（本節最有洞見的一段）

> "**RISC-V must support all flavors of signed and unsigned multiplication. SystemVerilog lacks a graceful mechanism
>  to express this. It would be possible to code the entire multiplier structurally, adding multiplexers to the
>  partial product generators from Fig. 15.7 to produce either signed or unsigned partial products.
>  **However, this would prevent logic synthesis tools from selecting their well-optimized adders or from mapping onto
>  hardware multiplier blocks on an FPGA.** Instead, our design observes that an N × N multiplier can be built from an
>  N-1 × N-1 multiplier and three other terms to handle the most significant bits. The N-1 × N-1 multiplier can be
>  expressed behaviorally to allow the logic synthesizer freedom to optimize.**"
> — p.607–608

中文解釋：**這段的推理鏈很值得學：**

```
1. 需求：要支援有號、無號、有號×無號三種乘法
2. 直接做法：結構化地寫整個乘法器，加多工器切換部分積的符號
3. 但這樣做的代價：
   - 合成工具無法選用它最佳化好的加法器
   - 無法映射到 FPGA 的硬體乘法器區塊
4. 更好的做法：把 N × N 拆成「一個 N−1 × N−1 的乘法器」+「三個處理 msb 的項」
   → N−1 × N−1 那塊用行為描述，讓合成工具自由最佳化
```

**「把難處理的部分（符號位元）分離出來，讓主體保持行為描述」——
這是一個很好的設計模式。**
（呼應 15.1.3.6 節：「最實用的做法是寫 `x * y`」——這裡是在盡可能遵守那個原則。）

### 數學推導

> "**Consider computing P = X × Y, with X and Y being N-bit numbers and P being the 2N-bit product. We can write
>  X = {X_{n-1}, X'}, with X_{n-1} being the most significant bit and X' = X_{n-2:0} being the remaining N-1 bits.
>  If X is treated as unsigned, its value is X' + (X_{n-1} × 2^{N-1}). If X is treated as a signed two's complement
>  number, its value is X' − (X_{n-1} × 2^{N-1}). The same applies to Y.**"
> — p.608

中文解釋：**關鍵洞見：有號和無號只差 msb 那一項的符號。**
```
無號：X = X' + X_{n-1} × 2^{N-1}
有號：X = X' − X_{n-1} × 2^{N-1}
```

**Table 15.5（p.608）定義四個部分積：**

| Term | Definition | Comments |
| --- | --- | --- |
| **P'** | **X' × Y'** | **N−1 × N−1 bit 乘法**（大的那塊） |
| PX | Y_{n-1} × X' | N−1 bit 部分積 |
| PY | X_{n-1} × Y' | N−1 bit 部分積 |
| P_msb | X_{n-1} × Y_{n-1} | **1-bit 部分積** |

**Table 15.6（p.608）三種版本的展開：**

| Flavor | X | Y | P |
| --- | --- | --- | --- |
| `mulhu` | Unsigned | Unsigned | **P' + (PX + PY)2^{N-1} + P_msb 2^{2N-2}** |
| `mulh` | Signed | Signed | **P' + (−PX + −PY)2^{N-1} + P_msb 2^{2N-2}** |
| `mulhsu` | Signed | Unsigned | **P' + (PX + −PY)2^{N-1} − P_msb 2^{2N-2}** |

**三種版本只差 PX、PY、P_msb 的符號——P' 完全相同。**

### 預先加總 1 的簡化

> "**The signed flavors involve some negative partial products. As in Fig. 15.5, these are produced by inverting the
>  bits and adding 1. This results in six 1s in the dot diagram, which can be simplified by pre-adding them.**"
> — p.608

中文解釋：**Fig. 15.18（p.609）的兩個部分：**
- **(a)** 負部分積被反相、符號延伸，各加一個 1（六個 1）
- **(b)** **四個簡化後的部分積**（1 已經預先加進去）

**Table 15.7（p.609）是簡化後的最終形式：**

| Flavor | P1 | P2 | P3 | **P4** |
| --- | --- | --- | --- | --- |
| `mulhu` | P' | (PX)2^{N-1} | (PY)2^{N-1} | **P_msb 2^{2N-2}** |
| `mulh` | P' | (P̄X)2^{N-1} | (P̄Y)2^{N-1} | **P_msb 2^{2N-2} + 2^{2N-1} + 2^N** |
| `mulhsu` | P' | (PX)2^{N-1} | (P̄Y)2^{N-1} | **P̄_msb 2^{2N-2} + 2^{2N-1} + 2^{N-1}** |

**書上的總結（p.609）：**
> "**In summary, each flavor of multiplication can be written as the sum of four partial products P = P1 + P2 + P3 + P4....
>  P1 involves a large N-1 × N-1 bit multiplication, and the other partial products are relatively small.
>  P4 accounts for the 1s from taking the two's complement, as well as the product of the sign bits.
>  The N least significant bits are the same for all flavors, so `mul` can be performed by doing any of these flavors
>  and then selecting the bottom half. Logic synthesis is good at optimizing large multiplications and the additions.**"

**「P4 同時處理二補數的 1 和符號位元的乘積」——把所有常數項集中到一處。**

**`mul` 的處理很聰明：隨便用哪個版本算，取低半部就好**（因為低 N 位元都一樣）。

**Example 15.2（p.609）的完整計算，X × Y = 1101 × 0110（−3 × 6 = −18）：**
```
X_{n-1} = 1,  X' = 101
Y_{n-1} = 0,  Y' = 110
P'    = X' × Y'          = 101 × 110 = 011110
PX    = Y_{n-1} × X'     = 0 × 101   = 000
PY    = X_{n-1} × Y'     = 1 × 110   = 110
P_msb = X_{n-1} × Y_{n-1} = 1 × 0    = 0
P1 = P'                  = 00011110
P2 = (P̄X) 2^{N-1}        = 00111000
P3 = (P̄Y) 2^{N-1}        = 00001000
P4 = P_msb 2^{2N-2} + 2^{2N-1} + 2^N = 10010000
P  = P1 + P2 + P3 + P4   = 11001000 + 00011110 = 11101110 = −18 ✓
```

### 乘法器的硬體

> "**Fig. 15.19 shows the integer multiplication unit (`mul`), which has a two-cycle latency. The Execute stage
>  generates partial products P1−P4 according to Table 15.7, and the Memory stage adds these products.
>  The slowest step is the N-1 × N-1 multiplier for P1.**"
> — p.610

中文解釋：**Fig. 15.19（p.610）的結構極簡：**
```
Execute 級：SrcAE, SrcBE, Funct3E → PPGen → PP1, PP2, PP3, PP4
           （經 pipeline 暫存器）
Memory 級： PP1..PP4 → CSA → CSA → CPA(+) → ProdM
```

**用兩層 CSA 加四個部分積，最後一個 CPA**——
正是 15.1.2 節 Fig. 15.1(c)(d) 的結構。

**「最慢的步驟是 P1 的 N−1 × N−1 乘法器」——這就是為什麼要讓合成工具自由最佳化它。**

### 除法器：可組態的每週期位元數

> "**Fig. 15.20 shows the Wally integer divide/remainder unit that computes Q = X/D and REM = X % D. It is based on the
>  design from Fig. 15.16. It is configurable to produce k = IDIV_BITSPERCYCLE = 1, 2, or 4 bits per cycle by
>  duplicating the core logic that many times (taking care that the divider doesn't become the critical path of the
>  processor).**"
> — p.610

中文解釋：**`IDIV_BITSPERCYCLE` = 1、2 或 4——**
**複製 `divstep` 那麼多份就能每週期多算幾個位元**
（呼應 15.1.4.3 節的最佳化）。

**注意括號裡的警告：「要小心除法器不要變成處理器的關鍵路徑」**——
複製越多，組合邏輯越深。

**Table 15.8（p.612）的延遲：**

| Architecture | `div`/`divu`/`rem`/`remu` | `divw`/`divuw`/`remw`/`remuw` |
| --- | --- | --- |
| **RV32M** | **32/k + 2** | n/a |
| **RV64M** | **64/k + 2** | **32/k + 2** |

**k = 4 時 RV64 的除法要 64/4 + 2 = 18 個週期。**

**除以 0 是特例（p.610）：「只要 2 個週期就完成」。**

### 除法器的資料流

> "**The inputs arrive at the top (Fig. 15.20) during the Execute stage, with X in SrcA and D in SrcB. RV64 handles
>  W-type operations in the shaded blue box by treating the inputs as 32-bit values: D is sign-extended to fill the
>  64-bit DinE, and the 32-bit value of X is placed in the top half of XInE so that only 32 division steps are
>  required to process. Negators and multiplexers take the absolute value of D and X during signed division.
>  On the first cycle, indicated by DivStartE, W is initialized to 0, XQ is initialized to X, and the absolute value
>  of D is registered.**"
> — p.610

中文解釋：**四個前處理步驟：**

| 步驟 | 做什麼 |
| --- | --- |
| **W-type 處理** | **D 符號延伸成 64-bit；X 放在 XInE 的上半部**（這樣只需要 32 步） |
| **取絕對值** | 有號除法時用 negator 和 mux（呼應 15.1.4.2 節） |
| **初始化** | `W = 0`、`XQ = X`、`|D|` 存進暫存器 |

**「X 放在上半部所以只需要 32 步」是個聰明的技巧**——
把 32-bit 的除法直接對映到 64-bit 硬體的前半。

**（p.610 邊欄的一個微妙細節：**
「即使 Execute 級的暫存器在除法期間被 stall，**`−|D|` 仍然被存在暫存器裡，
因為除數來自 `SrcBE`，而它來自 forwarding mux，
那些 mux 的值會隨著 Memory 和 Writeback 級的結果改變而改變。**」**
——這是一個很容易被忽略的 hazard！）

**迭代（p.610）：**
> "**The divider then iterates, with k copies of the restoring division hardware producing k bits of result on each
>  cycle. The pipeline stalls in the Execute stage while the iterations take place. After enough iterations, W and XQ
>  hold the absolute value of the remainder and quotient, respectively.**"

**後處理（p.612）：**
> "**Finally, the stall is released, and the divider continues to the Memory stage, in which it flips the sign of the
>  quotient and/or remainder when necessary for signed operations. Output multiplexers also choose the special case
>  values of X and all 1s for remainder/division by 0.**"

**Memory 級做兩件事：修正符號、處理除以 0 的特例。**
（呼應 15.2.2 節：除以 0 時商 = 全 1、餘數 = X。）

### 除法器的控制 FSM

> "**Fig. 15.21 shows the control logic. A simple finite state machine in Fig. 15.21(a) manages the sequencing through
>  Idle, Busy, and Done states to count the number of iterations needed and stall the pipeline appropriately.**"
> — p.612

中文解釋：**Fig. 15.21(a)（p.613）的三狀態機：**
```
reset | TrapM → Idle
Idle ──(DivStartE & ~Div0E)──→ Busy ──(Last step)──→ Done
Idle ──(DivStartE & Div0E)───────────────────────→ Done   ← 除以 0 跳過 Busy
Done ──(StallM)──→ Done（自環）
Done ──(~StallM)──→ Idle
```

**Fig. 15.21(b) 的兩個控制訊號：**
```
DivStartE = DivE & (state == IDLE) & ~StallM
DivBusyE  = DivStartE | (state == BUSY)
```

**書上的說明（p.612）：**
> "**It begins in the Idle state. When a division operation enters the Execute stage, DivE asserts, which causes
>  DivStartE to pulse high for a cycle.... Normally, the divider then enters the Busy state, which starts a step
>  counter. DivBusyE is raised on the starting cycle and while the divider is Busy, causing a StallE Execute stage
>  stall. After N steps, the FSM enters the Done state, and the division advances to the Memory stage.
>  **For division by 0, the FSM skips over Busy to complete in 2 cycles.** The divider registers are disabled to save
>  power (and simulation time) when idle.**"

**「閒置時停用除法器的暫存器以省電（和模擬時間）」**——
**注意「模擬時間」這個附帶好處**（沒有訊號切換就沒有事件，呼應 5.5 節的 event-driven 模擬）。

**Fig. 15.21(c) 的時序（N = 6，33/6 = 5 餘 3，p.612）：**

| Cycle | 發生什麼 |
| --- | --- |
| **1** | `XInitE = 100001`（33）、`DAbsBE = 000110`（6）、**`DivStartE` 脈衝** |
| **2–7** | **Execute 級 stall，除法進行。每步：W 左移 1 並移入 X 的下一個 bit，減 D 並比較得到 q_i** |
| | **同時 XQ 左移，丟棄 X 的 msb 並在前端加上藍色的商位元** |
| **8** | **結果在 `QuotM = 000101`（5）和 `RemM = 000011`（3）**，FSM 進入 Done，`StallE` 釋放 |

**（p.612 邊欄的取捨：**
「有些除法器會在餘數小於除數時提早終止。**我們的除法公式化方式讓 early termination 的硬體成本很低。
加上 early termination 需要一個昂貴的移位器，從 W 和 XQ 暫存器的可變位置抽出餘數和商。**」**
——這說明了 early termination 不是免費的。）

**（p.612 的一個重要選項：**
「浮點除法器用更精密的 recurrence 演算法，能在更短的週期時間內產生更多位元，而且處理 early termination。
**Wally 有 `IDIV_ON_FPU` 組態選項，把整數除法和餘數導向浮點除法器**（第 16.6.4 和 F.2.9 節）。
**這種統一的做法能有更低的延遲和更小的面積**，特別是像 rv32gc 這種浮點資料通路本來就比 XLEN 寬的組態。」**）

### MDU 的整合

> "**Fig. 15.22 shows a block diagram of the entire multiply and divide unit (MDU), omitting some control signals.
>  The unit contains the multiplier and divider that operate in the Execute and Memory stages. These are followed by a
>  result multiplexer that picks the quotient, remainder, or upper or lower half of the product based on the `funct3`
>  field of the instruction. Finally, in the RV64 configurations, to handle W-type instructions (`mulw`, `divw`,
>  `divuw`, `remw`, `remuw`), the bottom 32 bits of the result are sign-extended into the top 32.
>  The MDU's result is captured in a Writeback stage flip-flop, which connects to the IEU and forwarding logic.**"
> — p.613

中文解釋：**Fig. 15.22（p.614）的三層：**
```
Execute 級： SrcAE, SrcBE → mul、div（並行）→ DivBusyE 輸出
Memory 級：  ProdM(low/hi), QuotM, RemM → 8 選 1 mux（用 Funct3M）→ PrelimResultM
            → W64M 選擇是否符號延伸 → MulDivResultM
Writeback 級：MDUResultW → 到 IEU 的 Result Mux
```

**注意 `SrcAE`/`SrcBE` 來自「IEU forwarding muxes」——
所以 MDU 也受益於 forwarding（也因此有 p.610 邊欄那個 `−|D|` 要存起來的問題）。**

### Hazard 單元的兩個新訊號

> "**The multiplier is pipelined with a two-cycle latency (Execute + Memory) but a throughput of one instruction per
>  cycle. The divider also has a minimum two-cycle latency in special cases (division by zero), but it usually stalls
>  in the Execute stage for many cycles while completing the division. The multicycle division is not pipelined, so
>  only one divide can operate at a time. However, the next MDU instruction can issue when the division enters the
>  Memory stage.**"
> — p.614

中文解釋：**兩個 hazard，對應兩個訊號：**

**（1）`MDUStallD`（p.614）：**
> "**The MDU returns results in the Memory stage, so like other structural hazards, it stalls the Decode stage when the
>  next instruction depends on the result of the multiply or divide (MDUStallD = 1).**"

**和 load-use hazard 完全一樣的結構危障**（結果在 Memory 級才有，呼應 7.2.2.3 節）。

**（2）`DivBusyE`（p.614）——這個比較微妙：**
> "**The pipeline stalls at the Execute stage while the divider is busy. The divider FSM is reset to idle if the Execute
>  stage is flushed (FlushE). **However, when the IFU mispredicts the instruction class (BPPredWrongE) and needs to
>  flush the instructions currently in the Fetch and Decode stages by asserting FlushD and FlushE, it must wait for the
>  division to complete (~DivBusyE).**"

**這是一個真實的 corner case：**
**分支預測器誤預測要 flush，但除法器正在忙——必須等它完成。**

**Fig. 15.23（p.615）的 hazard 單元，藍色的兩處改動：**
```
Flush Cause Generation：DivBusyE 和 BPWrongE 做 AND → 影響 FlushECause
Stall Cause Generation：MDUStallD 加入 StructuralStallD 的 OR
                       DivBusyE 加入 StallECause
```

**注意 `StallECause` 是第一次被用到**——
前面幾章的 hazard 單元裡它一直是 0（Fig. 13.23 顯示 `StallECause` 是灰色的 0）。
**除法器是第一個需要 stall Execute 級的東西。**

## 所以呢

**這節的核心是「乘法和除法的特性截然不同」。五件最該帶走的事：**

1. **不直接寫 `x * y` 的理由很有說服力**：
   **要支援三種有號無號組合，而 SystemVerilog 沒有優雅的表達方式。**
   **解法：把 N × N 拆成「N−1 × N−1 的行為描述」加「三個處理 msb 的小項」**——
   讓合成工具能最佳化主體，也能映射到 FPGA 的硬體乘法器。

2. **三種乘法版本只差 PX、PY、P_msb 的符號**，P' 完全相同。
   **而 `mul` 隨便用哪個版本算、取低半部就好。**

3. **除法器的兩個聰明設計**：
   **W-type 把 X 放在上半部所以只需要 32 步**；
   **除以 0 跳過 Busy 狀態，2 週期完成。**

4. **除法器是第一個需要 stall Execute 級的東西**——
   前面所有章節的 `StallECause` 都是 0。
   **而且分支誤預測要 flush 時必須等除法完成（`~DivBusyE`）。**

5. **一個容易忽略的 hazard**（p.610 邊欄）：
   **`−|D|` 必須存進暫存器，因為 `SrcBE` 來自 forwarding mux，
   而那些 mux 的值會隨後面級的結果改變。**

下一節（15.5）是本章總結。
