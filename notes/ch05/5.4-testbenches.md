# 5.4 Testbenches

> 原書 p.204–206（Chapter 5: Design Verification）

## 這節在講什麼

**自我檢查 testbench 的標準骨架。**

核心概念是 **self-checking（自我檢查）**：
testbench 不只施加輸入，還**自己比對結果、自己數錯誤、自己決定何時停止**——
不需要人去看波形判斷對錯。

內容三塊：
1. **五個步驟的骨架**（Fig. 5.1）
2. **完整的全加器 testbench 範例**（Code Example 5.1）——這是整章最該精讀的一段程式碼
3. **testbench 專用的語法**（`$readmemb`、`$display`、`$stop` vs `$finish`、`===` vs `==`）

## 關鍵點

### Testbench 的五個步驟

> "*Testbenches* apply stimulus to a DUT, and preferably check that the results match
>  expectations. SystemVerilog offers a vast set of nonsynthesizable features for writing
>  testbenches, including generating clocks, reading files, and printing messages to the
>  screen."
> — p.204

> "A simple self-checking SystemVerilog testbench performs the following functions, as
>  illustrated in Fig. 5.1:
>  - Instantiate DUT.
>  - Generate clock and reset inputs.
>  - Read a set of *test vectors* (inputs and expected outputs) from a file.
>  - Apply the inputs on successive clock cycles and check the outputs.
>  - Log any mismatches."
> — p.204

中文解釋：**"preferably check that the results match expectations" 那個 preferably 很關鍵**——
只施加輸入而不檢查的 testbench 是半成品，**還是得靠人看波形。**

**Fig. 5.1（p.204）的結構（原書此處為方塊圖，以下為轉錄）：**
```
[Clock and Reset Generation] ──→ clk, reset ──→ ┐
                                                 │
[.tv testvector File] ──→ [Apply & Check         ├──→ [dut]
                            Testvectors]         │      inputs / outputs
                            ├─ inputs ───────────┘         │
                            └─ expected ──→ (比較器) ←──────┘
                                              ↓
                                       Report mismatches
```
**三個方塊：時脈與重置產生、測試向量施加與檢查、DUT。
測試向量從 `.tv` 檔案讀進來，比較器把 expected 和實際輸出比對。**

（注意：**object-oriented 那部分（UVM）超出本章範圍**，p.204。）

### 完整範例：全加器 testbench

中文解釋：Code Example 5.1（p.205）是全加器（4.2.1 節 Code Example 4.1）的 testbench。
**逐段拆解，這是整章最值得精讀的程式碼：**

**（1）宣告**
```systemverilog
module testbench();
  logic        clk, reset;
  logic        a, b, c, s, cout, sexpected, coutexpected;
  logic [31:0] vectornum, errors;          // 目前向量編號、錯誤數
  logic [4:0]  testvectors[10000:0];       // 測試向量陣列
```
**陣列寬 5 bit（3 個輸入 + 2 個輸出），深 10001 筆**——
書上說「即使把檔案改成更多向量也綽綽有餘」（p.205）。

**（2）實例化 DUT**
```systemverilog
  fulladder dut(a, b, c, s, cout);
```

**（3）產生時脈**
```systemverilog
  always
    begin
      clk = 1; #5; clk = 0; #5;
    end
```
**`always` 沒有 sensitivity list 就是「永遠重複」**（p.206）。
**週期 10 個時間單位。**

**（4）初始化：載入向量、脈衝 reset**
```systemverilog
  initial
    begin
      $dumpfile("fulladder.vcd");
      $dumpvars;
      $readmemb("fulladder.tv", testvectors);
      vectornum = 0; errors = 0;
      reset = 1; #22; reset = 0;
    end
```
**`initial` 只在模擬開始執行一次**（p.206）。
**`reset` 維持「略多於兩個週期」（22 個 tick）**——
比 20 多一點是為了確保跨過時脈邊緣。

**（5）在時脈上升緣施加輸入**
```systemverilog
  always @(posedge clk)
    begin
      #1; {a, b, c, coutexpected, sexpected} = testvectors[vectornum];
    end
```
**`#1` 是關鍵：在時脈邊緣「之後」才改變輸入**，避免競爭條件。

**（6）在時脈下降緣檢查輸出**
```systemverilog
  always @(negedge clk)
    begin
      if (~reset) begin                      // 重置期間跳過檢查
        if (s !== sexpected | cout !== coutexpected) begin
          $display("Error: inputs = %b", {a, b, c});
          $display("  outputs cout s = %b%b (%b%b expected)",
                   cout, s, coutexpected, sexpected);
          errors = errors + 1;
        end
        vectornum = vectornum + 1;
        if (testvectors[vectornum] === 'bx) begin
          $display("%d tests completed with %d errors", vectornum, errors);
          $stop;
        end
      end
    end
```

**這段的四個設計要點：**
1. **上升緣施加、下降緣檢查**——半個週期的間隔讓輸出穩定下來
2. **`if (~reset)` 跳過重置期間的檢查**
3. **錯誤時印出訊息並累加計數，但不停止**——繼續跑完所有向量
4. **用「讀到全 x」當結束條件**（`testvectors[vectornum] === 'bx`）——
   **陣列裡沒載入的部分自然是 x，所以不用額外記錄向量數量。很巧妙。**

### Testbench 專用語法

> "$dumpfile and $dumpvars write a Verilog Change Dump (.vcd) file used in Section 5.5.2 to
>  view waveforms after a Verilator simulation; **they are unnecessary for other simulators.**
>  $readmemb reads a text file in binary format into a memory array; $readmemh does the same
>  in hexadecimal format. $display writes to the console. $stop halts a simulation.
>  initial statements are run once at the start of a simulation. always statements without a
>  sensitivity list are repeated forever."
> — p.206

中文解釋：**速查表：**

| 語法 | 作用 |
| --- | --- |
| `$dumpfile` / `$dumpvars` | 產生 VCD 波形檔。**只有 Verilator 需要**，其他模擬器不用 |
| `$readmemb` / `$readmemh` | 從文字檔讀入記憶體陣列（二進位 / 十六進位） |
| `$display` | 印到主控台 |
| `$stop` / `$finish` | 停止模擬（兩者差別見下） |
| `initial` | 模擬開始時執行一次 |
| `always`（無 sensitivity list） | 永遠重複 |

### `===` vs `==`：容易忽略但重要

> "Testbenches use === and !== instead of == and != for equality and inequality comparison
>  to work properly on signals that might include x or z."
> — p.206

中文解釋：**這個區別一定要記住：**

| 運算子 | 行為 |
| --- | --- |
| `==` / `!=` | 遇到 x 或 z 會回傳 **x**（不確定），而不是 0 或 1 |
| **`===` / `!==`** | **逐位元精確比較，x 和 z 也參與比較**，結果一定是 0 或 1 |

**為什麼 testbench 一定要用 `===`：**
- 上面那個「讀到全 x 就結束」的判斷 `testvectors[vectornum] === 'bx`
  **用 `==` 會回傳 x，`if` 判斷就不成立，測試永遠不會結束。**
- 檢查結果時用 `!==`，**DUT 輸出 x 時才會被抓出來報錯**
  （用 `!=` 會得到 x，`if` 不成立，**x 的 bug 就被漏掉了**）

（呼應 4.2.2.3 節：x 是 bug 的訊號，不能讓它被吞掉。）

### 測試向量檔案

中文解釋：Code Example 5.2（p.206）的 `fulladder.tv`：
```
// abc_cout s
000_00
001_01
010_01
011_10
100_01
101_10
110_10
111_11
```

**三個特點（p.206）：**
- **這是窮舉測試**（3 個輸入 = 8 個向量，呼應 5.1.1 節）
- **底線只是為了可讀性，會被忽略**
- **可以用 `//` 寫註解**

**格式就是「輸入位元 + 預期輸出位元」串在一起**，
對應 testbench 裡的 `{a, b, c, coutexpected, sexpected}`。

### `$stop` vs `$finish`

> "A testbench may halt with $stop or $finish. $stop suspends the simulation. This is useful
>  in a graphical user interface environment where the user may want to inspect the waveforms
>  for troubleshooting. $finish(errcode) terminates the simulation and prints a diagnostic
>  message according to Table 5.3. If errcode is omitted, it defaults to 1."
> — p.206

中文解釋：**兩者的差別是「暫停」還是「終止」：**

| | 行為 | 適合 |
| --- | --- | --- |
| **`$stop`** | **暫停**模擬 | **GUI 環境**，使用者要檢查波形除錯 |
| **`$finish(errcode)`** | **終止**模擬，並依錯誤碼印出診斷訊息 | 批次執行 |

**Table 5.3（p.206）的 `$finish` 錯誤碼：**

| errcode | 診斷訊息 |
| --- | --- |
| 0 | 無 |
| **1（預設）** | 模擬時間與 `$finish` 的位置 |
| 2 | 模擬時間、位置，加上記憶體統計 |

**工具偏好不同（p.206 邊欄）——這個細節會踩到：**
> "Questa prefers $stop when the testbench is done applying vectors; $finish terminates
>  without an opportunity to generate coverage statistics or inspect waveforms. However,
>  **Verilator prefers to halt the testbench with $finish.**"

**Questa 用 `$stop`（否則來不及產生覆蓋率統計），Verilator 用 `$finish`。**
所以同一份 testbench 換模擬器時可能要改這一行。

## 名詞表

| 名詞 | 意思 |
| --- | --- |
| **Self-checking testbench** | 自我檢查測試平台。自行比對結果、計數錯誤、決定何時停止 |
| Test vector | 測試向量。一組輸入加上預期輸出 |
| `.tv` file | 測試向量檔 |
| `$readmemb` / `$readmemh` | 以二進位 / 十六進位格式從檔案讀入記憶體陣列 |
| `$dumpfile` / `$dumpvars` | 產生 VCD 波形檔（Verilator 需要） |
| VCD | Verilog Change Dump，波形檔格式 |
| `$display` | 印到主控台 |
| **`===` / `!==`** | **精確比較，x 和 z 也參與**；testbench 必用 |
| `$stop` / `$finish` | 暫停（Questa 偏好）/ 終止（Verilator 偏好）模擬 |
| `initial` / `always`（無 sensitivity list） | 開始時執行一次 / 永遠重複 |

## 所以呢

**self-checking testbench 的骨架是固定的：
實例化 DUT → 產生時脈與重置 → 從檔案讀向量 → 上升緣施加、下降緣檢查 → 記錄不符。**

三個容易踩到的細節：
1. **testbench 一定要用 `===` 和 `!==`**——否則 x 會讓判斷永遠不成立，
   既抓不到 x 的 bug，也可能讓測試永遠不結束。
2. **施加輸入時加 `#1` 延遲**，避開時脈邊緣的競爭條件。
3. **`$stop` 和 `$finish` 的工具偏好不同**：Questa 用前者（要產覆蓋率），
   Verilator 用後者。

**「讀到全 x 就結束」是個值得學的小技巧**——利用未初始化陣列自然是 x 的特性，
不必額外記錄向量數量。
