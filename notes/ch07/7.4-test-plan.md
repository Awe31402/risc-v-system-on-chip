# 7.4 Test Plan

> 原書 p.329–333（Chapter 7: Pipelined Core）

## 這節在講什麼

**這一章的驗證計畫：用 `riscv-arch-test` 測所有整數指令。**

三塊內容：
1. **測試怎麼產生**：**constrained random test generator（riscv-ctg）+ 約束檔**
2. **`addi` 的約束檔實例**（Code Example 7.3）——**這是本節最值得學的部分**
3. **測試數量統計**（Table 7.10）與**這套測試的三個限制**

## 關鍵點

### 測試套件與涵蓋範圍

> "The instructions are tested using the riscv-arch-test suite [riscv-arch-test]. **This is an
>  evolving set of tests provided by RISC-V International to offer a basic level of confidence that
>  an implementation conforms to the RISC-V specification.**"
> — p.329

> "The configuration in this chapter supports the **rv32i_m/I, rv32e_m/E, or rv64i_m/I suite of
>  tests.** These include a collection of tests for each of the RV32I or RV64I unprivileged
>  instructions. **Each instruction has a series of tests produced by the RISC-V constrained random
>  test generator, riscv-ctg. The tests perform an operation and then write a result called the
>  *signature* to memory. If the full set of signatures produced by the device under test matches a
>  reference signature, the test suite passes.**"
> — p.329

中文解釋：呼應 3.7 節。**注意措辭是 "a basic level of confidence"（基本程度的信心）**——
不是完整驗證。

**測試由 `riscv-ctg`（constrained random test generator）產生**，
機制是 signature 比對（呼應 3.3.8 節）。

### 約束檔：定義「該測哪些運算元」

> "The constrained random test generator is driven by a configuration file that lists the constraints
>  for each instruction [crtg]. Code Example 7.3 lists the constraints for the addi instruction.
>  **It tests all the different registers being used for rs1 and rd, including cases where rs1 and rd
>  are the same register. To test a range of operand values, it selects values including 0, 1, the
>  most negative, the most positive, walking ones, walking zeros, alternating bits, and random
>  values, including operand pairs that are equal, unequal, and that have each of the four patterns
>  of signs.**"
> — p.329

中文解釋：**這份清單是本節精華。整理成表：**

| 約束類別 | 涵蓋什麼 |
| --- | --- |
| **暫存器** | **所有暫存器都當過 rs1 和 rd，包括 rs1 == rd 的情況** |
| **極值** | **0、1、最負值（−2^(XLEN−1)）、最正值（2^(XLEN−1)−1）** |
| **Walking ones** | **全 0 只有一個 1，1 往左走**（00…001、00…010、00…100…） |
| **Walking zeros** | **全 1 只有一個 0，0 往左走** |
| **Alternating bits** | 交替位元（0101…、1010…） |
| **隨機值** | — |
| **運算元對的關係** | **相等、不相等、四種符號組合** |

**（p.329 定義了 walking ones/zeros：
「Walking ones 從全 0 只有最低位是 1 開始，那個 1 往左移；
walking zeros 類似但從全 1 開始，0 往左走。」）**

**Walking ones/zeros 的用途和 5.9 節的 toggle coverage 一樣：
抓「某一個位元接錯」的 bug。**

**Code Example 7.3（p.330）的實際 YAML 約束檔節錄：**
```yaml
addi:
  config:
    - check ISA:=regex(.*I.*)
  opcode:
    addi: 0
  rs1:
    <<: *all_regs
  rd:
    <<: *all_regs
  op_comb:
    <<: *ifmt_op_comb
  val_comb:
    <<: [ *ifmt_val_comb_sgn, *base_rs1val_sgn, *ifmt_base_immval_sgn]
    abstract_comb:
      'sp_dataset(xlen,["rs1_val",("imm_val",12)])': 0
      <<: [*rs1val_walking, *ifmt_immval_walking]

ifmt_val_comb_sgn: &ifmt_val_comb_sgn
  'rs1_val == imm_val': 0
  'rs1_val != imm_val': 0
  'rs1_val > 0 and imm_val > 0': 0
  'rs1_val > 0 and imm_val < 0': 0
  'rs1_val < 0 and imm_val > 0': 0
  'rs1_val < 0 and imm_val < 0': 0

base_rs1val_sgn: &base_rs1val_sgn
  'rs1_val == (-2**(xlen-1))': 0
  'rs1_val == 0': 0
  'rs1_val == (2**(xlen-1)-1)': 0
  'rs1_val == 1': 0

ifmt_base_immval_sgn: &ifmt_base_immval_sgn
  'imm_val == (-2**(12-1))': 0
  'imm_val == 0': 0
  'imm_val == (2**(12-1)-1)': 0
  'imm_val == 1': 0

rs1val_walking: &rs1val_walking
  'walking_ones("rs1_val", xlen)': 0
  'walking_zeros("rs1_val", xlen)': 0
  'alternate("rs1_val",xlen)': 0
```

**三個值得注意的設計：**

1. **`&name` 和 `<<: *name` 是 YAML 的錨點與合併**——
   **定義一次、多條指令共用。**
   （例如 `base_rs1val_sgn` 可以被所有用 rs1 的指令引用。）

2. **極值用公式寫而非寫死數字**：
   `-2**(xlen-1)`、`2**(xlen-1)-1`——**所以 RV32 和 RV64 共用同一份約束。**
   **立即值用 `2**(12-1)-1` 因為它是 12-bit。**

3. **`ifmt_val_comb_sgn` 的六種組合是完整的**：
   相等、不相等、以及**四種符號組合**（++、+−、−+、−−）。
   （呼應 5.9 節 Table 5.5 的 `cr_rs1_rs2` cross coverage。）

### 測試數量：Table 7.10

> "Table 7.10 lists the number of test cases per instruction for RV32I, RV32E, and RV64I.
>  **These statistics can be found using `$WALLY/bin/testcount.pl`. The tests are continually
>  evolving, and the test count has increased slightly since this data was last collected in 2022.
>  All these load and store tests are aligned so they do not cause misalignment faults** (see Section
>  8.2.5). **RV64 has more test cases because there are more operand values to cover.**"
> — p.330

中文解釋：**Table 7.10（p.331–332）的總計：**

| | RV32I | RV32E | RV64I |
| --- | --- | --- | --- |
| **Total** | **12,642** | **12,521** | **17,836** |

**幾個代表性的數字：**

| 指令 | RV32I | RV64I | 觀察 |
| --- | --- | --- | --- |
| `add-01` | 588 | 679 | R-type ALU 約 580–680 |
| `addi-01` | 561 | 619 | |
| **`bgeu-01`** | **726** | **821** | **無號分支測試最多** |
| **`auipc-01`** | **64** | **63** | **U-type 很少**（沒有暫存器運算元組合） |
| **`lui-01`** | **63** | **63** | 同上 |
| **`jal-01`** | **32** | **32** | **只有 rd 一個暫存器** |
| `jalr-01` | 33 | 33 | |
| **`lw-align-01`** | **32** | **32** | load 測試很少 |
| **`sll-01`** | **89** | **153** | **移位少很多**（移位量只有 5 或 6 bit） |
| **`sb-align-01`** | **70** | **135** | |
| **`fence-01`** | **1** | **1** | **只有一個測試**（在這章是 NOP） |
| `misalign1-jalr` | 1 | 1 | |

**三個規律值得注意：**
1. **ALU 指令（兩個暫存器運算元）測試最多**（約 560–730）
2. **移位指令少很多**（約 88–154）——因為移位量的範圍小
3. **U-type 和 jump 最少**（32–64）——運算元組合少

**RV32E 的總數（12,521）幾乎等於 RV32I（12,642）**——
**暫存器少一半，但測試數只少 1%**（因為主要是運算元值的組合，不是暫存器組合）。
但個別指令有差：`jal-01` 從 32 掉到 16、`lb-align-01` 從 33 掉到 18。

**RV64I 多出的指令**：`addiw`、`addw`、`ld`、`lwu`、`sd`、
`slliw`、`sllw`、`sraiw`、`sraw`、`srliw`、`srlw`、`subw`——
**正好對應 Table 7.1 的 RV64I 額外指令。**

### 這套測試的三個限制（很重要）

> "**The riscv-arch-test suite has several limitations. It does not test interactions between
>  instructions, such as those that cause pipeline hazards. It also has limited coverage of the
>  instruction operands. Wally uses other functional coverage tests to fill these gaps.**"
> — p.333

中文解釋：**三個限制，每一個都很關鍵：**

| 限制 | 為什麼重要 |
| --- | --- |
| **不測指令之間的交互作用** | **整個 7.2 節講的 hazard 完全沒被測到！** |
| **運算元涵蓋有限** | 雖然有 walking ones 等，但不完整 |
| — | **要靠其他功能覆蓋率測試補**（第 5.9 節） |

**第一點特別諷刺：這一章最難的部分（hazard 單元）
正好是官方測試套件不涵蓋的。**
（呼應 7.2.2.4 節邊欄：「hazard 單元是很多微妙 bug 的來源」，
以及 3.7 節：「通過官方測試是商標門檻，不是正確性保證」。）

**跑回歸測試的方法見第 5.11.6 節**（p.333）。

## 名詞表

| 名詞 | 意思 |
| --- | --- |
| `riscv-arch-test` | RISC-V 官方架構測試套件 |
| **`riscv-ctg`** | RISC-V constrained random test generator |
| Signature | 測試寫到記憶體的結果，用來和參考值比對 |
| **Walking ones / zeros** | 全 0 中一個 1（或全 1 中一個 0）逐位移動；抓「某位元接錯」的 bug |
| `$WALLY/bin/testcount.pl` | 統計各指令測試數量的腳本 |
| `-align` 後綴 | 對齊的 load/store 測試（不觸發 misalignment fault） |

## 所以呢

**這一章用 `riscv-arch-test` 測所有整數指令，RV32I 有 12,642 個測試、RV64I 有 17,836 個。**

兩件最該帶走的事：

1. **約束檔定義的那份清單，就是「一條 ALU 指令該測哪些運算元」的通用答案**：
   **所有暫存器組合（含 rs1 == rd）、極值（0/1/最正/最負）、
   walking ones/zeros、交替位元、隨機值、以及運算元對的六種關係。**

2. **這套測試的最大盲點：完全不測指令之間的交互作用，
   也就是整個 7.2 節的 hazard 機制。**
   **要靠第 5.9 節的功能覆蓋率測試（`cp_gpr_hazard`）來補。**
