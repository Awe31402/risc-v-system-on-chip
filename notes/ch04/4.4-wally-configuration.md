# 4.4 Wally Configuration

> 原書 p.190–191（Chapter 4: HDL Design Practices）

## 這節在講什麼

**很短，但實用性很高：Wally 的組態檔放在哪、怎麼產生、怎麼檢查。**

四件事：
1. **基本組態**（base configurations）的路徑
2. **衍生組態**（derived configurations）——用來測試選配功能的微調版本
3. 兩個特別的衍生組態：**buildroot 和 fpga**（開 Linux 用）
4. **`riscvassertions`**——自動檢查組態參數是否合法

**這節是「要改 Wally 的組態時，該去動哪個檔案」的答案。**

## 關鍵點

### 基本組態的路徑

> "As described in Section 2.8.2, Wally is configurable to scale from a tiny rv32e core to
>  simple rv{32/64}i cores to an rv32imc microcontroller with peripherals to rv{32/64}gc
>  application processors with floating-point, branch prediction, caches, and virtual
>  memory, all using the same code base. Each configuration is defined by:
>  `$WALLY/config/<configname>/config.vh`"
> — p.190

中文解釋：**一份程式碼、多種組態**（呼應 2.8.2 節）。

**路徑要記住：`$WALLY/config/<configname>/config.vh`**
例如 `$WALLY/config/rv64gc/config.vh`（呼應 4.2.5.6 的 Code Example 4.37）。

repository 的完整結構在 Fig. A.1（Appendix A）。

### 衍生組態：測試選配功能的微調版

> "In addition, Wally has many *derived configurations*, which are perturbations of the base
>  configurations. They are used to test optional features, such as whether caches are
>  enabled, how branch predictors perform with different table sizes, and whether various
>  combinations of floating-point data sizes can be supported."
> — p.190

> "These derived configurations are summarized in Table A.5 and defined in:
>  `$WALLY/config/deriv/<configname>/config.vh`
>  The derived configurations are generated with the bin/derivgen.pl script using the
>  config/derivlist.txt table. They are regenerated by running sim/make deriv or sim/make."
> — p.190

中文解釋：**「衍生組態」的概念要搞清楚：不是新的組態，是基本組態的微調版。**

用途是**測試選配功能的各種組合**：
- cache 開或關
- 分支預測器不同表格大小的效能
- 各種浮點資料大小組合能否支援

**這類組合爆炸式很多，所以用腳本自動產生：**

| 項目 | 位置/指令 |
| --- | --- |
| 定義表 | `config/derivlist.txt` |
| 產生腳本 | `bin/derivgen.pl` |
| 產生結果 | `$WALLY/config/deriv/<configname>/config.vh` |
| 重新產生 | **`sim/make deriv` 或 `sim/make`** |
| 清單 | Table A.5 |

**這是很典型的工程做法：手寫基本組態，衍生組合用腳本產生。**
（呼應 4.2.5 節：Wally 把可組態性推到極致。）

### 兩個特別的衍生組態：buildroot 和 fpga

> "Two notable derived configurations are buildroot and fpga, intended to boot Linux in
>  simulation and on an FPGA. These are variants of rv64gc, with the reset vector pointing
>  to a boot ROM at 0x1000 with a zero-stage boot loader."
> — p.190

中文解釋：**這兩個要記住，第 22、23 章會用到：**

| 組態 | 用途 | 特徵 |
| --- | --- | --- |
| **buildroot** | **在模擬中開 Linux**（第 22 章） | rv64gc 變體，**reset vector 指向 0x1000 的 boot ROM**，內含 zero-stage boot loader |
| **fpga** | **在 FPGA 上開 Linux**（第 23 章） | 同上 |

**reset vector 是 0x1000 而非 0x80000000**——呼應 2.4 節：
真實開機流程要先跑 boot ROM 裡的 boot loader，再載入 OS。
（也呼應 3.6 節：QEMU 的 bootloader 也在 0x1000。）

### 組態如何被使用

> "Simulation and synthesis scripts point to the desired configuration. The config.vh file
>  defines many parameters used in SystemVerilog generate blocks. Table A.3 lists key
>  configuration parameters for each configuration, and Table A.4 lists additional
>  configuration parameters."
> — p.190

中文解釋：**`config.vh` 定義的參數餵給 SystemVerilog 的 generate 區塊**
（呼應 4.2.5.3 的 conditional generate）。

**參數清單在 Appendix A：Table A.3（各組態的關鍵參數）、Table A.4（其他參數）。**

原始碼在 **`$WALLY/src`，每個單元一個子目錄**（p.190）。

### riscvassertions：自動檢查組態合法性

> "testbench.sv has a module called riscvassertions that checks legal values for
>  configuration parameters. Examples of checks include:
>  - Optional supported modes are self-consistent (e.g., D requires F).
>  - Parameters have a limited set of legal values (e.g., PMP_ENTRIES = 0, 16, or 64).
>  - Cache organization is legal (e.g., way size doesn't exceed VM page size)."
> — p.190–191

中文解釋：**這是防呆機制，值得學這個設計思路。**

**問題**：組態參數多到爆炸，很容易設出不合法的組合，
而且錯誤可能要等到模擬跑很久之後才浮現。

**解法**：在 `testbench.sv` 裡放一個 `riscvassertions` 模組，
**模擬一開始就檢查所有參數的合法性**（用 4.2.4.7 節的 `assert`）。

**三類檢查很有代表性：**

| 類型 | 例子 | 為什麼 |
| --- | --- | --- |
| **內部一致性** | **D 擴充需要 F** | 雙精度浮點建立在單精度之上（呼應 2.5 節） |
| **合法值集合** | `PMP_ENTRIES` 只能是 0、16、64 | 規格限制 |
| **結構合法性** | **cache 的 way 大小不能超過虛擬記憶體 page 大小** | 否則會有 aliasing 問題（第 10、11 章） |

**這是「fail fast」的實踐：與其讓錯誤組態跑出莫名其妙的結果，
不如一開始就報錯。**

## 名詞表

| 名詞 | 意思 |
| --- | --- |
| Base configuration | 基本組態。`$WALLY/config/<configname>/config.vh` |
| **Derived configuration** | **衍生組態**。基本組態的微調版，用來測試選配功能；`config/deriv/` 下 |
| `derivlist.txt` / `derivgen.pl` | 衍生組態的定義表 / 產生腳本 |
| `sim/make deriv` | 重新產生衍生組態 |
| **buildroot / fpga** | 開 Linux 用的衍生組態（模擬 / FPGA）。rv64gc 變體，reset vector 在 0x1000 |
| Zero-stage boot loader | boot ROM 中最初階的開機載入程式 |
| **`riscvassertions`** | `testbench.sv` 中檢查組態參數合法性的模組 |

## 所以呢

**要改 Wally 的組態，答案是 `$WALLY/config/<name>/config.vh`；
要測試選配功能的組合，用 `config/derivlist.txt` 加一筆再跑 `sim/make deriv`。**

兩個要記住的細節：
1. **buildroot 和 fpga 是開 Linux 用的衍生組態**，reset vector 在 0x1000 而非 0x80000000。
2. **`riscvassertions` 會在模擬開始時檢查組態合法性**——
   組態參數多到需要自動防呆，這本身就說明了 Wally 可組態性的規模。
