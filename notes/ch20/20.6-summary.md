# 20.6 Summary

> 原書 p.784.e23（Chapter 20: Peripherals）

## 這節在講什麼

第 20 章的總結，兩段話。第一段回顧五個周邊，第二段點出它們共通的存取機制。

## 關鍵點

### 五個周邊各自的角色

> "RISC-V systems commonly use a Core Local Interruptor (CLINT) to generate timer and software interrupts, and a Platform-Level Interrupt Controller (PLIC) to collect external interrupts from other peripherals and route them to machine or supervisor external interrupts of a core. They often have other peripherals such as a general-purpose I/O (GPIO) to read and write digital pins, a universal asynchronous receiver/transmitter (UART) for COM port communication, and a Serial Peripheral Interface (SPI) for higher-speed synchronous serial communication."
> — p.784.e23

中文解釋：可以分成兩類——**CLINT 和 PLIC 是中斷基礎設施**（讓核心知道外面發生了什麼），**GPIO、UART、SPI 是真正的 I/O**（和外面交換資料）。

### de facto standard 的重要性

> "The SiFive implementations of these peripherals are a de facto RISC-V standard with OS device driver support."
> — p.784.e23

中文解釋：這句話是整章最實用的結論。**選用事實標準的價值在於 OS 驅動程式已經寫好了**。自己設計一個更漂亮的 UART，代價是要自己寫並維護 Linux 驅動程式——這個成本遠高於硬體設計本身（呼應第 19.6 節講自訂擴充時的同一個教訓）。

### memory-mapped I/O 的完整路徑

> "The peripherals use memory-mapped I/O such that processor loads or stores to certain addresses interact with the hardware and external world, instead of memory. The PMA checker detects accesses to addresses in the peripherals, memory map and generates the corresponding AHB HSEL. The AHB-to-APB bridge in the uncore provides a simple synchronous interface to each peripheral with a few bits of PADDR to select the peripheral and PRDATA/PWDATA to read and write data busses."
> — p.784.e23

中文解釋：這段把前面各章串起來，完整的存取路徑是：

```
lw/sw 指令
  → LSU（第 12 章）
  → PMA checker（第 11 章）辨認出這是周邊位址，產生 AHB HSEL
  → EBU / AHB（第 9 章）
  → AHB-to-APB bridge（第 9 章）
  → 周邊的 APB 介面：PADDR 選暫存器、PRDATA/PWDATA 傳資料
```

**PMA checker 在這裡扮演了關鍵角色**——它不只是做權限檢查，也負責決定「這個位址要送到哪裡」。而且它標記的屬性（可不可快取、支不支援原子操作）直接影響前幾章講過的行為：周邊區域不可快取，所以 load/store 一定會走到匯流排；也不允許 AMO（第 17 章）和 CMO（第 19 章）。

## 名詞表

| 名詞 | 意思 |
| --- | --- |
| uncore | 核心之外、晶片之內的部分（周邊、匯流排、記憶體控制器） |
| HSEL | AHB 的周邊選擇訊號，由 PMA checker 的位址解碼產生 |
| PADDR / PRDATA / PWDATA | APB 的位址／讀取資料／寫入資料匯流排 |
| device driver | 作業系統中控制周邊的軟體 |

## 所以呢

到這裡，一台完整的電腦所需的硬體都講完了——核心（第 1–19 章）加上周邊（第 20 章）。剩下的章節換一個視角：**怎麼知道它跑得好不好**（第 21 章 Benchmarking）、**怎麼讓它跑真正的作業系統**（第 22 章 Booting Linux）、以及**怎麼把它做到真實的硬體上**（第 23 章 FPGA）。
