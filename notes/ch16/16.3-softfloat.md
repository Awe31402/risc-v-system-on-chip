# 16.3 SoftFloat

> 原書 p.641–646（Chapter 16: Extensions: F/D/Q/Zfh/Zfa (Floating-Point)）
> 涵蓋 16.3.1 SoftFloat Demo、16.3.2 fpcalc

## 這節在講什麼

寫完 FPU 硬體要怎麼知道算對了？浮點的 corner case 多到不可能手算驗證。答案是拿一個公認正確的軟體實作當「標準答案」，這就是 UCB SoftFloat——John Hauser 寫的開源浮點函式庫。RISC-V 官方把它當參考模型（reference model），Wally 也用它產生測試向量。這節示範兩個小工具：`softfloat_demo`（怎麼呼叫 SoftFloat 的 API）和 `fpcalc`（一個十六進位浮點計算機，debug 測試案例時很好用）。

## 關鍵點

### 為什麼需要參考模型

> "Checking floating-point arithmetic is notoriously difficult, so we need a reliable reference model. John Hauser has developed the open-source UCB SoftFloat library [Hauser18] that defines float_16t, float_32t, float_64t, and float_128t and operations on these types, including add, sub, mul, div, sqrt, mulAdd (FMA), remainder, comparisons, and type conversions."
> — p.641

中文解釋：這和第 13 章驗證那套思路一樣：硬體要有一個獨立實作當對照。SoftFloat 在 `cvw/addins/berkeley-softfloat-3` 目錄下。配套的 TestFloat 工具能自動產生 corner case 測試向量。

### SoftFloat 的 API 形狀

> "For example, f64_mulAdd takes three float64_t arguments and produces a float64_t result. The softfloat_roundingMode global variable specifies the rounding mode."
> — p.641

中文解釋：函式名的規律是 `f<精度>_<運算>`。捨入模式和旗標不是參數，而是全域變數——`softfloat_roundingMode` 設模式、`softfloat_exceptionFlags` 讀旗標。這正好對應硬體上的 `fcsr` CSR（下一節會講），所以參考模型和硬體的介面是一致的。

### 初始化 SoftFloat 的三件事

> "The program initializes SoftFloat by setting the rounding mode to RNE, clearing the flags, and setting the underflow logic to detect tininess before rounding (the default for RISC-V)."
> — p.643

中文解釋：Code Example 16.1 的 `softfloatInit()` 做這三件事。第三件最容易忽略：16.1.4 講過 underflow 的判定有「捨入前」與「捨入後」兩種流派，RISC-V 選的是——注意這裡書上寫 before，但 16.4.1 明確說 RISC-V detects tininess *after* rounding（p.648），兩處說法不一致，以 16.4.1 與程式碼 `softfloat_tininess_afterRounding` 為準。

### float32_t 是一個結構，不是 C 的 float

> "SoftFloat declares float32_t to be a 32-bit number with a value field (or member) .v that can be written with an ordinary unsigned number, so x.v = 0x3fc00000 gives that hexadecimal pattern to x, equivalent to 1.5."
> — p.643

中文解釋：這樣設計是為了避免編譯器把運算交給主機的 FPU。用 `union sp { uint32_t v; float f; }` 就能在「位元樣貌」和「數值」兩種視角間切換——列印時用 `.f`，寫入測試樣式時用 `.v`。

### softfloat_demo 的輸出

> "The program uses SoftFloat to compute 1.5 × 1.5 + the smallest subnormal number (1.4013e−45). It prints the results (rounded to 2.25) and the flags (Inexact is set because of the rounding)."
> — p.643

中文解釋：這個例子選得很巧：2.25 加上一個極小的 subnormal，結果在單精度下完全表示不出那個增量，所以答案還是 2.25，但 Inexact 旗標被設起來。這就是硬體必須複製的行為——答案對不夠，旗標也要對。

### fpcalc：十六進位浮點計算機

> "examples/fp/fpcalc contains a simple floating-point calculator that performs computations on half-, single-, or double-precision floating-point numbers in hexadecimal form and reports the results in hexadecimal, decimal, and scientific notation. This is a handy way to visualize an operation when debugging floating-point test cases."
> — p.643

中文解釋：用法就是 `./fpcalc 0x40000000 + 0x3f800000`。它會把每個輸入拆開顯示（biased exponent、fraction、是否 subnormal），再給結果與五個旗標。精度由十六進位字串的長度決定：4 個 nibble 是 half、8 個是 single、16 個是 double。也有線上版 WebFloat（s-y-wu.github.io/webfloat/）。

### fpcalc 的例子涵蓋哪些行為

> "Add floats with rounding to nearest (RNE), the default rounding mode, which sets the Inexact flag: 1.0 + 1.4 × 10^−45 = 1.0."（Example 16.14）
> — p.645

中文解釋：Example 16.13–16.18 一路示範：普通加法（無旗標）、RNE 造成 Inexact、加上 `RP` 參數改成朝 +∞ 捨入時同一題變成 1.0000...0001（結果不同、Inexact 仍設）、half 精度乘法溢位成 +inf 並設 Overflow、FMA、以及 ∞ / 1.5 = ∞（不設任何旗標，因為這是定義良好的運算）。第三個例子最有教育意義：**同樣的輸入，換捨入模式就換答案**，所以測試向量必須逐一涵蓋所有捨入模式。

## 名詞表

| 名詞 | 意思 |
| --- | --- |
| SoftFloat | UCB 的開源浮點軟體實作，RISC-V 的參考模型 |
| TestFloat | SoftFloat 配套的測試向量產生器 |
| reference model | 參考模型，硬體驗證時的標準答案來源 |
| `softfloat_roundingMode` | 設定捨入模式的全域變數 |
| `softfloat_exceptionFlags` | 讀取五個旗標的全域變數（bit0 NX、1 UF、2 OF、3 DZ、4 NV） |
| `softfloat_detectTininess` | 設定 underflow 判定是在捨入前或捨入後 |
| `float32_t` | SoftFloat 的 32 位元浮點型別（含 `.v` 欄位） |
| fpcalc | 書附的十六進位浮點計算機工具 |
| WebFloat | fpcalc 的線上版 |

## 所以呢

有了 SoftFloat 這個標準答案，硬體才有東西可對。不過在真正拿它跑驗證（16.5 測試計畫）之前，得先弄清楚 RISC-V 在 IEEE 754 之上還額外規定了什麼——像是 `fcsr` 怎麼擺、NaN 要不要傳遞 payload、單精度值存進雙精度暫存器要怎麼放。這些是下一節 16.4 RISC-V Practices 的內容。
