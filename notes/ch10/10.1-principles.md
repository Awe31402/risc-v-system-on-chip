## 關鍵點

### 記憶體階層：沒有又大又快又便宜的記憶體

> "An ideal processor would have a large, fast, cheap memory. **Unfortunately, the memory available on-chip
>  is usually static random access memory (SRAM), which is fast but expensive per bit and has relatively
>  low density. Off-chip dynamic random access memory (DRAM) provides gigabytes of memory at low cost and
>  high density but is significantly slower than a CPU.... Processors provide the illusion of a large,
>  fast, cheap memory by storing most data in the large, cheap DRAM but *caching* frequently accessed
>  information in the smaller but fast memory.**"
> — p.429

中文解釋：**核心手法是「製造幻覺」：大部分資料放便宜的 DRAM，常用的放快的 SRAM。**

**Fig. 10.1（p.430）的記憶體階層表是本章最實用的參考數據：**

| Technology | Capacity | Access Time | Bandwidth (GB/s) | Price / GiB |
| --- | --- | --- | --- | --- |
| **SSD** | 128 GiB – 8 TiB | **100–1000 μs** | 0.05–15 | **$0.05** |
| **HDD** | 1–20 TiB | **5–20 ms** | 0.001–0.1 | **$0.02** |
| **DRAM** | 16–128 GiB | **50–150 ns** | 30–50 | **$3** |
| SRAM (L3) | 3–100 MiB | 10–25 ns | > 100 | $100s |
| SRAM (L2) | 128 KiB – 2 MiB | 2–10 ns | > 100 | $100s |
| **SRAM (L1)** | **16–64 KiB** | **0.5–4 ns** | > 100 | $100s |
| **Flip-Flops** | **100–1000 Bytes** | **100–500 ps** | 250–1000 | **$1000s** |

**兩個數量級的對比值得記：
L1 SRAM 存取 0.5–4 ns，DRAM 是 50–150 ns（約 30–100 倍慢）；
DRAM 每 GiB $3，SRAM 是 $100 以上（30 倍以上貴）。**

### Cache 的層級組織

> "**Pipelined CPU designs typically use separate first-level (L1) caches for instructions and data so that
>  both can be accessed concurrently without stalling the pipeline. The *instruction cache* (I$) is
>  generally only readable, but the *data cache* (D$) must support both reads and writes.**"
> — p.429

中文解釋：**L1 分成 I$ 和 D$ 的理由：讓取指令和存取資料能同時進行**
（呼應 7.1 節的 Harvard vs von Neumann 討論）。

**階層（p.429）：**
- **L1I$ / L1D$**：分離
- **L2$**：容量較大但存取時間較長，**同時放指令和資料**
- **L3$**：多核系統常有，**跨核心共享**
- **L4$**：有些伺服器 SoC（如 IBM Power 8、9）用晶片外 eDRAM

**（p.429 邊欄的術語提醒：**「記憶體階層的**最低層是 L1$**；
**較高層**是 L2$ 和 L3$，然後是主記憶體，然後是虛擬記憶體。」**
——注意「高」和「低」的方向可能和直覺相反。）

**（p.430 邊欄的實例很有意思：**2025 年 3 月 AMD 發表 Ryzen 9 9950X3D，
**用 3D 堆疊記憶體做出 128 MiB 的 L3$**（兩顆 die：64 MiB L3 的 9950X 加上額外 64 MiB，
用 through-silicon via 堆疊連接）。
**9950X3D 把 cache die 移到 compute die 下方以改善散熱**，
讓兩個設計都能 boost 到 5.7 GHz。**在許多電玩中比 9950X 快 20–30%。**）

### Cache 效能：miss 的代價

> "**A memory access *hits* in the cache if it finds the information there. If it *misses* the cache, it
>  must go to the next-level cache or main memory to find the information, which increases the access
>  latency.**"
> — p.430

> "**Memory stall cycles = Number of instructions × (Memory accesses / instruction) × Miss rate × Miss
>  penalty**"
> — Eq. (10.1), p.430

中文解釋：**兩個定義：**
- **Miss rate**：cache 存取中 miss 的比例
- **Miss penalty**：處理一次 miss 平均要多少週期

**Example 10.1（p.430–431）的計算值得跟一遍：**
> "Suppose a pipelined processor has a CPI of 1.2 when all memory accesses hit in the cache.
>  **30% of instructions are loads or stores. The miss rate is 2%, and the miss penalty is 40 cycles.**"

```
記憶體存取數 = 1（取指令）+ 0.3（load/store）= 1.3 次/指令
memory stall CPI = 1.3 × 0.02 × 40 = 1.04
總 CPI = 1.2 + 1.04 = 2.24
執行時間增加 (2.24 − 1.2)/1.2 = 87%
```

**沒有 cache 的話（每次存取都付 40 週期）：**
```
CPI = 1.2 + (1.3 × 1 × 40) = 53.2
比有 cache 慢 53.2/2.24 ≈ 24 倍
```

**「2% 的 miss rate 就讓執行時間增加 87%；沒有 cache 會慢 24 倍」——
這兩個數字說明了 cache 的重要性。**

### AMAT：平均記憶體存取時間

> "**AMAT = A₁ + MR₁(A₂ + MR₂(A₃ + MR₃…))**"
> — Eq. (10.2), p.431

> "**A_i is access time, and MR_i is miss rate for level i of the memory hierarchy. The miss penalty for
>  level i is the AMAT starting at level i+1.**"
> — p.431

中文解釋：**這是一個遞迴公式：每一層的 miss penalty 就是下一層的 AMAT。**

**Example 10.2（p.431）：**
> "If 95% of instructions hit in the L1$, which has a 1-cycle access time and 15-cycle miss penalty, what
>  is the AMAT?
>  **AMAT = 1 + 0.05 × 15 = 1.75 cycles.**"

**Example 10.3（p.431）是更完整的兩層計算，值得完整看：**
> "A 5-stage pipelined CPU has 2 levels of caches and DRAM main memory. **The L1I$ has a hit rate of 98%
>  and a 1-cycle access time. The L1D$ behaves the same except the hit rate is 96% and The L2$ has a hit
>  rate of 80% (for accesses that missed the L1$) and a 3-cycle access time. DRAM has a 30-cycle access
>  time.** What is the AMAT for loads/stores and for instructions? Suppose the running application has 40%
>  loads/stores, and all other instructions take a single cycle to execute if the L1I$ hits."

```
取指令 AMAT = 0.98 × 1 + 0.02(3 + 0.2(30)) = 1.16
load/store AMAT = 0.96 × 1 + 0.04(3 + 0.2(30)) = 1.32

非 load/store 指令的 CPI = 取指令 AMAT = 1.16
load/store 的 CPI = 1.16 + 1.32 − 1 = 1.48   （兩個 AMAT 相加再減 1，因為取指令和存取資料重疊）
整體 CPI = 0.6 × 1.16 + 0.4 × 1.48 = 1.29 cycles
```

**「兩個 AMAT 相加再減 1」這個技巧要理解：
load/store 指令同時有取指令和資料存取，兩者在 pipeline 裡重疊了一個週期。**

### 三種 miss

> "**Cache misses are classified as *compulsory*, *capacity*, or *conflict*. The first time data is
>  accessed, a compulsory miss occurs because the data must be loaded into the cache. Capacity misses occur
>  when too much data is accessed and the cache is too small to hold the concurrently used data, which is
>  called the *working set*. Conflict misses occur when too many addresses map to the same cache set
>  (location in the cache), causing active cache lines to be *evicted*.**"
> — p.431

中文解釋：**三種 miss 的成因與解法（解法見 10.1.2 節起）：**

| 類型 | 成因 | 解法 |
| --- | --- | --- |
| **Compulsory（強制）** | **第一次存取，資料還沒進 cache** | 幾乎無解（prefetch 可減輕） |
| **Capacity（容量）** | **工作集（working set）大於 cache** | **加大 cache** |
| **Conflict（衝突）** | **太多位址映射到同一個 set** | **提高 associativity** |

**「working set」這個詞要記住：同時被使用的資料量。**

**（p.431 邊欄兩個重要補充：**
**「Out-of-order 處理器能在等待時執行其他指令，藏住部分 miss penalty，
但程式中的相依性限制了這種平行性。這種 cache 叫 *nonblocking*，因為 miss 時 CPU 不會 stall。
Multithreaded 處理器則在 cache miss 時切換到另一個執行緒來藏 miss penalty。」**

**「記憶體存取時間隨處理器時脈提高而成為越來越大的問題。
主記憶體要 50 ns 回傳資料時，跑 20 MHz（= 1/50 ns）的處理器只要等 1 個週期，
跑 2 GHz 的處理器要等 100 個週期。」**
——**這就是為什麼 cache 越來越重要。**）

### Locality：cache 為什麼有效

> "- **Temporal locality: Recently accessed memory is likely to be used again.**
>  - **Spatial locality: Nearby memory addresses are likely to be used.**"
> — p.432

中文解釋：**Code Example 10.1（p.432）的迴圈同時展現兩種 locality：**
```c
for (int index = 0; index < 100; index++)
  array[index] = array[index] + index;
```

| | I$ | D$ |
| --- | --- | --- |
| **Temporal** | **迴圈裡的同一批指令反覆執行** | **每個陣列元素先讀後寫** |
| **Spatial** | **連續的指令被執行** | **連續的元素被存取** |

**Cache line 的由來（p.432）：**
> "**However, if the item is missing, the cache fetches this item and nearby consecutive items into a
>  *cache line*. Spatial locality tells us the nearby addresses have a high probability of being used soon,
>  so it is beneficial to fetch data from these addresses into the cache. Each access to the next-level
>  cache incurs some latency independent of data size plus additional time to transfer each word in the
>  line, depending on line size. So, making the line too long may hurt performance.**"

**Cache line 的取捨：
長 line 利用空間局部性，但「每個字的傳輸時間」會拉長，太長反而傷效能。**

**（p.432 邊欄：**「有些教科書把 cache line 叫做 cache *block*。」**
以及：**「cache 裡的資訊通稱 data，即使 I$ 裡放的是指令。」**）

### Direct-mapped cache：最簡單的組織

> "**The simplest kind of cache is a *direct-mapped* cache, in which the least significant bits of the
>  address specify the location of an item in the cache.**"
> — p.432

中文解釋：**Fig. 10.2（p.433）的 4-KiB direct-mapped cache，
128 個 set，每個 set 一條 256-bit（32-byte）的 cache line 加一個 tag。**

**64-bit 位址的三個欄位（p.432）：**
```
┌──── Tag (52) ────┬── Set (7) ──┬─ Offset (5) ─┐
 63              12  11         5  4           0
                                   └ ww ┘└ 000 ┘
                                    word   byte
                                   offset  offset
```

| 欄位 | 位元 | 作用 |
| --- | --- | --- |
| **Offset** | **4:0** | **line 內的位元組位置** |
| — `ww`（word offset） | **4:3** | **選 line 內四個 8-byte 字中的哪一個** |
| — byte offset | **2:0** | **8-byte 對齊時永遠是 000**；subword 讀取用它選 byte |
| **Set** | **11:5** | **選 128 個 set 中的哪一個** |
| **Tag** | **63:12** | **存在 cache 裡，用來確認是不是要找的位址** |

**為什麼只存 tag 不存完整位址（p.433 邊欄）：**
> "**Because multiple addresses map to the same set, the cache must store a *tag* that indicates which
>  address is in the set, as well as its address. However, the set and word offset bits already encode the
>  lower bits of the address, so only the remaining upper bits, the tag, must be held in the cache, not the
>  entire address.**"

**「set 和 offset 位元已經編碼在位址裡了，所以只需要存上面剩下的位元」——
這是 cache 省空間的關鍵技巧。**

**命中的條件（p.433）：**
```
Hit = V（有效）& (Tag 相符)
```

**（p.433 邊欄：**「cache 的 size 或 capacity 指的是**資料位元數**，不計 tag 和 valid 位元。」**）

### Example 10.4：set 和 tag 的計算

> "In which set would the cache from Fig. 10.2 hold an 8-byte double-word located at memory address 0x2138?
>  What would the tag be?"
> — p.433

中文解釋：**解法（p.433）：**
```
0x2138 = 0010 0001 0011 1000（二進位，取低位）
                  └set┘└─┘
位元 2:0 = 000        （8-byte 字對齊）
位元 4:3 = 11         （line 內第 4 個字，最高位的那個）
位元 11:5 = 0001001 = 9    → set 9
位元 12 以上 = 2      → tag 2
```

**Conflict 的定義（p.433）：**
> "Multiple addresses map to the same cache set. Using the cache from Example 10.4, an 8-byte word at
>  address 0x4120 (**0100 0001 0001 00 000**) would also be held in set 9 but with a tag of 4.
>  **A *conflict* occurs when the cache accesses two different addresses with the same set but different
>  tags. The direct-mapped cache must evict one line to make room for the other. This increases the cache
>  miss rate.**"

### Miss 的處理與 dirty bit

> "**If the tag does not match or the set is invalid, the cache *misses*. The cache controller must send a
>  request to the next level of the memory hierarchy to fetch the line. The cache then writes the new data
>  along with the tag of the fetched line and sets the valid bit to 1. If the set previously contained a
>  valid line, the cache must first *evict* the old line to make room for the new one. Read-only caches
>  simply replace the old line with the new one. Writable caches may first have to write a line that has
>  been changed (called a *dirty line*) to the higher level of the hierarchy.... Each cache line adds a
>  *dirty bit* (D) to indicate a dirty line. The valid and dirty bits are collectively called *status
>  bits*.**"
> — p.434

中文解釋：**兩個狀態位元：**

| 位元 | 意義 |
| --- | --- |
| **V（valid）** | 這個 set 裡有沒有東西 |
| **D（dirty）** | **這條 line 被改過，和上層不一致，evict 時要先寫回** |

**唯讀 cache（I$）不需要 dirty bit——直接覆蓋就好。**

### Cache 寫入：ByteMask 與 LineByteMask

> "Instruction caches only need to read data, but data caches also need to write data from the CPU.
>  **This involves adding a write port, supporting partial line writes to a multiword cache line, and
>  updating the written data in higher levels of the memory hierarchy.**"
> — p.434

中文解釋：**Fig. 10.4（p.434）的讀寫 cache 介面：
`RW[1:0]`、`Address`、`ByteMask`、`WriteData` 進去，`ReadData` 出來。**

**`ByteMask` 的例子（p.435）：**

| 指令 | ByteMask |
| --- | --- |
| **`sd`**（寫 8 bytes） | **0b11111111** |
| **`sb`**（寫最低位 byte） | **0b00000001** |
| **`sh`**（寫最高位 half-word） | **0b11000000** |

**`RW[1:0]`：`RW[1]` 是讀取致能，`RW[0]` 是寫入致能。**

**寫入流程（p.435）：**
> "**A store begins the same way as a cache read: the cache reads the tag and valid fields of the selected
>  set to detect a hit. On a hit, WriteData is written to the correct word offset within the line, and the
>  dirty bit for that line is set so the cache knows that the line will need to be written back to the next
>  level of the memory hierarchy when it is evicted.**"

**Fig. 10.5（p.435）的具體例子非常清楚——寫 0xAABBCCDD 到位址 0x14：**
```
假設：XLEN = 32、16-byte（4-word）cache line、64 sets、16-bit 位址

1. WriteData 複製四份 → LineWriteData = 0xAABBCCDD_AABBCCDD_AABBCCDD_AABBCCDD
2. Demultiplexer 把 ByteMask（0xF）左移 word offset（0b01）個位置
   → LineByteMask = 0x00F0（其他位元清零）
3. LineByteMask 控制 line 內哪些 byte 被寫入
   → 只有 bytes 7:4 被更新
4. dirty bit 設為 1
```

**「複製滿 + 遮罩」的手法和 7.1.6 節的 subword store 完全一樣。**

**Miss 時的寫入（p.435）：**
> "**If a write misses, the cache must first fetch the line, as is done for a read miss. After the data
>  arrives from the next level of the memory hierarchy, the cache then merges the new write data into the
>  line at the correct word offset before writing the line into the cache memory. On read or write misses,
>  LineByteMask is 0xFFFF because all bytes need to be written.**"

**寫入 miss 也要先把整條 line 抓進來（因為只寫部分 byte，其他 byte 要保留原值）。**

### Write-through vs write-back

> "**In a write-through cache, each write is also sent to the next level(s) of the memory hierarchy, so all
>  memories remain consistent. This seriously limits write bandwidth and costs substantial power, so it is
>  only viable for simple low-performance systems.**"
> — p.436

> "**Practical processors now use write-back caches, which use the dirty bit to indicate that the cache line
>  has changed and, thus, is inconsistent with the next level of the memory hierarchy. When a line is
>  initially fetched on a read miss, the dirty bit is cleared. Cache writes set the dirty bit. When a dirty
>  line is *evicted*, it must be written back to the next level of the hierarchy.**"
> — p.436

中文解釋：

| 策略 | 做法 | 問題/優點 |
| --- | --- | --- |
| **Write-through** | 每次寫入也送到下一層 | **嚴重限制寫入頻寬、耗電**；只適合簡單低效能系統 |
| **Write-back** | **用 dirty bit 標記；只在 evict 時寫回** | **實務上的選擇** |

**多核的額外複雜度（p.436）：**
> "**Multicore systems add another degree of complexity because different cores may have different dirty
>  lines in their local caches. The programmer expects memory *coherency*, meaning that all cores will
>  eventually see the value most recently stored to an address. Thus, the memory system uses a *coherency
>  protocol* such as snooping or directories to maintain coherency between the caches.**"

**兩種 coherency protocol：snooping（監聽）和 directory（目錄）。**

### Associative cache：解決 conflict miss

**Code Example 10.2（p.436）的 thrashing 範例非常經典：**
```c
int64_t a[1024], b[1024];
int i;
for (i = 0; i < 1024; i++)
  b[i] = a[i];
```
> "**If run on a direct-mapped 8-KiB cache, every access will miss in the cache because each a[i] and b[i]
>  map to the same set. Thus, the cache has a 100% miss rate and does not benefit from spatial locality.
>  In fact, the system will run more slowly than it would without a cache because it wastes time fetching
>  each cache line and then immediately evicting it. This is called *thrashing*.**"

**Thrashing 的定義：不斷抓進來又立刻被踢掉，比沒有 cache 還慢。**
（因為 8 KiB 的 a 和 b 陣列剛好差 8 KiB = cache 大小，所以每一對都映射到同一個 set。）

**N-way set associative 的定義（p.436）：**
> "**An *N-way set associative cache* (or *associative cache*, for brevity) reduces conflicts by providing
>  N separate *ways* in each set. A line can be placed in any of the ways. Each way has its own tag, valid,
>  and dirty bits.**"

**Fig. 10.6（p.437）的 8-KiB 2-way associative cache：
128 個 set，每個 way 有 256 bit（32 bytes = 4 個 8-byte 字）的資料。**

**硬體結構：**
```
每個 way 各有一個比較器 → Hit₀、Hit₁
Hit = Hit₀ | Hit₁
Data = Hit₁ ? Way1 的資料 : Way0 的資料（再依 word offset 選字）
Dirty = (Hit₀ & Dirty₀) | (Hit₁ & Dirty₁)
```

**回到 Code Example 10.2（p.437）：**
> "**Considering Code Example 10.2 again with the 2-way associative cache, no conflict misses occur anymore
>  because a[i] and b[i] each reside in a different way. The cache misses on the first word in each line
>  but then hits on the next three words because of spatial locality. Even though the program has no
>  temporal locality (repeated access to the same data), it still has a 75% hit rate because of spatial
>  locality.**"

**100% miss → 75% hit。這就是 associativity 的價值。**

**兩個極端（p.437）：**
- **Direct-mapped = 1-way associative**
- **Fully associative = 只有一個 set，所有 line 都在不同的 way**

> "**Fully associative caches never have conflict misses, although they still have capacity misses.
>  The fully associative hit comparators and hit multiplexer are expensive and grow with the size of the
>  cache, so full associativity is only practical for modest-sized caches. Translation lookaside buffers
>  (TLBs)... are often fully associative to achieve the best hit rate for a limited capacity.**"

**Fully associative 只適合小 cache，典型用途是 TLB（第 11.4.1.3 節）。**

### 設計取捨：line size 與 associativity

**Fig. 10.7（p.438）miss rate vs line size（SPEC92，4–256 KiB cache）：**
> "**Section 10.1.2 describes how longer cache lines improve hit rate due to spatial locality but take
>  longer to fill or evict. For a given cache size, very long lines also increase the miss rate because
>  fewer lines are available altogether, increasing conflict misses.**"

**從圖上讀：4K cache 的 miss rate 在 line size 32–64 時最低（約 7%），
line size 256 時反而上升到 10%。大 cache（256K）幾乎不受影響。**

**Fig. 10.8（p.439）miss rate vs size and associativity（SPEC2000）——這張圖的分層很有價值：**
> "**Capacity misses dominate, especially for typical 16- to 32-KiB L1 caches. Capacity misses can be
>  alleviated by providing a larger L2$. Conflict misses can be significant in direct-mapped caches but
>  become rare in caches with at least 4-way associativity. As we will see in Section 11.1.1.7, in systems
>  with virtual memory, such associativity is also used to ensure that each way is no larger than the page
>  size, which moves address translation off the critical path. In nontrivial programs, compulsory misses
>  are negligible because they only occur at the start of a program.**"

**三種 miss 的相對重要性：**

| Miss 類型 | 在典型 L1 的情況 |
| --- | --- |
| **Capacity** | **主導**（尤其 16–32 KiB 的 L1） |
| **Conflict** | direct-mapped 時顯著，**4-way 以上就很少見** |
| **Compulsory** | **可忽略**（只在程式開始時發生） |

**「4-way associativity 還有一個虛擬記憶體上的理由：
確保每個 way 不大於 page size，讓位址轉換不在關鍵路徑上」**——
這在第 11.1.1.7 節詳述。

### Cache 的包含關係與容量規劃

> "**Higher-level caches may be *inclusive* (containing all contents of the lower-level cache), *exclusive*
>  (containing none), or *non-inclusive non-exclusive* (NINE, possibly containing some). Exclusive caches
>  make better use of limited cache space, but inclusive top-level caches are needed to maintain cache
>  coherence in multiprocessor systems.**"
> — p.438

中文解釋：**三種包含關係的取捨：exclusive 空間利用好，inclusive 方便維持 coherence。**

**容量規劃的經驗法則（p.438–439）：**
> "**To provide significant miss rate reduction, the next-level cache should be significantly (at least 4-8
>  times) bigger than the one below it. So, in a system with 16-KiB L1I$ and L1D$, the combined L2$ should
>  be at least 8(16 + 16) = 256 KiB. L2 caches with up to several MiB are sometimes used, but they can have
>  long access times when they get too big. Hence, the system may add an L3$, commonly with 4- to 64-MiB of
>  capacity. The highest-level cache is shared across all cores of a multicore system to support
>  shared-memory communication between cores.**"

**「下一層至少要大 4–8 倍」是很實用的規劃法則。**

**（p.439 邊欄的實務數字：**
**「L1 cache 通常 8–32 KiB 以達成 1–2 週期延遲。每個 way 通常 4 KiB 以配合 4-KiB 虛擬記憶體 page，
所以有 2–8 個 way。L1 cache 常用 64-byte line，在命中率和 miss penalty 之間取得好的平衡。」**）

### 替換策略：LRU 與 pLRU

> "**An ideal replacement policy selects the way with the lowest probability of being used in the near
>  future. However, program behavior is not known ahead of time, so we use past behavior to predict the
>  future. The *least recently used* (LRU) replacement policy records the order in which the ways are
>  accessed (read or written) and selects the oldest accessed way as the victim.**"
> — p.439

中文解釋：**LRU 的哲學：「用過去預測未來」。**

**2-way 的 LRU 很簡單（p.439）：**
> "**In a 2-way associative cache, LRU uses 1 extra bit in each set to indicate which of the two ways was
>  used least recently.**"

**但擴展性不好（p.439–440）：**
> "**LRU does not scale efficiently beyond two ways because recording the order of accesses and selecting
>  the oldest becomes expensive. For example, an N-way associate cache can keep a list of N entries for
>  each set indicating the relative order of accesses.... This requires Nlog₂N LRU bits per set and
>  hardware to search and update the list.**"

**N-way 的 LRU 要 N·log₂N 個位元（8-way 要 24 位元）。**

**pLRU 的解法（p.440）：**
> "***Tree pseudo-LRU*, also referred to as simply *pseudo-LRU* (pLRU), approximates LRU with a less-costly
>  implementation that uses only N-1 LRU bits and still achieves a hit rate that is nearly as good as LRU.
>  The bits are organized as a binary tree, with log₂N levels, to approximate which side of the tree was
>  least recently accessed. pLRU works by grouping ways into powers of two: 2 groups, then 4 groups, and so
>  on until only one way is in each group.**"

**pLRU：只要 N−1 個位元（8-way 只要 7 個），命中率幾乎和 LRU 一樣好。**

### pLRU 的樹狀演算法（值得完整理解）

**Fig. 10.9(a)（p.440）的初始狀態，8-way：**
```
                  N6=1
          ┌────────┴────────┐
        N5=0              N4=0
      ┌───┴───┐        ┌───┴───┐
    N3=0    N2=1     N1=0    N0=0
    ┌┴┐     ┌┴┐      ┌┴┐     ┌┴┐
    0 1     2 3      4 5     6 7   ← Way
              LRU=4
```

**讀法（p.440）：**
> "**A zero (0) in the tree indicates the right branch was more recently accessed and the left branch is
>  older, a one (1) indicates the opposite. Traversing the tree along the arrows to the leaf box finds the
>  pLRU (labeled LRU) victim way.**"

| 位元值 | 意義 | 往哪走 |
| --- | --- | --- |
| **0** | **右邊較近被存取，左邊較舊** | **往左** |
| **1** | 相反 | **往右** |

**找 victim 的路徑（p.440）：**
> "**In Fig. 10.9(a), the root LRU bit N6 is 1, so the right half (ways 4−7) were not used in the last
>  access. Following the arrow to the right half leads to a 0 bit at N4, so the left half (ways 4−5) were
>  not used the last time an access occurred to ways 4−7. Following the next arrow left to N1 reveals
>  another 0, so way 4 was not used the last time an access occurred to ways 4−5. When the set is full and
>  a new entry is needed, pLRU traverses the binary tree by following the arrows from N6 to N4 to N1 to
>  select way 4 as the victim way to replace.**"

**N6=1 → 右 → N4=0 → 左 → N1=0 → 左 → way 4。**

**更新規則（p.440）：**
> "**After a cache access uses a particular way, pLRU updates the tree to reflect this way's recent use.
>  Every node between the root and the accessed way is updated to point away from the accessed way.**"

**「路徑上每個節點都更新成指向遠離被存取的 way」。**

**Fig. 10.9(b)（p.440）存取 way 6 後（p.441）：**
> "**The path to traverse the tree from the root to the accessed way (6) is N6 to N4 to N0.... The root node
>  N6 changes to 0 to point away from ways 4−7 (toward ways 0−3). The next node N4 is already 0, pointing
>  away from ways 6−7 (toward ways 4−5). The final node N0 becomes 1 to point away from way 6 (toward way
>  7). Now the arrows indicate way 0 is least recently used.**"

**Example 10.5（p.441）：再存取 way 3 後**
> "The path from the root to way 3 traverses nodes N6, N5, and N2.... **Each node along this path is updated
>  to point *away* from way 3.... Now the arrows indicate way 4 is least recently used.**"

**（Fig. 10.10：N6=1、N5=0、N2=0，LRU 指向 way 4。）**

**（p.441 邊欄的歷史：**「Tree pLRU 最早用於 1989 年的 Intel 486 CPU。」**
以及 p.440 邊欄的術語提醒：**「儘管 pLRU 是 LRU 替換的近似，
要替換的那個 way 仍然叫 LRU way，追蹤它的位元仍然叫 LRU bits。」**）

**兩者的共同弱點（p.441）：**
> "**Both LRU and pLRU can behave poorly under pathological access patterns. Thrashing occurs if the working
>  set is larger than the number of ways. For example, if a program's working set maps five addresses to
>  the same set and then accesses them in the same order repeatedly, a 4-way associative cache will conflict
>  miss on every access.**"

**「5 個位址映射到同一個 set，在 4-way cache 上循環存取 → 每次都 miss」——
這是 LRU 的最壞情況。**

### Flush 與 Invalidate

> "**Sometimes the cache may need to be *flushed* (have dirty lines written back to the next level of the
>  memory hierarchy) or *invalidated* (valid bit V = 0 for all cache lines).**"
> — p.441

中文解釋：**兩個操作要分清楚：**

| 操作 | 做什麼 |
| --- | --- |
| **Flush** | **走過所有 data cache line，把 dirty 的寫回記憶體，然後清除 dirty 位元** |
| **Invalidate** | **走過所有 cache line，清除 valid 位元** |

**三個使用時機（p.441–442）：**

1. **重置時**：cache 必須被 invalidate
2. **`fence.i`**（p.441）：
   > "**because an instruction cache is read-only, anytime a program needs to write instructions, the writes
   >  go to the data cache instead. Hence, for the new instructions to be visible in the instruction cache,
   >  the processor must flush the dirty lines from the data cache back to the next level of the memory
   >  hierarchy and invalidate the instruction cache so that it reads the new instructions from the next
   >  level of the memory hierarchy.**"
   （呼應 8.4.5.5 節。**flush D$ + invalidate I$**。）
3. **進入 sleep mode（p.442）**：
   > "**Many processors support a sleep mode in which the cache array is powered off to save energy.
   >  Before entering sleep, write-back caches should be flushed. All caches should be invalidated when
   >  waking up.**"

**（p.442 邊欄的重要術語警告：**
> "**Beware that the term flush has multiple meanings. A *cache flush* writes back dirty lines. A *pipeline
>  flush* clears an instruction from a pipeline stage. In this chapter, *flush* refers to a cache flush
>  except when discussing pipeline hazards.**"

**「flush」在本書有兩個完全不同的意思，讀的時候要看上下文。**）

| 名詞 | 意思 |
| --- | --- |
| Memory hierarchy | 記憶體階層。**L1$（最低）→ L2$ → L3$ → 主記憶體 → 虛擬記憶體** |
| I$ / D$ | 指令 cache（唯讀）/ 資料 cache（可讀寫） |
| Hit / miss | 在 cache 中找到 / 找不到 |
| Miss rate / miss penalty | miss 的比例 / 處理 miss 的平均週期數 |
| **AMAT** | 平均記憶體存取時間 = **A₁ + MR₁(A₂ + MR₂(A₃ + …))** |
| **Compulsory / capacity / conflict miss** | 第一次存取 / **工作集大於 cache** / **太多位址映射到同一 set** |
| Working set | 工作集。同時被使用的資料量 |
| Nonblocking cache | miss 時 CPU 不 stall，可執行其他指令（亂序處理器） |
| **Temporal / spatial locality** | 最近用過的會再用 / 附近的位址會被用 |
| **Cache line（block）** | 一次抓進 cache 的連續資料；**太長反而傷效能** |
| **Tag / Set / Offset** | 位址的三個欄位；**只存 tag 因為 set 和 offset 已編碼在位址裡** |
| Word offset / byte offset | 選 line 內的字 / 選字內的位元組 |

| **Write-through / write-back** | 每次寫都送到下層（限制頻寬）/ **用 dirty bit，evict 時才寫回（實務選擇）** |
| Coherency protocol | snooping 或 directory，維持多核 cache 間的一致性 |
| **N-way set associative** | 每個 set 有 N 個 way，各有自己的 tag/valid/dirty |
| **Thrashing** | 不斷抓進來又立刻踢掉，**比沒有 cache 還慢** |

| **Cache flush / invalidate** | **寫回 dirty line 並清 dirty 位元** / **清除所有 valid 位元** |

## 所以呢

**這節建立了 cache 的完整理論。五件最該帶走的事：**

1. **AMAT 是遞迴的**：`AMAT = A₁ + MR₁ × (下一層的 AMAT)`。
   **2% 的 miss rate 就讓執行時間增加 87%；沒有 cache 會慢 24 倍。**

2. **三種 miss 的相對重要性**（Fig. 10.8）：
   **capacity 主導、conflict 在 4-way 以上就很少、compulsory 可忽略。**
   對應的解法分別是：**加大 cache、提高 associativity、（無解）。**

3. **位址的三個欄位（Tag/Set/Offset）**，
   **而 cache 只存 tag——因為 set 和 offset 已經編碼在位址裡了。**

4. **pLRU 用 N−1 個位元近似 LRU**（LRU 要 N·log₂N）：
   **0 = 往左、1 = 往右找 victim；存取後把路徑上每個節點更新成「指向遠離」。**

5. **Write-back + dirty bit 是實務選擇**；
   **flush（寫回 dirty）和 invalidate（清 valid）是兩個不同的操作**，
   `fence.i` 需要「flush D$ + invalidate I$」。

還有兩個實用的規劃法則：
**「下一層 cache 至少要大 4–8 倍」、「L1 每個 way 通常 4 KiB 以配合 page size」。**
