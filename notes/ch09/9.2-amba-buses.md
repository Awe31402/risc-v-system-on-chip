# 9.2 AMBA Buses

> 原書 p.391–410（Chapter 9: Bus Interface）
> 涵蓋 9.2.1 APB、9.2.2 AHB（9.2.2.1–9.2.2.6）、9.2.3 AXI

## 這節在講什麼

**ARM 的 AMBA 匯流排家族：APB、AHB、AXI 三種，由簡到繁。**

三者的一句話定位：

| 匯流排 | 定位 | 關鍵特性 |
| --- | --- | --- |
| **APB**（Advanced Peripheral Bus） | **簡單、無 pipeline** | 兩階段（Setup/Access），慢周邊用 |
| **AHB**（Advanced High-performance Bus） | **有 pipeline** | 兩階段可重疊，**吞吐量約 APB 的兩倍** |
| **AXI**（Advanced eXtensible Interface） | **多通道、高速** | **五個獨立通道、亂序回應、多筆傳輸並行** |

**Wally 用 AHB（和 APB 給慢周邊）。最該精讀的是 9.2.2 的 AHB——
它是本書後面實作的對象。**

## 關鍵點

### AMBA 的地位與三種版本

> "ARM's Advanced Microcontroller Bus Architecture (AMBA) has been a leading family of open-standard
>  on-chip buses used in both ASICs and FPGAs since 1996. The three major AMBA flavors are:
>  - **APB (Advanced Peripheral Bus): Simple unpipelined**
>  - **AHB (Advanced High-performance Bus): Pipelined**
>  - **AXI (Advanced eXtensible Bus): Multichannel, high-speed**"
> — p.391–392

中文解釋：**Fig. 9.7（p.392）的典型系統架構：**

```
External Memory Interface ─┐
CPU ───────────────────────┼─── AHB ───[AHB-to-APB Bridge]─── APB ───┬─ UART
On-Chip SRAM ──────────────┤                                          ├─ Timer
On-Chip ROM ───────────────┘                                          ├─ SPI
                                                                      └─ GPIO
```

**分工的原則（p.392）：**
> "**Whereas the high-speed CPU and on-chip memories use AHB, the slower peripherals use the simpler APB
>  bus. The AHB-to-APB bridge translates signals from one protocol to the other. AHB can also be used as
>  an interface to off-chip memory.**"

**快的（CPU、記憶體）用 AHB，慢的（UART、Timer、SPI、GPIO）用 APB，中間用 bridge。**

**AXI 的地位（p.392）：**
> "**AXI is now the dominant standard for systems with multiple controllers or high-speed DRAM
>  interfaces, but the 500-page specification [AXI21] is beyond the scope of this chapter.**"

**（p.392 邊欄介紹 AMBA 的原始架構師 David Flynn：
ARM 的可合成處理器和 AMBA 晶片內互連的原始架構師，
2019 年獲 IEEE/RSE James Clerk Maxwell Medal，
也是 *Low Power Methodology Manual* 的共同作者。**）

### APB：兩階段、無 pipeline

> "Each transfer has two phases: *Setup* and *Access*. **The Setup phase takes one clock cycle, during
>  which the controller drives the PADDR, PWRITE, and PSEL signals onto the bus along with PWDATA for a
>  write. The Access phase takes one or more clock cycles, during which the controller holds these Setup
>  phase signals steady and asserts PENABLE; the peripheral performs the read or write. Upon a read, the
>  peripheral responds with PRDATA. The peripheral raises PREADY when it is done reading or writing.**"
> — p.392

中文解釋：**Table 9.1（p.393）的主要 APB 訊號：**

| Signal | 說明 | 寬度 | Phase | 來源 |
| --- | --- | --- | --- | --- |
| **PADDR** | 要讀寫的位址 | 32 | **Setup** | Controller |
| **PRDATA** | 從周邊讀回的資料 | 32 | **Access** | **Peripheral** |
| **PWDATA** | 寫給周邊的資料 | 32 | **Setup** | Controller |
| **PWRITE** | 寫入致能 | 1 | Setup | Controller |
| **PENABLE** | 啟用讀寫 | 1 | **Access** | Controller |
| **PREADY** | 周邊在 Access 階段完成時 assert | 1 | **Access** | **Peripheral** |
| PSTRB | 寫入 byte enable | 4 | Setup | Controller |

**所有訊號都加 `P` 前綴。**

**兩個實用細節（p.393）：**
> "**A peripheral that always responds in a single Access phase cycle can tie its PREADY high.
>  If no peripheral is selected, the APB mux asserts PREADY so the bus remains in a ready state.**"

**「沒有周邊被選中時也要 assert PREADY」——否則匯流排會掛住。**

**Fig. 9.8（p.393）的波形示範三種傳輸：**
- **Cycle 1–2**：寫入 A1，無 wait state
- **Cycle 3–4**：讀取 A2，無 wait state
- **Cycle 5–7**：讀取 A3，**一個 wait state**（Access 階段拉長）

**兩個選配訊號（p.394）：`PSTRB[3:0]`（byte write enable，每 byte 一位元）
和 `PSLVERR`（周邊發生錯誤時 assert）。**

### APB 範例：GPIO 周邊

中文解釋：**Example 9.1（p.394）設計一個 32-bit GPIO 周邊，三個記憶體映射暫存器：**

| 暫存器 | 位址 | 用途 |
| --- | --- | --- |
| **GPIOOUT** | 00 | 輸出暫存器（寫入 GPIO 腳） |
| **GPIOEN** | 01 | 設定腳為輸出（1）或輸入（0） |
| **GPIOIN** | 10 | 唯讀輸入暫存器 |

**實作（Fig. 9.9，p.394）：**
> "**The core of the peripheral is a tristate buffer that enables writing GPIOOUT onto the GPIO pins for
>  each bit of GPIOEN[31:0] that is asserted. The pins can always be read onto GPIOIN. A 2:3 address
>  decoder determines which register is being accessed. When PWRITE, PSEL, and PENABLE are asserted, the
>  GPIOOUT or GPIOEN register is written when PADDR[1:0] is 00 or 01, respectively. The GPIO multiplexer
>  is controlled by the address (PADDR[1:0]) to read the appropriate register. The peripheral has no wait
>  states; thus, it always asserts PREADY.**"

**寫入的條件是三個訊號同時 assert：`PWRITE & PSEL & PENABLE`。**

**（p.394 邊欄：**「ASIC 和 FPGA 實作使用特別設計的 tristate buffer（也叫 *driver*），
能驅動大電容的 PCB 導線。它們在頂層模組實例化，
所以 `gpio_apb` 模組有三個介面訊號：GPIOEN、GPIOOUT、GPIOIN。」**
——呼應 4.2.2.3 節 Guideline 4.7：tristate 只用於 I/O 接腳。）

### AHB：pipeline 帶來兩倍吞吐量

> "Like APB, AHB uses two phases of operation and takes at least two cycles for a transfer, with the
>  option of additional wait states. **However, AHB doubles the throughput by pipelining, that is,
>  overlapping the two phases. AHB refers to the two phases as Address (Adr) and Data phases**, which are
>  similar to APB's Setup and Access phases."
> — p.395

中文解釋：**Table 9.2（p.395）的術語對照，很容易搞混，要記熟：**

| 概念 | APB | AHB |
| --- | --- | --- |
| Controller | **Requester** | **Manager** |
| Peripheral | **Completer** | **Subordinate** |
| Phase 1 | **Setup** | **Address (Adr)** |
| Phase 2 | **Access** | **Data** |
| 訊號前綴 | **P** | **H** |

**（p.395 邊欄直言：**「ARM 在 APB 和 AHB 之間用了不一致的術語。」**）

**Pipeline 的機制（p.396）：**
> "**The Address phase of the next transfer begins when the previous transfer is in its Data phase. This
>  requires an extra register to pipeline HADDR and the control signals. Because of this pipelining, AHB
>  has nearly twice the throughput of APB.**"

**下一筆傳輸的 Address 階段和上一筆的 Data 階段重疊**——
**代價是周邊要多一個暫存器來 pipeline HADDR 和控制訊號。**

**Fig. 9.10（p.396）的波形示範：寫 A1 → 讀 A2 → 讀 A3（含一個 wait state），
可以看到 Address 和 Data 階段交錯。**

### HTRANS：四種傳輸類型

中文解釋：**Table 9.3（p.395）：**

| HTRANS | Type | 說明 |
| --- | --- | --- |
| **00** | **IDLE** | 無資料傳輸 |
| **01** | **BUSY** | **像 IDLE，但在 burst 中間** |
| **10** | **NONSEQ** | **單次傳輸，或 burst 的第一筆** |
| **11** | **SEQ** | **burst 的後續傳輸** |

**`HTRANS[1]` = 1 表示 NONSEQ 或 SEQ（即「有有效傳輸」）**——
這個位元在周邊的偵測邏輯裡直接用得到（p.400 邊欄明說）。

### Default subordinate：避免匯流排掛住

> "**The AHB multiplexer chooses the HREADYOUT and, on a read, HRDATA from the selected peripheral.
>  It chooses based on HSELD, a version of HSEL delayed to align with the Data phase. As in APB, when no
>  HSEL signals are asserted, the AHB mux asserts HREADY to prevent the bus from hanging. This is called
>  the *default subordinate* behavior.**"
> — p.396

中文解釋：**`HSELD` 是延遲一個週期的 `HSEL`**——
因為 `HSEL` 在 Address 階段產生，但 `HRDATA` 和 `HREADYOUT` 在 Data 階段。

**Default subordinate：沒有周邊被選中時，多工器自己 assert HREADY。**

**HREADY 的雙重角色（p.396）：**
> "**AHB also sends HREADY to the peripherals to mark the completion of one transaction and start of the
>  next. When HTRANS is NONSEQ or SEQ and a peripheral receives HREADY and HSEL, the peripheral must
>  capture the Address phase inputs so that it can generate the addresses for the next transactions.**"

**`HREADY` 同時是「上一筆完成」和「這一筆開始」的訊號。**

### 位址解碼器與分散式 AND-OR 多工器

中文解釋：**Fig. 9.11（p.397）的三個部分：**

**（1）位址解碼器**：`HADDR` 和每個周邊的 `BaseAdr` 比較 → `HSEL[1..N]`
**（2）`HSELNone`**：所有 HSEL 的 NOR（沒有周邊被選中）
**（3）分散式 AND-OR 多工器**：
```
HREADY = OR over i of (HREADYOUT[i] & HSELD[i]) | HSELNoneD
HRDATA = OR over i of (HRDATA[i] & HSELD[i])
```

**這就是 4.2.5.5 節說的 distributed AND-OR mux 模式：
「全部讀出、不匹配的清成 0、再 OR 起來」。**

**`HSELD` 由一個 reset-enable 暫存器產生（延遲一週期對齊 Data 階段）。**

**（p.397 提到 Wally 的 PMA checker `pmachecker` 位於 MMU，
**擴充位址解碼器以同時檢查存取類型和大小**，見 Fig. 11.16。）

### Table 9.4：完整的 AHB 訊號

中文解釋：**Table 9.4（p.399）。除了 HCLK 和 HRESETn 之外的主要訊號：**

| Signal | 說明 | 寬度 | Phase | 來源 |
| --- | --- | --- | --- | --- |
| **HADDR** | 要讀寫的位址 | ADDR_WIDTH | Address | Controller |
| **HRDATA** | 從周邊讀回的資料 | AHBW | **Data** | **Peripheral** |
| **HWDATA** | 寫給周邊的資料 | AHBW | **Data** | Controller |
| **HWRITE** | 寫入致能 | 1 | Address | Controller |
| **HREADY** | 周邊在 Data 階段完成時 assert | 1 | Data | **Peripheral** |
| **HTRANS** | 傳輸類型（Table 9.3） | 2 | Address | Controller |
| **HSIZE** | 傳輸大小（Table 9.5） | 3 | Address | Controller |
| **HWSTRB** | Write strobe：指出要寫哪些 byte | AHBW/8 | **Data** | Controller |
| **HBURST** | Burst 資訊 | 3 | Address | Controller |
| **HPROT** | 保護資訊 | 4 | Address | Controller |
| **HMASTLOCK** | 原子指令的 master lock | 1 | Address | Controller |
| HEXCL / HMASTER | 原子指令用（選配） | 1 / 0-8 | Address | Controller |
| HNONSEC | 識別非安全交易（選配） | 1 | Address | Controller |
| **HRESP** | 周邊傳回傳輸狀態 | 1 | Data | Peripheral |
| HEXOKAY | 獨占傳輸成功時為 1（選配） | 1 | Data | Peripheral |

**關鍵觀察：`HWDATA` 和 `HWSTRB` 在 Data 階段，其餘控制訊號都在 Address 階段。**
（這是 pipeline 的直接結果——寫入資料比位址晚一個週期。）

**`HRESP` 是 2-bit 狀態（p.397）：00 = OKAY、01 = ERROR、10 = RETRY、11 = SPLIT。**

**Table 9.5（p.399）HSIZE 的編碼：**

| HSIZE[2:0] | 位元數 | 名稱 |
| --- | --- | --- |
| 0 | 8 | Byte |
| 1 | 16 | Half word |
| **2** | **32** | **Word** |
| **3** | **64** | **Double word** |
| 4–7 | 128–1024 | — |

**（p.397 邊欄：Wally 的 `HADDR` 寬度是 `ADDR_WIDTH = PA_BITS`（實體位址位元），
**RV32 為 34 bit、RV64 為 56 bit**，見第 11 章。）

### 一個 byte 傳輸的兩種寫法

> "**Table 9.6 shows two ways to write a single byte using an AHB bus. It assumes a little-endian memory
>  system with a 32-bit bus and writes 0x42 to address 0x1002. The first option sends a whole word and
>  only enables 1 byte in the word to be written, and the second option makes a single-byte transfer.**"
> — p.397

中文解釋：**Table 9.6（p.399）的對照非常有教育意義：**

| Signal | **Option 1**（整字 + byte enable） | **Option 2**（單 byte 傳輸） |
| --- | --- | --- |
| HADDR | **0x1000** | **0x1002** |
| HSIZE | **2（4 bytes）** | **0（1 byte）** |
| HWSTRB | **0b0100** | **0b0001** |
| HWDATA | **0x00420000** | **0x00000042** |

**兩種都寫 0x42 到位址 0x1002，但：**
- **Option 1**：位址對齊到字邊界，**資料放在字內的正確位置**（byte 2 → bit 23:16），
  **用 HWSTRB 選那個 byte**
- **Option 2**：位址就是 0x1002，**資料放在最低位元**，HWSTRB 只有 bit 0

**這個對照說明了 HSIZE 和 HWSTRB 的關係，以及「資料要對齊到哪裡」的規則。**

**簡化的可能（p.400 邊欄）——實用：**
> "**Many systems don't need all the signals listed in Table 9.4. The controller can tie HSIZE to the bus
>  size (e.g., 2 for a 32-bit bus), HPROT = 3 (ignored by most peripherals), HBURST = 0 (no burst), and
>  HMASTLOCK = 0, and omit optional signals. In a system where peripherals don't generate errors, the
>  peripheral can tie HRESP to 0 and the controller can ignore HRESP.**"

### AHB 周邊要做的五件事

> "**An AHB peripheral must perform several functions to interface with the bus:
>  - Detect new transactions.
>  - Retime writes, so that HWDATA arrives in the Data phase rather than in the Address phase.
>  - Read or write registers in the peripheral.
>  - Produce HRDATA in the Data phase.
>  - Generate the HREADYOUT, HRESP, and HEXOKAY acknowledgement.**"
> — p.400

中文解釋：**偵測新交易的條件（p.400）：**
```
initTrans = HTRANS[1] & HSEL & HREADY
```
> "**A peripheral starts a new transaction when the bus contains a valid transaction, the peripheral is
>  selected, and the previous transaction is completing. The peripheral detects these conditions by
>  asserting an internal signal, initTrans, when HTRANS is NONSEQ or SEQ, HSEL is asserted, and HREADY is
>  asserted from the previous transaction. When initTrans asserts, the peripheral either reads or writes
>  depending on the value of HWRITE.**"

**「三個條件的 AND」——這是所有 AHB 周邊的共同起點。**

**讀和寫的時序不對稱（p.400）——這是 AHB 最容易搞混的地方：**
> "**When interacting with a peripheral that has no wait states, a controller reads from the peripheral on
>  the rising edge after the Address phase and HRDATA is available during the Data phase. However, a write
>  to the peripheral occurs on the rising edge *after* the Data phase because HWDATA is not available until
>  the Data phase. Hence, when HREADY is asserted, HADDR and HWRITE must be captured at the end of the
>  Address phase to retain their values for writes in the Data phase.**"

| | 何時發生 | 為什麼 |
| --- | --- | --- |
| **讀** | Address 階段後的上升緣 | 位址在 Address 階段就有了 |
| **寫** | **Data 階段後的上升緣** | **HWDATA 要到 Data 階段才有** |

**→ 所以周邊必須把 HADDR 和 HWRITE 存起來，延到 Data 階段用於寫入。**

### AHB SRAM 介面範例

中文解釋：**Fig. 9.13（p.401）的 `ram_ahb` 模組。核心邏輯：**
```
initTrans = HSEL & HTRANS[1] & HREADY
memRead   = initTrans & ~HWRITE
memWrite  = initTrans & HWRITE        → 延遲一週期成 memWriteD
HADDRD    = 延遲一週期的 HADDR
A = memWriteD ? HADDRD : HADDR        （寫入用延遲版，讀取用當前）
```

**書上的分析（p.401）揭露了一個真實的限制：**
> "**Reads occur on the rising edge at the end of the Address phase. Writes occur on the rising edge at the
>  end of the Data phase, so their address and write enable must be delayed a cycle. Thus, the SRAM can
>  accommodate consecutive reads and consecutive writes and a read followed by write — but not a write
>  immediately followed by a read because the SRAM has a single read/write port and cannot accept the read
>  and write addresses on the same cycle. Therefore, the SRAM interface inserts a single wait state by
>  lowering HREADYOUT for one cycle for a write followed by read.**"

**四種組合，只有一種不行：**

| 序列 | 可以嗎 |
| --- | --- |
| 讀→讀 | ✓ |
| 寫→寫 | ✓ |
| 讀→寫 | ✓ |
| **寫→讀** | **✗ 需要插入一個 wait state** |

**理由：SRAM 只有一個讀寫埠，而寫入的位址被延遲了一週期，
所以會和下一筆讀取的位址在同一週期衝突。**
（**這正是 7.2.1 節那個 store-load 結構危障的匯流排版本。**）

**（p.401 邊欄很有洞見：**
> "**A simple SRAM expects the write data at the same time as the address and control signals. The AHB
>  protocol complicates the interface because write data arrives a cycle late. This timing is an artifact
>  of AHB's roots in early ARM processors [Flynn97]. For example, the ARM6 had a 3-stage pipeline in which
>  the address arrived a cycle before the write data.**"

**「寫入資料晚一週期」是 AHB 從早期 ARM 處理器繼承來的歷史產物**——
ARM6 的 3 級 pipeline 裡位址就是比寫入資料早一個週期。**）

### AHB-to-APB Bridge

中文解釋：**Fig. 9.14（p.402）的 bridge。它的角色是雙重的（p.401）：**
> "**The left side behaves as a peripheral on an AHB bus. The right side behaves as a controller on an APB
>  bus. The bridge translates AHB transactions to APB signals, adjusting the phases of the signals before
>  returning HREADYOUT.**"

**Fig. 9.15（p.403）的時序轉換說明（p.402）：**
> "**PRDATA (APB read data) is available in the cycle after PADDR changes, so no adjustments need to be
>  made on reads from the APB peripheral. On a write, because APB peripherals are not pipelined, HADDR,
>  HWRITE, and HSEL are delayed by a cycle to align with HWDATA. The resulting delay in PREADY would also
>  cause HREADYOUT to be delayed by a cycle.**"

**讀取不用調整，寫入要延遲一週期**——
**因為 APB 不是 pipeline 的，位址和資料必須同時出現。**

**bridge 還要做的事（p.402）：**
- 支援可組態數量的周邊
- 從 AHB 位址解碼器接收每個周邊的 select 訊號
- **內含 APB read mux 選出被選中周邊的結果**
- **接受完整寬度的資料匯流排，用 `HWSTRB` byte enable 做 subword 寫入**

### Burst Transfers

> "**DRAM is organized into rows called *pages*, which are typically 4−16 Kib in size. DRAM reads a full
>  page of memory into its sense amplifiers and returns words much faster from that open page than from a
>  new page. Thus, a DRAM controller is much faster at bursts of accesses to consecutive memory locations
>  than accesses to random memory locations.**"
> — p.402–403

中文解釋：**Burst 的價值來自 DRAM 的物理特性：
開啟的 page 內讀取快很多。**

> "**AHB uses SEQ transactions and the HBURST signal to tell a peripheral that such a burst is occurring so
>  that some peripherals can respond faster. The AHB standard defines various HBURST encodings for fixed
>  and variable length, with addresses that increment or wrap around an aligned line. Simple peripherals
>  ignore the SEQ and HBURST hints and just respond to HADDR.**"
> — p.403

**「簡單的周邊可以忽略 SEQ 和 HBURST 提示，只看 HADDR」**——
**這讓簡單周邊的實作不必支援 burst。**

**Fig. 9.16（p.404）的 4-word burst 波形（p.403 說明）：**
```
Cycle:    0      1        2      3      4      5        6
HADDR:           80       84     88     8C     40
HWDATA:                   1      2      3      4
HTRANS:   IDLE   NONSEQ   SEQ    SEQ    SEQ    NONSEQ   IDLE
HBURST:   SINGLE INCR     INCR   INCR   INCR   SINGLE   SINGLE
HSIZE:    010 (word)
```
**第一拍是 NONSEQ，後續是 SEQ；`HBURST = INCR` 表示位址遞增。
HSIZE = 2 所以每拍 32 bit，4 拍共 128 bit。**

### Multilayer AHB

> "**Multicontroller AHB systems use independent AHB buses called *layers* for each controller. The
>  controllers are connected to peripherals through an interconnect matrix with decoders for each
>  controller and arbiters managing access to each peripheral**, as shown in Fig. 9.17."
> — p.404

中文解釋：**Fig. 9.17（p.404）：每個控制器有自己的 layer，
透過 interconnect matrix（含 input stage、decoder & arbiter）連到周邊。**

**注意仲裁是「每個周邊一個」，不是「整條匯流排一個」**——
所以不同控制器可以同時存取不同周邊。

### AXI：為什麼需要它

> "**AHB is designed for the address phase to take a single clock cycle. The response may take multiple
>  cycles, but one transaction must complete before the next begins. However, modern SoCs must handle
>  multicycle on-chip delays, multiple cores accessing the same peripherals and memory, cache coherence,
>  and devices acting as both a controller and peripheral. As clock frequencies have increased, the flight
>  time to send information across an SoC has become multiple clock cycles.**"
> — p.404–405

中文解釋：**AHB 的四個限制，對應現代 SoC 的四個需求：**

| AHB 的假設 | 現代 SoC 的現實 |
| --- | --- |
| Address 階段一個週期 | **跨 SoC 傳訊號要多個週期**（時脈變高了） |
| **一筆交易完成才能開始下一筆** | 多核同時存取同一周邊和記憶體 |
| 無 cache coherence 支援 | 需要 snoop 其他核心的交易 |
| 控制器和周邊角色固定 | **DMA 裝置兩種角色都要當** |

**DRAM 的額外需求（p.405）：**
> "**The DRAM can service multiple concurrent requests, and access to an open page of DRAM is much faster
>  than access to a new page.**"

### AXI 的解法

> "**The Advanced eXtensible Interface (AXI) addresses all these issues by providing independent pipelined
>  address and data channels operating at high clock rates that handle multiple pending requests and
>  out-of-order responses.... Each channel can have arbitrary latency, so pipeline registers can be added
>  to meet clock speed targets. AXI handles large bursts, such as transferring entire cache lines between
>  memory and a core; the manager only sends the burst's start address, and the subordinate autoincrements
>  the address for subsequent beats. Byte strobes enable unaligned data transfers.**"
> — p.405

中文解釋：**AXI 的四個關鍵能力：**
1. **獨立的 pipeline 位址和資料通道**
2. **多筆 pending 請求 + 亂序回應**
3. **每個通道可以有任意延遲 → 可以插 pipeline 暫存器來拉高時脈**
4. **大 burst：manager 只送起始位址，subordinate 自動遞增**

**第 3 點特別重要：因為「跨 SoC 要多週期」，
所以協定必須容忍任意延遲——這是 AHB 做不到的。**

**AXI 用 manager/subordinate 取代 controller/peripheral。**

### AXI 的五個通道

> "AXI4 is based on five independent transaction channels. **For a read transaction, shown in Fig. 9.18(a),
>  a manager sends address and control information on the *read address channel* to a subordinate.
>  The subordinate responds with a burst of data on the *read data channel*, possibly taking multiple beats
>  (data transfers) to convey the information. For a write transaction, shown in Fig. 9.18(b), a manager
>  sends address and control information on the *write address channel* to a subordinate. It also sends a
>  burst of data on the *write data channel*. The write data burst can come after the address.
>  The subordinate acknowledges on the *write response channel*.**"
> — p.405

中文解釋：**五個通道：**

| 通道 | 方向 | 傳什麼 |
| --- | --- | --- |
| **Read Address** | Manager → Sub | 位址與控制 |
| **Read Data** | Sub → Manager | 讀取資料（可多拍） |
| **Write Address** | Manager → Sub | 位址與控制 |
| **Write Data** | Manager → Sub | 寫入資料（可多拍） |
| **Write Response** | **Sub → Manager** | **寫入確認** |

**注意寫入有獨立的 response 通道——這是 AHB 沒有的。**

**Table 9.7（p.406–407）的訊號命名很規律：**
- **`AR*`** = Read Address（ARID、ARADDR、ARLEN、ARSIZE、ARBURST、ARVALID、ARREADY）
- **`R*`** = Read Data（RID、RDATA、RRESP、RLAST、RVALID、RREADY）
- **`AW*`** = Write Address
- **`W*`** = Write Data（WID、WDATA、WSTRB、WLAST、WVALID、WREADY）
- **`B*`** = Write Response（BID、BRESP、BVALID、BREADY）

**四個關鍵欄位：**
| 欄位 | 意義 |
| --- | --- |
| **`xID`** | **識別標籤，用來區分亂序回應** |
| **`xLEN`** | **Burst 長度（beats）= xLEN + 1** |
| **`xSIZE`** | 每拍的 byte 數 = 2^xSIZE（1…128） |
| **`xLAST`** | **這是交易的最後一拍** |

### VALID/READY 握手：雙向流量控制

> "**Every channel has VALID and READY handshaking signals, thus providing two-way flow control so both the
>  manager and subordinate can control the rate of information movement.... The channel source places
>  information on the channel and raises the VALID signal to begin a transaction. The destination asserts
>  its READY signal to indicate that it is able to accept a transaction; it may do so even before seeing
>  VALID. The transaction occurs on the next rising ACLK edge when both VALID and READY are asserted.
>  The source can then lower VALID.**"
> — p.408

中文解釋：**AXI 握手的核心規則：**
**「VALID 和 READY 同時為 1 的那個時脈上升緣，交易就發生。」**

**關鍵性質：兩邊都能控制速率（雙向流量控制）。
而且 READY 可以在 VALID 之前就 assert（不必等）。**

**Fig. 9.19（p.408）的依賴關係圖，讀法（p.408）：**
> "**signals sent by the manager are blue, and those sent by the subordinate are black. Single-headed arrows
>  point to signals that may be asserted before or after the signal at the start of the arrow.
>  Double-headed arrows point to signals that must be asserted only after the signal at the start of the
>  arrow asserts.**"

**單箭頭 = 前後皆可；雙箭頭 = 必須在後。**

**讀取的握手順序（p.408–409）：**
1. **Manager 放資料在 Read Address 通道並 assert `ARVALID`，不等 `ARREADY`**
2. Subordinate 準備好時 raise `ARREADY`（**可在 ARVALID 之前或之後**）
3. **兩者都 assert 時，subordinate 接受交易**
4. 資料可用時，**subordinate assert `RVALID`，不等 `RREADY`**；`RRESP = 0` 表示成功
5. Manager 準備好時 raise `RREADY`（可在 RVALID 前或後）

**寫入的握手順序（p.409）：**
1. Manager 放位址並 assert `AWVALID`；**同時**放第一拍資料並 assert `WVALID`
2. **連續週期送後續拍，最後一拍 assert `WLAST`**
3. **Manager 不等 `AWREADY` 或 `WREADY` 就驅動 valid 訊號**
4. Subordinate 準備好時 raise `AWREADY` 和 `WREADY`
5. 看到 `AWVALID & AWREADY` → 接受寫入位址
6. 看到 `WVALID & WREADY & WLAST` → 接受寫入資料
7. **兩者都接受同一個 ID 後，subordinate 在 Write Response 通道放 `BRESP` 並 raise `BVALID`**
8. Manager 準備好時 raise `BREADY`

**一個重要的注意事項（p.409）：**
> "**Note that the subordinate may receive information on the Write Address and Write Data channels in
>  either order because of different numbers of register stages in the channel or uncertain delays through
>  the interconnect matrix.**"

**位址和資料到達的順序不確定**——這是「通道獨立」的必然後果。

### 為什麼 AXI 需要 buffer

> "**If sending information on a channel takes multiple cycles, a lag occurs between the time a subordinate
>  deasserts READY and the time the manager sees that the subordinate cannot receive more transactions.
>  The subordinate either needs an input buffer to accept transactions during this lag or must handshake by
>  waiting to assert READY until a VALID transaction arrives on the channel. Waiting on handshakes over a
>  multicycle channel keeps the bus idle most of the time, so buffering is necessary for good performance.**"
> — p.409

中文解釋：**這是 AXI 實作複雜度的主要來源：**
**多週期通道上，「subordinate 說不要了」到「manager 知道」有延遲 →
必須用 input buffer 接住這段期間送出的交易。**
**否則就只能等握手，而那會讓匯流排大部分時間閒置。**

### AXI 的變體

| 變體 | 說明 |
| --- | --- |
| **AXI5** | 加了各種選配功能（loopback、poison bits、ARM 專屬功能） |
| **AXI4-Lite** | **AXI 的子集，限於循序交易、單拍 32 或 64 bit 的 burst**；可用簡單 bridge 接到 AXI |
| **ACE**（AXI Coherence Extensions） | 提供更多 cache coherence 的硬體支援 |
| **CHI**（Coherent Hub Interface） | **擴充 ACE 以支援大型可擴充通訊網路，使用基於目錄的 cache coherence** |

### AXI vs AHB：什麼時候用哪個

> "**AXI is ideal for high-performance on-chip communication because it is easy to support wide buses on
>  chip, and they can be pipelined for speed. AXI's bursts and out-of-order capabilities are well-suited
>  for linking cores to on-chip memory controllers. However, a 32-bit AXI5 bus involves 224 interface pins
>  [AXI21], which is far too many for a chip-to-chip interface on a simple microcontroller. AXI also entails
>  greater implementation complexity, such as buffering of out-of-order responses. AHB is a better fit for
>  small cores with simple peripherals.**"
> — p.410

中文解釋：**選擇的判準很清楚：**

| | **AXI** | **AHB** |
| --- | --- | --- |
| 適合 | **高效能晶片內通訊、核心接記憶體控制器** | **小核心 + 簡單周邊** |
| 接腳數 | **32-bit AXI5 要 224 支接腳**——晶片對晶片介面太多 | 少 |
| 實作複雜度 | 高（要 buffer 亂序回應） | 低 |

**「224 支接腳」這個數字很有說服力——
對簡單微控制器的晶片對晶片介面來說完全不可行。**

## 所以呢

**三種 AMBA 匯流排的定位與選擇：**

| 用途 | 選哪個 |
| --- | --- |
| 慢周邊（UART、GPIO、Timer） | **APB** |
| **小核心 + 簡單周邊** | **AHB**（Wally 用這個） |
| 高效能多核、記憶體控制器 | **AXI**（但 32-bit AXI5 要 224 支接腳） |

三個最該記住的技術點：

1. **AHB 的 pipeline 讓吞吐量約為 APB 的兩倍，
   代價是「寫入資料比位址晚一個週期」**——
   這是從 ARM6 的 3 級 pipeline 繼承來的歷史產物，
   也是 AHB SRAM 介面「寫→讀」要插 wait state 的原因。

2. **AHB 周邊偵測新交易的條件永遠是
   `initTrans = HTRANS[1] & HSEL & HREADY`。**

3. **AXI 的核心是「VALID/READY 雙向握手」和「五個獨立通道」**——
   每個通道可以有任意延遲，所以能插 pipeline 暫存器來拉高時脈。
   **代價是必須用 buffer，否則多週期通道會讓匯流排大部分時間閒置。**
