# 15.5 Summary

> 原書 p.615–616（Chapter 15: Extensions: M (Multiply and Divide)）

## 這節在講什麼

第 15 章總結，五段。

**結構很清楚：為什麼是選配 → 乘法 → 除法 → Wally 實作 → 測試。**

**最有價值的是第二段和第三段的對比：
乘法「交給合成工具」，除法「不能交給合成工具」。**

## 關鍵點

### 為什麼 M 是選配的

> "**The RISC-V base instruction set omits multiply and divide instructions because they require substantially more
>  hardware than other instructions and are not necessary in all applications. The RISC-V M extension defines multiply,
>  divide, and remainder instructions. Different flavors are used for signed and unsigned operands and to obtain the
>  upper or lower half of a 2XLEN-sized product produced by an XLEN × XLEN multiplication.**"
> — p.615

中文解釋：**兩個理由：硬體成本高、不是所有應用都需要。**
（呼應 2.5 節「base 做到最小」的原則。）

### 乘法：交給合成工具

> "**Multiplication involves forming partial products and adding them together. The field has been studied extensively.
>  Booth encoding is used to reduce the number of partial products. Tree multipliers sum the partial products in
>  parallel for greater speed. Logic synthesis understands these optimizations, so the designer can simply write
>  `x * y` and allow the synthesis tool to produce the smallest multiplier that meets delay constraints.**"
> — p.615–616

中文解釋：**兩個最佳化技術 + 一個結論：**

| 技術 | 效果 |
| --- | --- |
| **Booth encoding** | **減少部分積數量** |
| **Tree multiplier** | **並行加總部分積** |

**結論：「寫 `x * y` 讓合成工具產生滿足延遲約束的最小乘法器」。**

**有號無號的處理（p.616）：**
> "**RISC-V defines both signed and unsigned multiplication, which differ in the handling of the most significant bit.
>  Wally handles this by synthesizing an XLEN-1 × XLEN-1 multiplier and adding three partial products that depend on
>  whether the most significant bit is signed.**"

**一句話總結 15.4.1 節：把 msb 分離出來，主體交給合成工具。**

### 除法：不能交給合成工具

> "**Unfortunately, combinational division is both large and slow, so synthesizing X/D generally produces unsatisfactory
>  results. Instead, division is usually implemented sequentially, producing one or a few bits per cycle.**"
> — p.616

中文解釋：**這是本節最重要的對比：**

| | **乘法** | **除法** |
| --- | --- | --- |
| 組合邏輯實作 | **可行且合成工具做得好** | **又大又慢，結果不令人滿意** |
| 實務做法 | **寫 `x * y`** | **循序實作，每週期 1 到數個位元** |

**為什麼差這麼多？**
**因為乘法的部分積可以並行產生和加總（CSA 樹），
但除法的每一步都依賴前一步的餘數——本質上是序列的。**
（呼應 11.4.2 節 HPTW 的頁表走訪：同樣是「下一步依賴上一步」的序列相依。）

**演算法回顧（p.616）：**
> "**A radix-2 restoring integer divider resembles long division in base 2. It initializes the partial remainder to 0.
>  At each step, it shifts 1 bit from the dividend X into the partial remainder. If the divisor D is less than or equal
>  to the partial remainder, the quotient digit is 1, and the divisor is subtracted from the partial remainder.
>  Otherwise, the quotient digit is 0. After XLEN steps, the divider has produced an XLEN-bit quotient, and the partial
>  remainder is the true remainder.**"

**「就像二進位的長除法」——這是最好的直覺。**

### Wally 的實作與兩個 hazard

> "**Wally adds the MDU to support the M extension. Multiplication is slower than other integer operations, so it is
>  pipelined to use both the Execute and Memory stages. Hence, a hazard exists when a multiply result is used by the
>  subsequent instruction. The hazard unit adds an `MDUStall` signal to resolve this hazard by waiting for a cycle.
>  It also adds a `DivBusy` signal to stall the pipeline while multicycle division is taking place.**"
> — p.616

中文解釋：**兩個 hazard 訊號，對應兩種不同的問題：**

| 訊號 | 對應什麼 | 類比 |
| --- | --- | --- |
| **`MDUStall`** | **乘法結果在 Memory 級才有，下一條相依指令要等一個週期** | **和 load-use hazard 一樣** |
| **`DivBusy`** | **除法要很多週期，整條 pipeline 要等** | 沒有類比（第一次需要 stall Execute 級） |

**「乘法比其他整數運算慢，所以 pipeline 成兩級」——
這是典型的「用 pipeline 換時脈」的做法**（呼應 2.7 節）。

### 測試

> "**The riscv-arch-test suite contains test cases for the M extension instructions.**"
> — p.616

中文解釋：呼應 15.3 節——**M 擴充由官方測試涵蓋。**

### 整章的一條主線

中文解釋：**把五段串起來，這一章其實在講一個主題：
「什麼該交給合成工具，什麼不該」。**

| 元件 | 交給合成工具？ | 理由 |
| --- | --- | --- |
| **加法器** | **是**（第 7 章） | 工具會依時序約束選 ripple/prefix |
| **乘法器主體** | **是** | **工具懂 Booth encoding 和 CSA 樹** |
| **乘法器的 msb 處理** | **否** | SystemVerilog 沒有優雅的表達方式 |
| **除法器** | **否** | **組合除法又大又慢** |

**這個判斷標準值得記住：
「這個運算有成熟的並行演算法嗎？」——有就交給工具，沒有就自己做序列電路。**

## 所以呢

**第 15 章的核心是一個對比：乘法交給合成工具，除法必須自己做。**

三件最該帶走的事：

1. **乘法：寫 `x * y` 就好**——
   合成工具懂 Booth encoding 和 CSA 樹，做得和手工一樣好。
   **Wally 唯一的例外是「把 msb 分離出來」處理有號無號。**

2. **除法：組合邏輯實作又大又慢**——
   必須用循序的 radix-2 restoring 演算法，**每週期 1 到數個位元**。
   **根本原因是「每一步依賴前一步的餘數」的序列相依。**

3. **兩個新的 hazard 訊號**：
   **`MDUStall`**（乘法結果在 Memory 級，和 load-use 一樣）和
   **`DivBusy`**（除法要很多週期，**第一次需要 stall Execute 級**）。

**一個可以帶到其他設計的判斷標準：
「這個運算有成熟的並行演算法嗎？」——
有就交給合成工具，沒有就自己做序列電路。**
