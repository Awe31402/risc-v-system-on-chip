# 11.4 Wally Implementation

> 原書 p.495–512（Chapter 11: Memory Management Unit）
> 涵蓋 11.4.1 MMU、11.4.2 HPTW、11.4.3 MMU Faults、11.4.4 Fence Instruction

## 這節在講什麼

**Wally 的 MMU 實作。**

結構很清楚：
```
MMU（IFU 和 LSU 各一個）
├── TLB（虛擬記憶體啟用時）
│   ├── tlbcam    ← CAM，比對 VPN 和 ASID
│   ├── tlbram    ← 存 PTE
│   ├── tlbmixer  ← 組合 PPN 和 page offset
│   ├── tlblru    ← 選替換的項目
│   └── tlbcontrol ← 判斷 hit/miss/page fault
├── pmpchecker（PMP_ENTRIES > 0 時）
└── pmachecker（永遠有）

HPTW（只有一個，在 LSU 裡，服務兩個 TLB）
```

**最該精讀的是 11.4.1.3 的 TLB 五個子模組，以及 11.4.2 的 HPTW 狀態機。**

## 關鍵點

### 兩個 MMU 加一個 HPTW

> "**Wally has two MMUs: an instruction MMU (IMMU) in the IFU and a data MMU (DMMU) in the LSU. Both have
>  identical SystemVerilog code, but the IMMU receives only execute requests (but no read or write requests),
>  and the DMMU receives only read or write requests (but no execute requests), so logic synthesis optimizes
>  out unnecessary access fault circuitry based on the parameters.**"
> — p.496

中文解釋：**同一份程式碼，靠參數讓合成器最佳化掉不需要的部分**（呼應 4.2.5.1 節）。

**MMU 的可組態範圍（p.496）：**
> "**At a minimum, the MMU must contain a small PMA checker to detect access and alignment faults for memory
>  reads and writes. At a maximum, the MMU further contains a TLB for virtual memory, a PMP checker with 16 or
>  64 entries, and a PMA checker that supports many devices. The MMUs are present whenever
>  ZICSR_SUPPORTED = 1 because they generate the access, misaligned, and page faults.**"

**PMA checker 是最小必要配備**——因為 access fault 和 misaligned fault 都由它產生。

**為什麼只有一個 HPTW（p.496）：**
> "**The HPTW services both instruction and data TLB misses; only one HPTW is needed because only one miss can
>  be serviced at a time through the bus interface anyway. All page table accesses are routed through the data
>  cache (and on to external memory if the cache misses) and are checked by PMA and PMP checkers in the DMMU.**"

**理由很實際：匯流排一次只能服務一個 miss，所以兩個 HPTW 沒意義。**
**而且所有頁表存取都走資料 cache——這樣頁表也能被 cache 加速。**

### 組態參數

中文解釋：**p.497 的六個關鍵參數：**

| 參數 | 意義 |
| --- | --- |
| **`VIRTMEM_SUPPORTED`** | 1 = 啟用虛擬記憶體 |
| **`ITLB_ENTRIES` / `DTLB_ENTRIES`** | **TLB 大小，典型各 16 個** |
| **`PMP_ENTRIES`** | 0、16 或 64 |
| **`SVNAPOT_SUPPORTED`** | 64-KiB huge page |
| `SVPBMT_SUPPORTED` | Page-based memory types |
| **`SVADU_SUPPORTED`** | **HPTW 在硬體中更新 PTE 的 A/D 位元** |

**記憶體映射由 `configs/*/config.vh` 的 `BASE` 和 `RANGE` 參數指定**；
**實體位址 `PA_BITS` 是 RV32 的 34 或 RV64 的 56**（p.497）。

### MMU 的關鍵路徑

> "**The MMU is on the critical path in Wally's 5-stage pipeline. The path occurs in the Memory stage, starting
>  with the TLB translating a virtual address to a physical address. The PMP checker then compares this address
>  to the PMP CSRs to determine if an access fault occurred. The privileged unit combines this information with
>  other possible faults to cause a trap. The trap changes the program counter, which must set up in time to
>  access the L1 I$ on the rising edge at the end of the cycle.**"
> — p.497–498

中文解釋：**這條關鍵路徑很長，而且呼應 6.5.3 節 Table 6.11
（rv64gc 的關鍵路徑就在 PMP 檢查）和 6.6 節的結論：**

```
TLB 轉譯 → PMP 檢查 → privileged 單元合併 fault → 改 PC → 及時 setup 存取 L1 I$
```

**「PMP 檢查在 TLB 送出實體位址之後才開始，而且必須及時完成以處理 fault。
這可能限制時脈週期。」**（p.502）

### PMA Checker 的實作

> "**The PMA checker uses the physical address to determine which memory region is accessed and the properties
>  of that region. The PMA triggers an access fault if the region is vacant or does not support the type or
>  size of access. Fig. 11.16 shows a block diagram of the RV64 PMA checker (`pmachecker`). It contains an array
>  of address decoders (`adrdecs`) to check addresses in each region of the memory map.**"
> — p.498

中文解釋：**Fig. 11.16（p.499）的結構：11 個 `adrdec`（每個記憶體區域一個），
產生 one-hot 的 `SelRegions`，再由 OR 閘組合出屬性：**

```
SelRegions[3,4,5] → Cacheable        （UNCORE_RAM、EXT_MEM、BOOTROM）
SelRegions[1,2,3,4,5] → Idempotent
SelRegions[1,2] → SelTIM             （DTIM、IROM）
SelRegions[1,3,5] → AtomicAllowed
SelRegions[0] → PMAAccessFault       （沒有區域匹配 = vacant）
```

**每個 `adrdec` 內部（Fig. 11.16 放大部分）：**
```
PhysicalAddress 的上位元與 BASE 比對 → Match
Size 與 SizeMask 比對 → SizeValid
AccessRW/AccessRX/AccessRWX 檢查 → AccessValid
三者 AND → SelRegions[i]
```

**位址解碼的最佳化（p.500）——這段很有洞見：**
> "**Wally address decoding is made fast and cheap by imposing a natural alignment requirement on the memory map
>  that each region covers all the possible combinations of the least significant bits while having the upper
>  significant bits be the same. For example, a region of 0x01000800-0x01000BFF is legal because it spans all
>  values of the bottom 10 address bits while keeping the upper 24 address bits the same. A region of
>  0x00001000-0x00003FFF is not legal because not all combinations of the lower 13 bits are in the region.
>  Because regions satisfy this requirement, address decoding simply involves an equality comparison on the
>  upper k bits of the address, which involves k 2-input XNOR gates and a k-input AND gate but no costly
>  subtraction. The base address is hardwired, so the XNORs further simplify to NOT gates or wires.**"

**關鍵設計決定：要求記憶體映射「自然對齊」，
把「範圍比較」（需要減法）變成「相等比較」（只要 XNOR + AND）。**

**而且 base address 是硬接的，所以 XNOR 進一步簡化成 NOT 閘或直接接線。**

**（Fig. 11.17（p.500）示範 0x001000800–0x001000BFF 的 Match 邏輯：
只比對上 24 個位元 `0b00 0000 0001 0000 0000 0000 10`。）**

**和 PMP 的對比（p.500）：**
> "**Compared to the PMP checker, the PMA checker does not need a costly priority encoder to choose among
>  multiple matching regions.**"

**PMA 的區域不重疊，所以不需要優先權編碼器；PMP 會重疊，所以需要。**

**兩個最佳化（p.500）：**
> "**Although the PMA checker is written to handle both instruction and data accesses, the ReadAccess and
>  WriteAccess signals are tied low for the IMMU, and the ExecuteAccess signal is tied low for the DMMU, so
>  logic synthesis can optimize away the unneeded access types in each PMA checker. If a given peripheral is
>  not supported, its address decoder (`adrdec`) is also optimized out of the circuit.**"

### PMP Checker 的實作

> "**The PMP checker causes access faults when a physical address violates PMP permission. Fig. 11.18 shows a
>  block diagram of the PMP checker. It contains 16 or 64 PMP address decoder (`pmpadrdec`) blocks, each of
>  which checks one PMP entry. Each `pmpadrdec` performs a less than comparison and a masked equality comparison
>  to check for TOR and NAPOT/NA4 (naturally aligned) matches. The masked equality comparator tests only the
>  more significant bits, disregarding trailing zeros in the PMP address.**"
> — p.501

中文解釋：**每個 `pmpadrdec` 做兩種比較：**
- **小於比較**（給 TOR 用）
- **遮罩相等比較**（給 NAPOT/NA4 用）

**優先權編碼（p.501）——用了一個聰明的手法：**
> "**More than one PMP entry could match a given address. A distributed priority encoder determines the first PMP
>  entry that matches, FirstMatch. It uses daisy-chained AND gates to create a thermometer-encoded NoLowerMatch
>  signal that is 1 for all of the entries up to the first match. The R, W, X, and L fields of `pmpcfg` for that
>  entry are extracted using a distributed mux made of AND gates and a wide OR.**"

**溫度計編碼（thermometer code）：`NoLowerMatch[i] = 1` 表示「編號 < i 的都沒匹配」。
`FirstMatch[i] = Match[i] & NoLowerMatch[i]`。**
（呼應 4.2.5.4 節那個 `prioritythermometer` 的範例。）

**PMP 的執行條件（p.501）：**
> "**`pmpchecker` enforces PMP rules when matching a locked region in M-mode, or anytime in S- or U-mode.**"

**關鍵路徑（p.501）：**
> "**The critical path through the PMP checker includes the magnitude comparator, priority encoder, wide OR, and
>  a handful of other gates.**"

**（p.501 邊欄的 grain size 提醒：**
「當 Wally 支援壓縮指令或未對齊的 load/store 時，**還需要 grain size（PMP 區域大小）至少和 cache line 一樣大。
跨越 grain 邊界的未對齊存取會被拆解成多次較小的存取。PMP 檢查對每次存取獨立執行，任何一次失敗就 trap。**」**）

### TLB 的整體結構

> "**The TLB quickly translates virtual to physical addresses using a cache of recent translations.
>  It behaves as a fully associative cache with {I/D}TLB_ENTRIES. Each entry consists of a VPN, ASID, PTE
>  (containing the PPN and access bits), and status bits including Page Type and Valid bits. During a memory
>  access, the TLB searches all entries in parallel. If it finds a PTE that matches the ASID in the satp register
>  and the VPN in the upper bits of the address, then the TLB checks the access permissions and either outputs
>  the PPN or triggers a page fault. If the TLB does not find a match, it invokes the HPTW to traverse the page
>  tables in main memory and fetch the missing PTE. An entry with the new PTE replaces one of the TLB's least
>  recently used entries.**"
> — p.502

中文解釋：**Fig. 11.19（p.503）的五個子模組：**

| 模組 | 職責 |
| --- | --- |
| **`tlbcam`** | **CAM（content-addressable memory）：比對 tag（VPN + ASID）** |
| **`tlbram`** | **存 PTE** |
| **`tlblru`** | LRU 替換邏輯 |
| **`tlbmixer`** | **組合 PPN 和 page offset 成實體位址** |
| **`tlbcontrol`** | **判斷 hit/miss/page fault、是否該轉譯** |

**加上一個 Misalign Logic（偵測 superpage 的對齊錯誤）。**

**One-hot 訊號的設計（p.502）：**
> "**Unlike a conventional memory that accepts an address in binary and decodes it, the TLB has 1-hot Matches and
>  WriteEnables signals to access an entry. The `tlblru` generates one WriteEnable for each entry, and the
>  `tlbcam` generates one Match for each entry.**"

**（p.502 邊欄的三個定義：**
「**fully associative cache 只有一個 set 和 N 個 way**，N 是行數（TLB 的話是項目數）。」
「**CAM 把輸入和每個項目比對。N 項的 CAM 由 N 個比較器組成。輸入匹配某項時，該項的 match 訊號 assert。**」
「**一個 PTE 最多存在一個 TLB 項目裡，所以最多一個項目會匹配。**」**）

### `tlbcam`：CAM 的實作

> "**Fig. 11.20 shows a schematic of the TLB CAM, which holds the tags. The CAM is shown for systems that support
>  Sv48 with a 36-bit VPN; those that only handle Sv39 or Sv32 use fewer bits and comparators. The CAM uses flops
>  to hold the VPN, ASID, Page Type, and Valid bit. Each entry receives a write enable. The Valid bit is set to 1
>  on a write and cleared for all lines on a CAM flush.**"
> — p.502

中文解釋：**Table 11.7（p.502）的 PageType 編碼：**

| PageType | Type |
| --- | --- |
| **00** | **kilopage** |
| 01 | megapage |
| 10 | gigapage |
| 11 | terapage |

**Superpage 的比對規則（p.502–503）：**
> "**The CAM matches if the VPN of the current access and the ASID field in satp match the values stored in a CAM
>  line. Lower-order bits of the VPN are ignored for superpages, and the most significant bits are ignored when
>  operating in Sv39 mode. The ASID is ignored if the PTE entry is marked global in the TLB RAM.**"

**三種「忽略」：superpage 忽略低位 VPN、Sv39 忽略高位、global page 忽略 ASID。**

**Fig. 11.20 的電路：**
```
Key_ASID 比 satp.ASID → MatchASID（或被 PTE_G 蓋過）
Key3 比 VPN[35:27] → Match3（或被 TeraPage 蓋過）
Key2 比 VPN[26:18] → Match2（或被 TeraGigaPage 蓋過）
Key1 比 VPN[17:9]  → Match1（或被 TeraGigaMegaPage 蓋過）
Key0 比 VPN[8:0]   → Match0
全部 AND + Valid → Match
```

**注意那三個 `Tera...Page` 訊號是由 PageType 解碼出來的「這一層要忽略」的旗標——
很漂亮的設計。**

**分散式 AND-OR 多工器（p.503）：**
> "**`CAMHit` asserts when any of the lines Match and TLBFlush is low. The CAM also outputs HitPageType, which
>  indicates the type of the matched line. CAMHit and HitPageType are output using a distributed AND-OR
>  multiplexer similar to Fig. 10.25 to combine the outputs of all the TLB lines (`tlbcamlines`)....
>  each `tlbcamline`'s PageType is ANDed with Match to produce PageTypeRead (so at most one PageTypeRead will be
>  1). Then `tlbcam` ORs PageTypeRead from all lines to produce HitPageType.**"

（呼應 10.4.5.1 節：分散式 AND-OR mux 又出現了。）

**（p.503 邊欄的實作現實：**
「傳統的客製 CAM 用特殊的 cell（同時存一個 bit 並偵測匹配）。
**典型的合成 ASIC 和 FPGA 缺少這種 cell，所以 TLB 用 flip-flop 和閘實作。**」**）

### `tlbram` 與 `tlbmixer`

**`tlbram`（p.504）：**
> "**`tlbram`, like `tlbcam`, is also built using flops on an FPGA or ASIC. `tlbram` holds TLB_ENTRIES lines, each
>  containing a PTE (PageTableEntry) which holds the PPN and 8 access bits.... Like `tlbcam`, the WriteEnables bus
>  determines which line to write, and a distributed AND-OR multiplexer reads out the line matched by the CAM.
>  Essentially, the Matches signals act as read enables to select which entry, if any, to read out.**"

**`tlbmixer`（p.504）——這個模組實現了 superpage 的位址組合：**
> "**It forms the PPN from a combination of the VPN and PPN and the page offset. For kilopages, it concatenates
>  the PPN with the page offset to form the physical address. For superpages, it selects some of the lower-order
>  page number bits from the VPN rather than the PPN, as shown in Example 11.5. Because these low-order bits are
>  always 0 in the PPN, the selection logic reduces from a multiplexer to an AND-OR gate.**"

**Fig. 11.22（p.505）的 `PageNumberMask`：**
```
HitPageType = 00 → 00000000000  （kilopage，全部用 PPN）
              01 → 000000001FF  （megapage，低 9 bits 用 VPN）
              10 → 0000003FFFF  （gigapage，低 18 bits 用 VPN）
              11 → 00007FFFFFF  （terapage，低 27 bits 用 VPN）

PPNMixed = (VPN & Mask) | PPN      ← AND-OR，不是多工器
TLBPAdr  = {PPNMixed, Offset[11:0]} & {TLBHit}
```

**「因為 PPN 的低位元在 superpage 中永遠是 0，所以選擇邏輯從多工器簡化成 AND-OR 閘」——
又一個「利用常數簡化硬體」的例子**（呼應 10.4.4 節的 pLRU）。

**TLB miss 時強制實體位址為 0（p.504）：**
> "**If the TLB misses, the physical address is forced to 0 (NULL); this isn't strictly necessary but will cause
>  an access fault in the event that the TLB output is incorrectly used later.**"

**這是防禦性設計：讓錯誤盡早暴露**（呼應 11.2.2.1 節「位址 0 不放記憶體」）。

### `tlblru`：比 cache 的 pLRU 更簡化

> "**Fig. 11.23 shows a schematic of the TLB LRU unit that determines a least-recently used entry to replace.
>  True LRU logic is too costly, so the block approximates it by keeping track of each entry that has been
>  accessed and picking the first entry that hasn't been accessed. The recently used bits (RUBits) register keeps
>  track of recently used entries. If all entries have been used recently, then all entries' RUBits are cleared.
>  The priority unit `pri` picks the first entry that has not been recently used. On a write, the corresponding
>  bit in the WriteEnables bus is raised to write the selected line of the CAM (tag) and RAM (PTE).**"
> — p.505

中文解釋：**這是比 cache 的樹狀 pLRU 更簡單的近似：**
```
每個項目一個 RUBit
被存取 → 設 RUBit
全部都被設了 → 全部清除
替換時 → 選第一個 RUBit = 0 的
```

**這正是 11.2.1.4 節說的 OS 用 A 位元做 pLRU 的同一個演算法**——
硬體和軟體用了同樣的思路。

### `tlbcontrol`：六種 page fault 條件

> "**The `tlbcontrol` module determines the effective privilege mode; whether translation should occur; and
>  whether the TLB hit, missed, or caused a page fault.**"
> — p.505

**Effective privilege mode（p.506）：**
> "**The TLB's EffectivePrivilegeMode is normally PrivilegeModeW, but is status.MPP for the DTLB when the
>  status.MPRV bit is set. Virtual address translation is enabled for S- and U-mode accesses when
>  satp.MODE ≠ BARE but disabled during page table walks and cache flushes.**"

**兩個「停用轉譯」的時機：頁表走訪期間（位址已經是實體的）和 cache flush 期間。**

**六種 page fault 條件（p.506），這份清單很完整：**

| 條件 | 說明 |
| --- | --- |
| **`UpperBitsUnequalPageFault`** | **VA 的高位元和 VPN 的 msb 不符**（呼應 11.2.1.2 節的符號延伸要求） |
| **`ImproperPrivilege`** | **有效特權模式和 `PTE.U` 不符**（也考慮 `status.SUM`） |
| **`InvalidRead`/`InvalidWrite`** | **操作被 `PTE.X/R/W` 禁止**（也考慮 `status.MXR`） |
| **`UpdateDA`** | **`PTE.A` 為 0，或寫入時 `PTE.D` 為 0**。**`SVADU_SUPPORTED = 0` 或 `menvcfg.ADUE = 0` 時 assert page fault 讓軟體處理；否則由 HPTW 管理** |
| **`PTE.V = 0`** | PTE 無效 |
| **`Misaligned`** | **superpage 的 PPN 未對齊** |

**ITLB 的差異（p.506）：**
> "**The ITLB is similar to the DTLB but is only used for instruction fetches. Hence, it checks PTE.X rather than
>  InvalidRead/InvalidWrite.**"

### Svnapot 的實作成本很低

> "**When SVNAPOT_SUPPORTED = 1, the `tlbram` also asserts a PTE_NAPOT signal for each entry that is marked as a
>  64-KiB huge page by having the PTE.N bit set and PPN[3:0] = 1000. For huge pages, the `tlbcam` ignores the
>  bottom four bits of the VPN, and the `tlbmixer` replaces the bottom four bits of the page number with the
>  corresponding VPN bits. Hence, the cost of supporting huge pages is small. Only one TLB entry is used for the
>  64-KiB huge page compared to 16 entries to hold consecutive 4-KiB regular pages.**"
> — p.507

中文解釋：**實作成本小，效益大（16 → 1 個 TLB 項目）**——
因為它重用了已有的機制（`tlbcam` 忽略位元、`tlbmixer` 換位元）。

### HPTW 的資料通路

> "**The HPTW services a TLB miss by issuing a sequence of physical memory accesses to traverse the page table and
>  fetch the missing PTE into the TLB. The HPTW consists of a datapath to insert page table accesses into the LSU,
>  an FSM to sequence the walk through the multilevel page table, and control logic to detect page faults.**"
> — p.507

中文解釋：**Fig. 11.25（p.508）的資料通路（p.508 說明）：**
> "**During a page table walk, the `IHAdrM` mux overrides the normal `IEUAdrM` to send a physical PTE address
>  (HPTWAdr) to the LSU. The walker receives the PTE on ReadDataM and captures it in the PTE register.
>  Whereas the most significant bits of the HPTW address (HPTWAdr) come from the PPN, the least significant bits
>  are the page offset, which is selected from a field in the VPN based on the current level of the page table
>  walk. The virtual address in turn comes from either IEUAdrM or PCF for data or instruction TLB misses,
>  respectively. On the initial step, the satp register provides the PPN of the top-level page table.
>  On subsequent steps, the PPN comes from the PTE of the previous step.**"

**位址的組成：**
```
HPTWAdr = {PPN（來自 satp 或前一層的 PTE）, VPN 的對應欄位（依目前層級）, 00}
```

**（p.508 邊欄的關鍵設計：**
「**HPTW 解除 LSU（和它的 D$）的 stall，同時其餘 pipeline 保持 stall，
這樣 HPTW 才能發出資料記憶體請求來存取 PTE。**」**）

**（p.508 邊欄的 fault 報告規則：**
「依照 RISC-V 規格，**HPTW 觸發 access fault 時，回報的是「原本造成頁表走訪的那種存取」的 access fault。
例如，指令抓取造成頁表走訪，而壞的 PTE 讓 HPTW 去讀不存在的記憶體位置，
MMU 會造成 *instruction* access fault 而非 load access fault。**
這樣例外處理器就知道根本原因和指令抓取有關而非 load 指令。」**）

### HPTW 的狀態機

中文解釋：**Fig. 11.26（p.509）的狀態機。核心結構：**

```
Idle ──(TLBMiss)──→ 依模式進入 L3_Adr(Sv48) / L2_Adr(Sv39) / L1_Adr(Sv32)
                     ↓
      每一層：Lx_Adr ──→ Lx_Rd ──(ValidNonLeafPTE)──→ L(x-1)_Adr
                     ↓ （不是 nonleaf）
                    Leaf ──→ Idle
      任何一層：LSUAccessFaultM | PBMTOrDAUFaultM → Fault → Idle
      （Svadu 時）Leaf ──(HPTWUpdateDA)──→ Update_PTE ──→ Leaf
```

**每一層至少兩個週期（p.508）：**
> "**Each level of the page table walk involves at least two cycles: driving the physical address to the LSU and
>  reading the PTE from the LSU. These steps cannot be pipelined because the next physical address depends on the
>  previous level's PTE.**"

**「不能 pipeline，因為下一層的位址取決於上一層的 PTE」——這是根本的序列相依。**

**所以 Sv48 的 TLB miss 至少要 8 個週期（4 層 × 2），加上 cache miss 的話更多。**

**每個狀態的輸出：`SelHPTW`（選擇 HPTW 的位址）、`HPTWStall`、
`HPTWRead`（在 Rd 狀態）。**

### HPTW Stalls 的細微之處

> "**When the HPTW is walking the page table, it asserts SelHPTW. This drives the `IHAdrM` multiplexer from
>  Fig. 11.25 to choose the address from the walker. Not shown in the figure, muxes also choose control signals
>  (e.g., the read enable and access size) from the walker.**"
> — p.510

> "**During a walk, HPTWStall asserts LSUStallM, which in turn asserts StallW to stall the pipeline. However, the
>  LSU doesn't stall. The `GatedStallW = StallW & ~SelHPTW` signal stalls the LSU when high, but it remains low
>  during a walk so that the LSU can continue to serve the walker requests while the rest of the pipeline stalls.**"
> — p.510

中文解釋：**這是一個很巧妙的設計：**
```
HPTWStall → LSUStallM → StallW → 整條 pipeline stall
但  GatedStallW = StallW & ~SelHPTW → 走訪期間為 0 → LSU 不 stall
```

**「整條 pipeline 停住，但 LSU 繼續跑以服務 HPTW」**——
這就是為什麼 HPTW 放在 LSU 裡。

### PTE 狀態位元的硬體更新（Svadu）

> "**Because not all hardware implementations support writing the PTE status bits, the OS must have code to support
>  this. However, the page fault handler takes a significant amount of time, so a hardware implementation is
>  attractive.**"
> — p.510

中文解釋：**Fig. 11.27（p.510）在 Fig. 11.25 上加了藍色的新硬體：**
- **`IHWriteDataM`**：用更新後的 PTE 寫頁表（取代一般的 `WriteDataM`）
- **`UpdatePTE` mux**：修改 A 和 D 位元
- **`HPTWReadAdr` / `HPTWWriteAdr`**：存下 leaf PTE 的位址以便寫回
- 一個暫存器和 mux 保存 leaf PTE 位址

**流程（p.511）：**
> "**The HPTW asserts HPTWUpdateDA when the A or D bits need to be updated. When hardware status bit updates are
>  disabled, this triggers a page fault. When hardware status bit updates are enabled and the FSM enters the Leaf
>  state, HPTWUpdateDA causes the FSM to go to the Update_PTE state rather than writing the TLB.
>  In Update_PTE, the FSM asserts HPTWRWM[0] to write the PTE back to memory, then returns to the Leaf state to
>  write the updated PTE to the TLB.**"

**兩次寫入必須是原子的（p.511）——這段很重要：**
> "**These two writes must be atomic so that the RAM and TLB remain coherent. This is guaranteed because interrupts
>  are disabled during page table walking because SelHPTW asserts CommittedM.**"

**「`SelHPTW` assert `CommittedM`，所以走訪期間中斷被停用」——
這保證了「寫記憶體」和「寫 TLB」兩個動作之間不會被打斷。**
（呼應 9.5.5、10.4.7 節的 `Committed` 機制。）

**Fault 的處理（p.511）：**
> "**The memory write may cause a PMA or PMP access fault, but no such check occurs with the TLB write.
>  If the PMA or PMP checkers fault, LSUAccessFaultM = 1 and the HPTW aborts immediately by transitioning to the
>  Fault state and then returning to Idle, thus not writing the TLB. The HPTW also exits to the Fault state if a
>  nonleaf PTE contains nonzero dirty, access, user, or PBMT bits (if Svpbmt is supported and enabled) when
>  PBMTOrADUFaultM = 1.**"

### MMU Fault 邏輯

> "**The MMU is responsible for access, misaligned, and page faults for instructions, loads, and store/AMO
>  operations, except that instruction-misaligned faults are created by the IFU based on the branch target
>  address.**"
> — p.511

中文解釋：**Fig. 11.28（p.512）合併四個來源：PMA、PMP、TLB、對齊檢查。**

**三個要點：**
1. **`Align Check` 驗證 `VAdr` 是存取大小的倍數**
2. **`privilegepiperegs` 把 Fetch 級的指令 fault pipeline 到 Memory 級**（trap 在那裡發生，呼應 8.4.1 節）
3. **「讀寫記憶體的原子操作 assert store/AMO fault 而非 load fault」**

**（p.511 邊欄的分工：**「IMMU 產生 instruction fault，DMMU 產生 load 和 store fault。
**回報原始原因（例如是 load 還是 store fault）的邏輯，在 HPTW 存取發生 fault 時，未顯示在 Fig. 11.28。**」

以及一個簡化技巧：**「如果 HPTW 遇到非法的 PTE（例如 `V = 0`），
它會把該項寫進 TLB 但不立即產生 fault。指令被重播時會抓到那個壞項目並在那時觸發 page fault。
**這個做法藉由重用既有的 page fault 機制簡化了 Wally 的 HPTW 實作。**」**）

### Fence 指令的實作

> "**The `sfence.vma` instruction flushes the TLB. Although the instruction supports flushing only particular
>  address space IDs or virtual addresses, Wally's simple implementation *overfences* by flushing all entries.**"
> — p.511

中文解釋：**"overfences"（過度 fence）是個好詞：
規格允許精細的 invalidate（只針對特定 ASID 或虛擬位址），
但 Wally 簡化成「全部清掉」——正確但效能較差。**

**虛擬化支援（p.511）：**
> "**If executed in supervisor mode when the `status.TVM` bit is set, `sfence.vma` raises an illegal-instruction
>  exception instead, to support virtualization.**"
（呼應 8.2.3.1 節的 TVM。）

**Svinval 擴充（p.511–512）：**
> "**The Svinval extension (SVINVAL_SUPPORTED = 1) adds the `sinval.vma`, `sfence.w.inval`, and `sfence.inval.ir`
>  instructions. These fine-grained TLB invalidation instructions provide further control of ordering for
>  out-of-order and multicore machines. Wally simply treats them the same as `sfence.vma`.**"

**Wally 把它們全都當成 `sfence.vma`——又一次的「正確但保守」。**

## 所以呢

**這節是 MMU 的完整實作。五件最該帶走的事：**

1. **兩個 MMU 但只有一個 HPTW**——
   因為匯流排一次只能服務一個 miss。**HPTW 放在 LSU 裡，
   所有頁表存取都走資料 cache。**

2. **位址解碼的最佳化**：要求記憶體映射自然對齊，
   **把「範圍比較」（需要減法）變成「相等比較」（XNOR + AND）。**
   PMA 的區域不重疊所以不需要優先權編碼器，PMP 會重疊所以需要。

3. **`tlbmixer` 的 AND-OR 簡化**：
   **因為 superpage 的 PPN 低位元永遠是 0，多工器可以退化成 AND-OR 閘**——
   和 10.4.4 節的 pLRU 是同一種「利用常數簡化硬體」的手法。

4. **`GatedStallW = StallW & ~SelHPTW`**：
   **整條 pipeline stall 但 LSU 繼續跑**，這樣 HPTW 才能發出記憶體請求。

5. **HPTW 的兩個「重用既有機制」的簡化**：
   **非法 PTE 照樣寫進 TLB，讓重播時的一般 page fault 機制去處理**；
   **Svadu 的兩次寫入靠 `CommittedM` 保證原子性。**

**還有一個誠實的地方：`sfence.vma` 是 overfence（全清），
Svinval 的細粒度指令也全當成 `sfence.vma`——正確但保守。**
