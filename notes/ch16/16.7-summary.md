# 16.7 Summary

> 原書 p.669–671（Chapter 16: Extensions: F/D/Q/Zfh/Zfa (Floating-Point)）

## 這節在講什麼

第 16 章的總結。把 IEEE 754 的格式、FPU 四大單元的演算法、多精度共用的策略、RISC-V 的具體約定、驗證方法，濃縮成幾段。值得單獨讀一次，因為書在這裡把「為什麼要這樣設計」講得比正文更直白。

## 關鍵點

### IEEE 754 解決的是什麼問題

> "The IEEE 754 Floating-Point Standard revolutionized numerical computing by allowing programmers to write code that behaves identically on different computers and performs gracefully in exceptional circumstances."
> — p.669

中文解釋：兩個字：**可攜**與**優雅**。標準之前，同一段程式在不同機器上算出不同答案；遇到除以零就當掉。IEEE 754 讓答案一致，也讓例外情況有定義良好的結果（∞、NaN、subnormal）而不是崩潰。

### 格式與 gradual underflow

> "Normalized numbers are of the form (−1)^s × (1.f) × (2^(e−bias)), where s is the sign, f is the fraction bits, and e is the exponent. The largest exponent is reserved for infinity and NaN. The smallest exponent is used for zero and subnormal numbers, which provide gradual underflow for more stable numerical computing."
> — p.669

中文解釋：注意 gradual underflow（漸進下溢）的價值敘述——「更穩定的數值計算」。沒有 subnormal 的話，兩個不相等的小數字相減可能得到 0，破壞「a ≠ b ⟹ a − b ≠ 0」這個程式設計師會依賴的性質。

### 多精度共用硬體的六個步驟

> "FPUs often support multiple-precision operands on shared hardware. This involves the following: Unpacking the specified-precision operands into the longest supported format; Detecting special cases; Performing the operation in the longest format; Normalization shift; Rounding to the specified precision; Handling special cases; Updating flags"
> — p.669–670

中文解釋：這七行就是 16.6 那一大節的骨架。核心句是「Performing the operation in the longest format」——全部用最寬格式算，只有進出兩端關心目標精度。

### FMA 為什麼值得拿來做所有事

> "The FMA block computes W = X × Y ± Z. Thus, it can also be used to perform addition, subtraction, and multiplication by setting Y to 1 or Z to 0. Wally uses the FMA for all four operations to save chip area."
> — p.670

中文解釋：理由直接寫出來了：**省晶片面積**。代價是純加法要走一條為乘加設計的長路徑，比專用加法器慢一點。

### 高效能 FMA 的兩個優化

> "High-performance FMAs have several logic optimizations, such as a dual path adder to remove absolute value logic from the critical path, and a leading zero anticipator to speed up normalization."
> — p.670

中文解釋：dual path（雙路徑）是 16.2.2 提到的 multipath 優化——根據指數差大小走不同路徑，把絕對值邏輯從關鍵路徑移開。LZA 在 16.2.2 講過：與加法平行預測前導零數量。Wally 用的是簡單的 single-path 版本。

### divsqrt 的四個要點

> "The key to recurrence divsqrt is to avoid slow carry-propagate addition in each step. To do this, the residual is maintained in carry-save redundant form... Furthermore, the recurrence algorithm uses a symmetric redundant digit set for the quotient or square root digits: {−1, 0, 1} for radix 2, or {−2, −1, 0, 1, 2} for radix 4. ... The algorithm uses an on-the-fly converter to form the nonredundant binary result without a CPA."
> — p.670

中文解釋：三層「避免慢加法」的設計疊在一起：部分餘數用 carry-save（避免進位傳遞）、商數位元用冗餘集合（讓猜錯可修正）、結果轉換用 on-the-fly（避免最後再來一次完整加法 CPA）。另外開根號需要輸入在 [1/4, 1) 且指數為偶數，所以要右移一到兩位——和除法需要 [1, 2) 的要求不同，這是兩者共用硬體時要處理的差異。

### 比較單元的一句話總結

> "The compare block takes advantage of the fact that positive floating-point numbers can be ordered with simple integer comparison. Therefore, it involves an integer comparator and some logic to handle sign correction and special cases."
> — p.671

中文解釋：biased exponent 的設計回報在這裡兌現——比較幾乎不花額外硬體。

### 驗證的一句話總結

> "Floating-point has many tricky corner cases and is notoriously difficult to get right. We check it against the UCB SoftFloat reference model using TestFloat and riscv-arch-test (IBM) test vectors."
> — p.671

中文解釋：兩層驗證、一個參考模型，就是 16.5 的全部。

### Wally FPU 的一句話定位

> "Wally implements a simple FPU operating in the Execute and Memory stages with a critical path comparable to the cache access paths in the rv{32/64}gc configurations. The fdivsqrt unit supports both floating-point and integer division and uses multiple copies of recurrence hardware to produce many result bits per cycle."
> — p.671

中文解釋：「critical path comparable to the cache access paths」這句是設計目標的表述——FPU 不該成為新的瓶頸，跟原本就最慢的快取存取路徑打平就夠了。再快就是浪費面積。

## 名詞表

| 名詞 | 意思 |
| --- | --- |
| gradual underflow | 漸進下溢，靠 subnormal 讓極小數逐步失去精度而非突然變 0 |
| dual path adder | FMA 的雙路徑優化，依指數差走不同路徑 |
| residual | 除法遞迴中的部分餘數 |
| symmetric redundant digit set | 對稱冗餘數位集合，如 {−1, 0, 1} |
| on-the-fly converter | 邊算邊把冗餘商轉成一般二進位，省掉最後的 CPA |
| CPA (carry-propagate adder) | 進位傳遞加法器，慢但結果是非冗餘的 |

## 所以呢

浮點這一章到此結束。第 17 章換一個完全不同的軸線：從「一個 hart 怎麼算得快又對」轉到「多個 hart 同時存取同一塊記憶體會出什麼事」——concurrency、consistency、coherence，以及 RISC-V 的 A（原子）擴充。
