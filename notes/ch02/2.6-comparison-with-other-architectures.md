# 2.6 Comparison with Other Architectures

> 原書 p.54–56（Chapter 2: Introduction to RISC-V）

## 這節在講什麼

把 1.7 節那份「ARM 設計陷阱清單」講完整，並擴大到 MIPS、SPARC、x86。

這節的價值不在「RISC-V 比較好」這個結論，而在**每個案例都示範同一種失敗模式**：

> **某個功能在當年的實作條件下很划算，但條件改變後變成負擔，
> 而 ISA 已經不能改了。**

ARM 的條件執行、MIPS 的 branch delay slot、SPARC 的 register window——
**三者當年都是聰明的最佳化，三者後來都變成包袱。**
這是本節真正要教的東西：**ISA 設計最大的風險是把實作細節寫進契約。**

最後很誠實地列出 RISC-V 目前的三個缺點。

## 關鍵點

### RISC-V 的強項：一大一小

> "RISC-V is a fifth-generation RISC architecture, with a basic instruction set
>  similar to other RISC processors. Its most important strength is that it is an
>  open architecture that companies can implement without license fees and
>  researchers can freely improve."
> — p.54

> "A minor strength is that the machine language encodings keep all register fields
>  and the sign bit of the immediate in the same position for all instructions,
>  slightly reducing hardware and the decode critical path."
> — p.54

中文解釋：**注意作者自己標了主次，而且很誠實。**

- **最重要的強項（most important）：開放。** 免授權費、研究者可自由改進。
- **次要強項（minor）：編碼整齊。** 暫存器欄位和立即值符號位元位置固定
  → 省一點硬體、縮短解碼關鍵路徑（2.2 節詳述）。

**"A minor strength"、"slightly reducing" 這些限定詞很重要**——
作者沒有宣稱 RISC-V 技術上大幅領先。基礎指令集跟其他 RISC 處理器**很像**。
**真正的差別是授權模式，不是技術。**（呼應 1.7 節。）

### ARMv7 的四個問題：連鎖反應

> "Such overly clever features in the 32-bit ARMv7 architecture include support of
>  *conditional execution* of instructions, allowing a variable shift before ALU and
>  memory instructions, and ALU and store instructions supporting three source
>  registers."
> — p.54

> "These features lead to more complex instruction encoding, leaving only enough
>  remaining bits for encoding 16 registers, which has proved to be a performance
>  limiter. The shifter is lightly used but impacts the critical path for all
>  instructions. The conditional execution and third register file port increase the
>  expense of building superscalar out-of-order processors. RISC-V eliminates all of
>  these features."
> — p.54

中文解釋：**"overly clever"（過度聰明）這個評語是本節的關鍵字。**
這些功能都很巧妙，問題就出在太巧妙。

**第二段是連鎖反應，要一步一步看：**

```
條件執行 + 可變移位 + 三來源暫存器
        ↓ 每個功能都要吃編碼位元
指令編碼變複雜，剩下的位元只夠編 16 個暫存器
        ↓
暫存器太少 → 編譯器被迫 spill 到記憶體 → 效能受限
```

**注意這是一個間接的傷害**：ARM 的問題不是「條件執行本身慢」，
而是**條件執行吃掉了編碼空間，害得暫存器只剩 16 個**。
1.7 節列的四項其實是一個原因（貪心）加三個症狀。

另外兩個獨立的傷害：
- **shifter 很少用，卻影響所有指令的關鍵路徑**——
  **這是最糟的一種設計：低收益、全域成本。**
  只有少數指令用得到，但電路在那裡，所有指令的時序都要遷就它。
- **條件執行和第三個暫存器讀取埠，讓 superscalar / out-of-order 的成本變高**——
  條件執行讓相依關係難以分析（這條指令到底會不會寫暫存器？要執行才知道）；
  第三個讀取埠讓暫存器檔案變大變慢，而在 superscalar 裡埠數要再乘上發射寬度。

**"RISC-V eliminates all of these features."** ——四個都不要。

### ARMv8：修好了大半，但編碼仍不規則

> "ARM recognized the same limitations of its instruction set and fixed some of them
>  with its 64-bit ARMv8 ISA in 2013. ARMv8 has 32 64-bit registers and generally
>  has many similarities to the RISC-V ISA."
> — p.54–55

> "The 64-bit ARMv8 architecture has an irregular machine language encoding that is
>  cruel for humans to manually translate; this is not a problem for assemblers,
>  although it makes it difficult to teach in an introductory course."
> — p.55

中文解釋：**ARM 自己也承認了，ARMv8 改成 32 個暫存器、拿掉多數問題功能，
變得跟 RISC-V 很像。** 這是對 RISC-V 設計方向最有力的背書——
**兩支獨立團隊在三十年後收斂到同樣的答案。**

但編碼仍然不規則。書上的評價很克制也很精準：
**對組譯器不是問題，對教學才是問題**（"cruel for humans to manually translate"）。
——這也是為什麼這本教科書選 RISC-V 而非 ARM。

ARM 的商業狀況（p.55，呼應 1.6 節）：
不自己製造，賣可合成核心的授權，也賣架構授權讓別人設計自己的 ARM 核心。
**Apple 的 M1 證明了 ARM 處理器能在功耗低很多的情況下匹敵甚至超越 x86。**
但收入靠權利金，所以嚴格控管存取，還告了最大客戶之一 Qualcomm。

### MIPS 的 branch delay slot：把 pipeline 寫進 ISA

> "MIPS is similar to RISC-V. However, the MIPS architecture has a *branch delay
>  slot*, meaning the instruction after the branch is always executed even if the
>  branch is taken. This improved performance of the original pipelined implementation
>  because it avoided flushing the next instruction when a branch was taken, but it
>  proved difficult for microarchitects and compilers in higher-performance
>  implementations."
> — p.55

中文解釋：**這是整節最經典的反面教材，一定要懂。**

**branch delay slot 是什麼**：分支指令**後面那一條指令一定會執行**，
不管分支有沒有成立。

**為什麼當年是好主意**：在經典 5 級 pipeline 裡，分支成立時已經抓進來的下一條指令
必須丟掉（flush），浪費一個週期。MIPS 的解法很巧妙——
**乾脆規定那條指令一定要執行**，讓編譯器塞一條有用的指令進去。零浪費。

**為什麼後來是災難**：
- 它把「pipeline 深度是 5 級」這個**實作細節寫進了 ISA 契約**
- 深 pipeline（1.6 節說高效能處理器 13–20 級）分支要丟掉的不只一條指令，
  一個 delay slot 根本不夠
- 但 ISA 已經承諾了這個行為，**所有實作都必須維持它**，即使毫無幫助
- 編譯器也痛苦：要找一條「無論分支成不成立都該執行」的指令來填

**教訓：不要把當下微架構的特性寫進 ISA。**
ISA 是幾十年的契約（1.4 節的 System/360 六十年），微架構五年就換一代。

（RISC-V 沒有 delay slot——分支成立就是 flush，交給微架構去做分支預測解決。）

MIPS 的現況：**"As ARM grew to dominate the market, MIPS market share has steadily
declined and is now negligible."**（p.55）

### SPARC 的 register window：對某些工作負載好，對其他的很糟

> "SPARC has *register windows*, in which the hardware automatically rotates through
>  a larger set of registers during function calls, so that the program does not have
>  to save and restore registers on the stack."
> — p.55

> "This worked well for benchmark programs on a pipelined microarchitecture with a
>  poor compiler but is unnecessary with a better compiler, degrades performance on
>  multitasking loads that have to save the registers during context switches, and
>  is costly in high-performance implementations."
> — p.55

中文解釋：**register window 是什麼**：硬體有一大堆實體暫存器，
函式呼叫時自動「轉」到另一組，所以不必像 2.1 節那樣手動存到堆疊上。聽起來很棒。

**第二句是一份完整的失效分析，三個失效條件各自獨立：**

| 條件 | 結果 |
| --- | --- |
| **編譯器變好了** | 編譯器自己就能避免多餘的存取（2.1 節 Code Example 2.12 那個最佳化就是例子）→ 這功能變成多餘 |
| **多工負載** | context switch 時要存的暫存器變超多 → **反而更慢** |
| **高效能實作** | 一大堆實體暫存器很貴 |

**「在 benchmark 上表現好」這句評語特別值得玩味**——
它暗示這個設計是為了跑分而不是為了真實工作負載。

**教訓：針對當下的軟體弱點（爛編譯器）做硬體最佳化，
會在軟體進步後變成純負擔。** 而 ISA 改不掉。

SPARC 現況：主要用在 Oracle 伺服器，市佔極小（p.55）。

### x86：靠蠻力維持相容性

> "The Intel x86 complex instruction set computer (CISC) architecture evolved
>  piecemeal from the 8088/8086 to today's modern processors. The complicated legacy
>  instructions, variable-length encoding, and limited set of registers make
>  high-performance x86 microarchitectures difficult."
> — p.55

> "The variable-length decoder and micro-op cache add hundreds of thousands of
>  transistors compared to a RISC processor but deliver comparable performance
>  [Isen09]."
> **Nearly all Windows PCs use x86 processors. Intel and AMD have a duopoly on the
>  architecture and can, thus, charge high prices."
> — p.55

中文解釋：**"evolved piecemeal"（零碎地演化）是關鍵詞**——
呼應 1.5 節的「Frankenstein monster」。x86 不是設計出來的，是長出來的。

**"hundreds of thousands of transistors" 這個數字是本節最具體的成本量化**：
為了處理變長指令，x86 需要**變長解碼器 + micro-op cache**，
比 RISC 處理器多幾十萬顆電晶體——**而效能只是「comparable」（相當）。**

**這就是相容性的實際價格**：幾十萬顆電晶體、對應的功耗和面積，
換到的是「跟 RISC 一樣快」而不是「更快」。
（也解釋了 1.6 節為什麼手機不用 x86——在低功耗場景，這個固定開銷划不來。）

最後一句點出商業現實：Windows PC 幾乎都用 x86，
**Intel 和 AMD 形成雙占（duopoly），所以能收高價。**
這跟 1.8 節的主權議題是同一件事的另一面。

### RISC-V 目前的三個缺點（作者很誠實）

> "The greatest present drawbacks of RISC-V are its lack of binary compatibility
>  with existing x86 and ARM software, its less-mature software and verification
>  ecosystem, and its less-mature suite of implementations. However, software,
>  verification, and implementations are advancing rapidly. The open architecture has
>  potential to surpass its proprietary competitors in many markets."
> — p.55

中文解釋：**三個缺點要記住，因為它們解釋了這本書為什麼要花那麼多篇幅講工具鏈和驗證：**

1. **沒有二進位相容性**——現有的 x86/ARM 執行檔不能跑。
   這是結構性的，**永遠不會改善**（呼應 1.7 節：RISC-V 不打 x86/ARM 的主場）。
2. **軟體和驗證生態系不夠成熟**——這是第 3 章（工具鏈）和第 5 章（驗證）
   在書裡份量這麼重的原因。
3. **實作品不夠成熟**——這正是 Wally（一個完整的開源實作）存在的意義。

**注意 2 和 3 是「時間問題」，1 是「本質問題」。** 作者的判斷是前兩者
"advancing rapidly"。

書上用一句話收尾（p.55）：

> "This is a new golden age to be a processor designer."

**「現在是當處理器設計師的新黃金年代。」**
理由就在前面：ISA 開放了，任何人都能做，而且生態系還在成形階段——
有事可做。

## 名詞表

| 名詞 | 意思 |
| --- | --- |
| Conditional execution | 條件執行（ARMv7）。指令帶條件碼；吃編碼位元、妨礙亂序執行 |
| Branch delay slot | 分支延遲槽（MIPS）。分支後一條指令必定執行；把 pipeline 深度寫進 ISA |
| Register windows | 暫存器視窗（SPARC）。呼叫時硬體自動輪替暫存器組；對多工與高效能實作不利 |
| Variable-length encoding | 變長編碼（x86）。需要變長解碼器與 micro-op cache，多數十萬顆電晶體 |
| Micro-op cache | 微指令快取。存已解碼的 micro-op，避開重複解碼成本 |
| Duopoly | 雙占。Intel 與 AMD 共同掌握 x86 架構 |
| Binary compatibility | 二進位相容性。RISC-V 缺乏與現有 x86/ARM 軟體的相容性 |

## 所以呢

**這節真正的教訓不是「RISC-V 比較好」，而是三個一模一樣的失敗案例：
ARM 的條件執行、MIPS 的 branch delay slot、SPARC 的 register window——
都是把當下的實作條件（編碼空間夠、pipeline 5 級、編譯器很爛）寫進了幾十年不能改的契約。**
RISC-V 的優勢很大一部分來自「晚三十年出生，看得到別人踩的雷」。
讀後面章節設計 Wally 時，這份清單就是「什麼不該做」的檢查表。
下一節（2.7）開始動手：用簡化的 RV32I 核心走一遍單週期和 pipeline 微架構。
