# 21.4 Summary

> 原書 p.784.e47（Chapter 21: Benchmarking）

## 這節在講什麼

第 21 章的總結，三句話。

## 關鍵點

### 這章做了什麼

> "This chapter has described how to compile and run the CoreMark and Embench benchmark suites on Wally. It also described performance verification tests showing that the cache and branch predictor perform as expected."
> — p.784.e47

中文解釋：兩件事——**跑 benchmark**（量效能）和**效能驗證**（確認沒有 performance bug）。兩者都需要參考模型：benchmark 的參考是 Cortex-M4，效能驗證的參考是 `CacheSim.py` 與 `sim_bp`。

### Wally 的定位

> "The benchmarks show that Wally is comparable in IPC performance to other single-issue pipelined RISC-V processors and to the ARM Cortex-M4. They also show that RV32GC and ARMv7 code density are similar."
> — p.784.e47

中文解釋：具體數字回顧——CoreMark 3.26 CM/MHz、Embench 速度 1.04（比 M4 快 4%）、程式大小 1.05（比 M4 大 5%）。

**「comparable（相當）」是一個誠實的定位**。Wally 是教學用的開源核心，能和商用的 Cortex-M4 打平就是很好的結果；它沒有要贏。而且這個比較本身有價值——它證明了**單發射五級管線這個架構在 RISC-V 上實作出來，效率和 ARM 的同級產品是同一個水準**，沒有因為 ISA 選擇而吃虧。

## 名詞表

| 名詞 | 意思 |
| --- | --- |
| IPC | instructions per cycle，CPI 的倒數 |
| single-issue | 單發射，每週期最多發射一條指令 |
| code density | 程式密度，同樣功能需要多少位元組 |
| ARMv7-M | Cortex-M4 使用的指令集架構 |

## 所以呢

這章的方法學收穫比數字更重要：**benchmark 分數不是客觀事實**——編譯器旗標、資料型別的調整（`ee_u32` 改 signed 得 13%）、甚至編譯器把整個 benchmark 最佳化掉（`nbody` 的 1,480 倍）都會扭曲結果。看分數要連同設定一起看，看到好得離譜的數字要先懷疑。

到這裡，Wally 已經被證明是正確的（第 13 章）而且夠快的（第 21 章）。下一章換一個終極測試：**讓它跑真正的 Linux**。這會同時壓測虛擬記憶體、特權模式、trap、中斷、周邊——所有子系統必須一起正確運作才行。
