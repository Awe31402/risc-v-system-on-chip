# 17.5 Summary

> 原書 p.712–713（Chapter 17: Extensions: A (Atomic)）

## 這節在講什麼

第 17 章的總結。用一頁把 coherence / consistency / synchronization 三者的關係、三種一致性模型的取捨、兩類同步問題、以及 RISC-V 提供的工具串起來。

## 關鍵點

### 三個需求

> "Programmers want coherence, consistency, and synchronization in concurrent systems. Coherence means that all processes eventually see the same value stored to memory. Consistency describes the ordering of reads and writes with respect to different locations."
> — p.712

中文解釋：再強調一次那個容易混淆的區別——**coherence 是同一位址的值最終一致，consistency 是不同位址之間的順序**。

### 為什麼不能都用 sequential consistency

> "Programmers intuitively expect a sequential consistency model, which means that each thread performs reads and writes in program order but that different threads may interleave in arbitrary ways. Unfortunately, guaranteeing sequential consistency precludes important hardware optimizations such as write buffers, so high-performance systems use more relaxed total store order or release consistency models."
> — p.712–713

中文解釋：這是整章最核心的張力，一句話講完：**程式設計師想要的模型，剛好擋住硬體最想做的最佳化**。所以高效能系統退到 TSO 或 release consistency，把「什麼時候需要順序」的判斷責任交回給程式設計師。

### 兩類同步問題

> "Mutual exclusion (locks): Only one thread can access a shared variable at a time. Producer-consumer (condition variables): Threads communicate by putting and getting information in a bounded buffer and waiting when the buffer is empty or full."
> — p.713

中文解釋：這個二分法值得記住。**互斥用鎖，生產者-消費者用條件變數。** 兩者都可以用 semaphore 實作，實務上則用 futex 或 pthread 函式庫。

### RISC-V 的工具與 Wally 的位置

> "The RISC-V atomic (A) extension defines LoadReserved-StoreConditional (lr-sc) and atomic memory operations (AMOs). RISC-V has a release consistency model, so it also defines a set of fences to enforce memory consistency. Wally is an in-order single-core processor, so it is inherently sequentially consistent. However, it still needs atomic instructions to synchronize multiple threads. It also uses fence.i to maintain coherence between the instruction and data caches and sfence.vma for TLB coherence."
> — p.713

中文解釋：最後這段把 Wally 的處境講得很清楚：**因為它簡單，所以 fence 免費；但因為它仍然跑多執行緒，所以原子指令不能省。** 這兩件事常被混為一談。

## 名詞表

| 名詞 | 意思 |
| --- | --- |
| coherence / consistency | 同址值一致／異址順序 |
| mutual exclusion | 互斥，用鎖解決 |
| producer-consumer | 生產者-消費者，用條件變數解決 |
| bounded buffer | 有限緩衝區 |
