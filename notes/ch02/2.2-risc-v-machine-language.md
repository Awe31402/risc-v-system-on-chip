# 2.2 RISC-V Machine Language

> 原書 p.43–45（Chapter 2: Introduction to RISC-V）

## 這節在講什麼

把 2.1 節的六種指令型別翻成實際的 32-bit 二進位編碼。

這節看起來像枯燥的位元表格，但**它其實在講 ISA 設計的取捨**，而且理由都很硬體導向：
為什麼 rs1/rs2/rd 永遠放在同一個位置？為什麼立即值被打散得亂七八糟？
為什麼符號位元一定在 bit 31？

**答案都是同一個：為了讓硬體更快、更簡單。**
這節是後面第 7 章設計 decoder 和 immediate extension 電路時的直接依據。

## 關鍵點

### 機器語言就是組合語言的二進位形式

> "Machine language is the binary representation of assembly language. Every
>  assembly language instruction corresponds to a 32-bit machine language instruction
>  stored in the computer's program memory."
> — p.43

> "Fig. I.1 (on the last pages of the book) summarizes the six instruction formats
>  used by RV{32/64}I and an R4 format used for floating-point multiply-accumulate
>  instructions."
> — p.43

中文解釋：**一條組語 = 一條 32-bit 機器碼**，一對一。
（壓縮指令 C 擴充是 16-bit，是例外，見 2.5 節。）

除了 2.1 節的六種格式，還有第七種 **R4 格式**——
給浮點的 multiply-accumulate（乘加融合）用，因為它要**三個**來源暫存器
（a×b+c）。注意這是浮點擴充才有的例外，整數指令最多兩個來源。

### op 欄位：解碼的第一步，永遠在最低 7 bit

> "RV32I instructions are distinguished by their op, funct3, and funct7 fields,
>  as given in Table I.1. The least significant 7 bits of an instruction always
>  contain op, which defines the type of instruction so that an instruction decoder
>  knows how to interpret the remaining bits."
> — p.43

> "For example, all R-type instructions have op = 51 (0x33). The processor must
>  examine the funct3 and funct7 fields to determine which R-type instruction is
>  being executed."
> — p.43

中文解釋：**解碼是兩層（有時三層）的**：

1. **op**（bit 6:0，永遠在同一個位置）→ 決定這是哪一「型」，於是知道其他欄位怎麼解讀
2. **funct3**（3 bit）→ 在同一型裡分出不同指令
3. **funct7**（7 bit）→ 再細分（例如 `add` 和 `sub` 的 op 和 funct3 完全一樣，只差 funct7）

**「op 永遠在最低 7 bit」是刻意的設計**：解碼器不需要先知道任何事就能讀到 op。
這是一個雞生蛋問題的解法——你必須先解碼才知道怎麼解碼，
所以第一個欄位的位置必須是絕對固定的。

（`sub` 的 funct7 = 0b0100000，`add` 的是 0b0000000——就差第 30 個 bit。
所以硬體上常直接拿 Instr[30] 當「要不要做減法」的控制訊號。）

### 暫存器欄位位置固定：省掉多工器

> "The rs1, rs2, and rd fields are always found in the same bit positions of the
>  instruction if they are needed. Thus, these fields can connect directly to address
>  inputs of the register file without a need for multiplexing, saving time and delay
>  compared with other ISAs."
> — p.43

中文解釋：**這是整節最重要的一句，也是 RISC-V 編碼設計的核心原則。**

想像另一種設計：如果 rs1 在 R-type 在某個位置、在 I-type 在另一個位置，
那硬體就必須**先解碼、再用多工器選出 rs1 的位置、才能去讀暫存器**。
這是一條串聯的長路徑，直接拉長關鍵路徑。

RISC-V 的做法是：**位置固定，線直接接過去。**
於是暫存器檔案可以**在解碼還沒完成時就開始讀**——
反正不管這是哪種指令，rs1 都在同一個地方。讀錯了就不用，沒有損失。

**這叫做「投機性讀取」，而它之所以可行，純粹是因為編碼格式配合。**
書上說的 "saving time and delay compared with other ISAs" 就是指這個。

### 立即值被打散：不是亂來，是為了讓別的東西不動

> "The immediate bits are sometimes scrambled around the instruction in an odd way,
>  as shown in Fig. 2.3, to keep the other fields in the same locations and to encode
>  each immediate bit in the same instruction bit when possible."
> — p.43

> "This bit swizzling does not impact performance because the immediate bits can be
>  rearranged and extended while the register file is reading a source register."
> — p.43

中文解釋：**第一次看 Fig. 2.3（p.44）會覺得 RISC-V 的立即值編碼很瘋狂**——
B-type 的立即值 bit 11 被塞到指令的 bit 7，bit 12 在 bit 31，中間的在 30:25 和 11:8。
為什麼要這樣？

**兩個原因，優先順序很清楚：**
1. **第一優先：別的欄位不能動**（op、rs1、rs2、funct3 位置固定，見上一點）。
   立即值只能撿別人剩下的位置。
2. **第二優先：同一個立即值 bit 盡量放在同一個指令 bit**（跨格式一致）。
   這樣選擇邏輯最簡單。

**第二句是關鍵的辯護**：打散不影響效能，因為**重排和延伸可以和讀暫存器平行進行**。
硬體裡這只是接線（wire），不花時間；而讀暫存器檔案才是慢的那一步。
**所以這個「醜」的編碼是零成本的。**

Fig. 2.3（p.44）畫的是「立即值的每個 bit 放在指令的哪個位置」，
五行分別是 I、S、B、U、J（R 沒有立即值）。

### ImmExt：從指令位元組出 32-bit 立即值

> "Fig. 2.4 shows how the extended immediate (ImmExt) is formed (bit-swizzled and
>  extended) from the instruction bits (Instr) in each instruction format."
> — p.44

> "Encoding a given immediate bit in the same instruction bit across formats, when
>  possible, minimizes extension hardware; multiplexers can then select a given
>  ImmExt bit from only a few options. For example, ImmExt[31] = Instr[31] for all
>  instruction types. ImmExt[20] = Instr[20] for U-type instructions, or Instr[31]
>  for other types. ImmExt[0] = Instr[20] for I-type, Instr[7] for S-type, or 0 for
>  other types."
> — p.44

中文解釋：Fig. 2.4（p.44）是**第 7 章要實作的 immediate extension 單元的規格書**，
非常實用。讀法是：每一行是一種格式，顯示 ImmExt 的每個 bit 從 Instr 的哪個 bit 來，
**藍色斜體的 0 表示硬接為 0（不是從指令來的）**。

三個具體例子說明「選項很少」這件事：
- `ImmExt[31]` = `Instr[31]`，**所有格式都一樣** → 完全不需要多工器，直接接線
- `ImmExt[20]` = U-type 取 `Instr[20]`，其他取 `Instr[31]` → **2 選 1**
- `ImmExt[0]` = I-type 取 `Instr[20]`，S-type 取 `Instr[7]`，其他為 0 → **3 選 1**

**設計目標就是讓每個 bit 的多工器輸入數越少越好。**
這就是上一點「同一個 bit 盡量放同一位置」的實際回報。

注意 B 和 J 格式的 ImmExt[0] 是硬接 0——這正是 2.1 節那個「最低位元恆為 0」的技巧
在硬體上長什麼樣：**不是一條線，是一個常數。**

### 符號位元永遠在 bit 31：因為它 fanout 最大

> "The most time-consuming part of extending the immediate is sign-extending its
>  most significant bit (msb) into the upper bits because it must drive many loads
>  (i.e., has a large *fanout*). Thus, RISC-V always places the immediate's msb in
>  bit 31 of the instruction, so it is available without further decoding.
>  RV64 also extends bit 31 into bits 63:32 of ImmExt."
> — p.44

中文解釋：**這是一個純電路層面的考量，但它決定了 ISA 的編碼——很值得體會。**

推理鏈：
1. 符號延伸 = 把 msb **複製到很多條線上**（12-bit 立即值要延伸成 32-bit，
   那一個 bit 要驅動 20 條線）
2. 一個訊號要驅動很多負載，叫 **fanout 大**
3. fanout 大 = 慢（要充很多電容）
4. 所以這個訊號**必須越早拿到越好**
5. → **把符號位元固定放在 Instr[31]**，不用解碼就知道它在哪，可以立刻開始驅動

**這是 1.7 節「ARM 的設計陷阱」的反面教材**：
好的 ISA 設計會考慮到電路的物理限制。
RV64 更誇張，那一個 bit 要延伸到 bit 63:32，fanout 更大——更需要早點拿到。

### 範例：組語 → 機器碼

> "Convert sub x3, x4, x5 to machine language."
> — Example 2.1, p.45

> "According to Table I.1, sub is an R-type instruction with op = 0b0110011,
>  funct3 = 0b000, and funct7 = 0b0100000. The source registers are rs1 = 4 =
>  0b00100, rs2 = 5 = 0b00101, and rd = 3 = 0b00011."
> — p.45

中文解釋：步驟很機械化——**查表拿欄位值，按格式排好，湊成 32 bit**：

```
funct7   rs2    rs1   funct3  rd     op
0100000  00101  00100  000    00011  0110011  = 0x40520 1B3
```

注意 R-type 的欄位順序（從高位到低位）：**funct7 | rs2 | rs1 | funct3 | rd | op**。
`rs2` 在 `rs1` 前面（bit 位置比較高），這點容易記反。

### 範例：機器碼 → 組語（反組譯）

> "Convert RISC-V machine instruction 0x03E90523 to assembly language."
> — Example 2.2, p.45

> "The instruction in binary is 0000 0011 1110 1001 0000 0101 0010 0011. The bottom
>  7 bits are 0100011, which, according to Table I.1, is an S-type instruction."
> — p.45

中文解釋：**反組譯的第一步永遠是看最低 7 bit（op）**，因為只有它的位置是絕對確定的。

```
imm[11:5]  rs2    rs1   funct3  imm[4:0]  op
0000001    11110  10010  000     01010    0100011
```
- op = 0100011 → S-type
- funct3 = 000 → `sb`（store byte）
- rs1 = x18 = **s2**，rs2 = x30 = **t5**
- 立即值要**把兩半拼回來**：`0000001` + `01010` = `000000101010` = **42**

結果：`sb t5, 42(s2)`

**「Cobble together the two halves of the immediate」（把立即值的兩半拼起來）
就是 S-type 編碼的代價**——但如前所述，硬體上這只是接線，不花時間。

書上邊欄推薦了一個線上組譯器可以驗證：**riscvasm.lucasteske.dev**（p.45 邊欄），
可以貼組語（含 pseudoinstruction）進去看機器碼和反組譯結果。

## 名詞表

| 名詞 | 意思 |
| --- | --- |
| Machine language | 機器語言。組合語言的二進位表示，一條指令 32-bit |
| op | 運算碼。永遠在 bit 6:0，決定指令型別 |
| funct3 / funct7 | 功能欄位。在同型別內區分不同指令（如 add vs sub 只差 funct7） |
| R4 format | 第七種格式，給浮點乘加（三個來源暫存器）用 |
| Bit swizzling | 位元打散。立即值被拆散編碼，以維持其他欄位位置固定 |
| ImmExt | 延伸後的立即值。由指令位元重排並符號延伸而成（Fig. 2.4 是其規格） |
| Fanout | 扇出。一個訊號要驅動的負載數量；fanout 大則慢 |

## 所以呢

**RISC-V 的編碼格式看起來混亂，但每一個決定都是為了硬體速度服務：
欄位位置固定 → 省多工器、能提前讀暫存器；符號位元固定在 bit 31 → 最早拿到 fanout 最大的訊號。**
Fig. 2.3 和 Fig. 2.4 是第 7 章實作 decoder 和 immediate extension 時要直接照抄的規格。
下一節（2.3）換個主題，講 hart、特權模式和 trap——處理器的執行環境。
