# 14.2 Test Plan

> 原書 p.582–583（Chapter 14: Extensions: C (Compressed)）

## 這節在講什麼

**只有兩句話 + 一張表。但那張表（Table 14.1）很有資訊量。**

## 關鍵點

### 用既有的測試套件

> "**The C-extension instructions are tested with the riscv-arch-test suite as discussed in Section 7.4.
>  Table 14.1 lists the number of test cases for each Zca and Zcb instruction.**"
> — p.582

中文解釋：**壓縮指令的測試是官方測試套件涵蓋的**——
這和特權、MMU、cache 的情況不同（那些都要自己寫）。

**理由不難理解：壓縮指令是「非特權指令」，
而 riscv-arch-test 的強項正是非特權指令**（呼應 3.7.1 節）。

### Table 14.1 的四欄與總計

中文解釋：**Table 14.1（p.583）列出每條指令在四種組態下的測試數。總計：**

| 組態 | 測試總數 |
| --- | --- |
| **RV32Zca** | **4,632** |
| **RV64Zca** | **7,829** |
| **RV32Zcb** | **957** |
| **RV64Zcb** | **1,496** |

**三個觀察：**

**（1）RV64 的測試數約是 RV32 的 1.7 倍**
（呼應 7.4 節：「RV64 有更多測試案例，因為要涵蓋的運算元值更多」）。

**（2）Zcb 的測試數遠少於 Zca**（約五分之一）——
因為 Zcb 的指令少很多。

**（3）指令之間的測試數差異極大，而且有規律：**

| 指令類型 | 代表 | RV32Zca 測試數 |
| --- | --- | --- |
| **兩個暫存器運算元的 ALU** | `c.or`, `c.sub`, `c.and`, `c.add`, `c.xor` | **580–590** |
| **一個暫存器 + 立即值** | `c.addi`, `c.andi` | **375–376** |
| **移位** | `c.slli`, `c.srai`, `c.srli` | **85–87** |
| **分支** | `c.beqz`, `c.bnez` | **85** |
| **load/store** | `c.lw`, `c.sw`, `c.swsp` | **14–70** |
| **跳躍** | `c.j`, `c.jal`, `c.jalr`, `c.jr` | **18–31** |
| **`c.ebreak`** | | **1** |

**這個分佈和 7.4 節 Table 7.10 的規律完全一致**：
**運算元組合越多，測試越多。**

**（4）RV32 和 RV64 各有獨有的指令**，直接反映了 14.1 節說的編碼重用：

| 只在 RV32 | 只在 RV64 |
| --- | --- |
| **`c.jal`**（18 個測試） | **`c.addiw`**（438）、**`c.addw`**（678）、**`c.subw`**（670） |
| | **`c.ld`**（13）、`c.ldsp`（31）、`c.sd`（132）、`c.sdsp`（131） |
| | `c.zext.w`（130，Zcb） |

**`c.jal` 只在 RV32 有，而 `c.addiw` 只在 RV64 有——
這正是 14.1 節說的「同一個編碼在兩種 ISA 表示不同指令」。**

### 這節沒說但值得注意的

中文解釋：**Table 14.1 只涵蓋 Zca 和 Zcb**——
**Zcf、Zcd、Zcmp、Zcmt 沒有列出。**

**理由從 14.3 節可以推出：Wally 不實作 Zcmp 和 Zcmt**
（所以沒有測試），而 Zcf/Zcd 的浮點壓縮 load/store
可能歸在浮點測試裡（第 16 章）。

**另外，這節完全沒提到 spill 的測試**——
而 spill 是壓縮指令最容易出錯的部分（14.3.3 節）。
**這是一個潛在的缺口**（呼應 13.2、12.6 節：整合性的行為常常沒有專門測試）。

## 所以呢

**壓縮指令的測試由官方 riscv-arch-test 涵蓋**——
這和特權、MMU、cache 不同（那些都要自己寫）。

**Table 14.1 的兩個要點：**
1. **測試數的分佈和指令的運算元組合數成正比**
   （兩個暫存器的 ALU 約 580、跳躍只有 18–31）。
2. **RV32 和 RV64 各有獨有的指令**（`c.jal` vs `c.addiw`/`c.addw`）——
   直接反映了 14.1 節「同一編碼在兩種 ISA 表示不同指令」的設計。

**一個潛在缺口：這節沒提到 spill 的測試**，
而 spill 正是壓縮指令最容易出錯的部分。
