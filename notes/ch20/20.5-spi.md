# 20.5 SPI

> 原書 p.784.e19–784.e23（Chapter 20: Peripherals）
> 涵蓋 20.5.1 Memory Map、20.5.2 Loopback Testing、20.5.3 Test Plan、20.5.4 Wally Implementation

## 這節在講什麼

SPI（Serial Peripheral Interface，唸作 "S-P-I"）是 UART 的反面：多拉一條時脈線，換來簡單、快速、幾乎沒有參數要對。它是**同步**的，所以不需要 baud rate 協議、不需要 start/stop bit、不需要 16 倍取樣。

Wally 用它來接 SD 記憶卡（開機時從 SD 卡載入 Linux，第 22 章會用到）。

## 關鍵點

### 三條線 + 一條選擇線

> "The Serial Peripheral Interface (SPI, pronounced 'S-P-I') is a simple standard for synchronous serial communication between a controller and a peripheral. It is easier to implement and runs far faster than a UART. As shown in Fig. 20.12(a), the physical interface consists of three pins: serial clock (SCK), serial data out (SDO), and serial data in (SDI)."
> — p.784.e19

中文解釋：接線方式是**直接對接**（不像 UART 的 TX 接對方 RX 那樣容易搞混）：
- controller 的 SCK → peripheral 的 SCK
- controller 的 SDO → peripheral 的 SDI
- controller 的 SDI ← peripheral 的 SDO

多一條時脈線就消除了 UART 的所有同步問題。

### 全雙工：送和收同時發生

> "The controller initiates communication by sending clock pulses on SCK. The controller sends data from its SDO pin to the peripheral's SDI pin one bit per cycle, starting with the most significant bit. The peripheral may simultaneously respond with its SDO pin back to the controller's SDI pin."
> — p.784.e19

中文解釋：這是 SPI 的一個重要特性——**送一個位元組的同時必然收到一個位元組**。想「只收不送」就送一個 dummy 位元組（例如 0x00），想「只送不收」就忽略收到的。後面 Example 20.5 會看到這個模式。

另外注意「**controller initiates**」——沒有時脈就沒有傳輸，所以 peripheral 不能主動說話，只能等 controller 來問。

### 時脈邊緣的分工

> "Fig. 20.12(b) shows the SPI waveforms for an 8-bit data transmission. Bits change on the falling edge of SCK and are stable to sample on the rising edge."
> — p.784.e19

中文解釋：**下降緣改變、上升緣取樣**——這樣取樣點落在資料穩定期的正中間，和 UART 的 16 倍取樣達到同樣目的，但完全不用額外電路。

「clock polarity 可以選擇性地反相」，加上 phase 的設定，就是常說的 SPI mode 0–3。

### chip enable：一條匯流排接多個裝置

> "The SPI interface may also send an active-low chip enable (CE) to select one peripheral from among several sharing an SPI bus."
> — p.784.e19

中文解釋：Fig. 20.13 顯示 Wally 有四條 CE（CE0b–CE3b），最多接四個周邊。

> "Each peripheral has a tristate driver on its SDO output controlled by its chip enable, so at most one peripheral will send a response to the controller."
> — p.784.e20

中文解釋：關鍵在於**每個周邊的 SDO 是三態的**——沒被選中就放開（高阻抗），這樣四個周邊的 SDO 可以並接在同一條線上。這和 20.1 GPIO 的三態驅動器是同一個概念。

### Wally 的 SPI 功能

> "Wally contains two SPI controllers compatible with the SiFive FU540 SPI [FU540] except that it does not implement memory-mapped SPI flash mode or 2/4-bit data width. The first SPI controller is instantiated as a generic SPI interface using SPI_SUPPORTED = 1, and the second is reserved for the SD flash memory card using SDC_SUPPORTED = 1."
> — p.784.e20

中文解釋：兩個控制器，一個通用、一個專給 SD 卡。功能清單：
- 時脈除頻器（從高速的 APB PCLK 產生較慢的 off-chip SCK）
- 可設定的時脈 phase 與 polarity
- 4 個可設定延遲的 chip select
- 可設定的 frame 大小（1–8 位元）與端序
- **8-frame 的收發 FIFO 加中斷**

> "The SPI controller sends SPIIntr back to the PLIC to raise an interrupt when the transmit FIFO is nearly empty or the receive FIFO is nearly full."
> — p.784.e20

中文解釋：「nearly」的門檻由 `txmark`/`rxmark`（watermark）暫存器設定。這比 UART 的「空了才通知」好——**提前通知，讓 CPU 有時間反應，避免傳輸中斷**。

### 記憶體映射的重點

> "Table 20.4 lists the memory-mapped SPI registers and their address offsets. All SPI registers are 32 bits, even on RV64."
> — p.784.e20

中文解釋：Table 20.4 的幾個關鍵暫存器：
- `sckdiv`（0x00）：時脈除頻，**f_SCK = f_PCLK / 2(sckdiv[11:0] + 1)**
- `sckmode`（0x04）：bit 0 是 phase、bit 1 是 polarity
- `csid` / `csdef` / `csmode`（0x10/0x14/0x18）：選哪個 chip select、預設值（通常 1111 全關）、是否在 frame 之間保持 assert
- `delay0` / `delay1`（0x28/0x2C）：CS 與 SCK 之間的額外延遲、CS 的非活動時間
- `fmt`（0x40）：寬度、端序、每 frame 的位元數
- `txdata`（0x48）：**bit[7:0] 是資料，bit[31] 是 full 旗標**
- `rxdata`（0x4C）：**bit[7:0] 是資料，bit[31] 是 empty 旗標**
- `txmark` / `rxmark`（0x50/0x54）：中斷門檻
- `ie` / `ip`（0x70/0x74）：中斷致能與 pending

**把狀態旗標塞進資料暫存器的最高位元（bit 31）是一個很實用的設計**——一次讀取就同時拿到「有沒有資料」和「資料是什麼」，不用先讀狀態暫存器再讀資料（省一次匯流排存取，也消除了兩次讀取之間的 race condition）。

### 一個完整的 SPI 程式：接 ADC

> "Consider interfacing the MCP3002 analog-to-digital converter (ADC) to an SoC using our SPI controller as shown in Fig. 20.14. ... Read channel 0 of the MCP3002 by sending 0x60 over SPI to begin conversion, then sending 0x00 and receiving a byte back from the ADC."
> — p.784.e21（Example 20.5）

中文解釋：Fig. 20.14 的接線很完整（值得注意 VDD 旁的 0.1 μF 去耦電容，這是類比晶片的標準配置）。程式核心：

```c
uint8_t spiSendReceive(uint8_t send) {
  uint32_t rxdata;
  while (*SPI_TXDATA >> 31);        // 等 TX FIFO 不滿（bit 31 是 full 旗標）
  *SPI_TX_DATA = send;              // 送一個位元組
  do {                              // 等 RX FIFO 非空
    rxdata = *SPI_RXDATA;
    if (!(rxdata >> 31)) return (uint8_t)rxdata;   // bit 31 是 empty 旗標
  }
}

void main(void) {
  *SPI_SCKDIV = 49;                 // 200 MHz / (2 × 50) = 2 MHz
  while (1) {
    spiSendReceive(0x60);           // 啟動轉換（回傳值丟掉）
    sample = spiSendReceive(0x00);  // 送 dummy，收回結果
    delay(200);
  }
}
```

**`spiSendReceive` 這個函式名字就說明了 SPI 的全雙工本質**——送和收是同一個動作。第一次呼叫的回傳值被丟棄（那是 ADC 還在轉換時吐出的垃圾），第二次送 0x00 只是為了產生時脈把結果搖出來。

除頻係數 49 的計算：`f_SCK = 200 MHz / (2 × (49 + 1)) = 2 MHz`。

### loopback 測試的一個巧合

> "When the Wally SPI_LOOPBACK_TEST configuration parameter is set, the SDI pin gets its value from SDO so the SPI can read back values it transmits. With the default clock sckmode = 00, the SPI transmitter changes data on the falling edge of the clock, and the SPI receiver samples data on the rising edge. Thus, in loopback testing, SDI is stable when sampled."
> — p.784.e22–e23

中文解釋：這個細節值得注意——**loopback 能運作是因為預設的時脈模式剛好讓「下降緣送、上升緣收」自洽**。如果 phase 或 polarity 設成別的值，直接把 SDO 接回 SDI 就可能取樣到正在變化的資料。

### 測試計畫的誠實揭露

> "The tests run in loopback mode. They check the reset state, then test each configuration register while sending single and 4-byte frame burst messages and checking that the same value was received. It then enables the PLIC and tests watermark interrupts. The SPI has not yet been tested with external peripherals."
> — p.784.e23

中文解釋：最後一句很誠實——**只測過 loopback，沒接過真的周邊**。這是一個重要的驗證限制：loopback 測不到時序參數（`delay0`/`delay1`）、chip select 的行為、以及和真實裝置的互通性。

### 實作

> "The SPI peripheral has an APB interface to the memory-mapped registers, transmit and receive FIFOs, and control logic driving the SPI pins."
> — p.784.e23

中文解釋：三個部分。程式碼在 `src/uncore/spi_apb.sv` 和 `src/uncore/spi_controller.sv`。書上同樣沒有細講，但 SPI 明顯比 UART 簡單——沒有非同步取樣、沒有 parity、沒有一堆 modem 握手訊號。

## 名詞表

| 名詞 | 意思 |
| --- | --- |
| SPI | Serial Peripheral Interface，同步序列通訊介面 |
| SCK / SDO / SDI | serial clock ／ serial data out ／ serial data in |
| CE (chip enable) | 低電位有效的晶片選擇訊號 |
| controller / peripheral | SPI 的主從角色（舊稱 master/slave） |
| full duplex | 全雙工，送與收同時進行 |
| clock phase / polarity | 時脈相位與極性，決定在哪個邊緣送與收 |
| frame | 一次傳輸的單位（Wally 支援 1–8 位元） |
| `sckdiv` | 時脈除頻係數，f_SCK = f_PCLK / 2(sckdiv + 1) |
| `csid` / `csdef` / `csmode` | 選哪個 CS ／ CS 預設值 ／ frame 間是否保持 assert |
| `txdata` / `rxdata` | 收發資料暫存器，bit[31] 兼作 full / empty 旗標 |
| `txmark` / `rxmark` | watermark，FIFO 中斷門檻 |
| watermark interrupt | FIFO 快空／快滿時提前發出的中斷 |
| `SPI_LOOPBACK_TEST` | 把 SDO 接回 SDI 的測試設定 |
| MCP3002 | 範例中的 SPI 介面類比數位轉換器 |
| 去耦電容 (decoupling capacitor) | Fig. 20.14 中 VDD 旁的 0.1 μF，穩定類比晶片的電源 |
| I²C | 另一種常見的同步序列介面（本書未詳述） |

## 所以呢

SPI 和 UART 的對比是一堂很好的介面設計課：**多一條線（時脈）就能消掉整套同步機制**（baud rate 協議、start/stop bit、16 倍取樣、重新對時），換來更簡單的硬體和高很多的速度。代價是多一根腳位，以及只能在同一塊板子上短距離通訊（時脈線在長纜線上會失真）。Wally 靠它讀 SD 卡，這是第 22 章開機載入 Linux 的關鍵路徑。
