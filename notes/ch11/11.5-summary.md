## 關鍵點

### MMU 的三個職責

> "**The MMU is responsible for virtual memory, PMA checking, and PMP checking.**"
> — p.512

中文解釋：**三個職責、三種檢查：**

| 職責 | 檢查什麼 |
| --- | --- |
| **虛擬記憶體** | **位址轉譯 + PTE 的權限旗標** |
| **PMA** | **這個實體位址對應哪個裝置、支援哪些操作** |
| **PMP** | **這個特權模式可不可以存取這個實體位址** |

### 虛擬記憶體解決什麼

> "**Virtual memory elegantly addresses the problems of relocation, fragmentation, and protection for cores running
>  multiple concurrent processes. It gives each process an independent virtual address space, so the process has
>  the illusion of its own large and continuous memory. The memory is divided into pages, commonly 4 KiB, which can
>  be placed anywhere in physical memory, or swapped out to disk when there is insufficient physical memory.
>  Each process is protected from other processes because they can only access their own virtual addresses.**"
> — p.512

中文解釋：**一個機制、三個問題、一句話的原理：
「每個 process 有獨立的虛擬位址空間」。**

**Page 的兩個好處：**
- **可以放在實體記憶體的任何地方**（解決 relocation 和 fragmentation）
- **實體記憶體不夠時可以換出到磁碟**（解決容量）

### 頁表與多層結構

> "**The MMU is responsible for translating the process's virtual address into a physical address to access main
>  memory. Each process has a page table that identifies the (PPN) for each virtual page. In a practical system,
>  the page table is too big, so it is organized hierarchically into 2-5 levels. The top-level page table is indexed
>  with the most significant bits of the virtual address. It points to the next-level page table, which is indexed
>  with the next most significant bits of the virtual address. This level in turn may point to another page table
>  until the leaf page table entry (PTE) is reached.**"
> — p.512–513

中文解釋：**「頁表太大」是多層結構存在的唯一理由**
（呼應 11.1.1.4 節：64-bit 單層頁表要 32 PiB）。

**索引的順序：最高位元索引最頂層，依序往下。**

**Leaf PTE 的內容與 fault 條件（p.513）：**
> "**The leaf PTE contains the PPN and a set of flags such as valid, accessed, dirty, and access permission bits.
>  If the PTE is invalid, has incorrect access permissions, or the page table is otherwise malformed, the MMU causes
>  a page-fault exception, which fetches the missing page from disk into main memory, or kills a misbehaving
>  process.**"

**三種 page fault 的原因：無效、權限不對、頁表畸形。
兩種處理：從磁碟抓 page，或殺掉行為不當的 process。**

### TLB 與 HPTW

> "**Traversing the page table on each memory access would greatly slow loads and stores, so the MMU contains a TLB,
>  which is a cache of frequently used PTEs. Pages are large, so even a small TLB generally has a high hit rate
>  because of spatial locality. If the TLB misses, the HPTW injects accesses into the LSU to walk the page table and
>  find the missing PTE.**"
> — p.513

中文解釋：**「Page 很大，所以即使小的 TLB 也有高命中率」——
這是 TLB 能用 16–128 個項目就達到 99% 命中率的原因**
（呼應 11.1.1.5 節）。

**注意「HPTW 把存取注入 LSU」這個描述**——
呼應 11.4.2 節：HPTW 借用 LSU 的資料通路來讀頁表。

### 誰用虛擬定址

> "**In RISC-V, machine-mode firmware uses physical addressing (except when `mstatus.MPRV` is enabled to facilitate
>  address translation in an exception handler). The supervisor-mode OS enables virtual addressing with the `satp`
>  CSR.**"
> — p.513

中文解釋：**M-mode 一律用實體定址，除了 `MPRV` 那個例外**（呼應 11.2.1.5 節）。

### PMA 與 PMP

> "**RISC-V also defines PMA and PMP checking. The PMA checker uses the physical address to determine which memory or
>  peripheral is being accessed and the attributes of that memory. If the access goes to an unimplemented physical
>  address or is of a type the peripheral cannot handle, the PMA checker causes an access-fault exception.
>  The PMA is typically hardwired to reflect the system's memory map.**"
> — p.513

> "**The PMP checker enhances security by limiting access to certain physical memory regions to machine or supervisor
>  mode, triggering an access fault exception for disallowed accesses. For example, PMP is often used to restrict
>  access to the firmware code to machine mode only, thus preventing a malicious user program from modifying the
>  firmware. RISC-V has 0, 16, or 64 PMP CSRs to define PMP regions; 16 is typical for an application processor.**"
> — p.513

中文解釋：**兩者的對比很清楚：**

| | **PMA** | **PMP** |
| --- | --- | --- |
| 依據 | **記憶體映射** | **特權模式** |
| 實作 | **通常硬接** | **軟體可組態的 CSR** |
| 典型用途 | 位址解碼、屬性檢查 | **保護韌體不被惡意使用者程式修改** |
| 數量 | — | **0、16 或 64；應用處理器典型是 16** |

### Wally 的實作，以及「way ≤ 4 KiB」的完整理由

> "**Wally's IFU and LSU each have their own MMU but share an HPTW in the LSU to handle TLB misses. Each MMU contains
>  a TLB to translate virtual to physical addresses when virtual memory is enabled. The TLB is fully associative,
>  using a CAM to identify which entry matches the VPN and then a RAM to read out the PPN and flags.**"
> — p.513

> "**The TLB operates concurrently with the cache access in the Fetch or Memory stage. Thus, the cache only knows the
>  bottom 12 bits of the physical address when the access begins. By limiting cache ways to 2^12 bytes = 4 KiB, the
>  way is always indexed by a physical address. The rest of the physical address is available from the TLB by the
>  time it is needed to compare against tags. Thus, the cache is physically addressed, avoiding synonym problems.**"
> — p.513

中文解釋：**這三句話是第 10 章和第 11 章的交會點，值得完整理解：**

```
1. TLB 和 cache 同時存取（平行）
2. 存取開始時，cache 只知道實體位址的低 12 bits（= page offset，不需轉譯）
3. 把 cache way 限制在 2^12 = 4 KiB → set 索引完全落在那 12 bits 裡
   → way 永遠是用「實體位址」索引的
4. 實體位址的其餘部分由 TLB 及時提供，用來和 tag 比對
5. → cache 實質上是「實體定址」的，避開 synonym 問題
```

**「By limiting cache ways to 4 KiB, the way is always indexed by a physical address」
——這一句就是第 10 章那條規則（way size ≤ page size）的完整理由。**

**注意措辭的細微之處：雖然用的是虛擬位址的低 12 bits 去索引，
但因為那 12 bits 在虛擬和實體位址中相同，所以「實質上是用實體位址索引」。**

**最後兩句（p.513）：**
> "**The `sfence.vma` instruction flushes the TLB by clearing its valid bits. The DMMU is on the critical path in
>  Wally's 5-stage pipeline.**"
> "**The wally-riscv-arch-test programs exercise the virtual memory system, PMA checkers, and PMP checkers.**"

**「DMMU 在關鍵路徑上」再次確認**（呼應 6.5.3 節 Table 6.11 和 11.4.1 節）。

## 所以呢

**第 11 章讓處理器能跑多個互相隔離的 process，並保護記憶體。**

四件最該帶走的事：

1. **虛擬記憶體用「每個 process 一個獨立位址空間」
   同時解決 relocation、fragmentation、protection。**

2. **兩個「太大/太慢」和它們的解法**：
   **頁表太大 → 2–5 層的階層結構；
   每次存取都走訪太慢 → TLB（page 很大，所以小 TLB 就有高命中率）。**

3. **PMA 和 PMP 的分工**：
   **PMA 依記憶體映射（通常硬接），PMP 依特權模式（軟體可組態）。**
   PMP 的典型用途是保護韌體不被使用者程式修改。

4. **「cache way ≤ 4 KiB」的完整理由**：
   **TLB 和 cache 平行存取 → 存取開始時只知道低 12 bits（page offset）
   → way 限制在 4 KiB 就能讓 set 索引完全落在那 12 bits 裡
   → cache 實質上是實體定址的 → 避開 synonym 問題。**

**這一章和第 10 章是一組：cache 的組織受虛擬記憶體的 page size 直接約束。**

下一章（第 12 章）把 cache、匯流排、MMU、HPTW 整合成完整的 LSU。
