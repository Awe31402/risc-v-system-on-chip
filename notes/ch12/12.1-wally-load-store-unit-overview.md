# 12.1 Wally Load/Store Unit Overview

> 原書 p.515–518（Chapter 12: Load/Store Unit）
> 含章首導論

## 這節在講什麼

**整合章的開場：把前面五章的零件拼成完整的 LSU。**

**這一章的定位很特別（書上明說）：
「本章不提出新原理，只聚焦於 LSU 的實作，
特別是 D$、MMU 和先前描述的匯流排元件的整合。」**

所以這一節的價值在於**「回顧地圖」**：
它把第 7、9、10、11 章各自加進 LSU 的東西列出來，
並說明各組態（rv32e / rv32i / rv32imc / rv{32/64}gc）各有什麼。

## 關鍵點

### LSU 的職責與本章範圍

> "**The load/store unit (LSU) handles data memory access for load and store instructions. It also fetches PTEs
>  (page table entries) on behalf of the hardware page table walker (HPTW). Chapter 17 adds LSU support for AMOs
>  (atomic memory operations).**"
> — p.515

中文解釋：**LSU 的三個職責（第三個在第 17 章）：**
1. **load/store 的資料記憶體存取**
2. **替 HPTW 抓取 PTE**
3. （第 17 章）原子記憶體操作

### 前面各章加了什麼

> "Past chapters described various LSU elements. **Chapter 7 introduced a simple LSU with a DTIM (data tightly
>  integrated memory). Chapter 9 added support for off-chip memory and peripherals via the external bus unit (EBU).
>  Chapter 10 described cache design, and Chapter 11 described the MMU (memory management unit), including address
>  translation, the TLB (translation lookaside buffer), the HPTW (hardware page table walker), and PMP (physical
>  memory protection) checker. This chapter combines all these capabilities into a fully featured LSU.**"
> — p.515

中文解釋：**這是一張很清楚的累積地圖：**

| 章 | 加了什麼到 LSU |
| --- | --- |
| **7** | **DTIM**（簡單的緊耦合資料記憶體） |
| **9** | **EBU**（晶片外記憶體與周邊） |
| **10** | **Cache** |
| **11** | **MMU**（位址轉譯、TLB、HPTW、PMP） |
| **12（本章）** | **把上面全部整合起來** |
| 17 | AMO（原子操作） |

**（p.515 明說本章的定位：**
「**This chapter presents no new principles but focuses on the implementation of the LSU,
especially the integration of the D$, MMU, and bus components previously described.**」**）

### 資料流的全貌

> "**The LSU receives memory addresses from the IEU (integer execution unit). When virtual memory is enabled, the
>  TLB translates the addresses from virtual to physical. The PMP checker within the LSU faults on illegal accesses
>  to protected memory. The LSU accesses the core memories: either the DTIM (not shown in Fig. 12.1) or the data
>  cache (D$). When the LSU requests an address that is not in the core memories, it uses the external bus to
>  access peripherals or memory in the uncore or off-chip. The HPTW is part of the LSU because it fetches PTEs
>  through the D$ for TLB misses. The HPTW services both data and instruction TLBs and writes status bits back to
>  the page tables in memory during page faults.**"
> — p.515

中文解釋：**一條完整的資料路徑，值得記住順序：**

```
IEU 送來位址
  ↓
TLB 轉譯（虛擬記憶體啟用時）
  ↓
PMP 檢查（違規就 fault）
  ↓
核心記憶體（DTIM 或 D$）
  ↓ （不在核心記憶體）
外部匯流排 → uncore 的周邊或記憶體、或晶片外
```

**HPTW 在 LSU 裡的兩個理由再確認：**
1. **它透過 D$ 抓 PTE**（所以頁表存取也能被 cache 加速）
2. **它服務兩個 TLB，並在 page fault 時把狀態位元寫回記憶體中的頁表**

### 各組態的 LSU 長什麼樣（本節最實用的部分）

> "**The Wally LSU can be configured to have a DTIM, a D$, or no core memory. Table A.1 in Appendix A lists various
>  standard configurations and their LSU parameters. The embedded rv32e configuration has no core memory.
>  The simple rv{32/64}i and microcontroller rv32imc configurations have tightly integrated memories.
>  The apps processors rv{32/64}gc have caches. The microcontroller and apps processors have a privileged unit and
>  MMU with a PMA (physical memory attributes) checker to catch illegal access and address misalignment faults;
>  they also have a bus interface to uncore peripherals, external memory, or both. The apps processors also add
>  virtual memory and a PMP checker to the MMU along with associated page faults.**"
> — p.516

中文解釋：**四種組態的 LSU 配備，這張表是本節的精華：**

| 組態 | 核心記憶體 | 特權單元 + MMU/PMA | 匯流排介面 | 虛擬記憶體 + PMP |
| --- | --- | --- | --- | --- |
| **rv32e**（嵌入式） | **無** | ✗ | ✓（只有匯流排） | ✗ |
| **rv{32/64}i**（簡單） | **DTIM** | ✗ | ✗ | ✗ |
| **rv32imc**（微控制器） | **DTIM** | **✓** | **✓** | ✗ |
| **rv{32/64}gc**（應用處理器） | **D$** | ✓ | ✓ | **✓** |

**三條演進線：核心記憶體（無 → TIM → cache）、
記憶體檢查（無 → PMA → PMA + PMP）、匯流排（無 → 有）。**

## 名詞表

| 名詞 | 意思 |
| --- | --- |
| LSU | Load/store unit。處理資料記憶體存取，並替 HPTW 抓 PTE |
| DTIM / D$ | 資料緊耦合記憶體 / 資料 cache |
| **LLEN** | max(XLEN, FLEN)。LSU 的原生字長 |
| **SCR** | Sub-cache line read。從 cache line 選出字產生 `ReadDataWord` |
| ES / SWR / SWW | `endianswap` / `subwordread` / `subwordwrite` |
| `ahbcacheinterface` | 支援 burst 的 AHB 介面（取代第 9 章的 `ahbinterface`） |

## 所以呢

**這節是整合章的地圖。三件最該帶走的事：**

1. **LSU 的完整資料路徑**：
   **IEU 位址 → TLB 轉譯 → PMP 檢查 → 核心記憶體（DTIM 或 D$）
   → 不在核心記憶體就走外部匯流排。**

2. **四種組態的 LSU 配備差異**：
   **rv32e（只有匯流排）→ rv{32/64}i（DTIM）→ rv32imc（DTIM + PMA + 匯流排）
   → rv{32/64}gc（D$ + 完整 MMU + HPTW）。**

3. **HPTW 在 LSU 裡的兩個理由**：
   **它透過 D$ 抓 PTE**（頁表也能被 cache 加速），
   **而且它服務兩個 TLB。**

**這一章不introduce新原理，是把第 7、9、10、11 章的零件組裝起來——
所以讀不懂時，回去看對應章節而不是硬讀。**
