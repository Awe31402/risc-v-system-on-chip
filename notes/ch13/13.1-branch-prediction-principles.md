| 元件 | 回答什麼問題 |

## 關鍵點

### 動機：誤預測的代價

> "**Recall that the basic 5-stage pipeline from Section 7.2 predicts that branches are not taken and continues
>  fetching subsequent instructions. In the Execute stage, it determines whether the branch should have been taken.
>  If so, it flushes the next two instructions and updates the PC to the correct branch target address (BTA).
>  So, the *misprediction penalty*, the number of cycles lost because of the misprediction, is 2 cycles.
>  The flush increases the CPI (cycles per instruction) to 3 for taken branches. Branches occur every 4-7
>  instructions in typical code, meaning that roughly 20% of executed instructions are branches.**"
> — p.545–546

中文解釋：**三個關鍵數字：**
- **誤預測懲罰 = 2 週期**（Wally 的 5 級 pipeline）
- **成立的分支 CPI = 3**
- **約 20% 的指令是分支**（每 4–7 條指令一個）

**Example 13.1（p.546–547）的計算很有說服力，值得跟一遍：**

**（1）Wally 的 5 級 pipeline：**
> "In the CoreMark benchmark from Section 7.2.2.5, 22.2% of executed instructions are branches, and 41.9% of them
>  are taken.... **A taken branch requires 3 cycles: 1 to execute and 2 to flush the Fetch and Decode stages.
>  A not-taken branch requires 1 cycle.
>  CPI = (1 − 0.168) × 1 + 0.168 × [3 × 0.423 + 1 × (1 − 0.423)] = 1.14, which is 14% slower than the ideal CPI
>  of 1.**"

**（2）2-way superscalar（理想 CPI = 0.5）：**
> "**A not-taken branch and other instructions require 0.5 cycles. A taken branch takes 3 cycles to execute, and it
>  flushes 5 instructions: 2 from the Fetch stage, 2 from Decode, and 1 from Execute.
>  CPI = (1 − 0.168) × 0.5 + 0.168 × [3 × 0.423 + 0.5 × (1 − 0.423)] = 0.68, which is 36% slower than the ideal CPI
>  of 0.5.**"

**關鍵對比：同樣的分支行為，5 級 pipeline 慢 14%，2-way superscalar 慢 36%。**

**為什麼越高效能的處理器越需要分支預測（p.547）：**
> "**Branch misprediction becomes much more significant in wide superscalar processors with deeper pipelines.
>  For example, the Pentium 4 has a 20-cycle branch misprediction penalty and dispatches up to 4 instructions per
>  cycle, meaning a misprediction could flush up to 80 instructions [Hinton01]. Even a misprediction rate of 1%
>  would have a significant impact on CPI.**"

**Pentium 4：20 週期 × 4 指令/週期 = 一次誤預測最多丟掉 80 條指令。**
**即使誤預測率只有 1% 也影響顯著。**
（呼應 1.6 節：Pentium 4 的 31 級 pipeline。）

### 分支預測器的三個職責

> "**Branch prediction takes place in the Fetch stage to predict which instruction the IFU should fetch next.
>  A dynamic branch predictor performs three main operations: it determines if the instruction is a branch or jump,
>  predicts whether the branch is taken, and keeps track of target addresses for branches and jumps. To do this, the
>  dynamic branch predictor uses:
>  - A *branch history table* (BHT) to track recent branch outcomes and use them to predict whether the branch will
>    be taken.
>  - A BTB to record recent branches or jumps and their target addresses. The target buffer is essentially a
>    direct-mapped cache indexed by the PC that produces the target address for taken branches and jumps.
>  - A *return address stack* (RAS) to track recent return addresses because function returns are poorly tracked
>    with an ordinary BTB.**"
> — p.547

中文解釋：**三個職責、三個元件，一對一。**

**（p.547 邊欄的重要區分：**
「**Direct jump**（如分支和 `jal`）用立即值欄位指定相對 PC 的目標位址。
**Indirect jump**（如 `jalr`）指定目標位址所在的*位置*，例如暫存器。
**Direct jump 每次執行都算出同樣的目標位址，indirect jump 不一定。**
例如 `ret`（`jr ra` 的 pseudoinstruction）是 indirect 的，
所以**同一個 `jr` 的每次執行目標位址可能不同。**」**）

**這個區分直接解釋了為什麼需要 RAS。**

### Static Branch Prediction

> "**A static branch predictor relies on information known at compile time. The simplest static predictor guesses
>  that a branch is not taken, as in Section 7.2. However, backward branches, such as those used in `for` and
>  `while` loops, are taken about 90% of the time. Forward branches are taken about 50% of the time. A better static
>  branch predictor guesses that backward branches are taken. The ARM 11 core used static branch prediction [ARM11].**"
> — p.548

中文解釋：**兩個很實用的統計數字：**

| 分支方向 | 成立機率 |
| --- | --- |
| **向後（backward）** | **約 90%** |
| **向前（forward）** | **約 50%** |

**所以「向後就預測成立」是一個零成本的改進**——
迴圈的結尾分支都是向後的。

### 1-bit 動態預測器的問題

> "**Dynamic branch prediction captures past program behavior to guess the *direction* of the current branch, that
>  is, whether it is taken or not. A *1-bit dynamic predictor* tracks whether a branch was taken last time and
>  predicts to do the same next time.**"
> — p.548

中文解釋：**Code Example 13.1（p.548）的巢狀迴圈是經典範例：**
```c
int i, j;
for (i=0; i<5; i++)
  for (j=0; j<10; j++)
    dostuff
```
```asm
0x134:   blt s1, t1, forj    # branch_j: Repeat if j < 10
0x13C:   blt s0, t0, fori    # branch_i: Repeat if i < 5
```

**1-bit 預測器的失敗分析（p.548）：**
> "**`branch_j` at the end of the j loop... is executed 10 times for each iteration of the i loop. That `blt` is
>  taken on the first nine times and not taken on the 10th. A 1-bit predictor mostly guesses taken. On the tenth
>  time, it is wrong, and it now records not taken. However, on the next iteration of the i loop, `branch_j` should
>  be taken, but it is predicted not taken. Thus, the branch is mispredicted on the first and last iteration of the
>  j loop. In this example, the prediction accuracy is 80% for `branch_j`. Similarly, the i loop's first and last
>  branches are also mispredicted, so that loop has a (5 − 2)/5 = 60% prediction accuracy.**"

**關鍵洞見：1-bit 預測器在每個迴圈會錯兩次（第一次和最後一次）——
「最後一次錯」是無可避免的，但「第一次錯」是 1-bit 的缺陷。**

### 2-bit 預測器：讓偶發的例外不翻轉預測

> "**The *2-bit dynamic branch predictor* (or *2-bit predictor*) in Fig. 13.2 improves the accuracy by remembering
>  more history and only changing the prediction after multiple incorrect guesses. The states are encoded such that
>  the most significant bit indicates the prediction (1 for taken, 0 for not taken). During the j loop, the predictor
>  for `branch_j` enters the Strongly Taken state, with an output of 11. When it mispredicts on the last time through
>  the j loop, it moves to the Weakly Taken state (10). The next time it starts the j loop, it still predicts
>  `branch_j` as taken. Thus, `branch_j` is only mispredicted the last time through the j loop. In this example, the
>  prediction accuracy is 90% for `branch_j`.**"
> — p.549

中文解釋：**四個狀態（Fig. 13.2，p.549）：**
```
Strongly Taken (11) ⇄ Weakly Taken (10) ⇄ Weakly Not Taken (01) ⇄ Strongly Not Taken (00)
      預測成立              預測成立              預測不成立              預測不成立
                                    ↑ reset
```

**設計的兩個巧妙之處：**
1. **最高位元就是預測結果**（1 = 成立）——**不需要額外的解碼邏輯**
2. **需要連錯兩次才會翻轉預測**——**所以「迴圈最後一次錯」不會影響下一輪**

**結果：`branch_j` 的準確率從 80% 提升到 90%。**

**（p.549 邊欄：**「2-bit 分支預測器也叫 *bimodal* 預測器。」
以及：**「FSM 的狀態位元叫 *saturating counter*，
在 Strongly Taken 時飽和在 11、Strongly Not Taken 時飽和在 00。」**）

### BHT 的實作

> "**The branch predictor stores the history information in a BHT (branch history table). The table has a finite
>  number of entries and is typically indexed by the less significant b bits of the PC, typically excluding the two
>  lsbs, which are 0 if all instructions are 32 bits.**"
> — p.549

中文解釋：**Fig. 13.3（p.550）的 BHT 是一個 `2^b × 2` 的 dual-port 同步 RAM：**
```
Fetch 級：  PCNextF 索引 BHT → BPDirF（預測方向）
           BPDirF 一路 pipeline：BPDirF → BPDirD → BPDirE
Execute 級：XOR 比較 BPDirE 和 PCSrcE（真實方向）
           不同 → BPDirWrongE = 1
           2-bit saturating counter 依 BPDirE 和 PCSrcE 算出 NewBPDirE
           用 PCE 的 b 個位元寫回 BHT
```

**（p.549 邊欄的重要提醒：**
「**BHT 的行為類似沒有 tag 的 direct-mapped cache，
這表示不同程式位址的分支之間可能存在衝突。這些衝突降低預測準確度，
但不會造成程式失敗，因為誤預測的後果只是 flush 掉錯誤抓取的指令。**」**）

**這是 BHT 和 cache 的關鍵差異：BHT 可以「錯」，cache 不行。**

**（p.549 邊欄的命名慣例：**「整個分支預測器中，**預測的訊號都加 `BP` 前綴**。」**）

**Example 13.2（p.550）的計算：**
> "Suppose Code Example 13.1 is run on the 2-bit branch predictor from Fig. 13.3 with b = 4.... **This first branch
>  is at address 0x134 = 0b000100110100. Bits 5:2 of this address are 1101, so the branch maps to BHT entry 13.
>  The next branch is at address 0x13C (0b000100111100) and maps to BHT entry 15.... Each branch is repeatedly taken,
>  moving to the Strongly Taken state. However, on the last iteration of each loop, the branch is not taken, moving
>  back to the Weakly Taken (10) state. Thus, entries 13 and 15 both contain 10, and the other entries remain at
>  their reset value 01.**"

**注意用的是 PC[5:2]（跳過最低兩位，因為 32-bit 指令永遠字對齊）。**

### 2-bit 預測器的實際準確度

中文解釋：**Fig. 13.4（p.551）在 SPEC89 上用 4,096 項 BHT 的誤預測率：**

| Benchmark | 誤預測率 |
| --- | --- |
| **matrix300** | **0%** |
| nasa7 / tomcatv | 1% |
| doduc / espresso | 5% |
| spice / fpppp | 9% |
| li | 10% |
| **gcc** | **12%** |
| **eqntott** | **18%** |

**書上的解讀（p.551）：**
> "**Some complex programs, such as gcc, have relatively low accuracy, but scientific computing programs with highly
>  repetitive loops (e.g., nasa7, matrix300, and tomcatv) have higher accuracy. Increasing the BHT size to infinity
>  improves results by less than 1%, so 4,096 entries is sufficient for many programs.**"

**「把 BHT 加大到無限只改善不到 1%」——所以 4,096 項就夠了。**
**這說明了瓶頸不在表的大小，而在預測演算法本身。**

**（p.551 邊欄的實作細節很實用：**
「**4,096 × 2-bit 的 SRAM 長寬比極端，在晶片上做不實際。
它通常會被摺疊成比較方形的形狀。例如摺疊 32 倍得到 128 × 64-bit 的 SRAM，
用原本位址的低位元當多工器選擇和位元寫入致能，來讀或寫 64 個位元中的 2 個。**」**）

### Gshare：利用分支之間的相關性

> "**The 2-bit predictor considers each branch independently. Careful program analysis shows that some branch
>  outcomes are correlated with others. To improve accuracy, a *global history dynamic branch predictor* considers
>  the history of the last several branches. The widely used *Gshare* predictor incorporates global history to
>  achieve prediction accuracy greater than 96% with 4,096 entries [McFarling93].**"
> — p.551

中文解釋：**Code Example 13.2（p.552）的相關分支範例，
來自 SPEC89 的 eqntott（Fig. 13.4 中準確度最差的那個）：**
```c
if (aa == 2) aa = 0;
if (bb == 2) bb = 0;
if (aa != bb) { dostuff }
```
```asm
0x1004: bne s0, t0, skipaa    # branch_aa: Skip if aa != 2
0x100C: bne s1, t0, skipbb    # branch_bb: Skip if bb != 2
0x1014: beq s0, s1, skipaabb  # branch_aabb: Skip if aa != bb
```

**相關性的來源（p.551）：**
> "**If `branch_aa` and `branch_bb` are both not taken (and hence make aa and bb = 0), then `branch_aabb` will be
>  taken. Hence, `branch_aabb` partially depends on the outcome of previous branches. By separating the prediction of
>  `branch_aabb` into four scenarios that depend on the outcomes of the previous two branches, the predictor can
>  reduce the interference between the different scenarios and improve the prediction accuracy.**"

**「把 `branch_aabb` 的預測依前兩個分支的結果分成四種情境」——
這就是全域歷史的核心想法。**

### Gshare 的機制

> "**Gshare adds a k-bit *global history shift register* (GHR) that tracks the outcome of the last k branches.
>  Instead of using the PC directly to index the PHT, Gshare indexes it using a *hash*, which is PCNextF ⊕ GHR.
>  Therefore, sequences of branches with different histories each map to different locations and are separately
>  predicted. Empirically, prediction accuracy is best when the number of table index bits b (extracted from the PC)
>  equals the GHR length k.**"
> — p.552

中文解釋：**兩個關鍵設計：**

| 元素 | 說明 |
| --- | --- |
| **GHR** | **k-bit 移位暫存器，記錄最近 k 個分支的結果** |
| **索引方式** | **`PCNextF ⊕ GHR`（XOR hash），而非直接用 PC** |
| **經驗法則** | **表索引位元數 b = GHR 長度 k 時準確度最佳** |

**XOR 的作用：讓「同一個分支 + 不同歷史」映射到不同的表項，
所以可以分別學習。**

**（p.552 邊欄的術語：**「Gshare 和 global history 預測器常被稱為
***correlating predictors***，因為它們考慮分支結果之間的關聯。
也常被稱為 ***2-level adaptive predictors***，因為它們用兩層記錄分支歷史：
**GHR 和 PHT**。」**）

**PHT vs BHT（p.552）：**
> "**Gshare calls this a *pattern history table* (PHT) instead of a BHT because it reflects patterns of branch
>  history.**"

**一個重要的實務問題（p.552）：**
> "**Gshare updates the GHR and PHT after each branch outcome is known in the Execute stage. A given branch affects
>  many entries of the PHT based on the GHR, so Gshare needs time to train all these entries before producing
>  accurate predictions.**"

**Gshare 需要更長的「暖機」時間**——因為一個分支會影響 PHT 的多個項目。

### Gshare vs 2-bit 的實測比較

中文解釋：**Fig. 13.6（p.553）在 Embench 上比較四條曲線
（gshareWally、twobitWally、twobitCModel、gshareCModel）：**

| Entries | 2-bit 準確度 | Gshare 準確度 |
| --- | --- | --- |
| **64** | **約 89.8%** | **約 88.4%（更差！）** |

**書上的解讀（p.552）：**

和 **Sun UltraSPARC-III**（16K 項）。」**）

### BTB：預測跳去哪

> "**The branch predictor must guess not only whether a branch is taken but also the branch target address (BTA) where
>  the branch would go if taken. Both guesses should be ready in time to fetch the next instruction. A BTB caches
>  BTAs. Like the BHT or PHT, a BTB is indexed with the lower bits of PC. The BTB is accessed in parallel with the
>  BHT/PHT. If the branch predictor guesses taken, the processor uses the BTA as the next PC; otherwise, it uses
>  PC + 4. Like the BHT/PHT and unlike a conventional cache, the BTB omits tags, so multiple branches could alias to
>  the same BTB entry.**"
> — p.554

中文解釋：**BTB 和 BHT 的共同點：都用 PC 低位元索引、都沒有 tag、都可能 alias。**

**誤預測的處理（p.554）：**
> "**If the BTB incorrectly guesses the target address, the pipeline flushes the bad fetch after the correct target
>  address is computed and updates the BTB with the corrected BTA. The BTB also caches the target address for jumps.**"

**（p.554 邊欄的觀察：**「因為多條指令會 alias 到同一個 BTB 項目，
**BTB 可能同時誤預測目標位址和指令類別**。資料顯示這通常對 BTB 準確度影響很小，
**雖然某些 benchmark（如 Embench 的 `nsichneu`）因為這種 aliasing 而有顯著的效能損失。**」**）

### 誤預測的偵測與恢復

> "**If the Execute stage determines the next PC was mispredicted, it asserts BPWrongE and PC logic selects
>  PCNextF = PCCorrectE, the PC of the correct next instruction after the branch. If the Execute stage instruction is
>  a taken branch or a jump, then PCCorrectE is the BTA, IEUAdrE. Otherwise, PCCorrectE is the fall through address
>  PCE + 4.**"
> — p.555

> "**Unlike the branch direction predictors of Fig. 13.3 and Fig. 13.5, which checks if the branch predictor's
>  direction matches, now the predictor needs to check if the PC of the next instruction (PCD) matches what the IEU
>  computed (PCCorrectE). If they mismatch and both instructions are valid (InstrValidD = InstrValidE = 1), the
>  branch predictor fetched the wrong instruction and must assert BPWrongE to flush the Decode and Execute stages.**"
> — p.555

中文解釋：**檢查方式的升級很重要：**

| 層次 | 檢查什麼 |
| --- | --- |
| **只有方向預測器** | **預測方向 vs 真實方向** |
| **加上 BTB** | **實際抓到的下一條指令的 PC（`PCD`）vs 正確的 PC（`PCCorrectE`）** |

**後者更根本——它一次涵蓋了方向錯、目標位址錯、指令類別錯等所有情況。**

**而且要檢查 `InstrValidD` 和 `InstrValidE`——避免對無效指令誤判。**

### BTB 的準確度

中文解釋：**Fig. 13.8（p.555）在 Embench 上的 BTB 準確度：**

| Entries | 準確度 |
| --- | --- |
| 64 | 約 98.3% |
| **256** | **約 99.7%** |
| 1024 以上 | **約 100%** |

**書上的解讀（p.555–556）：**
> "**The working sets of Embench programs are typically small and comfortably fit inside both the I$ and branch
>  predictor. Even with just 256 entries, the BTB hits 99% of all jump and branch instructions after a sufficient
>  warmup time. All RISC-V branches and most jumps have *direct* branch/jump targets because they compute their
>  target address relative to PC. A direct target never changes; therefore, the BTB readily achieves near 100%
>  accuracy.**"

**「Direct target 永遠不變，所以 BTB 很容易接近 100% 準確」——
這解釋了為什麼 BTB 比方向預測器容易做（後者只有 94–98%）。**

**（p.556：**「2.9 節列出了幾個 RISC-V 處理器的 BHT 和 BTB 大小。
**低階處理器的 BTB 從 4 到 256 項。較小的 BTB 通常是 associative 的，而且不包含指令類別預測。**」**）

### RAS：處理函式返回

> "**The BTB works well for branches and `jal` because the destination is part of the instruction. However, function
>  returns (`ret`) are difficult to predict because they have different return addresses depending on where the
>  function was called. Because function calls occur in pairs with returns, a *return address stack* (RAS) reliably
>  predicts the return address. A RAS is a small hardware stack that pushes the return address when calling a
>  function and pops the address when returning.**"
> — p.556

中文解釋：**問題的本質：**
**`ret` 是 indirect jump，同一條 `ret` 每次的目標位址都不同（取決於誰呼叫它）。**
**但「函式呼叫和返回成對出現」這個性質讓堆疊剛好適用。**

**Fig. 13.9（p.556）的硬體：一個小記憶體 + 一個指標 `Ptr`：**
```
Call（jal ra, <dest>）：
  計算 PCLinkE = PCE + 4
  遞增 Ptr
  把返回位址寫進 RAS 記憶體
Return（ret）：
  讀 RAS 記憶體的 Ptr 位置 → RASPCF
  遞減 Ptr
```

**Fig. 13.10（p.557）的五個步驟示範（4 項 RAS）：**
```
(a) Ptr 初始化在最底項
(b) 0x105c 的 jal 推入返回位址 0x1060
(c) 0x1140 的 jal 推入返回位址 0x1144
(d) 0x1230 的 ret 彈出 → 預測 PCNextF = 0x1144
(e) 0x11B4 的 ret 彈出 → 預測 PCNextF = 0x1060
```

**RAS 的大小（p.556）：**
> "**A RAS typically has 3 to 16 entries because the majority of programs have a limited call depth.
>  However, when the RAS overflows, Ptr wraps around, overwriting the oldest valid return address. In practice, this
>  has a small effect on prediction accuracy because the recent pushes are still valid.**"

**只要 3–16 項就夠**，而且**溢位時繞回覆蓋最舊的，影響很小**
（因為最近的呼叫仍然正確）。

**兩個失效情況（p.557）：**
> "**`jal` and `ret` instructions are usually paired together; however, buggy programs could execute `ret` without a
>  preceding `jal`. Without a preceding `jal`, the RAS pops the stack as usual but will contain an invalid return
>  address. The misprediction recovery logic of Fig. 13.11 detects the incorrect address and flushes the pipeline just
>  like a branch misprediction. Additionally, program code could change the return address in ra, but the RAS won't be
>  updated; this would cause `ret` to jump to (fetch) the wrong instruction. Again, the recovery logic detects the
>  mistake and flushes the pipeline.**"

**兩種情況都靠同一套恢復邏輯處理（p.557）：**
> "**In general, the recovery logic handles all control flow mispredictions regardless of the source of the
>  misprediction: BTB, RAS, and so on. If the calculated BTA (PCCorrectE) matches what was fetched (PCD), then the
>  branch predictor fetched the correct instruction.**"

**「不管誤預測的來源是什麼，恢復邏輯都一樣」——
這是一個很好的設計：把所有預測錯誤統一成「抓到的 PC 和正確的 PC 不符」。**

### TAGE：更高階的預測器

> "**High-performance processors need even better prediction accuracy than Gshare can provide. A *tournament branch
>  predictor* includes multiple subpredictors and chooses among them based on which proves most accurate for a given
>  branch.**"
> — p.557

> "**The *partially TAgged GEometric global history* tournament branch predictor (TAGE) achieves better than 99%
>  accuracy with sufficiently large memories [Seznec06, Hennessy19]. TAGE may be too complex to complete in one cycle.
>  Therefore, it is sometimes used as a second-level predictor to correct a faster but less accurate first-level
>  predictor. For example, recent AMD Ryzen CPUs use TAGE as a second-level predictor [Suggs20].**"
> — p.557

中文解釋：**TAGE 的定位：準確度 > 99%，但太複雜無法在一個週期內完成。**
**所以常當作「第二層預測器」來修正第一層的快速預測。**

**TAGE 的核心想法（p.557）：**
> "**TAGE uses multiple Gshare-like subpredictors, each with a different-length GHR. The lengths are typically 0, 2,
>  4, 8, 16, and so on, forming a geometric sequence. Shorter subpredictors warm up faster and avoid irrelevant
>  branch history, while the longer subpredictors capture the behavior of complex branch sequences.**"

**幾何級數的 GHR 長度（0, 2, 4, 8, 16…）——
短的暖機快且避免無關的歷史，長的能捕捉複雜的分支序列。**
**然後在它們之間選擇。**

## 名詞表

| 名詞 | 意思 |
| --- | --- |
| **Misprediction penalty** | 誤預測懲罰。Wally 是 **2 週期**；Pentium 4 是 20 週期 × 4 發射 = 最多 80 條指令 |
| **BTA** | Branch target address |
| Direct / indirect jump | 目標位址相對 PC 算出（永不變）/ 目標位址在暫存器裡（每次可能不同） |
| **Static branch prediction** | 編譯期資訊。**向後分支約 90% 成立、向前約 50%** |
| **1-bit predictor** | 記上次結果；**巢狀迴圈每輪錯兩次** |
| **2-bit predictor（bimodal）** | 四狀態飽和計數器；**msb 就是預測結果，要連錯兩次才翻轉** |
| Saturating counter | 飽和計數器。停在 11 或 00 不再變 |
| **BHT / PHT** | Branch history table / Pattern history table（Gshare 用的名稱） |
| **GHR** | Global history shift register，記錄最近 k 個分支的結果 |
| **Gshare** | **用 `PCNextF ⊕ GHR` 索引 PHT**；捕捉分支間的相關性；**b = k 時最佳** |
| Correlating / 2-level adaptive predictor | Gshare 類預測器的別稱 |
| **BTB** | Branch target buffer。**無 tag 的 direct-mapped cache，存 BTA** |
| `BPWrongE` / `PCCorrectE` | 誤預測旗標 / 正確的下一條指令位址 |
| **RAS** | Return address stack。**3–16 項；call 時 push、return 時 pop** |
| Tournament predictor | 多個子預測器，依哪個最準來選擇 |
| **TAGE** | Partially TAgged GEometric global history。**> 99% 準確，但常當第二層預測器** |

## 所以呢

**這節建立了分支預測的完整理論。五件最該帶走的事：**

1. **三個元件回答三個問題**：
   **BHT/PHT 答「會不會跳」、BTB 答「跳去哪」、RAS 答「函式返回跳去哪」。**

2. **2-bit 優於 1-bit 的理由很具體**：
   **需要連錯兩次才翻轉預測，所以「迴圈最後一次錯」不會影響下一輪。**
   巢狀迴圈的準確度從 80% 提升到 90%。

3. **Gshare 用 `PC ⊕ GHR` 索引**，捕捉分支間的相關性（97%+），
   **但表很小時反而不如 2-bit**（衝突更多），而且需要更長的暖機。

4. **BTB 比方向預測器容易做**（256 項就 99.7%）——
   **因為 RISC-V 的分支和多數跳躍是 direct 的，目標位址永不改變。**

5. **恢復邏輯統一處理所有誤預測**：
   **不管錯在 BTB、RAS 還是方向預測器，
   都是「抓到的 PC（`PCD`）和正確的 PC（`PCCorrectE`）不符」。**

**還有一個貫穿的觀念：分支預測器可以「錯」——
它是非架構狀態，錯了只是慢，不會讓程式跑錯。**
（呼應 2.7 節和 10.3 節。）
