# 22.4 Summary

> 原書 p.784.e76–784.e77（Chapter 22: Linux）

## 這節在講什麼

第 22 章的總結。用四段話把整個開機流程再走一遍——這是全章最好的複習材料。

## 關鍵點

### 五個元件

> "The OS components include a zero stage bootloader (ZSBL), firmware, device tree, kernel, and root file system. These may be read from an SD card into RAM on an FPGA board or simply initialized in RAM during logic simulation."
> — p.784.e76

中文解釋：**同樣五個元件，在模擬裡直接塞進記憶體，在 FPGA 上要從 SD 卡讀**——這就是第 23 章要處理的差別。

### 完整流程回顧

> "At reset, the processor executes the ZSBL from a small boot ROM. The ZSBL reads the firmware and device tree from the SD card if necessary, then jumps to the OpenSBI firmware bootloader."
> — p.784.e76

> "The OpenSBI firmware bootloader runs in M-mode. It sets up an M-mode trap handler; reads platform-specific information from the device tree; initializes harts, peripherals, and CSRs; and prints initial boot messages to the COM port. The bootloader then loads the kernel and enters S-mode to begin executing the kernel."
> — p.784.e77

> "The Linux kernel initializes the virtual memory page table and turns on virtual memory. Henceforth, Linux runs in S-mode with virtual addressing. It sets up an S-mode trap handler and then initializes many services including memory management, scheduling, timers, and console I/O. After this, the kernel reads the root file system and calls the init process, which is the first U-mode process and the parent of all other Linux processes. Finally, the user sees the login prompt on the console."
> — p.784.e77

中文解釋：三段話對應三個權限層級，每一層做的事有清楚的分工：

| 階段 | 模式 | 做什麼 |
| --- | --- | --- |
| ZSBL | M | 從 SD 卡讀 firmware 與 device tree，跳過去 |
| OpenSBI | M | 設 M-mode trap handler、讀 device tree 初始化硬體、印 banner，然後 **`mret` 降到 S-mode** |
| kernel | S | 開虛擬記憶體、設 S-mode trap handler、初始化服務、載入 rootfs，然後 **`sret` 降到 U-mode** |
| init | U | 啟動 daemon 與 shell，出現登入提示 |

**每一層都做三件事：設好自己的 trap handler、初始化這一層負責的資源、降權交棒給下一層。** 這個模式值得記住。

### 三個平台

> "The cvw repository supports booting Buildroot Linux on three platforms. First, a generic RISC-V processor can be emulated using QEMU. Second, a logic simulator (Questa, VCS, or Verilator) simulates Wally booting OpenSBI and the Linux kernel. Finally, Chapter 23 implements Wally physically on an FPGA and boots Linux into an interactive terminal shell."
> — p.784.e77

中文解釋：QEMU（軟體模擬處理器）→ 邏輯模擬（模擬 Wally 的 RTL）→ FPGA（真實硬體）。**抽象層一層層剝掉，最後只剩真的邏輯閘在跑。**

## 名詞表

| 名詞 | 意思 |
| --- | --- |
| COM port | 序列埠，開機訊息的輸出目的地（Wally 的 UART） |
| `mret` / `sret` | 從 M ／ S 模式返回較低權限模式的指令 |

## 所以呢

Linux 開機這一章的價值在於它是**唯一會同時用到前面所有章節的測試**——CSR、trap、虛擬記憶體、PMP、原子操作、快取、所有的周邊。能跑完登入提示，基本上就證明了整顆處理器是對的。

下一章把最後一層抽象也拿掉：把 Wally 合成、繞線、燒進一顆 Artix-7 FPGA，接上 DDR3 記憶體和 SD 卡，變成一台真的可以打字的電腦。
