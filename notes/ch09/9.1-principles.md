## 這節在講什麼

**匯流排設計的通用原理，按「逐步加功能」的順序展開。**

從最簡單的非同步唯讀匯流排開始，一層層加上：
**同步 → 讀寫 → 握手 → 多周邊 → 多控制器與仲裁 → 其他功能 → 晶片外高速連結。**

**最該帶走的是幾個「SoC 內部一律這樣做」的結論：
單向而非雙向、點對點而非共享、以及 handshaking 的必要性。**

## 關鍵點

### 匯流排的角色

> "A processor's capabilities are extended by interfacing it with external memory and peripherals such as
>  a keyboard, mouse, or display. **Digital systems use *bus interfaces* to connect components with
>  standardized communication protocols.... Using a standard SoC bus makes it practical to attach
>  off-the-shelf peripherals designed for that bus.**"
> — p.383

中文解釋：**標準化的價值就是「能接現成的周邊」**（呼應 4.1.3 節的 IP 重用）。

**本章的定位（p.383）：**
> "The chapter then extends the Wally processor by adding an external bus unit (EBU) that controls an AHB
>  bus. **Whereas the Wally processor from Chapter 7 used idealized instruction and data memories (IROM
>  and DTIM) located inside the core, the EBU added in this chapter provides access to RAM and ROM
>  located outside the processor in the uncore portion of the SoC.**"

**（p.384 邊欄：**「SoC 的 *uncore* 部分，如你所料，就是處理器核心以外的一切。
它包含匯流排介面、記憶體和周邊。」**——呼應 2.3.4 節。）

### 控制器與周邊，以及命名的演變

> "A bus connects one or more *controllers* to one or more *peripherals* or *responders*.
>  The peripheral might be a memory, such as SRAM..., DRAM..., or ROM, or an I/O... device such as a
>  timer, interrupt controller, general-purpose input/output (GPIO) device, serial port, or data
>  converter. **In most bus protocols, the controller sends an *address* to specify which peripheral and
>  which memory location or register within that peripheral to access. The bus also transmits *data*
>  that the controller reads from or writes to the peripheral.**"
> — p.383–384

中文解釋：**兩個角色、兩種訊號：控制器發位址、匯流排傳資料。**

**命名的演變（p.386 邊欄）值得一讀，因為讀舊文件會遇到：**
> "**Buses formerly used the nomenclature *master* and *slave*, and you will still see these terms in
>  standards documents. These terms carry dehumanizing and derogatory connotations, so the industry has
>  moved toward deprecating this language [Ellis21, OSHA22]. There is not yet agreement on new
>  terminology. In 2021, ARM began using the terms *manager* and *subordinate* or *requester* and
>  *completer*. Other applications, such as SCSI buses, use *initiator* and *target* for these two roles.
>  In the absence of a new standard, this book uses the terms *controller* and *peripheral* (or *device*).**"

**目前沒有統一的新術語**：ARM 用 manager/subordinate 或 requester/completer，
SCSI 用 initiator/target，本書用 controller/peripheral。

**（p.386 邊欄也提到：**「匯流排也叫 *links*。」**）

### 三種基本匯流排介面（逐步加功能）

> "Fig. 9.2 builds up a sequence of progressively more practical buses, showing the interface signals and
>  timing. **The simplest example of a bus is an *asynchronous read-only bus*, like the instruction memory
>  interface from Fig. 7.2.... However, most memories and peripherals are *synchronous* for ease of
>  implementation: they need the address to set up before a clock edge, and they return the read data
>  after that clock edge.... Peripherals other than ROMs and sensors need a read/write interface.
>  They need to know what to write (*write data*, WD), where to read/write (*address*, A), whether to
>  write (*write enable*, WE), and when to read/write (clk).**"
> — p.384–385

中文解釋：**Fig. 9.2（p.385）的三個階段：**

| 階段 | 訊號 | 特性 |
| --- | --- | --- |
| **(a) 非同步唯讀** | A、RD | 位址穩定後，一段有限時間內回傳資料 |
| **(b) 同步唯讀** | clk、A、RD | **位址要在時脈邊緣前 setup，資料在邊緣後回傳** |
| **(c) 同步讀寫** | clk、WE、A、WD、RD | **控制器在時脈邊緣前送出 A、WD、WE；周邊在邊緣後回 RD** |

**「寫什麼、寫哪裡、要不要寫、什麼時候寫」這四個問題就是 WD、A、WE、clk**
（呼應 2.7 節暫存器檔案寫入埠的四個要素）。

### 單向 vs 雙向：SoC 一律用單向

> "The bus in Fig. 9.2(c) has separate unidirectional RD and WD (read and write data) ports.
>  **Pins on a chip and wires on a circuit board are relatively expensive, so designers were historically
>  motivated to combine these two ports into a single bidirectional port, as shown in Fig. 9.3.
>  A tristate buffer, with alternating enable input polarity, is added on both the controller (left) and
>  peripheral (right) sides.**"
> — p.385

> "**In an SoC, far more wires are available. Moreover, long on-chip wires need repeaters (buffers) to
>  achieve reasonable speed, making bidirectional operation impractical. Hence, SoC buses universally
>  favor unidirectional buses. Tristate buffers driving on-chip bidirectional buses are typically
>  forbidden because of their poor performance and tool support.**"
> — p.385–386

中文解釋：**兩個理由，都是 SoC 特有的：**
1. **晶片內導線很多，不需要省**
2. **長導線需要 repeater（緩衝器）才能跑得快，而 repeater 是單向的**
   → **雙向操作不可行**

**結論：SoC 匯流排一律用單向，而且晶片內的 tristate 通常被禁止。**
（呼應 4.2.2.3 節 Guideline 4.7：tristate 只用於 I/O 接腳。）

### 點對點 vs 多點：高速連結的演變

> "**Unidirectional point-to-point off-chip buses also can run at a far higher speed than bidirectional
>  multidrop buses, which have multiple peripherals that connect to the bus at different points along the
>  bus wires. It is now cheaper to achieve a required bandwidth by running a moderate number of wires that
>  transmit data serially at high speed in each of several unidirectional links than to run a larger number
>  of wires at lower speed in a single bidirectional link.**"
> — p.386

中文解釋：**這是一個重要的經濟學轉折：
「少量高速序列的單向連結」比「大量低速的雙向連結」便宜。**

**這解釋了為什麼 PCIe、USB、SATA 都是序列而非並列**——
並列匯流排（如舊的 PCI、IDE）已經被淘汰了。

### Handshaking：不是所有周邊都一個週期回應

> "A controller only needs to access the bus some of the time. To save power, it can provide a *request*
>  (REQ) line that is only asserted when it puts a valid address on the bus."
> — p.386

> "**Some peripherals take more than one bus cycle to respond. For example, DRAM is fast for sequential
>  reads but slow for reads to random addresses. A bus often provides an *acknowledge* (ACK) or *ready*
>  (RDY) signal back from the peripheral indicating that the transfer is complete. This
>  request/acknowledge sequence is known as *handshaking*.**"
> — p.386

中文解釋：**兩個新訊號，各解決一個問題：**

| 訊號 | 方向 | 解決什麼 |
| --- | --- | --- |
| **REQ** | 控制器 → 周邊 | **省電**（只在有有效位址時 assert） |
| **RDY / ACK** | 周邊 → 控制器 | **周邊需要多個週期時，通知何時完成** |

**兩者合稱 handshaking（握手）。**

**Fig. 9.4（p.386）的波形：2 週期讀取存取時，
`RDY` 在第一個週期保持低電位，第二個週期升起，同時 `RD` 有效。**

### 多周邊：位址解碼器與 memory map

> "In a practical system, the controller communicates with multiple peripherals. **SoCs typically use
>  *memory-mapped I/O* to select a particular peripheral based on the address range. The SoC contains an
>  *address decoder* to produce select signals to choose which peripheral or memory to read based on the
>  address. The SoC *memory map* defines the addresses of each peripheral.**"
> — p.386

中文解釋：呼應 2.4 節。**位址解碼器把位址範圍轉成 select 訊號。**

**（p.386 邊欄：**「RISC-V 把位址解碼器一般化為 *physical memory attributes*（PMA）單元，
它同時決定該位址是否可 cache、允許哪些傳輸寬度等，見第 11.2.2.1 節。」**）

### 共享 vs 點對點資料埠（SoC 用點對點）

> "Fig. 9.5 shows buses that link multiple peripherals with *shared* and *point-to-point* data ports.
>  Both versions require an address decoder. **The shared bus allows multiple peripherals to drive the RD
>  and RDY lines using tristates.... In contrast, the point-to-point design requires a read multiplexer to
>  choose the read data (RD) and ready (RDY) signals from the selected peripheral. Shared buses minimize
>  the number of wires, but point-to-point buses are much faster and eliminate potential contention among
>  peripherals. Shared buses have many problems in SoCs, including accurately modeling delay, verifying
>  contention, and lacking repeaters to drive long wires. Therefore, SoC on-chip buses use point-to-point
>  wiring.**"
> — p.387

中文解釋：**Fig. 9.5（p.387）的兩種設計：**

| | **(a) 共享資料埠** | **(b) 點對點 + 讀取多工器** |
| --- | --- | --- |
| 實作 | **多個周邊用 tristate 驅動 RD 和 RDY** | **用多工器選出被選中周邊的 RD 和 RDY** |
| 優點 | 導線最少 | **快很多、無競爭風險** |
| 在 SoC 的問題 | **延遲難精確建模、競爭難驗證、缺乏 repeater 驅動長線** | — |

**結論：SoC 晶片內匯流排用點對點接線。**
（這和「單向 vs 雙向」是同一個道理的兩個面向。）

### 多控制器與仲裁

> "Larger systems also have multiple controllers that may share the same bus. One or more controllers may
>  place a request on any given cycle by asserting their REQ. **An *arbiter* picks among the requests by
>  granting access to at most one controller and chooses the address (A), write data (WD), and write
>  enable (WE) from that controller, as shown by the Grant Mux in Fig. 9.6.**"
> — p.387–388

中文解釋：**Fig. 9.6（p.388）多了兩個元件：**
- **Arbiter**：接收所有 REQ，輸出 GRANT
- **Grant Mux**：依 GRANT 選出哪個控制器的 A、WD、WE 送上匯流排

**四種仲裁演算法（p.388），這份清單很實用：**

| 演算法 | 做法 | 問題 |
| --- | --- | --- |
| **Static priority（靜態優先權）** | 每個控制器有固定優先權，最高的獲得存取 | **高優先權持續請求時會餓死低優先權的** |
| **Round robin（輪詢）** | **循環授予，每個控制器最終都會拿到** | **公平，但關鍵請求可能延遲很久** |
| **TDMA（分時多工）** | 依頻寬需求分配不同長度的時槽 | — |
| **Dynamic priority（動態優先權）** | **依系統需求即時調整優先權** | — |

**兩個經典的權衡：靜態優先權會 starvation，round robin 會 latency。**

### 多控制器帶來的兩個新問題

**（1）同步（p.389）**
> "**Systems with multiple controllers may need to *synchronize* between controllers so that only one can
>  access a resource at a time. Synchronization is performed with *atomic* operations described in Chapter
>  17. These operations often read, modify, and then write a location in memory in such a way that no
>  other controller can interrupt the operation. Thus, buses often have a *locking* signal so that a
>  controller that is granted access can complete the atomic operation before another controller gains
>  access.**"

**匯流排需要 locking 訊號來支援原子操作。**（第 17 章。）

**（2）DMA 與快取一致性（p.389）——這段很重要**
> "**In a multicontroller system, a device may act as both a peripheral and controller. When the device is
>  a controller, it may perform *direct memory access* (DMA), reading or writing memory without going
>  through the processor. DMA introduces challenges maintaining *coherence* between memory and caches such
>  that any store to an address will eventually be seen by subsequent loads from the same address.
>  For example, if a device writes directly to an address in DRAM but a cache already holds an older value
>  of the contents of that address, reads to the cache will not see the new value written by the device,
>  and the memory system is incoherent.**"

**DMA 的問題：裝置直接寫 DRAM，但 cache 裡還有舊值 → 不一致。**

**解法（p.389）：**
> "**Section 19.1 describes the RISC-V cache management operation (CMO) extension, which includes
>  additional RISC-V instructions to invalidate and clean the data cache to maintain coherence with a DMA
>  controller. A more detailed discussion of DMA coherence is beyond the scope of this book.**"

### 其他匯流排功能

**（1）傳輸模式（p.389）**

| 模式 | 說明 |
| --- | --- |
| **Subword write** | 用 `Size` 或 `ByteEn` 訊號指出要寫哪些 byte |
| **Burst transfer** | **一連串對連續位址的讀或寫，減少重複仲裁的開銷** |
| **Split transfer** | **資料傳輸很慢時（如 DRAM 讀新的 row 要數十週期），
用唯一 ID 標記傳輸並釋放匯流排；稍後再帶著資料和 ID 回應** |

**Split transfer 的價值：避免慢的傳輸佔住匯流排數十個處理器週期。**

**（2）Bridge（p.389）**
> "**Complex systems often use more than one type of bus interface. For example, a system may have a
>  high-speed memory bus and a low-speed bus for other (including legacy) peripherals. A *bridge*
>  interfaces two buses to translate the interaction from one bus to another and so that their protocols
>  are each satisfied.**"

（Fig. 9.7 的 AHB-to-APB bridge 就是例子。）

**（3）Cache coherency（p.390）**
> "**Some buses, such as ACE and TileLink Cached, incorporate *cache coherence* capabilities directly into
>  the bus protocols to support *shared-memory multiprocessors* in maintaining *coherence* across their
>  cache memories.**"

**（4）Network on Chip（NoC）（p.390）**
> "**High-performance systems often need more bandwidth than a single bus can provide.... A *Network on
>  Chip* (NoC) provides a flexible and high-performance interconnect. Types of NoC architectures include
>  *crossbars*, where every component can communicate with any other component; *indirect networks*, in
>  which components communicate through a series of switches; and *meshes* or *rings*, in which every
>  component can communicate with its neighbors.**"

**三種 NoC 架構：crossbar（任意對任意）、indirect network（經交換器）、mesh/ring（鄰居對鄰居）。**

### 晶片外高速連結的演進

> "**AT&T developed the first commercial modem in 1958 for the SAGE system that connected radar systems
>  across the United States to detect intrusions by Soviet nuclear bombers. The modem ran over the phone
>  lines at 110 baud (symbols per second), transmitting 80 bits per second (bps), which is 10 characters
>  per second, between mainframe computers and teletype terminals.**"
> — p.390

中文解釋：**1958 年：80 bps。** 對照 2025 年的數字（p.390）：

| 連結 | 頻寬 |
| --- | --- |
| **USB-C** | **40 Gbps** |
| **HDMI 2.2** | **96 Gbps** |
| **雙通道 DDR5-6400** | **約 400 Gbps**（DRAM 與 CPU 之間） |
| **PCIe 5.0 x16** | **最高 1 Tbps**（顯卡與 CPU 之間） |
| **Ethernet**（資料中心） | **800 Gbps** |
| Wi-Fi 7 / 5G | 理論上超過 10 Gbps |

**從 80 bps 到 1 Tbps：10 個數量級以上。**

### 高速訊號的三個技術

**（1）差動訊號（p.390）**
> "**As the data moves along the copper at nearly the speed of light, transmission line effects are
>  critical, and the wires must be properly *terminated* with a *matched impedance*, making point-to-point
>  links essential. The links use *differential signaling*, in which the data is represented as a
>  difference in voltage between a pair of wires, rather than as a single-ended signal relative to a ground
>  line. Differential signaling reduces *crosstalk*, *common-mode noise*, and *electromagnetic
>  interference* because current is balanced, flowing out and back along the pair rather than returning
>  over a shared ground line.**"

**差動訊號的原理：電流在一對線上來回，不經共用地線 → 平衡 → 減少串音、共模雜訊、電磁干擾。**

**（2）Source-synchronous clocking 與 DDR（p.391）**
> "**Some high-speed links such as DDR (double-data-rate) memory use *source-synchronous clocking*, in
>  which a clock is sent along with a parallel bundle of data bits.... If the memory bits only switched
>  once per clock cycle, they would only use half of the available bandwidth of the line. Hence, DDR links
>  send data on both rising and falling edges of the clock (thus, its name: double-data-rate) to use the
>  same toggle rate as the clock and fully saturate the transmission line's capabilities.**"

**DDR 的名字由來：資料在時脈的上升緣和下降緣都傳送，
讓資料的切換率和時脈一樣，充分利用傳輸線能力。**

**（3）高速序列連結與 CDR（p.391）**
> "**Source-synchronous speeds are limited by mismatches in flight time between bits in the bundle.
>  These mismatches are influenced by the line lengths, impedances, and noise. *High-speed serial links*
>  avoid these mismatches by sending a differential bitstream over a differential pair encoded in such a
>  way that the bitstream conveys both clock and data. The receiver performs *clock/data recovery* (CDR)
>  to determine when to sample the serial stream, then decodes the data bits.**"

**序列連結的優勢：沒有「bit 之間到達時間不一致」的問題（因為只有一條）。
代價是要從資料流裡恢復時脈（CDR）。**

**編碼方式（p.391）：**

| 編碼 | 用於 | 保證 |
| --- | --- | --- |
| **8b/10b** | — | **8 bit 資料編成 10 bit 符號，保證每 5 bit 至少一次切換** |
| **64b/66b** | 10-Gb Ethernet | 開銷較低 |
| **128b/130b** | PCIe 5 | 開銷更低 |
| 128b/132b | USB 3.1 | — |

**冗餘位元還能提供錯誤偵測與更正。PLL 偵測這些切換來對齊取樣時脈。**

**PCIe 5 x16 用 16 條序列 lane，每條 32 GHz（64 Gbps）。**

### 這些都超出本書範圍（但要知道怎麼取得）

> "**PCIe (PCI Express), DDR memory, USB, and Ethernet each have specifications that are many hundreds of
>  pages long, and they require a complex controller and *physical interface* (PHY) beyond the scope of
>  this book. SoC designers purchase these controllers and PHYs as *IP* (intellectual property) blocks.
>  The controllers may be integrated onto an ASIC... or FPGA... and connected to the rest of the SoC via
>  AXI or another standard on-chip bus. The SoC physical interface involves custom mixed-signal circuitry
>  such as impedance-controlled differential output drivers and phase-locked loops. These are also sold by
>  IP vendors.**"
> — p.391

中文解釋：**實務做法：買 IP。**（呼應 4.1.3 節。）
**controller 接到 AXI 或其他標準晶片內匯流排，PHY 是類比混合訊號電路。**

**本節的結論（p.391）：**
> "**All these sophisticated techniques for fast off-chip links cost chip area and power.
>  Within the SoC, it remains more cost-effective to use wide buses, instead of serial buses, to deliver
>  high local bandwidth.**"

**晶片內用寬的並列匯流排，晶片外用高速序列連結——
因為晶片內導線便宜，晶片外接腳貴。**

## 名詞表

| 名詞 | 意思 |
| --- | --- |
| Controller / peripheral（responder） | 控制器 / 周邊。舊稱 master/slave，ARM 現用 manager/subordinate |
| Uncore | SoC 中核心以外的部分：匯流排介面、記憶體、周邊 |
| **Unidirectional vs bidirectional** | **SoC 一律用單向**（長線需要 repeater，雙向不可行） |
| **Point-to-point vs shared** | **SoC 晶片內用點對點 + 讀取多工器**（共享匯流排延遲難建模、有競爭） |
| **Handshaking** | REQ（控制器發，省電）+ RDY/ACK（周邊回，表示完成） |
| Wait state | 周邊還沒好時插入的等待週期 |
| Address decoder | 依位址產生 select 訊號；RISC-V 一般化為 PMA 單元 |
| **Arbiter** | 仲裁器。四種演算法：**static priority（會餓死）、round robin（公平但延遲）、TDMA、dynamic priority** |
| Locking signal | 讓控制器能完成原子操作而不被搶走匯流排 |
| **DMA** | Direct memory access。裝置不經處理器直接讀寫記憶體；**造成 cache coherence 問題** |
| Coherence | 一致性。對某位址的 store 最終要被後續的 load 看到 |
| **Burst transfer** | 對連續位址的一連串傳輸，減少重複仲裁開銷 |
| **Split transfer** | 用 ID 標記慢速傳輸並釋放匯流排，稍後帶 ID 回應 |
| Bridge | 橋接器。轉譯兩種匯流排協定 |
| **NoC** | Network on Chip。架構有 crossbar、indirect network、mesh/ring |
| **Differential signaling** | 差動訊號。用一對線的電壓差表示資料；減少串音、共模雜訊、EMI |
| Matched impedance / termination | 阻抗匹配與端接；高速時必要，故需點對點 |
| **Source-synchronous clocking** | 時脈和並列資料一起送；DDR 用 |
| **DDR** | 在時脈上升緣和下降緣都送資料，充分利用傳輸線 |
| **CDR** | Clock/data recovery。從序列位元流中恢復時脈 |
| 8b/10b、64b/66b、128b/130b | 序列編碼，保證位元切換以利 CDR；冗餘位元可做錯誤偵測 |
| PHY | Physical interface。類比混合訊號電路；通常向 IP 廠商購買 |

## 所以呢

**這節建立了匯流排設計的通用詞彙，三個「SoC 一律這樣做」的結論最重要：**

1. **單向而非雙向**——長導線需要 repeater，雙向不可行。
2. **點對點 + 讀取多工器，而非共享 + tristate**——延遲可建模、無競爭。
3. **晶片內用寬並列，晶片外用高速序列**——因為接腳貴、導線便宜。

另外三個實用的概念：
- **Handshaking（REQ + RDY）**：解決「周邊需要多個週期」的問題。
- **仲裁的四種演算法**：static priority 會餓死、round robin 公平但延遲。
- **DMA 造成 cache 不一致**——需要 CMO 擴充（第 19.1 節）來處理。

下一節（9.2）進入具體的 AMBA 標準：APB、AHB、AXI。
