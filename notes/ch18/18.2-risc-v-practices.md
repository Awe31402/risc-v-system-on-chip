# 18.2 RISC-V Practices

> 原書 p.734–748（Chapter 18: Extensions: Zb* & Zk* (Bit Manipulation and Cryptography)）
> 涵蓋 18.2.1 Zba、18.2.2 Zbb、18.2.3 Zbc、18.2.4 Zbs、18.2.5 Zbkb、18.2.6 Zbkx、18.2.7 Zknd/Zkne、18.2.8 Zknh

## 這節在講什麼

前一節建立了背景，這節列出實際的指令。兩大家族：
- **Zb\***（bit manipulation）：Zba 位址產生、Zbb 基本位元操作、Zbc carry-less 乘法、Zbs 單位元操作。`B` 是 Zba + Zbb + Zbs 的簡寫（**不含 Zbc**）。
- **Zk\***（cryptography）：Zbkb/Zbkc/Zbkx 是給密碼學用的位元操作、Zknd/Zkne 是 AES 解密/加密、Zknh 是 SHA-2。`Zkn` = 這六個的總和，`Zk` = Zkn + Zkt + Zkr。

每個指令都值得問同一個問題：**它取代了幾條指令？** 書上大量用「Assembly Without / With」的並排對照來回答。

## 關鍵點

### 兩張擴充總表

> "Zba: Address generation — Shifts and add to access 2/4/8-byte elements; Zbb: Basic bit manipulation — Min/max, rotations, counting, sign/zero extension, etc.; Zbc: Carry-less multiplication — For Galois-field operations such as cryptography; Zbs: Single-bit instructions — Set, clear, invert, or extract single bits; B: Bit manipulation — Zba + Zbb + Zbs"
> — p.734（Table 18.8）

中文解釋：注意 **B 不包含 Zbc**。因為 carry-less 乘法只有密碼學和 CRC 用得到，一般程式不需要，所以獨立出來讓小型系統能省下這塊硬體。

> "Zbkb: Bit manipulation for cryptography; Zbkc: Carry-less multiplication (subset of Zbc); Zbkx: Crossbar permutations (useful for implementing S-boxes); Zknd: Decryption/key scheduling; Zkne: Encryption/key scheduling; Zknh: Hash functions; Zkn: NIST crypto instructions = Zbkb + Zbkc + Zbkx + Zknd + Zkne + Zknh; Zkt: Data-independent latency; Zkr: Entropy source; Zk: Standard scalar crypto = Zkn + Zkt + Zkr"
> — p.735（Table 18.9）

中文解釋：切得這麼細是有道理的——微控制器可能只需要加密不需要解密（例如只送不收的感測器），或只需要雜湊不需要 AES。

### Zkt：不加指令，只做承諾

> "If instructions have data-dependent delay, hackers can use timing attacks to infer information about a cryptographic key. Therefore, the Zkt extension specifies that a list of simple and common instructions execute in data-independent time to prevent such attacks; this list excludes division and remainder and is automatically satisfied by most microarchitectures, including Wally."
> — p.734

中文解釋：這是一個很特別的「擴充」——**它不加任何指令，只是保證一批既有指令的執行時間與資料無關**。除法和餘數被排除在外（因為它們的延遲本來就取決於運算元）。大多數微架構天生就滿足，包括 Wally。這呼應 18.1 開頭的 timing attack。Zkr 則提供一顆 `seed` CSR，給亂數產生器當熵源。

### Zba：把「index × size + base」壓成一條

> "To access an array, a program calculates an element's address by adding the array's base address to the element index multiplied by the element size. The Zba extension makes accessing halfwords, words, and double words more efficient by incorporating multiplications by 2, 4, and 8 into an add instruction."
> — p.734

中文解釋：`sh2add t0, s0, s2` 就是 `t0 = s2 + (s0 << 2)`。Code Example 18.2 對照：沒有 Zba 要 `slli` + `addi` 兩條，有 Zba 一條。這是最常見的操作之一（每次陣列存取都會用到），所以省的量很可觀。

RV64 另加 `.uw` 系列（`add.uw`、`sh2add.uw`、`slli.uw`），專門處理 32 位元 `unsigned int` 索引——在 RV64 上把 32 位元無號數擴展成 64 位元本來要 `slli` + `srli` 兩條移位，`add.uw` 一條解決（Code Example 18.3）。

### Zbb 的五組指令

**(1) Rotates**（`rol`、`ror`、`rori`）

> "Rotations show up in many algorithms from discrete mathematics, including hashing, cryptography, and cyclic redundancy checks (CRCs) used in error correction."
> — p.736

中文解釋：C 語言沒有旋轉運算子，只能寫成 `(a << n) | (a >> (32-n))`，編譯出來是 4 條指令（Code Example 18.4）；有 `rol` 就一條。注意沒有 `roli`（左旋立即值）——因為 `roli t0, s0, 1` 等同 `rori t0, s0, 31`，用互補的立即值就好。另外 RV32 的移位量是 mod 32，所以 `32−n` 可以直接寫成 `−n`。

**(2) Inverted operations**（`andn`、`orn`、`xnor`）

> "Inverted operations (andn, orn, xnor) perform the base operation (and, or, xor) with the second operand inverted. This is essentially free in hardware because subtraction already requires the ability to invert the second operand."
> — p.736

中文解釋：**「硬體上基本免費」**是關鍵——ALU 為了做減法本來就有反相第二運算元的能力，直接複用。`andn` 最常用，用來遮掉指定的位元。

**(3) Max/Min**（`max`、`maxu`、`min`、`minu`）

中文解釋：Code Example 18.5 對照：沒有時要 `blt` + `mv` + 標籤（**而且有分支，可能預測錯誤**），有 `max` 就一條而且無分支。消除分支的價值往往比省指令數更大。

**(4) Extension**（`zext.h`、`sext.h`、`sext.b`）

中文解釋：Code Example 18.6：兩個 `short` 相加，32 位元加法會溢位到第 17 位元，所以要符號擴展。沒有指令時要 `slli` + `srai` 兩條移位，有 `sext.h` 一條。邊欄列出其他擴展可以用偽指令：`zext.b` = `andi rd, rs1, 255`、`zext.w` = `add.uw rd, rs1, 0`、`sext.w` = `addiw rd, rs1, 0`。

**(5) Counting, Combining, Reversing**（`cpop`、`clz`、`ctz`、`orc.b`、`rev8`）

> "cpop has many applications, such as counting 1s in a bitstream, computing Hamming distance, and implementing associative arrays with an efficient data structure called hashed array mapped trie (HAMT). Computing Hamming distance is important for cryptanalysis, and the National Security Agency reportedly asked for the cpop instruction in early supercomputers."
> — p.738（邊欄）

中文解釋：`cpop`（population count）數 1 的個數、`clz`/`ctz` 數前導/尾隨零。`orc.b` 檢查每個位元組，非零就把該位元組設成全 1——**用來找字串的 NULL 位元組**，`strlen`/`strcmp` 的關鍵。`rev8` 反轉位元組順序——**大小端轉換**，密碼學輸入輸出常需要。

> "C does not have any of these operators. GCC currently does not infer them from C code either, but it does produce them using built-in counting functions: `__builtin_popcount`, `__builtin_clz`, `__builtin_ctz`"
> — p.738

中文解釋：這點很實用——**編譯器不會自動用這些指令**，要靠 built-in 函式明確叫出來。

### Zbc：carry-less 乘法

> "Carry-less multiplication produces partial products like regular multiplication but sums each column using XOR, discarding carries out of each column. ... Carry-less multiplication is a building block for multiplication in the Galois field GF(2ⁿ). It is used in a variety of algorithms, including CRC, Galois/Counter Mode symmetric key encryption, and fast universal hash functions."
> — p.738

中文解釋：這正是 18.1.1.2 講的 GF(2ⁿ) 乘法——部分積相加改成 XOR。Fig. 18.16 用 4×4 位元示範。三個指令：`clmul`（低半部）、`clmulh`（高半部）、`clmulr`（反轉版，CRC 用）。Table I.23 用 `@` 符號表示 carry-less 乘法。

### Zbs：單位元操作

> "Zbs provides instructions to set, clear, invert, and extract a bit within a register. ... These instructions are often used to modify bitfields within a word. In memory-mapped I/O, they are used to turn on and off control bits or to check the value of a status bit."
> — p.739

中文解釋：`bset`、`bclr`、`binv`、`bext`（各有立即值版本）。Code Example 18.7 的對照很驚人——四個操作，沒有 Zbs 要 8 條指令（每個都要先 `li` + `sll` 造遮罩），有 Zbs 就 4 條。**驅動程式的主要工作就是設定/清除暫存器位元**，所以這組指令對嵌入式程式碼密度影響很大。

### Zbkb：密碼學專用的位元操作

> "Zbkb provides bit manipulation instructions specifically for cryptography. In addition to crypto-related instructions also available in Zbb, it provides pack, packh, packw, brev8, zip, and unzip."
> — p.739

**Packing**（`pack`、`packh`、`packw`）

> "Packing instructions place the bottom portions of two source register into a destination register. This is useful for rearranging small data elements within wider registers. For example, AES uses packing when loading keys that are not word aligned."
> — p.740

中文解釋：`pack` 把兩個暫存器的低半部拼成一個。Code Example 18.9 對照：沒有時要 3 次移位 + 1 次 or（4 條），有 `pack` 就 1 條。

**Bit Reversal**（`brev8`）

> "The brev8 instruction reverses the bits within each byte of a register. This is a step in the GHASH (Galois Hash) authentication function for AES encryption and, without brev8, this step is painful to implement in software."
> — p.740

中文解釋：注意和 `rev8` 的差別——`rev8` 反轉**位元組的順序**，`brev8` 反轉**每個位元組內的位元**。

**Bit Interleaving**（`zip`、`unzip`）

> "64-bit rotations are difficult to implement with 32-bit arithmetic. Various algorithms including SHA-3 require such 64-bit rotations. Hence, RV32Zbkb provides zip and unzip instructions to facilitate longer rotations. zip interleaves bits (like a zipper interleaves its two sides)"
> — p.740

中文解釋：只有 RV32 有。Fig. 18.17：`zip` 把低半部的位元放進偶數位置、高半部放進奇數位置，`unzip` 是反操作。用途：RV32 上實作 SHA-3 的 64 位元旋轉——把一對 32 位元字 zip 成交錯形式後，偶數半和奇數半各自旋轉就等同原本的 64 位元旋轉。

### Zbkx：crossbar permutation，用來抵抗時序攻擊

> "Crossbar permutations are used to select nibbles or bytes from one register based on indices stored in another register. For example, xperm4 uses each nibble of rs2 as an index to select a nibble from rs1. ... If the index is out of bounds, the permutation returns 0."
> — p.741

中文解釋：`xperm4`（nibble）和 `xperm8`（byte）。想成一個「用暫存器當查表」的指令。

> "Crossbar permutations are useful for implementing S-boxes that create nonlinearities in many symmetric key cryptosystems, including AES. The substitution could be done with a table lookup from memory, but cache systems introduce data-dependent delays that can leak information about the key."
> — p.741

中文解釋：這是整個 Zbkx 存在的理由，而且是這節最重要的安全觀念。**用記憶體查 S-box 表會因為快取命中/失誤產生與資料相關的延遲，洩漏金鑰資訊**。Code Example 18.10 用 `xperm8` 實作一個延遲固定的 S-box：256 項表壓縮成 32 個 64 位元字，用一個 `mask` 逐步走過每個位元組的高 5 位元，`xperm8` 在高 5 位元吻合時用低 3 位元選值。關鍵在於——**迴圈永遠跑 32 次，所有記憶體存取都與輸入無關**。

### Zknd/Zkne：AES 的 RV64 與 RV32 兩種策略

> "AES decryption and encryption are such common and computationally intensive operations that it is valuable to have specialized instructions to accelerate them. ... Note that the order of ShiftRows and SubBytes does not matter because these operations are commutative."
> — p.742

中文解釋：這個「可交換」的觀察讓硬體能重排步驟以方便打包。

> "RV64 can pack the state matrix into two 64-bit registers in such a way that SubBytes, ShiftRows, and MixColumns can all be performed on the whole matrix with just two identical instructions called aes64esm. ... On the other hand, RV32 cannot provide the whole state matrix at once and instead operates one byte of one column at a time using aes32esm."
> — p.742

中文解釋：這是 RV64 與 RV32 的關鍵分歧，根源是 **RISC-V 指令只有兩個來源暫存器**：
- **RV64**：128 位元狀態 = 兩個 64 位元暫存器，剛好塞進一條指令的兩個來源。所以 `aes64esm(x, y)` 一次處理兩整欄。一輪只要 **2 條 XOR + 2 條 `aes64esm`**（Code Example 18.11）。
- **RV32**：128 位元 = 四個 32 位元暫存器，一條指令拿不到全部。所以 `aes32esmi(x, y, bs)` 一次只處理一欄的一個位元組。一輪要 **16 條 `aes32esmi`**（Code Example 18.12）。

### aes64esm 內部做了什麼

> "aes64esm(x, y): w = ShiftRows(x, y) // Wires permute inputs; s = Sbox(w) // S-box operations on all 8 bytes in parallel; return t = {MixColumns(s_{63:32}), MixColumns(s_{31:0})}"
> — p.744

中文解釋：三步一條指令。狀態矩陣以 **column-major order（行優先）** 打包進兩個暫存器（Fig. 18.18），這個打包方式是精心設計的——ShiftRows 變成純粹的接線置換（式 18.2），而且**把兩個來源暫存器對調再呼叫一次就得到另外兩欄**（所以 Code Example 18.11 裡兩條 `aes64esm` 的來源順序是相反的：`a0, t0, t1` 與 `a1, t1, t0`）。

MixColumns 的展開（式 18.3）也印證了 18.1 的分析——只有 `xz`（乘 x，即左移 + 條件 XOR）和 XOR，沒有真正的乘法器。

### aes32esmi 內部做了什麼

> "aes32esm(x, y, bs): si = y[bs] // Select one of the four elements of y; s = sbox(si) // S-box on one element; col = {xs ⊕ s, s, s, xs} // One row of MixColumns matrix; mixed = col rol bs // Rotate col into proper place; return t = x ⊕ mixed"
> — p.746

中文解釋：五步。注意最後的 `x ⊕ mixed`——**累加**。所以 16 條指令是「四欄 × 每欄四個位元組」逐步累加出結果。第二個來源暫存器在四條之間變化（這就是 ShiftRows），`bs` 從 0 到 3 走過一欄的四個位元組。最後一輪用 `aes32esi`（少了 `m`），省略 MixColumns。

### 解密與 key scheduling

> "The inverse of AES encryption is decryption, which uses aes32dsmi, aes32dsi, aes64dsm, and aes64ds instructions. These instructions apply inverse operations, in the same order as encryption. They use an inverse S-box and the InvMixColumns matrix from Fig. 18.13 ... ShiftRows is inverted by shifting in the opposite direction."
> — p.746–747

中文解釋：命名規律：`aes{32|64}{e|d}s{m|}[i]`——32/64 位元、encrypt/decrypt、s = 一輪、m = 含 MixColumns、i = 帶 byte-select 立即值。

> "RV64Zkn{e/d} introduce aes64ks1i, aesks2, and aes64im instructions to accelerate key scheduling by processing two 32-bit words at a time in a 64-bit register and applying four S-boxes in parallel."
> — p.747

中文解釋：RV32 沒有專用的 key scheduling 指令，用 `rori` + `xor` + `aes32esi`（當 S-box 用）在軟體做。這又是一個「RV64 暫存器夠寬所以能硬體加速」的例子。

### Zknh：SHA-2 的 sigma 函數

> "For SHA-256, the instructions are called sha256sig0, sha256sig1, sha256sum0, and sha256sum1, with sig corresponding to σ and sum corresponding to Σ. Each instruction takes a register containing a 32-bit value and applies the rotations, shifts, and XORs to produce a 32-bit output."
> — p.747

中文解釋：命名對照——`sig` = σ（小寫 sigma）、`sum` = Σ（大寫 sigma）。四條指令正好對應 18.1.3 的四個函數：

```
sha256sig0: rd = (rs1 ror 7)  ⊕ (rs1 ror 18) ⊕ (rs1 >> 3)
sha256sig1: rd = (rs1 ror 17) ⊕ (rs1 ror 19) ⊕ (rs1 >> 10)
sha256sum0: rd = (rs1 ror 2)  ⊕ (rs1 ror 13) ⊕ (rs1 ror 22)
sha256sum1: rd = (rs1 ror 6)  ⊕ (rs1 ror 11) ⊕ (rs1 ror 25)
```

**每條指令取代 5 條**（三次旋轉/移位 + 兩次 XOR，而且旋轉在沒有 Zbb 時還要更多）。RV64Zknh 會把 32 位元結果符號擴展填滿上半，但雜湊時會忽略那些位元。

SHA-512 有對應的 `sha512sig0`、`sha512sig1`、`sha512sum0`、`sha512sum1`（RV64 上是 64 位元運算）。

> "In RV32Zknh, SHA-512 is somewhat more difficult because the 64-bit words do not fit in a single register. Instead, the words are kept in a pair of registers, and a pair of instructions are needed to compute the upper and lower half of each function."
> — p.748

中文解釋：所以 RV32 有 `sha512sig0h`/`sha512sig0l`、`sha512sum0r` 這種成對的變體（Table 18.11 的測試清單可以看到）。

### 這些指令要手寫組語

> "Compilers cannot generally infer these instructions, so crypto libraries are normally written by domain experts in assembly language."
> — p.742

中文解釋：和 Zbb 的 `cpop`/`clz` 一樣，編譯器不會自動用。Code Example 18.13 示範怎麼用 GCC 的 inline assembly 把 `sha512sig0` 包成 C 的 inline function，再用巨集組出完整的 ROUND 和 SCHEDULE 操作。

## 所以呢

這一大批指令的共同模式：**把演算法裡反覆出現的固定樣式（移位+加、旋轉+XOR、S-box 查表、GF 乘法）直接做成硬體**。省下的不只是指令數，還有兩件事——消除分支（`max`/`min`）和消除與資料相關的延遲（`xperm8` 取代記憶體查表）。RV64 與 RV32 的 AES 策略分歧則揭露了一個 ISA 層級的限制：兩個來源暫存器塞不下 128 位元狀態，所以只能一次處理一半或一個位元組。接下來 18.3 看測試、18.4 看 Wally 怎麼把這些接進整數 ALU。
