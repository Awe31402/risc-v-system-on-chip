# 20.2 CLINT

> 原書 p.784.e8–784.e10（Chapter 20: Peripherals）
> 涵蓋 20.2.1 Memory Map、20.2.2 Test Plan、20.2.3 Wally Implementation

## 這節在講什麼

CLINT（Core Local Interruptor，核心區域中斷器）是整本書裡最小的周邊——只有三種暫存器——但它提供的兩樣東西是作業系統的命脈：**計時器中斷**（用來做 preemptive multitasking）和**軟體中斷**（用來讓核心之間互相通知）。

## 關鍵點

### CLINT 的三樣東西

> "The Core Local Interruptor (CLINT) contains memory-mapped registers to generate software and timer interrupts and read the current time. Specifically, it has a 64-bit time counter, a 64-bit time compare register that produces a timer interrupt when the timer exceeds the compare value, and a 1-bit register to create a software interrupt."
> — p.784.e8

中文解釋：Fig. 20.6 的介面只有三組：APB、`MSwInt`、`MTimerInt`。兩個中斷都是 **M-mode 專屬**，直接送給核心（不經過 PLIC）——這是「core local」這個名字的由來。

Table 20.2 的記憶體映射：
- `0x00`：hart 0 的 `msip`（1 位元軟體中斷 pending）
- `i * 4`：hart i 的 `msip`
- `0x4000`：hart 0 的 `mtimecmp`（64 位元比較值）
- `0x4000 + i * 8`：hart i 的 `mtimecmp`
- `0xBFF8`：`mtime`（64 位元計時器，**所有 hart 共用**）

注意這個不對稱：**每個 hart 有自己的 `msip` 和 `mtimecmp`，但 `mtime` 只有一份**。這正是多核心系統需要的——共同的時間基準，各自的鬧鐘。`mtime` 和 `msip` 在 reset 時歸零。

### mtime 為什麼要跑在不同的時脈域

> "The time memory-mapped register is a system timer that typically runs continuously at a constant frequency even if some or all of the cores are sleeping with their clocks stopped. It may use a different frequency clock than the core, especially if the core frequency is variable. If the timer is asynchronous to the cores, the CLINT requires clock domain crossing circuitry."
> — p.784.e8

中文解釋：這是一個重要的系統層考量。現代處理器會**動態調整頻率**（DVFS）或**停掉時脈省電**，但「時間」不能跟著變——不然 OS 的排程、逾時、時間戳全部亂掉。所以 `mtime` 通常掛在一個獨立的固定頻率時脈上，代價是需要跨時脈域電路（和 20.1 的 GPIO 輸入同步器是同類問題）。

### 軟體中斷用來做什麼

> "Cores can send messages to each other using software interrupts. Operating systems use timer interrupts to schedule one of several U-mode processes."
> — p.784.e8（邊欄）

中文解釋：兩個用途講得很清楚：
- **軟體中斷**：核心間通訊（IPI, inter-processor interrupt）。例如一個核心改了頁表，要通知其他核心作廢它們的 TLB（第 11 章、第 19 章的 `sfence.vma` / Svinval）。
- **計時器中斷**：**搶佔式多工的基礎**。沒有它，一個不肯讓出 CPU 的程式就能霸佔整台機器（呼應第 17 章講 lock 時提到「關中斷會讓系統沒反應」的問題）。

### hart 只能讀 time

> "Recall from Section 8.2.3 that a hart can read (but not write) the read-only time memory-mapped register from the CLINT."
> — p.784.e8

中文解釋：這是第 8 章 CSR 的延伸。`time` 這顆 CSR 其實不是真的 CSR，而是**映射到 CLINT 的 `mtime`**。唯讀是合理的：如果 U-mode 程式能改系統時間，所有的排程和逾時都會被破壞。

### 怎麼用 CLINT 做延遲

> "Write functions to set the CLINT software interrupt to 0 or 1 and to create a delay of a specified number of timer ticks."
> — p.784.e9（Example 20.2）

中文解釋：Example 20.2 的 `delay()` 函式示範了最常見的用法：

```c
volatile uint64_t *CLINT_MTIME = (uint64_t*)0x2000BFF8;

void delay(uint64_t ticks) {
  uint64_t doneTime = *CLINT_MTIME + ticks;
  while (*CLINT_MTIME < doneTime);   // 自旋直到時間到
}
```

**注意 `volatile` 又出現了**——沒有它，編譯器會把 `*CLINT_MTIME` 從迴圈裡提出來，變成無窮迴圈。

這是一個「讀 `mtime` 輪詢」的版本，不用中斷。若要用中斷，就把 `*CLINT_MTIMECMP` 設成目標時間，時間到時 `MTimerInt` 會拉起。

### 測試方法

> "The CLINT is tested by toggling software interrupts, mtime and mtimecmp, and checking that the mip.MSIP and mip.MTIP (software and timer interrupt pending) bits respond accordingly."
> — p.784.e9

中文解釋：測試的關鍵是檢查**核心那一端**的 `mip` CSR 位元有沒有跟著動，而不只是檢查 CLINT 自己的暫存器——這才驗證了整條中斷路徑。

### 硬體實作

> "The CLINT has a 64-bit mtime counter, a 64-bit mtimecmp register, 1-bit msip register, and a 64-bit timer interrupt comparator along with circuitry to read and write these registers. The mtime counter increments on each cycle unless it is being written."
> — p.784.e10

中文解釋：Fig. 20.7 的整個模組就是：
- 一個 64 位元計數器（`mtime`），每個 cycle 加 1
- 一個 64 位元暫存器（`mtimecmp`）
- 一個 1 位元暫存器（`msip`）
- 一個 64 位元比較器（`mtime >= mtimecmp` 產生 `MTimerInt`）
- 位址解碼器 + read multiplexer（和 GPIO 完全一樣的模式）

「unless it is being written」這個細節：軟體寫 `mtime` 時那個 cycle 不遞增，不然寫進去的值馬上就被加 1 了。

## 名詞表

| 名詞 | 意思 |
| --- | --- |
| CLINT | Core Local Interruptor，SiFive 定義的事實標準計時器/軟體中斷控制器 |
| `mtime` | 64 位元系統計時器，所有 hart 共用，位於 0xBFF8 |
| `mtimecmp` | 64 位元比較值，每個 hart 一份 |
| `msip` | 1 位元軟體中斷 pending，每個 hart 一份 |
| `MTimerInt` / `MSwInt` | 計時器／軟體中斷訊號，直送核心的 M-mode |
| `mip.MTIP` / `mip.MSIP` | 核心端對應的中斷 pending CSR 位元 |
| IPI (inter-processor interrupt) | 核心間中斷，靠軟體中斷實作 |
| clock domain crossing | 跨時脈域電路 |
| DVFS | 動態電壓頻率調節，核心頻率會變但 `mtime` 不該跟著變 |
| preemptive multitasking | 搶佔式多工，靠計時器中斷強制切換執行緒 |
| timer tick | 計時器的一個計數單位 |

## 所以呢

CLINT 小到只有三個暫存器，卻是「多工作業系統能不能存在」的關鍵——計時器中斷讓 OS 能強制收回 CPU，軟體中斷讓核心能互相協調。這兩個中斷都直接連到核心的 M-mode，不需要仲裁。但一台實際的機器還有很多其他中斷來源（UART 收到字元、GPIO 按鈕被按下、SD 卡完成傳輸），它們數量多、優先權不同、可能要送給不同的 hart 和不同的權限層級——這就需要一個仲裁器，也就是下一節的 PLIC。
